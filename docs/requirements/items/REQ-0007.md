### REQ-0007: Polyrepo Architectural Partitioning & Boundary Enforcement
- **Normative Statement**: The compiler architecture shall maintain strict polyrepo partitioning between upstream distribution toolchains and downstream customer domain workspaces. Upstream toolchain updates shall be deliverable via automated installers (`install_pipeline.sh`) without mutating downstream domain models.
- **Formal Semantics & Invariants**:
  Let $\mathcal{U}$ be upstream pipeline tools and $\mathcal{D}$ be downstream domain specifications. The module boundary mapping $\Omega$ ensures:
  $$
  \mathcal{U} \cap \mathcal{D} = \emptyset
  $$
  Pipeline installation replaces tooling directories (`.pipeline/`, `scripts/`) while preserving intact all files in `schema/`, `docs/`, and application source trees.
- **Error Diagnostics & Quality Boundaries**:
  Modification or overwrite of downstream user domain files during upstream pipeline synchronization shall emit `E0125` (Polyrepo Boundary Collision).
- **Acceptance Criteria**:
  - **AC-1**: Running pipeline upgrade script leaves existing `schema/*.sysml` files completely untouched.
  - **AC-2**: Upstream tooling updates install cleanly across downstream projects with verified checksum validation.
  - **AC-3**: Versioned configuration manifest tracks upstream release level within downstream workspaces.
