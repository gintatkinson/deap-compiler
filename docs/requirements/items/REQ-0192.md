### REQ-0192: Rich Source-Mapped Compiler Diagnostic Reporting with Byte Spans & ASCII Snippets
- **Normative Statement**: The compiler diagnostic engine shall emit rich, human-readable and machine-parseable diagnostics for all compilation errors and warnings. Every diagnostic shall include an error code (`E0100`--`E0599`), severity level (Error, Warning, Note), file path, 1-indexed line and column numbers, exact byte span, underlined source snippet, and actionable remediation guidance.
- **Formal Semantics & Invariants**:
  A diagnostic $D$ is structured as:
  ```rust
  pub struct Diagnostic {
      pub code: DiagnosticCode, // E0100 through E0599
      pub severity: Severity,   // Fatal, Error, Warning, Informational
      pub message: String,
      pub primary_span: SourceSpan,
      pub secondary_spans: Vec<(SourceSpan, String)>,
      pub remediation_hint: Option<String>,
  }
  ```
  Byte span mapping: `SourceSpan` indexes directly into the source file buffer without allocating string copies.
- **Error Diagnostics & Quality Boundaries**:
  Diagnostics with unmapped or out-of-bounds byte spans shall fall back cleanly to file-level scope without panicking; reverse synchronization AST delta conflicts or reconciliation errors shall emit compiler error `E0509` (Reverse synchronization AST delta conflict or reconciliation error).
- **Acceptance Criteria**:
  - **AC-1**: Emits highlighted terminal diagnostics with ANSI color codes and ASCII line pointers.
  - **AC-2**: Emits machine-parseable JSON diagnostic streams when invoked with `--json-diagnostics`.
  - **AC-3**: Source line numbers and column offsets match original input files with 100% precision.
