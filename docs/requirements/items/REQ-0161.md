### REQ-0161: Deterministic UUIDv5 Frontmatter Identity Anchors for Specification Artifacts
- **Normative Statement**: The specification projection engine shall inject an immutable UUIDv5 identity anchor and canonical metadata table into the YAML frontmatter of every generated Markdown document. Document identities shall derive deterministically from the fully qualified AST element path.
- **Formal Semantics & Invariants**:
  For an artifact generated for AST node $N$:
  $$
  \text{id}(N) = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{QualifiedName}(N))
  $$
  The metadata table format:
  ```markdown
  | Attribute | Specification Record |
  | :--- | :--- |
  | **Document ID** | `urn:uuid:<uuidv5>` |
  | **AST Path** | `Package_0::Subsystem_Alpha::Classifier_Beta` |
  | **Type** | feature |
  ```
- **Error Diagnostics & Quality Boundaries**:
  Generation of non-deterministic or missing identity anchors shall emit `E0502` (Missing or Non-Deterministic Document Identity Anchor).
- **Acceptance Criteria**:
  - **AC-1**: Every generated Epic, Feature, User Story, and Use Case contains an RFC 4122 UUIDv5 anchor.
  - **AC-2**: Re-generating documents against unchanged schemas preserves identical UUIDs.
  - **AC-3**: Metadata table parses cleanly and matches canonical specification format.
