### REQ-0087: SysML v2 VerificationCaseDefinition (`verification def`) & VerificationUsage
- **Normative Statement**: The verification engine shall formalize `verification def` and `verification` usages as behavioral verification procedures specializing KerML `Behavior`, executing test, analysis, or inspection methods against subject models to emit formal tri-state verification verdicts.
- **Formal Invariant**: A verification case $V$ specializes KerML `Behavior`:
$$
\text{VerificationDef} \le \text{Behavior}
$$
Execution mapping: A verification case takes subject instance $s : \text{Subject}$ and produces verdict $\nu \in \mathcal{V}$:
$$
\text{eval}(V, s) \in \mathcal{V} = \{ \text{Pass}, \text{Fail}, \text{Inconclusive} \}
$$
Verification binding: A `verify` relationship binds verification case $V$ to requirement $R$ ($V \xrightarrow{\text{verifies}} R$), certifying that $R$ is verified if and only if $\text{eval}(V, s) = \text{Pass}$.
Complexity bound: Verification case dispatch and verdict recording execute in $O(1)$ state machine updates per execution run.
