### REQ-0038: Explicit Definition vs Usage Metamodel Lowering (`ClassifierDef` vs `FeatureUsage`)
- **Normative Statement**: The core metamodel shall strictly distinguish between Definition elements (types, classifiers, components) and Usage elements (features, parts, ports, actions), reflecting the fundamental OMG KerML / SysML v2 architectural separation. Usages shall type against Definitions through explicit `feature_typing` relations.
- **Formal Semantics & Invariants**:
  In `deap-core`, every structural classifier implements the `ClassifierDef` trait, while every contextual instance implements the `FeatureUsage` trait:
  $$
  \text{FeatureUsage}(u) \implies \exists d \in \text{ClassifierDef} \quad \text{such that } \text{typing}(u) = d
  $$
  Usages inherit structural features and constraints from their typing definitions via covariant specialization.
- **Error Diagnostics & Quality Boundaries**:
  Instantiating a usage without a valid definition type shall emit `E0204` (Untyped Feature Usage).
- **Acceptance Criteria**:
  - **AC-1**: Metamodel enforces distinct AST node types for `PartDefNode` (definition) and `PartUsageNode` (usage).
  - **AC-2**: Usages correctly reference their typing definitions via `NodeId` handles.
  - **AC-3**: Connection bindings connect usages exclusively, requiring definition nodes to be instantiated as usages prior to connection.
