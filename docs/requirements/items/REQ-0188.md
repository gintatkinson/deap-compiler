### REQ-0188: Freestanding RTOS Memory-Mapped Register Header Generation
- **Normative Statement**: The deap-codegen engine shall generate freestanding C++20 and C99 memory-mapped I/O register definition headers from hardware interconnect AST nodes with compile-time base address offsets, bitfield structs, and volatile accessors without runtime heap allocation or external library dependencies.
- **Formal Semantics & Invariants**:
  Every register definition maps to a strongly-typed volatile structure with exact bitfield alignment and compile-time address offsets:
  $$
  \text{RegAddress}(R) = \text{BaseOffset} + \Delta_{\text{register}}, \quad \text{sizeof}(R) \in \{1, 2, 4, 8\} \text{ bytes}
  $$
  Volatile access semantics guarantee direct memory access across hardware interconnect boundaries with compile-time register map constants and zero heap allocation.
- **Error Diagnostics & Quality Boundaries**:
  Register address overlap, conflicting bitfield spans, or alignment violations shall emit compiler error `E0505` (Code generation register address conflict or alignment violation).
- **Acceptance Criteria**:
  - **AC-1**: Emits valid freestanding C++20 and C99 header files with compile-time base address constants and bitfield structs.
  - **AC-2**: Generates volatile read and write accessor methods enforcing hardware bit-width boundaries.
  - **AC-3**: Compiles cleanly with standard freestanding compilers without external runtime library dependencies.
