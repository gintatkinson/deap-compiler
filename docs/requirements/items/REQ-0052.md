### REQ-0052: Incremental Compilation Cache Invalidation via Module Dependency DAG
- **Normative Statement**: The compiler shall implement an incremental compilation caching system based on a module dependency DAG. The cache shall compute 64-bit cryptographic hashes (XXH3) for each module and only re-analyze and re-emit modules whose source code or upstream dependencies have changed.
- **Formal Semantics & Invariants**:
  Let $M$ be a module with source hash $H_{\text{source}}(M)$ and dependency set $\text{Deps}(M)$. The module state hash $H_{\text{state}}(M)$ satisfies:
  $$
  H_{\text{state}}(M) = \text{XXH3}\left( H_{\text{source}}(M) \mathbin{\Vert} \bigoplus_{D \in \text{Deps}(M)} H_{\text{state}}(D) \right)
  $$
  If $H_{\text{state}}(M) == H_{\text{cached}}(M)$, the compiler reuses cached artifacts and bypasses analysis.
- **Error Diagnostics & Quality Boundaries**:
  Corrupted cache records shall be automatically discarded and rebuilt without failing the compilation; calculation definition type mismatches or expression binding errors encountered during cache rebuild shall emit compiler error `E0216` (Calculation definition return type or expression binding violation).
- **Acceptance Criteria**:
  - **AC-1**: Modifying an isolated leaf module triggers recompilation of only that module and its direct dependents.
  - **AC-2**: Incremental rebuilds of unchanged projects complete in under 5 milliseconds.
  - **AC-3**: Cache invalidation correctly cascades when an upstream shared type definition changes.
