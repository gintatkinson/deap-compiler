### REQ-0022: Tabular Schema Ingestion for Structural Parts & Component Assemblies
- **Normative Statement**: The ingestion engine shall parse tabular schemas specifying structural parts and component assemblies into `IngestedPart` intermediate entities. The schema shall extract part names, types, multiplicity intervals `[min..max]`, structural containment hierarchies, and owned sub-components.
- **Formal Semantics & Invariants**:
  An `IngestedPart` node is defined as:
  ```rust
  pub struct IngestedPart {
      pub id: Spur,
      pub type_name: Spur,
      pub multiplicity: (u32, Option<u32>),
      pub is_composite: bool,
      pub subparts: Vec<Spur>,
      pub ports: Vec<Spur>,
      pub docstring: Option<String>,
  }
  ```
  Multiplicity strings (e.g. `1`, `0..1`, `1..*`) are parsed into exact numeric lower and upper bounds $(l, u)$, where $u = \text{None}$ represents unbounded ($\infty$).
- **Error Diagnostics & Quality Boundaries**:
  Invalid multiplicity strings (e.g. `2..1` where lower bound exceeds upper bound) shall emit `E0107` (Invalid Multiplicity Interval).
- **Acceptance Criteria**:
  - **AC-1**: Structural parts table extracts part definitions with exact multiplicity bounds.
  - **AC-2**: Composite parts correctly register child subpart relationships in the AST hierarchy.
  - **AC-3**: Markdown documentation text in part rows attaches cleanly as docstrings to AST nodes.
