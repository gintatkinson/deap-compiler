### REQ-0058: KerML Core Classifiers: Type, Classifier, DataType, Class, Structure
- **Normative Statement**: The KerML lowering engine shall implement the normative KerML core classifier hierarchy, lowering `Type`, `Classifier`, `DataType`, `Class`, and `Structure` elements. The engine shall enforce classifier subtyping rules and specialization semantics.
- **Formal Semantics & Invariants**:
  The classifier hierarchy enforces:
  $$
  \text{Structure} \le \text{Class} \le \text{Classifier} \le \text{Type}
  $$
  Specialization relation: $C_1 \text{ specializes } C_2$ implies that the instance set of $C_1$ is a subset of the instance set of $C_2$:
  $$
  C_1 \le C_2 \iff \text{Instances}(C_1) \subseteq \text{Instances}(C_2)
  $$
  `DataType` elements represent identity-less value types, whereas `Class` and `Structure` elements represent elements with distinct object identities.
- **Error Diagnostics & Quality Boundaries**:
  Specialization between incompatible classifier kinds (e.g. `DataType` specializing `Class`) shall emit `E0217` (Incompatible Classifier Specialization).
- **Acceptance Criteria**:
  - **AC-1**: Correctly parses and lowers `type`, `classifier`, `datatype`, `class`, and `struct` KerML keywords.
  - **AC-2**: Enforces that data types are value-typed without persistent object identity.
  - **AC-3**: Specialization links correctly establish subtyping relationships in the compiler type lattice.
