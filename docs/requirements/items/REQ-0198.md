### REQ-0198: Bidirectional Reverse-Sync Prose Gate: Tri-State Reconciliation & Prose Protection
- **Normative Statement**: The reverse synchronization engine (`backend::reverse`) shall implement a tri-state reconciliation prose gate (`ExactMatch`, `Renamed`, `NewProseEntity`). The engine shall reject unauthorized prose-only entity creation without schema grounding, protecting the Single Source of Truth from spurious additions.
- **Formal Semantics & Invariants**:
  When parsing an entity $E_{\text{doc}}$ from a modified Markdown document against AST arena $\mathcal{A}$:
  $$
  \text{Classify}(E_{\text{doc}}, \mathcal{A}) = \begin{cases}
  \text{ExactMatch}(n), & \text{if } \exists n \in \mathcal{A} \text{ such that } \text{id}(E_{\text{doc}}) == \text{id}(n) \wedge \text{name}(E_{\text{doc}}) == \text{name}(n) \\
  \text{Renamed}(n), & \text{if } \exists n \in \mathcal{A} \text{ such that } \text{id}(E_{\text{doc}}) == \text{id}(n) \wedge \text{name}(E_{\text{doc}}) \ne \text{name}(n) \\
  \text{NewProseEntity}, & \text{if } \neg \exists n \in \mathcal{A} \text{ such that } \text{id}(E_{\text{doc}}) == \text{id}(n)
  \end{cases}
  $$
  Prose Gate rule: `NewProseEntity` instances are rejected unless explicitly authorized by `--allow-prose-additions` CLI flag.
- **Error Diagnostics & Quality Boundaries**:
  Encountering an unauthorized `NewProseEntity` shall emit compiler error `E0513` (Reverse-Sync Prose Gate Rejection).
- **Acceptance Criteria**:
  - **AC-1**: Correctly identifies renamed features via immutable UUIDv5 anchors without deleting model nodes.
  - **AC-2**: Rejects invented prose entities that lack positive provenance in the source schema.
  - **AC-3**: Inoculates against entity deletion defects caused by pure name-based matching.
