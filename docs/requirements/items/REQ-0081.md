### REQ-0081: SysML v2 TransitionUsage (`transition`) with Triggers, Guards & Effects
- **Normative Statement**: The SysML v2 lowering engine shall lower `transition` usages into `TransitionUsageNode` entities. Transitions shall specify state changes between source and target states, containing trigger events, Boolean guard conditions, and transition effect actions.
- **Formal Semantics & Invariants**:
  A transition $T$ is defined as a tuple:
  $$
  T = (S_{\text{src}}, S_{\text{tgt}}, \text{trigger}, \text{guard}, \text{effect})
  $$
  Transition firing rule: When event `trigger` occurs, if `guard` evaluates to `true`, state machine exits $S_{\text{src}}$, executes `effect`, and enters $S_{\text{tgt}}$.
- **Error Diagnostics & Quality Boundaries**:
  A transition referencing a non-existent source or target state shall emit `E0252` (Invalid Transition State Endpoint).
- **Acceptance Criteria**:
  - **AC-1**: Parses `transition first S_1 accept Event_A if Guard_B do Action_C then S_2;`.
  - **AC-2**: Binds parsed triggers, guard expressions, and effect actions to transition AST nodes.
  - **AC-3**: Supports anonymous initial transitions (`first start then S_1;`).
