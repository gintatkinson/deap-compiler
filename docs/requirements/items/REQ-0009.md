### REQ-0009: Zero-Copy Bump Arena Memory Management
- **Normative Statement**: The compiler front-end and core AST engine shall utilize zero-copy memory management via contiguous bump allocation arenas for all parsed AST nodes, token streams, and intermediate representation graphs. AST node references shall borrow string slices (`&str`) directly from memory-mapped source file buffers.
- **Formal Semantics & Invariants**:
  Let $\mathcal{B}_{\text{file}}$ be a memory-mapped byte buffer of length $L$. An AST string token $T$ is represented as a slice reference:
  $$
  T = \&\mathcal{B}_{\text{file}}[s \dots s+l], \quad \text{where } 0 \le s < s+l \le L
  $$
  All string tokens during AST construction are allocated exclusively within the interner or borrowed from memory-mapped source buffers; node data structures reside exclusively in contiguous memory arenas (`typed-arena` or `bumpalo`).
- **Error Diagnostics & Quality Boundaries**:
  Excessive heap allocation churn or buffer out-of-bounds slicing shall trigger compiler error `E0127` (Arena Allocation Fault).
- **Acceptance Criteria**:
  - **AC-1**: AST parsing of a 10,000-line schema performs zero per-token heap allocations.
  - **AC-2**: Memory profiling confirms AST nodes reside in contiguous memory pages allocated from the arena.
  - **AC-3**: Memory-mapped file buffer lifetimes correctly enclose all borrowed token string slices.
