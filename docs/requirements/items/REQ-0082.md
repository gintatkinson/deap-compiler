### REQ-0082: SysML v2 EntryAction, DoAction & ExitAction State Lifecycle Hooks
- **Normative Statement**: The SysML v2 lowering engine shall lower `entry`, `do`, and `exit` action usages within states into dedicated lifecycle hook nodes on the enclosing `StateDefNode` or `StateUsageNode`.
- **Formal Semantics & Invariants**:
  For state $S$ with entry action $A_{\text{entry}}$, do activity $A_{\text{do}}$, and exit action $A_{\text{exit}}$:
  $$
  t_{\text{entry}} \le t(A_{\text{entry}}) < t(A_{\text{do}}) < t(A_{\text{exit}}) \le t_{\text{exit}}
  $$
  $A_{\text{entry}}$ executes instantaneously upon entering $S$; $A_{\text{do}}$ executes continuously while remaining in $S$; $A_{\text{exit}}$ executes instantaneously prior to departure.
- **Error Diagnostics & Quality Boundaries**:
  Invalid behavioral action definitions inside state lifecycle blocks shall emit `E0253` (Invalid State Lifecycle Action).
- **Acceptance Criteria**:
  - **AC-1**: Parses `entry action A_1;`, `do action A_2;`, and `exit action A_3;` inside state bodies.
  - **AC-2**: Preserves execution ordering semantics across state lifecycle phases.
  - **AC-3**: Emits valid state machine lifecycle representations for code generation.
