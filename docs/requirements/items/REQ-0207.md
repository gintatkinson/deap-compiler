### REQ-0207: Linear-Time Table Parsing & Catastrophic Backtracking Immunity
- **Normative Statement**: The CommonMark table parser shall operate strictly in linear time $O(N)$ with respect to input byte length, enforcing algorithmic immunity against regular expression catastrophic backtracking on deeply nested, unescaped, or pathological table content.
- **Formal Semantics & Invariants**:
  Let $N$ be the input byte count of a table row. The parser's execution time $T(N)$ satisfies:
  $$
  T(N) \le c \cdot N, \quad \text{where } c \text{ is a constant independent of cell content}
  $$
  The lexer operates via an event-driven deterministic state machine (`pulldown-cmark`) with zero backtracking steps.
- **Error Diagnostics & Quality Boundaries**:
  Input rows exceeding linear parsing time limits shall be flagged by the diagnostic sink with `E0101`.
- **Acceptance Criteria**:
  - **AC-1**: Automated test verifies linear execution time on 100,000-character pathological table rows.
  - **AC-2**: Eliminates regular expression backtracking across all table ingestion routines.
  - **AC-3**: Parser processes large tables without stack overflow or thread execution stalls.
