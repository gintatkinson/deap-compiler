### REQ-0054: Tombstone Pruning Engine for Renamed & Orphaned AST Nodes
- **Normative Statement**: The persistence engine shall maintain a centralized manifest of generated artifacts (`CodegenManifest`) and execute automated tombstone pruning (`prune_tombstones`). When a SysML classifier is deleted or renamed, all previously generated artifacts derived from that element shall be cleanly pruned from disk.
- **Formal Semantics & Invariants**:
  Let $\mathcal{A}_{\text{current}}$ be the set of active generated file paths, and $\mathcal{A}_{\text{manifest}}$ be the set recorded in the previous compilation manifest. The set of orphaned artifacts to prune $\mathcal{T}_{\text{prune}}$ satisfies:
  $$
  \mathcal{T}_{\text{prune}} = \mathcal{A}_{\text{manifest}} \setminus \mathcal{A}_{\text{current}}
  $$
  The persistence engine safely unlinks each file $f \in \mathcal{T}_{\text{prune}}$ and removes empty parent directories.
- **Error Diagnostics & Quality Boundaries**:
  Failure to delete an orphaned file due to OS file lock contention shall emit warning `E0233` (Orphaned Artifact Prune Failure).
- **Acceptance Criteria**:
  - **AC-1**: Deleting a part definition from the schema automatically removes its generated feature and ICD markdown files.
  - **AC-2**: Renaming a part generates the new file and cleans up the old file without leaving duplicates.
  - **AC-3**: Manifest cleanly updates to reflect only currently active artifacts.
