### REQ-0014: Synchronization Token Error Recovery Architecture
- **Normative Statement**: All front-end schema and language parsers shall implement synchronization token error recovery. Upon encountering a syntax error, the parser shall emit a rich diagnostic, discard tokens up to the nearest synchronization boundary (e.g. semicolon, closing brace, or record delimiter), and resume parsing to collect all subsequent errors in a single pass.
- **Formal Semantics & Invariants**:
  Let $\mathcal{T}_{\text{sync}}$ be the designated set of synchronization tokens for grammar rule $R$. Upon syntax fault at token $t_k$:
  $$
  \text{SkipUntil}(\mathcal{T}_{\text{sync}}) = \{ t_i \mid k \le i < m, t_m \in \mathcal{T}_{\text{sync}} \}
  $$
  The parser advances to $t_{m+1}$ in parsing state $S_{\text{recovered}}$, accumulating diagnostic $D_k$ into the diagnostic sink:
  $$
  \text{Diagnostics} \leftarrow \text{Diagnostics} \cup \{ D_k \}
  $$
- **Error Diagnostics & Quality Boundaries**:
  Parsers shall accumulate up to a configurable maximum error limit (default 50) before halting further lexical analysis; exceeding parser error limits or cell boundary failures shall emit compiler error `E0106` (Multi-line cell block delimiter or newline integrity violation).
- **Acceptance Criteria**:
  - **AC-1**: Parser detects and reports multiple syntax errors in a single execution without aborting on the first error.
  - **AC-2**: Diagnostic output precisely indicates file name, line, column, and token span for each discovered error.
  - **AC-3**: Clean sections of partially malformed files continue to parse into valid partial AST subgraphs.
