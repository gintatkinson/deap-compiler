### REQ-0166: Feature Projection: 3-Layer Definition of Done Mandatory Structural Enforcement
- **Normative Statement**: The projection engine shall synthesize Features (`docs/features/feat-*.md`) strictly enforcing the 3-Layer Definition of Done: Layer 1 (Domain State & Data Model), Layer 2 (Logic & State Management), and Layer 3 (Presentation & Actuator Interface Binding). Every feature specification shall exhaustively populate each of the three mandatory layers.
- **Formal Semantics & Invariants**:
  Every generated Feature specification must provide concrete content for:
  $$
  \text{Feature}(F) = \text{Layer}_1(F) \cup \text{Layer}_2(F) \cup \text{Layer}_3(F)
  $$
  Where:
  - $\text{Layer}_1$: Data structures, attributes, types, units, and ranges.
  - $\text{Layer}_2$: Algorithms, statecharts, operations, and guard conditions.
  - $\text{Layer}_3$: Visual UI layout, API endpoints, or hardware register bindings.
- **Error Diagnostics & Quality Boundaries**:
  Omitting any of the 3 layers or providing raw `N/A` text shall fail compilation with `E0505` (3-Layer Definition of Done Incomplete).
- **Acceptance Criteria**:
  - **AC-1**: 100% of generated feature specifications fully populate all 3 layers.
  - **AC-2**: Layer 1 details exact attributes, types, bounds, and engineering units.
  - **AC-3**: Layer 2 specifies operations and state machine transitions; Layer 3 specifies concrete interface bindings.
