### REQ-0163: Epics Projection: Structural Decomposition & Subsystem Capability Mapping
- **Normative Statement**: The projection engine shall synthesize Epics (`docs/epics/epic-*.md`) from architectural package boundaries in the AST. Every Epic shall catalog its owned subsystem capabilities (`capability def`), component parts, provided/required interfaces, and a complete checklist of child features.
- **Formal Semantics & Invariants**:
  An Epic $E$ corresponds to an AST `PackageNode` $P$:
  $$
  E = \text{ProjectEpic}(P) = \langle \text{title}, \text{context}, \text{capabilities}, \text{components}, \text{checklist} \rangle
  $$
  Checklist items must link to valid child feature markdown files with semantic justifications.
- **Error Diagnostics & Quality Boundaries**:
  An Epic referencing non-existent child feature files shall emit `E0503` (Dangling Feature Reference in Epic Checklist).
- **Acceptance Criteria**:
  - **AC-1**: Generates 1 Epic per major architectural package subsystem.
  - **AC-2**: Formally allocates all owned `capability def` elements to the Epic.
  - **AC-3**: Tasklist references valid relative markdown links (`../features/feat-*.md`).
