### REQ-0085: SysML v2 AssertConstraintUsage (`assert constraint`) Lowering
- **Normative Statement**: The SysML v2 lowering engine shall lower `assert constraint` usages into `AssertConstraintNode` entities. Assert constraints shall declare non-negotiable safety and operational invariants that must hold at runtime, generating runtime assertions and formal proof obligations.
- **Formal Semantics & Invariants**:
  An `assert constraint` usage binds a constraint expression $P$ to a component context $C$:
  $$
  \text{assert constraint } P \implies \square P \quad (\text{always } P \text{ holds})
  $$
  In contrast to general constraints, `assert constraint` triggers compiler verification obligations and runtime safety monitors.
- **Error Diagnostics & Quality Boundaries**:
  Statically refutable assert constraints (predicates proven false at compile time) shall emit fatal compiler error `E0401` (Statically Refuted Assert Constraint).
- **Acceptance Criteria**:
  - **AC-1**: Parses `assert constraint { val >= 0.0; }` inside part bodies into an `AssertConstraintNode`.
  - **AC-2**: Generates formal verification proof obligations for each assert constraint.
  - **AC-3**: Synthesizes runtime assertion monitor code from assert constraint blocks.
