### REQ-0151: Port Definition Rosters & Hierarchical Port Type Binding
- **Normative Statement**: The ICD engine shall generate exhaustive Port Definition Rosters cataloging every declared port definition, its parent component, port directionality, protocol specification, payload data type, and electrical/logical interface standard.
- **Formal Semantics & Invariants**:
  The port roster indexes all `PortDefNode` and `PortUsageNode` elements:
  $$
  \text{Roster}_{\text{ports}} = \{ (p, \text{owner}(p), \text{dir}(p), \text{type}(p), \text{protocol}(p)) \mid p \in \text{Ports} \}
  $$
- **Error Diagnostics & Quality Boundaries**:
  Duplicate port identifiers within the same component boundary shall emit `E0444` (Duplicate Port Identifier in Component).
- **Acceptance Criteria**:
  - **AC-1**: Catalogs all component boundary ports into a clean structured roster.
  - **AC-2**: Correctly records directionality and payload typing for every port.
  - **AC-3**: Preserves pin mapping and hardware register offset metadata.
