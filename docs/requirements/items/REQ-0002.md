### REQ-0002: Bijective Lexical Provenance Gate & Positive AST Provenance
- **Normative Statement**: The compiler shall enforce a bijective lexical provenance gate across all synthesized AST elements. Every generated classifier, port, connector, attribute, constraint, and action identifier must establish a verifiable derivation link back to a corresponding AST node within the parsed schema source files.
- **Formal Semantics & Invariants**:
  Let $\text{Nodes}(\mathcal{A})$ be the set of nodes in synthesized AST $\mathcal{A}$, and $\text{ASTNodes}(\mathcal{S})$ be the set of parsed schema source nodes. The provenance function $\Pi : \text{Nodes}(\mathcal{A}) \longrightarrow \text{ASTNodes}(\mathcal{S})$ satisfies:
  $$
  \forall n \in \text{Nodes}(\mathcal{A}), \quad \exists s \in \text{ASTNodes}(\mathcal{S}) \quad \text{such that} \quad \Pi(n) = s
  $$
  Each node $n$ retains an immutable provenance descriptor:
  ```rust
  pub struct ProvenanceRecord {
      pub source_file: std::path::PathBuf,
      pub span_start: usize,
      pub span_end: usize,
      pub source_token_hash: u64,
  }
  ```
  The compiler validates that $\Pi$ is surjective across all structural definitions in $\mathcal{A}$.
- **Error Diagnostics & Quality Boundaries**:
  Discovery of an AST node lacking an origin in $\text{ASTNodes}(\mathcal{S})$ shall halt compilation and emit `E0120` (Lexical Provenance Resolution Failure).
- **Acceptance Criteria**:
  - **AC-1**: Every synthesized `ClassifierDefNode` retains a valid `ProvenanceRecord` containing line and column offsets in the source schema.
  - **AC-2**: Automated audit verifies 100% of generated model elements possess valid source provenance.
  - **AC-3**: Re-parsing the schema preserves identical provenance mappings across repeated compilation passes.
