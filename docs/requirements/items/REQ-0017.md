### REQ-0017: Synchronization Token Recovery on Table Delimiter Boundaries
- **Normative Statement**: The CommonMark table parser shall implement synchronization token recovery on table delimiter boundaries (`|`, `
`). When a cell contains unexpected formatting or malformed data, the parser shall record the diagnostic and resynchronize at the next pipe delimiter or newline boundary.
- **Formal Semantics & Invariants**:
  Let $C_j$ be cell $j$ in row $R_i$. If lexical parsing of $C_j$ fails:
  $$
  \text{State} \leftarrow \text{RecoverToNextDelimiter}(\text{\'|\'}, \text{\'\\n\'})
  $$
  The parser increments the error counter, retains valid cells $C_1, \dots, C_{j-1}$, and resumes analysis at $C_{j+1}$.
- **Error Diagnostics & Quality Boundaries**:
  A malformed cell emits `E0102` (Table Cell Token Error) while preserving the remainder of the table row.
- **Acceptance Criteria**:
  - **AC-1**: A corrupted table row with missing delimiters does not abort parsing of subsequent valid table rows.
  - **AC-2**: Diagnostic message specifies the exact row index and column header where the delimiter error occurred.
  - **AC-3**: Valid entries in partially corrupted tables are successfully ingested into the intermediate representation.
