### REQ-0055: KerML Root, Element, Relationship & Annotation Abstract Syntax
- **Normative Statement**: The KerML lowering engine shall implement the normative KerML Kernel abstract syntax root hierarchy, modeling every syntactic construct as an `Element` with support for directed `Relationship`s, owned elements, and attached `Annotation`s.
- **Formal Semantics & Invariants**:
  Every metamodel node derives from the base `Element` trait:
  ```rust
  pub trait KerMlElement {
      fn element_id(&self) -> NodeId;
      fn owner(&self) -> Option<NodeId>;
      fn owned_elements(&self) -> &[NodeId];
      fn documentation(&self) -> Option<Spur>;
  }
  ```
  Directed relationship invariant: For any relationship $R$, there exist defined non-empty source set $\text{source}(R)$ and target set $\text{target}(R)$ within the AST arena.
- **Error Diagnostics & Quality Boundaries**:
  A relationship element missing source or target references shall emit compiler error `E0200` (Dangling Relationship Endpoints).
- **Acceptance Criteria**:
  - **AC-1**: All parsed KerML model elements instantiate types implementing the `KerMlElement` trait.
  - **AC-2**: Comments, notes, and documentation strings lower cleanly into `Annotation` nodes.
  - **AC-3**: Relationship graphs preserve source-to-target directionality across lowering passes.
