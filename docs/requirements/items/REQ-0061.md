### REQ-0061: KerML Core Features: Feature, Parameter, Step & FeatureTyping Semantics
- **Normative Statement**: The KerML lowering engine shall implement normative KerML `Feature` elements, including `Parameter` and `Step`. Features shall represent typed structural and behavioral properties owned by classifiers, bound via explicit `FeatureTyping` relationships.
- **Formal Semantics & Invariants**:
  A `Feature` $f$ has a declared type $T$ via `FeatureTyping`:
  $$
  \text{type}(f) = T \in \text{Type}
  $$
  Feature multiplicity is represented as an interval $[m_{\min} \dots m_{\max}]$ where $m_{\min} \in \mathbb{N}_0$ and $m_{\max} \in \mathbb{N}_0 \cup \{ \infty \}$.
  Features inherit typing, multiplicity, and constraints from specialized parent features.
- **Error Diagnostics & Quality Boundaries**:
  A feature declared with an undefined type shall emit compiler error `E0204` (Untyped Feature Usage).
- **Acceptance Criteria**:
  - **AC-1**: Features, parameters, and steps lower into strongly-typed AST nodes.
  - **AC-2**: Multiplicity intervals parse and validate correctly for all features.
  - **AC-3**: Directional parameters (`in`, `out`, `inout`) retain direction metadata on feature nodes.
