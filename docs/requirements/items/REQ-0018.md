### REQ-0018: Dynamic Semantic Header Key Normalization & Order-Independent Binding
- **Normative Statement**: The table ingestion engine shall implement dynamic semantic header key normalization (`readers/markdown.rs`). The parser shall match column headers in an order-independent manner by normalizing header strings (case folding, trimming punctuation, stripping stop-words) to bind schema attributes dynamically to table columns.
- **Formal Semantics & Invariants**:
  Let $H$ be a raw column header string. The normalization function $\eta(H)$ is defined as:
  $$
  \eta(H) = \text{Lowercase}(\text{StripPunctuation}(\text{Trim}(H)))
  $$
  The column-to-field binding $\beta$ maps $\eta(H)$ against a dictionary of canonical attribute keys $\mathcal{K}_{\text{canonical}}$:
  $$
  \beta(H) = k \in \mathcal{K}_{\text{canonical}} \iff \eta(H) \in \text{Aliases}(k)
  $$
  Column ordering in the source Markdown file is arbitrary; bindings resolve dynamically based on semantic aliases.
- **Error Diagnostics & Quality Boundaries**:
  Missing mandatory table columns (e.g. absent `Identifier` or `Name` header) shall emit compiler error `E0103` (Missing Mandatory Table Header).
- **Acceptance Criteria**:
  - **AC-1**: Tables with columns in arbitrary orders (e.g. `[Name, Type, Description]` vs `[Type, Description, Name]`) parse identically.
  - **AC-2**: Variations such as `Part Name`, `part_name`, `Part-Name`, and `Name` all map cleanly to canonical `name`.
  - **AC-3**: Header binding failure clearly lists missing mandatory columns and discovered header aliases.
