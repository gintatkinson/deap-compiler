### REQ-0063: KerML Redefinition Relationship (`:>>`) Lowering & Type Conformance
- **Normative Statement**: The KerML lowering engine shall implement KerML feature redefinition (`:>>`). Redefinition shall replace an inherited feature in a specialized context, enforcing strict subtyping conformance, multiplicity compatibility, and semantic consistency.
- **Formal Semantics & Invariants**:
  Let $f_{\text{redef}}$ redefine inherited feature $f_{\text{orig}}$ ($f_{\text{redef}} :>> f_{\text{orig}}$). The redefinition invariant satisfies:
  $$
  \text{Values}(o, f_{\text{redef}}) \equiv \text{Values}(o, f_{\text{orig}}) \quad \text{in context } C_{\text{specialized}}
  $$
  Type conformance: $\text{type}(f_{\text{redef}}) \le \text{type}(f_{\text{orig}})$.
  Multiplicity conformance: $[l_{\text{redef}}, u_{\text{redef}}] \subseteq [l_{\text{orig}}, u_{\text{orig}}]$.
- **Error Diagnostics & Quality Boundaries**:
  Attempting to redefine a non-existent feature or widening the type shall emit `E0221` (Invalid Feature Redefinition).
- **Acceptance Criteria**:
  - **AC-1**: Parses `:>>` redefinition syntax cleanly into AST redefinition links.
  - **AC-2**: Rejects redefinitions where the redefined type does not specialize the original type.
  - **AC-3**: In inherited scopes, accesses to the original feature resolve to the redefined feature.
