### REQ-0160: Worst-Case Execution Time (WCET) Propagation across Interconnect Latency Paths
- **Normative Statement**: The ICD engine shall propagate Worst-Case Execution Times (WCET) and transport latencies along end-to-end signal communication paths, asserting that total end-to-end latency does not exceed the maximum allowable response deadline.
- **Formal Semantics & Invariants**:
  Let a signal path traverse sensor sensing ($t_{\text{sense}}$), controller compute ($t_{\text{compute}}$), bus transmission ($t_{\text{transport}}$), and actuator response ($t_{\text{actuate}}$):
  $$
  t_{\text{end\_to\_end}} = t_{\text{sense}} + t_{\text{compute}} + t_{\text{transport}} + t_{\text{actuate}}
  $$
  Deadline verification: $t_{\text{end\_to\_end}} \le T_{\text{deadline}}$.
- **Error Diagnostics & Quality Boundaries**:
  An end-to-end latency calculation exceeding the specified deadline shall emit `E0451` (End-to-End Latency Deadline Miss).
- **Acceptance Criteria**:
  - **AC-1**: Computes worst-case latency across multi-hop communication paths.
  - **AC-2**: Compares end-to-end latency against requirement timing deadlines.
  - **AC-3**: Highlights latency bottleneck components in timing analysis reports.
