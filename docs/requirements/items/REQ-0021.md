### REQ-0021: Disambiguation of Array-Indexed Entity Identifiers (`Identifier[1]` vs `Identifier[2]`)
- **Normative Statement**: The ingestion engine shall disambiguate array-indexed entity identifiers (e.g. `Sensor[1]`, `Sensor[2]`) into distinct, syntactically valid SysML v2 identifiers (`Sensor_1`, `Sensor_2`) while recording their array index semantics in intermediate structural properties.
- **Formal Semantics & Invariants**:
  Let $S$ be an identifier matching regex `^([A-Za-z_][A-Za-z0-9_]*)\[([0-9]+)\]$`. The disambiguation operator $\theta_{\text{array}}$ decomposes $S$ into:
  $$
  \theta_{\text{array}}(S) = (\text{base}, \text{index}) \implies \text{identifier} = \text{format!}("{}_{}", \text{base}, \text{index})
  $$
  The entity records array metadata: `multiplicity_index: Some(index)`. Identifiers without brackets receive `multiplicity_index: None`.
- **Error Diagnostics & Quality Boundaries**:
  Duplicate array indices for the same base identifier within a single namespace shall emit `E0106` (Duplicate Array Index Declaration).
- **Acceptance Criteria**:
  - **AC-1**: Table entries `Port_A[1]` and `Port_A[2]` generate distinct AST nodes `Port_A_1` and `Port_A_2`.
  - **AC-2**: Generated SysML model includes multiplicity annotations reflecting array instance indices.
  - **AC-3**: Duplicate entries with identical indices trigger immediate compiler error diagnostics.
