### REQ-0178: LUMI IR Memory Semantics: Typed Allocations, Immutability & Value Semantics
- **Normative Statement**: LUMI IR shall enforce strict value semantics and typed memory allocations. Variable references shall be immutable by default; mutable state shall be explicitly encapsulated in typed state slots with bounded execution lifetimes.
- **Formal Semantics & Invariants**:
  Every LUMI IR value possesses a concrete scalar or compound type:
  $$
  \tau \in \{ \text{Bool}, \text{I32}, \text{I64}, \text{F32}, \text{F64}, \text{Struct}(\dots), \text{Array}(\tau, N) \}
  $$
  All memory allocations in core execution blocks occur exclusively via static global buffers or stack frames.
- **Error Diagnostics & Quality Boundaries**:
  Type mismatch in LUMI IR instruction operands shall emit compiler error `E0502` (LUMI IR Type Incoherence).
- **Acceptance Criteria**:
  - **AC-1**: LUMI IR enforces zero-heap-allocation memory semantics in generated execution paths.
  - **AC-2**: All memory operations are strongly typed and statically verified.
  - **AC-3**: Constant values are folded and propagated across basic blocks.
