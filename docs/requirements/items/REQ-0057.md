### REQ-0057: KerML Import Declaration Semantics (Public, Private, All, Filtered)
- **Normative Statement**: The KerML lowering engine shall implement the normative import semantics specified in KerML Clause 8.2. Imports shall support public (`public import`) and private (`private import`) visibilities, wildcard imports (`::*`), recursive subtree imports (`::**`), and filtered member imports.
- **Formal Semantics & Invariants**:
  Let $N_{\text{importer}}$ import namespace $N_{\text{imported}}$ with visibility $V \in \{ \text{Public}, \text{Private} \}$. The imported membership set $\mathcal{M}_{\text{imp}}$ satisfies:
  $$
  \mathcal{M}_{\text{imp}} = \{ m \in \text{memberships}(N_{\text{imported}}) \mid \text{MatchesFilter}(m, \text{filter}) \wedge \text{IsExportable}(m) \}
  $$
  If $V = \text{Public}$, imported members are re-exported and visible to downstream importers of $N_{\text{importer}}$.
- **Error Diagnostics & Quality Boundaries**:
  Attempting to import from a non-existent namespace shall emit `E0216` (Import Target Namespace Not Found).
- **Acceptance Criteria**:
  - **AC-1**: Wildcard imports (`import P::*`) make all public members of `P` accessible in local scope.
  - **AC-2**: Private imports are not re-exported across multi-file package boundaries.
  - **AC-3**: Recursive imports (`import P::**`) bring nested subpackages into visible scope.
