### REQ-0089: SysML v2 ViewDefinition (`view def`), ViewUsage & Viewpoint Lowering
- **Normative Statement**: The SysML v2 lowering engine shall lower `view def`, `view`, `viewpoint def`, and `viewpoint` usages into `ViewDefNode` and `ViewpointDefNode` entities. Views shall define structured queries and projections over the AST model graph according to stakeholder concerns.
- **Formal Semantics & Invariants**:
  A `viewpoint` specifies stakeholder concerns and model filter criteria. A `view` conforms to a viewpoint and defines an `expose` set:
  $$
  \text{view } V \text{ satisfies } VP \{ \text{expose } P_1, P_2; \}
  $$
- **Error Diagnostics & Quality Boundaries**:
  A view conforming to an undefined viewpoint shall emit `E0254` (Undefined Viewpoint Reference).
- **Acceptance Criteria**:
  - **AC-1**: Parses `viewpoint def ArchitectureViewpoint { ... }` into a viewpoint node.
  - **AC-2**: Parses `view SystemView : ArchitectureViewpoint { ... }` into a view node.
  - **AC-3**: Validates view conformance against declared viewpoint rules.
