### REQ-0019: Multi-Line Table Cell Block Token Preservation & Normalization
- **Normative Statement**: The table ingestion engine shall preserve multi-line cell content, nested bullet points, and code spans within table cells without dropping formatting or truncating text. Embedded newlines (`<br>`, `
`) shall be normalized into canonical whitespace-delimited block tokens.
- **Formal Semantics & Invariants**:
  Let $C_{\text{raw}}$ be the raw cell string containing HTML break tags or escaped linefeeds. The block normalizer $\Phi_{\text{block}}$ satisfies:
  $$
  \Phi_{\text{block}}(C_{\text{raw}}) = \text{ReplaceAll}(C_{\text{raw}}, \text{"<br\\s*/?>"}, \text{"\\n"})
  $$
  Nested list items inside cells are parsed into an ordered sequence of sub-item tokens:
  ```rust
  pub struct CellBlock {
      pub text: String,
      pub bullet_items: Vec<String>,
      pub code_spans: Vec<String>,
  }
  ```
- **Error Diagnostics & Quality Boundaries**:
  Unterminated code spans or malformed HTML tags inside table cells shall emit warning `E0104` (Malformed Cell Block Formatting).
- **Acceptance Criteria**:
  - **AC-1**: Multi-line descriptions containing `<br>` tags parse into multi-line docstrings without text loss.
  - **AC-2**: Bullet points inside table cells are preserved and extracted as distinct sub-item tokens.
  - **AC-3**: Code spans (`` `param_x` ``) inside cells retain backtick framing and identifier purity.
