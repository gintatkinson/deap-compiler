### REQ-0034: Multi-File Cryptographic Digest Computation (`.pipeline/schema-digest.json`)
- **Normative Statement**: The ingestion engine shall compute a multi-file cryptographic manifest (`digest.rs`) recording SHA-256 content hashes, byte sizes, line counts, and AST entity counts for all input schema files and the emitted `schema/model.sysml`. The manifest shall be written atomically to `.pipeline/schema-digest.json`.
- **Formal Semantics & Invariants**:
  The digest manifest contains an entry for every input file $F_i$:
  $$
  \text{Digest}(F_i) = \{ \text{path}: P_i, \text{sha256}: \text{Hex}(\text{SHA256}(F_i)), \text{bytes}: |F_i|, \text{nodes}: N_i \}
  $$
  The manifest also records the aggregate composite hash:
  $$
  \text{CompositeHash} = \text{SHA256}\left( \bigoplus_{i=1}^M \text{Digest}(F_i) \right)
  $$
- **Error Diagnostics & Quality Boundaries**:
  IO errors or serialization failures during digest creation shall emit `E0131` (Digest Manifest Creation Failure).
- **Acceptance Criteria**:
  - **AC-1**: Generates `.pipeline/schema-digest.json` containing hashes for all input schemas and output model.
  - **AC-2**: Structural node counts in the manifest accurately reflect ingested entities.
  - **AC-3**: File hash mismatch detects external modifications to input schemas instantly.
