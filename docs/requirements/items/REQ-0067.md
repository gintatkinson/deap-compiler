### REQ-0067: KerML Functions: Function, Parameter Directions & Return Typing
- **Normative Statement**: The KerML lowering engine shall implement KerML `Function` classifiers. Functions shall declare input parameters (`in`), output parameters (`out`), and return types, modeling pure mathematical transformations with zero side effects.
- **Formal Semantics & Invariants**:
  A `Function` $F$ maps input parameters $x_1: T_1, \dots, x_k: T_k$ to result $y: T_{\text{result}}$:
  $$
  F : T_1 \times \dots \times T_k \longrightarrow T_{\text{result}}
  $$
  Purity invariant: KerML functions are referentially transparent; invoking $F$ with identical arguments yields identical results.
- **Error Diagnostics & Quality Boundaries**:
  A function lacking an explicit or inferred return type shall emit `E0225` (Missing Function Return Type).
- **Acceptance Criteria**:
  - **AC-1**: Parses KerML `function` definitions with parameter lists and return types.
  - **AC-2**: Validates that function bodies return expressions matching the declared return type.
  - **AC-3**: Enforces referential transparency during constant folding and symbolic evaluation.
