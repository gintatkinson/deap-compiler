### REQ-0176: Bidirectional Specification Realization Matrix Synthesis & Markdown Tasklists
- **Normative Statement**: The projection engine shall synthesize bidirectional realization matrices and interactive Markdown tasklists linking Epics to Features, Features to User Stories, and User Stories to Use Cases. Checklist items shall resolve live tracker issue identifiers or maintain explicit placeholders with semantic justifications.
- **Formal Semantics & Invariants**:
  The realization matrix establishes a bipartite mapping:
  $$
  \mathbf{R} \in \{0, 1\}^{|\text{Specs}| \times |\text{ASTNodes}|}, \quad R_{ij} = 1 \iff \text{Spec}_i \text{ realizes } \text{Node}_j
  $$
  Checklist lines adhere strictly to the format:
  `- [ ] #[IssueID] - [Title](../relative/path.md) (semantic linkage justification)`
- **Error Diagnostics & Quality Boundaries**:
  Checklist items missing semantic justifications or containing unescaped raw IDs shall emit `E0510` (Malformed Realization Checklist Entry).
- **Acceptance Criteria**:
  - **AC-1**: Generates realization matrix tables in all parent specification documents.
  - **AC-2**: Checklist items contain canonical relative links and concise semantic justifications.
  - **AC-3**: Retains literal `#[IssueID]` placeholders until tracker registration.
