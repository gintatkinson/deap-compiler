### REQ-0128: State Machine Simulation Stepper & Trace Log Generation
- **Normative Statement**: The compiler core shall provide a deterministic state machine simulation stepper (`crates/deap-core`) that executes statecharts step-by-step against simulated event traces, producing structured JSON execution logs detailing state entries, exits, guard evaluations, and action executions.
- **Formal Semantics & Invariants**:
  Given initial configuration $C_0$ and event sequence $\vec{e} = \langle e_1, \dots, e_m \rangle$, the stepper computes:
  $$
  \text{Trace}(\vec{e}) = \langle (C_0, e_1, C_1, A_1), (C_1, e_2, C_2, A_2), \dots, (C_{m-1}, e_m, C_m, A_m) \rangle
  $$
  Simulation execution is completely deterministic and reproducible across repeated runs.
- **Error Diagnostics & Quality Boundaries**:
  Unhandled event errors during strict simulation runs shall be recorded in the trace log with diagnostic `E0260`.
- **Acceptance Criteria**:
  - **AC-1**: Simulates state machine execution against input event vectors without native compilation.
  - **AC-2**: Emits detailed step-by-step trace logs recording all active state changes.
  - **AC-3**: Execution traces validate statechart logic before code emission.
