### REQ-0191: Atomic In-Place File Overwrite & APFS/NTFS Metadata Lock Serialization Prevention
- **Normative Statement**: The file persistence engine shall perform atomic in-place file overwrites when updating changed artifacts, completely bypassing temporary sibling file creation (`.tmp_{uuid}`) and `fs::rename` syscall storms that cause parent directory VFS metadata lock serialization on APFS and NTFS filesystems.
- **Formal Semantics & Invariants**:
  For an existing file at path $P$ whose content has changed:
  $$
  \text{UpdateFile}(P, B_{\text{new}}) = \text{OpenWithFlags}(P, \text{O\_WRONLY} | \text{O\_TRUNC}).\text{write\_all}(B_{\text{new}})
  $$
  Direct file rewriting maintains inode stability and avoids parent directory locks during parallel Rayon emission.
- **Error Diagnostics & Quality Boundaries**:
  File open or write permission errors during in-place overwrite shall emit `E0512` (In-Place File Overwrite Failure).
- **Acceptance Criteria**:
  - **AC-1**: Overwrites changed files directly in-place without generating temporary sibling files.
  - **AC-2**: Eliminates parent directory metadata lock contention during parallel file emission.
  - **AC-3**: Demonstrates verified 3x throughput improvement on multi-thousand-file generation benchmarks.
