### REQ-0175: Use Cases Projection: Alternate Flows & Exception Handler Branching
- **Normative Statement**: Every generated Use Case shall specify Alternate Flows (valid secondary operational pathways) and Exception Flows (fault handling, emergency safing, and recovery pathways) branching from specific primary flow step indices.
- **Formal Semantics & Invariants**:
  An alternate or exception branch $B$ branches from primary step index $k$:
  $$
  B = \langle \text{branch\_step}: k, \text{condition}: \text{GuardExpr}, \text{steps}: \langle b_1, \dots, b_m \rangle, \text{rejoin\_step}: \text{Option}<\text{usize}> \rangle
  $$
  Exception flows must terminate in a designated safe system state.
- **Error Diagnostics & Quality Boundaries**:
  An exception flow lacking a defined terminal safe state shall emit `E0405` (Missing Failsafe Fallback Transition).
- **Acceptance Criteria**:
  - **AC-1**: Generates alternate flows for non-nominal operational branches.
  - **AC-2**: Details exception handling sequences for communication loss and sensor faults.
  - **AC-3**: Verifies that exception sequences return to safe or initial states.
