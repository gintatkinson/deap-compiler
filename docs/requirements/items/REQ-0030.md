### REQ-0030: OpenAPI (JSON/YAML) Schema Ingestion for Paths, Operations & Payloads
- **Normative Statement**: The ingestion engine shall provide an OpenAPI parser (`readers/openapi.rs`) that parses OpenAPI 3.0/3.1 specifications (in JSON or YAML format) into intermediate schema IR. The parser shall map schema component objects to parts/data types, API paths to interface endpoints, and HTTP operations (GET, POST) to actions with request/response payload schemas.
- **Formal Semantics & Invariants**:
  Let $\mathcal{O}$ be an OpenAPI document. The mapping $\mathcal{T}_{\text{openapi}}$ satisfies:
  $$
  \begin{aligned}
  \text{components/schemas/}S &\longmapsto \text{IngestedPart}(S) \\
  \text{paths/}P/\text{get} &\longmapsto \text{IngestedAction}(\text{format!}("{}_{}", \text{"get"}, P))
  \end{aligned}
  $$
- **Error Diagnostics & Quality Boundaries**:
  Schema validation failures in OpenAPI documents shall emit `E0115` (OpenAPI Ingestion Error).
- **Acceptance Criteria**:
  - **AC-1**: Ingests JSON and YAML OpenAPI specifications without manual pre-processing.
  - **AC-2**: Extracts request body schemas and response status code schemas into typed AST entities.
  - **AC-3**: Preserves parameter query and path constraints (ranges, regex patterns) in generated attributes.
