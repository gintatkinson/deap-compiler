### REQ-0206: 4-Pass Semantic Parity Verification Framework (Frontmatter, Graph, Tables, Float Deltas)
- **Normative Statement**: The compiler platform shall provide a 4-Pass Semantic Parity Verification Framework (`parity_auditor`) that replaces fragile byte-for-byte diff comparisons with semantic equivalence checks across YAML frontmatter keys, Mermaid graph topology isomorphism, Markdown table cells, and floating-point tolerances.
- **Formal Semantics & Invariants**:
  The 4-pass verification pipeline asserts:
  $$
  \Phi(\text{Doc}_A, \text{Doc}_B) = \Phi_{\text{YAML}} \wedge \Phi_{\text{Mermaid}} \wedge \Phi_{\text{Table}} \wedge \Phi_{\text{Float}}
  $$
  Where:
  - $\Phi_{\text{YAML}}$: Frontmatter key-value equivalence independent of key ordering.
  - $\Phi_{\text{Mermaid}}$: Directed graph isomorphism $G_A \cong G_B$ ignoring styling and whitespace.
  - $\Phi_{\text{Table}}$: Cell-by-cell equivalence ignoring table column padding.
  - $\Phi_{\text{Float}}$: Relative floating-point tolerance check: $\frac{|v_A - v_B|}{\max(|v_A|, |v_B|)} < 10^{-6}$.
- **Error Diagnostics & Quality Boundaries**:
  Semantic divergence exceeding tolerance thresholds shall fail validation with detailed diff traces and emit compiler error `E0512` (Regression test suite invariant violation).
- **Acceptance Criteria**:
  - **AC-1**: 4-pass parity framework evaluates document equivalence semantically.
  - **AC-2**: Immune to trivial formatting discrepancies (whitespace, table column widths, key order).
  - **AC-3**: Accurately detects true semantic alterations in architecture or constraints.
