### REQ-0013: Bounded Work-Stealing Parallelism (`rayon`) Thread Isolation
- **Normative Statement**: All multi-threaded graph traversals, combinatorial safety calculations, and parallel artifact code generation shall execute through bounded work-stealing thread pools using `rayon`. All concurrent task execution shall remain strictly bounded within the configured worker thread pool.
- **Formal Semantics & Invariants**:
  Let $P$ denote the global or local `rayon::ThreadPool` initialized with thread count $N_{\text{threads}} = \min(C_{\text{logical}}, N_{\text{max\_workers}})$. All concurrent operations satisfy:
  $$
  \text{ActiveThreads}(t) \le N_{\text{threads}}, \quad \forall t \ge 0
  $$
  Workloads are partitioned into data-parallel iterators (`par_iter`) with adaptive chunk sizing to prevent thread starvation and scheduling overhead.
- **Error Diagnostics & Quality Boundaries**:
  Worker thread exhaustion or deadlock during parallel computation shall emit `E0130` (Thread Pool Execution Timeout).
- **Acceptance Criteria**:
  - **AC-1**: Multi-threaded AST graph traversals execute within a bounded `rayon` thread pool without spawning raw OS threads.
  - **AC-2**: Setting `--threads N` via CLI strictly constrains active worker count to $N$.
  - **AC-3**: Parallel execution scales linearly across available CPU cores on large multi-subsystem schemas.
