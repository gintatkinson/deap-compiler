### REQ-0169: User Stories Projection: Deterministic Gherkin BDD Synthesis from AST Constraints

- **Normative Statement**: The downstream specification projection engine, User Story synthesizer, and formal constraint translation framework of Subsystem 9 shall synthesize User Story specifications with deterministic Gherkin Given-When-Then behavior-driven development (BDD) scenarios derived directly from abstract syntax tree (AST) constraint blocks, action pre/post-conditions, statechart transition guards and effects, operational range envelopes, and formal invariant assertions, eliminating manual narrative drift across downstream specification artifacts. Every synthesized User Story specification shall bind bijectively to an owning Feature classifier, and every synthesized Gherkin scenario shall bind bijectively to an underlying AST constraint node identifier, recording exact source-mapped lexical provenance spans and deterministic RFC 4122 UUIDv5 identification anchors. If any AST constraint expression contains ungrounded variable references, malformed operator expressions, unsynthesizable tripartite clauses, untraced scenario linkages, or colliding scenario identifiers, the compiler shall fail closed and emit diagnostic error code `E0500`.

  Specifically, the downstream projection engine, User Story synthesizer, and Gherkin scenario emitter shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Hierarchical Specification Scope & User Story Organization**:
     - The compiler shall partition downstream specification artifacts along the structural decomposition hierarchy established in REQ-0160 and REQ-0161: Epics decompose into Features, and Features decompose into User Stories containing formal Gherkin scenarios.
     - For every feature classifier $F \in \mathcal{F}_{\text{proj}}$ projected from the sovereign AST compilation unit, the engine shall construct a set of User Story specifications $\mathcal{U}(F)$ encapsulating the functional requirements, operational capabilities, and behavioral contracts of feature $F$.
     - Each User Story specification $U \in \mathcal{U}(F)$ shall define a standard agile narrative preamble formatted in plain text:
       * `As a <Role>`: interned stakeholder, system operator, or communicating actor handle;
       * `I want <Capability>`: interned functional behavior, operation invocation, or capability handle;
       * `So that <Benefit>`: interned operational goal, constraint satisfaction, or mission objective.
  2. **AST Constraint Extraction & Semantic Classification**:
     - The synthesizer shall traverse the AST feature definition and exhaustively extract all formal constraint blocks, operational envelopes, and behavioral assertions into an ordered constraint set $\mathcal{C}(F) \subset \mathcal{V}_{\text{AST}}$, classified across five canonical constraint origins:
       * *Action Pre/Post-Condition Contracts*: Preconditions (`pre`) and postconditions (`post`) declared on SysML v2 `action def` and KerML behavior steps in accordance with REQ-0060, REQ-0066, and REQ-0078;
       * *Behavioral Invariant Assertions*: Global and local invariant expressions declared via SysML v2 `assert constraint` usages in accordance with REQ-0083 and REQ-0084;
       * *State Machine Transitions*: Guard conditions (`guard`), event triggers (`trigger`), and effect behaviors (`effect`) declared on statechart transitions in accordance with REQ-0080, REQ-0120, and REQ-0122;
       * *Parametric Operational Envelopes*: Lower and upper boundary interval assertions $[v_{\min}, v_{\max}]$ declared on domain state attributes in accordance with REQ-0112, REQ-0113, and REQ-0165;
       * *Safety Invariant Contracts*: Synthesized boolean safety invariants and control barrier assertions synthesized from STPA hazard analyses in accordance with REQ-0137, REQ-0138, and REQ-0143.
     - No declared constraint, precondition, postcondition, or invariant assertion within feature $F$ shall be elided from Gherkin scenario synthesis.
  3. **Canonical Gherkin Tripartite Translation Contract**:
     - Every extracted AST constraint $c \in \mathcal{C}(F)$ shall be mapped via syntax-directed translation into a deterministic tripartite Gherkin scenario:
       $$S = \langle \text{Given}(P_{\text{pre}}), \text{When}(A_{\text{action}}), \text{Then}(Q_{\text{post}}) \rangle$$
     - The tripartite clauses shall map directly to the model state vector transition $\sigma \xrightarrow{A_{\text{action}}} \sigma'$:
       * `Given`: Establishes the initial state vector predicate $P_{\text{pre}}(\sigma)$, asserting precondition satisfaction, attribute initialization within operational range $[v_{\min}, v_{\max}]$, and active source state configuration;
       * `When`: Formulates the operational stimulus or action invocation $A_{\text{action}}$, asserting the execution of an action step, receipt of an input message payload, or dispatch of a statechart transition trigger event;
       * `Then`: Asserts the post-condition contract $Q_{\text{post}}(\sigma')$, asserting the post-state predicate, output port payload emission, statechart landing state arrival, and invariant preservation over the updated state vector $\sigma'$.
     - The translation shall satisfy the formal logical entailment:
       $$\forall \sigma \in \Sigma, \quad P_{\text{pre}}(\sigma) \land \text{Exec}(A_{\text{action}}, \sigma, \sigma') \implies Q_{\text{post}}(\sigma')$$
  4. **Compound Predicates & Multi-Clause Conjunctions**:
     - Where an AST constraint block specifies conjunctive preconditions ($P_1 \land P_2 \land \dots \land P_m$), the Gherkin scenario shall format the leading clause as `Given <P_1>` followed by sequential `And <P_i>` clauses ($i = 2, \dots, m$).
     - Where an operational stimulus comprises composite or sequenced actions ($A_1 ; A_2$), the scenario shall format sequential `When <A_1>` and `And <A_2>` clauses.
     - Where a postcondition specifies multiple asserted guarantees ($Q_1 \land Q_2 \land \dots \land Q_k$), the scenario shall format sequential `Then <Q_1>` followed by `And <Q_j>` clauses ($j = 2, \dots, k$).
     - Negative conditions and exclusion predicates ($\neg P$) shall be synthesized using the Gherkin `But` clause to maintain human readability and clear semantic distinction from positive assertions.
  5. **Bijective Traceability & Bidirectional Linkage Invariant**:
     - The projection engine shall establish a strict bijective linkage between the set of synthesized Gherkin scenarios $\mathbf{S}_{\text{synthesized}}$ and the set of source AST constraint nodes $\mathcal{C}_{\text{AST}}$:
       $$\tau_{\text{trace}} : \mathbf{S}_{\text{synthesized}} \longleftrightarrow \mathcal{C}_{\text{AST}}$$
     - Every synthesized scenario $S$ must store the exact 32-bit arena node handle of its generating AST constraint ($c_S \in \mathcal{V}_{\text{AST}}$) and the handle of its owning Feature ($F_S \in \mathcal{V}_{\text{AST}}$).
     - Every synthesized scenario must retain exact source-mapped lexical provenance $\text{span}_S = \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle$ corresponding to the source constraint declaration.
     - If any scenario is emitted without a valid AST constraint node handle, or if an AST constraint fails to produce a corresponding Gherkin scenario, the compiler shall fail closed and emit diagnostic error code `E0500` (`UntracedScenarioViolation`).
  6. **Deterministic Output Formatting & Lexicographical Ordering**:
     - Emitted User Story specifications shall adhere strictly to canonical Gherkin syntax without narrative variation:
       * User Story titles shall be formatted as `Feature: <Interned Feature Title> - <User Story Title>`;
       * Each scenario shall begin with `Scenario: <Scenario Title>`;
       * Clause indentation shall be fixed at two ASCII spaces for `Given`, `When`, `Then`, `And`, and `But` keywords;
       * Variable placeholders within scenarios shall be rendered using plain-text parameter syntax without unescaped math delimiters.
     - Within each User Story specification, constituent scenarios shall be sorted deterministically in ascending lexicographical order by interned constraint symbol identifier and qualified name (REQ-0032), guaranteeing 0-byte diff churn across repeated compilation runs (REQ-0003).
     - Emitted Markdown and Gherkin text must use ASCII `--` or `-` exclusively, with zero Unicode em dashes.
  7. **Contiguous Memory Bump Arena & Stable Handle Addressing**:
     - All User Story projection records, scenario descriptors, clause tuples, and traceability mappings shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit arena node handles (REQ-0035).
  8. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every User Story specification $U$ and constituent Gherkin scenario $S$ shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier generated by hashing the canonical DEAP namespace OID and the node fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel extraction of AST constraints, Gherkin clause synthesis, and scenario formatting across independent features and compilation units shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $N_{\text{max\_workers}}$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: User Story narrative titles, Gherkin keywords (`Given`, `When`, `Then`, `And`, `But`), actor roles, scenario identifiers, and predicate symbol strings shall be interned into the deduplicated global symbol interner pool during lexical and AST analysis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The User Story projection engine shall implement synchronization token error recovery on constraint block delimiters (`;`, `}`), scenario boundaries (`Scenario:`), and markdown section delimiters (`###`, `---`) in accordance with REQ-0013 and REQ-0016. When constraint translation errors or untraced scenarios (`E0500`) occur, the engine shall record structured diagnostics into the preallocated error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels ($\bot_{\text{scenario}}$), and continue synthesizing subsequent scenarios. If accumulated diagnostics reach capacity limit $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The User Story projection engine and Gherkin synthesizer shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency (strictly under 25 ms for an architectural model containing $|C_{\text{constraints}}| = 10^4$ AST constraints across projected features) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  9. **Pure Abstract MBSE Placeholder Mandate**:
     - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Feature_0`, `Feature_1`, `Feature_Alpha`, `UserStory_0`, `UserStory_Alpha`, `Scenario_0`, `Scenario_1`, `Scenario_Alpha`, `Constraint_0`, `Constraint_1`, `Constraint_Alpha`, `Action_0`, `State_0`, `State_1`, `param_x : Real`, `attr_0`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes in contiguous bump arena storage, and let $\mathcal{S}_{\text{intern}}$ denote the deduplicated global symbol interner pool.

  Let $\mathcal{F}_{\text{proj}} \subset \mathcal{V}_{\text{AST}}$ denote the finite set of features projected by Subsystem 9.
  Let $\mathcal{C}_{\text{AST}} \subset \mathcal{V}_{\text{AST}}$ denote the finite set of formal AST constraint blocks declared across all features in $\mathcal{F}_{\text{proj}}$.

  Each AST constraint $c \in \mathcal{C}_{\text{AST}}$ is formalized as an 8-tuple:

  $$
  c = \langle \text{id}_c, \text{name}_c, F_c, \kappa_c, P_{\text{pre}}(c), A_{\text{action}}(c), Q_{\text{post}}(c), \text{span}_c \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_c &\in \mathbb{N}_{32} \quad (\text{contiguous arena constraint node handle}) \\
  \text{name}_c &\in \mathcal{S}_{\text{intern}} \quad (\text{interned constraint symbol identifier}) \\
  F_c &\in \mathcal{F}_{\text{proj}} \quad (\text{owning feature classifier handle}) \\
  \kappa_c &\in \{ \text{PrePostContract}, \text{AssertInvariant}, \text{StatechartTransition}, \text{OperationalEnvelope}, \text{SafetyInvariant} \} \\
  P_{\text{pre}}(c) &\in \text{Expr}_{\text{bool}} \quad (\text{precondition boolean AST expression}) \\
  A_{\text{action}}(c) &\in \text{Expr}_{\text{act}} \cup \{ \bot \} \quad (\text{stimulus action or event invocation handle}) \\
  Q_{\text{post}}(c) &\in \text{Expr}_{\text{bool}} \quad (\text{postcondition boolean AST expression}) \\
  \text{span}_c &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
  $$

  1. User Story Formal Model:
  For each feature $F \in \mathcal{F}_{\text{proj}}$, the synthesized User Story specification $U \in \mathcal{U}(F)$ is formalized as a 6-tuple:

  $$
  U = \langle \text{id}_U, \text{name}_U, F, \mathbf{N}_U, \mathbf{S}_U, \Delta_U \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_U &\in \mathbb{N}_{32} \quad (\text{contiguous arena User Story handle}) \\
  \text{name}_U &\in \mathcal{S}_{\text{intern}} \quad (\text{interned User Story title}) \\
  F &\in \mathcal{F}_{\text{proj}} \quad (\text{owning feature handle}) \\
  \mathbf{N}_U &= \langle \text{role}_U, \text{want}_U, \text{benefit}_U \rangle \in \mathcal{S}_{\text{intern}}^3 \quad (\text{narrative preamble triple}) \\
  \mathbf{S}_U &= \langle S_1, S_2, \dots, S_k \rangle \quad (\text{ordered sequence of synthesized Gherkin scenarios}) \\
  \Delta_U &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor})
  \end{aligned}
  $$

  2. Gherkin BDD Scenario Formal Model:
  Each synthesized Gherkin scenario $S \in \mathbf{S}_U$ is formalized as an 8-tuple:

  $$
  S = \langle \text{id}_S, \text{name}_S, U_S, c_S, \mathbf{G}_S, \mathbf{W}_S, \mathbf{T}_S, \Delta_S \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_S &\in \mathbb{N}_{32} \quad (\text{contiguous arena scenario handle}) \\
  \text{name}_S &\in \mathcal{S}_{\text{intern}} \quad (\text{interned scenario title}) \\
  U_S &\in \mathcal{U}(F) \quad (\text{owning User Story handle}) \\
  c_S &\in \mathcal{C}_{\text{AST}} \quad (\text{source AST constraint handle}) \\
  \mathbf{G}_S &= \langle g_1, \dots, g_m \rangle \in \mathcal{S}_{\text{intern}}^m \quad (\text{sequence of Given/And precondition clauses}, \, m \ge 1) \\
  \mathbf{W}_S &= \langle w_1, \dots, w_p \rangle \in \mathcal{S}_{\text{intern}}^p \quad (\text{sequence of When/And action clauses}, \, p \ge 1) \\
  \mathbf{T}_S &= \langle t_1, \dots, t_q \rangle \in \mathcal{S}_{\text{intern}}^q \quad (\text{sequence of Then/And/But postcondition clauses}, \, q \ge 1) \\
  \Delta_S &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor})
  \end{aligned}
  $$

  3. Operational Semantic Entailment Invariant:
  Let $\Sigma$ denote the model state space, where each state $\sigma \in \Sigma$ is a valuation mapping variables to domain values.
  Let $\text{Exec}(A_{\text{action}}, \sigma, \sigma')$ denote the transition relation asserting that executing action or event $A_{\text{action}}$ from pre-state $\sigma$ yields post-state $\sigma'$.
  Every synthesized scenario $S = \langle \text{id}_S, \text{name}_S, U_S, c_S, \mathbf{G}_S, \mathbf{W}_S, \mathbf{T}_S, \Delta_S \rangle$ satisfies:

  $$
  \forall \sigma, \sigma' \in \Sigma, \quad \left( \bigwedge_{g \in \mathbf{G}_S} \text{Eval}(g, \sigma) \right) \land \text{Exec}(A_{\text{action}}(c_S), \sigma, \sigma') \implies \left( \bigwedge_{t \in \mathbf{T}_S} \text{Eval}(t, \sigma') \right)
  $$

  where $\text{Eval}(e, \sigma)$ denotes boolean evaluation of clause $e$ under state valuation $\sigma$.

  4. Bijective Traceability Mapping:
  Let $\mathbf{S}_{\text{all}} = \bigcup_{F \in \mathcal{F}_{\text{proj}}} \bigcup_{U \in \mathcal{U}(F)} \mathbf{S}_U$ denote the universe of all synthesized scenarios.
  The mapping $\tau_{\text{trace}} : \mathbf{S}_{\text{all}} \to \mathcal{C}_{\text{AST}}$ defined by $\tau_{\text{trace}}(S) = c_S$ is a bijective function:

  $$
  |\mathbf{S}_{\text{all}}| = |\mathcal{C}_{\text{AST}}|
  $$

  $$
  \forall S_a, S_b \in \mathbf{S}_{\text{all}}, \quad S_a \ne S_b \implies c_{S_a} \ne c_{S_b}
  $$

  $$
  \forall c \in \mathcal{C}_{\text{AST}}, \quad \exists ! S \in \mathbf{S}_{\text{all}} \text{ s.t. } c_S = c
  $$

  Furthermore, feature ownership is strictly preserved:

  $$
  \forall S \in \mathbf{S}_{\text{all}}, \quad F_{U_S} = F_{c_S}
  $$

  5. Deterministic RFC 4122 UUIDv5 Identification Invariant (Directive 1):
  Every User Story and Gherkin scenario binds an immutable UUIDv5 derived from the DEAP namespace OID:

  $$
  \begin{aligned}
  \forall U \in \mathcal{U}(F), &\quad \Delta_U = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::UserStory::"} \mathbin{\Vert} \text{name}_U) \\
  \forall S \in \mathbf{S}_U, &\quad \Delta_S = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U) \mathbin{\Vert} \text{"::Scenario::"} \mathbin{\Vert} \text{name}_S)
  \end{aligned}
  $$

  6. Deterministic Diagnostic Trigger Rules (REQ-0191):
  If an AST constraint block contains malformed or unresolvable expressions, fails tripartite synthesis, lacks bijective traceability, or produces duplicate scenario identifiers, diagnostic error code `E0500` shall be emitted into the preallocated error sink buffer $\mathcal{D}_{\text{sink}}$:

  $$
  \begin{aligned}
  \exists c \in \mathcal{C}_{\text{AST}} : \text{IsMalformed}(c) &\implies \text{Diagnostic}(c, \text{DiagnosticCode::E0500}, \text{MalformedConstraintBlockViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists c \in \mathcal{C}_{\text{AST}} : \neg\text{CanSynthesizeGherkin}(c) &\implies \text{Diagnostic}(c, \text{DiagnosticCode::E0500}, \text{UnsatisfiedConstraintSynthesisViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists S \in \mathbf{S}_{\text{all}} : c_S \notin \mathcal{C}_{\text{AST}} \lor F_{U_S} \ne F_{c_S} &\implies \text{Diagnostic}(S, \text{DiagnosticCode::E0500}, \text{UntracedScenarioViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists S_a, S_b \in \mathbf{S}_U : S_a \ne S_b \land \text{name}_{S_a} = \text{name}_{S_b} &\implies \text{Diagnostic}(S_b, \text{DiagnosticCode::E0500}, \text{DuplicateScenarioIdentifierViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

  7. Fail-Closed Pipeline Halting Invariant:

  $$
  |\mathcal{D}_{\text{sink}} \cap \{ D \mid \text{code}(D) \in \{ \text{E0500}, \text{E0199} \} \}| \gt 0 \implies \text{HaltPipeline}() \land \text{UserStoryArtifactEmissionGate} = \text{BLOCKED}
  $$

- **Computational Complexity & Algorithmic Bounds**: The User Stories Projection and Gherkin BDD synthesis engine resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing with deterministic linear asymptotic time complexity $O(|C_{\text{constraints}}|)$ over the number of AST constraints in the compilation unit, with linear space complexity $O(|C_{\text{constraints}}|)$ in contiguous bump arena storage.

  **Mathematical Delineation from the 8 NP-Completeness Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 addresses qualitative temporal interval consistency over occurrence lifecycles using Allen's 13 interval relations and ORD-Horn difference logic SMT solving in $O(N^3)$ polynomial time. In contrast, REQ-0169 translates already parsed and validated AST constraint expressions into textual Gherkin clauses in deterministic linear time $O(|C_{\text{constraints}}|)$ without performing temporal interval constraint propagation.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 solves multi-dimensional vector bin packing and channel multiplexing (strongly NP-hard), employing First-Fit Decreasing approximations. In contrast, REQ-0169 performs syntax-directed AST constraint projection and template formatting without combinatorial resource optimization or knapsack packing.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 resolves multiple inheritance subtyping lattices and redefinitions via monotonic C3 linearization in $O(V + E)$ time. In contrast, REQ-0169 operates downstream of type checking, extracting concrete constraint blocks attached to typed features.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0169 ingests already synthesized safety invariants and translates them directly into Gherkin BDD scenarios in linear time.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 addresses orthogonal state machine reachability, deadlock, and livelock (PSPACE-complete / NP-complete under BMC unrolling). In contrast, REQ-0169 projects state machine transitions into Given-When-Then scenarios by direct inspection of transition tuples $\langle s_{\text{src}}, e_{\text{trig}}, g_{\text{guard}}, s_{\text{tgt}} \rangle$ without traversing the full orthogonal state reachability tree.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks via linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0169 emits documentation and test scenarios from discrete AST expressions without solving continuous or piecewise numerical complementarity equations.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs Chaitin graph coloring for SSA register allocation in LUMI IR (NP-complete). In contrast, REQ-0169 operates at the specification projection tier, transforming AST constraint structures into Gherkin text prior to downstream IR lowering.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the formal satisfiability of first-order invariant contracts via DPLL(T) SMT solvers, which is NP-complete for quantifier-free decidable fragments and undecidable for non-linear arithmetic. In sharp contrast, REQ-0169 does not invoke SMT solvers to prove validity or find satisfying assignments; rather, REQ-0169 performs deterministic syntax-directed translation of AST constraint expressions into textual Gherkin Given-When-Then specification scenarios in deterministic linear time $O(|C_{\text{constraints}}|)$.

  **Asymptotic Complexity Analysis**:
  Let $N_C = |\mathcal{C}_{\text{AST}}|$ denote the total number of AST constraint blocks in the compilation unit, let $N_F = |\mathcal{F}_{\text{proj}}|$ denote the number of projected features ($N_F \le N_C$), and let $L$ denote the aggregate byte length of generated Gherkin scenario text.
  1. *AST Constraint Extraction & Traversal*:
     Traversing the AST nodes of each feature $F \in \mathcal{F}_{\text{proj}}$ to identify and collect constraint blocks visits each feature AST node exactly once:
     $$T_{\text{extract}}(N_C) \in O(N_C)$$
  2. *Gherkin Clause Synthesis & Template Lowering*:
     For each constraint $c \in \mathcal{C}_{\text{AST}}$, mapping the precondition AST to `Given`, the action AST to `When`, and the postcondition AST to `Then` performs a constant number of AST node traversals bounded by the maximum expression depth $d_{\max} \le c_{\text{depth}}$:
     $$T_{\text{synth}}(N_C) = \sum_{c \in \mathcal{C}_{\text{AST}}} O(\text{depth}(c)) \in O(N_C)$$
  3. *Bijective Traceability Table Construction*:
     Registering each scenario in the bidirectional traceability index uses direct 32-bit arena node handle indexing with $O(1)$ amortized insertion:
     $$T_{\text{trace}}(N_C) \in O(N_C)$$
  4. *Deterministic Lexicographical Scenario Sorting*:
     For a User Story containing $k$ scenarios, sorting scenarios by interned constraint symbol identifier takes $O(k \log k)$ integer comparisons. Summing across all User Stories:
     $$T_{\text{sort}}(N_C) = \sum_{U} O(k_U \log k_U) \le O(N_C \log N_C)$$
     Using pre-sorted arena handle arrays, this reduces to strictly linear time $O(N_C)$.
  5. *Scenario Text Formatting & Streaming Emission*:
     Formatting interned clause symbols and writing scenario text to downstream streaming sinks is linear in total emitted byte length $L$:
     $$T_{\text{emit}}(L) \in O(L)$$
  6. *Aggregate Sequential Execution Time*:
     The total execution time across all phases of User Story Gherkin synthesis is strictly bounded by:
     $$T_{\text{total}}(N_C, L) = T_{\text{extract}} + T_{\text{synth}} + T_{\text{trace}} + T_{\text{sort}} + T_{\text{emit}} \in O(N_C + L) = O(|\mathcal{C}_{\text{AST}}|)$$
  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     When synthesizing scenarios across independent features on a bounded work-stealing thread pool with $N_{\text{max\_workers}}$ threads:
     $$T_{\text{parallel}}(N_C, N_{\text{max\_workers}}) \in O\left( \frac{N_C}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)$$
     guaranteeing near-linear throughput scaling without cross-thread lock contention.
  8. *Space Complexity & Arena Memory Bounds*:
     Allocations for User Story descriptors, scenario records, clause lists, and traceability tables reside in contiguous typed bump arena storage. Storing $N_C$ scenario records requires $O(N_C)$ bytes of arena memory. Interned strings reside in the global symbol pool. The diagnostic error sink buffer requires bounded $O(C_{\text{max\_errors}}) = O(1)$ capacity. Auxiliary heap allocation is strictly $O(1)$, fully preserving zero-copy bump arena guarantees.
