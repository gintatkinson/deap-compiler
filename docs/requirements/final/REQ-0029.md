### REQ-0029: OpenAPI (JSON/YAML) Schema Ingestion for Paths, Operations & Payloads

- **Normative Statement**: The Universal Schema Ingestion Engine shall provide a native, self-contained OpenAPI specification parser and intermediate representation lowering engine that ingests OpenAPI 3.0 and 3.1 specifications in JSON and YAML serialization formats into intermediate schema IR without external compiler dependencies, third-party parsers, or runtime toolchain invocations. The ingestion engine shall parse document hierarchies, resolve JSON Pointer schema references, and lower OpenAPI structural elements into intermediate schema IR entities in accordance with the following contract:
  1. Specification Namespace Lowering: The root OpenAPI specification document shall lower to an `IngestedPackage` namespace entity derived from the specification info title and version, establishing a deterministic lexical scope and constructing fully qualified symbol paths (e.g., `Package_0::Spec_Alpha`).
  2. Schema Component Lowering: Object definitions declared under `components/schemas` shall lower to `IngestedClassifierDef` entities with structural kind `ClassifierKind::Struct` (or `IngestedPart` when tagged with component stereotypes). Each schema property shall lower to an `IngestedAttr` property binding property identifier, resolved classifier type reference, multiplicity interval $\langle l, u \rangle \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})$, and operational constraint bounds. Schema composition constructs (`allOf`, `oneOf`, `anyOf`) shall lower to structural inheritance, variant union types, and interface conformance relationships respectively. Enumerated schema definitions (`enum`) shall lower to `IngestedClassifierDef` entities with structural kind `ClassifierKind::Enum`.
  3. Primitive Data Type Mapping: OpenAPI primitive data types and formats shall map deterministically to canonical MBSE scalar types: `string` maps to `String` (with format subtypes `Date`, `DateTime`, `Byte`, `Binary`), `integer` with format `int32` maps to `Int32`, `integer` with format `int64` maps to `Int64`, `number` with format `float` maps to `Real32`, `number` with format `double` maps to `Real64`, `boolean` maps to `Boolean`, and `array` maps to the item element type with array multiplicity bounds.
  4. Path and Interface Endpoint Lowering: API path item objects declared under `paths` (e.g., `/endpoint_alpha/{param_id}`) shall lower to structural interface endpoints within the enclosing service package. URL template path parameters enclosed in braces (`{param}`) shall be extracted, validated against the operation parameter roster, and mapped directly to required input parameters on each enclosed operation.
  5. Operation Lowering: HTTP operation declarations (`get`, `put`, `post`, `delete`, `options`, `head`, `patch`, `trace`) defined within a path item shall lower to `IngestedAction` operation entities. If an explicit `operationId` is specified, it shall serve as the primary action symbol identifier; if `operationId` is omitted, the ingestion engine shall synthesize a deterministic identifier by concatenating the lowercased HTTP verb, an underscore delimiter, and the sanitized path route string (e.g., `get_endpoint_alpha_param_id`). Duplicate `operationId` values within the compilation unit are strictly prohibited and shall deterministically trigger diagnostic error code `E0102`.
  6. Parameter Lowering and Partitioning: Operation parameters declared in the `parameters` roster across path and operation scopes shall be partitioned into typed input parameters:
     - `in: path`: Path parameters shall be mapped to input parameters with mandatory `required: true` and multiplicity $\langle 1, 1 \rangle$. If a template variable in the path route lacks a corresponding path parameter definition, or if a declared path parameter is absent from the URL route template, the ingestion engine shall record diagnostic error code `E0102`.
     - `in: query`, `in: header`, `in: cookie`: Query, header, and cookie parameters shall be mapped to action input parameters. Parameters marked with `required: true` shall bind multiplicity $\langle 1, 1 \rangle$; optional parameters (`required: false` or omitted) shall bind multiplicity $\langle 0, 1 \rangle$. Array-typed parameters shall bind multiplicity intervals $\langle \kappa_{\min}, \kappa_{\max} \rangle$ where $\kappa_{\min} = \text{minItems}$ (default 0) and $\kappa_{\max} = \text{maxItems}$ (default $\infty$).
  7. Request Body Payload Lowering: If an operation declares a `requestBody` object, the ingestion engine shall synthesize a formal input parameter named `payload` binding the lowered classifier type of the schema associated with the primary content media type (e.g., `application/json`). If `required: true` is specified, the parameter multiplicity shall be $\langle 1, 1 \rangle$; otherwise, it shall be $\langle 0, 1 \rangle$.
  8. Response Payload Lowering: Response definitions under `responses` shall be partitioned into output parameters and error variants. Success responses with HTTP status codes in the $2xx$ range ($200$, $201$, $204$) shall synthesize a formal output parameter named `result` binding the declared response payload schema type with multiplicity $\langle 1, 1 \rangle$ (or $\langle 0, 0 \rangle$ for empty payloads such as status $204$). Non-2xx response definitions (client errors $4xx$ and server errors $5xx$) shall be captured as typed exception signatures on the `IngestedAction`.
  9. JSON Pointer Reference Resolution: Schema references utilizing JSON Pointer URI fragments (e.g., `#/components/schemas/Schema_Alpha`) shall be resolved via URI fragment JSON Pointer dereferencing within the compilation unit symbol table. Cyclic schema references (e.g., recursive composite structures) shall be resolved via node handle indirection without triggering infinite recursion. Unresolvable schema reference targets shall emit diagnostic error code `E0102`.

  All synthesized intermediate AST nodes (`IngestedPackage`, `IngestedPart`, `IngestedClassifierDef`, `IngestedAction`, `IngestedAttr`) shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, yielding deterministic node handles with stable relative offsets. In accordance with Architectural Directive 1 and REQ-0010, every lowered AST node shall receive a deterministic RFC 4122 UUIDv5 identifier derived from the namespace OID and the fully qualified symbol path. In accordance with Architectural Directive 3 and REQ-0036, copying string bytes from the input JSON or YAML buffer into the global symbol interner pool for scalar `SymbolId` tokens during this initial lexical pass is the sole permitted exception to the zero-copy invariant. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the ingestion engine shall implement synchronization token error recovery on statement, mapping, and delimiter boundaries (structural brackets `}`, `]`, comma `,`, or line break $\text{SYM}_{\text{LF}}$): upon encountering a syntax violation, unresolvable reference, or schema type mismatch, the parser shall record a structured diagnostic record binding diagnostic error code `E0100` (JSON/YAML grammar or format error), `E0102` (OpenAPI structural entity or mapping error), or `E0103` (unsupported data type or constraint violation) per REQ-0191, substitute a typed sentinel error node $\bot_{\text{openapi}}$, and resynchronize at the next path item or schema definition without aborting compilation. If accumulated diagnostics reach the bounded error sink capacity limit $C_{\text{max\_errors}}$, the parser shall emit diagnostic error code `E0199` and terminate processing gracefully. Multi-file OpenAPI compilation units shall be processed in parallel across a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with Architectural Directive 2 and REQ-0012. The ingestion parser must enforce Architectural Directive 5, guaranteeing a total, deterministic, non-panicking execution contract with total-function termination across all inputs. Performance latency (< 25 ms) and RSS memory (< 100 MB) budget gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196. All test models, diagnostic messages, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Spec_Alpha`, `Endpoint_1`, `Schema_Alpha`, `Schema_Beta`, `Action_0`, `op_post`, `param_x : Real`, `Payload_0`, `Response_Alpha`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $\mathcal{O}$ denote an OpenAPI specification document formalized as a 4-tuple:

$$
\mathcal{O} = \langle V_{\text{version}}, \mathcal{I}_{\text{info}}, \mathcal{P}_{\text{paths}}, \mathcal{C}_{\text{components}} \rangle
$$

where:
- $V_{\text{version}} \in \{ \text{"3.0.0"}, \text{"3.0.1"}, \text{"3.0.2"}, \text{"3.0.3"}, \text{"3.1.0"} \}$ represents the validated OpenAPI specification version,
- $\mathcal{I}_{\text{info}} = \langle \text{title}, \text{ver} \rangle \in \mathcal{S}_{\text{sym}} \times \mathcal{S}_{\text{sym}}$ encapsulates specification metadata,
- $\mathcal{P}_{\text{paths}} = \{ P_1, P_2, \dots, P_k \}$ is the finite set of path item objects, where each path $P_i$ binds a URL route template string $u(P_i) \in \mathcal{S}_{\text{str}}$ and a set of HTTP operations $\text{Ops}(P_i)$,
- $\mathcal{C}_{\text{components}} = \langle \mathcal{S}_{\text{schemas}}, \mathcal{R}_{\text{responses}}, \mathcal{B}_{\text{parameters}} \rangle$ encapsulates reusable schema definitions.

The lowering transformation $\mathcal{T}_{\text{openapi}} : \mathcal{O} \longrightarrow \mathcal{A}_{\text{IR}}$ maps OpenAPI constructs into intermediate schema IR entities:

$$
\begin{aligned}
\text{components/schemas/} S &\longmapsto \text{IngestedClassifierDef}(S, \text{kind}: \text{ClassifierKind::Struct}, \text{fields}: \mathcal{T}_{\text{schema}}(S)) \\
\text{paths/} P / m &\longmapsto \text{IngestedAction}(\text{ActionId}(P, m), \text{endpoint}: u(P), \text{inputs}: \mathcal{P}_{\text{in}}(P, m), \text{outputs}: \mathcal{P}_{\text{out}}(P, m))
\end{aligned}
$$

Operation Action Identifier Invariant: The action identifier for operation $m \in \text{Ops}(P)$ satisfies:

$$
\text{ActionId}(P, m) = 
\begin{cases}
\text{id}_{\text{op}}, & \text{if } \text{operationId}(P, m) = \text{id}_{\text{op}} \ne \bot \\
m \mathbin{\Vert} \text{"\_"} \mathbin{\Vert} \text{Sanitize}(u(P)), & \text{otherwise}
\end{cases}
$$

where $\mathbin{\Vert}$ denotes string concatenation, and $\text{Sanitize}(u)$ replaces characters $\{ \text{'/'}, \text{'\{'}, \text{'\}'}, \text{'-'} \}$ with character $\text{'\_'}$.

Operation Identifier Uniqueness Invariant: All synthesized action identifiers across the specification must be pairwise distinct:

$$
\forall (P_1, m_1) \ne (P_2, m_2), \quad \text{ActionId}(P_1, m_1) \ne \text{ActionId}(P_2, m_2)
$$

Parameter Multiplicity Invariant: Let $p \in \text{Params}(P, m)$ denote an operation parameter with location $\text{in}(p) \in \{ \text{Path}, \text{Query}, \text{Header}, \text{Cookie} \}$. The multiplicity interval $\mu(p) \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})$ satisfies:

$$
\mu(p) = 
\begin{cases}
\langle 1, 1 \rangle, & \text{if } \text{in}(p) = \text{Path} \\
\langle 1, 1 \rangle, & \text{if } \text{in}(p) \ne \text{Path} \;\wedge\; \text{required}(p) = \text{true} \;\wedge\; \neg \text{IsArray}(p) \\
\langle 0, 1 \rangle, & \text{if } \text{in}(p) \ne \text{Path} \;\wedge\; \text{required}(p) = \text{false} \;\wedge\; \neg \text{IsArray}(p) \\
\langle \kappa_{\min}, \kappa_{\max} \rangle, & \text{if } \text{IsArray}(p)
\end{cases}
$$

where $\kappa_{\min} = \text{minItems}(p)$ (defaulting to 0) and $\kappa_{\max} = \text{maxItems}(p)$ (defaulting to $\infty$).

Path Parameter Consistency Invariant: Let $\text{Vars}(u(P)) = \{ v \mid \text{"\{"} \mathbin{\Vert} v \mathbin{\Vert} \text{"\}"} \sqsubseteq u(P) \}$ denote the set of variable names embedded in the path route template. The declared path parameters must be bijectively equivalent to the template variables:

$$
\forall P \in \mathcal{P}_{\text{paths}}, \, \forall m \in \text{Ops}(P), \quad \{ \text{name}(p) \mid p \in \text{Params}(P, m) \;\wedge\; \text{in}(p) = \text{Path} \} = \text{Vars}(u(P))
$$

Payload Schema Mapping Invariant: Lowering of request bodies and response status payloads satisfies:

$$
\begin{aligned}
\text{requestBody}(P, m) &\longmapsto \text{IngestedAttr}(\text{"payload"}, \text{type}: \tau_{\text{req}}, \text{mult}: \mu_{\text{req}}) \\
\text{responses}(P, m, c) &\longmapsto \text{IngestedAttr}(\text{"result"}, \text{type}: \tau_{\text{resp}}, \text{mult}: \langle 1, 1 \rangle), \quad \forall c \in [200, 299]
\end{aligned}
$$

where:

$$
\mu_{\text{req}} = 
\begin{cases}
\langle 1, 1 \rangle, & \text{if } \text{required}(\text{requestBody}(P, m)) = \text{true} \\
\langle 0, 1 \rangle, & \text{if } \text{required}(\text{requestBody}(P, m)) = \text{false}
\end{cases}
$$

Input and Output Partition Sets: The parameter rosters for the synthesized action satisfy:

$$
\begin{aligned}
\mathcal{P}_{\text{in}}(P, m) &= \{ \text{LowerParam}(p) \mid p \in \text{Params}(P, m) \} \;\cup\; \{ \text{LowerBody}(\text{requestBody}(P, m)) \mid \text{requestBody} \ne \bot \} \\
\mathcal{P}_{\text{out}}(P, m) &= \{ \text{LowerResp}(r) \mid r \in \text{Responses}(P, m) \;\wedge\; \text{code}(r) \in [200, 299] \}
\end{aligned}
$$

JSON Pointer Reference Resolution Invariant: For any schema reference $R = \text{"\#/components/schemas/"} \mathbin{\Vert} S$, the dereferencing function satisfies:

$$
\text{ResolveRef}(R, \mathcal{O}) = 
\begin{cases}
\mathcal{C}_{\text{components}}.\mathcal{S}_{\text{schemas}}[S], & \text{if } S \in \text{dom}(\mathcal{C}_{\text{components}}.\mathcal{S}_{\text{schemas}}) \\
\bot, & \text{otherwise}
\end{cases}
$$

Deterministic UUIDv5 & Bump Arena Invariant: For every lowered AST node $u \in \mathcal{A}_{\text{IR}}$, its RFC 4122 UUIDv5 identifier satisfies:

$$
\text{UUID}(u) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))
$$

and sequential allocation into the contiguous typed bump arena satisfies:

$$
\forall i \in \{1, \dots, M-1\}, \quad \text{Offset}(h_{i+1}) = \text{Offset}(h_i) + \text{sizeof}(\text{ASTNode})
$$

Diagnostic Code Binding Invariant: Structural, syntax, reference, and typing violations construct structured diagnostics in accordance with REQ-0191:

$$
\begin{aligned}
V_{\text{version}} \notin \{ \text{"3.0.0"}, \dots, \text{"3.1.0"} \} &\implies \text{Diagnostic}(\text{span}(V), \text{DiagnosticCode::E0100}, \text{UnsupportedOpenAPIVersion}) \in \mathcal{D} \\
\text{HasSyntaxError}(\text{token}_k) &\implies \text{Diagnostic}(\text{span}(\text{token}_k), \text{DiagnosticCode::E0100}, \text{JSONYAMLParseError}) \in \mathcal{D} \\
\text{ActionId}(P_1, m_1) = \text{ActionId}(P_2, m_2) &\implies \text{Diagnostic}(\text{span}(P_2), \text{DiagnosticCode::E0102}, \text{DuplicateOperationIdentifier}) \in \mathcal{D} \\
\text{in}(p) = \text{Path} \;\wedge\; \text{name}(p) \notin \text{Vars}(u(P)) &\implies \text{Diagnostic}(\text{span}(p), \text{DiagnosticCode::E0102}, \text{PathParameterNotInRoute}) \in \mathcal{D} \\
v \in \text{Vars}(u(P)) \;\wedge\; v \notin \text{PathParams}(P, m) &\implies \text{Diagnostic}(\text{span}(u(P)), \text{DiagnosticCode::E0102}, \text{MissingPathParameterDeclaration}) \in \mathcal{D} \\
\text{ResolveRef}(R, \mathcal{O}) = \bot &\implies \text{Diagnostic}(\text{span}(R), \text{DiagnosticCode::E0102}, \text{UnresolvableSchemaReference}) \in \mathcal{D} \\
\text{IsUnsupportedType}(\tau) &\implies \text{Diagnostic}(\text{span}(\tau), \text{DiagnosticCode::E0103}, \text{UnsupportedSchemaDataType}) \in \mathcal{D} \\
|\mathcal{D}| \ge C_{\text{max\_errors}} &\implies \text{Diagnostic}(\text{span}(\text{EOF}), \text{DiagnosticCode::E0199}, \text{ErrorCapacityExceeded}) \in \mathcal{D}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant: All emitted diagnostics strictly belong to the Subsystem 2 ingestion family:

$$
\forall D \in \mathcal{D}_{\text{openapi}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0100}, \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0103}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{ingest}}
$$

- **Computational Complexity & Algorithmic Bounds**: The OpenAPI AST ingestion engine executes within Complexity Class $\mathbf{P}$. Lexical analysis and structural parsing of the input JSON or YAML stream execute via a deterministic, single-pass streaming parser scanning an input document of $N$ bytes monotonically in deterministic $O(N)$ linear time without backtracking. Constructing the document object model requires visiting each structural token (keys, scalar values, delimiter tokens) at most once, executing in $O(N)$ operations. Symbol interning into the global symbol pool for identifier tokens of length $L \le 256$ executes in $O(L) = O(1)$ amortized time per token. Lowering $S$ component schemas with $F$ aggregate properties executes in $O(S + F)$ time, where $S + F \le N$. Resolving local JSON Pointer schema references across the schema graph $G_{\text{ref}} = (V_{\text{schema}}, E_{\text{ref}})$ operates via a depth-first traversal with cycle memoization; since each reference pointer is visited at most once, reference resolution completes in $O(V_{\text{schema}} + E_{\text{ref}}) = O(N)$ time. Lowering $P$ path items with $M$ operations and $K$ parameters evaluates in $O(P + M + K) \le O(N)$ time. Path parameter validation checks the set equality between path template variables and declared path parameters in $O(|V|)$ time using hash sets or sorted identifier arrays. Node allocations into the contiguous typed bump arena require a single pointer bump operation per AST entity, executing in $O(1)$ constant time per node. Multi-file compilation across $K$ OpenAPI specifications scheduled on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ yields an aggregate parallel wall-clock runtime bounded by $O(\lceil K / N_{\text{max\_workers}} \rceil \cdot N_{\text{max}})$. Auxiliary memory space is strictly bounded by $O(N)$ for synthesized AST nodes allocated in the bump arena and symbol pool strings, with recursive stack depth strictly bounded by the maximum syntactic nesting depth $D_{\text{max}} \le 64$, ensuring $O(D_{\text{max}}) = O(1)$ call stack frames.

- **Verification & Conformance Criteria**: Automated verification suites shall assert 100% parsing accuracy, structural integrity, and diagnostic conformance across synthetic OpenAPI 3.0 and 3.1 specifications containing abstract MBSE entities (e.g., `Package_0`, `Spec_Alpha`, `Endpoint_1`, `Schema_Alpha`, `Schema_Beta`, `Action_0`, `op_post`, `param_x : Real`, `Payload_0`, `Response_Alpha`). Conformance shall be validated through the following deterministic test gates:
  1. Canonical Schema Component Lowering Gate: Ingest an OpenAPI 3.0/3.1 document declaring component schemas (`components/schemas/Schema_Alpha`) with primitive properties (`string`, `integer`, `number`, `boolean`), nested objects, and arrays; assert that the parser lowers them into `IngestedClassifierDef` nodes with `ClassifierKind::Struct`, matching `IngestedAttr` properties, and valid scalar types.
  2. Path and Operation Lowering Gate: Ingest an OpenAPI specification declaring path items (`/endpoint_alpha`, `/endpoint_beta/{param_id}`) with operations (`get`, `post`, `put`, `delete`); assert that the parser synthesizes `IngestedAction` nodes binding correct endpoint URLs and action identifiers (`op_get_alpha`, `op_post_beta`).
  3. Path Parameter Consistency Gate: Ingest an operation defining path template `/node/{id_param}/status` with declared path parameter `id_param` (`in: path`, `required: true`); assert successful lowering with parameter multiplicity $\langle 1, 1 \rangle$. Ingest a path template `/node/{id_param}` where `id_param` is missing from the parameter list; assert deterministic emission of diagnostic error code `E0102` (`MissingPathParameterDeclaration`). Ingest a declaration where `in: path` parameter is named `extraneous_id` not found in `/node/{id_param}`; assert emission of diagnostic error code `E0102` (`PathParameterNotInRoute`).
  4. Query, Header, and Cookie Parameter Multiplicity Gate: Ingest operations with query and header parameters with varying `required` flags and array bounds (`minItems: 2`, `maxItems: 5`); assert that required parameters map to $\langle 1, 1 \rangle$, optional parameters map to $\langle 0, 1 \rangle$, and array parameters map to $\langle 2, 5 \rangle$.
  5. Request Body Payload Lowering Gate: Ingest an operation declaring `requestBody` with `required: true` and content schema `Schema_Alpha`; assert that the parser synthesizes an input parameter named `payload` with multiplicity $\langle 1, 1 \rangle$ and referenced classifier type `Schema_Alpha`.
  6. Response Payload Lowering Gate: Ingest operations with response status codes $200$ (with schema `Schema_Beta`), $204$ (no content), and $404$ (error schema); assert that $200$ synthesizes an output parameter `result : Schema_Beta` with multiplicity $\langle 1, 1 \rangle$, $204$ synthesizes an empty output with multiplicity $\langle 0, 0 \rangle$, and $404$ is captured as an exception signature.
  7. JSON Pointer Dereferencing and Recursion Gate: Ingest an OpenAPI document with schema reference pointers (`#/components/schemas/Schema_Alpha`) and recursive self-referential schemas (`Schema_Node` referencing `Schema_Node`); assert that the reference resolver dereferences pointers correctly without infinite recursion or stack overflow. Ingest an unresolvable schema reference pointer (`#/components/schemas/NonExistent`); assert emission of diagnostic error code `E0102` (`UnresolvableSchemaReference`).
  8. Duplicate Operation Identifier Gate: Ingest an OpenAPI specification containing two distinct operations declaring identical `operationId: op_duplicate`; assert deterministic emission of diagnostic error code `E0102` (`DuplicateOperationIdentifier`) on the duplicate entry.
  9. Version Validation Gate: Ingest an OpenAPI document declaring `openapi: "2.0"` (Swagger) or `openapi: "4.0.0"`; assert deterministic rejection with diagnostic error code `E0100` (`UnsupportedOpenAPIVersion`). Ingest specifications declaring `3.0.0`, `3.0.3`, and `3.1.0`; assert successful version validation.
  10. Synchronization Token Error Recovery Gate: Ingest an OpenAPI JSON or YAML file containing deliberate syntax errors (e.g., malformed brackets, invalid indentation, or truncated schema object) on specific lines; assert that the parser records structured diagnostic records with code `E0100` or `E0102`, substitutes sentinel $\bot_{\text{openapi}}$, resynchronizes at the subsequent path or component boundary, and successfully extracts all subsequent valid paths and schemas.
  11. Total Non-Panicking Contract Gate: Execute automated fuzz testing with 100,000 malformed, truncated, and randomized JSON and YAML inputs; assert 100% total-function termination with structured diagnostic reporting and zero panics, crashes, or unhandled exceptions.
  12. Release Mode Latency & RSS Gate: Evaluate ingestion latency and memory footprint strictly in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests, asserting execution latency strictly within the 25 ms budget and peak memory RSS strictly below 100 MB for standard schemas up to 10 MB.
  13. Bitwise Determinism Gate: Verify 0-byte diff churn across repeated compilation passes of identical OpenAPI sources under both single-threaded and multi-threaded worker configurations, asserting byte-identical AST serialization.
