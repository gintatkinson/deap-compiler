### REQ-0059: KerML Interaction & Step Abstract Syntax Semantics

- **Normative Statement**: The semantic lowering and behavioral analysis engine of Subsystem 4 shall formalize communications, message exchanges, and flow transfers between occurrences as `Interaction` classifiers in accordance with the OMG Kernel Modeling Language (KerML) specification. An `Interaction` classifier shall multiply specialize both `Behavior` and `Association`, combining behavioral occurrence execution semantics with relational association semantics across two or more participant occurrences ($k \ge 2$).

  As an `Association`, each `Interaction` classifier shall define two or more participant end features ($P_1, P_2, \dots, P_k$ where $k \ge 2$) representing interacting lifelines or occurrence roles, specifying their declared classifier types and multiplicity bounds. As a `Behavior`, each `Interaction` classifier shall define an occurrence lifecycle governing constituent `Step` features owned by or invoked within the interaction. Every constituent `Step` in an interaction shall model an occurrence performance typed by a constituent `Behavior` or sub-interaction.

  Constituent steps shall include discrete message transfer and item flow steps $s_{\text{transfer}} = \langle e_{\text{send}}, e_{\text{recv}}, \delta_{\text{payload}}, p_{\text{src}}, p_{\text{tgt}}, \tau_{\text{msg}} \rangle$, formalizing the transmission of payload item $\delta_{\text{payload}}$ from a sending occurrence event $e_{\text{send}}$ on source participant $p_{\text{src}}$ to a receiving occurrence event $e_{\text{recv}}$ on target participant $p_{\text{tgt}}$. The engine shall enforce causal precedence relations $\prec$ over the constituent step set $\mathcal{S}_I$, forming a strict occurrence partially ordered set (poset) $(\mathcal{S}_I, \prec)$. Causal precedence shall strictly enforce temporal non-inversion: for any two constituent steps $s_1, s_2 \in \mathcal{S}_I$, $s_1 \prec s_2$ entails that the termination time of $s_1$ cannot exceed the initiation time of $s_2$ ($\tau_{\text{end}}(s_1) \le \tau_{\text{start}}(s_2)$).

  The behavioral lowering engine shall enforce message transfer causality and payload type conformance:
  1. Directional Causality: For every message transfer step $s_{\text{transfer}}$, the transmission event $e_{\text{send}}$ must strictly precede the reception event $e_{\text{recv}}$ in monotonic time ($\tau(e_{\text{send}}) \lt \tau(e_{\text{recv}})$). If the reception event is observed before or simultaneously with the transmission event ($\tau(e_{\text{recv}}) \le \tau(e_{\text{send}})$), the engine shall emit structured diagnostic error code `E0201` per REQ-0191.
  2. Payload Typing: The payload entity $\delta_{\text{payload}}$ must statically and dynamically conform to the declared message classifier type $\tau_{\text{msg}}$ ($\tau(\delta_{\text{payload}}) \le_{\text{sub}} \tau_{\text{msg}}$). Any type incompatibility between the payload and the transfer contract shall deterministically emit structured diagnostic error code `E0202` per REQ-0191.
  3. Participant Cardinality: Every interaction classifier must declare at least two participant end features ($k \ge 2$). Declaring an interaction with fewer than two participants shall emit structured diagnostic error code `E0200` per REQ-0191.
  4. Causal Consistency and Acyclicity: The directed causal precedence graph $G = (\mathcal{S}_I, \prec)$ must form a directed acyclic graph (DAG). The engine shall execute deterministic cycle detection via topological sorting (Tarjan strongly connected components or Kahn in-degree reduction). If any circular causal dependency or contradictory precedence chain ($s \prec^+ s$) is detected, the engine shall isolate the cycle and emit structured diagnostic error code `E0203` per REQ-0191.

  In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the engine shall implement synchronization token error recovery: upon recording any diagnostic (`E0200`, `E0201`, `E0202`, or `E0203`) into the preallocated diagnostic sink buffer $\mathcal{D}_{\text{sink}}$, the engine shall sever closing cyclic precedence edges in an overlay graph $\mathcal{E}_{\text{overlay}}$ and continue evaluating subsequent steps and interactions rather than aborting compilation. If accumulated diagnostics reach the sink capacity limit $C_{\text{max\_errors}}$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.

  All interaction definitions, step features, participant ends, and precedence relations shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009, REQ-0034, and REQ-0035, addressed exclusively via stable 32-bit typed node handles. In accordance with Architectural Directive 1 and REQ-0010, every lowered interaction and step node must receive an immutable, deterministic RFC 4122 UUIDv5 identifier derived from the compiler namespace OID and the fully qualified symbol path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))$). In accordance with Architectural Directive 3 and REQ-0036, scalar identifier tokens for interaction names, step names, and participant roles shall be interned into the global deduplicated symbol interner pool. Parallel verification of independent interaction graphs across separate compilation units shall be scheduled strictly onto a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with Architectural Directive 2 and REQ-0012. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs, evaluating performance gates (execution latency strictly below 25 ms, peak RSS memory strictly below 100 MB) exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests. All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Interaction_Alpha`, `Interaction_Beta`, `Participant_0`, `Participant_1`, `Participant_2`, `Step_1`, `Step_2`, `Step_Transfer`, `Payload_Type_A`, `Payload_Type_B`, `param_x : Real`) with zero hardcoded domain concepts.

- **Formal Invariant**: Let $\mathcal{T}_{\text{metamodel}}$ denote the KerML classifier specialization poset ordered by subtyping relation $\le_{\text{sub}}$. The dual inheritance invariant of `Interaction` is formalized as:

$$
\text{Interaction} \le_{\text{sub}} \text{Behavior} \;\wedge\; \text{Interaction} \le_{\text{sub}} \text{Association}
$$

The taxonomic ancestor chains of `Behavior` and `Association` satisfy:

$$
\begin{aligned}
\text{Behavior} &\le_{\text{sub}} \text{Class} \le_{\text{sub}} \text{Classifier} \le_{\text{sub}} \text{Type} \\
\text{Association} &\le_{\text{sub}} \text{Relationship} \;\wedge\; \text{Association} \le_{\text{sub}} \text{Classifier}
\end{aligned}
$$

Each lowered interaction classifier $I$ is formalized as a 6-tuple:

$$
I = \langle \text{id}, \text{owner}, \mathcal{P}_I, \mathcal{S}_I, \prec_I, \text{span} \rangle
$$

where:
- $\text{id} \in \mathcal{S}_{\text{sym}}$ is the interned scalar symbol handle of the interaction identifier,
- $\text{owner} \in \mathcal{H}_{\text{pkg}}$ is the enclosing package or namespace arena handle,
- $\mathcal{P}_I = \{ p_1, p_2, \dots, p_k \}$ ($k \ge 2$) is the finite set of participant end features,
- $\mathcal{S}_I = \{ s_1, s_2, \dots, s_m \}$ is the finite set of constituent step features,
- $\prec_I \subseteq \mathcal{S}_I \times \mathcal{S}_I$ is the binary causal precedence relation over constituent steps,
- $\text{span} = \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle$ is the source provenance coordinate span.

Each participant feature $p_i \in \mathcal{P}_I$ is formalized as:

$$
p_i = \langle \text{role}_i, \tau(p_i), \mu(p_i) \rangle
$$

where $\text{role}_i \in \mathcal{S}_{\text{sym}}$ is the interned role identifier, $\tau(p_i) \in \mathcal{H}_{\text{classifier}}$ is the participant classifier type handle, and $\mu(p_i) = [l_i, u_i]$ ($l_i \in \mathbb{N}_0$, $u_i \in \mathbb{N}_0 \cup \{ \infty \}$, $l_i \le u_i$) is the multiplicity interval. The participant cardinality invariant satisfies:

$$
|\mathcal{P}_I| \ge 2
$$

The causal precedence relation $\prec_I$ over constituent steps $\mathcal{S}_I$ defines an occurrence strict partial order (poset) satisfying the irreflexivity, asymmetry, and transitivity axioms:

$$
\forall s \in \mathcal{S}_I, \quad \neg(s \prec_I s)
$$

$$
\forall s_1, s_2 \in \mathcal{S}_I, \quad s_1 \prec_I s_2 \implies \neg(s_2 \prec_I s_1)
$$

$$
\forall s_1, s_2, s_3 \in \mathcal{S}_I, \quad (s_1 \prec_I s_2 \;\wedge\; s_2 \prec_I s_3) \implies s_1 \prec_I s_3
$$

Let $\tau_{\text{start}}(s) \in \mathbb{R}$ and $\tau_{\text{end}}(s) \in \mathbb{R}$ denote the initiation and termination timestamps of step execution $s \in \mathcal{S}_I$, with $\tau_{\text{start}}(s) \le \tau_{\text{end}}(s)$. The temporal realization of causal precedence satisfies:

$$
\forall s_1, s_2 \in \mathcal{S}_I, \quad s_1 \prec_I s_2 \implies \tau_{\text{end}}(s_1) \le \tau_{\text{start}}(s_2)
$$

Each message transfer step $s_{\text{transfer}} \in \mathcal{S}_I$ is formalized as:

$$
s_{\text{transfer}} = \langle e_{\text{send}}, e_{\text{recv}}, \delta_{\text{payload}}, p_{\text{src}}, p_{\text{tgt}}, \tau_{\text{msg}} \rangle
$$

where $p_{\text{src}}, p_{\text{tgt}} \in \mathcal{P}_I$, $e_{\text{send}}$ is the transmission event occurring at timestamp $\tau(e_{\text{send}})$, $e_{\text{recv}}$ is the reception event occurring at timestamp $\tau(e_{\text{recv}})$, $\delta_{\text{payload}}$ is the payload entity, and $\tau_{\text{msg}} \in \mathcal{H}_{\text{type}}$ is the declared message type.

Message transfer causality and denotational type conformance satisfy:

$$
\tau(e_{\text{send}}) \lt \tau(e_{\text{recv}}) \;\wedge\; \llbracket \delta_{\text{payload}} \rrbracket \in \llbracket \tau_{\text{msg}} \rrbracket
$$

with static subtyping validity:

$$
\tau(\delta_{\text{payload}}) \le_{\text{sub}} \tau_{\text{msg}}
$$

Let $G_I = (\mathcal{S}_I, \prec_I)$ denote the directed causal precedence graph. The acyclicity invariant is formalized via transitive closure $\prec_I^+$:

$$
\text{IsAcyclic}(G_I) \iff \forall s \in \mathcal{S}_I, \quad \neg(s \prec_I^+ s)
$$

Topological ordering existence invariant:

$$
\text{IsAcyclic}(G_I) \iff \exists \sigma : \mathcal{S}_I \to \{ 1, 2, \dots, |\mathcal{S}_I| \} \quad \text{such that} \quad \forall (s_1, s_2) \in \prec_I, \; \sigma(s_1) \lt \sigma(s_2)
$$

Diagnostic Code Binding Invariant: Violations of participant cardinality, directional causality, payload typing, or precedence acyclicity trigger structured diagnostic records in accordance with REQ-0191:

$$
\begin{aligned}
|\mathcal{P}_I| \lt 2 &\implies \text{Diagnostic}(I, \text{DiagnosticCode::E0200}, \text{InsufficientParticipants}) \in \mathcal{D}_{\text{sink}} \\
\tau(e_{\text{send}}) \ge \tau(e_{\text{recv}}) &\implies \text{Diagnostic}(s_{\text{transfer}}, \text{DiagnosticCode::E0201}, \text{MessageCausalityInversion}) \in \mathcal{D}_{\text{sink}} \\
\neg(\tau(\delta_{\text{payload}}) \le_{\text{sub}} \tau_{\text{msg}}) &\implies \text{Diagnostic}(s_{\text{transfer}}, \text{DiagnosticCode::E0202}, \text{PayloadTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists s \in \mathcal{S}_I : s \prec_I^+ s &\implies \text{Diagnostic}(I, \text{DiagnosticCode::E0203}, \text{InteractionCausalCycle}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Sanitized Overlay Precedence Graph Invariant: To prevent cascading diagnostics during error recovery, the closing back-edge of any detected causal cycle is severed in the analysis overlay graph $\mathcal{E}_{\text{overlay}}$:

$$
\prec_{I, \text{overlay}} = \prec_I \setminus \{ (u, v) \in \prec_I \mid u \prec_I^+ v \;\wedge\; v \prec_I^+ u \}
$$

$$
\text{IsAcyclic}((\mathcal{S}_I, \prec_{I, \text{overlay}})) \equiv \text{true}
$$

Deterministic UUIDv5 and Arena Node Handle Addressing Invariant: Every lowered interaction entity, participant end, step, and precedence relation receives an immutable UUIDv5 identifier and a stable arena node handle:

$$
\begin{aligned}
\forall u \in \{ I \} \cup \mathcal{P}_I \cup \mathcal{S}_I \cup \prec_I, \quad \text{UUID}(u) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u)) \\
\forall u \in \{ I \} \cup \mathcal{P}_I \cup \mathcal{S}_I \cup \prec_I, \quad \text{Handle}(u) &= \langle \text{ArenaId}, \text{Offset}_u \rangle \in \mathbb{N}_{32}
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Verification and semantic lowering of KerML interactions and constituent steps execute strictly within Complexity Class $\mathbf{P}$. For an interaction $I$ containing $V = |\mathcal{S}_I|$ constituent steps, $E = |\prec_I|$ causal precedence relations, and $K = |\mathcal{P}_I|$ participant end features, algorithmic bounds are established as follows:
  1. Participant Validation & Setup: Validating participant cardinality $K \ge 2$, role uniqueness, and multiplicity interval validity executes in deterministic $O(K)$ time.
  2. Step Registration & Type Conformance: Registering $V$ constituent steps and validating message transfer payload subtyping ($\tau(\delta_{\text{payload}}) \le_{\text{sub}} \tau_{\text{msg}}$) via precomputed subtyping lattice lookup tables executes in $O(1)$ time per step, requiring $O(V)$ total time. Directional timestamp comparisons $\tau(e_{\text{send}}) \lt \tau(e_{\text{recv}})$ execute in $O(1)$ scalar comparison time per transfer step.
  3. Precedence Graph Construction & In-Degree Array Allocation: Constructing the adjacency list and allocating dense in-degree tracking arrays indexed directly by 32-bit arena node handle offsets $\text{Offset}_s \in [0, V-1]$ executes in $O(V + E)$ time. Direct indexing eliminates dynamic hashing overhead and guarantees $O(1)$ constant time state mutations.
  4. Deterministic Acyclicity & Topological Sort: Executing Kahn's algorithm or Tarjan's strongly connected components algorithm on $G_I = (\mathcal{S}_I, \prec_I)$ processes each step vertex $s \in \mathcal{S}_I$ at most twice (enqueue and dequeue) and traverses each precedence edge $(s_1, s_2) \in \prec_I$ exactly once:

$$
T_{\text{topo}}(V, E) = \sum_{s \in \mathcal{S}_I} \left( O(1) + \sum_{s' \in \text{Succ}(s)} O(1) \right) \in O(V + E)
$$

  If a cycle is detected, reconstructing the deterministic cycle traceback path $\mathcal{P}_{\text{cycle}} = \langle s_1, s_2, \dots, s_p, s_1 \rangle$ executes in $O(V_C + E_C) \subseteq O(V + E)$ time via breadth-first traversal over the non-trivial strongly connected component.
  5. Total Sequential Complexity: Combining all analysis phases, total execution time for interaction $I$ is strictly linear with respect to the step and precedence graph size:

$$
T_{\text{total}}(V, E, K) \in O(K + V + E) \subseteq O(V + E) \quad (\text{since } K \le 2V)
$$

  6. Parallel Work-Stealing Scaling: When $M$ independent interactions $\{ I_1, I_2, \dots, I_M \}$ across disjoint packages are evaluated concurrently on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$:

$$
T_{\text{parallel}} \in O\left( \frac{\sum_{i=1}^M (V_i + E_i)}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  7. Space Complexity & Memory Bounds: Auxiliary working memory is strictly bounded by $O(V + E)$ for adjacency lists, the in-degree count array, and the topological evaluation queue. Memory for the diagnostic sink buffer is strictly bounded by $O(C_{\text{max\_errors}}) = O(1)$, guaranteeing that total auxiliary memory remains $O(V + E)$ with zero unbounded heap allocations.

- **Verification & Conformance Criteria**: Deterministic conformance shall be verified by automated test suites operating on synthetic MBSE models containing abstract placeholders (`Package_0`, `Interaction_Alpha`, `Interaction_Beta`, `Participant_0`, `Participant_1`, `Participant_2`, `Step_1`, `Step_2`, `Step_3`, `Step_Transfer`, `Payload_Type_A`, `Payload_Type_B`, `param_x : Real`). Conformance validation shall enforce the following test gates:
  1. Dual Inheritance Metamodel Gate: Ingest an interaction declaration `Interaction_Alpha` specializing `Behavior` and `Association`. Assert that the metamodel lowered AST node exhibits dual generalization edges to both `Behavior` and `Association`, and inherits features from both classifier roots without ambiguity.
  2. Minimum Participant Cardinality Gate: Ingest an interaction `Interaction_Alpha` specifying only 1 participant `Participant_0`. Assert that the lowering engine rejects the malformed interaction and emits structured diagnostic error code `E0200` (`InsufficientParticipants`). Re-test with 2 participants (`Participant_0`, `Participant_1`) and assert valid compilation with zero diagnostics.
  3. Acyclic Precedence DAG Gate: Ingest an interaction `Interaction_Alpha` containing 3 steps (`Step_1`, `Step_2`, `Step_3`) with causal precedence relations `Step_1 \prec Step_2` and `Step_2 \prec Step_3`. Assert that topological sort succeeds, yielding valid execution sequence $\langle \text{Step\_1}, \text{Step\_2}, \text{Step\_3} \rangle$ with zero diagnostics emitted.
  4. Causal Cycle Detection & Traceback Gate: Ingest an interaction containing a circular precedence chain `Step_1 \prec Step_2`, `Step_2 \prec Step_3`, and `Step_3 \prec Step_1`. Assert that the cycle detection engine isolates the cycle, emits structured diagnostic error code `E0203` (`InteractionCausalCycle`), and provides an ordered cycle traceback path $\langle \text{Step\_1}, \text{Step\_2}, \text{Step\_3}, \text{Step\_1} \rangle$ with accurate source byte spans.
  5. Message Transfer Directional Causality Gate: Ingest a message transfer step $s_{\text{transfer}}$ between `Participant_0` and `Participant_1` where the reception timestamp precedes the transmission timestamp ($\tau(e_{\text{send}}) = 10.0$, $\tau(e_{\text{recv}}) = 8.0$) or equals it ($\tau(e_{\text{send}}) = \tau(e_{\text{recv}}) = 5.0$). Assert deterministic emission of structured diagnostic error code `E0201` (`MessageCausalityInversion`).
  6. Payload Subtyping Conformance Gate: Ingest a message transfer step $s_{\text{transfer}}$ declared with message classifier type `Payload_Type_A`. Inject a payload entity $\delta_{\text{payload}}$ of type `Payload_Type_B`, where `Payload_Type_B` does not specialize `Payload_Type_A`. Assert deterministic emission of structured diagnostic error code `E0202` (`PayloadTypeMismatch`). Inject a conforming subtype and assert successful type checking with zero diagnostics.
  7. Synchronization Token Error Recovery Gate: Ingest an interaction model containing two independent faults (a causal cycle between `Step_1` and `Step_2`, and a payload type mismatch in `Step_Transfer`). Assert that synchronization token error recovery accumulates both diagnostic records (`E0203` and `E0202`) into $\mathcal{D}_{\text{sink}}$, prunes the closing cycle edge in $\mathcal{E}_{\text{overlay}}$, and successfully analyzes remaining independent steps without crashing. Inject malformed steps exceeding $C_{\text{max\_errors}}$ and assert graceful compilation halt with terminal code `E0199`.
  8. Deterministic UUIDv5 Anchor Gate: Assert that 100% of generated interaction nodes, participant end features, step features, and precedence edges receive deterministic RFC 4122 UUIDv5 identifiers computed from the compiler namespace OID and canonical fully qualified names per REQ-0010.
  9. Bounded Work-Stealing Parallelism Gate: Concurrently verify $10^4$ synthetic interaction models across $N_{\text{max\_workers}}$ threads in the bounded work-stealing pool. Assert data-race freedom, zero deadlocks, and 100% bitwise identical diagnostic outputs compared to single-threaded sequential execution.
  10. Deterministic Non-Panicking Execution & Performance Gate: Execute verification across deeply nested and pathologically malformed interaction models. Assert total-function termination with zero panics or uncaught exceptions. In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, assert that verifying $10^4$ interaction step nodes executes in under 25 ms and peak RSS memory remains strictly below 100 MB.
  11. Bitwise Determinism & Zero Diff Churn Gate: Re-run compilation on an unmodified interaction AST. Assert that generated diagnostic collections, node handles, and topological schedules exhibit 0-byte diff churn across successive runs.
