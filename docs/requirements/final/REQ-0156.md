### REQ-0156: Earliest Deadline First (EDF) Dynamic Schedulability Verification

- **Normative Statement**: The Level 1C Interface Control Documents (ICD) synthesis engine, real-time interconnect contract verifier, and dynamic schedulability analyzer of Subsystem 8 shall perform Earliest Deadline First (EDF) dynamic schedulability verification for all periodic and sporadic transmission tasks mapped across shared communication buses, multiplexed interconnect channels, and network interfaces. The engine shall verify that total channel utilization satisfies the exact schedulability bound ($U \le 1.0$) for implicit deadline task systems ($D_i = T_i$), or evaluate the Processor Demand Criterion (PDC) over the synchronous busy period $L^*$ for constrained deadline task systems ($D_i \le T_i$, with $\exists i : D_i < T_i$). If total utilization exceeds capacity ($U > 1.0$) or if processor demand exceeds available transmission time ($\exists t \in \mathcal{D} : h(t) > t$), the compiler shall fail closed and emit diagnostic error code `E0444`.

  Specifically, the ICD dynamic schedulability verification engine and interconnect contract validator shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Transmission Task Set Formalization & Channel Extraction**:
     - The verification engine shall extract transmission tasks $\tau_i \in \Gamma_K$ mapped to each shared interconnect channel $K \in \mathcal{K}$ from the Master Signal Flow Dictionary (REQ-0148), Channel Allocation Rosters (REQ-0147), and Connection Binding Rosters (REQ-0150).
     - Each transmission task $\tau_i$ represents the recurring transmission of a discrete message payload, structured telemetry frame, or multiplexed flow packet over channel $K$.
     - Each task $\tau_i$ shall declare:
       - Worst-case transmission duration / execution time $C_i \in \mathbb{Q}^+$, derived from payload serialization bit length, protocol framing overhead (REQ-0157), and channel bandwidth capacity (REQ-0154), or explicitly defined worst-case transmission time (WCET per REQ-0158);
       - Relative transmission deadline $D_i \in \mathbb{Q}^+$, defining the maximum tolerable elapsed duration from task release to complete transmission reception;
       - Transmission period or minimal inter-arrival time $T_i \in \mathbb{Q}^+$, defining the recurrence interval for periodic flows or minimal separation interval for sporadic flows.
     - All timing parameters ($C_i, D_i, T_i$) shall be stored as exact irreducible rational numbers in the formal metrology time dimension $[0, 0, 1, 0, 0, 0, 0]^T \in \mathbb{Q}^7$ (REQ-0098, REQ-0152). Floating-point representations (`f32`, `f64`) are strictly prohibited to eliminate rounding divergence and ensure bitwise reproducible schedulability outcomes.
     - Parameter validity requirement: Every task must satisfy positive execution time, deadline, and period ($C_i > 0$, $D_i > 0$, $T_i > 0$), and individual execution time shall not exceed relative deadline ($C_i \le D_i$). If $C_i > D_i$, the task is intrinsically unschedulable and the compiler shall immediately fail closed with diagnostic error code `E0444` (`ExecutionTimeExceedsDeadline`).
  2. **Implicit Deadline Task Set Verification ($D_i = T_i$)**:
     - When all transmission tasks assigned to channel $K$ have relative deadlines equal to their respective periods ($\forall \tau_i \in \Gamma_K, \; D_i = T_i$):
       - The verification engine shall calculate total channel utilization as the rational summation:
         $$U(\Gamma_K) = \sum_{i=1}^n \frac{C_i}{T_i}$$
       - The engine shall evaluate the exact Liu & Layland dynamic schedulability condition:
         $$U(\Gamma_K) \le 1.0$$
       - Exact Schedulability Guarantee: Under preemptive Earliest Deadline First scheduling, $U(\Gamma_K) \le 1.0$ is both necessary and sufficient. If $U(\Gamma_K) \le 1.0$, the task set is proven to meet 100% of transmission deadlines without queue overflow or frame drop.
       - Overload Rejection Gate: If $U(\Gamma_K) > 1.0$, the channel is oversubscribed; the compiler shall fail closed and emit diagnostic error code `E0444` (`UtilizationOverloadViolation`), citing the channel identifier, total utilization $U(\Gamma_K)$, individual task utilization components, and source byte spans.
  3. **Constrained Deadline Task Set Verification ($D_i \le T_i$)**:
     - When one or more transmission tasks declare constrained deadlines ($D_i \le T_i$, with $\exists i : D_i < T_i$):
       - The utilization bound $U(\Gamma_K) \le 1.0$ is necessary but insufficient to guarantee schedulability. The engine shall first check $U(\Gamma_K) \le 1.0$; if $U(\Gamma_K) > 1.0$, it shall fail closed immediately with diagnostic error code `E0444`.
       - If $U(\Gamma_K) \le 1.0$, the engine shall execute the exact Processor Demand Criterion (PDC) by evaluating the Demand Bound Function $h(t)$:
         $$h(t) = \sum_{i=1}^n \max\left(0, \; \left\lfloor \frac{t - D_i}{T_i} \right\rfloor + 1\right) C_i$$
       - Schedulability Condition: The task set is schedulable under EDF if and only if for all testing points $t \in \mathcal{D}_K$, processor demand does not exceed interval length:
         $$\forall t \in \mathcal{D}_K, \quad h(t) \le t$$
       - Finite Testing Point Horizon ($L^*$): Testing points shall be evaluated strictly within the synchronous busy period horizon $[0, L^*]$:
         $$\mathcal{D}_K = \left\{ k \cdot T_i + D_i \le L^* \mid k \in \mathbb{N}_0, \; 1 \le i \le n \right\}$$
       - Busy Period Length ($L^*$):
         - The synchronous busy period length $L_{\text{busy}}$ is computed via fixed-point iteration:
           $$w^{(0)} = \sum_{i=1}^n C_i, \quad w^{(m+1)} = \sum_{i=1}^n \left\lceil \frac{w^{(m)}}{T_i} \right\rceil C_i$$
           terminating at the first step where $w^{(m+1)} = w^{(m)} = L_{\text{busy}}$.
         - When $U(\Gamma_K) < 1.0$, the Baruah upper bound $L_B$ is evaluated:
           $$L_B = \max\left( \max_{1 \le i \le n} D_i, \; \frac{\sum_{i=1}^n (T_i - D_i) \frac{C_i}{T_i}}{1 - U(\Gamma_K)} \right)$$
         - The testing horizon is bounded by $L^* = \min(L_{\text{busy}}, L_B)$ if $U(\Gamma_K) < 1.0$, and $L^* = L_{\text{busy}}$ if $U(\Gamma_K) = 1.0$.
       - Testing Set Sorting & Monotonic Evaluation: The engine shall construct testing set $\mathcal{D}_K$, deduplicate identical deadlines, sort them in strictly ascending order, and evaluate $h(t) \le t$ at each point $t \in \mathcal{D}_K$.
       - PDC Violation Gate: If for any $t \in \mathcal{D}_K$, $h(t) > t$, the engine shall abort further point checks for that channel, fail closed, and emit diagnostic error code `E0444` (`ProcessorDemandCriterionViolation`), specifying failing instant $t$, cumulative demand $h(t)$, deficit $h(t) - t$, and contributing task instances.
  4. **Non-Preemptive Physical Transmission Framing Invariant**:
     - Where physical communication links require non-preemptible message transmission frames (e.g., serial busses, CAN frames, Ethernet packets without preemption), the engine shall incorporate the maximum blocking term:
       $$B_i = \max_{j : \tau_j \in \Gamma_K \setminus \{\tau_i\}} C_j^{\text{frame}}$$
       where $C_j^{\text{frame}} \le C_j$ is the longest non-preemptible frame duration.
     - For non-preemptive EDF verification, the demand criterion is strengthened to:
       $$\forall t \in \mathcal{D}_K, \quad h(t) + \max_{j : T_j > t} C_j^{\text{frame}} \le t$$
       guaranteeing that lower-priority message transmission already in flight cannot cause high-priority dynamic deadline inversions exceeding tolerance.
  5. **Delineation from Rate Monotonic Scheduling (REQ-0155)**:
     - The compiler shall support declarative scheduling policy selection on interconnect channels (`policy = EDF` vs `policy = RMS`).
     - When `policy = EDF` is selected, the engine shall apply REQ-0156 instead of the Liu-Layland RMS fixed-priority bound ($n(2^{1/n} - 1)$ per REQ-0155), enabling channel designers to achieve up to 100% link utilization without fixed-priority rate-monotonic underutilization penalties.
  6. **Contiguous Bump Arena Storage & Node Handles**:
     - All transmission task records, schedulability analysis descriptors, testing sets $\mathcal{D}_K$, and verification witnesses shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit arena node handles in accordance with REQ-0035.
  7. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every task record $\tau_i$, channel task set $\Gamma_K$, and schedulability verification outcome witness shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the node fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))$) in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel schedulability verification across multiple independent interconnect channels $K_1, K_2, \dots, K_m$ shall execute strictly on a centralized, bounded work-stealing thread pool with worker upper bound $N_{\text{max\_workers}}$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Task names, signal labels, channel identifiers, and diagnostic strings shall be interned into the deduplicated global symbol interner pool during lexical analysis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The dynamic schedulability verification engine shall implement synchronization token error recovery on channel declaration boundaries and statement delimiters (`;`) in accordance with REQ-0013 and REQ-0016. When schedulability violations occur (`E0444`), the engine shall record structured diagnostics into the preallocated error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels ($\bot_{\text{sched}}$), and continue validating remaining channels. If accumulated diagnostics reach capacity limit $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The dynamic schedulability verification engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency (strictly under 25 ms for $|\mathcal{K}| = 50$ channels and $10^3$ transmission tasks) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  8. **Pure Abstract MBSE Placeholder Mandate**:
     - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Subsystem_0`, `Subsystem_1`, `Channel_0`, `Channel_1`, `Port_0`, `Port_1`, `Flow_0`, `Flow_1`, `Task_0`, `Task_1`, `Task_i`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes in contiguous bump arena storage, and let $\mathcal{S}_{\text{intern}}$ denote the deduplicated global symbol interner pool.

  Let $\mathcal{K} \subset \mathcal{V}_{\text{AST}}$ denote the finite set of communication channels, physical buses, and multiplexed interconnects cataloged in the Level 1C Interface Control Document.

  Let $\mathcal{T} \subset \mathcal{V}_{\text{AST}}$ denote the universe of periodic and sporadic transmission tasks. For each channel $K \in \mathcal{K}$, let $\Gamma_K \subset \mathcal{T}$ denote the set of transmission tasks mapped to channel $K$:

  $$
  \Gamma_K = \{ \tau_1, \tau_2, \dots, \tau_n \}
  $$

  where channel task assignments form disjoint subsets of $\mathcal{T}$:

  $$
  \forall K_a, K_b \in \mathcal{K} \text{ with } K_a \ne K_b, \quad \Gamma_{K_a} \cap \Gamma_{K_b} = \emptyset
  $$

  Each transmission task $\tau_i \in \Gamma_K$ is formalized as an 8-tuple:

  $$
  \tau_i = \langle \text{id}_i, \text{name}_i, C_i, D_i, T_i, K, \Delta_i, \text{span}_i \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_i &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_i &\in \mathcal{S}_{\text{intern}} \quad (\text{interned task symbol identifier}) \\
  C_i &\in \mathbb{Q}^+ \quad (\text{worst-case transmission duration, } C_i = p_{C,i} / q_{C,i}, \; p_{C,i}, q_{C,i} \in \mathbb{Z}^+) \\
  D_i &\in \mathbb{Q}^+ \quad (\text{relative transmission deadline, } D_i = p_{D,i} / q_{D,i}, \; p_{D,i}, q_{D,i} \in \mathbb{Z}^+) \\
  T_i &\in \mathbb{Q}^+ \quad (\text{transmission period / minimum inter-arrival time, } T_i = p_{T,i} / q_{T,i}, \; p_{T,i}, q_{T,i} \in \mathbb{Z}^+) \\
  K &\in \mathcal{K} \quad (\text{assigned communication channel handle}) \\
  \Delta_i &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_i &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
  $$

  Every valid task must satisfy the strict parameter bounding invariant:

  $$
  \forall \tau_i \in \Gamma_K, \quad 0 < C_i \le D_i \le T_i \quad \text{or} \quad (0 < C_i \le D_i \wedge D_i > T_i)
  $$

  For constrained and implicit deadline systems addressed herein:

  $$
  \forall \tau_i \in \Gamma_K, \quad 0 < C_i \le D_i \le T_i
  $$

  1. Channel Total Resource Utilization Invariant:
  For each channel $K \in \mathcal{K}$, total resource utilization $U(\Gamma_K)$ is defined as:

  $$
  U(\Gamma_K) = \sum_{i=1}^n \frac{C_i}{T_i} \in \mathbb{Q}^+
  $$

  2. Implicit Deadline Schedulability Invariant ($D_i = T_i$):
  If all transmission tasks on channel $K$ satisfy $D_i = T_i$:

  $$
  \left( \forall \tau_i \in \Gamma_K, \; D_i = T_i \right) \implies \left( \text{Schedulable}_{\text{EDF}}(\Gamma_K) \iff U(\Gamma_K) \le 1.0 \right)
  $$

  3. Constrained Deadline Processor Demand Criterion (PDC) Invariant ($D_i \le T_i$):
  For any time interval of duration $t \ge 0$, the cumulative processor demand function $h(t)$ is defined as:

  $$
  h(t) = \sum_{i=1}^n \max\left(0, \; \left\lfloor \frac{t - D_i}{T_i} \right\rfloor + 1\right) C_i
  $$

  The finite testing set $\mathcal{D}_K$ of absolute deadline evaluation points is defined as:

  $$
  \mathcal{D}_K = \left\{ k \cdot T_i + D_i \mid k \in \mathbb{N}_0, \; 1 \le i \le n, \; k \cdot T_i + D_i \le L^* \right\}
  $$

  where the synchronous busy period upper evaluation bound $L^*$ is computed as:

  $$
  \begin{aligned}
  w^{(0)} &= \sum_{i=1}^n C_i \\
  w^{(m+1)} &= \sum_{i=1}^n \left\lceil \frac{w^{(m)}}{T_i} \right\rceil C_i \\
  L_{\text{busy}} &= w^{(m^*)} \quad \text{such that } w^{(m^*)} = w^{(m^*-1)} \\
  L_B &= \max\left( \max_{1 \le i \le n} D_i, \; \frac{\sum_{i=1}^n (T_i - D_i) \frac{C_i}{T_i}}{1 - U(\Gamma_K)} \right) \quad (\text{defined for } U(\Gamma_K) < 1.0) \\
  L^* &= \begin{cases} \min(L_{\text{busy}}, L_B) & \text{if } U(\Gamma_K) < 1.0 \\ L_{\text{busy}} & \text{if } U(\Gamma_K) = 1.0 \end{cases}
  \end{aligned}
  $$

  The task set $\Gamma_K$ satisfies the Processor Demand Criterion if and only if demand does not exceed available transmission time at every point in $\mathcal{D}_K$:

  $$
  \text{Schedulable}_{\text{EDF}}(\Gamma_K) \iff \left( U(\Gamma_K) \le 1.0 \;\wedge\; \forall t \in \mathcal{D}_K, \; h(t) \le t \right)
  $$

  4. Non-Preemptive Framing Extension Invariant:
  When physical transmissions are subject to non-preemptible message frame boundaries with frame length $C_j^{\text{frame}} \le C_j$:

  $$
  \text{Schedulable}_{\text{NP-EDF}}(\Gamma_K) \iff \left( U(\Gamma_K) \le 1.0 \;\wedge\; \forall t \in \mathcal{D}_K, \; h(t) + \max_{\substack{j \in \{1,\dots,n\} \\ T_j > t}} C_j^{\text{frame}} \le t \right)
  $$

  5. Deterministic Diagnostic Trigger Rules (REQ-0191):

  $$
  \begin{aligned}
  \exists \tau_i \in \mathcal{T} : C_i > D_i &\implies \text{Diagnostic}(\tau_i, \text{DiagnosticCode::E0444}, \text{ExecutionTimeExceedsDeadline}) \in \mathcal{D}_{\text{sink}} \\
  \exists \tau_i \in \mathcal{T} : (C_i \le 0 \lor D_i \le 0 \lor T_i \le 0) &\implies \text{Diagnostic}(\tau_i, \text{DiagnosticCode::E0444}, \text{NonPositiveTaskParameter}) \in \mathcal{D}_{\text{sink}} \\
  \exists K \in \mathcal{K} : U(\Gamma_K) > 1.0 &\implies \text{Diagnostic}(K, U(\Gamma_K), \text{DiagnosticCode::E0444}, \text{UtilizationOverloadViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists K \in \mathcal{K}, \; \exists t \in \mathcal{D}_K : h(t) > t &\implies \text{Diagnostic}(K, t, h(t), \text{DiagnosticCode::E0444}, \text{ProcessorDemandCriterionViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

  6. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

  $$
  \begin{aligned}
  \Delta_{\tau_i} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\tau_i)) \\
  \Delta_{\Gamma_K} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(K) \mathbin{\Vert} \text{"::TaskSet"}) \\
  \Delta_{\text{witness}(K)} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(K) \mathbin{\Vert} \text{"::EDFSchedulabilityWitness"})
  \end{aligned}
  $$

- **Computational Complexity & Algorithmic Bounds**: Earliest Deadline First Dynamic Schedulability Verification exhibits exact partitioned complexity bounds depending on task deadline classification:
  - For **implicit deadline task sets** ($D_i = T_i$): Resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in strictly deterministic linear time $O(n)$ where $n = |\Gamma_K|$ is the number of transmission tasks mapped to channel $K$.
  - For **constrained deadline task sets** ($D_i \le T_i$): Resides in **Pseudo-Polynomial Time** $O(|\mathcal{D}_K| \cdot n)$ when channel utilization is bounded away from unity ($U(\Gamma_K) \le 1 - \epsilon$ for some fixed $\epsilon > 0$). In the unconstrained general case where utilization approaches 1 with arbitrary input periods encoded in binary, EDF schedulability verification over constrained deadlines is coNP-hard. In the DEAP compiler, because task periods and transmission lengths are derived from discrete engineering interconnect registers and bounded operational frequencies, $|\mathcal{D}_K|$ is strictly finite and pseudo-polynomially bounded by the hyperperiod or synchronous busy period $L^*$.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 solves qualitative temporal consistency over occurrence lifecycles using Allen's 13 interval relations and ORD-Horn difference logic SMT solving in $O(N^3)$ time. In contrast, REQ-0156 evaluates quantitative numeric execution times, periods, and deadlines over real-time communication channels via cumulative demand step functions.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses structural allocation, interconnect clustering, and logical channel multiplexing via strongly NP-hard vector bin packing. In contrast, REQ-0156 verifies temporal schedulability of transmission tasks already assigned to an allocated channel, evaluating dynamic priority deadline constraints without bin packing or channel assignment optimization.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 resolves multiple inheritance subtyping lattices, redefinitions, and conjugations via C3 linearization in deterministic $O(V + E)$ time. In contrast, REQ-0156 performs temporal schedulability analysis on numeric task sets rather than type-theoretic poset linearization.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 solves minimal hitting sets over STPA hazard cut-sets (NP-complete). In contrast, REQ-0156 evaluates deterministic arithmetic demand functions $h(t)$ along a discrete time horizon.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 resolves orthogonal discrete state machine reachability, deadlock, and livelock (PSPACE-complete in general, NP-complete for bounded unrolling). In contrast, REQ-0156 evaluates deterministic processor demand functions over a 1-dimensional time horizon without exploring state product graphs.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks via linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0156 evaluates discrete periodic message transmission timing on interconnects.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs register allocation and instruction scheduling in LUMI IR basic blocks via Chaitin graph coloring (NP-complete). In contrast, REQ-0156 operates at the architectural ICD interconnect contract layer.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the satisfiability of first-order invariant contracts via DPLL(T) SMT solvers. In contrast, REQ-0156 evaluates closed-form rational summations and floor functions over sorted testing points.

  **Asymptotic Complexity Analysis**:
  Let $n = |\Gamma_K|$ denote the number of tasks on channel $K$, and let $|\mathcal{K}|$ denote the total number of channels in the Level 1C ICD.
  1. *Implicit Deadline Utilization Check*:
     - Computing total utilization $U(\Gamma_K) = \sum_{i=1}^n \frac{C_i}{T_i}$ requires $n$ rational additions and divisions.
     - For bounded 64-bit integer rational coordinates, each operation executes in strictly $O(1)$ CPU cycles.
     - Total time and auxiliary space bounds:
       $$T_{\text{implicit}}(n) \in O(n), \quad S_{\text{implicit}}(n) \in O(1)$$
  2. *Synchronous Busy Period Fixed-Point Iteration*:
     - The sequence $w^{(0)}, w^{(1)}, \dots, w^{(m^*)}$ is monotonically non-decreasing.
     - Each iteration requires $n$ ceiling evaluations and rational multiplications, taking $O(n)$ time.
     - The number of iterations $m^*$ is bounded by $L_{\text{busy}} / \min_i C_i$.
     - Total time for busy period convergence:
       $$T_{\text{busy}}(n) \in O(m^* \cdot n)$$
  3. *Testing Set Generation & Sorting*:
     - Generating points $k \cdot T_i + D_i \le L^*$ produces $|\mathcal{D}_K|$ elements, where:
       $$|\mathcal{D}_K| \le \sum_{i=1}^n \left( \left\lfloor \frac{L^* - D_i}{T_i} \right\rfloor + 1 \right)$$
     - Deduplicating and sorting $\mathcal{D}_K$ requires:
       $$T_{\text{sort}}(|\mathcal{D}_K|) \in O(|\mathcal{D}_K| \log |\mathcal{D}_K|)$$
  4. *Processor Demand Function Evaluation*:
     - Evaluating $h(t)$ at a single testing point $t \in \mathcal{D}_K$ requires iterating over $n$ tasks, computing floor functions, and summing demand, taking strictly $O(n)$ operations.
     - Evaluating $h(t) \le t$ across all $|\mathcal{D}_K|$ testing points requires:
       $$T_{\text{PDC}}(n, |\mathcal{D}_K|) \in O(|\mathcal{D}_K| \cdot n)$$
     - With early termination upon the first failing testing instant $t^*$.
  5. *Aggregate Sequential Complexity across all Channels*:
     - Summing across all $|\mathcal{K}|$ interconnect channels:
       $$T_{\text{total}} \in O\left( \sum_{K \in \mathcal{K}} \left( n_K + |\mathcal{D}_K| \log |\mathcal{D}_K| + |\mathcal{D}_K| \cdot n_K \right) \right)$$
     - Space complexity is bounded by preallocated contiguous bump arena storage for task descriptors, testing points, and verification outcome witnesses:
       $$S_{\text{total}} \in O\left( \sum_{K \in \mathcal{K}} (n_K + |\mathcal{D}_K|) \right)$$
  6. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning independent channels $K \in \mathcal{K}$ across $N_{\text{max\_workers}}$ threads on the bounded work-stealing thread pool yields:
       $$T_{\text{parallel}} \in O\left( \frac{\sum_{K \in \mathcal{K}} |\mathcal{D}_K| \cdot n_K}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)$$
     - Near-linear speedup with minimal synchronization overhead.
  7. *Memory Allocations & Zero-Copy Preservation*:
     - All task parameter tuples, busy period records, sorted testing arrays, and verification witnesses reside in preallocated contiguous bump arena storage.
     - The error sink buffer is capped at capacity $C_{\text{max\_errors}}$, requiring strictly $O(1)$ auxiliary storage. Heap allocations outside the symbol interner are strictly zero.
