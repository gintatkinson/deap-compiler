### REQ-0175: LUMI Intermediate Representation (LUMI IR): SSA Basic Blocks & Control Flow Graph

- **Normative Statement**: The code generation engine, intermediate representation lowering pipeline, and intermediate representation verification framework of Subsystem 10 shall lower abstract syntax tree (AST) behaviors, action sequences, calculations, discrete state machine transitions, operational flows, and mathematical constraints into a strongly-typed Static Single Assignment (SSA) intermediate representation denoted as LUMI IR. LUMI IR shall structure all executable logic as a directed Control Flow Graph (CFG) of basic blocks $`\mathcal{G}_{\text{cfg}} = (\mathcal{B}, \mathcal{E}_{\text{cfg}})`$`. The compiler shall enforce that every basic block `$`B \in \mathcal{B}`$` contains an optional sequence of `$`\phi`$`-node instructions (`$`\Phi`$`-nodes) at join points, a linear sequence of non-terminator SSA body instructions, and terminates with exactly one control flow terminator instruction concluding the block. The compiler shall verify that every SSA value variable `$`v \in \mathcal{V}_{\text{ssa}}`$` satisfies the single-definition invariant `$`|\text{Def}(v)| = 1`$`, and that every variable use `$`u \in \text{Uses}(v)`$` is strictly dominated by its unique definition site `$`\text{Def}(v)`$` within the function dominator tree `$`\mathcal{T}_{\text{dom}}`$`. If any variable definition count violates `$`|\text{Def}(v)| = 1`$`, any use violates dominance, any `$`\phi`$-node exhibits arity or predecessor divergence, or any basic block violates terminator invariants, the compiler shall fail closed and emit diagnostic error code `E0500`.

  Specifically, the code generation engine, IR lowering pipeline, and verification framework shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **AST Behavior Lowering & CFG Topology Construction**:
     - The code generation engine shall lower AST behavioral elements, including SysML v2 action definitions (`action def`, REQ-0078), calculation definitions (`calc def`, REQ-0082), state transition actions (REQ-0080), state lifecycle hooks (REQ-0081), and discrete simulation steppers (REQ-0127) into discrete LUMI IR functions $`\mathcal{F}_{\text{lumi}}`$.
     - Each LUMI IR function $`F \in \mathcal{F}_{\text{lumi}}`$` shall be structured as a rooted directed Control Flow Graph `$`\mathcal{G}_{\text{cfg}} = (\mathcal{B}, \mathcal{E}_{\text{cfg}})`$`, where `$`\mathcal{B}`$` is the non-empty finite set of basic blocks and `$`\mathcal{E}_{\text{cfg}} \subseteq \mathcal{B} \times \mathcal{B}`$ is the set of directed control flow transitions.
     - Every function $`F`$` shall possess exactly one distinguished entry basic block `$`B_{\text{entry}} \in \mathcal{B}`$` having zero predecessor edges (`$`\text{pred}(B_{\text{entry}}) = \emptyset`$).
     - For every reachable basic block $`B \in \mathcal{B}`$`, there shall exist at least one directed path from `$`B_{\text{entry}}`$` to `$`B`$` in `$`\mathcal{G}_{\text{cfg}}`$`. If any unreachable block `$`B_{\text{dead}} \in \mathcal{B} \setminus \{B_{\text{entry}}\}`$` is detected where `$`\text{Paths}(B_{\text{entry}}, B_{\text{dead}}) = \emptyset`$, the compiler shall emit diagnostic error code `E0500` (`CFGUnreachableBlockViolation`).
  2. **Basic Block Internal Linear Structure & Terminator Invariant**:
     - A basic block $`B \in \mathcal{B}`$ is a maximal sequence of linear instructions satisfying the single-entry, single-exit execution invariant.
     - The interior instructions of basic block $`B`$ must execute strictly sequentially without internal branching, jumps, or external entry points.
     - Each basic block $`B`$ shall comprise three strictly ordered regions:
       - Leading $`\phi`$`-node section (`$`\mathbf{\Phi}_B`$): An optional sequence of zero or more parallel join instructions defining SSA value registers;
       - Body instruction section ($`\mathbf{I}_B`$): An optional sequence of zero or more non-terminator linear instructions (arithmetic, logical, bitwise, memory allocation, load, store, cast, function invocation);
       - Terminator instruction ($`T_B`$): Exactly one control flow terminator concluding the block.
     - Supported control flow terminators shall include unconditional branch (`br label`), conditional branch (`cond_br cond, label_true, label_false`), function return (`ret val` or `ret void`), multi-way switch (`switch val, default_label, [case_val: label]`), and unreachable sentinel (`unreachable`).
     - If a basic block lacks a terminator instruction, contains multiple terminators, or contains a terminator in a non-terminal position, the compiler shall emit diagnostic error code `E0500` (`CFGTerminatorMissingViolation`).
     - Every target label referenced by terminator $`T_B`$` must correspond to a valid successor basic block `$`B' \in \mathcal{B}`$` such that `$`(B, B') \in \mathcal{E}_{\text{cfg}}`$. If a terminator references a non-existent block label, the compiler shall emit diagnostic error code `E0500` (`CFGMalformedEdgeViolation`).
  3. **Static Single Assignment (SSA) Value Register Invariant**:
     - LUMI IR enforces strict Static Single Assignment semantics over an unbounded set of virtual value registers $`\mathcal{V}_{\text{ssa}}`$.
     - Every value register $`v \in \mathcal{V}_{\text{ssa}}`$` defined within function `$`F`$ shall possess exactly one assignment instruction across the entire function CFG:

```math
\forall v \in \mathcal{V}_{\text{ssa}}(F), \quad |\text{Def}(v)| = 1
```

     - If any register $`v`$` is assigned more than once (`$`|\text{Def}(v)| \gt 1`$), the compiler shall emit diagnostic error code `E0500` (`SSAMultipleDefinitionViolation`).
     - If any instruction references a register $`v`$` that has no definition site in the function (`$`|\text{Def}(v)| = 0`$), the compiler shall emit diagnostic error code `E0500` (`SSAUseWithoutDefinitionViolation`).
  4. **Join Block $`\phi`$-Node Semantics & Predecessor Bijective Binding**:
     - At every confluence or join block $`B \in \mathcal{B}`$` possessing multiple incoming control flow edges (`$`|\text{pred}(B)| = k \ge 2`$`), converging values from distinct execution paths must be merged exclusively via `$`\phi`$-node instructions.
     - Each $`\phi`$`-node instruction defining register `$`v_{\phi}`$` shall bind an explicit set of `$`k`$` incoming tuples `$`\langle v_i, B_i \rangle`$:

```math
v_{\phi} = \phi\left( \langle v_1, B_1 \rangle, \langle v_2, B_2 \rangle, \dots, \langle v_k, B_k \rangle \right)
```

     - The set of incoming basic block labels $`\{B_1, B_2, \dots, B_k\}`$` in the `$`\phi`$`-node must bijectively match the predecessor set `$`\text{pred}(B)`$` of block `$`B`$:

```math
\{ B_1, B_2, \dots, B_k \} = \text{pred}(B) \quad \wedge \quad k = |\text{pred}(B)|
```

     - If the number of incoming operands in a $`\phi`$`-node does not equal `$`|\text{pred}(B)|`$, the compiler shall emit diagnostic error code `E0500` (`PhiNodeArityMismatchViolation`).
     - If a $`\phi`$`-node specifies an incoming predecessor block `$`B_i \notin \text{pred}(B)`$, the compiler shall emit diagnostic error code `E0500` (`PhiNodePredecessorDivergenceViolation`).
     - If the static data types of incoming operands $`\tau(v_i)`$` do not conform identically to the defined register type `$`\tau(v_{\phi})`$, the compiler shall emit diagnostic error code `E0500` (`PhiNodeTypeMismatchViolation`).
     - Blocks with at most one predecessor ($`|\text{pred}(B)| \le 1`$`) must not contain any `$`\phi`$`-node instructions; any `$`\phi`$-node in a single-predecessor block shall trigger diagnostic error code `E0500` (`PhiNodeInSinglePredecessorBlockViolation`).
  5. **Dominance Tree & Strict Dominance Property Enforcement**:
     - Let $`\mathcal{T}_{\text{dom}}(F) = (\mathcal{B}, \mathcal{E}_{\text{dom}})`$` denote the directed dominator tree of function `$`F`$`, rooted at `$`B_{\text{entry}}`$.
     - A basic block $`B_d`$` dominates block `$`B_u`$` (`$`B_d \ \mathbf{dom} \ B_u`$`) if and only if every directed path from `$`B_{\text{entry}}`$` to `$`B_u`$` in `$`\mathcal{G}_{\text{cfg}}`$` contains `$`B_d`$.
     - The compiler shall compute the immediate dominator $`\text{idom}(B)`$` for every reachable block `$`B \in \mathcal{B} \setminus \{B_{\text{entry}}\}`$`, constructing the tree where directed edges represent immediate dominance: `$`(B_d, B_u) \in \mathcal{E}_{\text{dom}} \iff B_d = \text{idom}(B_u)`$.
     - Dominance Property of Value Uses:
       - For every non-$`\phi`$` instruction use `$`u \in \text{Uses}(v)`$` occurring within basic block `$`B_{\text{use}}`$`, the definition site `$`\text{Def}(v)`$` occurring in block `$`B_{\text{def}}`$` must dominate `$`B_{\text{use}}`$:
         - If $`B_{\text{def}} = B_{\text{use}}`$`, then `$`\text{Def}(v)`$` must strictly precede `$`u`$` in the linear instruction sequence of `$`B_{\text{def}}`$` (`$`\text{pos}(\text{Def}(v)) \lt \text{pos}(u)`$);
         - If $`B_{\text{def}} \ne B_{\text{use}}`$`, then `$`B_{\text{def}}`$` must strictly dominate `$`B_{\text{use}}`$` (`$`B_{\text{def}} \ \mathbf{sdom} \ B_{\text{use}}`$).
       - For every $`\phi`$`-node operand `$`\langle v_i, B_i \rangle`$`, the definition site `$`\text{Def}(v_i)`$` must dominate the incoming predecessor block `$`B_i`$`: `$`B_{\text{def}}(v_i) \ \mathbf{dom} \ B_i`$.
     - If any variable use violates these dominance conditions, the compiler shall emit diagnostic error code `E0500` (`SSADominanceViolation`).
  6. **Dominance Frontier Calculation & Pruned SSA Construction**:
     - During the lowering of AST mutable variables and local state variables into LUMI IR, the lowering engine shall compute the dominance frontier $`\text{DF}(B)`$` for each basic block `$`B \in \mathcal{B}`$:

```math
\text{DF}(B) = \{ Y \in \mathcal{B} \mid \exists P \in \text{pred}(Y) : B \ \mathbf{dom} \ P \quad \wedge \quad \neg(B \ \mathbf{sdom} \ Y) \}
```

     - The engine shall compute the iterated dominance frontier $`\text{IDF}(S)`$` for each variable definition set `$`S`$` to place minimal `$`\phi`$-nodes.
     - The engine shall employ Pruned SSA construction, inserting a $`\phi`$`-node at block `$`B \in \text{IDF}(S)`$` if and only if the corresponding variable is live on entry to block `$`B`$` (`$`\text{LiveIn}(B)`$`), eliminating dead `$`\phi`$-nodes and maintaining minimal IR footprint.
  7. **Strong Static Typing & Value Semantic Invariants**:
     - Every SSA value register $`v \in \mathcal{V}_{\text{ssa}}`$` shall bind an explicit static type `$`\tau(v) \in \mathcal{T}_{\text{lumi}}`$.
     - Supported types $`\mathcal{T}_{\text{lumi}}`$ encompass primitive integers (`i1`, `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`), IEEE 754 floating-point scalars (`f32`, `f64`), fixed-size arrays (`[T; N]`), typed continuous state vectors (`vector<f64, D>`), typed structs (`struct { ... }`), and function pointers (`fn(...) -> T`).
     - In accordance with REQ-0176, LUMI IR instructions operate on pure value semantics. Pointers, raw address arithmetic, and unmanaged memory aliases are strictly prohibited.
     - If an instruction receives arguments whose static types do not conform to the opcode typing signature, the compiler shall emit diagnostic error code `E0500` (`IRTypeMismatchViolation`).
  8. **Bijective Lexical Provenance & Traceability Anchoring**:
     - Every LUMI IR function, basic block, instruction, and SSA value register shall maintain bijective source provenance back to its originating AST node handle and source file byte span ($`\langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$) in accordance with REQ-0002.
     - If downstream codegen or verification encounters an invalid IR state, error diagnostics shall report the precise source line, column, and token span of the originating SysML v2 / KerML model construct.
  9. **Contiguous Bump Arena Memory Allocation & Node Addressing**:
     - All LUMI IR functions, basic block descriptors, instruction nodes, $`\phi`$-node operand arrays, and dominator tree graph records shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
     - IR entities shall be referenced exclusively by stable 32-bit arena node handles (REQ-0035), prohibiting internal raw heap pointers and reference cycles.
  10. **Enforcement of the 5 Executive Architectural Directives**:
      - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every LUMI IR function $`F \in \mathcal{F}_{\text{lumi}}`$`, basic block `$`B \in \mathcal{B}`$`, instruction `$`I`$`, and value register `$`v \in \mathcal{V}_{\text{ssa}}`$` shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the entity fully qualified topological path (`$`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{label}_B \mathbin{\Vert} \text{"::"} \text{name}_v)`$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
      - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel lowering of independent AST functions, state machines, and behavioral action sequences into LUMI IR CFGs shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
      - *Directive 3 (String Interner Memory Allocation Exception)*: Function symbols, block labels, variable identifiers, and opcode names shall be interned into the deduplicated global symbol interner pool during IR lowering in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
      - *Directive 4 (Synchronization Token Error Recovery)*: The IR lowering and validation engine shall implement synchronization token error recovery on statement delimiters (`;`), function boundaries, and basic block terminators in accordance with REQ-0013 and REQ-0016. When SSA or CFG malformations (`E0500`) occur, the engine shall record structured diagnostics into the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{ir}}`$`), and continue validating subsequent basic blocks and functions. If accumulated diagnostics reach capacity limit `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
      - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The LUMI IR construction and verification engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Lowering and validation latency (strictly under 25 ms for an architectural model containing $`10^4`$ basic blocks and instructions) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  11. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Function_0`, `Block_Entry`, `Block_0`, `Block_1`, `Block_Join`, `Var_0`, `Var_1`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous typed bump arena storage, and let `$`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.

  Let $`\mathcal{F}_{\text{lumi}}`$ denote the set of lowered LUMI IR functions within a compilation unit.
  Each function $`F \in \mathcal{F}_{\text{lumi}}`$ is formalized as a 9-tuple:

```math
  F = \langle \text{id}_F, \text{name}_F, \tau_{\text{ret}}, \mathbf{P}_F, B_{\text{entry}}, \mathcal{B}, \mathcal{E}_{\text{cfg}}, \Delta_F, \text{span}_F \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_F &\in \mathbb{N}_{32} \quad (\text{contiguous arena function handle}) \\
  \text{name}_F &\in \mathcal{S}_{\text{intern}} \quad (\text{interned function symbol identifier}) \\
  \tau_{\text{ret}} &\in \mathcal{T}_{\text{lumi}} \quad (\text{formal return type}) \\
  \mathbf{P}_F &= \langle p_1, p_2, \dots, p_m \rangle \quad (\text{ordered vector of formal parameter registers}) \\
  B_{\text{entry}} &\in \mathcal{B} \quad (\text{distinguished unique entry basic block}) \\
  \mathcal{B} &= \{ B_0, B_1, \dots, B_{n-1} \} \quad (\text{finite set of basic blocks}) \\
  \mathcal{E}_{\text{cfg}} &\subseteq \mathcal{B} \times \mathcal{B} \quad (\text{directed control flow graph edges}) \\
  \Delta_F &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_F &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
```

  Each basic block $`B \in \mathcal{B}`$ is formalized as a 6-tuple:

```math
  B = \langle \text{id}_B, \text{label}_B, \mathbf{\Phi}_B, \mathbf{I}_B, T_B, \Delta_B \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_B &\in \mathbb{N}_{32} \quad (\text{contiguous arena basic block handle}) \\
  \text{label}_B &\in \mathcal{S}_{\text{intern}} \quad (\text{interned block label identifier}) \\
  \mathbf{\Phi}_B &= \langle \phi_1, \dots, \phi_p \rangle \quad (\text{ordered sequence of parallel } \phi \text{-nodes}) \\
  \mathbf{I}_B &= \langle I_1, \dots, I_q \rangle \quad (\text{ordered sequence of linear SSA body instructions}) \\
  T_B &\in \mathcal{T}_{\text{term}} \quad (\text{unique control flow terminator instruction}) \\
  \Delta_B &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor})
  \end{aligned}
```

  The set of predecessor and successor blocks in the control flow graph are defined as:

```math
  \begin{aligned}
  \text{pred}(B) &= \{ B' \in \mathcal{B} \mid (B', B) \in \mathcal{E}_{\text{cfg}} \} \\
  \text{succ}(B) &= \{ B'' \in \mathcal{B} \mid (B, B'') \in \mathcal{E}_{\text{cfg}} \}
  \end{aligned}
```

  1. Rooted Entry Block Invariant:

```math
  \text{pred}(B_{\text{entry}}) = \emptyset \quad \wedge \quad \forall B \in \mathcal{B}, \quad \text{Paths}(B_{\text{entry}}, B) \ne \emptyset
```

  2. Static Single Assignment (SSA) Unique Definition Invariant:
  Let $`\mathcal{V}_{\text{ssa}}(F)`$` denote the set of all virtual value registers defined within function `$`F`$.
  Let $`\text{Def}(v)`$` denote the set of instructions defining register `$`v`$:

```math
  \forall v \in \mathcal{V}_{\text{ssa}}(F), \quad |\text{Def}(v)| = 1
```

  3. Join Block $`\phi`$-Node Invariant:
  For every basic block $`B \in \mathcal{B}`$` with `$`k = |\text{pred}(B)|`$ incoming control flow edges:

```math
  \forall \phi \in \mathbf{\Phi}_B, \quad \phi = \left( v_{\phi} \leftarrow \phi\left( \langle v_1, B_1 \rangle, \dots, \langle v_k, B_k \rangle \right) \right)
```

  satisfying bijective correspondence with predecessor blocks and homogeneous operand typing:

```math
  \begin{aligned}
  \{ B_1, B_2, \dots, B_k \} &= \text{pred}(B) \\
  \forall i, j \in \{1, \dots, k\}, \quad i \ne j &\implies B_i \ne B_j \\
  \forall i \in \{1, \dots, k\}, \quad \tau(v_i) &\equiv \tau(v_{\phi})
  \end{aligned}
```

  For blocks with single or zero predecessors:

```math
  |\text{pred}(B)| \le 1 \implies \mathbf{\Phi}_B = \emptyset
```

  4. Dominance Tree & Strict Dominance Property:
  Let $`\mathbf{dom} \subseteq \mathcal{B} \times \mathcal{B}`$ denote the dominance relation:

```math
  B_d \ \mathbf{dom} \ B_u \iff \left( \forall \mathcal{P} \in \text{Paths}(B_{\text{entry}}, B_u), \quad B_d \in \mathcal{P} \right)
```

  Strict dominance ($`\mathbf{sdom}`$`) and immediate dominance (`$`\text{idom}`$):

```math
  \begin{aligned}
  B_d \ \mathbf{sdom} \ B_u &\iff \left( B_d \ \mathbf{dom} \ B_u \quad \wedge \quad B_d \ne B_u \right) \\
  B_d = \text{idom}(B) &\iff \left( B_d \ \mathbf{sdom} \ B \quad \wedge \quad \forall B' \in \mathcal{B}, \ B' \ \mathbf{sdom} \ B \implies B' \ \mathbf{dom} \ B_d \right)
  \end{aligned}
```

  The directed Dominator Tree is formalized as $`\mathcal{T}_{\text{dom}}(F) = (\mathcal{B}, \mathcal{E}_{\text{dom}})`$ where:

```math
  (B_d, B_u) \in \mathcal{E}_{\text{dom}} \iff B_d = \text{idom}(B_u)
```

  5. SSA Dominance Invariant across Variable Uses:
  Let $`\text{Uses}(v)`$` denote the set of all sites consuming value register `$`v`$.
  - For each non-$`\phi`$` body use `$`u \in \text{Uses}_{\text{body}}(v)`$` occurring in instruction `$`I_u`$` inside basic block `$`B_{\text{use}}`$`, where definition site `$`\text{Def}(v)`$` resides in block `$`B_{\text{def}}`$:

```math
  \begin{aligned}
  B_{\text{def}} = B_{\text{use}} &\implies \text{pos}(\text{Def}(v)) \lt \text{pos}(I_u) \\
  B_{\text{def}} \ne B_{\text{use}} &\implies B_{\text{def}} \ \mathbf{sdom} \ B_{\text{use}}
  \end{aligned}
```

  - For each $`\phi`$`-node use where register `$`v_i`$` is supplied as the operand for predecessor block `$`B_i \in \text{pred}(B)`$:

```math
  B_{\text{def}}(v_i) \ \mathbf{dom} \ B_i
```

  6. Dominance Frontier Formulation:

```math
  \text{DF}(B) = \{ Y \in \mathcal{B} \mid \exists P \in \text{pred}(Y) : B \ \mathbf{dom} \ P \quad \wedge \quad \neg(B \ \mathbf{sdom} \ Y) \}
```

  7. Basic Block Terminator Consistency:
  Let $`\text{targets}(T_B)`$` denote the set of target basic blocks referenced by terminator `$`T_B`$:

```math
  \forall B \in \mathcal{B}, \quad \text{succ}(B) = \text{targets}(T_B) \quad \wedge \quad \text{targets}(T_B) \subseteq \mathcal{B}
```

  8. Deterministic Diagnostic Trigger Rules (REQ-0191):

```math
  \begin{aligned}
  |\text{Def}(v)| \gt 1 &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0500}, \text{SSAMultipleDefinitionViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\text{Def}(v)| = 0 &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0500}, \text{SSAUseWithoutDefinitionViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists u \in \text{Uses}(v) : \neg(\text{Def}(v) \ \mathbf{dom} \ u) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0500}, \text{SSADominanceViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists \phi \in \mathbf{\Phi}_B : |\text{operands}(\phi)| \ne |\text{pred}(B)| &\implies \text{Diagnostic}(\phi, \text{DiagnosticCode::E0500}, \text{PhiNodeArityMismatchViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists \langle v_i, B_i \rangle \in \phi : B_i \notin \text{pred}(B) &\implies \text{Diagnostic}(\phi, \text{DiagnosticCode::E0500}, \text{PhiNodePredecessorDivergenceViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists \langle v_i, B_i \rangle \in \phi : \tau(v_i) \not\equiv \tau(\phi) &\implies \text{Diagnostic}(\phi, \text{DiagnosticCode::E0500}, \text{PhiNodeTypeMismatchViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\text{pred}(B)| \le 1 \wedge \mathbf{\Phi}_B \ne \emptyset &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0500}, \text{PhiNodeInSinglePredecessorBlockViolation}) \in \mathcal{D}_{\text{sink}} \\
  T_B = \bot \lor |\text{Terminators}(B)| \ne 1 &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0500}, \text{CFGTerminatorMissingViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists B' \in \text{targets}(T_B) : B' \notin \mathcal{B} &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0500}, \text{CFGMalformedEdgeViolation}) \in \mathcal{D}_{\text{sink}} \\
  B \ne B_{\text{entry}} \wedge \text{Paths}(B_{\text{entry}}, B) = \emptyset &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0500}, \text{CFGUnreachableBlockViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  9. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
  \begin{aligned}
  \Delta_F &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F)) \\
  \Delta_B &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{label}_B) \\
  \Delta_v &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{label}_B \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{name}_v)
  \end{aligned}
```

  **Asymptotic Complexity Analysis**:
  Let $`N_F = |\mathcal{F}_{\text{lumi}}|`$` denote the number of functions, `$`N_B = |\mathcal{B}|`$` denote the aggregate number of basic blocks, `$`N_E = |\mathcal{E}_{\text{cfg}}|`$` denote the aggregate number of CFG edges, and `$`N_I = |\mathcal{I}|`$ denote the aggregate number of instructions across a compilation unit.
  1. *AST Lowering & CFG Construction Phase*:
     - Traversal of AST actions, calculations, and state machine transition statements and allocation of basic block handles executes in single-pass linear time:

```math
T_{\text{cfg}}(N_B, N_E, N_I) \in O(N_B + N_E + N_I), \quad S_{\text{cfg}} \in O(N_B + N_E + N_I)
```

  2. *Dominator Tree Computation ($`\mathcal{T}_{\text{dom}}`$)*:
     - Computing immediate dominators $`\text{idom}(B)`$` via the standard Lengauer-Tarjan algorithm executes in deterministic quasi-linear time `$`O(N_E \cdot \alpha(N_E, N_B))`$` (where `$`\alpha`$` is the inverse Ackermann function) or strictly `$`O(N_B + N_E)`$ via the linear dominator tree algorithm of Buchsbaum et al.:

```math
T_{\text{dom}}(N_B, N_E) \in O(N_B + N_E), \quad S_{\text{dom}} \in O(N_B)
```

  3. *Dominance Frontier & Pruned SSA Construction*:
     - Calculating $`\text{DF}(B)`$` for all blocks and placing minimal `$`\phi`$-nodes via iterated dominance frontiers with live variable analysis executes in linear time for standard structured control flow:

```math
T_{\text{ssa}}(N_B, N_E, N_I) \in O(N_B + N_E + N_I), \quad S_{\text{ssa}} \in O(N_B + N_I)
```

  4. *SSA Invariant & Dominance Verification*:
     - Validating $`|\text{Def}(v)| = 1`$` requires a single array scan over virtual registers (`$`O(N_I)`$).
     - Dominance checks between $`\text{Def}(v)`$` and use sites are executed in `$`O(1)`$` constant time per use by pre-computing entry and exit DFS discovery timestamps over `$`\mathcal{T}_{\text{dom}}`$` (ancestor query in `$`O(1)`$):

```math
T_{\text{verify}}(N_B, N_I) = O(N_B) + \sum_{u \in \text{Uses}} O(1) \in O(N_B + N_I)
```

  5. *Aggregate Compilation Unit Complexity*:
     - Summing across all phases:

```math
T_{\text{total}} = T_{\text{cfg}} + T_{\text{dom}} + T_{\text{ssa}} + T_{\text{verify}} \in O(N_B + N_E + N_I)
```

     - Space complexity is strictly $`O(N_B + N_E + N_I)`$ in contiguous bump arena storage, requiring zero individual heap allocations outside the arena.
  6. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning independent functions across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool achieves near-linear speedup:

```math
T_{\text{parallel}}(N_B, N_E, N_I, N_{\text{max\_workers}}) \in O\left( \frac{N_B + N_E + N_I}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```
