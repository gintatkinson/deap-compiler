### REQ-0134: Hierarchical Control Structure (HCS) AST Extraction & Controller-Process Topology

- **Normative Statement**: The safety compiler, control structure extraction engine, and formal verification framework of Subsystem 7 shall extract, validate, index, and query a formal Hierarchical Control Structure (HCS) topology from the compilation unit abstract syntax tree (AST) model graph, identifying and resolving controlling entities, execution interfaces, controlled processes, observation interfaces, control action flows, and state feedback observation flows across all architectural tiers.

  Specifically, the safety compiler, topology extraction engine, and control structure validator shall strictly enforce the following structural, algebraic, and operational invariants:
  1. **Disjoint Entity Partitioning & Role Classification**:
     - The compiler shall inspect the AST model graph $\mathcal{G}_{\text{AST}} = (\mathcal{V}_{\text{AST}}, \mathcal{E}_{\text{AST}})$ and partition the extracted control structure entities into four mutually disjoint node sets:
       - Controlling entities ($C \subset \mathcal{V}_{\text{AST}}$): Architectural classifiers, components, parts, or software actors that formulate, schedule, and dispatch control actions based on internal process models, control algorithms, or state machines.
       - Execution interfaces ($E \subset \mathcal{V}_{\text{AST}}$): Actuators, digital-to-analog converters, driver mechanisms, command ports, or communication channels through which control action signals are transmitted, converted, or asserted onto controlled processes.
       - Controlled processes ($P \subset \mathcal{V}_{\text{AST}}$): Physical plants, hardware assemblies, dynamic systems, or subordinate subsystems whose physical or logical state evolution is governed by incoming control actions.
       - Observation interfaces ($O \subset \mathcal{V}_{\text{AST}}$): Sensors, analog-to-digital converters, feedback telemetry ports, or measurement channels through which dynamic physical states or operational variables are sensed from controlled processes and transmitted to controlling entities.
     - Within any single elementary control loop, the controlling entity and controlled process must be distinct ($c \ne p$). A node cannot act as its own controlled process within the same control loop.
     - Execution interfaces and observation interfaces shall be functionally disjoint ($E \cap O = \emptyset$).
     - Declaring an entity with conflicting or ambiguous role classifications within a single loop shall be deterministically rejected at compile time with diagnostic error code `E0400` (`ConflictingControlRole`).
  2. **Formal Control Action and State Feedback Flow Lowering**:
     - Control action flows ($\mathcal{U} \subseteq C \times E \times P$): The compiler shall extract directed ternary relations $u = (c, e, p) \in \mathcal{U}$ linking a controlling entity $c \in C$, through an execution interface $e \in E$, to a target controlled process $p \in P$.
     - State feedback observation flows ($\mathcal{Y} \subseteq P \times O \times C$): The compiler shall extract directed ternary relations $y = (p, o, c) \in \mathcal{Y}$ linking a source controlled process $p \in P$, through an observation interface $o \in O$, back to a sink controlling entity $c \in C$.
     - Port Directionality Invariants:
       - Control action flows must strictly connect an output command port of controller $c$ (`out`), to an input interface port of execution interface $e$ (`in`), whose output port (`out`) connects to an input actuation port of process $p$ (`in`).
       - State feedback flows must strictly connect an output state port of process $p$ (`out`), to an input sensing port of observation interface $o$ (`in`), whose output port (`out`) connects to an input telemetry port of controller $c$ (`in`).
       - Any flow violating directional invariants (e.g., feedback directed from controller to process or control actions directed from process to controller) shall be deterministically rejected at compile time with diagnostic error code `E0400` (`InvalidControlFlowDirection`).
     - Strongly Typed Payloads: Each flow $u \in \mathcal{U}$ and $y \in \mathcal{Y}$ shall bind an explicit data type, item definition, or physical quantity in the $\mathbb{Q}^7$ rational metric space (REQ-0098).
  3. **Hierarchical Multi-Level Control Topology & Acyclic Supervisory DAG**:
     - The compiler shall construct a hierarchical stratification of controllers and processes via a level assignment function $\ell : C \cup P \to \mathbb{N}_0$.
     - Base physical processes ($P_{\text{base}} = \{ p \in P \mid p \notin C \}$) shall reside strictly at ground level $\ell(p) = 0$.
     - Hierarchical Controllers: A controlling entity $c_{\text{sub}} \in C$ at level $k \ge 1$ may act as a controlled process for a higher-level supervisory controller $c_{\text{sup}} \in C$ at level $m \gt k$ via supervisory control action flows $(c_{\text{sup}}, e, c_{\text{sub}}) \in \mathcal{U}$ and subordinate feedback flows $(c_{\text{sub}}, o, c_{\text{sup}}) \in \mathcal{Y}$.
     - Strict Acyclicity of Supervisory Hierarchy: The supervisory control precedence relation $\prec_{\text{sup}}$ defined on $C$ shall form a strict directed acyclic graph (DAG). No controller may directly or indirectly supervise itself ($\forall c \in C, \neg(c \prec_{\text{sup}}^+ c)$). Circular supervisory dependencies shall be deterministically rejected at compile time with diagnostic error code `E0400` (`CyclicSupervisoryHierarchy`).
  4. **Closed-Loop Structural Integrity & Open-Loop Policy**:
     - Closed-Loop Completeness: For every declared control action flow $(c, e, p) \in \mathcal{U}$, there must exist at least one matching state feedback observation flow $(p, o, c) \in \mathcal{Y}$ completing the feedback control loop between controller $c$ and process $p$.
     - Open-Loop Exception Gate: If an engineering control action is strictly feedforward without feedback, the AST declaration must explicitly attach an `@open_loop` semantic metadata annotation to the control action flow or controller definition.
     - Any control action flow $(c, e, p) \in \mathcal{U}$ lacking a corresponding state feedback flow $(p, o, c) \in \mathcal{Y}$ without an explicit `@open_loop` annotation shall be deterministically rejected at compile time with diagnostic error code `E0400` (`UnobservableControlLoop`).
     - Dangling Interface Verification: Any control action flow referencing an unmapped, unconnected, or unresolved execution interface $e \notin E$ shall be deterministically rejected with diagnostic error code `E0400` (`DanglingExecutionInterface`). Any feedback observation flow referencing an unmapped, unconnected, or unresolved observation interface $o \notin O$ shall be deterministically rejected with diagnostic error code `E0400` (`DanglingObservationInterface`).
  5. **Controller Internal Process Model Binding**:
     - Every controlling entity $c \in C$ shall bind at least one internal process model representation $\mathcal{M}_{\text{proc}}(c) \in \mathcal{V}_{\text{AST}}$ (such as an internal discrete state machine per REQ-0079 and REQ-0120, an action step sequence per REQ-0078 and REQ-0119, or a calculation definition per REQ-0082) representing the controller's belief state and decision logic over the controlled process dynamics.
     - Declaring a controller that issues control actions in $\mathcal{U}$ without binding a valid internal process model or control algorithm shall trigger compile-time rejection with diagnostic error code `E0400` (`MissingProcessModel`).
  6. **Foundation for Downstream STPA Safety Verification**:
     - The extracted HCS topology $\text{HCS} = \langle C, E, P, O, \mathcal{U}, \mathcal{Y} \rangle$ shall serve as the canonical substrate for downstream safety analysis passes:
       - STPA Unsafe Control Action (UCA) combinatorial tensor expansion and pruning under REQ-0136 ($U = A \times G \times S_{\text{context}}$ where $A = \mathcal{U}$).
       - STPA minimal hazard cut-sets and UCA minimization under REQ-0135 (NP-4).
       - Automated Boolean safety invariant synthesis from hazard scenarios under REQ-0137 and REQ-0138.
       - FMECA failure mode synthesis across interfaces, states, actions, and resources under REQ-0139.
  7. **The 5 Executive Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every controller node, process node, execution interface, observation interface, control action flow, feedback observation flow, and HCS record shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(v))$ for vertices, and $\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(c) \mathbin{\Vert} \text{FQN}(e) \mathbin{\Vert} \text{FQN}(p))$ for ternary flows) in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel extraction of HCS subgraphs, interface port resolution, and loop integrity verification across independent packages or models shall execute strictly on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Controller names, process identifiers, interface labels, flow names, and fully qualified path tokens shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The safety compiler shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When semantic HCS violations occur (`E0400`), diagnostics shall accumulate in the error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels ($\bot_{\text{ctrl}}$, $\bot_{\text{proc}}$, $\bot_{\text{flow}}$), and continue validating subsequent control structure declarations. If accumulated diagnostics reach capacity $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The HCS extraction engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Extraction and validation latency ($\lt 25\text{ ms}$ for $10^4$ AST nodes and control flows) and peak RSS memory ($\lt 100\text{ MB}$) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Controller_0`, `Controller_1`, `Controller_Alpha`, `Controller_Beta`, `Process_0`, `Process_1`, `Process_Alpha`, `Process_Beta`, `Actuator_0`, `Actuator_1`, `Sensor_0`, `Sensor_1`, `Flow_Command_0`, `Flow_Feedback_0`, `Port_1`, `Port_2`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes in contiguous bump arena storage, and let $\mathcal{S}_{\text{intern}}$ denote the deduplicated global symbol interner pool.

  An abstract Hierarchical Control Structure (HCS) topology is formalized as an 8-tuple:

  $$
  \text{HCS} = \langle C, E, P, O, \mathcal{U}, \mathcal{Y}, \ell, \mathcal{M}_{\text{proc}} \rangle
  $$

  where:

  $$
  \begin{aligned}
  C &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of controlling entities}) \\
  E &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of execution interfaces / actuators}) \\
  P &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of controlled processes}) \\
  O &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of observation interfaces / sensors}) \\
  \mathcal{U} &\subseteq C \times E \times P \quad (\text{finite set of control action flows}) \\
  \mathcal{Y} &\subseteq P \times O \times C \quad (\text{finite set of state feedback observation flows}) \\
  \ell &: C \cup P \to \mathbb{N}_0 \quad (\text{hierarchical supervisory level assignment}) \\
  \mathcal{M}_{\text{proc}} &: C \to \mathcal{V}_{\text{AST}} \quad (\text{internal process model / control algorithm mapping})
  \end{aligned}
  $$

  1. Entity Role Partitioning & Interface Disjointness Invariants:

  $$
  \begin{aligned}
  E \cap O &= \emptyset \\
  \forall c \in C, \quad & (c, e, p) \in \mathcal{U} \implies c \ne p \\
  \forall c \in C, \quad & (p, o, c) \in \mathcal{Y} \implies c \ne p
  \end{aligned}
  $$

  where base physical processes are defined as:

  $$
  P_{\text{base}} = \{ p \in P \mid p \notin C \}
  $$

  2. Control Action Flow Formalization ($\mathcal{U}$):
  Each control action flow $u \in \mathcal{U}$ is formalized as a 5-tuple:

  $$
  u = \langle c_u, e_u, p_u, \tau_u, \Delta_u \rangle
  $$

  where:

  $$
  \begin{aligned}
  c_u &\in C \quad (\text{source controlling entity handle}) \\
  e_u &\in E \quad (\text{intermediary execution interface handle}) \\
  p_u &\in P \quad (\text{target controlled process handle}) \\
  \tau_u &\in \mathcal{V}_{\text{AST}} \quad (\text{control action payload type descriptor}) \\
  \Delta_u &\in \mathbb{U}_{128} \quad (\text{deterministic RFC 4122 UUIDv5 flow identifier})
  \end{aligned}
  $$

  3. State Feedback Observation Flow Formalization ($\mathcal{Y}$):
  Each state feedback observation flow $y \in \mathcal{Y}$ is formalized as a 5-tuple:

  $$
  y = \langle p_y, o_y, c_y, \tau_y, \Delta_y \rangle
  $$

  where:

  $$
  \begin{aligned}
  p_y &\in P \quad (\text{source controlled process handle}) \\
  o_y &\in O \quad (\text{intermediary observation interface handle}) \\
  c_y &\in C \quad (\text{sink controlling entity handle}) \\
  \tau_y &\in \mathcal{V}_{\text{AST}} \quad (\text{state feedback payload type descriptor}) \\
  \Delta_y &\in \mathbb{U}_{128} \quad (\text{deterministic RFC 4122 UUIDv5 flow identifier})
  \end{aligned}
  $$

  4. Port Directionality Invariants:
  Let $\text{PortDir}(v, \text{port}) \in \{ \text{In}, \text{Out}, \text{InOut} \}$. Every control action flow $u = (c, e, p) \in \mathcal{U}$ traversing controller port $p_c$, execution interface input $p_{e,\text{in}}$ and output $p_{e,\text{out}}$, and process port $p_{p,\text{in}}$ satisfies:

  $$
  \text{PortDir}(c, p_c) = \text{Out} \land \text{PortDir}(e, p_{e,\text{in}}) = \text{In} \land \text{PortDir}(e, p_{e,\text{out}}) = \text{Out} \land \text{PortDir}(p, p_{p,\text{in}}) = \text{In}
  $$

  Every state feedback observation flow $y = (p, o, c) \in \mathcal{Y}$ traversing process port $p_{p,\text{out}}$, observation interface input $p_{o,\text{in}}$ and output $p_{o,\text{out}}$, and controller port $p_{c,\text{in}}$ satisfies:

  $$
  \text{PortDir}(p, p_{p,\text{out}}) = \text{Out} \land \text{PortDir}(o, p_{o,\text{in}}) = \text{In} \land \text{PortDir}(o, p_{o,\text{out}}) = \text{Out} \land \text{PortDir}(c, p_{c,\text{in}}) = \text{In}
  $$

  5. Hierarchical Level Stratification & Supervisory Acyclicity Invariant:
  Let $\prec_{\text{sup}} \subset C \times (C \cup P)$ denote the directed supervisory control relation defined by:

  $$
  c \prec_{\text{sup}} x \iff \exists e \in E : (c, e, x) \in \mathcal{U}
  $$

  The hierarchical level assignment $\ell : C \cup P \to \mathbb{N}_0$ satisfies:

  $$
  \begin{aligned}
  \forall p \in P_{\text{base}}, &\quad \ell(p) = 0 \\
  \forall c \in C, \forall x \in (C \cup P), &\quad c \prec_{\text{sup}} x \implies \ell(c) \gt \ell(x)
  \end{aligned}
  $$

  Supervisory hierarchy acyclicity prohibits circular supervisory loops:

  $$
  \forall c \in C, \quad \neg(c \prec_{\text{sup}}^+ c)
  $$

  6. Closed-Loop Structural Observability Invariant:
  Let $\text{IsAnnotatedOpenLoop}(c, p) \in \{ \text{true}, \text{false} \}$ indicate whether an explicit `@open_loop` metadata attribute is attached to the controller-process relationship. Every control action flow must possess a corresponding feedback observation flow unless formally annotated as open-loop:

  $$
  \forall (c, e, p) \in \mathcal{U}, \quad (\exists (p', o, c') \in \mathcal{Y} : p' = p \land c' = c) \lor \text{IsAnnotatedOpenLoop}(c, p) = \text{true}
  $$

  7. Controller Internal Process Model Binding Invariant:
  Every controlling entity $c \in C$ must bind an internal process model or control algorithm:

  $$
  \forall c \in C, \quad \mathcal{M}_{\text{proc}}(c) \ne \bot \land \mathcal{M}_{\text{proc}}(c) \in \mathcal{V}_{\text{AST}}
  $$

  8. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

  $$
  \begin{aligned}
  \forall v \in C \cup E \cup P \cup O, &\quad \Delta(v) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(v)) \\
  \forall u = (c, e, p) \in \mathcal{U}, &\quad \Delta(u) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(c) \mathbin{\Vert} \text{FQN}(e) \mathbin{\Vert} \text{FQN}(p)) \\
  \forall y = (p, o, c) \in \mathcal{Y}, &\quad \Delta(y) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(p) \mathbin{\Vert} \text{FQN}(o) \mathbin{\Vert} \text{FQN}(c))
  \end{aligned}
  $$

  9. Deterministic Diagnostic Trigger Rules (REQ-0191):

  $$
  \begin{aligned}
  \exists (c, e, p) \in \mathcal{U} : (\neg \exists (p, o, c) \in \mathcal{Y}) \land \neg \text{IsAnnotatedOpenLoop}(c, p) &\implies \text{Diagnostic}((c, p), \text{DiagnosticCode::E0400}, \text{UnobservableControlLoop}) \in \mathcal{D}_{\text{sink}} \\
  \exists (c, e, p) \in \mathcal{U} : e \notin E \lor e = \bot &\implies \text{Diagnostic}((c, p), \text{DiagnosticCode::E0400}, \text{DanglingExecutionInterface}) \in \mathcal{D}_{\text{sink}} \\
  \exists (p, o, c) \in \mathcal{Y} : o \notin O \lor o = \bot &\implies \text{Diagnostic}((p, c), \text{DiagnosticCode::E0400}, \text{DanglingObservationInterface}) \in \mathcal{D}_{\text{sink}} \\
  \exists c \in C : c \prec_{\text{sup}}^+ c &\implies \text{Diagnostic}(c, \text{DiagnosticCode::E0400}, \text{CyclicSupervisoryHierarchy}) \in \mathcal{D}_{\text{sink}} \\
  \exists c \in C : \mathcal{M}_{\text{proc}}(c) = \bot &\implies \text{Diagnostic}(c, \text{DiagnosticCode::E0400}, \text{MissingProcessModel}) \in \mathcal{D}_{\text{sink}} \\
  \exists u \in \mathcal{U} \cup \mathcal{Y} : \text{InvalidPortDirections}(u) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0400}, \text{InvalidControlFlowDirection}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

- **Computational Complexity & Algorithmic Bounds**: Extraction, indexing, loop matching, and topological validation of the Hierarchical Control Structure (HCS) reside strictly in **Complexity Class P** (Deterministic Polynomial Time).

  **Mathematical Delineation from Algorithmic Bound NP-4**:
  In formal STPA safety verification, computing the minimal hitting set of safety constraints covering all hazard scenarios and Unsafe Control Actions (UCAs) corresponds to the Minimal Hitting Set / Set Cover problem, which is NP-complete as cataloged under Algorithmic Bound NP-4 (REQ-0135). In contrast, REQ-0134 establishes the underlying structural topology $\text{HCS} = \langle C, E, P, O, \mathcal{U}, \mathcal{Y} \rangle$ upon which STPA hazard analyses are subsequently evaluated. Extracting entity roles, indexing execution and observation interfaces, matching control action and feedback pairs, and verifying supervisory hierarchy acyclicity via topological sort (Kahn's algorithm or Tarjan's strongly connected components algorithm) operate strictly in deterministic linear time proportional to the AST graph size $|V| + |E|$. No combinatorial search, SAT unrolling, or exponential backtracking is executed.

  **Asymptotic Complexity Analysis**:
  Let $V_{\text{AST}} = |\mathcal{V}_{\text{AST}}|$ and $E_{\text{AST}} = |\mathcal{E}_{\text{AST}}|$ denote the total number of nodes and edges in the ingested AST graph. Let $N_{\text{ctrl}} = |C|$, $N_{\text{proc}} = |P|$, $N_{\text{exec}} = |E|$, $N_{\text{obs}} = |O|$, $M_u = |\mathcal{U}|$, and $M_y = |\mathcal{Y}|$ denote the cardinalities of the extracted HCS components.
  1. *Entity Extraction & Role Classification*:
     Traversing the AST model graph to classify controlling entities ($C$), controlled processes ($P$), execution interfaces ($E$), and observation interfaces ($O$) via node metadata and port signatures requires a single linear scan over AST elements:
     $$
     T_{\text{extract}}(V_{\text{AST}}) \in O(V_{\text{AST}})
     $$
  2. *Ternary Flow Extraction & Port Resolution*:
     Resolving connection usages and flow bindings into ternary relations $\mathcal{U} \subseteq C \times E \times P$ and $\mathcal{Y} \subseteq P \times O \times C$, while verifying port directions (`in`, `out`), inspects each interface connection once:
     $$
     T_{\text{flows}}(E_{\text{AST}}) \in O(E_{\text{AST}})
     $$
  3. *Closed-Loop Matching & Observability Verification*:
     Inserting feedback pairs $(p, c)$ into a deterministic hash set or radix-indexed bitset and testing membership for each control action $(c, e, p) \in \mathcal{U}$ requires $O(1)$ amortized time per flow. For all flows:
     $$
     T_{\text{loop}}(M_u, M_y) \in O(M_u + M_y)
     $$
  4. *Supervisory Hierarchy DAG Acyclicity & Level Assignment*:
     Constructing the supervisory precedence multigraph $(C, \prec_{\text{sup}})$ and computing the topological sort or strongly connected components via Tarjan's or Kahn's algorithm requires linear time in controllers and supervisory flows:
     $$
     T_{\text{topo}}(N_{\text{ctrl}}, M_u) \in O(N_{\text{ctrl}} + M_u)
     $$
  5. *Process Model Verification*:
     Verifying that each controlling entity $c \in C$ binds an internal process model $\mathcal{M}_{\text{proc}}(c) \ne \bot$ in contiguous arena storage takes $O(1)$ time per controller:
     $$
     T_{\text{proc\_model}}(N_{\text{ctrl}}) \in O(N_{\text{ctrl}})
     $$
  6. *Aggregate Worst-Case Execution Time*:
     Summing all extraction, indexing, matching, and validation passes:
     $$
     T_{\text{total}}(V_{\text{AST}}, E_{\text{AST}}) \in O(V_{\text{AST}} + E_{\text{AST}})
     $$
     The algorithm is strictly linear in the size of the ingested AST model graph, executing deterministically without recursion stack overflow.
  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     When extracting and validating HCS topologies across $K$ independent packages or decoupled subsystem models on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$:
     $$
     T_{\text{parallel}}(V_{\text{AST}}, E_{\text{AST}}, N_{\text{max\_workers}}) \in O\left( \frac{V_{\text{AST}} + E_{\text{AST}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
     $$
  8. *Space Complexity & Arena Memory Bounds*:
     The extracted HCS entity vectors ($C, E, P, O$) and ternary flow arrays ($\mathcal{U}, \mathcal{Y}$) reside in contiguous bump arena allocations, requiring $O(N_{\text{ctrl}} + N_{\text{proc}} + N_{\text{exec}} + N_{\text{obs}} + M_u + M_y)$ bytes. Adjacency lists and topological queue buffers require $O(N_{\text{ctrl}})$ auxiliary integers. Interned symbol descriptors require $O(V_{\text{AST}})$ table memory. The diagnostic error sink buffer is strictly bounded by $O(C_{\text{max\_errors}}) = O(1)$ capacity.
