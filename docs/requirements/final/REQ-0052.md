### REQ-0052: Memory-Mapped Diff Engine & Unmodified Output File Bypass

- **Normative Statement**: The compilation and artifact persistence engine shall implement memory-mapped diffing against on-disk files prior to writing output artifacts, strictly bypassing file write operations when newly generated artifact content matches existing on-disk content byte-for-byte. This bypass shall preserve existing file modification timestamps (`mtime`), filesystem inodes, and file metadata, thereby preventing cascading rebuild churn across downstream build systems, continuous integration toolchains, and file-watching daemons. The diffing and persistence engine must remain abstract, platform-agnostic, and decoupled from concrete external libraries or third-party crates, operating exclusively through technology-neutral virtual memory mapping abstractions and standard operating system page-cache primitives.

  The persistence engine shall enforce the following normative guarantees:
  1. Metadata Pre-Check and Constant-Time Short-Circuit: For each candidate output artifact designated by canonical target filesystem path $P$ and in-memory byte buffer $B_{\text{new}}$, the persistence engine shall first query the filesystem metadata of $P$ without loading file contents into memory:
     - Non-Existent Target: If the target file does not exist on disk ($\neg \text{FileExists}(P)$), the engine shall evaluate the emission decision predicate $\text{ShouldWrite}(P, B_{\text{new}}) = \text{true}$ and proceed with file writing.
     - Size Discrepancy Short-Circuit: If the file exists on disk, the engine shall inspect the metadata to obtain the current on-disk byte size $\text{FileSize}(P)$ in $O(1)$ constant time. If $\text{FileSize}(P) \ne |B_{\text{new}}|$, the engine shall immediately evaluate $\text{ShouldWrite}(P, B_{\text{new}}) = \text{true}$ and proceed with file writing, completely bypassing memory mapping and file read operations.
  2. Memory-Mapped Vectorized Byte Comparison: If and only if $\text{FileExists}(P) = \text{true}$ and $\text{FileSize}(P) = |B_{\text{new}}|$, the persistence engine shall establish a read-only memory-mapped virtual memory view $\mathcal{B}_{\text{mmap}}(P)$ over the existing on-disk file. The engine shall compare $\mathcal{B}_{\text{mmap}}(P)$ against $B_{\text{new}}$ byte-for-byte using vectorized word-level comparisons. If all bytes are identical ($\mathcal{B}_{\text{mmap}}(P) == B_{\text{new}}$), the engine shall evaluate $\text{ShouldWrite}(P, B_{\text{new}}) = \text{false}$ and strictly bypass writing to disk.
  3. Modification Timestamp and Inode Invariance: When file write is bypassed ($\text{ShouldWrite}(P, B_{\text{new}}) = \text{false}$), the on-disk file shall remain completely untouched. The compiler shall issue zero write-related system calls (`write`, `pwrite`, `ftruncate`), guaranteeing that the file modification timestamp (`mtime`), status change timestamp (`ctime`), access permissions (`mode`), and filesystem inode remain strictly unchanged ($\text{mtime}(P, t+1) = \text{mtime}(P, t)$). Downstream tools consuming generated artifacts shall observe zero timestamp updates, guaranteeing zero build system churn.
  4. Atomic Emission upon Content Divergence: If byte comparison reveals any differing byte ($\mathcal{B}_{\text{mmap}}(P) \ne B_{\text{new}}$), or if the file does not exist, the persistence engine shall write $B_{\text{new}}$ to disk atomically (utilizing a temporary sibling file and atomic rename operation) to eliminate the risk of torn writes or corrupt partial files in the event of an interruption.
  5. Zero Dynamic Heap Allocation: Memory-mapped diffing shall execute with zero dynamic heap allocations ($\text{HeapAllocs} = 0$), comparing the generated in-memory buffer directly against page-cache-backed virtual memory addresses.
  6. Deterministic UUIDv5 Anchor Invariant: Every generated artifact, manifest descriptor, and lowered AST entity shall bind a deterministic RFC 4122 UUIDv5 identifier derived from the compiler namespace UUID and its canonical topological path (e.g., `Package_0::Artifact_Alpha`), adhering to Architectural Directive 1 and REQ-0010.
  7. Bounded Work-Stealing Parallelism: Diff evaluation and artifact persistence across multi-file compilation units shall execute concurrently over a bounded work-stealing thread pool with worker thread upper bound $N_{\text{max\_workers}}$, adhering to Architectural Directive 2 and REQ-0012. Each thread shall maintain isolated memory mappings without lock contention across distinct output paths.
  8. Memory Management Architecture: String literals and identifiers referenced by compilation units shall reside in interned scalar `SymbolId` pools within the global symbol interner, representing the sole permitted exception to zero-copy memory management per Architectural Directive 3 and REQ-0036.
  9. Non-Panicking Execution Contract and Diagnostic Binding: In accordance with Architectural Directive 5 and REQ-0011, the persistence engine shall strictly enforce a deterministic, non-panicking execution contract. If filesystem operations encounter an I/O fault (such as permission denial, unreadable directory, invalid path encoding, or virtual memory mapping failure), the engine shall emit structured diagnostic error code `E0200` per REQ-0191 and terminate the unit gracefully without unwinding or process aborts.
  10. Performance Budget and Release Isolation: Execution latency (< 25 ms) and peak memory RSS (< 100 MB for $10^6$ AST entities) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.
  11. Clean-Room Domain Purity: All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Port_1`, `Flow_A`, `param_x : Real`, `Artifact_0`, `Path_0`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $\mathcal{P}_{\text{out}}$ denote the universe of canonical output filesystem paths. Let $P \in \mathcal{P}_{\text{out}}$ be a target output path, and let $B_{\text{new}} \in \Sigma^*$ denote the newly generated in-memory byte buffer of length $|B_{\text{new}}| \in \mathbb{N}_0$. Let $\mathcal{F}_{\text{disk}}$ denote the filesystem state at compiler start time $t$, and let $\mathcal{F}_{\text{disk}}'$ denote the filesystem state at pass completion time $t+1$.

  The emission decision function $\text{ShouldWrite} : \mathcal{P}_{\text{out}} \times \Sigma^* \longrightarrow \{ \text{true}, \text{false} \}$ evaluates:

$$
\text{ShouldWrite}(P, B_{\text{new}}) = \begin{cases}
\text{true}, & \text{if } \neg \text{FileExists}(P) \\
\text{false}, & \text{if } \text{FileExists}(P) \wedge \text{FileSize}(P) = |B_{\text{new}}| \wedge \mathcal{B}_{\text{mmap}}(P) = B_{\text{new}} \\
\text{true}, & \text{otherwise}
\end{cases}
$$

  Modification Timestamp Preservation Invariant:
  When file write is bypassed, the file modification timestamp $\text{mtime}(P)$ remains strictly identical across time:

$$
\text{ShouldWrite}(P, B_{\text{new}}) = \text{false} \implies \text{mtime}(P, t+1) = \text{mtime}(P, t)
$$

  Conversely, when new content is committed, the modification timestamp reflects the new emission event:

$$
\text{ShouldWrite}(P, B_{\text{new}}) = \text{true} \implies \text{mtime}(P, t+1) \ge t
$$

  Zero Build Churn Invariant:
  Let $\mathcal{T}_{\text{build}}$ denote the set of downstream build tasks or compilation units that declare $P$ as an input dependency. A downstream task $T \in \mathcal{T}_{\text{build}}$ triggers re-execution if and only if the dependency timestamp is strictly greater than the task cached build timestamp $\tau_{\text{cached}}(T)$:

$$
\text{NeedsRebuild}(T, P) \iff \text{mtime}(P, t+1) \gt \tau_{\text{cached}}(T)
$$

  Consequently, bypassing unmodified file writes guarantees zero downstream build churn:

$$
\text{ShouldWrite}(P, B_{\text{new}}) = \text{false} \implies \forall T \in \mathcal{T}_{\text{build}}, \quad \text{NeedsRebuild}(T, P) = \text{false}
$$

  Filesystem Inode and Metadata Invariance:
  When writing is bypassed, filesystem inode identity, file permissions, and size remain invariant:

$$
\text{ShouldWrite}(P, B_{\text{new}}) = \text{false} \implies \begin{aligned}
\text{inode}(P, t+1) &= \text{inode}(P, t) \\
\text{mode}(P, t+1) &= \text{mode}(P, t) \\
\text{size}(P, t+1) &= \text{size}(P, t)
\end{aligned}
$$

  Short-Circuit Evaluation Invariant:
  Let $\text{MmapInvoked}(P) \in \{ \text{true}, \text{false} \}$ indicate whether a memory-mapping system call was executed for target path $P$. If file sizes differ, memory mapping is strictly bypassed:

$$
\text{FileSize}(P) \ne |B_{\text{new}}| \implies \text{MmapInvoked}(P) = \text{false}
$$

  Zero Dynamic Heap Allocation Invariant:
  The memory-mapped diff engine executes comparisons directly between the in-memory buffer and the page-cache-backed virtual memory buffer with zero dynamic heap allocations:

$$
\text{HeapAllocs}(\text{DiffEngine}(P, B_{\text{new}})) = 0
$$

  Byte-Level Equivalence Invariant:
  Let $B_{\text{disk}} = \mathcal{B}_{\text{mmap}}(P)$ when $\text{FileSize}(P) = |B_{\text{new}}| = L$. Byte buffer equality holds if and only if every byte index matches identically:

$$
B_{\text{disk}} = B_{\text{new}} \iff \forall i \in \{0, 1, \dots, L - 1\}, \quad B_{\text{disk}}[i] = B_{\text{new}}[i]
$$

  Let $k^* \in \{0, 1, \dots, L\}$ denote the index of the first byte divergence:

$$
k^* = \min\left( \{ i \in \{0, 1, \dots, L - 1\} \mid B_{\text{disk}}[i] \ne B_{\text{new}}[i] \} \cup \{ L \} \right)
$$

$$
B_{\text{disk}} = B_{\text{new}} \iff k^* = L
$$

  Parallel Work-Stealing Bounded Execution Invariant:
  Let $\mathcal{A}_{\text{out}} = \{ (P_1, B_{\text{new}, 1}), (P_2, B_{\text{new}, 2}), \dots, (P_K, B_{\text{new}, K}) \}$ denote the collection of $K$ candidate emission artifacts distributed across $N_{\text{max\_workers}}$ threads scheduled on the bounded work-stealing pool:

$$
T_{\text{persistence}}(\mathcal{A}_{\text{out}}) \le \left\lceil \frac{K}{N_{\text{max\_workers}}} \right\rceil \cdot \max_{j \in \{1, \dots, K\}} T_{\text{diff}}(P_j, B_{\text{new}, j}) + c_{\text{pool}}
$$

  Diagnostic Error Code Binding Invariant:
  Filesystem access faults, mapping errors, or I/O failures trigger structured diagnostic records in accordance with REQ-0191:

$$
\begin{aligned}
\text{PermissionDenied}(P) &\implies \text{Diagnostic}(\text{span}(P), \text{DiagnosticCode::E0200}, \text{FileAccessDenied}) \in \mathcal{D} \\
\text{MappingFailed}(P) &\implies \text{Diagnostic}(\text{span}(P), \text{DiagnosticCode::E0200}, \text{MemoryMappingFailure}) \in \mathcal{D} \\
\text{IOBusError}(P) &\implies \text{Diagnostic}(\text{span}(P), \text{DiagnosticCode::E0200}, \text{FilesystemIOError}) \in \mathcal{D}
\end{aligned}
$$

  Diagnostic Taxonomy Containment Invariant:
  All diagnostics emitted by the persistence diff engine strictly belong to the Subsystem 3 metamodel and typing family:

$$
\forall d \in \mathcal{D}_{\text{persistence}}, \quad \text{code}(d) = \text{DiagnosticCode::E0200} \in \mathcal{E}_{\text{type}}
$$

- **Computational Complexity & Algorithmic Bounds**: The memory-mapped diff engine and persistence bypass execute strictly within Complexity Class $\mathbf{P}$. Algorithmic execution adheres to the following exact computational bounds:
  1. Metadata Inspection: Querying filesystem metadata (`stat`) to determine file existence and on-disk size $\text{FileSize}(P)$ executes in $O(1)$ constant time via operating system directory and inode cache lookups.
  2. Size Mismatch Fast Short-Circuit: When $\text{FileSize}(P) \ne |B_{\text{new}}|$, the decision predicate terminates in strict $O(1)$ time, bypassing memory mapping, file reading, and byte comparison completely.
  3. Memory Mapping Overhead: Establishing the read-only memory-mapped buffer view $\mathcal{B}_{\text{mmap}}(P)$ requires $O(1)$ operating system page-table setup operations. Virtual address space is allocated without copying physical pages until accessed.
  4. Memory Comparison: For matching file sizes $L = |B_{\text{new}}|$, byte comparison executes in $O(k^*)$ operations, where $k^* \le L$ is the index of the first differing byte. In the worst-case scenario (where files are identical or differ only at the terminal byte, $k^* = L$), comparison executes in deterministic $O(L)$ linear time proportional to buffer length $L$.
  5. Vectorized SIMD Acceleration: Word-level comparisons evaluate $W$ bytes per machine instruction ($W = 32\text{ bytes}$ for 256-bit SIMD registers), reducing the inner loop iteration count to $\lceil L / W \rceil$, achieving memory bandwidth saturation bounded by CPU L1/L2 cache and page cache throughput.
  6. Parallel Persistence Scaling: When evaluating $K$ output artifacts concurrently across $N_{\text{max\_workers}}$ threads scheduled on the bounded work-stealing pool, total persistence wall-clock runtime is bounded by $O(\lceil K / N_{\text{max\_workers}} \rceil \cdot \bar{L})$, where $\bar{L} = \frac{1}{K} \sum_{j=1}^K |B_{\text{new}, j}|$ is the average artifact byte size.
  7. Space Complexity: Auxiliary heap space is strictly $O(1)$ constant memory. The diff engine performs zero dynamic heap allocations, comparing the pre-existing generated buffer $B_{\text{new}}$ directly against the virtual memory-mapped slice. Auxiliary stack frame depth is strictly bounded by $O(1)$.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic MBSE compilation units using abstract placeholders (`Package_0`, `Classifier_Alpha`, `Port_1`, `Flow_A`, `param_x : Real`, `Artifact_0`, `Path_0`). Conformance validation shall enforce the following test gates:
  1. Bitwise Identity & `mtime` Preservation Gate: Run emission across a suite of $N = 100$ synthetic output artifacts; immediately re-run the compilation pipeline with identical AST inputs; assert that 100% of target files maintain identical `mtime` timestamps ($\text{mtime}(P, t+1) == \text{mtime}(P, t)$) and that zero write system calls are executed against the filesystem.
  2. File Size Mismatch Fast Short-Circuit Gate: Test against on-disk files whose byte sizes differ by $+1$, $-1$, and $\pm 1024$ bytes relative to $B_{\text{new}}$. Assert that $\text{FileSize}(P) \ne |B_{\text{new}}|$ short-circuits in $O(1)$ time, verifying via system call instrumentation that memory-mapping primitives are never invoked ($\text{MmapInvoked}(P) == \text{false}$) and that write operations proceed immediately.
  3. Single-Byte Divergence Detection Gate: Generate artifact payloads differing by exactly 1 bit or 1 byte at the initial byte ($k = 0$), the midpoint byte ($k = \lfloor L/2 \rfloor$), and the final byte ($k = L - 1$). Assert that the diff engine detects divergence, evaluates $\text{ShouldWrite} == \text{true}$, commits the modified artifact, and advances $\text{mtime}$.
  4. Downstream Build Churn Prevention Gate: Connect a synthetic build harness monitoring file modification timestamps of compiler emission targets. Assert that re-running compilation on unchanged models triggers zero downstream target rebuilds ($\text{NeedsRebuild} == \text{false}$ across 100% of targets).
  5. Zero Dynamic Heap Allocation Gate: Instrument the compiler memory allocator during the diff comparison phase of pre-existing identical files. Assert that exactly zero dynamic heap allocations occur ($\text{HeapAllocs} == 0$).
  6. Non-Existent Target Path Gate: Verify that non-existent target paths immediately evaluate $\text{ShouldWrite} == \text{true}$ and are created atomically with correct directory structures and file permissions.
  7. Bounded Work-Stealing Parallelism Gate: Concurrently evaluate diffs across $K = 500$ output files on a work-stealing pool bounded by $N_{\text{max\_workers}}$ threads adhering to Architectural Directive 2 and REQ-0012. Assert zero data races, thread-isolated memory mappings, and identical bitwise results.
  8. Total Function and Non-Panicking Diagnostic Gate: Simulate filesystem error conditions (read-only target files, unreadable destination directories, invalid paths, and simulated bus faults). Assert that the persistence engine emits structured diagnostic error code `E0200` per REQ-0191 and terminates the operation gracefully without panicking or process unwinding per Architectural Directive 5.
  9. Deterministic RFC 4122 UUIDv5 Anchor Gate: Verify that 100% of persisted artifacts and manifest descriptors maintain deterministic RFC 4122 UUIDv5 identifiers derived from the compiler namespace UUID and canonical topological paths per Architectural Directive 1 and REQ-0010.
  10. Release Mode Latency and Memory Budget Gate: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per Architectural Directive 5 and REQ-0196, assert that diff evaluation across $10^3$ output files completes in $< 25\text{ ms}$ with peak memory RSS $< 100\text{ MB}$.
  11. Bitwise Parity & Zero Churn Gate: Assert 0-byte diff churn across repeated compilations of synthetic test suites.
