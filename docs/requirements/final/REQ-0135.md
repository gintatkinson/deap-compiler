### REQ-0135: STPA Minimal Hazard Cut-Sets & Unsafe Control Action Minimization (NP-4)

#### 1. Normative Statement

The safety compiler, formal hazard analysis engine, and traceability verification pipeline of Subsystem 7 shall solve the minimal hazard cut-set problem by determining the minimal hitting set of safety constraints covering all identified system hazards across candidate unsafe control actions (UCAs), executing via a deterministic polynomial-time greedy logarithmic approximation engine or an exact bounded Min-Unsat / MaxSAT SMT reduction engine governed by a deterministic execution step budget $`\kappa_{\text{safety}}`$.

  Specifically, the safety compiler, cut-set solver, and hazard minimization pipeline shall strictly enforce the following structural, algebraic, and algorithmic invariants across all compilation units:
  1. **Hazard Scenario Hypergraph & Candidate Constraint Space**:
     - The safety compiler shall represent the global hazard-mitigation topology as an abstract hypergraph $`\mathcal{H}_{\text{hyper}} = (\mathcal{C}, \mathcal{H})`$`, where vertex universe `$`\mathcal{C} = \{ c_1, c_2, \dots, c_n \}`$` denotes candidate mitigating safety constraints and hyperedge family `$`\mathcal{H} = \{ H_1, H_2, \dots, H_m \}`$ denotes system hazard scenarios.
     - Each hazard scenario $`H_i \in \mathcal{H}`$` shall define a non-empty cut-set of candidate mitigating constraints `$`\mathbf{C}_{\text{mitig}}(H_i) \subseteq \mathcal{C}`$`, such that enforcement of any single constraint `$`c \in \mathbf{C}_{\text{mitig}}(H_i)`$ is formally certified to prevent or mitigate the hazardous state.
     - Each candidate safety constraint $`c_j \in \mathcal{C}`$` shall define an associated hazard coverage set `$`\text{Cov}(c_j) = \{ H_i \in \mathcal{H} \mid c_j \in \mathbf{C}_{\text{mitig}}(H_i) \} \subseteq \mathcal{H}`$.
     - Each candidate safety constraint $`c_j \in \mathcal{C}`$` may optionally define an explicit rational cost weight `$`w(c_j) \in \mathbb{Q}^+`$` representing architectural, computational, or latency overhead (defaulting to uniform unit weight `$`w(c_j) = 1.0`$).
     - All hazard scenario and constraint descriptors shall be allocated in contiguous bump arena storage with deterministic RFC 4122 UUIDv5 identifiers.
  2. **Minimal Hitting Set Formulation (Algorithmic Bound NP-4)**:
     - In accordance with Algorithmic Bound NP-4, determining the minimal hitting set covering a family of hazard cut-sets is NP-complete (equivalent to Minimal Hitting Set and Hypergraph Transversal).
     - A valid hitting set $`C \subseteq \mathcal{C}`$ must satisfy the universal coverage invariant:

```math
\forall H_i \in \mathcal{H}, \quad C \cap \mathbf{C}_{\text{mitig}}(H_i) \ne \emptyset
```

     - The minimal hitting set optimization problem seeks a constraint subset $`C^* \subseteq \mathcal{C}`$ that minimizes total constraint cost:

```math
C^* = \arg\min_{C \subseteq \mathcal{C}} \left\{ \sum_{c \in C} w(c) \;\middle|\; \forall H_i \in \mathcal{H}, \, C \cap \mathbf{C}_{\text{mitig}}(H_i) \ne \emptyset \right\}
```

  3. **Deterministic Greedy Logarithmic Approximation Engine**:
     - In standard compilation mode (`OptimizationMode::Greedy`), the safety compiler shall compute an approximate minimal hitting set $`C_{\text{greedy}} \subseteq \mathcal{C}`$ using an iterative greedy selection algorithm operating in deterministic polynomial time.
     - At each iteration step $`t \ge 0`$`, let `$`\mathcal{H}_{\text{uncovered}}^{(t)} \subseteq \mathcal{H}`$` denote the set of hazard scenarios not yet hit by selected constraints `$`C^{(t)}`$` (with `$`C^{(0)} = \emptyset`$` and `$`\mathcal{H}_{\text{uncovered}}^{(0)} = \mathcal{H}`$).
     - The greedy selection rule shall select the candidate constraint $`c_{(t+1)} \in \mathcal{C} \setminus C^{(t)}`$ maximizing the marginal coverage-to-cost ratio:

```math
c_{(t+1)} = \arg\max_{c \in \mathcal{C} \setminus C^{(t)}} \left\{ \frac{|\text{Cov}(c) \cap \mathcal{H}_{\text{uncovered}}^{(t)}|}{w(c)} \right\}
```

     - Strict deterministic tie-breaking: If multiple candidate constraints achieve the identical maximal ratio, the compiler shall select the candidate constraint with the lowest lexicographical fully qualified name ($`\text{FQN}(c)`$) or RFC 4122 UUIDv5 byte order, guaranteeing zero-churn bitwise determinism across compilation passes.
     - The greedy selection loop shall terminate when $`\mathcal{H}_{\text{uncovered}}^{(t)} = \emptyset`$, guaranteeing the theoretical logarithmic approximation ratio:

```math
\sum_{c \in C_{\text{greedy}}} w(c) \le \left( 1 + \ln |\mathcal{H}| \right) \cdot \sum_{c \in C^*} w(c)
```

       and for maximum cut-set cardinality $`d = \max_{H_i \in \mathcal{H}} |\mathbf{C}_{\text{mitig}}(H_i)|`$`, `$`|C_{\text{greedy}}| \le H_d \cdot |C^*| = \left( \sum_{k=1}^d \frac{1}{k} \right) \cdot |C^*|`$.
  4. **Exact Bounded Min-Unsat / MaxSAT SMT Reduction Engine**:
     - When exact optimization mode is specified (`OptimizationMode::Exact`), the safety compiler shall lower the minimal hitting set problem into a Partial MaxSAT / Min-Unsat formula $`\Phi_{\text{MHS}} = \Phi_{\text{hard}} \land \Phi_{\text{soft}}`$` over boolean indicator variables `$`\{ x_c \mid c \in \mathcal{C} \}`$`, where `$`x_c = \text{true}`$` denotes selection of constraint `$`c`$:
       * Hard clauses: For each hazard scenario $`H_i \in \mathcal{H}`$, the compiler emits the hard disjunctive clause:

```math
\bigvee_{c \in \mathbf{C}_{\text{mitig}}(H_i)} x_c
```

         mandating that at least one candidate constraint mitigating $`H_i`$ must evaluate to true.
       * Soft clauses: For each candidate constraint $`c \in \mathcal{C}`$`, the compiler emits the weighted soft clause `$`\langle \neg x_c, \, w(c) \rangle`$`, penalizing the selection of constraint `$`c`$.
     - The solver shall execute an integrated core-guided MaxSAT / Min-Unsat algorithm under a strict deterministic step budget $`\kappa_{\text{safety}}`$` (defaulting to `$`\kappa_{\text{safety}} = 10^5`$ operations).
     - Each CDCL decision step, conflict analysis iteration, and unsatisfiable core extraction shall increment a monotonic step counter $`N_{\text{step}}`$.
     - If the solver establishes exact optimality ($`\Phi_{\text{MHS}} \implies C^*`$`) within `$`N_{\text{step}} \le \kappa_{\text{safety}}`$`, the compiler emits the certified optimal minimal hitting set `$`C^*`$.
     - If the solver exceeds the step budget ($`N_{\text{step}} \gt \kappa_{\text{safety}}`$) without proving optimality, compilation shall fail deterministically with diagnostic error code `E0406` (`SafetySolverStepLimitExceeded`), reporting the unreduced hazard cut-sets, active decision depth, and step limit cutoff, unless automatic fallback to greedy mode (`FallbackPolicy::GreedyOnTimeout`) is configured.
  5. **Unmitigated Hazard Scenario Detection (`E0400`)**:
     - If any declared hazard scenario $`H_i \in \mathcal{H}`$` possesses an empty candidate mitigation set (`$`\mathbf{C}_{\text{mitig}}(H_i) = \emptyset`$`), the hard clause for `$`H_i`$` is unsatisfiable (`$`\bigvee_{c \in \emptyset} x_c \equiv \text{false}`$).
     - The safety compiler shall immediately identify unmitigated hazards and deterministically reject the compilation unit at compile time with diagnostic error code `E0400` (`UnmitigatedHazardScenario`), reporting the hazard identifier, participating unsafe control actions, and source span coordinates.
     - If the compilation unit declares hazards ($`\mathcal{H} \ne \emptyset`$`) while the candidate safety constraint universe is completely empty (`$`\mathcal{C} = \emptyset`$), the compiler shall emit diagnostic error code `E0400` (`EmptyConstraintCoverage`).
  6. **STPA Unsafe Control Action (UCA) Cut-Set Duality**:
     - The safety compiler shall maintain bidirectional traceability between hazard scenarios $`\mathcal{H}`$` and unsafe control actions `$`\mathcal{U}_{\text{UCA}} \subseteq A \times G \times S_{\text{context}}`$ generated in REQ-0136.
     - Each hazard $`H_i \in \mathcal{H}`$` is causally induced by a cut-set of unsafe control actions `$`\mathbf{U}_i \subseteq \mathcal{U}_{\text{UCA}}`$.
     - Dually, the safety compiler shall compute the minimal UCA cut-sets $`\mathbf{K}_{\text{UCA}} \subseteq \mathcal{P}(\mathcal{U}_{\text{UCA}})`$ whose simultaneous prevention eliminates all causal paths to system hazards.
     - The compiler shall verify that for every computed minimal UCA cut-set $`K \in \mathbf{K}_{\text{UCA}}`$`, the synthesized hitting set constraints `$`C^*`$` enforce corresponding boolean invariants (REQ-0137) sufficient to eliminate `$`K`$.
  7. **Hypergraph Pre-Processing & Absorption Reductions**:
     - Prior to invoking either the greedy or exact solver, the compiler shall execute polynomial-time hypergraph simplification reductions:
       * *Subset Elimination (Absorption)*: If two hazard scenarios satisfy $`\mathbf{C}_{\text{mitig}}(H_a) \subseteq \mathbf{C}_{\text{mitig}}(H_b)`$`, then any constraint hitting `$`H_a`$` necessarily hits `$`H_b`$`. The compiler shall subsume and remove dominated hyperedge `$`H_b`$ from the active solver formulation.
       * *Singleton Constraint Enlistment*: If $`|\mathbf{C}_{\text{mitig}}(H_k)| = 1`$` with unique constraint `$`c`$`, constraint `$`c`$` is mandatory (`$`c \in C^*`$`). The compiler shall immediately enlist `$`c`$` into the solution set, prune all hazards hit by `$`c`$`, and remove `$`c`$` from `$`\mathcal{C}`$.
  8. **Executive Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every hazard scenario node, candidate safety constraint record, hypergraph cut-set, and hitting set solution artifact shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel extraction of hazard scenarios, independent hypergraph connected component partitioning, dual UCA cut-set generation, and multi-package hitting set evaluations shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Allocation Exception)*: Hazard names, constraint identifiers, UCA labels, guide words, and fully qualified path strings shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The safety compiler shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When hazard completeness violations (`E0400`) or solver timeouts (`E0406`) occur, diagnostics shall accumulate in the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{cutset}}`$`, `$`\bot_{\text{hazard}}`$`), and continue validating subsequent safety declarations. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The hazard minimization and cut-set solver pipeline shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($`\lt 25\text{ ms}`$` for `$`10^3`$` hazards and candidate constraints) and peak RSS memory (`$`\lt 100\text{ MB}`$) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Hazard_0`, `Hazard_1`, `Hazard_Alpha`, `Hazard_Beta`, `Constraint_0`, `Constraint_1`, `Constraint_Alpha`, `Constraint_Beta`, `UCA_1`, `UCA_2`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous bump arena storage.

  Let $`\mathcal{H}_{\text{hyper}} = (\mathcal{C}, \mathcal{H})`$ denote the abstract hazard-mitigation hypergraph.

  The candidate safety constraint universe is formalized as:

```math
  \mathcal{C} = \{ c_1, c_2, \dots, c_n \} \subset \mathcal{V}_{\text{AST}}
```

  Each candidate safety constraint $`c_j \in \mathcal{C}`$ is formalized as a 7-tuple:

```math
  c_j = \langle \text{id}_{c_j}, \text{name}_{c_j}, \text{expr}_{c_j}, w(c_j), \text{Cov}(c_j), \Delta_{c_j}, \text{span}_{c_j} \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_{c_j} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_{c_j} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
  \text{expr}_{c_j} &\in \mathcal{E}_{\text{expr}} \quad (\text{boolean constraint expression AST handle}) \\
  w(c_j) &\in \mathbb{Q}^+ \quad (\text{strictly positive constraint cost weight}) \\
  \text{Cov}(c_j) &\subseteq \mathcal{H} \quad (\text{set of hazards mitigated by constraint } c_j) \\
  \Delta_{c_j} &\in \Sigma^{36} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_{c_j} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance span})
  \end{aligned}
```

  The family of hazard scenarios is formalized as:

```math
  \mathcal{H} = \{ H_1, H_2, \dots, H_m \} \subset \mathcal{V}_{\text{AST}}
```

  Each hazard scenario $`H_i \in \mathcal{H}`$ is formalized as an 8-tuple:

```math
  H_i = \langle \text{id}_{H_i}, \text{name}_{H_i}, \mathbf{U}_i, \mathbf{C}_{\text{mitig}}(H_i), \text{sev}_i, \Delta_{H_i}, \text{provenance}_{H_i}, \text{span}_{H_i} \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_{H_i} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_{H_i} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
  \mathbf{U}_i &\subseteq \mathcal{U}_{\text{UCA}} \quad (\text{set of unsafe control actions causally linked to hazard } H_i) \\
  \mathbf{C}_{\text{mitig}}(H_i) &\subseteq \mathcal{C} \quad (\text{candidate mitigating safety constraints for hazard } H_i) \\
  \text{sev}_i &\in \{ \text{Catastrophic}, \text{Critical}, \text{Major}, \text{Minor} \} \quad (\text{hazard severity classification}) \\
  \Delta_{H_i} &\in \Sigma^{36} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{provenance}_{H_i} &\in \mathcal{V}_{\text{AST}} \quad (\text{owning structural block or component handle}) \\
  \text{span}_{H_i} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance span})
  \end{aligned}
```

  Incidence Duality Invariant:

```math
  \forall c \in \mathcal{C}, \forall H \in \mathcal{H}, \quad H \in \text{Cov}(c) \iff c \in \mathbf{C}_{\text{mitig}}(H)
```

  1. Universal Hitting Set Coverage Invariant:
  A constraint subset $`C \subseteq \mathcal{C}`$` is a valid hitting set for `$`\mathcal{H}`$ if and only if:

```math
  \forall H_i \in \mathcal{H}, \quad C \cap \mathbf{C}_{\text{mitig}}(H_i) \ne \emptyset
```

  Equivalently, expressed via hazard coverage:

```math
  \bigcup_{c \in C} \text{Cov}(c) = \mathcal{H}
```

  2. Minimal Hitting Set Optimization Invariant:
  The optimal hitting set $`C^* \subseteq \mathcal{C}`$ minimizes the aggregate objective function:

```math
  C^* = \arg\min_{C \subseteq \mathcal{C}} \left\{ \sum_{c \in C} w(c) \;\middle|\; \forall H_i \in \mathcal{H}, \, C \cap \mathbf{C}_{\text{mitig}}(H_i) \ne \emptyset \right\}
```

  Under uniform unit cost weights ($`w(c) = 1`$` for all `$`c \in \mathcal{C}`$):

```math
  C^* = \arg\min_{C \subseteq \mathcal{C}} \left\{ |C| \;\middle|\; \forall H_i \in \mathcal{H}, \, C \cap \mathbf{C}_{\text{mitig}}(H_i) \ne \emptyset \right\}
```

  3. Deterministic Greedy Logarithmic Approximation Invariant:
  The greedy sequence of selected constraints $`C_{\text{greedy}} = \{ c_{(1)}, c_{(2)}, \dots, c_{(k)} \}`$ is generated by:

```math
  \begin{aligned}
  C^{(0)} &= \emptyset \\
  \mathcal{H}_{\text{uncovered}}^{(0)} &= \mathcal{H} \\
  c_{(t+1)} &= \arg\max_{c \in \mathcal{C} \setminus C^{(t)}} \left\{ \frac{|\text{Cov}(c) \cap \mathcal{H}_{\text{uncovered}}^{(t)}|}{w(c)} \right\} \\
  C^{(t+1)} &= C^{(t)} \cup \{ c_{(t+1)} \} \\
  \mathcal{H}_{\text{uncovered}}^{(t+1)} &= \mathcal{H}_{\text{uncovered}}^{(t)} \setminus \text{Cov}(c_{(t+1)})
  \end{aligned}
```

  Deterministic Tie-Breaking Rule:

```math
  \begin{aligned}
  \mathbf{T}^{(t)} &= \arg\max_{c \in \mathcal{C} \setminus C^{(t)}} \left\{ \frac{|\text{Cov}(c) \cap \mathcal{H}_{\text{uncovered}}^{(t)}|}{w(c)} \right\} \\
  c_{(t+1)} &= \min_{\text{lex}} \left\{ \text{FQN}(c) \;\middle|\; c \in \mathbf{T}^{(t)} \right\}
  \end{aligned}
```

  Greedy Approximation Ratio Bound:

```math
  \sum_{c \in C_{\text{greedy}}} w(c) \le \left( 1 + \ln |\mathcal{H}| \right) \cdot \sum_{c \in C^*} w(c)
```

  and for maximum cut-set size $`d = \max_{H_i \in \mathcal{H}} |\mathbf{C}_{\text{mitig}}(H_i)|`$:

```math
  |C_{\text{greedy}}| \le H_d \cdot |C^*| = \left( \sum_{k=1}^d \frac{1}{k} \right) \cdot |C^*|
```

  4. Exact Min-Unsat / MaxSAT SMT Reduction Invariant:
  Let $`x_c \in \{0, 1\}`$` denote the boolean decision literal for candidate constraint `$`c \in \mathcal{C}`$.
  The minimal hitting set instance is lowered to the partial MaxSAT formula $`\Phi_{\text{MHS}}`$:

```math
  \Phi_{\text{MHS}} = \Phi_{\text{hard}} \land \Phi_{\text{soft}}
```

  where:

```math
  \begin{aligned}
  \Phi_{\text{hard}} &= \bigwedge_{H_i \in \mathcal{H}} \left( \bigvee_{c \in \mathbf{C}_{\text{mitig}}(H_i)} x_c \right) \\
  \Phi_{\text{soft}} &= \bigwedge_{c \in \mathcal{C}} \langle \neg x_c, \, w(c) \rangle
  \end{aligned}
```

  Optimal solution extraction:

```math
  C^* = \{ c \in \mathcal{C} \mid x_c = \text{true} \text{ in optimal model of } \Phi_{\text{MHS}} \}
```

  5. Safety Solver Monotonic Step Bound Invariant:

```math
  N_{\text{step}} = \text{Steps}(\text{MaxSAT\_Solver}(\Phi_{\text{MHS}})) \le \kappa_{\text{safety}}
```

  6. Hypergraph Absorption Reduction Invariants:

```math
  \begin{aligned}
  \exists H_a, H_b \in \mathcal{H} : \mathbf{C}_{\text{mitig}}(H_a) \subseteq \mathbf{C}_{\text{mitig}}(H_b) &\implies \mathcal{H}_{\text{reduced}} = \mathcal{H} \setminus \{ H_b \} \\
  \exists H_k \in \mathcal{H} : \mathbf{C}_{\text{mitig}}(H_k) = \{ c \} &\implies c \in C^* \;\land\; \mathcal{H}_{\text{reduced}} = \mathcal{H} \setminus \text{Cov}(c)
  \end{aligned}
```

  7. Deterministic Diagnostic Trigger Rules (REQ-0191):

```math
  \begin{aligned}
  \exists H_i \in \mathcal{H} : \mathbf{C}_{\text{mitig}}(H_i) = \emptyset &\implies \text{Diagnostic}(H_i, \text{DiagnosticCode::E0400}, \text{UnmitigatedHazardScenario}) \in \mathcal{D}_{\text{sink}} \\
  (\mathcal{H} \ne \emptyset \land \mathcal{C} = \emptyset) &\implies \text{Diagnostic}(\mathcal{H}, \text{DiagnosticCode::E0400}, \text{EmptyConstraintCoverage}) \in \mathcal{D}_{\text{sink}} \\
  N_{\text{step}} \gt \kappa_{\text{safety}} &\implies \text{Diagnostic}(\mathcal{H}, \text{DiagnosticCode::E0406}, \text{SafetySolverStepLimitExceeded}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  8. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
  \begin{aligned}
  \forall H_i \in \mathcal{H}, &\quad \Delta_{H_i} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(H_i)) \\
  \forall c_j \in \mathcal{C}, &\quad \Delta_{c_j} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(c_j)) \\
  \forall K \in \mathbf{K}_{\text{UCA}}, &\quad \Delta_K = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(K)) \\
  \Delta_{C^*} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\text{"MinimalHittingSet"}))
  \end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

Minimal Hazard Cut-Sets & Unsafe Control Action Minimization resides in **Complexity Class NP-complete** for the decision formulation (determining whether there exists a hitting set $`C^*`$` with `$`|C^*| \le k`$`), and is **NP-hard** for the optimization formulation (finding `$`\min \sum w(c)`$) in accordance with Algorithmic Bound NP-4 (Karp, 1972; Garey & Johnson, 1979).

  **Mathematical Delineation from Other Algorithmic Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 addresses qualitative temporal interval algebra path consistency and difference logic SMT solving. In contrast, NP-4 solves combinatorial hypergraph transversals and minimum hitting sets over discrete boolean hazard-mitigation incidence matrices.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses vector bin packing and multi-capacity resource allocation. In contrast, NP-4 is an uncapacitated hitting set coverage problem where each hyperedge must be intersected by at least one selected vertex.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 addresses PSPACE-complete orthogonal state machine reachability. In contrast, NP-4 evaluates static hazard cut-sets extracted from the AST model without state-space unrolling.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the satisfiability of arbitrary first-order invariant formulas via DPLL(T). In contrast, NP-4 utilizes propositional Horn-clause structures and partial MaxSAT formulations dedicated to hitting set minimization.

  **Asymptotic Complexity Analysis**:
  Let $`m = |\mathcal{H}|`$` denote the number of hazard scenarios, `$`n = |\mathcal{C}|`$` denote the number of candidate safety constraints, and `$`L = \sum_{H_i \in \mathcal{H}} |\mathbf{C}_{\text{mitig}}(H_i)| = \sum_{c \in \mathcal{C}} |\text{Cov}(c)|`$` denote the total number of incidence pairs in the hazard-constraint bipartite incidence graph (`$`L \le m \cdot n`$).
  1. *Hypergraph Ingestion & Inverted Index Construction*:
     Traversing the bump arena AST nodes to extract hazard scenarios $`\mathcal{H}`$`, candidate constraints `$`\mathcal{C}`$, and constructing the inverted coverage map takes:

```math
T_{\text{index}}(m, n, L) \in O(m + n + L)
```

  2. *Unmitigated Hazard Scenario Detection*:
     Verifying $`\mathbf{C}_{\text{mitig}}(H_i) \ne \emptyset`$ for each hazard scenario requires scanning the hyperedge degrees, executing in:

```math
T_{\text{unmitigated}}(m) \in O(m)
```

  3. *Hypergraph Simplification & Absorption Reductions*:
     Sorting hyperedges by cardinality and performing pairwise subset checks using 64-bit word bitsets takes $`O(m \cdot \lceil n / 64 \rceil)`$ per pair, bounded in practice by:

```math
T_{\text{absorption}}(m, n) \in O(m^2 \cdot \lceil n / 64 \rceil)
```

     Dominance pruning removes redundant hyperedges, significantly shrinking the solver instance.
  4. *Greedy Logarithmic Approximation Engine Complexity*:
     The greedy algorithm maintains candidate constraints in bucket queues indexed by dynamic uncovered coverage count $`\delta(c) = |\text{Cov}(c) \cap \mathcal{H}_{\text{uncovered}}|`$.
     Selecting the maximal ratio candidate constraint takes $`O(1)`$ amortized time.
     When candidate $`c`$ is selected, marking incident hazards as covered decrements the coverage counts of competing constraints.
     Across the entire algorithm, each incidence pair $`(H_i, c_j)`$` is visited at most once when hazard `$`H_i`$ transitions from uncovered to covered.
     Therefore, greedy hitting set construction executes in deterministic polynomial time:

```math
T_{\text{greedy}}(m, n, L) \in O(m + n + L) \subseteq O(m \cdot n)
```

     guaranteeing $`O(m \cdot n)`$ worst-case execution without backtracking or branching.
  5. *Exact Bounded Min-Unsat / MaxSAT SMT Reduction*:
     Generating the MaxSAT formula $`\Phi_{\text{MHS}} = \Phi_{\text{hard}} \land \Phi_{\text{soft}}`$` produces `$`m`$` hard disjunctions with `$`L`$` literals and `$`n`$` weighted soft unit clauses, constructed in `$`O(m + n + L)`$ time.
     While unconstrained MaxSAT has exponential worst-case complexity $`O(2^n \cdot (m + n))`$`, the compiler enforces an explicit deterministic step budget `$`\kappa_{\text{safety}}`$.
     Under the monotonic step counter $`N_{\text{step}} \le \kappa_{\text{safety}}`$, the computational cost of the exact solver is strictly bounded by:

```math
T_{\text{exact}}(m, n, \kappa_{\text{safety}}) \in O(\kappa_{\text{safety}} \cdot (m + n))
```

     If $`N_{\text{step}} \gt \kappa_{\text{safety}}`$`, the compiler terminates execution deterministically in `$`O(1)`$ operations with diagnostic `E0406`, precluding exponential solver stagnation.
  6. *Aggregate Worst-Case Time Complexity*:
     - In greedy approximation mode:

```math
T_{\text{total, greedy}}(m, n, L) \in O(m^2 \cdot \lceil n / 64 \rceil + m \cdot n)
```

     - In exact Min-Unsat mode:

```math
T_{\text{total, exact}}(m, n, L, \kappa_{\text{safety}}) \in O(m^2 \cdot \lceil n / 64 \rceil + \kappa_{\text{safety}} \cdot (m + n))
```

  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     When evaluating $`P`$` independent hazard packages or hypergraph connected components across `$`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool:

```math
T_{\text{parallel}}(m, n, L, \kappa_{\text{safety}}, N_{\text{max\_workers}}) \in O\left( \frac{m \cdot n + \kappa_{\text{safety}} \cdot (m + n)}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  8. *Space Complexity & Arena Memory Bounds*:
     Allocations for candidate constraints, hazard scenarios, hypergraph incidence bitsets, and solver clause structures reside in contiguous bump arena storage, requiring $`O(m \cdot \lceil n / 64 \rceil)`$` bytes for bitsets and `$`O(m + n + L)`$` bytes for AST nodes. Interned symbol identifiers require `$`O(m + n)`$` bytes in the global symbol pool. The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ capacity.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Hazard_0`, `Hazard_1`, `Hazard_Alpha`, `Hazard_Beta`, `Constraint_0`, `Constraint_1`, `Constraint_Alpha`, `Constraint_Beta`, `UCA_1`, `UCA_2`, `Port_1`, `Flow_A`, `param_x : Real`) across the following 16 verification gates:

  1. **Canonical Greedy Hitting Set Gate**: Ingest synthetic model `Package_0` declaring 4 hazard scenarios `Hazard_0` through `Hazard_3` and 5 candidate safety constraints `Constraint_0` through `Constraint_4`. Verify that the greedy approximation engine computes a valid hitting set $`C_{\text{greedy}}`$ covering 100% of declared hazards and terminates with zero diagnostics emitted.
  2. **Greedy Logarithmic Approximation Bound Verification Gate**: Ingest a synthetic benchmark model where the known optimal hitting set $`C^*`$` has cardinality `$`|C^*| = 3`$` across `$`|\mathcal{H}| = 100`$` hazard scenarios. Verify that `$`|C_{\text{greedy}}| \le \lfloor (1 + \ln 100) \cdot 3 \rfloor = 16`$, validating the theoretical logarithmic approximation ratio.
  3. **Deterministic Greedy Tie-Breaking Gate**: Ingest a synthetic model declaring symmetric candidate constraints possessing identical coverage-to-cost ratios. Verify that the compiler resolves ties deterministically using fully qualified symbol name lexicographical sorting, guaranteeing 0-byte diff churn across 100 repeated compilation runs.
  4. **Exact Min-Unsat Minimal Hitting Set Gate**: Ingest a synthetic model in exact optimization mode (`OptimizationMode::Exact`) containing 8 hazard scenarios and 10 candidate constraints. Verify that the core-guided MaxSAT solver derives the exact minimal hitting set $`C^*`$` within `$`\kappa_{\text{safety}}`$ steps and outputs the minimal cardinality constraint set with zero diagnostics.
  5. **Cost-Weighted Minimal Hitting Set Gate**: Ingest a model with non-uniform constraint cost weights $`w(c)`$`. Verify that the solver minimizes aggregate cost `$`\sum_{c \in C} w(c)`$ rather than pure cardinality, selecting a single constraint of cost 1.5 over two constraints each of cost 1.0 when both candidate sets achieve full coverage.
  6. **Unmitigated Hazard Scenario Rejection Gate (`E0400`)**: Ingest a synthetic model declaring hazard scenario `Hazard_Beta` with an empty candidate mitigation set ($`\mathbf{C}_{\text{mitig}}(\text{Hazard\_Beta}) = \emptyset`$). Assert deterministic compile-time rejection with diagnostic error code `E0400` (`UnmitigatedHazardScenario`), reporting the exact AST node handle and source code span of `Hazard_Beta`.
  7. **Empty Candidate Constraint Universe Gate (`E0400`)**: Ingest a model declaring 3 hazards but 0 candidate constraints ($`\mathcal{C} = \emptyset`$). Assert deterministic compile-time rejection with diagnostic error code `E0400` (`EmptyConstraintCoverage`).
  8. **Solver Step Budget Cutoff Enforcement Gate (`E0406`)**: Ingest a complex combinatorial hitting set model in exact mode configured with a restricted step budget $`\kappa_{\text{safety}} = 50`$. Verify that when the solver exceeds 50 operations without proving optimality, compilation halts deterministically with diagnostic error code `E0406` (`SafetySolverStepLimitExceeded`), reporting the unreduced hazard cut-sets and active decision depth.
  9. **Automatic Fallback to Greedy Approximation Gate**: Ingest the same combinatorial model configured with fallback policy enabled (`FallbackPolicy::GreedyOnTimeout`). Verify that upon reaching step cutoff $`\kappa_{\text{safety}}`$, the compiler emits an informational diagnostic, invokes the greedy approximation engine, successfully returns a valid hitting set, and completes compilation.
  10. **STPA Unsafe Control Action (UCA) Cut-Set Duality Gate**: Ingest a synthetic model declaring 4 UCAs `UCA_1` through `UCA_4` inducing 3 hazard scenarios. Verify that the compiler extracts both the primal constraint hitting set and the dual minimal UCA cut-set, certifying that mitigating any minimal hitting set breaks all causal UCA hazard paths.
  11. **Disjoint Hazard Hypergraph Component Partitioning Gate**: Ingest a model containing two completely disjoint hazard-constraint subgraphs `HazardCluster_Alpha` and `HazardCluster_Beta`. Verify that the solver partitions the hypergraph into connected components, solves each component independently, and unions the resulting hitting sets with zero cross-talk.
  12. **Hypergraph Absorption and Dominated Cut-Set Pruning Gate**: Ingest a model where hazard $`H_1 \subset H_2`$` (hazard `$`H_1`$`'s mitigations are a strict subset of `$`H_2`$`'s). Verify that the engine applies hypergraph absorption reduction, pruning dominated hyperedge `$`H_2`$ prior to hitting set optimization.
  13. **Singleton Constraint Immediate Enlistment Gate**: Ingest a model containing a hazard scenario $`H_{\text{crit}}`$` mitigated by exactly one candidate constraint `$`c_{\text{mandatory}}`$`. Verify that the pre-processor immediately enlists `$`c_{\text{mandatory}}`$` into the solution set and prunes all hazards hit by `$`c_{\text{mandatory}}`$ before invoking the main solver.
  14. **Synchronization Token Error Recovery & Error Accumulation Gate (Architectural Directive 4)**: Ingest a compilation unit containing 5 distinct malformed hazard declarations (unmitigated hazards, empty constraint blocks, unresolvable UCA references) separated by statement delimiters (`;`). Verify that the compiler resynchronizes on delimiter tokens, accumulates all 5 `E0400` diagnostics with precise source spans into $`\mathcal{D}_{\text{sink}}`$`, and when the error count reaches `$`C_{\text{max\_errors}}`$, emits terminal diagnostic `E0199` and halts gracefully.
  15. **Deterministic RFC 4122 UUIDv5 Anchor Gate (Architectural Directive 1)**: Verify that 100% of generated hazard scenario nodes, candidate constraint records, cut-set hyperedges, and hitting set solution artifacts receive immutable RFC 4122 UUIDv5 identifiers derived from canonical namespace OID and symbol fully qualified paths, maintaining 0-byte diff churn across consecutive compilation runs.
  16. **Bounded Work-Stealing Parallelism & Release Mode Performance Gate (Architectural Directives 2 & 5)**: Ingest a synthetic model containing 50 independent hazard packages evaluated across $`N_{\text{max\_workers}}`$ threads on the bounded work-stealing thread pool; assert thread isolation, data-race freedom, and identical hitting set derivations compared to single-threaded execution. In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, verify that greedy hitting set computation for a benchmark model of $`10^3`$` hazards and `$`2 \times 10^3`$ candidate constraints executes in under 25 ms with peak RSS memory under 100 MB.
