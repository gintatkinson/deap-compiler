### REQ-0130: Downward Realization Completeness Gate ($`\forall \text{Element}, \exists \text{Req}`$)

- **Normative Statement**: The formal safety, traceability, and regulatory verification engine of Subsystem 7 shall construct, validate, and enforce a downward realization completeness gate across the 7-tier bipartite traceability directed acyclic graph (DAG) asserting that every declared architectural element traces backward to at least one parent system requirement.

  Specifically, the safety compiler, traceability graph builder, and realization completeness verifier shall strictly enforce the following structural, algebraic, and operational invariants:
  1. **Universal Downward Realization Completeness**:
     - The compiler shall construct the system-wide traceability DAG $`G_{\text{trace}} = (V_{\text{trace}}, E_{\text{trace}})`$, partitioned into the 7 tiers defined in REQ-0128: Mission Requirements ($`T_1 = \mathcal{R}_{\text{mission}}`$), System Requirements ($`T_2 = \mathcal{R}_{\text{system}}`$), Architectural Classifiers ($`T_3 = \mathcal{E}_{\text{architecture}}`$), Ports and Interfaces ($`T_4 = \mathcal{I}_{\text{interface}}`$), Safety Invariants ($`T_5 = \mathcal{I}_{\text{safety}}`$), Realization Code ($`T_6 = \mathcal{C}_{\text{realization}}`$), and Verification Witnesses ($`T_7 = \mathcal{W}_{\text{verification}}`$).
     - For every architectural element $`e \in \mathcal{E}_{\text{architecture}}`$ (including part definitions, part usages, component classifiers, item definitions, item usages, action definitions, action usages, state definitions, state usages, connection definitions, connection usages, interface definitions, interface usages, port definitions, and directed port usages), there shall exist at least one parent system requirement $`r \in \mathcal{R}_{\text{system}}`$ such that a valid realization relationship connects $`r`$ to $`e`$:

$$
       \exists r \in \mathcal{R}_{\text{system}} \quad \text{such that } (r, e) \in E_{\text{trace}}
$$

     - Any architectural element $`e \in \mathcal{E}_{\text{architecture}}`$ that does not trace backward to any parent requirement in $`\mathcal{R}_{\text{system}}`$ shall be flagged as an unallocated or orphan element and deterministically rejected at compile time with diagnostic error code `E0400` (`UnallocatedArchitecturalElement`).
  2. **Direct Realization and Hierarchical Trace Inheritance**:
     - Direct realization shall be declared via explicit SysML v2 `satisfy requirement` statements, realization dependencies, or allocation relationships linking an architectural element handle $`e`$ to a system requirement handle $`r`$.
     - For child architectural elements (including nested sub-parts, internal statechart states, internal action steps, and local features) embedded within an enclosing parent classifier container $`P \in \mathcal{E}_{\text{architecture}}`$ via the structural containment relation ($`e \sqsubset^+ P`$), the compiler shall support hierarchical realization inheritance:

$$
       \text{Realizers}(e) = \{ r \in \mathcal{R}_{\text{system}} \mid (r, e) \in E_{\text{trace}} \lor \exists p \in \text{anc}(e) : (r, p) \in E_{\text{trace}} \}
$$

     - When compiling under safety certification profiles (such as DO-178C DAL-A/B, ISO 26262 ASIL-D, or IEC 61508 SIL-3, in accordance with REQ-0144), the compiler shall support a configurable `strict_leaf_realization` mode requiring explicit, non-inherited realization edges for all designated safety-critical leaf elements. Any safety-critical leaf element relying solely on ancestor inheritance in strict mode shall be deterministically rejected with diagnostic error code `E0400` (`MissingLeafRealizationTrace`).
  3. **Transitive Grounding to Mission Requirements ($`T_1`$)**:
     - The realization completeness gate shall verify end-to-end upward transitivity: for every architectural element $`e \in \mathcal{E}_{\text{architecture}}`$ and its realizing system requirement $`r \in \mathcal{R}_{\text{system}}`$, requirement $`r`$ must itself trace upward to at least one root mission requirement $`m \in \mathcal{R}_{\text{mission}}`$ ($`T_1`$):

$$
       \forall e \in \mathcal{E}_{\text{architecture}}, \quad \exists r \in \mathcal{R}_{\text{system}}, \exists m \in \mathcal{R}_{\text{mission}} : (m, r) \in E_{\text{trace}} \land (r, e) \in E_{\text{trace}}
$$

     - Any architectural element linked to a detached or floating system requirement that lacks upward traceability to $`T_1`$ shall be deterministically rejected at compile time with diagnostic error code `E0400` (`UngroundedRequirementTrace`).
  4. **Bipartite Surjectivity & Traceability Matrix Consistency**:
     - The compiler shall enforce bipartite surjectivity across the allocation-realization boundary:
       * Upward allocation completeness (REQ-0129): $`\forall r \in \mathcal{R}_{\text{system}}, \exists e \in \mathcal{E}_{\text{architecture}} : (r, e) \in E_{\text{trace}}`$ (total domain).
       * Downward realization completeness (REQ-0130): $`\forall e \in \mathcal{E}_{\text{architecture}}, \exists r \in \mathcal{R}_{\text{system}} : (r, e) \in E_{\text{trace}}`$ (total codomain).
     - This pair of invariants guarantees that no requirement remains unimplemented and no architectural element exists without formal requirement justification, eliminating gold-plating, unintended functionality, and untracked architectural scope.
     - The compiler shall generate the canonical Downward Realization Matrix $`\mathbf{M}_{\text{realize}} \in \{0, 1\}^{|\mathcal{E}_{\text{architecture}}| \times |\mathcal{R}_{\text{system}}|}`$, where row sums satisfy $`\sum_{j=1}^{|\mathcal{R}_{\text{system}}|} M_{\text{realize}, i, j} \ge 1`$ for all rows $`i`$.
  5. **Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every architectural element node, requirement node, traceability edge, and realization matrix record shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))`$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel downward realization completeness validation across independent compilation units, packages, or subsystem modules shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Element identifiers, requirement names, qualifier tokens, and fully qualified path segments shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The downward realization verifier shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When semantic traceability violations occur (`E0400`), diagnostics shall accumulate in the error sink buffer $`\mathcal{D}_{\text{sink}}`$, substitute typed error sentinels ($`\bot_{\text{elem}}`$, $`\bot_{\text{trace}}`$), and continue validating subsequent architectural element declarations. If accumulated diagnostics reach capacity $`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The downward realization completeness gate pipeline shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($`\lt 25\text{ ms}`$ for $`10^4`$ architectural elements and traceability edges) and peak RSS memory ($`\lt 100\text{ MB}`$) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Part_Alpha`, `Part_Beta`, `Part_Child_0`, `Part_Child_1`, `Component_0`, `Component_1`, `Req_Mission_0`, `Req_System_0`, `Req_System_1`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous bump arena storage. Let $`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.

  Let $`G_{\text{trace}} = (V_{\text{trace}}, E_{\text{trace}})`$ denote the 7-tier bipartite traceability directed acyclic graph:

$$
  V_{\text{trace}} = \bigcup_{k=1}^7 T_k = \mathcal{R}_{\text{mission}} \cup \mathcal{R}_{\text{system}} \cup \mathcal{E}_{\text{architecture}} \cup \mathcal{I}_{\text{interface}} \cup \mathcal{I}_{\text{safety}} \cup \mathcal{C}_{\text{realization}} \cup \mathcal{W}_{\text{verification}}
$$

  where tier vertex sets are mutually disjoint:

$$
  \forall j, k \in \{1, \dots, 7\}, \quad j \ne k \implies T_j \cap T_k = \emptyset
$$

  Traceability edges satisfy the inter-tier directed progression:

$$
  E_{\text{trace}} \subseteq \bigcup_{k=1}^6 (T_k \times T_{k+1})
$$

  Each architectural element $`e \in \mathcal{E}_{\text{architecture}}`$ ($`T_3`$) is formalized as a 6-tuple:

$$
  e = \langle \text{id}_e, \text{name}_e, \text{kind}_e, \text{scope}_e, \Delta_e, \text{span}_e \rangle
$$

  where:

$$
  \begin{aligned}
  \text{id}_e &\in \mathbb{N}_{32} \quad (\text{contiguous bump arena node handle}) \\
  \text{name}_e &\in \mathcal{S}_{\text{intern}} \quad (\text{interned identifier symbol}) \\
  \text{kind}_e &\in \{ \text{Classifier}, \text{Part}, \text{Item}, \text{Action}, \text{State}, \text{Connection}, \text{Interface}, \text{Port} \} \\
  \text{scope}_e &\in \mathcal{V}_{\text{AST}} \cup \{ \bot \} \quad (\text{enclosing parent classifier or container handle}) \\
  \Delta_e &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_e &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
  \end{aligned}
$$

  Each system requirement $`r \in \mathcal{R}_{\text{system}}`$ ($`T_2`$) is formalized as a 6-tuple:

$$
  r = \langle \text{id}_r, \text{name}_r, \text{text}_r, \text{crit}_r, \Delta_r, \text{span}_r \rangle
$$

  where:

$$
  \begin{aligned}
  \text{id}_r &\in \mathbb{N}_{32} \quad (\text{contiguous bump arena node handle}) \\
  \text{name}_r &\in \mathcal{S}_{\text{intern}} \quad (\text{interned requirement identifier}) \\
  \text{text}_r &\in \mathcal{S}_{\text{intern}} \quad (\text{interned normative prose payload}) \\
  \text{crit}_r &\in \{ \text{SafetyCritical}, \text{MissionCritical}, \text{Standard} \} \quad (\text{criticality tier}) \\
  \Delta_r &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_r &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
  \end{aligned}
$$

  Let $`\sqsubset \subset \mathcal{E}_{\text{architecture}} \times \mathcal{E}_{\text{architecture}}`$ denote the irreflexive, acyclic parent-child structural containment relation, with transitive closure $`\sqsubset^+`$. The ancestor set of an element $`e`$ is:

$$
  \text{anc}(e) = \{ p \in \mathcal{E}_{\text{architecture}} \mid e \sqsubset^+ p \}
$$

  Realization sets are defined as follows:

$$
  \begin{aligned}
  \text{Realizers}_{\text{direct}}(e) &= \{ r \in \mathcal{R}_{\text{system}} \mid (r, e) \in E_{\text{trace}} \} \\
  \text{Realizers}_{\text{inherited}}(e) &= \{ r \in \mathcal{R}_{\text{system}} \mid \exists p \in \text{anc}(e) : (r, p) \in E_{\text{trace}} \} \\
  \text{Realizers}(e) &= \text{Realizers}_{\text{direct}}(e) \cup \text{Realizers}_{\text{inherited}}(e)
  \end{aligned}
$$

  Downward Realization Completeness Invariants:

  1. Standard Compositional Downward Realization Invariant:

$$
  \forall e \in \mathcal{E}_{\text{architecture}}, \quad |\text{Realizers}(e)| \ge 1 \iff \text{Realizers}(e) \ne \emptyset
$$

  2. Strict Leaf Realization Invariant (safety certification profile $`\sigma_{\text{profile}} = \text{StrictLeaf}`$):

$$
  \forall e \in \mathcal{E}_{\text{architecture}}, \quad |\text{Realizers}_{\text{direct}}(e)| \ge 1
$$

  3. Transitive Root Mission Requirement Grounding Invariant:

$$
  \forall e \in \mathcal{E}_{\text{architecture}}, \quad \exists r \in \text{Realizers}(e), \exists m \in \mathcal{R}_{\text{mission}} : (m, r) \in E_{\text{trace}}
$$

  4. Downward Realization Matrix Row-Sum Invariant:
  Let $`N_{\text{elem}} = |\mathcal{E}_{\text{architecture}}|`$ and $`N_{\text{req}} = |\mathcal{R}_{\text{system}}|`$. The downward realization matrix $`\mathbf{M}_{\text{realize}} \in \{0, 1\}^{N_{\text{elem}} \times N_{\text{req}}}`$ is defined by:

$$
  M_{\text{realize}, i, j} = \begin{cases} 1, & \text{if } r_j \in \text{Realizers}(e_i) \\ 0, & \text{otherwise} \end{cases}
$$

  Row completeness requires every architectural element to possess at least one realizing requirement:

$$
  \forall i \in \{1, \dots, N_{\text{elem}}\}, \quad \sum_{j=1}^{N_{\text{req}}} M_{\text{realize}, i, j} \ge 1
$$

  5. Joint Bipartite Surjectivity System:
  Let $`\mathbf{M}_{\text{alloc}} \in \{0, 1\}^{N_{\text{req}} \times N_{\text{elem}}}`$ denote the upward allocation matrix defined in REQ-0129 where $`M_{\text{alloc}, j, i} = 1 \iff (r_j, e_i) \in E_{\text{trace}}`$. The coupled bipartite system satisfies simultaneous row completeness across both allocation and realization:

$$
  \begin{aligned}
  \forall j \in \{1, \dots, N_{\text{req}}\}, \quad &\sum_{i=1}^{N_{\text{elem}}} M_{\text{alloc}, j, i} \ge 1 \quad (\text{Upward Allocation Completeness, REQ-0129}) \\
  \forall i \in \{1, \dots, N_{\text{elem}}\}, \quad &\sum_{j=1}^{N_{\text{req}}} M_{\text{realize}, i, j} \ge 1 \quad (\text{Downward Realization Completeness, REQ-0130})
  \end{aligned}
$$

  6. Deterministic Diagnostic Trigger Rules (REQ-0191):

$$
  \begin{aligned}
  \exists e \in \mathcal{E}_{\text{architecture}} : |\text{Realizers}(e)| = 0 &\implies \text{Diagnostic}(e, \text{DiagnosticCode::E0400}, \text{UnallocatedArchitecturalElement}) \in \mathcal{D}_{\text{sink}} \\
  \sigma_{\text{profile}} = \text{StrictLeaf} \land \exists e \in \mathcal{E}_{\text{architecture}} : |\text{Realizers}_{\text{direct}}(e)| = 0 &\implies \text{Diagnostic}(e, \text{DiagnosticCode::E0400}, \text{MissingLeafRealizationTrace}) \in \mathcal{D}_{\text{sink}} \\
  \exists e \in \mathcal{E}_{\text{architecture}}, \forall r \in \text{Realizers}(e) : \text{InDegree}_{E_{\text{trace}}}(r) = 0 &\implies \text{Diagnostic}(e, \text{DiagnosticCode::E0400}, \text{UngroundedRequirementTrace}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
$$

  7. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

$$
  \begin{aligned}
  \forall e \in \mathcal{E}_{\text{architecture}}, &\quad \Delta_e = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(e)) \\
  \forall r \in \mathcal{R}_{\text{system}}, &\quad \Delta_r = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(r)) \\
  \forall (u, v) \in E_{\text{trace}}, &\quad \Delta_{(u, v)} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u) \mathbin{\Vert} \text{SYM}_{\text{EDGE}} \mathbin{\Vert} \text{FQN}(v))
  \end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Downward realization completeness verification, hierarchical trace inheritance analysis, and transitive mission requirement grounding reside in **Complexity Class P** (Deterministic Polynomial Time).

  **Mathematical Delineation from Algorithmic Bounds NP-4 and NP-8**:
  In formal safety analysis, computing minimal hazard cut-sets and unsafe control action combinations is NP-complete, as formalized under Algorithmic Bound NP-4 (REQ-0135) via Minimal Hitting Set reduction. Similarly, formal proof obligation discharge over general non-linear AST constraints is NP-complete or undecidable, governed by Algorithmic Bound NP-8 (REQ-0197) via DPLL(T) SMT solving.
  In contrast, REQ-0130 solves deterministic graph reachability and in-degree queries over a finite directed acyclic graph $`G_{\text{trace}} = (V_{\text{trace}}, E_{\text{trace}})`$ and structural containment tree $`(\mathcal{E}_{\text{architecture}}, \sqsubset)`$. The algorithm requires zero combinatorial search, zero SAT unrolling, and zero backtracking, guaranteeing deterministic polynomial-time execution.

  **Asymptotic Complexity Analysis**:
  Let $`V_{\text{trace}} = |V_{\text{trace}}|`$ denote the total number of nodes across all 7 tiers, $`E_{\text{trace}} = |E_{\text{trace}}|`$ denote the total number of directed traceability edges, $`N_{\text{elem}} = |\mathcal{E}_{\text{architecture}}|`$ denote the number of architectural elements, and $`N_{\text{req}} = |\mathcal{R}_{\text{system}}|`$ denote the number of system requirements. Let $`h`$ denote the maximum structural containment depth ($`h \le 32 \ll N_{\text{elem}}`$ in valid MBSE models).
  1. *Traceability Graph Ingestion & Adjacency Construction*:
     Parsing AST `satisfy requirement` statements and building the forward and inverted adjacency lists in contiguous arena memory requires inspecting each node and edge exactly once:

$$
     T_{\text{graph}}(V_{\text{trace}}, E_{\text{trace}}) \in O(V_{\text{trace}} + E_{\text{trace}})
$$

  2. *Structural Containment Hierarchy Traversal & Realization Inheritance*:
     Propagating realization links downward from parent containers to nested sub-parts along the containment tree $`(\mathcal{E}_{\text{architecture}}, \sqsubset)`$ via top-down breadth-first traversal visits each element once and climbs at most $`h`$ levels:

$$
     T_{\text{containment}}(N_{\text{elem}}, h) \in O(N_{\text{elem}} \cdot h) = O(N_{\text{elem}})
$$

  3. *Downward Realization Completeness Evaluation*:
     For each architectural element $`e_i`$, testing whether $`|\text{Realizers}(e_i)| \ge 1`$ requires inspecting the direct edge bitset or the inherited realization set, executing in $`O(1)`$ amortized time per element:

$$
     T_{\text{check}}(N_{\text{elem}}) \in O(N_{\text{elem}})
$$

  4. *Transitive Mission Requirement Grounding via Reverse Traversal*:
     Verifying that each system requirement $`r \in \mathcal{R}_{\text{system}}`$ traces upward to a root mission requirement $`m \in \mathcal{R}_{\text{mission}}`$ requires a forward reachability traversal from $`\mathcal{R}_{\text{mission}}`$ over $`T_1 \times T_2`$ edges. Visiting each requirement node and edge once requires:

$$
     T_{\text{grounding}}(V_{\text{trace}}, E_{\text{trace}}) \in O(V_{\text{trace}} + E_{\text{trace}})
$$

  5. *Downward Realization Matrix Generation*:
     Constructing the boolean sparse incidence matrix $`\mathbf{M}_{\text{realize}} \in \{0, 1\}^{N_{\text{elem}} \times N_{\text{req}}}`$ inspects each realized pair once, executing in $`O(N_{\text{elem}} + E_{\text{trace}})`$ time and $`O(N_{\text{elem}} + E_{\text{trace}})`$ space (or $`O(N_{\text{elem}} \cdot N_{\text{req}})`$ for dense representation).
  6. *Aggregate Worst-Case Time Complexity*:
     Combining all verification and matrix construction passes, the total execution time is strictly linear in the size of the traceability graph:

$$
     T_{\text{total}}(V_{\text{trace}}, E_{\text{trace}}) \in O(V_{\text{trace}} + E_{\text{trace}})
$$

  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     When verifying $`P`$ independent packages or decoupled subsystem models across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool:

$$
     T_{\text{parallel}}(V_{\text{trace}}, E_{\text{trace}}, N_{\text{max\_workers}}) \in O\left( \frac{V_{\text{trace}} + E_{\text{trace}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  8. *Space Complexity & Arena Memory Bounds*:
     Traceability vertices, edges, containment indices, and incidence matrices reside in contiguous bump arena storage, requiring $`O(V_{\text{trace}} + E_{\text{trace}})`$ bytes. Traversal bitsets and FIFO queues require $`O(V_{\text{trace}})`$ auxiliary memory. Deduplicated string interner storage is bounded by $`O(V_{\text{trace}})`$ symbol descriptors. The diagnostic sink buffer is strictly bounded by $`O(C_{\text{max\_errors}}) = O(1)`$ capacity.
