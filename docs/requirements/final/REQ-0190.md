### REQ-0190: Rich Source-Mapped Diagnostic Reporting with Byte Spans, Synchronization Tokens & Error Accumulation

- **Normative Statement**: The compiler diagnostic engine, source-mapping framework, synchronization recovery coordinator, and diagnostic emission backend of Subsystem 11 shall capture, source-map, structure, format, and emit rich compiler diagnostic records for all compilation stages--including lexical scanning, grammar parsing, schema ingestion, metamodel lowering, type-checking, metrological validation, discrete dynamic verification, safety constraint evaluation, and multi-target code generation. The diagnostic engine shall construct structured diagnostic records containing exact half-open source byte spans $`[b_{\text{start}}, b_{\text{end}})`$, resolved 1-indexed line and column coordinates $`\langle \ell_{\text{start}}, c_{\text{start}}, \ell_{\text{end}}, c_{\text{end}} \rangle`$, standardized architectural error codes $`c \in [100, 599]`$ strictly partitioned per REQ-0191, severity tiers $`s \in \{\text{Fatal}, \text{Error}, \text{Warning}, \text{Info}\}`$, structured remediation guidance $`\mu`$, synchronization recovery tokens $`\sigma \in \Sigma_{\text{sync}}`$, and contextual ASCII code snippets rendering source lines, line margin numbers, underline carets (`^`), and span squiggles (`~~~`). The compiler shall accumulate diagnostic records across all compilation phases into a bounded diagnostic sink rather than aborting execution on first fault, supporting accumulation up to a configurable saturation threshold $`K_{\text{max\_errors}} \ge 100`$ (defaulting to $`C_{\text{max\_errors}} = 100`$). When the diagnostic sink accumulates $`K_{\text{max\_errors}}`$ records, the diagnostic engine shall record terminal diagnostic `E0199` and gracefully halt compilation without panic.

  Specifically, the diagnostic engine and reporting framework shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Source-Mapped Byte Span & Coordinate Resolution Architecture**:
     - Every emitted diagnostic record $`D`$ shall capture an exact half-open byte interval $`[b_{\text{start}}, b_{\text{end}}) \subset \mathbb{N}`$ within the source file buffer $`B`$, where $`0 \le b_{\text{start}} \le b_{\text{end}} \le |B|`$.
     - For point diagnostics where a fault occurs at a single character or token boundary, $`b_{\text{end}} = b_{\text{start}} + 1`$ or $`b_{\text{end}} = b_{\text{start}}`$.
     - The diagnostic engine shall maintain a monotonic line-start index table $`L_{\text{starts}} = \langle l_1 = 0, l_2, \dots, l_M \rangle`$ for each ingested source buffer $`B`$, recording the 0-indexed byte offset of each newline delimiter ($`\text{SYM}_{\text{LF}}`$).
     - Source line numbers $`\ell(b) \in \{1, \dots, M\}`$ and 1-indexed column numbers $`c(b) \in \mathbb{N}_{>0}`$ shall be resolved deterministically via binary search over $`L_{\text{starts}}`$ in $`O(\log M)`$ time, guaranteeing bijective correspondence between byte offsets and human-readable text locations.
  2. **Multi-Tier Severity Classification & Compilation Status Contract**:
     - The diagnostic engine shall classify every diagnostic record into one of four mutually exclusive severity tiers: $`\text{Fatal}`$, $`\text{Error}`$, $`\text{Warning}`$, or $`\text{Info}`$.
     - Occurrence of at least one diagnostic of severity $`\text{Fatal}`$ or $`\text{Error}`$ shall mark the compilation pass as failed ($`\text{CompilationFailure}`$), prohibiting downstream code emission and artifact synchronization.
     - A compilation run producing exclusively $`\text{Warning}`$ diagnostics shall yield $`\text{CompilationWarning}`$, permitting artifact generation while reporting warnings to stderr.
     - A compilation run producing only $`\text{Info}`$ diagnostics or zero diagnostics shall yield $`\text{CompilationSuccess}`$.
  3. **Rich Contextual ASCII Code Snippet Formatting**:
     - For each diagnostic record associated with a valid source file byte span, the diagnostic engine shall format a contextual ASCII snippet displaying the originating source text.
     - The formatted snippet shall include:
       - File path and resolved coordinate header: `--> <source_path>:<line_start>:<col_start>`.
       - Right-aligned margin line numbers separated by a vertical bar (`|`).
       - Source text lines containing the byte span $`[b_{\text{start}}, b_{\text{end}})`$.
       - A dedicated annotation line placed beneath each affected source line, utilizing underline carets (`^`) to identify the primary fault location and span squiggles (`~~~`) to denote the extent of the span.
       - Inline error code and severity labels prefixed to the diagnostic description (e.g., `error[E0102]: invalid table row delimiter`).
       - A footer section presenting structured remediation guidance $`\mu`$, including optional machine-readable diff replacements $`\langle [b_{\text{start}}, b_{\text{end}}), \text{replacement\_str} \rangle`$.
  4. **Monotonic Bounded Error Accumulation & Saturation Gate**:
     - The diagnostic engine shall maintain a preallocated diagnostic sink buffer $`\mathcal{D}`$ that accumulates diagnostics monotonically across lexing, parsing, lowering, type checking, metrology verification, and code generation phases.
     - The sink shall enforce a strictly bounded capacity limit $`K_{\text{max\_errors}} \ge 100`$ (configurable via CLI flag `--max-errors`, defaulting to $`C_{\text{max\_errors}} = 100`$).
     - If the number of accumulated diagnostics reaches $`K_{\text{max\_errors}}`$, the compiler shall synthesize a terminal diagnostic record $`D_{\text{term}}`$ with error code `E0199` (`DiagnosticSinkCapacityExceeded`) and severity $`\text{Fatal}`$, append $`D_{\text{term}}`$ as the final element of $`\mathcal{D}`$, and terminate compilation gracefully.
     - Bounded accumulation prevents memory exhaustion and denial-of-service from degenerate or maliciously constructed source inputs.
  5. **Cascading Error Suppression Window**:
     - Following a synchronization recovery event at token stream index $`\tau_{\text{last}}`$, front-end parsers and semantic checkers shall activate a cascading error suppression window of proximity length $`\delta \le 3`$ tokens.
     - Syntax and grammar faults detected within $`\delta`$ tokens of $`\tau_{\text{last}}`$ that are attributable to recovery realignment ambiguity shall be suppressed from insertion into $`\mathcal{D}`$, preventing diagnostic flooding.
     - Faults detected at distance $`j - \tau_{\text{last}} \gt \delta`$ shall be recorded normally, updating $`\tau_{\text{last}} \leftarrow j`$.
  6. **Deterministic Diagnostic Output Sorting Invariant**:
     - Prior to serialization or terminal emission, all accumulated diagnostic records in $`\mathcal{D}`$ shall be sorted according to a total, deterministic ordering relation $`\prec_{\text{diag}}`$.
     - Sorting shall order diagnostics primary by interned source artifact path ($`p_i \prec_{\text{lex}} p_j`$), secondary by start byte offset ($`b_{\text{start}, i} \lt b_{\text{start}, j}`$), tertiary by end byte offset ($`b_{\text{end}, i} \lt b_{\text{end}, j}`$), quaternary by severity rank ($`\text{Fatal} \gt \text{Error} \gt \text{Warning} \gt \text{Info}`$), and quinary by numeric error code ($`c_i \lt c_j`$).
     - Deterministic sorting guarantees 0-byte diff churn across consecutive compiler runs on identical source inputs.
  7. **Bijective Source Provenance & RFC 4122 UUIDv5 Anchors (Directive 1)**:
     - Every diagnostic record $`D`$ shall bind a deterministic RFC 4122 UUIDv5 identifier $`\Delta_{\text{diag}}`$ computed via SHA-1 hashing over the DEAP namespace OID and the concatenation of source path, error code, and byte span:

$$
\Delta_{\text{diag}} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, p \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{str}(c) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{str}(b_{\text{start}}) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{str}(b_{\text{end}}))
$$

     - Time-based UUIDs (such as UUIDv1 or UUIDv7) are strictly prohibited, ensuring reproducible diagnostic digests across all execution environments.
  8. **Bounded Work-Stealing Parallelism & Thread Isolation (Directive 2)**:
     - Parallel compilation passes executing across independent modules, packages, and translation units on a bounded work-stealing thread pool with worker thread bound $`N_{\text{max\_workers}}`$ (per REQ-0012) shall maintain thread-local diagnostic accumulators $`\mathcal{D}^{(w)}`$.
     - Upon completion of parallel tasks, thread-local diagnostic buffers shall be merged into the centralized diagnostic sink $`\mathcal{D}`$ via a deterministic reduction operator that applies total ordering $`\prec_{\text{diag}}`$.
     - Unbounded manual thread spawning is strictly banned; all parallel diagnostic collection shall adhere to $`N_{\text{max\_workers}}`$.
  9. **String Interner Memory Allocation Exception (Directive 3)**:
     - Source file paths $`p`$, diagnostic error messages, remediation guidance strings, and identifier tokens shall be interned into the deduplicated global symbol interner pool during diagnostic generation in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - Emitted diagnostic records shall reference interned strings via compact 32-bit symbol handles ($`\text{SymbolId}`$), preserving a bounded memory footprint.
  10. **Synchronization Token Error Recovery Architecture (Directive 4)**:
      - Front-end parsers and schema ingestion passes shall implement synchronization token error recovery on statement terminators (`;`), block delimiters (`}`, `]`, `)`), line breaks ($`\text{SYM}_{\text{LF}}`$), and tabular row boundaries (`|`) in accordance with REQ-0013 and REQ-0016.
      - When an error occurs, the parser shall record the diagnostic into $`\mathcal{D}`$, discard tokens until the nearest designated synchronization token $`\sigma \in \Sigma_{\text{sync}}`$, advance the stream pointer, and resume parsing to collect subsequent diagnostics.
  11. **Total Non-Panicking Execution Contract & Benchmarking Isolation (Directive 5)**:
      - The diagnostic engine shall enforce a total-function, deterministic, non-panicking execution contract across all inputs, including empty buffers, malformed UTF-8 byte sequences, out-of-bounds byte spans, and degenerate syntax trees. Zero unhandled exceptions or panic halts are permitted.
      - Diagnostic formatting latency (< 25 ms for 100 accumulated diagnostics over $`10^4`$ source lines) and peak RSS memory (< 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from standard CI logic tests in accordance with REQ-0011 and REQ-0196.
  12. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic formatting tests, error catalog descriptions, illustrative examples, and verification models shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Flow_A`, `param_x : Real`, `State_0`, `SourceFile_0`, `Diagnostic_0`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{B}`$ denote the universe of immutable source file buffers stored in the compilation environment, where buffer $`B \in \mathcal{B}`$ is a sequence of bytes $`B = \langle u_0, u_1, \dots, u_{N-1} \rangle`$ of length $`N = |B|`$.

  Let $`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.
  A diagnostic record $`D`$ is formalized as an 8-tuple:

$$
  D = \langle c, s, p, [b_{\text{start}}, b_{\text{end}}), \lambda, \mu, \sigma, \Delta_{\text{diag}} \rangle
$$

  where:

$$
  \begin{aligned}
  c &\in \{100, \dots, 599\} \quad (\text{standardized diagnostic error code}) \\
  s &\in \{ \text{Fatal}, \text{Error}, \text{Warning}, \text{Info} \} \quad (\text{diagnostic severity tier}) \\
  p &\in \mathcal{S}_{\text{intern}} \quad (\text{interned source artifact path}) \\
  [b_{\text{start}}, b_{\text{end}}) &\subset \mathbb{N} \quad (\text{half-open byte interval in source buffer } B, \; 0 \le b_{\text{start}} \le b_{\text{end}} \le |B|) \\
  \lambda &= \langle \ell_{\text{start}}, c_{\text{start}}, \ell_{\text{end}}, c_{\text{end}} \rangle \in \mathbb{N}_{>0}^4 \quad (\text{1-indexed line and column coordinates}) \\
  \mu &\in \mathcal{T}_{\text{remediation}} \quad (\text{structured remediation guidance and diff hint}) \\
  \sigma &\in \Sigma_{\text{sync}} \cup \{ \varepsilon \} \quad (\text{synchronization recovery token, or } \varepsilon \text{ if none}) \\
  \Delta_{\text{diag}} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor})
  \end{aligned}
$$

  1. Line-Start Index Table & Coordinate Resolution Invariant:
  For each source buffer $`B`$, let $`L_{\text{starts}} = \langle l_1, l_2, \dots, l_M \rangle`$ denote the ordered sequence of newline delimiter offsets, where $`l_1 = 0`$ and:

$$
  \forall i \in \{2, \dots, M\}, \quad l_i \in \{ j + 1 \mid 0 \le j \lt |B| \;\wedge\; u_j = \text{SYM}_{\text{LF}} \}
$$

  The line coordinate function $`\ell : \{0, \dots, |B|\} \to \{1, \dots, M\}`$ and column coordinate function $`c : \{0, \dots, |B|\} \to \mathbb{N}_{>0}`$ evaluate deterministically:

$$
  \begin{aligned}
  \ell(b) &= \max \{ i \in \{1, \dots, M\} \mid l_i \le b \} \\
  c(b) &= (b - l_{\ell(b)}) + 1
  \end{aligned}
$$

  The coordinate quad $`\lambda`$ satisfies:

$$
  \lambda = \text{SpanToLoc}([b_{\text{start}}, b_{\text{end}})) = \langle \ell(b_{\text{start}}), c(b_{\text{start}}), \ell(b_{\text{end}}), c(b_{\text{end}}) \rangle
$$

  2. Monotonic Error Accumulation & Saturation Invariant:
  Let $`\mathcal{D}_k`$ denote the sequence of accumulated diagnostic records at step $`k \in \mathbb{N}`$. The accumulation state evolves according to:

$$
  \mathcal{D}_{k+1} = \begin{cases}
  \mathcal{D}_k \cup \{ D_{k+1} \}, & \text{if } |\mathcal{D}_k| \lt K_{\text{max\_errors}} \\
  \mathcal{D}_k, & \text{if } |\mathcal{D}_k| \ge K_{\text{max\_errors}}
  \end{cases}
$$

  guaranteeing strictly bounded capacity:

$$
  \forall k \in \mathbb{N}, \quad |\mathcal{D}_k| \le K_{\text{max\_errors}}
$$

  When $`|\mathcal{D}_k| = K_{\text{max\_errors}}`$, the compiler triggers terminal saturation:

$$
  |\mathcal{D}_k| = K_{\text{max\_errors}} \implies \exists D_{\text{term}} \in \mathcal{D}_k : \left( c(D_{\text{term}}) = 199 \;\wedge\; s(D_{\text{term}}) = \text{Fatal} \right)
$$

  3. Cascading Error Suppression Invariant:
  Let $`\tau_{\text{last}} \in \mathbb{N}`$ denote the token stream position of the most recent synchronization event. For any subsequent syntax error detected at token index $`j \gt \tau_{\text{last}}`$:

$$
  \text{EmitDecision}(j, \tau_{\text{last}}) = \begin{cases}
  \text{Suppress}, & \text{if } j - \tau_{\text{last}} \le \delta \\
  \text{Record}, & \text{if } j - \tau_{\text{last}} \gt \delta
  \end{cases}
$$

  where suppression proximity threshold satisfies $`\delta \le 3`$.

  4. Total Deterministic Diagnostic Ordering Relation $`\prec_{\text{diag}}`$:
  For any two diagnostic records $`D_i, D_j \in \mathcal{D}`$:

$$
  D_i \prec_{\text{diag}} D_j \iff \begin{cases}
  p_i \prec_{\text{lex}} p_j \\
  \text{or } (p_i = p_j \;\wedge\; b_{\text{start}, i} \lt b_{\text{start}, j}) \\
  \text{or } (p_i = p_j \;\wedge\; b_{\text{start}, i} = b_{\text{start}, j} \;\wedge\; b_{\text{end}, i} \lt b_{\text{end}, j}) \\
  \text{or } (p_i = p_j \;\wedge\; [b_{\text{start}}, b_{\text{end}})_i = [b_{\text{start}}, b_{\text{end}})_j \;\wedge\; \text{rank}(s_i) \gt \text{rank}(s_j)) \\
  \text{or } (p_i = p_j \;\wedge\; [b_{\text{start}}, b_{\text{end}})_i = [b_{\text{start}}, b_{\text{end}})_j \;\wedge\; s_i = s_j \;\wedge\; c_i \lt c_j)
  \end{cases}
$$

  where severity ranking is defined as:

$$
  \text{rank}(\text{Fatal}) = 4 \gt \text{rank}(\text{Error}) = 3 \gt \text{rank}(\text{Warning}) = 2 \gt \text{rank}(\text{Info}) = 1
$$

  5. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

$$
  \Delta_{\text{diag}} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, p \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{str}(c) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{str}(b_{\text{start}}) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{str}(b_{\text{end}}))
$$

  6. Thread-Safe Parallel Reduction Invariant (Directive 2):
  Let $`\mathcal{D}^{(w)}`$ denote the local diagnostic buffer of worker thread $`w \in \{1, \dots, N_{\text{max\_workers}}\}`$. The merged global diagnostic sink satisfies:

$$
  \mathcal{D} = \text{Sort}_{\prec_{\text{diag}}}\left( \bigcup_{w=1}^{N_{\text{max\_workers}}} \mathcal{D}^{(w)} \right)
$$

  7. Standardized Diagnostic Taxonomy Partitioning (REQ-0191):

$$
  \forall D \in \mathcal{D}, \quad c(D) \in \mathcal{E}_{\text{catalog}} = \mathcal{E}_{\text{ingest}} \cup \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{metrology}} \cup \mathcal{E}_{\text{dynamics}} \cup \mathcal{E}_{\text{backend}}
$$

  where the taxonomic sub-ranges are mutually disjoint:

$$
  \begin{aligned}
  \mathcal{E}_{\text{ingest}} &= \{ c \in \mathbb{N} \mid 100 \le c \le 199 \} \\
  \mathcal{E}_{\text{type}} &= \{ c \in \mathbb{N} \mid 200 \le c \le 299 \} \\
  \mathcal{E}_{\text{metrology}} &= \{ c \in \mathbb{N} \mid 300 \le c \le 399 \} \\
  \mathcal{E}_{\text{dynamics}} &= \{ c \in \mathbb{N} \mid 400 \le c \le 499 \} \\
  \mathcal{E}_{\text{backend}} &= \{ c \in \mathbb{N} \mid 500 \le c \le 599 \}
  \end{aligned}
$$

  and satisfy pairwise disjointness:

$$
  \forall j, k \in \{ \text{ingest}, \text{type}, \text{metrology}, \text{dynamics}, \text{backend} \}, \quad j \ne k \implies \mathcal{E}_j \cap \mathcal{E}_k = \emptyset
$$

- **Computational Complexity & Algorithmic Bounds**: Rich Source-Mapped Diagnostic Reporting with Byte Spans, Synchronization Tokens & Error Accumulation resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in strictly deterministic linear time $`O(N_{\text{bytes}} + K_{\text{max\_errors}} \log K_{\text{max\_errors}})`$ and linear auxiliary space $`O(M + K_{\text{max\_errors}})`$ over the source byte count $`N_{\text{bytes}}`$, source line count $`M`$, and diagnostic sink saturation limit $`K_{\text{max\_errors}}`$.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 resolves qualitative temporal interval consistency over occurrence lifecycles using Allen's 13 interval relations via ORD-Horn SMT difference logic in $`O(N^3)`$ polynomial time. In contrast, REQ-0190 performs 1-dimensional byte-span calculations over concrete scalar offsets $`[b_{\text{start}}, b_{\text{end}})`$ via direct integer comparison in $`O(1)`$ time, requiring zero constraint propagation or interval network solving.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses strongly NP-hard vector bin packing for structural allocation and interconnect channel multiplexing. In contrast, REQ-0190 stores diagnostic records in a contiguous, preallocated linear vector of bounded capacity $`K_{\text{max\_errors}}`$ in $`O(1)`$ amortized time per insertion without multi-dimensional knapsack constraints.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 formalizes subtyping lattice redefinition and multiple inheritance linearization via C3 linearization in $`O(V + E)`$ time. In contrast, REQ-0190 maps diagnostic codes to flat numeric taxonomy intervals ($`[100, 599]`$) via constant-time range checks in $`O(1)`$ time without poset traversal or semilattice operations.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0190 accumulates and suppresses independent diagnostic records using a scalar proximity window ($`\delta \le 3`$) in $`O(1)`$ time without combinatorial hitting set minimization.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking). In contrast, REQ-0190 formats and reports state-reachability errors as static diagnostic records in $`O(1)`$ time without exploring state-space product graphs or reachability transitions.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks using linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0190 formats conservation violation diagnostics directly from verified AST error records in $`O(1)`$ time without continuous matrix pivoting.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 formalizes global register allocation (Chaitin Graph $`K`$-Coloring, NP-complete) and basic block scheduling in LUMI IR. In contrast, REQ-0190 serializes diagnostic text and ASCII snippets into contiguous memory buffers in linear time $`O(W \cdot \Delta \ell)`$ without interference graph construction or register coloring.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves satisfiability of first-order invariant contracts via DPLL(T) SMT solvers. In contrast, REQ-0190 receives already-computed invariant violation witnesses and emits structured diagnostic messages without invoking theorem provers or SAT decision procedures.

  **Asymptotic Complexity Analysis**:
  Let $`N_{\text{bytes}} = |B|`$ denote the source file byte count, $`M`$ denote the number of source lines, $`K = |\mathcal{D}| \le K_{\text{max\_errors}}`$ denote the number of accumulated diagnostics, and $`W_{\text{max\_line}}`$ denote the maximum source line length in bytes ($`W_{\text{max\_line}} \le 4{,}096`$).
  1. *Line-Start Table Indexing Phase*:
     - Scanning source buffer $`B`$ to identify newline characters and populate array $`L_{\text{starts}}`$ executes in a single linear pass:

$$
T_{\text{index}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{index}}(M) \in O(M)
$$

  2. *Coordinate Resolution Phase ($`\text{SpanToLoc}`$)*:
     - For each diagnostic record, resolving byte span $`[b_{\text{start}}, b_{\text{end}})`$ to line and column coordinates via binary search over $`L_{\text{starts}}`$ executes in:

$$
T_{\text{loc}}(M) \in O(\log M), \quad S_{\text{loc}} \in O(1)
$$

     - Resolving coordinates for all $`K`$ diagnostics requires $`O(K \log M)`$ aggregate time.
  3. *Diagnostic Insertion & Cascading Suppression Phase*:
     - Checking the cascading suppression window ($`j - \tau_{\text{last}} \le \delta`$) executes in $`O(1)`$ scalar subtraction.
     - Appending an unsuppressed diagnostic record to preallocated sink $`\mathcal{D}`$ executes in $`O(1)`$ amortized time.
     - Total time across all error detections is bounded by $`O(K)`$.
  4. *Deterministic Diagnostic Sorting Phase*:
     - Sorting $`K`$ accumulated diagnostic records using comparison operator $`\prec_{\text{diag}}`$ executes in:

$$
T_{\text{sort}}(K) \in O(K \log K), \quad S_{\text{sort}}(K) \in O(K)
$$

     - Because $`K \le K_{\text{max\_errors}}`$, sort time is bounded by constant $`O(K_{\text{max\_errors}} \log K_{\text{max\_errors}})`$.
  5. *Contextual ASCII Snippet Formatting Phase*:
     - Rendering line margin numbers, extracting source line text, and generating underline carets (`^`) and wavy spans (`~~~`) executes in time proportional to line length:

$$
T_{\text{format}} \in O(K \cdot (\ell_{\text{end}} - \ell_{\text{start}} + 1) \cdot W_{\text{max\_line}})
$$

     - For localized errors spanning bounded lines ($`\ell_{\text{end}} - \ell_{\text{start}} \le 5`$), formatting executes in $`O(K \cdot W_{\text{max\_line}})`$ time.
  6. *Aggregate Diagnostic Engine Bounds*:
     - Summing across all phases, total execution time satisfies:

$$
T_{\text{total}} \in O(N_{\text{bytes}} + K_{\text{max\_errors}} \log M + K_{\text{max\_errors}} \log K_{\text{max\_errors}} + K_{\text{max\_errors}} \cdot W_{\text{max\_line}})
$$

     - Total auxiliary memory overhead is strictly bounded by:

$$
S_{\text{total}} \in O(M + K_{\text{max\_errors}})
$$

       which remains strictly under 100 MB RSS for files containing up to $`10^6`$ lines and $`10^4`$ diagnostic entries.
  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning independent source files across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool scales indexing and local diagnostic capture as:

$$
T_{\text{parallel}} \in O\left( \frac{N_{\text{bytes}}}{N_{\text{max\_workers}}} + K_{\text{max\_errors}} \log K_{\text{max\_errors}} \right)
$$
