### REQ-0009: Zero-Copy Bump Arena Memory Management

- **Normative Statement**: The compiler front-end, lexical analyzer, parser, and core abstract syntax tree (AST) engine shall utilize zero-copy memory management via contiguous bump allocation arenas for all parsed AST nodes, token streams, syntax trees, and intermediate representation graphs. Lexical tokens and string identifiers representing slices of source text shall directly borrow contiguous byte slice references from read-only memory-mapped source file buffers without intermediate heap string allocations or dynamic buffer cloning. Bump arenas must allocate AST nodes sequentially along contiguous memory segments, advancing a monotonic bump pointer with strict data alignment boundaries (64-bit alignment). Arena lifecycle management must reset or deallocate entire arena chunks in a single bulk operation upon completion of compilation units or compilation phases, eliminating individual node deallocation overhead, per-node allocator metadata headers, and memory fragmentation. Memory allocation during the lexical and parsing passes shall strictly enforce zero individual heap allocations for AST nodes and token strings. The copying of string bytes from the source buffer into the deduplicated global symbol interner pool for scalar symbol identifier tokens during the initial lexical pass shall constitute the sole permitted exception to the zero-copy invariant, as specified in REQ-0036. If an arena segment exhausts its pre-allocated capacity, the arena manager shall allocate a new contiguous memory chunk without moving, reallocating, or invalidating previously allocated node memory references.

- **Formal Invariant**: Let $\mathcal{B}_{\text{file}} \in \{0, 1\}^L$ represent a contiguous read-only memory-mapped byte buffer of length $L = |\mathcal{B}_{\text{file}}|$. An AST token slice $T$ is defined as a borrowed contiguous byte slice reference over offset $s$ and length $l$:

$$
T = \text{Slice}(\mathcal{B}_{\text{file}}, s, l) = \mathcal{B}_{\text{file}}[s \dots s+l-1], \quad \text{where } 0 \le s \le s+l \le L
$$

Let $\mathcal{A}_{\text{arena}}$ represent a contiguous arena segment of capacity $C \in \mathbb{N}$ starting at base address $\text{Base}(\mathcal{A}_{\text{arena}})$. Let $\text{ArenaOffset}_k$ denote the monotonic bump pointer offset within $\mathcal{A}_{\text{arena}}$ after allocating $k$ nodes. The allocation of node $\text{Node}_k$ with byte size $\text{sizeof}(\text{Node}_k)$ and alignment constraint $\text{Alignment} \in \{2^p \mid p \in \mathbb{N}\}$ satisfies monotonic pointer progression:

$$
\text{ArenaOffset}_{k+1} = \text{Align}(\text{ArenaOffset}_k + \text{sizeof}(\text{Node}_k), \text{Alignment})
$$

where the alignment function is defined as:

$$
\text{Align}(x, a) = \left\lceil \frac{x}{a} \right\rceil \cdot a, \quad a \in \{2^p \mid p \in \mathbb{N}\}
$$

The arena state adheres to the Monotonic Progression Invariant across all allocation steps:

$$
\forall k \ge 0, \quad 0 \le \text{ArenaOffset}_k \le \text{ArenaOffset}_{k+1} \le C
$$

Let $r_k$ denote the memory reference to $\text{Node}_k$ allocated at virtual address $\text{Addr}(r_k) = \text{Base}(\mathcal{A}_{\text{arena}}) + \text{ArenaOffset}_k$. The arena allocator guarantees reference stability throughout the arena lifetime $\tau_{\text{arena}}$:

$$
\forall t_1, t_2 \in \tau_{\text{arena}}, \quad \text{Addr}(r_k, t_1) = \text{Addr}(r_k, t_2)
$$

Let $\text{HeapAllocs}(\text{Pass})$ represent the count of dynamic individual heap allocations performed for AST nodes and token strings during the primary parsing pass $\text{ParsePass}(\mathcal{B}_{\text{file}})$. The system satisfies the Zero Heap Allocation Invariant:

$$
\text{HeapAllocs}(\text{ParsePass}(\mathcal{B}_{\text{file}})) = 0
$$

Bulk arena deallocation upon compilation unit completion executes as a total reset of the bump pointer:

$$
\text{Reset}(\mathcal{A}_{\text{arena}}) \implies \text{ArenaOffset}_{\text{reset}} = 0
$$

- **Computational Complexity & Algorithmic Bounds**: Arena memory operations execute within Complexity Class $\mathbf{P}$. Individual node allocation executes in strict $O(1)$ worst-case constant time, requiring only an integer addition, alignment arithmetic, and pointer comparison against capacity $C$. Token byte slice extraction executes in $O(1)$ constant time with zero string cloning. Bulk arena chunk deallocation and memory reset execute in $O(1)$ constant time, independent of the total number of allocated AST nodes $N = |\text{Nodes}(\mathcal{A})|$. Total front-end memory consumption is strictly bounded by $O(N)$ linear space proportional to AST node count and alignment padding, eliminating per-object dynamic heap header overhead.

- **Verification & Conformance Criteria**: Deterministic conformance shall be verified via automated memory profiling test harnesses instrumenting front-end compilation passes. The verification harness shall intercept heap allocation calls during $\text{ParsePass}(\mathcal{B}_{\text{file}})$ and assert that individual heap allocation count is strictly zero: $\text{HeapAllocs}(\text{ParsePass}(\mathcal{B}_{\text{file}})) = 0$ (with the sole exception of the global symbol interner pool defined in REQ-0036). The harness shall assert that every token byte slice address interval $[\text{ptr}, \text{ptr} + l)$ falls strictly within the memory-mapped buffer interval $[\text{Base}(\mathcal{B}_{\text{file}}), \text{Base}(\mathcal{B}_{\text{file}}) + L)$ and that all allocated node pointers satisfy 64-bit alignment ($\text{ptr} \equiv 0 \pmod 8$). If an arena allocation exceeds segment capacity without memory availability, or if an out-of-bounds slice reference or unauthorized heap allocation is detected, the compiler shall halt execution and emit diagnostic error code `E0100` detailing the offending byte offset, buffer length, alignment violation, and arena allocation failure context.
