### REQ-0047: Graph-Theoretic AST Representation & Directed Multigraph Metamodel

- **Normative Statement**: The compiler core shall construct, maintain, traverse, and query an in-memory bidirectional directed property multigraph $`G = (V, E)`$ representing all structural containment, feature typings, port connections, flow paths, generalizations, allocations, operational constraints, and module dependencies across the abstract syntax tree (AST) nodes stored in the contiguous node arena. The multigraph implementation must remain strictly technology-neutral, clean-room engineered, and decoupled from external graph libraries, operating directly on arena-backed index slabs, scalar node handles (`NodeHandle<T>`), and deterministic adjacency lists.

  The graph-theoretic AST architecture shall enforce the following normative guarantees:
  1. Vertex Identification & Handle Addressing: Every vertex $`v \in V`$ shall correspond to a typed node handle referencing an allocated arena slot in accordance with REQ-0034 and REQ-0035. Direct virtual memory pointers, raw references, and unaligned offsets are strictly prohibited across all graph vertices and edges.
  2. Property Multigraph Semantics & Parallel Edges: The graph model shall support multiple directed edges between the same ordered pair of vertices $`(u, v)`$`, permitting parallel relationships representing distinct semantic facets (such as concurrent containment and typing links, parallel port interconnections, or independent flow channels). Every edge `$`e \in E`$ shall possess a unique 32-bit unsigned edge handle (`EdgeId`), a source node handle $`u = \text{src}(e)`$`, a target node handle `$`v = \text{dst}(e)`$`, an edge category discriminant tag `$`k \in \mathcal{K}_{\text{edge}}`$`, and an extensible property payload `$`\mathbf{p} \in \mathcal{P}`$.
  3. Canonical Edge Categorization: Multigraph edges shall belong to an explicit closed set of edge kinds $`\mathcal{K}_{\text{edge}}`$, comprising:
     - `Contains`: Hierarchical structural containment forming an acyclic spanning forest over model elements.
     - `Specializes`: Generalization, inheritance, and subtyping relationships in the classifier lattice.
     - `Types`: Feature typing bindings from contextual feature usages to authoritative classifier definitions.
     - `ConnectsTo`: Topological port-to-port and interface interconnect contracts.
     - `FlowsTo`: Directed item, energy, or signal flow paths between communicating endpoints.
     - `AllocatesTo`: Cross-domain structural allocations (such as logical functions allocated to physical components).
     - `Constrains`: Asserted invariants, preconditions, postconditions, and parametric operational envelopes.
     - `DependsOn`: Lexical imports and compilation unit module dependencies.
  4. Bidirectional Adjacency & Symmetric Navigability: For every edge $`e = (u, v, k, \mathbf{p}) \in E`$`, the graph engine shall register `$`e`$` simultaneously within the forward outgoing adjacency list of source vertex `$`u`$` (`$`\text{OutEdges}(u)`$`) and the backward incoming adjacency list of target vertex `$`v`$` (`$`\text{InEdges}(v)`$`). Traversing from target `$`v`$` backward to source `$`u`$` shall execute with identical algorithmic complexity as traversing forward from source `$`u`$` to target `$`v`$.
  5. Deterministic Adjacency Ordering & Diff Parity: Incident edges within forward and backward adjacency lists shall maintain a strict deterministic canonical order keyed by: (1) edge kind discriminant tag, (2) target or source node index, and (3) edge declaration sequence. Adjacency iteration order shall remain invariant under compilation order variations, runtime memory layout, and platform architecture, ensuring bitwise reproducible compilation artifacts (REQ-0003) and deterministic cryptographic Merkle tree hashing (REQ-0010, REQ-0133).
  6. Constant-Degree Neighbor Query Bounds: Querying the incident outgoing edges $`\text{OutEdges}(v)`$`, incoming edges `$`\text{InEdges}(v)`$`, adjacent successors, or predecessors of any vertex `$`v \in V`$` shall execute via direct contiguous index lookups in time proportional strictly to the local vertex degree `$`O(\text{deg}(v))`$`, strictly prohibiting linear scans over the global vertex set `$`V`$` or edge set `$`E`$`. Filtered neighbor queries by edge kind shall evaluate within bounded `$`O(\text{deg}(v))`$ time.
  7. Total-Function Execution & Panic-Free Error Recovery: In accordance with Architectural Directive 5 and REQ-0011, multigraph operations shall strictly enforce a deterministic, non-panicking execution contract. Attempting to insert an edge referencing an invalid, out-of-bounds, or stale node handle, or attempting to introduce a cyclic dependency in an acyclic subgraph (such as `Contains`), shall return a structured error result, emit diagnostic error code `E0200` (or `E0203` for cyclic dependency violations) per REQ-0191, and prevent system panic.
  8. Thread Isolation & Bounded Work-Stealing Traversal: In accordance with Architectural Directive 2 and REQ-0012, immutable multigraph snapshots shall be safely accessible concurrently across the bounded work-stealing thread pool without locks, mutexes, or atomic reference counting, enabling parallel AST queries, slicing (REQ-0049), and verification without data races.
  9. Abstract Placeholder Purity: All test cases, diagnostic reports, and operational schemas shall strictly employ synthetic MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Port_2`, `Flow_A`, `Usage_1`, `param_x : Real`), with zero hardcoded domain concepts and zero mock data.

- **Formal Invariant**: Let $`\mathcal{A}`$ denote the contiguous node arena. The AST model multigraph is formally defined as a 6-tuple:

```math
G = \langle V, E, \text{src}, \text{dst}, \text{kind}, \text{prop} \rangle
```

where:

```math
\begin{aligned}
V &= \text{Nodes}(\mathcal{A}) \subset \mathbb{U}_{64} \quad (\text{typed arena node handles}) \\
E &\subset \mathbb{U}_{32} \quad (\text{dense arena edge identifiers}) \\
\text{src} &: E \longrightarrow V \quad (\text{source node handle mapping}) \\
\text{dst} &: E \longrightarrow V \quad (\text{target node handle mapping}) \\
\text{kind} &: E \longrightarrow \mathcal{K}_{\text{edge}} \quad (\text{edge kind classification}) \\
\text{prop} &: E \longrightarrow \mathcal{P} \quad (\text{extensible edge property record})
\end{aligned}
```

The set of canonical edge kinds $`\mathcal{K}_{\text{edge}}`$ is defined as:

```math
\mathcal{K}_{\text{edge}} = \{ \text{Contains}, \text{Specializes}, \text{Types}, \text{ConnectsTo}, \text{FlowsTo}, \text{AllocatesTo}, \text{Constrains}, \text{DependsOn} \}
```

Multigraph Parallel Edge Admissibility Invariant: Multiple distinct edge identifiers may share identical source and target vertices:

```math
\exists e_1, e_2 \in E, \quad e_1 \ne e_2 \;\wedge\; \langle \text{src}(e_1), \text{dst}(e_1) \rangle = \langle \text{src}(e_2), \text{dst}(e_2) \rangle
```

Forward and Backward Incident Adjacency Mappings: For each vertex $`v \in V`$, the incident edge sets are defined as:

```math
\begin{aligned}
\text{OutEdges}(v) &= \{ e \in E \mid \text{src}(e) = v \} \\
\text{InEdges}(v) &= \{ e \in E \mid \text{dst}(e) = v \}
\end{aligned}
```

Bidirectional Adjacency Invariant: Every edge $`e \in E`$ simultaneously belongs to the outgoing edge set of its source vertex and the incoming edge set of its destination vertex:

```math
\forall e \in E, \quad e \in \text{OutEdges}(\text{src}(e)) \;\wedge\; e \in \text{InEdges}(\text{dst}(e))
```

Degree Accounting and Conservation Invariant: For each vertex $`v \in V`$`, let `$`\text{deg}^+(v) = |\text{OutEdges}(v)|`$` and `$`\text{deg}^-(v) = |\text{InEdges}(v)|`$:

```math
\begin{aligned}
\text{deg}(v) &= \text{deg}^+(v) + \text{deg}^-(v) \\
\sum_{v \in V} \text{deg}^+(v) &= |E| = \sum_{v \in V} \text{deg}^-(v)
\end{aligned}
```

Deterministic Canonical Edge Ordering Invariant: Let $`\prec_E`$` denote the strict total ordering defined over edges incident to vertex `$`v`$:

```math
\begin{aligned}
e_1 \prec_E e_2 \iff &\; (\text{kind}(e_1) \lt \text{kind}(e_2)) \;\lor \\
&\; (\text{kind}(e_1) = \text{kind}(e_2) \wedge \text{Index}(\text{dst}(e_1)) \lt \text{Index}(\text{dst}(e_2))) \;\lor \\
&\; (\text{kind}(e_1) = \text{kind}(e_2) \wedge \text{Index}(\text{dst}(e_1)) = \text{Index}(\text{dst}(e_2)) \wedge e_1 \lt e_2)
\end{aligned}
```

where $`\text{Index}(h)`$` extracts the 32-bit slot index from node handle `$`h`$.

Output-Sensitive Adjacency Query Bound: Retrieval of incident edges for any vertex $`v`$ satisfies an execution time bound proportional strictly to the local vertex degree:

```math
T_{\text{neighbors}}(v) \le C_{\text{adj}} \cdot (\text{deg}(v) + 1)
```

where $`C_{\text{adj}}`$` is a constant independent of `$`|V|`$` and `$`|E|`$.

Containment Hierarchy Subgraph DAG Invariant: Let $`E_{\text{Contains}}`$ denote the subset of edges with kind `Contains`. The structural containment subgraph $`G_{\text{cont}} = (V, E_{\text{Contains}})`$ must form a directed acyclic forest:

```math
\begin{aligned}
E_{\text{Contains}} &= \{ e \in E \mid \text{kind}(e) = \text{Contains} \} \\
G_{\text{cont}} &= (V, E_{\text{Contains}}) \\
\text{Cycles}(G_{\text{cont}}) &= \emptyset \quad \wedge \quad \forall v \in V, \; |\text{InEdges}_{\text{Contains}}(v)| \le 1
\end{aligned}
```

Diagnostic Code Trigger Invariant: Attempting to insert an edge connecting invalid or stale node handles triggers diagnostic code `E0200`, and introducing a cycle into the containment hierarchy triggers diagnostic code `E0203`:

```math
\begin{aligned}
(\neg \text{Valid}(\text{src}(e), \mathcal{A}) \lor \neg \text{Valid}(\text{dst}(e), \mathcal{A})) &\implies \text{Diagnostic}(e, \text{DiagnosticCode::E0200}, \text{InvalidNodeHandleReference}) \in \mathcal{D} \\
\text{Cycles}(G_{\text{cont}}) \ne \emptyset &\implies \text{Diagnostic}(e, \text{DiagnosticCode::E0203}, \text{CyclicContainmentHierarchy}) \in \mathcal{D}
\end{aligned}
```

Diagnostic Taxonomy Containment Invariant: All diagnostics emitted by the multigraph metamodel engine strictly belong to the Metamodel and Typing taxonomy defined in REQ-0191:

```math
\forall D \in \mathcal{D}_{\text{graph}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0203} \} \subset \mathcal{E}_{\text{metamodel}}
```

- **Computational Complexity & Algorithmic Bounds**: Graph-theoretic AST multigraph construction, updates, and traversals execute within Complexity Class $`\mathbf{P}`$`. For an AST multigraph comprising `$`|V|`$` vertices and `$`|E|`$ directed property edges:
  1. Vertex Handle Lookup & Slot Access: Accessing or dereferencing any vertex $`v \in V`$` executes in deterministic `$`O(1)`$ worst-case time via direct arena slot indexing.
  2. Edge Allocation & Insertion: Inserting a new directed property edge $`e = (u, v, k, \mathbf{p})`$` into the multigraph executes in `$`O(1)`$` amortized time, appending the edge record to a contiguous edge slab and pushing `$`e`$` to the forward adjacency vector of `$`u`$` and backward adjacency vector of `$`v`$.
  3. Incident Neighbor Retrieval: Retrieving $`\text{OutEdges}(v)`$` and `$`\text{InEdges}(v)`$` executes in strictly output-sensitive `$`O(\text{deg}^+(v))`$` and `$`O(\text{deg}^-(v))`$ time respectively, requiring zero scanning of non-incident graph vertices or edges.
  4. Kind-Filtered Edge Queries: Filtering incident edges of vertex $`v`$` by edge kind `$`k \in \mathcal{K}_{\text{edge}}`$` evaluates within `$`O(\text{deg}(v))`$` time via direct linear scan of the local incident slab, or `$`O(1)`$ when indexed by edge kind bucket.
  5. Total Multigraph Construction: Building the complete AST multigraph from an ingested model with $`|V|`$` nodes and `$`|E|`$` relationships scales linearly in `$`O(|V| + |E|)`$ deterministic time.
  6. Memory Footprint & Space Complexity: Total graph memory scales strictly in linear space $`O(|V| + |E|)`$`. Adjacency lists utilize compact flat 32-bit integer index arrays, avoiding pointer indirection and eliminating per-node heap allocations. Auxiliary stack space for standard graph traversals (such as DFS/BFS reachability or topological scheduling per REQ-0048) is bounded by `$`O(|V|)`$ depth.

- **Verification & Conformance Criteria**: Automated test suites shall verify compliance using synthetic CommonMark and SysML v2 model definitions containing abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Port_2`, `Flow_A`, `Usage_1`, `param_x : Real`). Conformance shall be validated through the following deterministic test gates:
  1. Bidirectional Consistency Gate: The test harness shall construct a synthetic multigraph containing $`10^4`$` vertices and `$`5 \times 10^4`$` edges across all canonical kinds `$`\mathcal{K}_{\text{edge}}`$`. The harness shall verify that for 100% of edges `$`e \in E`$`, `$`e \in \text{OutEdges}(\text{src}(e))`$` and `$`e \in \text{InEdges}(\text{dst}(e))`$`. The harness shall assert that `$`\sum_{v \in V} \text{deg}^+(v) = |E| = \sum_{v \in V} \text{deg}^-(v)`$ with zero discrepancy.
  2. Multigraph Parallel Edge Admissibility Gate: The harness shall declare vertices `Classifier_Alpha` and `Classifier_Beta` connected by multiple parallel edges: an edge $`e_1`$ of kind `Specializes`, an edge $`e_2`$ of kind `ConnectsTo`, and two parallel flow edges $`e_3, e_4`$ of kind `FlowsTo` (representing distinct flow paths `Flow_A` and `Flow_B`). The harness shall assert that all parallel edges are independently registered, resolvable by distinct `EdgeId`, and retain their respective property payloads without collisions or data overwrites.
  3. Containment Forest Acyclicity & Single-Parent Gate: The harness shall construct hierarchical containment edges (`Contains`) rooted at `Package_0`. The harness shall assert that $`\text{Cycles}(G_{\text{cont}}) = \emptyset`$` and that every node has at most one containment parent (`$`\forall v \in V, |\text{InEdges}_{\text{Contains}}(v)| \le 1`$). Attempting to insert a containment edge that introduces a cycle (`Package_0` contains `Package_1` which contains `Package_0`) shall be deterministically rejected at compile time with structured diagnostic error code `E0203`, verifying total-function non-panicking recovery.
  4. Dangling Handle & Stale Reference Rejection Gate: The test suite shall attempt to insert an edge where `src(e)` or `dst(e)` is an unallocated handle or a stale handle with a mismatched generation counter (per REQ-0035). The harness shall assert deterministic rejection with structured diagnostic error code `E0200`, returning an error sentinel and avoiding system panic.
  5. Canonical Adjacency Ordering & Bitwise Parity Gate: The harness shall ingest AST elements declared in randomized lexical order, construct the multigraph, and iterate over incident edges. The harness shall assert that canonical ordering $`\prec_E`$ produces identical sorted adjacency lists across consecutive runs, guaranteeing 0-byte diff churn (REQ-0003) and invariant cryptographic Merkle root digests (REQ-0010).
  6. Performance & Memory Budget Gate: In accordance with Directive 5, REQ-0011, and REQ-0196, benchmarks shall execute exclusively in compiled Release mode (`--release`) under an isolated benchmark harness. The harness shall assert that constructing and traversing an AST multigraph with $`10^5`$` nodes and `$`5 \times 10^5`$ edges completes within 25 ms, achieves an average neighbor retrieval latency below 15 ns per query, and consumes peak resident set size (RSS) memory strictly below 100 MB.
