### REQ-0082: SysML v2 CalculationDefinition (`calc def`) & CalculationUsage Lowering

- **Normative Statement**: The Core Metamodel, Node Arena & AST Graph Engine and KerML metamodel lowering engine shall formalize all mathematical calculation definitions and functional computational usages as instances of `CalculationDefinition` and `CalculationUsage` abstract syntax elements. In the SysML v2 metamodel taxonomy, `CalculationDefinition` (`calc def`) shall specialize KerML `Function` (which transitively specializes `Behavior`, `Step`, `Type`, `Class`, and `Classifier`), formalizing deterministic, referentially transparent, and side-effect-free mathematical computations mapping input argument vectors to deterministic scalar or tensor output results. `CalculationUsage` (`calc`) shall specialize KerML `Step` and SysML v2 `ActionUsage`, representing the pure functional execution or evaluation step of a calculation within an enclosing classifier definition, action, calculation, state lifecycle hook, or constraint context.

  The lowering engine shall strictly enforce referential transparency, idempotency, and side-effect freedom across all calculation definitions. A calculation definition must evaluate as a pure mathematical function: for every input argument vector $`\mathbf{x} \in \prod_{i=1}^m \llbracket \tau(p_i) \rrbracket`$, the evaluation shall produce a deterministic output result $`y = f(\mathbf{x})`$ without mutating any system state ($`\Delta \text{State} \equiv \emptyset`$). Any syntactic or semantic construct within a calculation body that attempts state mutation -- including assigning to non-local features, invoking non-functional actions, performing external I/O or message emissions, or triggering state machine transitions -- shall be strictly prohibited at compile time, deterministically emitting diagnostic error code `E0200` (`ImpureCalculationMutation`) in accordance with the standardized diagnostic taxonomy of REQ-0191.

  Every `CalculationDefinition` shall declare an ordered sequence of input parameters and exactly one designated return parameter (or bound return expression) typed by an authoritative classifier $`T_{\text{out}}`$. All input parameters $`p \in \mathcal{P}^{\text{in}}`$ must declare immutable input directionality $`\text{dir}(p) = \text{In}`$ exclusively. The declaration of mutating parameter directionalities (`InOut`, or mutable `Out`) on a `CalculationDefinition` shall be strictly forbidden, deterministically emitting diagnostic error code `E0201` (`CalculationParameterDirectionViolation`). Every parameter must bind to a resolvable classifier type; any unresolvable parameter type or return type shall deterministically trigger diagnostic error code `E0200` (`UnresolvedCalculationParameterType` / `UnresolvedCalculationReturnType`).

  The compiler shall bind every `CalculationUsage` to an authoritative `CalculationDefinition` or specialized `Function` classifier via a formal `FeatureTyping` relationship ($`\tau(u) \le \text{Function}`$). Attempting to type a `CalculationUsage` with a non-functional classifier definition (such as a structural `PartDefinition`, `ItemDefinition`, or impure `ActionDefinition`) shall deterministically trigger diagnostic error code `E0200` (`InvalidCalculationUsageClassifier`). For each bound argument expression $`a_i`$ passed to input parameter $`p_i`$, the lowering engine shall verify covariant type conformance: the evaluated type of $`a_i`$ must specialize or equal the declared parameter type ($`\tau(a_i) \le \tau(p_i)`$). Any argument type incompatibility shall deterministically emit diagnostic error code `E0200` (`CalculationArgumentTypeMismatch`). Omission of any mandatory input parameter lacking a declared default expression shall deterministically emit diagnostic error code `E0200` (`MissingCalculationArgument`).

  Every `CalculationUsage` shall specify an explicit or defaulted multiplicity interval $`\mu(u) = [m_{\min}, m_{\max}]`$ governing evaluation cardinality, subject to the interval well-formedness invariant $`0 \le m_{\min} \le m_{\max}`$. Any malformed multiplicity interval where $`m_{\min} \gt m_{\max}`$ shall be rejected with diagnostic error code `E0200` (`InvalidCalculationMultiplicityBounds`).

  Within composite calculation definitions or networks of interconnected calculation usages, calculation steps and intermediate expression evaluations induce a directed dependency graph $`G_{\text{calc}} = (V_{\text{calc}}, E_{\text{calc}})`$. The calculation dependency graph must be a strict Directed Acyclic Graph (DAG) for static compile-time evaluation. Static circular dependencies between calculations ($`u \to_{\text{calc}}^+ u`$) shall be detected via Tarjan's strongly connected components algorithm and rejected at compile time with diagnostic error code `E0203` (`CircularCalculationDependency`). Non-recursive calculation DAGs shall be scheduled and evaluated in deterministic reverse topological order.

  All `CalculationDefinition` and `CalculationUsage` AST nodes shall be stored sequentially in contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, addressed via stable 32-bit arena node handles per REQ-0035. Every lowered calculation AST node must receive a deterministic RFC 4122 UUIDv5 identifier computed by namespace-hashing the node fully qualified topological path with the canonical compiler namespace OID in accordance with Architectural Directive 1 and REQ-0010. Scalar symbol identifiers for calculation names, parameter names, and expression variables shall be interned into the global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management in accordance with Architectural Directive 3.

  In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the lowering engine shall implement synchronization token error recovery on declaration and delimiter boundaries (e.g., `;`, `}`, `end`). Upon detecting an invalid calculation declaration, impure mutation (`E0200`), direction violation (`E0201`), argument type mismatch (`E0200`), or circular dependency (`E0203`), the engine shall record structured diagnostics into the diagnostic sink buffer $`\mathcal{D}_{\text{sink}}`$, bind an error sentinel $`\bot_{\text{calc}}`$ or $`\bot_{\text{type}}`$, and continue verifying subsequent declarations without aborting on first fault. If accumulated diagnostics reach the sink capacity limit $`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.

  Parallel lowering and type checking across independent compilation units shall be scheduled on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with Architectural Directive 2 and REQ-0012. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the calculation lowering engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs; performance latency ($`\lt 25\text{ ms}`$ for $`10^4`$ calculation declarations) and peak memory RSS ($`\lt 100\text{ MB}`$ RSS) performance gates shall be verified exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests. All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Package_1`, `CalcDef_Alpha`, `CalcDef_Beta`, `CalcUsage_1`, `CalcUsage_2`, `Param_X : Real`, `Param_Y : Real`, `Result_Val : Real`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes. The metamodel partitions calculation elements into calculation definitions $`\mathcal{C}_{\text{calc}} \subset \mathcal{V}_{\text{AST}}`$ and calculation usages $`\mathcal{U}_{\text{calc}} \subset \mathcal{V}_{\text{AST}}`$:

$$
\mathcal{C}_{\text{calc}} \cap \mathcal{U}_{\text{calc}} = \emptyset, \quad \mathcal{C}_{\text{calc}} \cup \mathcal{U}_{\text{calc}} \subset \mathcal{V}_{\text{AST}}
$$

Each calculation definition $`D \in \mathcal{C}_{\text{calc}}`$ is formalized as an 8-tuple:

$$
D = \langle \text{id}_D, \text{name}_D, \mathcal{P}_D^{\text{in}}, p_D^{\text{ret}}, \mathcal{E}_D, \mathcal{S}_D, \Delta_D, \text{span}_D \rangle
$$

where:

$$
\begin{aligned}
\text{id}_D &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_D &\in \mathcal{S}_{\text{intern}} \quad (\text{interned scalar symbol identifier}) \\
\mathcal{P}_D^{\text{in}} &= [p_1, p_2, \dots, p_m] \in \mathcal{V}_{\text{param}}^* \quad (\text{ordered sequence of input parameters}) \\
p_D^{\text{ret}} &\in \mathcal{V}_{\text{param}} \quad (\text{designated pure return parameter}) \\
\mathcal{E}_D &\in \mathcal{V}_{\text{expr}} \quad (\text{functional calculation expression AST root}) \\
\mathcal{S}_D &\subseteq \mathcal{C} \quad (\text{specialized supertypes, subject to } \mathcal{S}_D \le \text{Function}) \\
\Delta_D &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_D &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

Each calculation usage $`U \in \mathcal{U}_{\text{calc}}`$ is formalized as an 8-tuple:

$$
U = \langle \text{id}_U, \text{name}_U, \text{owner}_U, \tau(U), \mathcal{B}_U, \mu(U), \Delta_U, \text{span}_U \rangle
$$

where:

$$
\begin{aligned}
\text{id}_U &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_U &\in \mathcal{S}_{\text{intern}} \quad (\text{interned scalar symbol identifier}) \\
\text{owner}_U &\in \mathcal{V}_{\text{AST}} \quad (\text{featuring definition or enclosing step context}) \\
\tau(U) &\in \mathcal{C}_{\text{calc}} \setminus \{ \bot_{\text{type}} \} \quad (\text{bound calculation definition type}) \\
\mathcal{B}_U &= \{ (p_i, a_i) \mid p_i \in \mathcal{P}_{\tau(U)}^{\text{in}}, \, a_i \in \mathcal{V}_{\text{expr}} \} \quad (\text{argument parameter bindings}) \\
\mu(U) &= [m_{\min}(U), m_{\max}(U)] \subseteq \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \}) \quad (\text{declared multiplicity interval}) \\
\Delta_U &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_U &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

Metamodel Subtyping Specialization Invariant: Every calculation definition specializes KerML `Function`, and every calculation usage specializes KerML `Step` and SysML v2 `ActionUsage`:

$$
\begin{aligned}
\forall D \in \mathcal{C}_{\text{calc}}, &\quad D \le \text{Function} \le \text{Behavior} \le \text{Class} \\
\forall U \in \mathcal{U}_{\text{calc}}, &\quad U \le \text{Step} \wedge \tau(U) \le \text{Function}
\end{aligned}
$$

Pure Functional Semantics & Referential Transparency Invariant: A calculation evaluates a mathematical function mapping input argument domains to the return type domain:

$$
f_D : \prod_{i=1}^m \llbracket \tau(p_i) \rrbracket \longrightarrow \llbracket \tau(p_D^{\text{ret}}) \rrbracket
$$

For any system state $`\sigma \in \Sigma`$, evaluation of calculation $`D`$ with input arguments $`\mathbf{x} \in \prod_{i=1}^m \llbracket \tau(p_i) \rrbracket`$ preserves system state identically:

$$
\text{eval}(D, \mathbf{x}, \sigma) = \langle y, \sigma' \rangle \implies (\sigma' = \sigma) \wedge (y = f_D(\mathbf{x}))
$$

yielding state invariance and evaluation determinism:

$$
\forall \mathbf{x} \in \prod_{i=1}^m \llbracket \tau(p_i) \rrbracket, \quad \Delta \text{State} \equiv \emptyset \wedge f_D(\mathbf{x}) = f_D(\mathbf{x})
$$

Parameter Directionality Invariant: Every input parameter must be strictly directional `In`, the designated return parameter must be `Return` or `Out`, and mutating `InOut` parameters are strictly forbidden:

$$
\begin{aligned}
\forall p \in \mathcal{P}_D^{\text{in}}, &\quad \text{dir}(p) = \text{In} \\
&\quad \text{dir}(p_D^{\text{ret}}) \in \{ \text{Return}, \text{Out} \} \\
\forall p \in \mathcal{P}_D^{\text{in}} \cup \{ p_D^{\text{ret}} \}, &\quad \text{dir}(p) \ne \text{InOut}
\end{aligned}
$$

Covariant Argument Subtyping Conformance Invariant: Every argument bound to an input parameter must satisfy covariant subtyping in the bounded meet-semilattice $`(\mathcal{C}, \le)`$:

$$
\forall (p_i, a_i) \in \mathcal{B}_U, \quad \tau(a_i) \le \tau(p_i) \wedge \tau(a_i) \ne \bot_{\text{type}}
$$

Argument Completeness Invariant: Every declared input parameter must receive a conforming argument binding or define an authoritative default expression:

$$
\forall p \in \mathcal{P}_{\tau(U)}^{\text{in}}, \quad p \in \text{dom}(\mathcal{B}_U) \vee \text{HasDefault}(p) \equiv \text{true}
$$

Multiplicity Interval Well-Formedness Invariant: The multiplicity interval of every calculation usage must satisfy:

$$
\forall U \in \mathcal{U}_{\text{calc}}, \quad 0 \le m_{\min}(U) \le m_{\max}(U) \wedge (m_{\max}(U) \ge 1 \vee m_{\max}(U) = 0)
$$

Calculation Dependency Graph Acyclicity Invariant: Let $`G_{\text{calc}} = (V_{\text{calc}}, E_{\text{calc}})`$ denote the directed dependency graph of calculation steps, where $`(u, v) \in E_{\text{calc}}`$ indicates that calculation $`u`$ depends upon the evaluation result of calculation $`v`$. The transitive closure $`E_{\text{calc}}^+`$ must be irreflexive:

$$
\forall v \in V_{\text{calc}}, \quad (v, v) \notin E_{\text{calc}}^+
$$

Deterministic RFC 4122 UUIDv5 Anchor Invariant (Architectural Directive 1): Every calculation definition and usage binds an immutable RFC 4122 UUIDv5 identifier computed from the compiler namespace OID and canonical fully qualified path:

$$
\begin{aligned}
\forall D \in \mathcal{C}_{\text{calc}}, \quad \Delta_D &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(D)) \\
\forall U \in \mathcal{U}_{\text{calc}}, \quad \Delta_U &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U))
\end{aligned}
$$

Diagnostic Code Trigger Invariants: Violations of functional supertyping, parameter directionality, purity, argument typing, completeness, dependency acyclicity, or multiplicity bounds deterministically trigger standardized diagnostic error codes per REQ-0191:

$$
\begin{aligned}
\exists D \in \mathcal{C}_{\text{calc}} : D \not\le \text{Function} &\implies \text{Diagnostic}(D, \text{DiagnosticCode::E0200}, \text{InvalidCalculationSupertype}) \in \mathcal{D}_{\text{sink}} \\
\exists D \in \mathcal{C}_{\text{calc}}, \exists p \in \mathcal{P}_D^{\text{in}} : \text{dir}(p) \ne \text{In} &\implies \text{Diagnostic}(p, \text{DiagnosticCode::E0201}, \text{CalculationParameterDirectionViolation}) \in \mathcal{D}_{\text{sink}} \\
\exists D \in \mathcal{C}_{\text{calc}} : \text{HasSideEffect}(\mathcal{E}_D) \equiv \text{true} &\implies \text{Diagnostic}(D, \text{DiagnosticCode::E0200}, \text{ImpureCalculationMutation}) \in \mathcal{D}_{\text{sink}} \\
\exists U \in \mathcal{U}_{\text{calc}} : \tau(U) \not\le \text{Function} &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0200}, \text{InvalidCalculationUsageClassifier}) \in \mathcal{D}_{\text{sink}} \\
\exists (p_i, a_i) \in \mathcal{B}_U : \tau(a_i) \not\le \tau(p_i) &\implies \text{Diagnostic}(a_i, \text{DiagnosticCode::E0200}, \text{CalculationArgumentTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists p \in \mathcal{P}_{\tau(U)}^{\text{in}} : p \notin \text{dom}(\mathcal{B}_U) \wedge \neg\text{HasDefault}(p) &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0200}, \text{MissingCalculationArgument}) \in \mathcal{D}_{\text{sink}} \\
\exists v \in V_{\text{calc}} : (v, v) \in E_{\text{calc}}^+ &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0203}, \text{CircularCalculationDependency}) \in \mathcal{D}_{\text{sink}} \\
\exists U \in \mathcal{U}_{\text{calc}} : m_{\min}(U) \gt m_{\max}(U) &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0200}, \text{InvalidCalculationMultiplicityBounds}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Lowering, type checking, and dependency analysis of `CalculationDefinition` and `CalculationUsage` elements execute strictly within Complexity Class $`\mathbf{P}`$.

  **Verification Complexity Breakdown**: For an AST model containing $`V = |\mathcal{C}_{\text{calc}}| + |\mathcal{U}_{\text{calc}}|`$ calculation nodes and $`E = |E_{\text{calc}}|`$ dependency edges:
  1. *AST Lowering & Arena Allocation*: Allocating $`V`$ calculation nodes in contiguous bump arena storage and interning symbol strings requires amortized $`O(1)`$ time per node, totaling $`O(V)`$ time.
  2. *Parameter Directionality & Typing Validation*: For each calculation definition with $`m`$ parameters, verifying $`\text{dir}(p) = \text{In}`$ and checking parameter/return types against the subtyping lattice requires $`O(m)`$ operations where $`m \le 32 = O(1)`$, totaling $`O(V)`$ time across the model.
  3. *Side-Effect & Purity AST Traversal*: Recursively validating expression tree $`\mathcal{E}_D`$ for absence of mutating operations traverses $`K_D`$ expression nodes in deterministic $`O(K_D)`$ linear time, totaling $`O(\sum K_D) = O(V)`$ time.
  4. *Argument Subtyping Conformance*: For each calculation usage, validating covariant subtyping $`\tau(a_i) \le \tau(p_i)`$ evaluates in $`O(1)`$ time via bitset reachability or bounded ancestor array climbing ($`h \le 32`$), totaling $`O(V)`$ time.
  5. *Dependency DAG Acyclicity & Scheduling (Tarjan SCC / Kahn's Algorithm)*: Detecting circular calculation dependencies and computing the reverse topological evaluation order over dependency graph $`G_{\text{calc}} = (V_{\text{calc}}, E_{\text{calc}})`$ executes in deterministic $`O(V + E)`$ time and $`O(V)`$ auxiliary stack space.
  6. *Multiplicity Validation*: Checking $`0 \le m_{\min}(U) \le m_{\max}(U)`$ executes in strictly $`O(1)`$ scalar integer comparisons per usage, totaling $`O(V)`$ time.

  Total sequential verification time across all calculation elements is strictly linear in the size of the calculation graph:

$$
T_{\text{validate}}(V, E) \in O(V + E)
$$

  **Parallel Work-Stealing Scheduling (Architectural Directive 2)**: When calculation lowering and type checking across independent compilation units is scheduled on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

$$
T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{V + E}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  **Space Complexity & Memory Bounds**: Auxiliary memory is bounded by $`O(V + E)`$ for contiguous arena storage and dependency adjacency lists. Expression traversal recursion depth is bounded by tree depth $`d \le 64`$ ($`O(1)`$ stack). The preallocated diagnostic sink buffer is strictly bounded by $`O(C_{\text{max\_errors}}) = O(1)`$ records, guaranteeing zero unbounded heap allocations during calculation compilation.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models containing abstract placeholders (`Package_0`, `Package_1`, `CalcDef_Alpha`, `CalcDef_Beta`, `CalcUsage_1`, `CalcUsage_2`, `Param_X : Real`, `Param_Y : Real`, `Result_Val : Real`). Conformance validation shall enforce the following test gates:

  1. **Canonical Calculation Definition Lowering Gate**: Declare `CalcDef_Alpha(in Param_X : Real, in Param_Y : Real) : Real { return Param_X + Param_Y; }`. Assert 100% lowering into contiguous arena storage, valid arena node handle, valid RFC 4122 UUIDv5 anchor, specialization of KerML `Function`, and zero diagnostic emissions.
  2. **Canonical Calculation Usage & Binding Gate**: Lower `CalcUsage_1 : CalcDef_Alpha(Param_X = 10.0, Param_Y = 20.0)`. Assert valid parameter-argument bindings, evaluated return type `Real`, and zero diagnostics emitted.
  3. **Covariant Argument Type Conformance Gate (`E0200`)**: Declare `CalcDef_Alpha(in Param_X : Real) : Real`. Ingest `CalcUsage_Err : CalcDef_Alpha(Param_X = "InvalidString")`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`CalculationArgumentTypeMismatch`), exact source byte span mapping, and error sentinel $`\bot_{\text{calc}}`$ assignment.
  4. **Non-Functional Classifier Typing Gate (`E0200`)**: Declare structural `PartDef_Alpha` lacking `Function` specialization. Attempt to lower `CalcUsage_Bad : PartDef_Alpha`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`InvalidCalculationUsageClassifier`).
  5. **Missing Mandatory Argument Gate (`E0200`)**: Declare `CalcDef_Beta(in Param_A : Real, in Param_B : Real) : Real` with no default expressions. Lower `CalcUsage_Incomplete : CalcDef_Beta(Param_A = 5.0)` omitting `Param_B`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`MissingCalculationArgument`).
  6. **Parameter Directionality Violation Gate (`E0201`)**: Attempt to declare `calc def CalcDef_Impure(inout Param_M : Real) : Real`. Assert deterministic compile-time rejection with diagnostic error code `E0201` (`CalculationParameterDirectionViolation`).
  7. **Impure State Mutation Gate (`E0200`)**: Ingest a calculation definition whose body attempts feature assignment to an external classifier or invokes an impure non-functional action. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`ImpureCalculationMutation`).
  8. **Circular Calculation Dependency Gate (`E0203`)**: Construct mutually dependent calculation usages where `CalcUsage_1` depends on `CalcUsage_2` and `CalcUsage_2` depends on `CalcUsage_1`. Assert deterministic cycle detection via Tarjan SCC, emission of diagnostic error code `E0203` (`CircularCalculationDependency`) detailing the cycle path, and graceful recovery.
  9. **Multiplicity Bounds Well-Formedness Gate (`E0200`)**: Declare `CalcUsage_BadMult : CalcDef_Alpha [5..2]`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`InvalidCalculationMultiplicityBounds`).
  10. **Synchronization Token Recovery & Error Accumulation Gate (Architectural Directive 4)**: Ingest a model unit containing 5 distinct malformed calculation declarations (direction violation, argument type mismatch, circular dependency, impure mutation, invalid multiplicity) separated by delimiter tokens. Assert that the lowering engine resynchronizes on token boundaries, accumulates all 5 structured diagnostics with precise source spans, and when the error count reaches $`C_{\text{max\_errors}}`$, emits terminal diagnostic `E0199` and halts gracefully.
  11. **Deterministic UUIDv5 Topological Identity Gate (Architectural Directive 1)**: Verify that 100% of lowered `CalculationDefinition` and `CalculationUsage` AST nodes bind valid RFC 4122 UUIDv5 identifiers computed from the fixed DEAP namespace OID and canonical fully qualified paths, asserting bitwise identical digests and 0-byte diff churn across 10 repeated compilation runs.
  12. **Bounded Work-Stealing Parallelism Gate (Architectural Directive 2)**: Ingest a multi-package model containing 50 packages with $`10^4`$ calculation definitions and usages across $`N_{\text{max\_workers}}`$ threads; assert data-race freedom, deterministic AST output, and identical node ordering compared to single-threaded compilation.
  13. **Release Mode Latency & Memory Budget Gate (Architectural Directive 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, verify that lowering, type checking, and dependency DAG analysis for $`10^4`$ synthetic calculations executes in under 25 ms, peak RSS memory remains strictly under 100 MB, zero panics occur, and 0-byte diff churn is preserved.
