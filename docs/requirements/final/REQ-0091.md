### REQ-0091: KerML Standard Library: `Base` Package & Primitive Equality Lowering

- **Normative Statement**: The KerML/SysML v2 metamodel lowering engine and root symbol resolution subsystem shall bootstrap the normative KerML `Base` standard library package into the global root symbol table during compiler initialization. The bootstrapped `Base` package shall establish the universal root type `Anything`, foundational classifiers `Element` and `Relationship`, bottom type `Nothing`, and primitive equivalence operators (`==`, `!=`) axiomatized over data values and object identities.

  The lowering engine and semantic type checker shall strictly enforce the following structural, semantic, and typing invariants during `Base` package bootstrapping and expression lowering:
  1. **Universal Top-Type Axiomatization (`Anything`)**: The compiler shall define `Anything` as the unique maximum element ($`\top`$`) of the subtyping partially ordered set (poset) `$`(\mathcal{T}, \le, \wedge, \top)`$. Every classifier, data type, class, structure, and interface defined in user models or imported libraries shall explicitly or implicitly specialize `Anything` ($`\forall T \in \mathcal{T}, T \le \text{Anything}`$). The semantic denotation of `Anything` shall encompass the entire universe of instances ($`\llbracket \text{Anything} \rrbracket = \mathcal{U}_{\text{universe}}`$`), partitioned into pure identity-free data values (`$`\mathcal{V}_{\text{values}}`$`) and extensional identity-bearing entities (`$`\mathcal{O}_{\text{entities}}`$).
  2. **Base Classifier Hierarchy (`Element` & `Relationship`)**: In the bootstrapped classifier hierarchy:
     - `Element` shall specialize `Anything` ($`\text{Element} \le \text{Anything}`$), serving as the common root classifier for all syntactic and semantic model elements possessing identity, annotations, documentation, and owned relationships.
     - `Relationship` shall specialize `Element` ($`\text{Relationship} \le \text{Element}`$), providing the foundational reified abstraction for directed and undirected links, associations, specializations, subsets, and connectors across model elements.
     - The taxonomic specialization chain $`\text{Relationship} \le \text{Element} \le \text{Anything}`$ shall be pre-compiled into contiguous arena storage and marked as transitively closed.
  3. **Universal Bottom-Type Dual (`Nothing`)**: The `Base` package shall define `Nothing` as the unique minimum element ($`\bot`$`) of the subtyping poset `$`(\mathcal{T}, \le, \wedge, \top, \bot)`$`, satisfying `$`\forall T \in \mathcal{T}, \text{Nothing} \le T`$` with empty denotation (`$`\llbracket \text{Nothing} \rrbracket = \emptyset`$).
  4. **Primitive Equivalence Operator Lowering (`==`, `!=`)**: The compiler shall provide built-in primitive equality (`==`) and inequality (`!=`) operator functions accepting operands conforming to `Anything`:
     - **Identity Duality for DataTypes**: For operands $`a, b \in \llbracket \text{DataType} \rrbracket`$`, equivalence shall be evaluated strictly via structural value congruence (`$`a \equiv_{\text{val}} b`$), wherein two values are equal if and only if their concrete types unify and all corresponding feature projections evaluate to equivalent values.
     - **Identity Duality for Classes**: For operands $`u, v \in \llbracket \text{Class} \rrbracket`$ (including `Structure`), equivalence shall be evaluated strictly via extensional object token identity ($`\text{id}(u) = \text{id}(v)`$), such that two distinct object allocations remain non-identical even when all observed feature values are congruent.
     - **Cross-Domain Disjoint Comparison**: Comparing a `DataType` value against a `Class` entity shall evaluate deterministically to `false` ($`a == u \equiv \text{false}`$`), conforming to the strict disjointness invariant `$`\llbracket \text{DataType} \rrbracket \cap \llbracket \text{Class} \rrbracket = \emptyset`$ without raising runtime faults or exceptions.
     - **Equivalence Relation Axioms**: Primitive equality `==` shall satisfy the mathematical axioms of reflexivity ($`x == x`$`), symmetry (`$`x == y \iff y == x`$`), and transitivity (`$`x == y \wedge y == z \implies x == z`$).
     - **Inequality Derivation**: Primitive inequality shall be lowered as logical negation: $`x != y \iff \neg(x == y)`$.
  5. **Implicit Root Scope Visibility & Name Resolution**: The public symbols of the `Base` package (`Anything`, `Element`, `Relationship`, `Nothing`, `==`, `!=`) shall be injected into the root lexical scope of every compilation unit (equivalent to an implicit `private import Base::*;`). User models shall access these symbols without explicit import declarations.
  6. **Immutability & Reserved Namespace Protection**: All bootstrapped `Base` AST nodes shall be flagged as immutable root symbols. Any user declaration attempting to shadow, rebind, redefine, or mutate symbols within the reserved `Base` namespace, or attempting to introduce an inheritance cycle placing `Anything` as a subtype of a user-defined classifier ($`\text{Anything} \le C`$` for `$`C \ne \text{Anything}`$), shall be strictly rejected at compile time with diagnostic error code `E0200` or `E0203`.

  **Algorithmic Bound NP-3 Integration**: In arbitrary partially ordered sets (posets), general subtyping satisfiability and multiple-inheritance feature redefinition is NP-complete. By establishing `Anything` as the unique maximum element ($`\top`$) within a monotonic meet-semilattice and resolving multiple inheritance via C3 linearization, subtyping queries against `Anything` evaluate in deterministic $`O(1)`$ constant time without backtracking.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every bootstrapped AST node in `Base` (including `Base`, `Anything`, `Element`, `Relationship`, `Nothing`, `==`, `!=`, and their formal parameters) shall be bound to an immutable, bitwise deterministic RFC 4122 UUIDv5 identifier generated by namespace-hashing the fully qualified symbol path (e.g., `Base::Anything`, `Base::Element`, `Base::Relationship`, `Base::"=="`) with the canonical compiler namespace OID per REQ-0010.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Bootstrapping of `Base` shall execute once during compiler initialization. The resulting immutable symbol table and AST graph shall be shared across worker threads on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012, guaranteeing zero lock contention during parallel semantic analysis.
  - *Directive 3 (String Interner Allocation Exception)*: String bytes representing bootstrapped symbol names (`Base`, `Anything`, `Element`, `Relationship`, `Nothing`, `==`, `!=`, parameter names `a`, `b`) shall be copied into the global symbol interner pool during compiler initialization per REQ-0036 as the sole permitted exception to zero-copy memory management.
  - *Directive 4 (Synchronization Token Error Recovery)*: The lowering engine shall implement synchronization token error recovery per REQ-0013 and REQ-0016 on declaration and delimiter boundaries. Upon detecting an invalid override or malformed reference to a `Base` entity, the engine records diagnostic `E0200` or `E0203` into error sink $`\mathcal{D}_{\text{sink}}`$`, assigns error sentinel type `$`\bot_{\text{type}}`$`, and recovers gracefully without aborting compilation. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, the compiler emits terminal diagnostic `E0199` and halts.
  - *Directive 5 (Panic-Free Release Isolation)*: Production compiler library code shall enforce a deterministic, non-panicking execution contract with total-function error handling. Bootstrap latency ($`\lt 1\text{ ms}`$`), total lowering latency (`$`\lt 25\text{ ms}`$`), and peak memory RSS (`$`\lt 100\text{ MB}`$) performance gates shall be verified exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.


  **Algorithmic Bound NP-3 Formulation**: In general unconstrained partially ordered sets (posets), general subtyping satisfiability and multiple-inheritance feature redefinition is NP-complete. The DEAP compiler eliminates backtracking and combinatorial search through two structural guarantees:
  1. The subtyping hierarchy forms a monotonic meet-semilattice $`(\mathcal{T}, \le, \wedge, \top)`$` anchored by the universal supremum `$`\top = \text{Anything}`$.

  1. *Bootstrapping Initialization*: Allocating the fixed core entities ($`K_{\text{Base}} \le 16 = O(1)`$` AST nodes) into the contiguous bump arena and interning symbol identifiers executes in `$`O(1)`$ constant time during compiler initialization.
