### REQ-0014: File Format Detection Engine by Extension & Magic Signatures

- **Normative Statement**: The compiler ingestion engine shall classify input schema files into target schema formats using file extensions and deterministic content prefix signatures across 5 supported schema formats: CommonMark Markdown tables, Protocol Buffers (`.proto`), OMG IDL (`.idl`), OpenAPI (`.json`/`.yaml`), and XML Schema Definitions (`.xml`/`.xsd`). Detection must execute using deterministic byte prefix scanning without regular expressions or exploratory backtracking. Prefix inspection shall examine a bounded initial byte window $`[0, K]`$` where `$`K = 512`$` bytes (or `$`[0, |F|]`$` for files where `$`|F| \lt K`$). The detection engine shall evaluate file extensions as an initial filter, followed by deterministic magic byte prefix signatures to verify and disambiguate format identity. If an input file cannot be classified into any of the 5 supported schema formats, or exhibits an unrecognized, corrupt, or ambiguous format signature, the engine shall classify it as `Unknown` and emit structured diagnostic code `E0100` in accordance with the ingestion diagnostic taxonomy. Rather than aborting the compilation process upon encountering an unrecognized or malformed file, the ingestion engine shall implement synchronization recovery, recording the diagnostic and proceeding to subsequent compilation units to accumulate all diagnostics. Format classification shall enforce a strict total-function contract with zero panics across all inputs, including empty 0-byte files, truncated files, binary objects, and adversarial payloads. When classifying multi-file compilation units in parallel, worker tasks shall be dispatched strictly onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$`, prohibiting unbounded thread spawning. Format detection latency across the `$`K`$-byte window shall be evaluated exclusively in compiled Release mode (`--release`) within dedicated benchmark harnesses isolated from continuous integration logic tests.

- **Formal Invariant**: Let $`\mathcal{F}`$` denote the universe of input schema files. For any file `$`F \in \mathcal{F}`$`, let `$`|F| \in \mathbb{N}_0`$` denote the byte length of `$`F`$`, let `$`\text{ext}(F) \in \Sigma^*`$` denote the canonical lowercase file extension string including the leading dot, let `$`B(F) = \langle b_0, b_1, \dots, b_{|F|-1} \rangle`$` denote the raw byte sequence of `$`F`$` where `$`b_i \in \{0, \dots, 255\}`$`, and let `$`K = 512`$ denote the fixed prefix inspection window bound. The bounded prefix byte sequence is defined as:

```math
\text{head}(F, K) = \langle b_0, \dots, b_{\min(|F|, K) - 1} \rangle
```

The target format domain $`\mathcal{M}`$ is defined as:

```math
\mathcal{M} = \{ \text{MarkdownTable}, \text{Protobuf}, \text{OmgIdl}, \text{OpenApi}, \text{XmlSchema}, \text{Unknown} \}
```

The deterministic format classifier function $`\Delta : \mathcal{F} \longrightarrow \mathcal{M}`$ is defined as:

```math
\Delta(F) = \begin{cases}
\text{MarkdownTable}, & \text{if } \text{ext}(F) \in \{\text{".md"}, \text{".markdown"}\} \wedge \text{ContainsMarkdownTable}(\text{head}(F, K)) \\
\text{Protobuf}, & \text{if } \text{ext}(F) = \text{".proto"} \vee \text{ContainsPrefix}(\text{head}(F, K), \text{"syntax = proto"}) \\
\text{OmgIdl}, & \text{if } \text{ext}(F) = \text{".idl"} \vee \text{ContainsKeyword}(\text{head}(F, K), \text{"module"}) \\
\text{OpenApi}, & \text{if } \text{ext}(F) \in \{\text{".json"}, \text{".yaml"}, \text{".yml"}\} \wedge \text{ContainsKeys}(\text{head}(F, K), \{\text{"openapi"}, \text{"swagger"}\}) \\
\text{XmlSchema}, & \text{if } \text{ext}(F) \in \{\text{".xml"}, \text{".xsd"}\} \wedge \text{ContainsXmlRoot}(\text{head}(F, K)) \\
\text{Unknown}, & \text{otherwise}
\end{cases}
```

Bounded Inspection Window Invariant: For every input file $`F \in \mathcal{F}`$`, the number of bytes read and inspected by `$`\Delta(F)`$ is strictly bounded:

```math
\forall F \in \mathcal{F}, \quad \text{BytesInspected}(F) = \min(|F|, K) \le K = 512
```

Strict Regex Prohibition Invariant: Format classification executes without invoking regular expression engines or non-deterministic automata:

```math
\text{RegexEvaluations}(\Delta) = 0
```

Monotonic Forward Scan Invariant: The byte inspection pointer across $`\text{head}(F, K)`$ advances monotonically without exploratory backtracking:

```math
\text{BacktrackCount}(\Delta) = 0
```

Deterministic Classification Invariant: Given identical extensions and byte prefixes, classification decisions are bitwise invariant:

```math
\forall F_1, F_2 \in \mathcal{F}, \quad (\text{ext}(F_1) = \text{ext}(F_2) \wedge \text{head}(F_1, K) = \text{head}(F_2, K)) \implies \Delta(F_1) = \Delta(F_2)
```

Total Non-Panicking Contract: The classifier terminates as a total function without panics or unhandled exceptions across all inputs:

```math
\forall F \in \mathcal{F}, \quad \text{Panic}(\Delta(F)) \equiv \text{false} \quad \wedge \quad \Delta(F) \in \mathcal{M}
```

Diagnostic Trigger Invariant: Classification of an unknown or malformed file triggers a structured diagnostic record within the ingestion taxonomy:

```math
\Delta(F) = \text{Unknown} \implies \mathcal{D}_{\text{emit}}(F) = \langle \text{E0100}, \text{path}(F), \text{span}(0, \min(|F|, K)) \rangle
```

where emitted diagnostics satisfy the ingestion diagnostic range defined in REQ-0191:

```math
\forall D \in \mathcal{D}_{\text{format}}, \quad \text{code}(D) \in \mathcal{E}_{\text{ingest}} = \{ e \in \mathcal{E} \mid 100 \le \text{code}(e) \le 199 \}
```

- **Computational Complexity & Algorithmic Bounds**: The format detection engine executes within Complexity Class $`\mathbf{P}`$`. Classification of an individual file executes in strict `$`O(K) = O(1)`$` constant time with respect to total file size `$`|F|`$`, since at most `$`K = 512`$` bytes are loaded into memory and inspected. File extension normalization and set membership lookups operate in `$`O(L_{\text{ext}}) = O(1)`$` time where `$`L_{\text{ext}} \le 16`$`. Content prefix scanning executes via single-pass exact byte comparison over the fixed window `$`[0, \min(|F|, K)]`$`, guaranteeing that every inspected byte is evaluated at most `$`O(1)`$` times with zero backtracking. For a multi-file compilation unit containing `$`M`$` schema files, aggregate sequential detection time is strictly bounded by `$`O(M \cdot K) = O(M)`$` linear time. When executing across a bounded work-stealing thread pool with `$`N_{\text{max\_workers}}`$` threads, parallel wall-clock execution time is bounded by `$`O(\lceil M / N_{\text{max\_workers}} \rceil \cdot K) = O(M / N_{\text{max\_workers}})`$`. Auxiliary memory consumption is strictly bounded by `$`O(K) = O(1)`$ constant space per worker thread for the fixed 512-byte inspection window, requiring zero heap allocations during format evaluation.

- **Verification & Conformance Criteria**: Automated test suites shall verify 100% precision and zero false positives across a canonical test corpus comprising all 5 supported schema formats: synthetic CommonMark tables containing component declarations (`Package_0`, `Classifier_Alpha`), Protocol Buffer definitions with `syntax` declarations, OMG IDL definitions with `module` blocks, OpenAPI specifications containing `openapi` or `swagger` keys, and XML Schema files containing XML declarations or schema root elements. Pathological test suites shall verify that empty 0-byte files, truncated files where $`|F| \lt K`$, binary data streams, invalid UTF-8 sequences, and adversarial random byte streams terminate cleanly without panics, classifying as `Unknown` and emitting structured diagnostic error code `E0100` with the file path and span coordinates. Static call graph audits and link-time checks shall assert that zero regular expression libraries or backtracking automata are referenced within the format detection module ($`\text{RegexEvaluations}(\Delta) = 0`$`). Multi-file parallel processing tests shall assert that classification completes under the bounded work-stealing thread pool with `$`N_{\text{max\_workers}}`$ workers with zero deadlocks and bitwise identical results. Latency compliance shall be evaluated exclusively in compiled Release mode (`--release`) under isolated benchmark harnesses, verifying that per-file detection latency does not exceed $`10\,\mu\text{s}`$` at the 99th percentile (`$`p_{99} \le 10\,\mu\text{s}`$), contributing negligibly to the overall 25 ms compiler execution budget.
