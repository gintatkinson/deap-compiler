### REQ-0139: FMECA Failure Mode Synthesis across 4 Universal Dimensions (Interface, State, Action, Resource)

- **Normative Statement**: The safety compiler, formal hazard analysis engine, and regulatory verification pipeline of Subsystem 7 shall automatically synthesize Failure Mode, Effects, and Criticality Analysis (FMECA) records across four universal failure dimensions--Interface, State, Action, and Resource--for every architectural component declared in the system AST.

  Specifically, the FMECA synthesis engine, failure propagator, and criticality classifier shall strictly enforce the following structural, dimensional, and operational invariants across all compilation units:
  1. **Architectural Component Element Decomposition**:
     - The safety compiler shall inspect every architectural component $C \in \mathcal{C}_{\text{arch}}$ (or component classifier, subsystem, part, or structural block) and extract its constituent structural and behavioral elements $\text{Elements}(C)$.
     - The extracted elements shall be partitioned into four mutually disjoint dimensional subsets:
       - $\text{Elements}_{\text{Interface}}(C)$: Directed ports, flow properties, connection endpoints, signal interfaces, and external message channels;
       - $\text{Elements}_{\text{State}}(C)$: Discrete operational states, composite statechart regions, operational modes, and lifecycle phases;
       - $\text{Elements}_{\text{Action}}(C)$: Action usages, behavioral invocations, computational transfer functions, and coordinated execution steps;
       - $\text{Elements}_{\text{Resource}}(C)$: Bounded physical and logical resources, allocated buffer storage, execution time budgets, memory pools, and energy reservoirs.
     - Element partition disjointness: $\forall d_i \ne d_j \in \{ \text{Interface}, \text{State}, \text{Action}, \text{Resource} \}$, $\text{Elements}_{d_i}(C) \cap \text{Elements}_{d_j}(C) = \emptyset$.
     - If an architectural component requiring safety verification declares zero elements across all four dimensions ($|\text{Elements}(C)| = 0$), the compiler shall reject the component declaration with diagnostic error code `E0400` (`EmptyComponentElements`).
  2. **Universal 4-Dimension Failure Kinds Alphabet**:
     - The safety compiler shall enforce an invariant catalog of failure kinds for each universal dimension:
       - For dimension $\text{Interface}$, the failure kind alphabet $\text{FailureKinds}(\text{Interface})$ shall comprise exactly 6 canonical failure modes:
         - $\text{Omission}$: Total loss or non-transmission of signal, data packet, or physical substance;
         - $\text{Commission}$: Babbling, unsolicited transmission, or transmission in an unauthorized operational phase;
         - $\text{ValueCorruption}$: Payload data corruption, out-of-range numerical value, or inverted mathematical sign;
         - $\text{EarlyArrival}$: Data or signal arrival prior to the earliest valid temporal envelope bound;
         - $\text{LateArrival}$: Data or signal arrival exceeding the maximum latency or deadline bound;
         - $\text{FrozenStream}$: Repeated or stalled constant payload transmission violating fresh data invariants.
       - For dimension $\text{State}$, the failure kind alphabet $\text{FailureKinds}(\text{State})$ shall comprise exactly 5 canonical failure modes:
         - $\text{StateTrapping}$: Component entrapped in an active state due to deadlock or unreachable outgoing transitions;
         - $\text{SpuriousTransition}$: Unintended state change triggered erroneously by noisy triggers or malformed guards;
         - $\text{OmittedTransition}$: Required state transition failing to execute despite satisfied trigger events and guards;
         - $\text{Desynchronization}$: Component operational state diverging from concurrent orthogonal state regions or system mode;
         - $\text{HookFailure}$: Lifecycle failure during entry action, exit action, or ongoing do-activity execution.
       - For dimension $\text{Action}$, the failure kind alphabet $\text{FailureKinds}(\text{Action})$ shall comprise exactly 5 canonical failure modes:
         - $\text{NonExecution}$: Behavioral action omitted or skipped entirely;
         - $\text{ErroneousComputation}$: Mathematical or algorithmic transfer function producing incorrect outputs;
         - $\text{PrematureTermination}$: Action execution terminated before postconditions or transfer goals are established;
         - $\text{SequenceReversal}$: Action executed out of order, violating causal control precedence;
         - $\text{InfiniteExecution}$: Behavioral step failing to terminate within allocated loop bounds or execution timeout.
       - For dimension $\text{Resource}$, the failure kind alphabet $\text{FailureKinds}(\text{Resource})$ shall comprise exactly 5 canonical failure modes:
         - $\text{Exhaustion}$: Allocated resource fully depleted or buffer capacity exceeded;
         - $\text{Starvation}$: Component denied required resource allocation due to scheduling lockouts;
         - $\text{Leakage}$: Monotonic un-reclaimed resource consumption across recurring execution cycles;
         - $\text{Contention}$: Circular wait deadlock or priority inversion across shared resource channels;
         - $\text{BoundaryViolation}$: Memory or parameter write exceeding allocated physical address boundaries.
     - The total failure kind universe shall remain strictly invariant with cardinality $K_{\text{kinds}} = 6 + 5 + 5 + 5 = 21$.
     - Any declaration of an unresolvable or malformed failure kind shall be rejected deterministically with diagnostic error code `E0400` (`InvalidFailureKind`).
  3. **Combinatorial Failure Mode Synthesis & Cartesian Space Formulation**:
     - For every component $C \in \mathcal{C}_{\text{arch}}$, the compiler shall synthesize the candidate failure mode space as the union of Cartesian products across the four universal dimensions:
       $$
       \mathcal{F}(C) = \bigcup_{d \in \{ \text{Interface}, \text{State}, \text{Action}, \text{Resource} \}} \left\{ (c, d, m) \;\middle|\; c \in \text{Elements}_d(C), \, m \in \text{FailureKinds}(d) \right\}
       $$
     - The total synthesized failure mode cardinality for component $C$ shall satisfy:
       $$
       |\mathcal{F}(C)| = \sum_{d \in \mathcal{D}_{\text{univ}}} \left( |\text{Elements}_d(C)| \cdot |\text{FailureKinds}(d)| \right) \le 21 \cdot |\text{Elements}(C)|
       $$
     - Across the entire system architecture, the universal failure mode catalog shall be formed as $\mathcal{F}_{\text{sys}} = \bigcup_{C \in \mathcal{C}_{\text{arch}}} \mathcal{F}(C)$.
  4. **FMECA Record Attribute Formulation & Propagation Analysis**:
     - For every synthesized failure mode tuple $(c, d, m) \in \mathcal{F}(C)$, the compiler shall construct a structured FMECA record node in contiguous bump arena storage comprising:
       - Unique handle $\text{id}_R \in \mathbb{N}_{32}$ and deterministic RFC 4122 UUIDv5 identifier $\Delta_R$;
       - References to owning component $C$, target element $c$, dimension $d$, and failure kind $m$;
       - Local Effect ($\mathcal{E}_{\text{local}}$): Formal expression detailing immediate state variable degradation or port output disruption within component $C$;
       - Next-Higher Effect ($\mathcal{E}_{\text{next}}$): Formal expression detailing propagated degradation across connected ports, interfaces, and adjacent components along interconnect graph edges;
       - End Effect ($\mathcal{E}_{\text{end}}$): Directed causal link to top-level system hazard scenarios $H \in \mathcal{H}$ established in STPA hazard analysis (REQ-0134, REQ-0135);
       - Detection Mechanism ($\mathcal{D}_{\text{mech}}$): Explicit reference to built-in tests, invariant assertion monitors, watchdog timers, or parity verifiers capable of detecting failure mode $(c, d, m)$;
       - Compensating Provision ($\mathcal{M}_{\text{prov}}$): Formal reference to failsafe transition handlers (REQ-0125), Run-Time Assurance (RTA) simplex/duplex fallbacks (REQ-0141), or redundant architectural channels.
     - Unmapped Propagation Check: If an element $c \in \text{Elements}_{\text{Interface}}(C)$ participates in an active connection but the next-higher effect $\mathcal{E}_{\text{next}}$ cannot be resolved across the interconnect topology, the compiler shall emit diagnostic error code `E0400` (`UnmappedFailurePropagation`).
     - Unmitigated Critical Failure Mode Check: If a failure mode induces a catastrophic or critical end effect ($\mathcal{E}_{\text{end}} \cap \mathcal{H}_{\text{critical}} \ne \emptyset$) while lacking both an automated detection mechanism and a compensating provision ($\mathcal{D}_{\text{mech}} = \bot \land \mathcal{M}_{\text{prov}} = \bot$), the compiler shall emit diagnostic error code `E0400` (`UnmitigatedCriticalFailureMode`).
  5. **Deterministic Ordering & Bitwise Parity Invariant**:
     - Synthesized FMECA records shall be sorted into a canonical deterministic sequence using the total order $\prec_{\text{fmeca}}$ governed by:
       1. Component fully qualified name lexicographical order ($\text{FQN}(C)$);
       2. Constituent element fully qualified name lexicographical order ($\text{FQN}(c)$);
       3. Dimensional index $\text{idx}(d) \in \{0, 1, 2, 3\}$;
       4. Failure kind index $\text{idx}(m) \in \{0, \dots, |\text{FailureKinds}(d)| - 1\}$.
     - Multi-threaded execution across varying worker thread pool counts shall produce 100% bitwise identical FMECA tables and artifact digests with zero diff churn.
  6. **Compliance with the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized failure mode record node $R_{(c,d,m)}$ shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the compound string $\text{FQN}(C) \,\|\, \text{"::"} \,\|\, \text{FQN}(c) \,\|\, \text{"::"} \,\|\, \text{String}(d) \,\|\, \text{"::"} \,\|\, \text{String}(m)$ in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel synthesis of FMECA records across multiple independent architectural components shall execute exclusively through a centralized, bounded work-stealing thread pool with worker ceiling $P_{\text{workers}} \le \min(C_{\text{logical}}, N_{\text{max\_workers}})$ in accordance with REQ-0012. Unbounded dynamic thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Failure kind names, component tokens, dimensional tags, and effect strings shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The safety compiler shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When semantic violations occur (`E0400`), diagnostics shall accumulate in the error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels ($\bot_{\text{fmeca}}$), and continue validating subsequent component declarations. If accumulated diagnostics reach capacity $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The FMECA synthesis engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($\lt 25\text{ ms}$ for $10^4$ synthesized failure modes) and peak RSS memory ($\lt 100\text{ MB}$) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Component_0`, `Component_1`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Port_2`, `Flow_A`, `Flow_B`, `State_0`, `State_1`, `Action_0`, `Action_1`, `Resource_0`, `Resource_1`, `Hazard_0`, `Hazard_1`, `Invariant_0`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes in contiguous bump arena storage.

  Let $\mathcal{C}_{\text{arch}} \subset \mathcal{V}_{\text{AST}}$ denote the set of architectural component nodes.

  The FMECA synthesis model is formalized as an 8-tuple:

  $$
  \mathcal{M}_{\text{FMECA}} = \langle \mathcal{C}_{\text{arch}}, \mathcal{D}_{\text{univ}}, \text{FailureKinds}, \text{Elements}, \mathcal{F}_{\text{sys}}, \text{PropagateEffects}, \prec_{\text{fmeca}}, P_{\text{workers}} \rangle
  $$

  where:

  $$
  \begin{aligned}
  \mathcal{C}_{\text{arch}} &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of architectural components}, \, |\mathcal{C}_{\text{arch}}| \ge 1) \\
  \mathcal{D}_{\text{univ}} &= \{ \text{Interface}, \text{State}, \text{Action}, \text{Resource} \} \quad (\text{universal 4-dimension failure universe}, \, |\mathcal{D}_{\text{univ}}| = 4) \\
  \text{FailureKinds} &: \mathcal{D}_{\text{univ}} \to \mathcal{P}(\mathcal{S}_{\text{intern}}) \quad (\text{canonical failure kind mapping}) \\
  \text{Elements} &: \mathcal{C}_{\text{arch}} \times \mathcal{D}_{\text{univ}} \to \mathcal{P}(\mathcal{V}_{\text{AST}}) \quad (\text{dimensional component element partition}) \\
  \mathcal{F}_{\text{sys}} &\subset \mathcal{V}_{\text{AST}} \quad (\text{synthesized universal FMECA record universe}) \\
  \text{PropagateEffects} &: \mathcal{F}_{\text{sys}} \to (\mathcal{V}_{\text{AST}} \times \mathcal{V}_{\text{AST}} \times \mathcal{P}(\mathcal{H})) \quad (\text{local, next-higher, and end effect mapping}) \\
  \prec_{\text{fmeca}} &\subset \mathcal{F}_{\text{sys}} \times \mathcal{F}_{\text{sys}} \quad (\text{canonical strict total ordering relation}) \\
  P_{\text{workers}} &\quad (\text{bounded work-stealing worker thread pool})
  \end{aligned}
  $$

  1. Universal Dimensional Failure Alphabet Invariant:

  $$
  \begin{aligned}
  \text{FailureKinds}(\text{Interface}) &= \{ \text{Omission}, \text{Commission}, \text{ValueCorruption}, \text{EarlyArrival}, \text{LateArrival}, \text{FrozenStream} \} \\
  \text{FailureKinds}(\text{State}) &= \{ \text{StateTrapping}, \text{SpuriousTransition}, \text{OmittedTransition}, \text{Desynchronization}, \text{HookFailure} \} \\
  \text{FailureKinds}(\text{Action}) &= \{ \text{NonExecution}, \text{ErroneousComputation}, \text{PrematureTermination}, \text{SequenceReversal}, \text{InfiniteExecution} \} \\
  \text{FailureKinds}(\text{Resource}) &= \{ \text{Exhaustion}, \text{Starvation}, \text{Leakage}, \text{Contention}, \text{BoundaryViolation} \}

  $$
  \begin{aligned}

  \end{aligned}
  $$

  2. Component Element Partitioning Invariant:
  For every architectural component $C \in \mathcal{C}_{\text{arch}}$, its constituent elements are partitioned into pairwise disjoint subsets:

  $$
  \text{Elements}(C) = \bigcup_{d \in \mathcal{D}_{\text{univ}}} \text{Elements}_d(C)
  $$

  satisfying:

  $$
  \forall d_i \ne d_j \in \mathcal{D}_{\text{univ}}, \quad \text{Elements}_{d_i}(C) \cap \text{Elements}_{d_j}(C) = \emptyset
  $$

  3. Combinatorial Cartesian Space Failure Mode Synthesis Invariant:
  For every component $C \in \mathcal{C}_{\text{arch}}$, the synthesized failure mode set $\mathcal{F}(C)$ satisfies:

  $$
  \mathcal{F}(C) = \bigcup_{d \in \mathcal{D}_{\text{univ}}} \left\{ (c, d, m) \;\middle|\; c \in \text{Elements}_d(C), \, m \in \text{FailureKinds}(d) \right\}
  $$

  The cardinality of the synthesized component failure mode space satisfies:

  $$
  |\mathcal{F}(C)| = \sum_{d \in \mathcal{D}_{\text{univ}}} \left( |\text{Elements}_d(C)| \cdot |\text{FailureKinds}(d)| \right)
  $$

  and is bounded above by:

  $$
  0 \le |\mathcal{F}(C)| \le 21 \cdot |\text{Elements}(C)|
  $$

  The universal system-wide failure mode catalog is the disjoint union:

  $$
  \mathcal{F}_{\text{sys}} = \biguplus_{C \in \mathcal{C}_{\text{arch}}} \mathcal{F}(C), \quad |\mathcal{F}_{\text{sys}}| = \sum_{C \in \mathcal{C}_{\text{arch}}} |\mathcal{F}(C)|
  $$

  4. FMECA Record Node Formalization:
  Each synthesized record $R \in \mathcal{F}_{\text{sys}}$ corresponding to tuple $(c, d, m)$ within component $C$ is formalized as an 11-tuple:

  $$
  R = \langle \text{id}_R, C, c, d, m, \mathcal{E}_{\text{local}}, \mathcal{E}_{\text{next}}, \mathcal{E}_{\text{end}}, \mathcal{D}_{\text{mech}}, \mathcal{M}_{\text{prov}}, \Delta_R \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_R &\in \mathbb{N}_{32} \quad (\text{contiguous arena record handle}) \\
  C &\in \mathcal{C}_{\text{arch}} \quad (\text{owning architectural component handle}) \\
  c &\in \text{Elements}_d(C) \quad (\text{target element handle}) \\
  d &\in \mathcal{D}_{\text{univ}} \quad (\text{universal failure dimension}) \\
  m &\in \text{FailureKinds}(d) \quad (\text{canonical failure kind identifier}) \\
  \mathcal{E}_{\text{local}} &\in \mathcal{V}_{\text{AST}} \quad (\text{local failure effect AST handle}) \\
  \mathcal{E}_{\text{next}} &\in \mathcal{V}_{\text{AST}} \quad (\text{propagated interface effect AST handle}) \\
  \mathcal{E}_{\text{end}} &\subseteq \mathcal{H} \quad (\text{associated system hazard cut-set}) \\
  \mathcal{D}_{\text{mech}} &\in \mathcal{V}_{\text{AST}} \cup \{ \bot \} \quad (\text{detection mechanism or monitor assertion}) \\
  \mathcal{M}_{\text{prov}} &\in \mathcal{V}_{\text{AST}} \cup \{ \bot \} \quad (\text{compensating safety provision or fallback}) \\

  \end{aligned}

  6. Canonical Deterministic Sorting & Bitwise Parity Invariant:
  Let $\text{idx}(d)$ denote the dimensional index mapping ($\text{idx}(\text{Interface}) = 0$, $\text{idx}(\text{State}) = 1$, $\text{idx}(\text{Action}) = 2$, $\text{idx}(\text{Resource}) = 3$).
  Let $\text{idx}(m)$ denote the 0-based index of failure kind $m$ within its respective alphabet $\text{FailureKinds}(d)$.
  The canonical strict total order $\prec_{\text{fmeca}}$ over records $R_1 = (C_1, c_1, d_1, m_1)$ and $R_2 = (C_2, c_2, d_2, m_2)$ is defined as:

  $$
  R_1 \prec_{\text{fmeca}} R_2 \iff \begin{cases}
  \text{FQN}(C_1) \lt_{\text{lex}} \text{FQN}(C_2) \\
  \text{FQN}(C_1) = \text{FQN}(C_2) \land \text{FQN}(c_1) \lt_{\text{lex}} \text{FQN}(c_2) \\
  \text{FQN}(C_1) = \text{FQN}(C_2) \land \text{FQN}(c_1) = \text{FQN}(c_2) \land \text{idx}(d_1) \lt \text{idx}(d_2) \\
  \text{FQN}(C_1) = \text{FQN}(C_2) \land \text{FQN}(c_1) = \text{FQN}(c_2) \land \text{idx}(d_1) = \text{idx}(d_2) \land \text{idx}(m_1) \lt \text{idx}(m_2)

In contrast, REQ-0139 inductively synthesizes the underlying failure modes and maps them to hazards via linear graph traversals without solving minimal hitting sets.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 addresses PSPACE-complete orthogonal state machine reachability. In contrast, REQ-0139 generates failure modes for discrete state elements using static syntactic inspection without state-space unrolling.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched piecewise conservative flow networks via linear complementarity solvers. In contrast, REQ-0139 inspects flow port interfaces statically to synthesize failure mode tuples.

  **Asymptotic Complexity Analysis**:
  Let $M = |\mathcal{C}_{\text{arch}}|$ denote the number of architectural components, let $N = \sum_{C \in \mathcal{C}_{\text{arch}}} |\text{Elements}(C)|$ denote the total number of architectural elements across all components, let $K_{\text{kinds}} = 21$ denote the fixed universal failure kinds constant, and let $E_{\text{conn}}$ denote the number of structural interconnect edges between component ports.
  1. *Cartesian Failure Mode Space Expansion*:
     Iterating through the partitioned elements of each component $C$ and pairing each element $c \in \text{Elements}_d(C)$ with its corresponding failure kinds $m \in \text{FailureKinds}(d)$ requires:
     $$
     T_{\text{expand}}(N) = \sum_{C \in \mathcal{C}_{\text{arch}}} \sum_{d \in \mathcal{D}_{\text{univ}}} |\text{Elements}_d(C)| \cdot |\text{FailureKinds}(d)| \le 21 \cdot N \in O(N)
     $$
  2. *Local Effect & Detection Binding*:
     Binding local effect expressions $\mathcal{E}_{\text{local}}$ and detection mechanisms $\mathcal{D}_{\text{mech}}$ from component internal contracts and invariant tables takes $O(1)$ constant time per synthesized failure mode:
     $$
     T_{\text{local}}(N) \in O(N)
     $$
  3. *Next-Higher & End Effect Propagation Analysis*:
     Propagating interface failure modes across structural interconnect edges requires traversing topologically adjacent components. For each connected interface element, single-hop propagation executes in $O(1)$ time per connection, requiring:
     $$
     T_{\text{propagate}}(N, E_{\text{conn}}) \in O(N + E_{\text{conn}})
     $$
     End effect mapping to pre-computed hazard scenarios $\mathcal{H}$ executes via hash-indexed hazard lookup tables in $O(1)$ time per failure mode.
  4. *Canonical Deterministic Sorting*:
     Sorting the total synthesized failure mode set $\mathcal{F}_{\text{sys}}$ of cardinality $|\mathcal{F}_{\text{sys}}| \le 21 \cdot N$ under the canonical strict total order $\prec_{\text{fmeca}}$ requires:
     $$
     T_{\text{sort}}(N) \in O(|\mathcal{F}_{\text{sys}}| \log |\mathcal{F}_{\text{sys}}|) \subseteq O(N \log N)
     $$
  5. *Aggregate Sequential Time Complexity*:
     Summing expansion, effect propagation, and canonical sorting:
     $$
     T_{\text{total}}(N, E_{\text{conn}}) \in O(N \log N + E_{\text{conn}})
     $$
     The algorithm operates deterministically without backtracking or recursion stack growth.
  6. *Bounded Work-Stealing Parallel Speedup (Directive 2)*:
     When synthesizing FMECA records across $M$ components using $P = \min(C_{\text{logical}}, N_{\text{max\_workers}})$ worker threads on a bounded work-stealing thread pool:
     $$
     T_P(N, E_{\text{conn}}, P) \le \frac{T_1}{P} + O(T_\infty) \in O\left( \frac{N \log N + E_{\text{conn}}}{P} + \log N \right)
     $$
     where critical-path span $T_\infty \in O(\log N)$ bounds task deque decomposition, work-stealing attempts, and parallel reduction.
