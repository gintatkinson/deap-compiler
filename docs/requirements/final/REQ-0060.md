# REQ-0060: KerML Core Features: Feature, Parameter, Step & FeatureTyping Semantics

## 1. Normative Statement

The semantic lowering engine and AST graph engine shall formalize properties, behavioral invocations, structural slots, directional parameters, and execution steps as instances of the unified `Feature` abstract syntax metaclass. In the KerML metamodel lowering pipeline, `Feature` shall specialize both `Type` and `Relationship`, unifying structural value projection, behavioral invocation, and relational typing. Every `Feature` must bind to declared classifier types via formal `FeatureTyping` relationships ($`\tau`$). The compiler shall prohibit un-typed features whose types cannot be resolved within lexical scope, emitting diagnostic error code `E0200`.

A feature $`f`$ owned by classifier definition $`C`$ shall induce an evaluation projection mapping $`\pi_f : \llbracket C \rrbracket \longrightarrow \mathcal{P}(\llbracket \tau(f) \rrbracket)`$, mapping each instance of $`C`$ to a finite subset of values in $`\llbracket \tau(f) \rrbracket`$. Every feature must declare a multiplicity interval $`\mu(f) = [m_{\min}, m_{\max}]`$ ($`m_{\min} \in \mathbb{N}_{0}`$, $`m_{\max} \in \mathbb{N}_{0} \cup \{ \infty \}`$, $`m_{\min} \le m_{\max}`$) constraining instance fiber cardinality: $`\forall x \in \llbracket C \rrbracket, \; m_{\min} \le |\pi_f(x)| \le m_{\max}`$. Inverted intervals ($`m_{\min} \gt m_{\max}`$) or instance fiber violations shall emit diagnostic error code `E0200`.

The metamodel shall provide `Parameter` as a specialized `Feature` declaring directionality $`\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}`$. `In` parameters accept inputs and remain immutable within the behavior body; `Out` parameters yield outputs assigned before termination; `InOut` parameters permit bidirectional transfer. Passing unassignable values to `Out`/`InOut` parameters or writing to `In` parameters shall emit diagnostic error code `E0201`.

The metamodel shall provide `Step` as a specialized `Feature` representing contextual execution typed by a classifier specializing `Behavior` ($`\tau(s) \le \text{Behavior}`$). Typing a `Step` with a non-behavioral classifier shall emit diagnostic error code `E0200`. Steps project parameter interfaces of their typing behavior as child features.

Feature, parameter, step, and typing nodes shall be allocated in contiguous arena storage addressed via 32-bit handles, with identifiers interned in the global symbol pool. In accordance with Directive 4, the engine shall implement synchronization token error recovery on faults (`E0200`, `E0201`), recording diagnostics with source byte spans, binding sentinel $`\bot_{\text{type}}`$, and continuing analysis. Reaching error capacity limit $`C_{\text{max\_errors}}`$ emits `E0199` and halts execution. All models, diagnostics, and test fixtures shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Behavior_Alpha`, `Feature_A`, `Step_Alpha`, `Param_In`, `Param_Out`, `param_x : Real`).

## 2. Formal Invariant

Let $`\mathcal{V}_{\text{feat}}`$ denote the universe of lowered feature nodes in the AST arena, and $`\mathcal{C}`$ denote the set of classifier definitions. Every feature node $`f \in \mathcal{V}_{\text{feat}}`$ is formalized as:

```math
f = \langle \text{id}_f, \text{name}_f, \text{owner}_f, \tau(f), \mu(f), \text{dir}(f), \kappa_f \rangle
```

where $`\text{id}_f \in \mathbb{N}_{32}`$, $`\text{name}_f \in \mathcal{S}_{\text{intern}}`$, $`\text{owner}_f \in \mathcal{C} \cup \mathcal{V}_{\text{feat}}`$, $`\tau(f) \subseteq \mathcal{C} \setminus \{ \emptyset \}`$, $`\mu(f) = [m_{\min}(f), m_{\max}(f)] \subseteq \mathbb{N}_{0} \times (\mathbb{N}_{0} \cup \{ \infty \})`$, $`\text{dir}(f) \in \{ \text{In}, \text{Out}, \text{InOut}, \bot_{\text{dir}} \}`$, and $`\kappa_f \in \{ \text{Structural}, \text{Parameter}, \text{Step} \}`$.

Feature evaluation projection:

```math
\pi_f : \llbracket C \rrbracket \longrightarrow \mathcal{P}(\llbracket \tau(f) \rrbracket)
```

Multiplicity interval and fiber cardinality invariants:

```math
\begin{aligned}
\Phi_{\text{mult}}(f) &\iff (m_{\min}(f) \le m_{\max}(f)) \wedge (m_{\max}(f) \ge 1 \vee m_{\max}(f) = 0) \\
\Phi_{\text{fiber}}(f) &\iff \forall x \in \llbracket C \rrbracket, \quad m_{\min}(f) \le |\pi_f(x)| \le m_{\max}(f)
\end{aligned}
```

Multi-type intersection and step behavioral typing invariants:

```math
\begin{aligned}
\llbracket \tau(f) \rrbracket &= \bigcap_{T \in \tau(f)} \llbracket T \rrbracket, \quad \forall x \in \llbracket C \rrbracket, \; \pi_f(x) \subseteq \llbracket \tau(f) \rrbracket \\
\kappa_f = \text{Step} &\implies \exists T \in \tau(f) : T \le \text{Behavior} \wedge T \ne \bot_{\text{type}}
\end{aligned}
```

Parameter invocation binding validity:

```math
\text{ValidBinding}(a, p) \iff \begin{cases}
(\tau(a) \le \tau(p)) \wedge \text{IsReadable}(a), & \text{dir}(p) = \text{In} \\
(\tau(p) \le \tau(a)) \wedge \text{IsAssignable}(a), & \text{dir}(p) = \text{Out} \\
(\tau(a) \equiv \tau(p)) \wedge \text{IsReadable}(a) \wedge \text{IsAssignable}(a), & \text{dir}(p) = \text{InOut}
\end{cases}
```

Diagnostic mapping invariant:

```math
\begin{aligned}
(\tau(f) = \emptyset \vee \bot_{\text{type}} \in \tau(f) \vee \neg \Phi_{\text{mult}}(f)) &\implies \text{Diagnostic}(f, \text{E0200}) \\
(\kappa_f = \text{Step} \wedge \forall T \in \tau(f), \, T \not\le \text{Behavior}) &\implies \text{Diagnostic}(f, \text{E0200}) \\
(\kappa_f = \text{Parameter} \wedge \neg \text{ValidBinding}(a, f)) &\implies \text{Diagnostic}(f, \text{E0201})
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The feature, parameter, step, and typing lowering pass operates within Complexity Class $`\mathbf{P}`$. Bump arena allocation and symbol interning execute in amortized $`O(1)`$ time and $`O(1)`$ space. Multiplicity checks, fiber cardinality evaluation, and parameter direction validation require strictly $`O(1)`$ scalar operations. For an AST with $`N_{\text{feat}}`$ features and typing hierarchy depth $`h \le 32 = O(1)`$, total verification time is $`O(N_{\text{feat}})`$ with $`O(1)`$ auxiliary memory. While general multiple-inheritance subtyping posets can induce NP-complete verification (NP-3), single-step FeatureTyping conformance queries execute over precomputed monotonic lattices in deterministic $`O(1)`$ time per feature.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: FeatureTyping Binding & Value Projection Resolution

- **Given:** `Classifier_Alpha` declaring `Feature_A` typed by `Classifier_Beta` via `FeatureTyping`.
- **When:** Lowering executes feature type resolution.
- **Then:** `Feature_A` binds to `Classifier_Beta` with node handle resolution, valid projection mapping $`\pi_{\text{Feature\_A}}`$, zero diagnostics emitted, and total-function completion.
- **Diagnostic:** `E0200` emitted on unresolved feature type.

### AC-02: Multiplicity Interval Bounds Validation

- **Given:** AST feature declarations with valid intervals `[0..1]`, `[1..*]` and malformed interval `[5..2]` ($`m_{\min} \gt m_{\max}`$).
- **When:** Multiplicity well-formedness $`\Phi_{\text{mult}}`$ is evaluated.
- **Then:** Valid intervals are accepted; malformed interval `[5..2]` is rejected and sentinel $`\bot_{\text{type}}`$ is assigned.
- **Diagnostic:** `E0200` emitted on $`m_{\min} \gt m_{\max}`$.

### AC-03: Fiber Cardinality Enforcement

- **Given:** `Classifier_Alpha` instance possessing `Feature_A` with multiplicity `[1, 3]` and evaluated instance fiber cardinality 0 or 4.
- **When:** The type verification engine validates fiber cardinality against $`\mu(\text{Feature\_A})`$.
- **Then:** Cardinality violations outside $`[m_{\min}, m_{\max}]`$ are detected and rejected.
- **Diagnostic:** `E0200` emitted on fiber cardinality violation.

### AC-04: Parameter Directionality & Invocation Binding

- **Given:** `Behavior_Alpha` defining parameters `Param_In` ($`\text{dir} = \text{In}`$) and `Param_Out` ($`\text{dir} = \text{Out}`$).
- **When:** An invocation passes an immutable constant expression to `Param_Out` or attempts to write to `Param_In`.
- **Then:** Parameter direction mismatch is detected and invocation binding is rejected.
- **Diagnostic:** `E0201` emitted for invalid parameter flow or mutability mismatch.

### AC-05: Step Behavioral Classifier Typing Gate

- **Given:** `Step_Alpha` typed by `Behavior_Beta` and `Step_Beta` typed by non-behavioral `Classifier_Alpha`.
- **When:** Lowering validates step typing conformance ($`\tau(s) \le \text{Behavior}`$).
- **Then:** `Step_Alpha` is accepted and inherits the parameter interface of `Behavior_Beta`; `Step_Beta` is rejected.
- **Diagnostic:** `E0200` emitted on non-behavioral step type.

### AC-06: Synchronization Token Error Recovery & Sink Bound

- **Given:** A compilation unit containing 8 feature declarations with 3 intentional typing faults.
- **When:** The lowering pass processes the input unit with error capacity $`C_{\text{max\_errors}} = 50`$.
- **Then:** The compiler records all 3 diagnostics (`E0200`, `E0201`), substitutes $`\bot_{\text{type}}`$ without panicking, and completes verification; reaching $`C_{\text{max\_errors}}`$ emits `E0199` and terminates.
- **Diagnostic:** `E0199` emitted when accumulated diagnostic count reaches $`C_{\text{max\_errors}}`$.
