### REQ-0060: KerML Core Features: Feature, Parameter, Step & FeatureTyping Semantics

- **Normative Statement**: The Core Metamodel, Node Arena & AST Graph Engine shall model all properties, behavioral invocations, structural slots, directional parameters, and execution steps as instances of the unified `Feature` abstract syntax metaclass. In the KerML metamodel lowering pipeline, `Feature` shall specialize both `Type` and `Relationship`, unifying structural value projection, behavioral invocation, and relational typing under a common formal foundation. Every `Feature` must bind to one or more declared classifier types via formal `FeatureTyping` relationships ($\tau$). An un-typed feature whose type cannot be resolved within the lexical scope table shall be strictly prohibited at compile time, deterministically emitting diagnostic error code `E0200` in accordance with the standardized diagnostic taxonomy of REQ-0191.

  A feature $f$ owned by an enclosing classifier definition $C$ shall induce an evaluation projection mapping $\pi_f : \llbracket C \rrbracket \longrightarrow \mathcal{P}(\llbracket \tau(f) \rrbracket)$, mapping each instance of the featuring classifier $C$ to a finite set of values within the semantic denotation of its declared type $\tau(f)$. Every feature must specify an explicit or defaulted multiplicity interval $\mu(f) = [m_{\min}, m_{\max}]$ where $m_{\min} \in \mathbb{N}_{0}$ and $m_{\max} \in \mathbb{N}_{0} \cup \{ \infty \}$, subject to the structural well-formedness invariant $m_{\min} \le m_{\max}$. The type checking engine shall enforce fiber cardinality constraints: for every instance $x \in \llbracket C \rrbracket$, the cardinality of the evaluated feature value set $|\pi_f(x)|$ must satisfy $m_{\min} \le |\pi_f(x)| \le m_{\max}$. Any malformed multiplicity interval where $m_{\min} \gt m_{\max}$ or where an instance value set violates $[m_{\min}, m_{\max}]$ shall deterministically emit diagnostic error code `E0200`.

  The metamodel shall provide `Parameter` as a specialized `Feature` owned by a `Function`, `Behavior`, or `Step`. Every parameter $p$ must declare an immutable directionality tag $\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}$. The type checking engine shall enforce directional information flow invariants across behavioral invocation boundaries:
  1. An `In` parameter shall accept values flowing strictly into the behavior execution from the calling scope and shall remain immutable within the behavior body.
  2. An `Out` parameter shall yield values flowing strictly out of the behavior execution to the calling scope and must be assigned prior to behavior termination.
  3. An `InOut` parameter shall permit bidirectional flow, requiring an initialized argument value upon invocation and returning an updated value upon termination.
  Any violation of parameter directionality -- including passing an immutable value or literal to an `Out` or `InOut` parameter, or binding an `In` parameter to an output sink -- shall deterministically emit diagnostic error code `E0201`.

  The metamodel shall provide `Step` as a specialized `Feature` representing the contextual execution or performance of a nested behavior within an enclosing behavioral scope. Every step $s$ must be typed by an authoritative `Behavior` or `Interaction` classifier definition via a `FeatureTyping` relation ($\tau(s) \le \text{Behavior}$). Attempting to type a `Step` with a non-behavioral classifier definition shall deterministically emit diagnostic error code `E0200`. The input and output parameters of the typing behavior shall be projected as sub-features of the step, inheriting parameter types, multiplicities, and directionalities.

  All feature, parameter, step, and feature typing nodes shall be stored sequentially in contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, addressed via stable 32-bit relative node handles per REQ-0035. In accordance with Architectural Directive 1 and REQ-0010, every lowered feature node must receive a deterministic RFC 4122 UUIDv5 identifier computed by hashing the namespace OID and the fully qualified symbol path. In accordance with Architectural Directive 3 and REQ-0036, scalar symbol identifiers for feature names, parameter names, and step names shall be interned into the global symbol interner pool. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the type checking engine shall implement synchronization token error recovery: upon encountering a type resolution failure (`E0200`), malformed multiplicity (`E0200`), or directional incompatibility (`E0201`), the engine shall record a structured diagnostic record containing the exact source byte span, substitute an error sentinel $\bot_{\text{type}}$, and continue verifying subsequent features without aborting compilation. If accumulated diagnostics reach the sink capacity limit $C_{\text{max\_errors}}$, the compiler shall emit diagnostic error code `E0199` and terminate gracefully. Parallel feature typing validation across independent compilation units shall be scheduled strictly onto a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with Architectural Directive 2 and REQ-0012. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the type checking engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs, evaluating performance gates (< 25 ms latency, < 100 MB RSS) exclusively in compiled Release mode (`--release`). All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Behavior_Alpha`, `Feature_A`, `Feature_B`, `Step_Alpha`, `Param_In`, `Param_Out`, `param_x : Real`) with zero domain contamination.

- **Formal Invariant**: Let $\mathcal{V}_{\text{feat}}$ denote the universe of lowered feature nodes within the AST arena, and let $\mathcal{C}$ denote the set of lowered classifier definitions. Every feature node $f \in \mathcal{V}_{\text{feat}}$ is formalized as a 9-tuple:

$$
f = \langle \text{id}_f, \text{name}_f, \text{owner}_f, \tau(f), \mu(f), \text{dir}(f), \kappa_f, \Delta_f, \text{span}_f \rangle
$$

where:

$$
\begin{aligned}
\text{id}_f &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_f &\in \mathcal{S}_{\text{intern}} \quad (\text{interned scalar symbol identifier}) \\
\text{owner}_f &\in \mathcal{C} \cup \mathcal{V}_{\text{feat}} \quad (\text{featuring classifier or enclosing step/behavior}) \\
\tau(f) &\subseteq \mathcal{C} \setminus \{ \emptyset \} \quad (\text{authoritative classifier types bound via FeatureTyping}) \\
\mu(f) &= [m_{\min}(f), m_{\max}(f)] \subseteq \mathbb{N}_{0} \times (\mathbb{N}_{0} \cup \{ \infty \}) \quad (\text{declared multiplicity interval}) \\
\text{dir}(f) &\in \{ \text{In}, \text{Out}, \text{InOut}, \bot_{\text{dir}} \} \quad (\text{parameter directionality tag}) \\
\kappa_f &\in \{ \text{FeatureKind::Structural}, \text{FeatureKind::Parameter}, \text{FeatureKind::Step} \} \quad (\text{discriminant kind}) \\
\Delta_f &\in \Sigma^* \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_f &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

Let $\llbracket C \rrbracket$ denote the semantic value universe of instances of classifier $C \in \mathcal{C}$, and let $\llbracket T \rrbracket$ denote the semantic denotation of type $T \in \mathcal{C}$. A feature $f$ featuring classifier $C$ induces an evaluation projection mapping:

$$
\pi_f : \llbracket C \rrbracket \longrightarrow \mathcal{P}(\llbracket \tau(f) \rrbracket)
$$

Multiplicity Interval Well-Formedness Invariant: The lower and upper multiplicity bounds must form a valid closed interval:

$$
\Phi_{\text{mult\_valid}}(f) \iff (m_{\min}(f) \le m_{\max}(f)) \wedge (m_{\max}(f) \ge 1 \vee m_{\max}(f) = 0)
$$

Fiber Cardinality Invariant: For every instance $x \in \llbracket C \rrbracket$, the fiber cardinality of the evaluation projection is constrained by the multiplicity interval:

$$
\forall x \in \llbracket C \rrbracket, \quad m_{\min}(f) \le |\pi_f(x)| \le m_{\max}(f)
$$

Value Typing Conformance Invariant: Every projected value within the fiber must belong to the semantic denotation of each bound classifier type in $\tau(f)$:

$$
\forall x \in \llbracket C \rrbracket, \quad \forall v \in \pi_f(x), \quad \forall T \in \tau(f), \quad v \in \llbracket T \rrbracket
$$

When a feature declares multiple types $\tau(f) = \{ T_1, T_2, \dots, T_k \}$, the effective semantic denotation corresponds to the intersection of the component types:

$$
\llbracket \tau(f) \rrbracket = \bigcap_{i=1}^k \llbracket T_i \rrbracket
$$

Parameter Directionality & Invocation Binding Invariant: For any parameter $p \in \mathcal{V}_{\text{feat}}$ with $\kappa_p = \text{FeatureKind::Parameter}$, the directionality is strictly non-null ($\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}$). For any behavioral invocation binding an argument expression $a$ to parameter $p$, directional validity $\text{ValidParamBinding}(a, p)$ satisfies:

$$
\text{ValidParamBinding}(a, p) \iff \begin{cases}
(\tau(a) \le \tau(p)) \wedge \text{IsReadable}(a), & \text{if } \text{dir}(p) = \text{In} \\
(\tau(p) \le \tau(a)) \wedge \text{IsAssignable}(a), & \text{if } \text{dir}(p) = \text{Out} \\
(\tau(a) \equiv \tau(p)) \wedge \text{IsReadable}(a) \wedge \text{IsAssignable}(a), & \text{if } \text{dir}(p) = \text{InOut}
\end{cases}
$$

Step Behavioral Classifier Invariant: For any step $s \in \mathcal{V}_{\text{feat}}$ with $\kappa_s = \text{FeatureKind::Step}$, the bound type $\tau(s)$ must specialize the standard metamodel `Behavior` classifier:

$$
\Phi_{\text{step\_valid}}(s) \iff \exists T \in \tau(s) : T \le \text{Behavior} \wedge T \ne \bot_{\text{type}}
$$

Deterministic UUIDv5 & Handle Identity Invariant: Every lowered feature node receives a deterministic RFC 4122 UUIDv5 identifier and a stable arena handle:

$$
\begin{aligned}
\forall f \in \mathcal{V}_{\text{feat}}, \quad \Delta_f &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(f)) \\
\forall f \in \mathcal{V}_{\text{feat}}, \quad \text{Handle}(f) &= \langle \text{ArenaId}, \text{Offset}_f \rangle
\end{aligned}
$$

Diagnostic Code Trigger Invariants: Violations of feature typing, multiplicity well-formedness, step behavioral typing, or parameter directionality deterministically trigger diagnostic error codes per REQ-0191:

$$
\begin{aligned}
(\tau(f) = \emptyset \vee \bot_{\text{type}} \in \tau(f)) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0200}, \text{UnresolvedFeatureType}) \in \mathcal{D}_{\text{sink}} \\
\neg \Phi_{\text{mult\_valid}}(f) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0200}, \text{InvalidMultiplicityBounds}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_f = \text{FeatureKind::Step} \wedge \neg \Phi_{\text{step\_valid}}(f)) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0200}, \text{InvalidStepClassifierType}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_f = \text{FeatureKind::Parameter} \wedge \neg \text{ValidParamBinding}(a, f)) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0201}, \text{ParameterDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Feature, parameter, step, and feature typing lowering and validation execute strictly within Complexity Class $\mathbf{P}$. The algorithmic bounds across operations are formalized as follows:
  1. Feature Allocation & Handle Resolution: Lowering each feature into contiguous bump arena storage and interning its scalar symbol name requires amortized $O(1)$ time and $O(1)$ auxiliary space.
  2. Multiplicity Interval Verification: Validating $m_{\min}(f) \le m_{\max}(f)$ and instance cardinality inclusion $m_{\min}(f) \le |\pi_f(x)| \le m_{\max}(f)$ requires strictly $O(1)$ scalar integer comparisons.
  3. FeatureTyping Subtyping Queries: For each feature with at most $k_{\text{type}}$ bound types ($k_{\text{type}} \le 4 = O(1)$), validating type conformance against target classifiers executes in $O(1)$ time using precomputed topological reachability bitsets or bounded tree-climbing where inheritance depth $h \le 32 = O(1)$.
  4. Step Behavioral Typing Verification: Verifying that a step's classifier specializes `Behavior` executes a single reachability bitset test in deterministic $O(1)$ time.
  5. Parameter Direction & Flow Verification: Evaluating $\text{ValidParamBinding}(a, p)$ tests a 2-bit direction enum discriminant and an assignability bitfield in deterministic $O(1)$ time.
  6. Aggregate Metamodel Verification Bounds: For an AST graph containing $N_{\text{feat}} = |\mathcal{V}_{\text{feat}}|$ features, parameters, and steps across $N_{\text{class}} = |\mathcal{C}|$ classifiers:

$$
T(N_{\text{feat}}, N_{\text{class}}) = \sum_{f \in \mathcal{V}_{\text{feat}}} O(1 + k_{\text{type}} \cdot h) = O(N_{\text{feat}})
$$

  7. Parallel Verification Bounds: Under bounded work-stealing multithreading scheduled across $N_{\text{max\_workers}}$ worker threads:

$$
T_{\text{parallel}}(N_{\text{feat}}) \in O\left(\frac{N_{\text{feat}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}}\right)
$$

  8. Space Complexity: Auxiliary heap allocation is strictly bounded by $O(1)$ beyond contiguous bump arena storage for AST nodes and the diagnostic sink buffer $O(C_{\text{max\_errors}})$, ensuring zero heap reallocation churn during the type validation pass.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (e.g., `Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Behavior_Alpha`, `Feature_A`, `Feature_B`, `Step_Alpha`, `Param_In`, `Param_Out`, `Param_InOut`, `param_x : Real`) across the following verification gates:
  1. FeatureTyping Binding & Resolution Gate: Ingest a model containing `Classifier_Alpha` owning `Feature_A` typed by `Classifier_Beta` via `FeatureTyping`; assert 100% resolution to contiguous arena node handles, valid projection mapping, and zero diagnostics emitted.
  2. Multiplicity Interval Well-Formedness Gate: Ingest feature declarations with valid multiplicity intervals `[0..1]`, `[1..1]`, `[0..*]`, and `[2..5]`; assert successful validation with zero diagnostics; ingest malformed intervals `[5..2]` ($m_{\min} \gt m_{\max}$) and `[-1..3]`; assert deterministic rejection with diagnostic error code `E0200` (`InvalidMultiplicityBounds`).
  3. Fiber Cardinality Verification Gate: Instantiate `Classifier_Alpha` with feature `Feature_A` declaring multiplicity `[1..3]`; evaluate an instance fiber with cardinality 0 (violating $m_{\min}$) and cardinality 4 (violating $m_{\max}$); assert deterministic emission of diagnostic error code `E0200`.
  4. Parameter Directionality & Flow Boundary Gate: Ingest `Behavior_Alpha` declaring parameters `Param_In` (`in`), `Param_Out` (`out`), and `Param_InOut` (`inout`); verify that passing an immutable literal expression to `Param_In` succeeds with zero diagnostics; attempt to pass an immutable literal or unassignable expression to `Param_Out` or `Param_InOut`; assert deterministic emission of diagnostic error code `E0201` (`ParameterDirectionMismatch`).
  5. Step Behavioral Typing Gate: Ingest a model containing `Step_Alpha` typed by `Behavior_Alpha`; assert that `Step_Alpha` inherits the parameter interface of `Behavior_Alpha` with zero diagnostics; attempt to type `Step_Beta` with non-behavioral `Classifier_Alpha`; assert deterministic emission of diagnostic error code `E0200` (`InvalidStepClassifierType`).
  6. Multiple FeatureTyping Type Intersection Gate: Ingest `Feature_A` declaring multiple `FeatureTyping` bindings to `Classifier_Alpha` and `Classifier_Beta`; verify that instances assigned to `Feature_A` must conform to both classifiers, and assert that an instance conforming to only `Classifier_Alpha` is rejected with diagnostic error code `E0200`.
  7. Synchronization Token Recovery & Diagnostic Accumulation Gate: Ingest an AST model containing 10 feature declarations with 4 intentional typing and multiplicity faults; assert that the compiler records all 4 structured diagnostics (`E0200` and `E0201`), substitutes the error sentinel $\bot_{\text{type}}$, and completes verification across all remaining features without panicking; inject malformed features exceeding $C_{\text{max\_errors}}$ and assert graceful termination with diagnostic error code `E0199`.
  8. Deterministic UUIDv5 Topological Identity Gate: Verify that every lowered feature, parameter, and step receives an immutable RFC 4122 UUIDv5 identifier computed from its topological namespace path, asserting bitwise identical UUIDs and 0-byte diff churn across repeated compilation runs.
  9. Directive 5 Performance & Memory Gate: In compiled Release mode (`--release`), benchmark verification across an AST containing $10^5$ synthetic features, parameters, and steps; assert total execution latency strictly under 25 ms and peak RSS memory strictly under 100 MB per REQ-0011 and REQ-0196.
