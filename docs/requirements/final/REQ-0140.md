### REQ-0140: Quantitative Risk Priority Number (RPN) Integer Scoring Engine ($`RPN = S \times O \times D`$)

#### 1. Normative Statement

The safety compiler, formal hazard analysis engine, and quantitative risk evaluation pipeline of Subsystem 7 shall compute deterministic Risk Priority Numbers (RPN) for all declared and synthesized failure modes across architectural classifiers and components by calculating exact positive integer scores from Severity ($`S`$`), Occurrence (`$`O`$`), and Detection (`$`D`$) rating attributes, classifying criticality states against configurable dual-threshold safety criteria, enforcing certified mitigation obligations for all critical failure modes, and establishing a canonical deterministic Pareto risk ordering across all compilation units.

  Specifically, the quantitative safety evaluation engine, rating validator, and risk prioritization pipeline shall strictly enforce the following structural, algebraic, and operational invariants:
  1. **Failure Mode Universe Ingestion & Attribute Binding**:
     - The compiler shall ingest the failure mode universe $`\mathcal{F} = \{ f_1, f_2, \dots, f_N \}`$ synthesized across the four universal dimensions of Interface, State, Action, and Resource (REQ-0139) or declared directly on structural elements and behavioral state machines in the abstract syntax tree (AST).
     - Each failure mode $`f \in \mathcal{F}`$` shall bind an owning architectural element handle, an interned symbol identifier, three positive integer rating attributes `$`\langle S(f), O(f), D(f) \rangle`$`, an associated candidate mitigation constraint set `$`\mathbf{C}_{\text{mitig}}(f) \subseteq \mathcal{V}_{\text{AST}}`$, an immutable deterministic RFC 4122 UUIDv5 identifier, and lexical source provenance coordinates.
     - If the compilation unit specifies formal safety evaluation but the failure mode universe is completely empty ($`|\mathcal{F}| = 0`$), the compiler shall complete validation vacuously with zero diagnostics emitted.
  2. **Integer Rating Domain Invariants & Validation**:
     - The Severity rating $`S(f) \in \mathbb{Z}^+`$` measures the worst-case potential consequence of the failure mode on system safety and functional objectives, constrained to the discrete closed integer interval `$`[1, 10]`$.
     - The Occurrence rating $`O(f) \in \mathbb{Z}^+`$` measures the likelihood or estimated frequency of failure manifestation, constrained to the discrete closed integer interval `$`[1, 10]`$.
     - The Detection rating $`D(f) \in \mathbb{Z}^+`$` measures the inverse probability that existing architectural monitors, runtime assertions, or verification witnesses will fail to detect or contain the failure condition before hazardous effect realization, constrained to the discrete closed integer interval `$`[1, 10]`$` (where `$`1`$` denotes virtually certain detection and `$`10`$ denotes absolute non-detectability).
     - Strict Integer Typestate: All rating attributes must evaluate to positive integers. Any floating-point, rational fractional, non-numerical, or out-of-range value ($`v \lt 1`$` or `$`v \gt 10`$) shall be deterministically rejected at compile time with diagnostic error code `E0400` (`RatingDomainViolation`).
     - Completeness of Rating Triples: Every failure mode $`f \in \mathcal{F}`$` must declare all three rating dimensions `$`\langle S(f), O(f), D(f) \rangle`$`. If any single rating attribute is omitted, unassigned, or unresolved, the compiler shall halt evaluation of `$`f`$ and emit diagnostic error code `E0400` (`MissingFailureModeRating`).
     - Contradictory Declarations: If a compilation unit specifies conflicting or duplicate rating values for the same failure mode $`f`$, the compiler shall deterministically reject the declaration with diagnostic error code `E0400` (`ContradictoryRatingDeclaration`).
  3. **Multiplicative Integer Scoring Engine ($`RPN = S \times O \times D`$)**:
     - The compiler shall evaluate the quantitative Risk Priority Number $`RPN(f)`$ as the exact multiplicative product:

```math
RPN(f) = S(f) \times O(f) \times D(f)
```

     - The RPN value shall be represented as an exact unsigned integer residing strictly in the closed integer interval $`[1, 1000]`$.
     - All calculations shall execute using exact integer arithmetic without truncation, floating-point rounding errors, or numerical drift.
     - The engine shall verify the boundary limits: the absolute theoretical minimum is $`\min RPN = 1 \times 1 \times 1 = 1`$`, and the absolute theoretical maximum is `$`\max RPN = 10 \times 10 \times 10 = 1000`$.
  4. **Dual-Criterion Criticality Classification**:
     - The safety compiler shall classify each failure mode $`f \in \mathcal{F}`$` into a binary criticality state `$`\text{IsCritical}(f) \in \{ \text{true}, \text{false} \}`$ governed by a dual-threshold condition:

```math
\text{IsCritical}(f) \iff \left( S(f) \ge S_{\text{crit\_thresh}} \;\lor\; RPN(f) \ge RPN_{\text{crit\_thresh}} \right)
```

     - Canonical default thresholds shall be $`S_{\text{crit\_thresh}} = 9`$` and `$`RPN_{\text{crit\_thresh}} = 200`$.
     - Severity Primacy Invariant: Any failure mode with Severity $`S(f) \ge S_{\text{crit\_thresh}}`$` (catastrophic or critical effect) shall be classified as Critical regardless of how low its Occurrence or Detection ratings may be (e.g., `$`S=9, O=1, D=1 \implies RPN=9`$`, but `$`\text{IsCritical} \equiv \text{true}`$).
     - RPN Magnitude Invariant: Any failure mode whose cumulative product satisfies $`RPN(f) \ge RPN_{\text{crit\_thresh}}`$` shall be classified as Critical regardless of whether `$`S(f) \lt S_{\text{crit\_thresh}}`$` (e.g., `$`S=5, O=8, D=5 \implies RPN=200 \implies \text{IsCritical} \equiv \text{true}`$).
  5. **Critical Failure Mode Mitigation Obligation Gate**:
     - Every failure mode classified as Critical ($`\text{IsCritical}(f) \equiv \text{true}`$`) must bind at least one certified mitigating safety constraint, barrier contract, or Run-Time Assurance pattern (`$`\mathbf{C}_{\text{mitig}}(f) \ne \emptyset`$) verified under REQ-0135, REQ-0137, or REQ-0141.
     - If any critical failure mode lacks an active, certified mitigation ($`\text{IsCritical}(f) \land \mathbf{C}_{\text{mitig}}(f) = \emptyset`$), the safety compiler shall deterministically reject the compilation unit at compile time with diagnostic error code `E0400` (`UnmitigatedCriticalFailureMode`), identifying the failure mode handle, rating triple, RPN score, and source span coordinates.
  6. **Multi-Tier Action Priority (AP) Classification Matrix**:
     - In addition to binary criticality, the compiler shall assign every failure mode $`f \in \mathcal{F}`$` to a discrete Action Priority tier `$`\text{AP}(f) \in \{ \text{High}, \text{Medium}, \text{Low} \}`$ to guide architectural mitigation allocation:
       - $`\text{AP}(f) = \text{High}`$` if `$`S(f) \ge 9`$`, or if `$`(S(f) \ge 7 \land O(f) \ge 6 \land D(f) \ge 5)`$`, or if `$`RPN(f) \ge 200`$;
       - $`\text{AP}(f) = \text{Medium}`$` if not High, and `$`(S(f) \ge 6 \land O(f) \ge 4)`$` or `$`RPN(f) \ge 80`$;
       - $`\text{AP}(f) = \text{Low}`$ otherwise.
     - Action Priority assignments shall be deterministically recorded in the failure mode metadata record.
  7. **Deterministic Pareto Total Precedence Ordering**:
     - The compiler shall establish a strict, canonical total ordering $`\succ_{\text{RPN}}`$` across all failure modes in `$`\mathcal{F}`$ to produce deterministic Pareto risk ranking tables.
     - The total ordering shall be evaluated using a hierarchical 5-level lexicographical comparison rule:
       1. Primary key: $`RPN(f)`$ descending (higher risk numbers first);
       2. Secondary key: $`S(f)`$ descending (higher severity first);
       3. Tertiary key: $`O(f)`$ descending (higher occurrence first);
       4. Quaternary key: $`D(f)`$ descending (harder to detect first);
       5. Quinary key (deterministic tie-breaker): Lexicographical byte order of the fully qualified name ($`\text{FQN}(f)`$) or deterministic RFC 4122 UUIDv5 byte order.
     - The resulting sorted sequence $`\vec{\mathcal{F}}_{\text{Pareto}} = \langle f_{(1)}, f_{(2)}, \dots, f_{(N)} \rangle`$ shall guarantee 100% bitwise identical output emission with 0-byte diff churn across all compilation invocations.
  8. **Cumulative System Risk Metrics & Budgeting**:
     - The compiler shall compute aggregate quantitative risk metrics across the failure mode universe:
       - Total system risk score: $`RPN_{\text{total}} = \sum_{f \in \mathcal{F}} RPN(f)`$;
       - Mean failure mode risk score: $`RPN_{\text{mean}} = \frac{1}{|\mathcal{F}|} \sum_{f \in \mathcal{F}} RPN(f)`$` (evaluating to zero if `$`|\mathcal{F}| = 0`$);
       - Critical failure mode census: $`N_{\text{crit}} = |\{ f \in \mathcal{F} \mid \text{IsCritical}(f) \}|`$.
     - When an architectural package declares an explicit risk budget limit $`RPN_{\text{budget}} \in \mathbb{N}^+`$`, the compiler shall verify that `$`RPN_{\text{total}} \le RPN_{\text{budget}}`$`. If `$`RPN_{\text{total}} \gt RPN_{\text{budget}}`$, the compiler shall emit diagnostic error code `E0400` (`RiskBudgetExceeded`).
  9. **Compliance with the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every failure mode record, RPN score structure, criticality classification result, and Pareto ranking artifact shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(f))`$` for failure modes, and `$`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(f) \mathbin{\Vert} \text{"::RPN"})`$ for score records) in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Multithreaded evaluation of failure mode rating validation, RPN integer scoring, and component-wise risk ranking across independent packages shall execute strictly on a centralized, bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Failure mode identifiers, classifier names, severity/occurrence/detection labels, risk priority tier tags, and fully qualified path strings shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The safety compiler shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When rating validation errors (`E0400`), unmitigated critical failure mode violations (`E0400`), or risk budget overruns (`E0400`) occur, diagnostics shall accumulate in the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{rpn}}`$`), and continue validating subsequent failure modes. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The quantitative RPN scoring engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($`\lt 25\text{ ms}`$` for `$`10^4`$` failure modes) and peak RSS memory (`$`\lt 100\text{ MB}`$) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Component_0`, `Component_1`, `FailureMode_0`, `FailureMode_1`, `FailureMode_Alpha`, `FailureMode_Beta`, `Constraint_0`, `Constraint_1`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous bump arena storage.

  Let $`\mathcal{F} = \{ f_1, f_2, \dots, f_N \} \subset \mathcal{V}_{\text{AST}}`$ denote the universe of analyzed failure modes.

  Each failure mode $`f \in \mathcal{F}`$ is formalized as an 9-tuple:

```math
  f = \langle \text{id}_f, \text{name}_f, S(f), O(f), D(f), \mathbf{C}_{\text{mitig}}(f), \Delta_f, \text{provenance}_f, \text{span}_f \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_f &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_f &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
  S(f) &\in \mathbb{Z}^+ \quad (\text{severity rating}) \\
  O(f) &\in \mathbb{Z}^+ \quad (\text{occurrence rating}) \\
  D(f) &\in \mathbb{Z}^+ \quad (\text{detection rating}) \\
  \mathbf{C}_{\text{mitig}}(f) &\subseteq \mathcal{V}_{\text{AST}} \quad (\text{set of associated mitigating safety constraints}) \\
  \Delta_f &\in \Sigma^{36} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{provenance}_f &\in \mathcal{V}_{\text{AST}} \quad (\text{owning architectural classifier or component handle}) \\
  \text{span}_f &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance span})
  \end{aligned}
```

  1. Rating Domain Invariants:

```math
  \forall f \in \mathcal{F}, \quad S(f) \in [1, 10] \cap \mathbb{Z}^+, \quad O(f) \in [1, 10] \cap \mathbb{Z}^+, \quad D(f) \in [1, 10] \cap \mathbb{Z}^+
```

  2. Quantitative Risk Priority Number (RPN) Evaluation Invariant:

```math
  RPN(f) = S(f) \times O(f) \times D(f)
```

  with exact integer range bounds:

```math
  \forall f \in \mathcal{F}, \quad RPN(f) \in [1, 1000] \cap \mathbb{Z}^+
```

  and boundary extremum guarantees:

```math
  \begin{aligned}
  \min_{f \in \mathcal{F}} RPN(f) &= 1 \times 1 \times 1 = 1 \\
  \max_{f \in \mathcal{F}} RPN(f) &= 10 \times 10 \times 10 = 1000
  \end{aligned}
```

  3. Dual-Criterion Criticality Predicate Invariant:

```math
  \text{IsCritical}(f) \iff \left( S(f) \ge S_{\text{crit\_thresh}} \;\lor\; RPN(f) \ge RPN_{\text{crit\_thresh}} \right)
```

  where canonical thresholds satisfy:

```math
  S_{\text{crit\_thresh}} = 9, \quad RPN_{\text{crit\_thresh}} = 200
```

  4. Critical Failure Mode Mitigation Obligation Invariant:

```math
  \forall f \in \mathcal{F}, \quad \text{IsCritical}(f) \implies \mathbf{C}_{\text{mitig}}(f) \ne \emptyset
```

  5. Action Priority Tier Assignment Invariant:

```math
  \text{AP}(f) = \begin{cases}
  \text{High}, & \text{if } S(f) \ge 9 \;\lor\; (S(f) \ge 7 \land O(f) \ge 6 \land D(f) \ge 5) \;\lor\; RPN(f) \ge 200 \\
  \text{Medium}, & \text{if } \neg(\text{AP}(f) = \text{High}) \land \left( (S(f) \ge 6 \land O(f) \ge 4) \lor (RPN(f) \ge 80) \right) \\
  \text{Low}, & \text{otherwise}
  \end{cases}
```

  6. Pareto Total Precedence Order Invariant ($`\succ_{\text{RPN}}`$):
  For any distinct failure modes $`f_a, f_b \in \mathcal{F}`$`, the relation `$`f_a \succ_{\text{RPN}} f_b`$ holds if and only if:

```math
  \begin{aligned}
  \left( RPN(f_a) \gt RPN(f_b) \right) &\lor \\
  \left( RPN(f_a) = RPN(f_b) \land S(f_a) \gt S(f_b) \right) &\lor \\
  \left( RPN(f_a) = RPN(f_b) \land S(f_a) = S(f_b) \land O(f_a) \gt O(f_b) \right) &\lor \\
  \left( RPN(f_a) = RPN(f_b) \land S(f_a) = S(f_b) \land O(f_a) = O(f_b) \land D(f_a) \gt D(f_b) \right) &\lor \\
  \left( RPN(f_a) = RPN(f_b) \land S(f_a) = S(f_b) \land O(f_a) = O(f_b) \land D(f_a) = D(f_b) \land \text{FQN}(f_a) \lt_{\text{lex}} \text{FQN}(f_b) \right)
  \end{aligned}
```

  The relation $`\succ_{\text{RPN}}`$` defines a strict total order over `$`\mathcal{F}`$, satisfying irreflexivity, asymmetry, transitivity, and totality:

```math
  \begin{aligned}
  \forall f \in \mathcal{F}, &\quad \neg(f \succ_{\text{RPN}} f) \quad (\text{irreflexivity}) \\
  \forall f_a, f_b \in \mathcal{F}, &\quad f_a \succ_{\text{RPN}} f_b \implies \neg(f_b \succ_{\text{RPN}} f_a) \quad (\text{asymmetry}) \\
  \forall f_a, f_b, f_c \in \mathcal{F}, &\quad (f_a \succ_{\text{RPN}} f_b \land f_b \succ_{\text{RPN}} f_c) \implies f_a \succ_{\text{RPN}} f_c \quad (\text{transitivity}) \\
  \forall f_a \ne f_b \in \mathcal{F}, &\quad f_a \succ_{\text{RPN}} f_b \;\lor\; f_b \succ_{\text{RPN}} f_a \quad (\text{totality})
  \end{aligned}
```

  7. Cumulative System Risk Metrics Invariants:

```math
  \begin{aligned}
  RPN_{\text{total}} &= \sum_{f \in \mathcal{F}} RPN(f) \\
  RPN_{\text{mean}} &= \begin{cases}
  \frac{1}{|\mathcal{F}|} \sum_{f \in \mathcal{F}} RPN(f), & \text{if } |\mathcal{F}| \gt 0 \\
  0, & \text{if } |\mathcal{F}| = 0
  \end{cases} \\
  N_{\text{crit}} &= \sum_{f \in \mathcal{F}} \mathbf{1}_{\{ \text{IsCritical}(f) \}}
  \end{aligned}
```

  8. Deterministic Diagnostic Trigger Rules (REQ-0191):

```math
  \begin{aligned}
  \exists f \in \mathcal{F} : \left( S(f) \notin [1, 10] \lor O(f) \notin [1, 10] \lor D(f) \notin [1, 10] \right) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0400}, \text{RatingDomainViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists f \in \mathcal{F} : \left( \text{IsCritical}(f) \land \mathbf{C}_{\text{mitig}}(f) = \emptyset \right) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0400}, \text{UnmitigatedCriticalFailureMode}) \in \mathcal{D}_{\text{sink}} \\
  \exists f \in \mathcal{F} : \left( \text{MissingRating}(f) \right) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0400}, \text{MissingFailureModeRating}) \in \mathcal{D}_{\text{sink}} \\
  \left( \exists RPN_{\text{budget}} \land RPN_{\text{total}} \gt RPN_{\text{budget}} \right) &\implies \text{Diagnostic}(\mathcal{F}, \text{DiagnosticCode::E0400}, \text{RiskBudgetExceeded}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  9. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
  \begin{aligned}
  \forall f \in \mathcal{F}, &\quad \Delta_f = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(f)) \\
  \forall f \in \mathcal{F}, &\quad \Delta_{\text{RPN}(f)} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(f) \mathbin{\Vert} \text{"::RPN"}) \\
  \forall f \in \mathcal{F}, &\quad \Delta_{\text{crit}(f)} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(f) \mathbin{\Vert} \text{"::Criticality"}) \\
  \Delta_{\text{ParetoRanking}} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\text{"ParetoRiskRanking"}))
  \end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

The Quantitative Risk Priority Number (RPN) Integer Scoring Engine resides in **Complexity Class P** (Deterministic Polynomial Time), operating with linear and log-linear asymptotic algorithmic upper bounds across all evaluation stages.

  **Mathematical Delineation from Other Algorithmic Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 addresses qualitative temporal interval algebra path consistency and difference logic SMT solving (ORD-Horn subclass in $`O(N^3)`$). In contrast, REQ-0140 computes point-wise scalar integer products and discrete range verifications without temporal constraint propagation.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses vector bin packing and multi-capacity structural resource allocation (strongly NP-hard). In contrast, REQ-0140 evaluates static failure mode rating attributes without packing or knapsack combinatorial constraints.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 resolves multiple inheritance subtyping lattices via C3 linearization in $`O(V + E)`$ time. In contrast, REQ-0140 operates on a flat or hierarchical list of failure modes to evaluate quantitative risk scores.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 solves the minimal hitting set problem over hypergraph hazard cut-sets (NP-complete). In contrast, REQ-0140 computes quantitative scalar scores for individual failure modes, providing prioritized criticality inputs that downstream cut-set solvers use as objective weights.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 addresses PSPACE-complete orthogonal state machine reachability. In contrast, REQ-0140 performs static algebraic evaluations on failure mode attributes without state space unrolling.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks via linear complementarity problems. In contrast, REQ-0140 executes pure integer arithmetic without matrix inversion or pivot iterations.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs Chaitin graph coloring for SSA register allocation. In contrast, REQ-0140 sorts evaluated failure modes into priority sequences.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the satisfiability of arbitrary first-order invariant formulas via DPLL(T). In contrast, REQ-0140 performs elementary integer multiplication and total order sorting.

  **Asymptotic Complexity Analysis**:
  Let $`N = |\mathcal{F}|`$` denote the total number of failure modes across the compilation unit, and let `$`K = 1000`$` denote the fixed cardinality of the discrete RPN integer score range (`$`[1, 1000]`$).
  1. *Failure Mode Ingestion & Rating Validation*:
     Traversing the bump arena AST nodes to extract failure mode records and verifying that $`S(f), O(f), D(f) \in [1, 10] \cap \mathbb{Z}^+`$` takes `$`O(1)`$ operations per failure mode, executing in:

```math
T_{\text{validate}}(N) \in O(N)
```

  2. *Quantitative Multiplicative Scoring ($`RPN = S \times O \times D`$)*:
     Computing the exact integer product requires exactly 2 integer multiplication instructions per failure mode. For $`N`$ failure modes, execution requires:

```math
T_{\text{eval}}(N) \in O(N)
```

     with zero dynamic memory allocations and strict $`O(1)`$ evaluation per node.
  3. *Criticality Classification & Action Priority Assignment*:
     Evaluating the dual-threshold condition $`S(f) \ge 9 \lor RPN(f) \ge 200`$ and assigning Action Priority tiers involves at most 5 integer comparisons per failure mode, executing in:

```math
T_{\text{classify}}(N) \in O(N)
```

  4. *Critical Failure Mode Mitigation Obligation Verification*:
     Checking that $`\mathbf{C}_{\text{mitig}}(f) \ne \emptyset`$` for each critical failure mode takes `$`O(1)`$ operations per critical mode, bounded by:

```math
T_{\text{mitigation}}(N) \in O(N_{\text{crit}}) \subseteq O(N)
```

  5. *Deterministic Pareto Ranking & Total Order Sorting*:
     - Comparison-based sorting: Sorting $`N`$` failure mode references using a deterministic stable introsort or merge sort under the 5-level total precedence relation `$`\succ_{\text{RPN}}`$ executes in:

```math
T_{\text{sort, comp}}(N) \in O(N \log N)
```

     - Integer distribution (bucket/radix) sorting: Because the primary key is bounded by a fixed constant range $`RPN \in [1, 1000]`$`, failure modes can be partitioned into `$`K = 1000`$` buckets in `$`O(N + K) = O(N)`$` time. Further sub-bucket distribution across `$`S \in [1, 10]`$`, `$`O \in [1, 10]`$`, and `$`D \in [1, 10]`$` partitions items across exactly `$`1000`$ discrete tuples, allowing linear sorting:

```math
T_{\text{sort, bucket}}(N, K) \in O(N + K) = O(N)
```

       with final lexicographical tie-breaking applied only within identical $`\langle RPN, S, O, D \rangle`$ collision equivalence classes.
  6. *Cumulative System Risk Metric Computation*:
     Computing $`RPN_{\text{total}}`$`, `$`RPN_{\text{mean}}`$`, and `$`N_{\text{crit}}`$` is an online single-pass aggregation over `$`N`$ items, executing in:

```math
T_{\text{aggregate}}(N) \in O(N)
```

  7. *Aggregate Worst-Case Time Complexity*:
     The total execution time across all evaluation passes is strictly bounded by:

```math
T_{\text{total}}(N) \in O(N \log N)
```

     under comparison-based sorting, and reduces to strict linear time $`O(N)`$ when bucket distribution is employed.
  8. *Parallel Work-Stealing Scaling (Directive 2)*:
     When evaluating $`M`$` independent architectural packages containing `$`N`$` total failure modes across `$`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool:

```math
T_{\text{parallel}}(N, N_{\text{max\_workers}}) \in O\left( \frac{N \log N}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

     guaranteeing linear speedup with bounded scheduling overhead.
  9. *Space Complexity & Arena Memory Bounds*:
     Allocations for failure mode tuples, RPN score structures, criticality records, and sorted pointer arrays reside in contiguous bump arena storage. Each record requires 32 bytes of aligned memory, yielding $`S_{\text{arena}}(N) \in O(N)`$` bytes total. Deduplicated interned symbols require `$`O(N)`$` bytes in the global symbol pool. The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ capacity.
