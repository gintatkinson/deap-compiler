### REQ-0038: Strongly Typed Port Directions (`in`, `out`, `inout`) & Directional Invariants

- **Normative Statement**: The Core Metamodel, Node Arena & AST Graph Engine shall enforce strongly typed port directionality (`in`, `out`, `inout`) on all port definitions (`PortDef`) and port usages (`PortUsage`), requiring topological connection bindings between ports to enforce strict directional compatibility invariants across hierarchical assembly boundaries. The metamodel shall define a discrete, closed direction domain $`\mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut} \}`$. Every port definition must declare an immutable base direction $`d_{\text{decl}} \in \mathcal{D}`$. Every port usage referencing a port definition must inherit the declared base direction, subject to optional conjugation denoted by the conjugation marker (`~`). When a port usage is conjugated, the compiler shall evaluate an algebraic involution operator $`\tau_{\text{conj}}`$ to compute the effective direction $`d_{\text{eff}} \in \mathcal{D}`$, where $`\tau_{\text{conj}}(\text{In}) = \text{Out}`$, $`\tau_{\text{conj}}(\text{Out}) = \text{In}`$, and $`\tau_{\text{conj}}(\text{InOut}) = \text{InOut}`$.

  The AST graph type checking engine shall partition all topological connections into two mutually exclusive structural categories based on their hierarchical placement:
  1. Peer-to-Peer (Assembly) Connections: Connections linking two ports located on sibling component usages at the same hierarchical assembly level. For peer-to-peer connections, the engine shall enforce anti-parallel directed flow or mutual bidirectional flow: a source port with effective direction `Out` must connect to a target port with effective direction `In`, a source port with effective direction `In` must connect to a target port with effective direction `Out`, or both ports must possess effective direction `InOut`. Connections between two `In` ports, between two `Out` ports, or between an `InOut` port and a unidirectional `In` or `Out` port without an explicit adapter are strictly invalid and must deterministically emit diagnostic error code `E0201` per REQ-0191.
  2. Hierarchical Delegation (Boundary / Pass-Through) Connections: Connections linking an outer boundary port on an enclosing parent component definition to an inner port on an enclosed child component usage. For hierarchical delegation connections, the engine shall enforce parallel flow preservation across the structural containment boundary: the outer boundary port and inner child port must have identical effective directions ($`P_{\text{outer}}.d_{\text{eff}} = P_{\text{inner}}.d_{\text{eff}}`$). Specifically, an outer `In` port must delegate exclusively to an inner `In` port, an inner `Out` port must delegate exclusively to an outer `Out` port, and an outer `InOut` port must delegate exclusively to an inner `InOut` port. Any directional inversion across delegation boundaries (such as outer `In` connected to inner `Out`, or outer `Out` connected to inner `In`) is strictly invalid and must deterministically emit diagnostic error code `E0201`.

  All port definitions, port usages, and connection bindings shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit relative node handles in accordance with REQ-0035. In accordance with Architectural Directive 1 and REQ-0010, every lowered port and connection node must receive a deterministic RFC 4122 UUIDv5 identifier computed by hashing the namespace OID and the fully qualified symbol path. In accordance with Architectural Directive 3 and REQ-0036, scalar symbol identifiers for port names and qualified paths shall be interned into the global symbol interner pool. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the type checking engine shall implement synchronization token error recovery during connection verification: upon detecting a directional compatibility failure (`E0201`), the engine shall record a structured diagnostic record containing the exact source byte span, port identifiers, and direction mismatch details, mark the connection edge with an invalid status flag, and continue verifying subsequent connections rather than aborting compilation. If accumulated diagnostics reach the sink capacity limit $`C_{\text{max\_errors}}`$, the compiler shall emit diagnostic error code `E0199` and terminate type checking gracefully. Parallel AST connection validation across independent component assemblies shall be scheduled strictly onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with Architectural Directive 2 and REQ-0012. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the type checking engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs, evaluating performance gates (< 25 ms latency, < 100 MB RSS) exclusively in compiled Release mode (`--release`). All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Component_Alpha`, `Component_Beta`, `Part_0`, `Part_1`, `Port_1`, `Port_2`, `Port_Src`, `Port_Tgt`, `Conn_0`, `param_x : Real`) with zero domain contamination.

- **Formal Invariant**: Let $`\mathcal{D}`$ denote the discrete ternary port direction domain:

$$
\mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut} \}
$$

The port conjugation involution operator $`\tau_{\text{conj}} : \mathcal{D} \to \mathcal{D}`$ is defined as:

$$
\tau_{\text{conj}}(d) = \begin{cases}
\text{Out}, & \text{if } d = \text{In} \\
\text{In}, & \text{if } d = \text{Out} \\
\text{InOut}, & \text{if } d = \text{InOut}
\end{cases}
$$

Involution Identity Invariant: Conjugating a direction twice returns the original direction identically:

$$
\forall d \in \mathcal{D}, \quad \tau_{\text{conj}}(\tau_{\text{conj}}(d)) \equiv d
$$

Each lowered port usage entity $`P \in \mathcal{V}_{\text{port}}`$ is formalized as a 9-tuple:

$$
P = \langle \text{id}, \text{owner}, \text{def\_ref}, d_{\text{decl}}, c, d_{\text{eff}}, \tau_{\text{payload}}, \mu, \text{span} \rangle
$$

where:
- $`\text{id} \in \mathcal{S}_{\text{sym}}`$ is the interned scalar symbol handle representing the port identifier,
- $`\text{owner} \in \mathcal{H}_{\text{comp}}`$ is the parent component handle,
- $`\text{def\_ref} \in \mathcal{H}_{\text{port\_def}}`$ is the port definition reference handle,
- $`d_{\text{decl}} \in \mathcal{D}`$ is the declared base direction,
- $`c \in \mathbb{B}`$ is the boolean conjugation flag ($`\text{is\_conjugated}`$),
- $`d_{\text{eff}} \in \mathcal{D}`$ is the resolved effective direction,
- $`\tau_{\text{payload}} \in \mathcal{H}_{\text{type}}`$ is the payload classifier type handle,
- $`\mu = \langle l, u \rangle \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \})`$ denotes the multiplicity bounds ($`0 \le l \le u`$, $`u \ge 1`$),
- $`\text{span} = \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$ is the exact source provenance coordinate.

Effective Direction Resolution: The effective direction function $`d_{\text{eff}} : \mathcal{D} \times \mathbb{B} \to \mathcal{D}`$ is computed as:

$$
d_{\text{eff}}(P) = \begin{cases}
\tau_{\text{conj}}(P.d_{\text{decl}}), & \text{if } P.c = \text{true} \\
P.d_{\text{decl}}, & \text{if } P.c = \text{false}
\end{cases}
$$

Each connection entity $`C \in \mathcal{E}_{\text{conn}}`$ is formalized as a 5-tuple:

$$
C = \langle \text{id}, P_{\text{src}}, P_{\text{tgt}}, \kappa_{\text{conn}}, \text{span} \rangle
$$

where $`\kappa_{\text{conn}} \in \{ \text{Assembly}, \text{Delegation} \}`$ is the structural connection kind, $`P_{\text{src}} \in \mathcal{H}_{\text{port}}`$, and $`P_{\text{tgt}} \in \mathcal{H}_{\text{port}}`$.

Let $`\text{EnclosingComponent}(C) \in \mathcal{H}_{\text{comp}}`$ denote the component classifier enclosing connection $`C`$, and let $`\text{Parent}(P) \in \mathcal{H}_{\text{comp}}`$ denote the owning component of port $`P`$. The structural connection kind is classified as:

$$
\kappa_{\text{conn}}(C) = \begin{cases}
\text{Assembly}, & \text{if } \text{Parent}(P_{\text{src}}) \ne \text{EnclosingComponent}(C) \;\wedge\; \text{Parent}(P_{\text{tgt}}) \ne \text{EnclosingComponent}(C) \\
\text{Delegation}, & \text{if } (\text{Parent}(P_{\text{src}}) = \text{EnclosingComponent}(C) \;\wedge\; \text{Parent}(P_{\text{tgt}}) \ne \text{EnclosingComponent}(C)) \\
& \quad \vee \; (\text{Parent}(P_{\text{tgt}}) = \text{EnclosingComponent}(C) \;\wedge\; \text{Parent}(P_{\text{src}}) \ne \text{EnclosingComponent}(C))
\end{cases}
$$

1. Peer-to-Peer (Assembly) Directional Compatibility Relation $`\sim_{\text{peer}}`$:

$$
P_{\text{src}} \sim_{\text{peer}} P_{\text{tgt}} \iff \begin{cases}
(P_{\text{src}}.d_{\text{eff}} = \text{Out} \wedge P_{\text{tgt}}.d_{\text{eff}} = \text{In}), & \text{or} \\
(P_{\text{src}}.d_{\text{eff}} = \text{In} \wedge P_{\text{tgt}}.d_{\text{eff}} = \text{Out}), & \text{or} \\
(P_{\text{src}}.d_{\text{eff}} = \text{InOut} \wedge P_{\text{tgt}}.d_{\text{eff}} = \text{InOut})
\end{cases}
$$

2. Hierarchical Delegation Directional Compatibility Relation $`\sim_{\text{delegation}}`$:
Let $`P_{\text{outer}}`$ denote the boundary port ($`\text{Parent}(P_{\text{outer}}) = \text{EnclosingComponent}(C)`$) and $`P_{\text{inner}}`$ denote the internal sub-component port ($`\text{Parent}(P_{\text{inner}}) \ne \text{EnclosingComponent}(C)`$):

$$
P_{\text{outer}} \sim_{\text{delegation}} P_{\text{inner}} \iff P_{\text{outer}}.d_{\text{eff}} = P_{\text{inner}}.d_{\text{eff}}
$$

Universal Connection Directional Validity Invariant:
For every connection edge $`C \in \mathcal{E}_{\text{conn}}`$, directional validity $`\text{ValidDirection}(C)`$ satisfies:

$$
\text{ValidDirection}(C) \iff \begin{cases}
P_{\text{src}} \sim_{\text{peer}} P_{\text{tgt}}, & \text{if } \kappa_{\text{conn}}(C) = \text{Assembly} \\
P_{\text{outer}} \sim_{\text{delegation}} P_{\text{inner}}, & \text{if } \kappa_{\text{conn}}(C) = \text{Delegation}
\end{cases}
$$

Diagnostic Code Binding Invariant:
Any connection violating directional compatibility triggers structured diagnostic error code `E0201` per REQ-0191:

$$
\begin{aligned}
\kappa_{\text{conn}}(C) = \text{Assembly} \wedge \neg(P_{\text{src}} \sim_{\text{peer}} P_{\text{tgt}}) &\implies \text{Diagnostic}(C, \text{DiagnosticCode::E0201}, \text{PeerDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
\kappa_{\text{conn}}(C) = \text{Delegation} \wedge \neg(P_{\text{outer}} \sim_{\text{delegation}} P_{\text{inner}}) &\implies \text{Diagnostic}(C, \text{DiagnosticCode::E0201}, \text{DelegationDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Deterministic UUIDv5 & Bump Arena Storage Invariant:
Every lowered port node $`P`$ and connection edge $`C`$ receives an immutable UUIDv5 identifier and a stable arena node handle:

$$
\begin{aligned}
\forall u \in \mathcal{V}_{\text{port}} \cup \mathcal{E}_{\text{conn}}, \quad \text{UUID}(u) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u)) \\
\forall u \in \mathcal{V}_{\text{port}} \cup \mathcal{E}_{\text{conn}}, \quad \text{Handle}(u) &= \langle \text{ArenaId}, \text{Offset}_u \rangle
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Direction compatibility verification executes strictly within Complexity Class $`\mathbf{P}`$. The algorithmic bounds across data structures and operations are formalized as follows:
  1. Effective Direction Computation: For any port usage $`P`$, computing $`d_{\text{eff}}(P)`$ evaluates a conditional branch and a discrete 3-element lookup table for $`\tau_{\text{conj}}`$, requiring $`O(1)`$ constant time with zero heap allocations.
  2. Connection Edge Verification: For any connection $`C = \langle \text{id}, P_{\text{src}}, P_{\text{tgt}}, \kappa_{\text{conn}}, \text{span} \rangle`$, dereferencing endpoint handles $`P_{\text{src}}`$ and $`P_{\text{tgt}}`$ in the contiguous typed bump arena requires $`O(1)`$ constant time via direct 32-bit offset addressing. Evaluating $`\text{Kind}(C)`$ evaluates two handle equality checks in $`O(1)`$ time. Evaluating $`P_{\text{src}} \sim_{\text{peer}} P_{\text{tgt}}`$ or $`P_{\text{outer}} \sim_{\text{delegation}} P_{\text{inner}}`$ executes in deterministic $`O(1)`$ time by evaluating a precomputed truth table over the 2-bit direction discriminant representation.
  3. Total Interconnect Graph Verification: For an AST interconnect graph $`G = (\mathcal{V}_{\text{port}}, \mathcal{E}_{\text{conn}})`$ containing $`V = |\mathcal{V}_{\text{port}}|`$ port instances and $`E = |\mathcal{E}_{\text{conn}}|`$ connection edges:

$$
T(V, E) = \sum_{e=1}^{E} O(1) \in O(E) \subseteq O(V + E)
$$

  4. Parallel Verification Bounds: Under bounded work-stealing multithreading scheduled over $`N_{\text{max\_workers}}`$ worker threads:

$$
T_{\text{parallel}}(V, E) \in O\left(\frac{E}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}}\right)
$$

  5. Space Complexity: Auxiliary memory overhead is strictly $`O(1)`$ beyond the contiguous node arena storage and the preallocated diagnostic sink buffer $`O(C_{\text{max\_errors}})`$, ensuring zero heap reallocation during the verification pass.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (e.g., `Package_0`, `Component_Alpha`, `Component_Beta`, `Part_0`, `Part_1`, `Port_1`, `Port_2`, `Port_Src`, `Port_Tgt`, `Conn_0`, `param_x : Real`) across the following verification gates:
  1. Peer-to-Peer Direction Truth Table Gate: Validate all 9 pairwise direction combinations for assembly connections between sibling child components:
     - Assert that `(Out, In)`, `(In, Out)`, and `(InOut, InOut)` evaluate to valid with zero diagnostics emitted.
     - Assert that `(In, In)` and `(Out, Out)` emit diagnostic error code `E0201`.
     - Assert that `(In, InOut)`, `(Out, InOut)`, `(InOut, In)`, and `(InOut, Out)` emit diagnostic error code `E0201`.
  2. Hierarchical Delegation Truth Table Gate: Validate all 9 pairwise direction combinations for delegation connections across parent-child structural boundaries:
     - Assert that `(In, In)`, `(Out, Out)`, and `(InOut, InOut)` evaluate to valid with zero diagnostics emitted.
     - Assert that mismatched delegation pairs `(In, Out)`, `(Out, In)`, `(In, InOut)`, `(Out, InOut)`, `(InOut, In)`, and `(InOut, Out)` emit diagnostic error code `E0201`.
  3. Conjugation Involution & Effective Direction Gate: Validate algebraic properties of $`\tau_{\text{conj}}`$:
     - Assert that $`\tau_{\text{conj}}(\text{In}) = \text{Out}`$, $`\tau_{\text{conj}}(\text{Out}) = \text{In}`$, and $`\tau_{\text{conj}}(\text{InOut}) = \text{InOut}`$.
     - Assert that the involution identity $`\tau_{\text{conj}}(\tau_{\text{conj}}(d)) \equiv d`$ holds for all $`d \in \mathcal{D}`$.
     - Verify that connecting a non-conjugated port $`P_1`$ with $`d_{\text{decl}} = \text{In}`$ to a conjugated port $`P_2`$ with $`d_{\text{decl}} = \text{In}`$ and $`c = \text{true}`$ (yielding $`d_{\text{eff}} = \text{Out}`$) evaluates to valid peer-to-peer compatibility with zero diagnostics emitted.
  4. Diagnostic Error Code Binding & Recovery Gate: Ingest an AST model containing 10 connection edges with 4 intentional directional mismatches:
     - Assert that the type checking engine accumulates all 4 structured diagnostic records with diagnostic error code `E0201`.
     - Assert that each diagnostic record accurately cites the source code coordinate span, the offending connection identifier, and the conflicting port identifiers.
     - Assert that verification continues across all connection edges without early termination.
     - Inject malformed connections exceeding $`C_{\text{max\_errors}}`$ and assert that verification halts gracefully with diagnostic error code `E0199`.
  5. Deterministic Non-Panicking Execution & Performance Gate: Execute type checking across pathologically malformed AST graphs (unresolved port handles, dangling connection endpoints, circular delegation paths):
     - Assert total-function termination with zero panics or unwinding crashes.
     - In compiled Release mode (`--release`), benchmark verification across an interconnect graph with $`10^5`$ connection edges, asserting execution latency strictly below 25 ms and peak RSS memory strictly below 100 MB per REQ-0011 and REQ-0196.
  6. Bitwise Determinism Gate: Verify that repeated compilation runs on identical AST models produce bitwise identical diagnostic collections and node handle states with zero diff churn.
