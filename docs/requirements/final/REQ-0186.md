### REQ-0186: Freestanding RTOS Memory-Mapped Register Header Generation

- **Normative Statement**: The code generation engine, multi-target backend emission pipeline, and embedded hardware interface framework of Subsystem 10 shall synthesize freestanding, zero-allocation ISO/IEC 9899:1999 (C99) and ISO/IEC 14882:2020 (C++20) memory-mapped input/output (MMIO) register definition headers (`.h` and `.hpp`) from lowered abstract syntax tree (AST) interconnect nodes, hardware peripheral definitions, register banks, and port interface models for safety-critical real-time operating system (RTOS) and bare-metal embedded execution targets. The emission engine shall generate strongly-typed register definitions comprising compile-time peripheral base address offsets, register byte offsets, bitfield mask constants, bit shift positions, bitfield width bounds, volatile-qualified pointer accessors, and atomic read-modify-write (RMW) helper functions. The compiler shall verify that every register address satisfies natural alignment ($`\text{RegAddress}(R) \equiv 0 \pmod{\text{sizeof}(R)}`$`), that every register width belongs strictly to the standardized fixed-width integer scalar type universe (`$`\text{sizeof}(R) \in \{1, 2, 4, 8\}`$ bytes, corresponding to `uint8_t`, `uint16_t`, `uint32_t`, `uint64_t`), that all bitfields fit strictly within register boundaries without overlapping unless explicitly annotated as union fields, and that registers do not collide within the peripheral address map. If any register definition violates natural alignment, specifies a non-standard width, contains out-of-bounds or overlapping bitfields, exceeds peripheral address boundaries, or violates static code emission constraints, the compiler shall fail closed and emit diagnostic error code `E0500`.

  Specifically, the code generation engine, backend emission pipeline, and MMIO synthesis framework shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Base Address & Offset Architecture**:
     - The code generator shall ingest peripheral block descriptors containing compile-time base addresses $`\text{BaseOffset}(B) \in \mathbb{N}_{64}`$` and register relative byte offsets `$`\Delta_{\text{register}}(R) \in \mathbb{N}_{64}`$.
     - Absolute register addresses shall evaluate deterministically as $`\text{RegAddress}(R) = \text{BaseOffset}(B) + \Delta_{\text{register}}(R)`$.
     - Emitted headers shall provide both compile-time address macro definitions (e.g., `#define PERIPHERAL_0_REGISTER_0_ADDR (PERIPHERAL_0_BASE + 0x00000004ULL)`) and strongly-typed base-pointer struct overlays (`typedef struct { ... } Peripheral_0_Type;`) to support diverse embedded and RTOS firmware paradigms.
  2. **Exact Natural Alignment Invariant**:
     - Every register address $`\text{RegAddress}(R)`$` and relative offset `$`\Delta_{\text{register}}(R)`$ shall be strictly aligned to the natural boundary of its width:

```math
\text{RegAddress}(R) \equiv 0 \pmod{\text{sizeof}(R)}, \quad \Delta_{\text{register}}(R) \equiv 0 \pmod{\text{sizeof}(R)}
```

     - Peripheral base offsets $`\text{BaseOffset}(B)`$ shall be aligned to the maximum register alignment requirement within the peripheral block:

```math
\text{BaseOffset}(B) \equiv 0 \pmod{\max_{R \in \mathcal{R}(B)} \text{sizeof}(R)}
```

     - If an offset or base address violates natural alignment, the compiler shall fail closed and emit diagnostic error code `E0500` (`RegisterAlignmentViolation`).
  3. **Strongly-Typed Register Sizing & Fixed-Width Types**:
     - Every register $`R`$` shall be sized to exactly 1, 2, 4, or 8 bytes (`$`\text{sizeof}(R) \in \{1, 2, 4, 8\}`$).
     - Generated register accessors and struct members shall exclusively use standardized fixed-width unsigned integer scalar types from `<stdint.h>`: `uint8_t`, `uint16_t`, `uint32_t`, and `uint64_t`.
     - Bare native integer types (`int`, `short`, `long`, `char`) and non-standard register widths (e.g., 24-bit or 48-bit) are strictly prohibited; encountering them shall trigger diagnostic error code `E0500` (`RegisterWidthViolation`).
  4. **Bitfield Mask, Shift, & Access Policy Definition**:
     - For every declared bitfield $`f \in \mathcal{F}(R)`$`, the emission backend shall compute an exact bit shift position `$`\text{Shift}(f) \in \mathbb{N}_0`$`, bit width `$`\text{Width}(f) \ge 1`$, and bit mask constant:

```math
\text{Mask}(f) = \left( (1 \mathbin{\ll} \text{Width}(f)) - 1 \right) \mathbin{\ll} \text{Shift}(f)
```

     - Bitfields must fit strictly within register boundaries: $`\text{Shift}(f) + \text{Width}(f) \le 8 \times \text{sizeof}(R)`$.
     - Distinct non-aliased bitfields $`f_i, f_j`$` within the same register shall be mutually disjoint (`$`\text{Mask}(f_i) \mathbin{\&} \text{Mask}(f_j) = 0`$).
     - The generator shall emit access policy definitions for each bitfield and register conforming to declared MBSE hardware contracts: Read-Only (`RO`), Write-Only (`WO`), Read-Write (`RW`), Write-1-to-Clear (`W1C`), Read-Clear (`RC`), and Reserved (`RES`).
     - If a bitfield exceeds register width or collides with another bitfield without an explicit union annotation, the compiler shall emit diagnostic error code `E0500` (`BitfieldBoundsViolation` or `BitfieldOverlapViolation`).
  5. **Volatile-Qualified Accessor Invariants**:
     - All register pointer definitions, dereference macros, and accessor functions shall be explicitly qualified with the `volatile` keyword:
       `#define REG_READ32(addr) (*(volatile uint32_t*)(addr))`
       `#define REG_WRITE32(addr, val) (*(volatile uint32_t*)(addr) = (uint32_t)(val))`
     - Inline static accessor functions (`read_reg`, `write_reg`, `read_field`, `write_field`) shall enforce `volatile` qualification across all memory operations to guarantee that optimizing cross-compilers do not omit, cache, or reorder MMIO accesses across optimization barriers.
  6. **Atomic Read-Modify-Write (RMW) Helpers**:
     - The emission backend shall synthesize atomic bitwise manipulation helpers for all read-write registers containing bitfields:
       * Atomic bit set (`atomic_set_bits`)
       * Atomic bit clear (`atomic_clear_bits`)
       * Atomic bit toggle (`atomic_toggle_bits`)
       * Atomic bitfield write (`atomic_write_field`)
     - Atomic helpers shall be emitted as inline functions utilizing target-configured atomic primitives (e.g., standard C11/C++20 atomic operations `atomic_fetch_or`, `atomic_fetch_and`, or compare-and-swap loops) or RTOS interrupt-locking critical-section wrappers (`ENTER_CRITICAL()` and `EXIT_CRITICAL()`) to prevent race conditions during concurrent peripheral register updates.
  7. **Register Non-Overlap & Peripheral Boundary Verification**:
     - The address spans of distinct registers $`R_i, R_j`$` within peripheral block `$`B`$` (`$`R_i \ne R_j`$) shall not overlap:

```math
[\Delta_{\text{register}}(R_i), \Delta_{\text{register}}(R_i) + \text{sizeof}(R_i) - 1] \cap [\Delta_{\text{register}}(R_j), \Delta_{\text{register}}(R_j) + \text{sizeof}(R_j) - 1] = \emptyset
```

       unless explicitly modeled as union/aliased registers in AST metadata.
     - All registers must reside strictly within the allocated address span of the peripheral block:

```math
\Delta_{\text{register}}(R) + \text{sizeof}(R) \le \text{BlockSize}(B)
```

     - Overlapping registers or boundary overruns shall be deterministically rejected with diagnostic error code `E0500` (`RegisterOverlapViolation` or `BlockBoundaryOverflowViolation`).
  8. **Freestanding RTOS & Embedded Target Compatibility**:
     - Emitted header files shall target freestanding execution environments adhering to ISO/IEC 9899:1999 §4 and ISO/IEC 14882:2020 §4.1 (`-ffreestanding`).
     - Standard header inclusions shall be restricted exclusively to freestanding headers: `<stdint.h>`, `<stddef.h>`, and `<stdbool.h>` for C99 headers; `<cstdint>` and `<cstddef>` for C++20 headers.
     - Runtime dynamic heap allocations (`malloc`, `free`, `new`, `delete`) and hosted operating system dependencies are strictly prohibited ($`\text{HeapAllocations} \equiv 0`$).
     - Emitted headers shall provide idempotent preprocessor include guards (`#ifndef PERIPHERAL_0_H ... #endif`) and `extern "C"` linkage wrappers for bidirectional C/C++ cross-compilation.
  9. **Bijective Lexical Provenance & Traceability Anchoring**:
     - Every emitted header file, peripheral struct, register macro, bitfield constant, and accessor helper shall embed structured comments documenting bijective source provenance back to its originating AST node handle and source file byte span ($`\langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$) in accordance with REQ-0002.
  10. **Contiguous Bump Arena Memory Allocation & Node Addressing**:
      - All intermediate register AST entities, peripheral descriptors, bitfield representations, and text emission chunk buffers shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
      - Register and peripheral nodes shall be addressed exclusively by compact 32-bit arena node handles (REQ-0035), prohibiting internal raw heap pointers and reference cycles.
  11. **Enforcement of the 5 Executive Architectural Directives**:
      - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every generated peripheral block, register definition, and bitfield mask shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(B) \mathbin{\Vert} \text{"::MMIO::"} \mathbin{\Vert} \text{sym})`$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
      - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel header generation across independent peripheral blocks, interconnect buses, and register banks shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
      - *Directive 3 (String Interner Memory Allocation Exception)*: Peripheral names, register identifiers, bitfield symbols, macro prefixes, and typename tokens shall be interned into the deduplicated global symbol interner pool during register AST construction in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
      - *Directive 4 (Synchronization Token Error Recovery)*: The MMIO emission backend and register verifier shall implement synchronization token error recovery on register statement delimiters (`;`) and peripheral block boundaries (`}`) in accordance with REQ-0013 and REQ-0016. When non-compliant constructs (`E0500`) are encountered, the engine shall record structured diagnostics into preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute safe dummy declarations, and continue validating subsequent registers. If accumulated diagnostics reach capacity limit `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
      - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The register header generation engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Emission latency (strictly under 25 ms for an architectural model containing $`10^4`$ register definitions / AST nodes) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  12. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Peripheral_0`, `RegisterBlock_0`, `Register_0`, `Register_1`, `Field_Alpha`, `Field_Beta`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

  1. Register Address & Offset Invariant:
  Every register definition maps to a strongly-typed volatile structure with exact address offsets:

```math
  \text{RegAddress}(R) = \text{BaseOffset}(B) + \Delta_{\text{register}}(R), \quad \text{sizeof}(R) \in \{1, 2, 4, 8\} \text{ bytes}
```

  2. Natural Alignment Invariant:
  All register addresses, peripheral base offsets, and relative register offsets satisfy natural alignment:

```math
  \begin{aligned}
  \text{RegAddress}(R) &\equiv 0 \pmod{\text{sizeof}(R)} \\
  \text{BaseOffset}(B) &\equiv 0 \pmod{\max_{R \in \mathcal{R}(B)} \text{sizeof}(R)} \\
  \Delta_{\text{register}}(R) &\equiv 0 \pmod{\text{sizeof}(R)}
  \end{aligned}
```

  3. Bitfield Geometry & Mask Invariant:
  For every bitfield $`f \in \mathcal{F}(R)`$, the width and shift satisfy register bounds:

```math
  \begin{aligned}
  \forall f \in \mathcal{F}(R), \quad \text{Width}(f) &\ge 1 \quad \wedge \quad \text{Shift}(f) \ge 0 \\
  \text{Shift}(f) + \text{Width}(f) &\le 8 \times \text{sizeof}(R) \\
  \text{Mask}(f) &= \left( (1 \mathbin{\ll} \text{Width}(f)) - 1 \right) \mathbin{\ll} \text{Shift}(f)
  \end{aligned}
```

  Distinct non-aliased bitfields $`f_i, f_j \in \mathcal{F}(R)`$` (`$`i \ne j`$) are mutually disjoint:

```math
  \forall f_i, f_j \in \mathcal{F}(R), \quad i \ne j \implies \text{Mask}(f_i) \mathbin{\&} \text{Mask}(f_j) = 0
```

  4. Volatile Register & Bitfield Access Invariants:
  Let $`\tau(R)`$` denote the standardized fixed-width integer scalar type corresponding to `$`\text{sizeof}(R)`$:

```math
  \tau(R) = \begin{cases}
  \texttt{uint8\_t} & \text{if } \text{sizeof}(R) = 1 \\
  \texttt{uint16\_t} & \text{if } \text{sizeof}(R) = 2 \\
  \texttt{uint32\_t} & \text{if } \text{sizeof}(R) = 4 \\
  \texttt{uint64\_t} & \text{if } \text{sizeof}(R) = 8
  \end{cases}
```

  Volatile register read and write operations evaluate strictly as:

```math
  \begin{aligned}
  \text{ReadReg}(R) &= *( \text{volatile } \tau(R)* )\text{RegAddress}(R) \\
  \text{WriteReg}(R, v) &\implies *( \text{volatile } \tau(R)* )\text{RegAddress}(R) \leftarrow v
  \end{aligned}
```

  Bitfield read and write operations evaluate as:

```math
  \begin{aligned}
  \text{ReadField}(R, f) &= ( *( \text{volatile } \tau(R)* )\text{RegAddress}(R) \mathbin{\&} \text{Mask}(f) ) \mathbin{\gg} \text{Shift}(f) \\
  \text{WriteField}(R, f, v) &\implies \text{WriteReg}\left( R, (\text{ReadReg}(R) \mathbin{\&} \sim\text{Mask}(f)) \mathbin{|} ((v \mathbin{\ll} \text{Shift}(f)) \mathbin{\&} \text{Mask}(f)) \right)
  \end{aligned}
```

  5. Atomic Read-Modify-Write Invariants:
  For any atomic bit-manipulation mask $`m \le (1 \mathbin{\ll} (8 \times \text{sizeof}(R))) - 1`$:

```math
  \begin{aligned}
  \text{AtomicSetBits}(R, m) &\implies \text{atomic\_fetch\_or}(\text{RegAddress}(R), m) \\
  \text{AtomicClearBits}(R, m) &\implies \text{atomic\_fetch\_and}(\text{RegAddress}(R), \sim m) \\
  \text{AtomicToggleBits}(R, m) &\implies \text{atomic\_fetch\_xor}(\text{RegAddress}(R), m) \\
  \text{AtomicModifyField}(R, f, v) &\implies \text{CAS\_Loop}\left( \text{RegAddress}(R), \text{Mask}(f), (v \mathbin{\ll} \text{Shift}(f)) \mathbin{\&} \text{Mask}(f) \right)
  \end{aligned}
```

  6. Register Non-Overlap & Block Bounds Invariants:
  For any two distinct non-aliased registers $`R_i, R_j \in \mathcal{R}(B)`$` (`$`i \ne j`$):

```math
  \begin{aligned}
  \forall R_i, R_j \in \mathcal{R}(B), \ i \ne j \implies &[ \Delta_{\text{register}}(R_i), \Delta_{\text{register}}(R_i) + \text{sizeof}(R_i) - 1 ] \\
  &\cap [ \Delta_{\text{register}}(R_j), \Delta_{\text{register}}(R_j) + \text{sizeof}(R_j) - 1 ] = \emptyset
  \end{aligned}
```

  All registers reside strictly within the peripheral block boundary:

```math
  \forall R \in \mathcal{R}(B), \quad \Delta_{\text{register}}(R) + \text{sizeof}(R) \le \text{BlockSize}(B)
```

```math

  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

In contrast, REQ-0186 performs deterministic arithmetic checks on register alignment and bit ranges without symbolic reasoning, first-order quantifiers, or automated theorem proving.

  **Asymptotic Complexity Analysis**:
  Let $`N_V = |V_{\text{AST}}|`$` denote the aggregate AST node count, `$`N_B = |\mathcal{B}_{\text{peripheral}}|`$` denote the number of peripheral blocks, `$`N_R = |\mathcal{R}_{\text{registers}}|`$` denote the aggregate number of registers across all blocks, `$`N_F = |\mathcal{F}_{\text{fields}}|`$` denote the aggregate count of declared bitfields, and `$`N_{\text{bytes}} = \sum |B_k|`$ denote the total emitted header byte count.
  1. *AST Traversal & Register Node Extraction Phase*:
     - Traversal of lowered AST interconnect nodes, peripheral blocks, and register declarations executes in single-pass linear time:

```math
T_{\text{traversal}}(N_V) \in O(N_V), \quad S_{\text{traversal}} \in O(N_V)
```

  2. *Register Layout & Overlap Detection Phase*:
     - Sorting registers by relative offset $`\Delta_{\text{register}}(R)`$ within each peripheral block to verify natural alignment and absence of address overlaps executes in:

```math
T_{\text{layout}}(N_R) \in O(N_R \log N_R), \quad S_{\text{layout}} \in O(N_R)
```

     - When registers are ingested in ascending offset order from tabular schemas, overlap verification executes in strictly linear time $`O(N_R)`$.
  3. *Bitfield Geometry & Disjointness Validation Phase*:
     - Computing mask constants $`\text{Mask}(f)`$`, verifying width bounds (`$`\text{Shift} + \text{Width} \le 8 \times \text{sizeof}`$), and asserting bitfield disjointness executes in strictly linear time:

```math
T_{\text{bitfield}}(N_F) \in O(N_F), \quad S_{\text{bitfield}} \in O(N_F)
```

  4. *Header Formatting & Accessor Serialization Phase*:
     - Formatting C99/C++20 struct overlays, address macros, bitfield masks, volatile pointer accessors, and atomic RMW inline helpers executes in deterministic linear time:

```math
T_{\text{format}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{format}} \in O(1)
```

  5. *Streaming Artifact Sink Buffering (REQ-0177)*:
     - Streaming emitted header chunks through the abstract `StreamingArtifactSink` uses fixed-size memory chunk buffers bounded by $`B_{\text{max\_chunk\_size}} = 65{,}536\text{ bytes}`$:

```math
M_{\text{streaming}} \le B_{\text{max\_chunk\_size}} \in O(1)
```

  6. *Aggregate Execution Complexity*:
     - Summing across all phases, total wall-clock runtime is bounded by:

```math
T_{\text{total}} \in O(N_V + N_R \log N_R + N_F + N_{\text{bytes}})
```

     - Total space complexity is strictly $`O(N_V + N_R + N_F)`$ in contiguous bump arena storage, requiring zero individual heap allocations.
  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Distributing independent peripheral blocks across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool achieves near-linear speedup:

```math
T_{\text{parallel}} \in O\left( \frac{N_V + N_R \log N_R + N_F + N_{\text{bytes}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```
