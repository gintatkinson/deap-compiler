### REQ-0189: Atomic In-Place File Overwrite & Filesystem Metadata Lock Serialization Prevention

- **Normative Statement**: The file persistence engine, artifact emission pipeline, and filesystem interface of Subsystem 10 shall perform atomic in-place file overwrites when updating changed artifacts on disk, strictly bypassing temporary sibling file creation and atomic rename operations (`rename`, `MoveFileEx`) for existing files. When an emitted code artifact at canonical workspace-relative path $`p`$ exhibits content divergence relative to cached manifest records or previous compilation outputs, the persistence engine shall open the existing destination file directly with truncation write flags (`O_WRONLY | O_TRUNC`) and stream newly synthesized byte buffer $`B`$ directly into the existing filesystem inode. By overwriting in place, the persistence engine shall avoid acquiring exclusive write locks on the parent directory's metadata and directory index B-trees, thereby eliminating directory metadata lock contention and serialization bottlenecks across highly parallel worker threads on modern filesystems. When persisting newly created artifacts whose destination paths do not exist on disk, the engine shall create files directly using atomic creation flags (`O_WRONLY | O_CREAT | O_EXCL`) without intermediate temporary staging files, bounding directory metadata mutations to a single atomic entry insertion. If a destination path attempts directory traversal escaping the designated workspace root directory, if an I/O device write fails, or if post-write hash verification detects byte corruption, the compiler shall fail closed and emit diagnostic error code `E0500`.

  Specifically, the file persistence engine, multi-target backend code generators, and parallel emission workers shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **In-Place Overwrite Protocol & Directory Lock Serialization Elimination**:
     - When persisting an artifact to path $`p`$ where `FileExists(p) == true` and content has changed ($`\text{XXH3}_{64}(B) \ne \text{ManifestHash}(p)`$ per REQ-0178), the persistence engine shall open the file descriptor using truncation open flags (`O_WRONLY | O_TRUNC`).
     - Writing directly to an existing open file descriptor shall modify exclusively the file's own inode (block pointers, file size, and modification timestamp `mtime`).
     - The engine shall never create temporary sibling files (such as `path.tmp.XXXXXX`) or invoke directory rename operations (`rename`, `MoveFileEx`) when updating existing files.
     - Because POSIX and modern operating systems require only a shared read/lookup lock on the parent directory during path resolution for open existing operations, directory metadata write lock contention across parallel workers shall evaluate to identically zero ($`\text{DirectoryLockContention}(\text{InPlaceWrite}) \equiv 0`$).
  2. **File Inode Preservation & Directory B-Tree Invariance**:
     - Atomic in-place file overwrites shall preserve the invariant filesystem inode number of the target file: $`\text{inode}(p, t+1) = \text{inode}(p, t)`$.
     - Parent directory directory entries, directory index structures (such as HTrees, B-trees, and directory allocation tables), and directory inode modification timestamps shall remain strictly unmutated: $`\text{inode}(\text{dir}(p), t+1) = \text{inode}(\text{dir}(p), t)`$ and $`\text{TreeState}(\text{dir}(p), t+1) = \text{TreeState}(\text{dir}(p), t)`$.
     - Inode preservation shall guarantee that active external file watchers, build system indexers, integrated development environment handles, and memory-mapped file descriptors referencing path $`p`$ retain stable inode identities across recompilations without stale-handle errors.
  3. **Disjoint Path Concurrency & Work-Stealing Parallelism Contract**:
     - Concurrent worker threads executing on the bounded work-stealing thread pool (Directive 2, REQ-0012) shall operate on strictly disjoint, partitioned destination paths: $`\mathcal{P}_i \cap \mathcal{P}_j = \emptyset`$ for all workers $`i \ne j`$.
     - Because each worker thread locks only its assigned target file inode and bypasses parent directory write locks, worker threads writing concurrently into the same directory or sibling directory trees shall execute with complete filesystem-level independence, eliminating inter-thread serialization bottlenecks.
  4. **Direct Creation vs. In-Place Update Bifurcation**:
     - Prior to invoking open operations, the persistence engine shall evaluate destination file existence via filesystem status queries (`stat`):
       - *Existing File Branch (`FileExists(p) == true`)*: Invoke atomic in-place overwrite via `open(p, O_WRONLY | O_TRUNC, mode)`, modifying file content while preserving file inode;
       - *New File Branch (`FileExists(p) == false`)*: Invoke atomic file creation via `open(p, O_WRONLY | O_CREAT | O_EXCL, mode)`, creating the initial directory entry in a single atomic transaction without intermediate temporary file hops.
     - If concurrent file creation encounters an existing file due to external race conditions, the engine shall catch the collision, fall back to in-place truncation open, and complete the write safely.
  5. **Streaming I/O Integration & Bounded Chunk Buffering**:
     - In-place file persistence shall integrate directly with the abstract streaming artifact sink interface specified in REQ-0177.
     - Synthesized content byte slices shall stream into the destination file descriptor in bounded sequential chunks of capacity $`B_{\text{max\_chunk\_size}} = 65{,}536\text{ bytes}`$ ($`64\text{ KB}`$), ensuring strict constant auxiliary heap memory overhead $`O(1)`$ regardless of total file size $`|B|`$.
     - Following sequential chunk streaming, the engine shall ensure file length alignment via truncation (`ftruncate`) matching exact buffer length $`|B|`$ and flush buffers to underlying storage media.
  6. **Post-Write Verification & Content Digest Integrity**:
     - Upon completing an in-place overwrite, the persistence engine shall verify post-write file integrity by querying on-disk file size ($`\text{stat}(p).\text{size} == |B|`$) and confirming digest equality:

$$
\text{XXH3}_{64}(\text{ReadDiskBytes}(p), \text{seed}_0) == \text{XXH3}_{64}(B, \text{seed}_0)
$$

     - If byte length or content digest diverges, or if a write system call returns a short write or I/O error, the engine shall immediately record diagnostic `E0500` into error sink buffer $`\mathcal{D}_{\text{sink}}`$ and fail closed.
  7. **Contiguous Arena Allocation & Zero-Copy Memory Management**:
     - All in-memory filesystem descriptors, I/O buffer metadata, file path handles, and telemetry records shall reside in contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit arena node handles (REQ-0035).
  8. **Total-Function Error Propagation & Fail-Closed Diagnostics (`E0500`)**:
     - All persistence functions shall implement total-function contracts returning explicit `Result<(), Diagnostic>` status codes without panicking.
     - Destination paths shall be validated against workspace root confinement; any attempt to specify parent directory traversal tokens (`..`), leading slashes, or drive letters escaping the designated root shall be rejected immediately with diagnostic error code `E0500` (`PathTraversalSecurityViolation`).
     - Filesystem permission denials (`EACCES`, `EPERM`) and storage exhaustion (`ENOSPC`) shall be mapped deterministically to diagnostic error code `E0500` (`ArtifactPersistenceIOFailure`).
  9. **Enforcement of the 5 Executive Architectural Directives**:

Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Concurrent file persistence operations across multiple compilation units and output paths shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Relative destination paths, directory segments, and backend target labels shall be interned into the deduplicated global symbol interner pool during path normalization in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The file persistence engine shall implement synchronization token error recovery on artifact emission boundaries and file I/O loops in accordance with REQ-0013 and REQ-0016. If a write fault or permission error occurs on path $`p_k`$ (`E0500`), the engine shall record the diagnostic into preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$, isolate the fault, and proceed to process path $`p_{k+1}`$. If accumulated diagnostics reach capacity limit $`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: File persistence and in-place overwrite operations shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. File write latency (strictly under 25 ms for persisting $`10^4`$ code artifacts) and peak RSS memory (strictly under 100 MB RSS) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

- **Formal Invariant**: Let $`\mathcal{F} = \langle \mathcal{P}, \mathcal{I}, \mathcal{D}_{\text{tree}}, \mathcal{M}_{\text{inode}} \rangle`$ denote the state of the host filesystem, where $`\mathcal{P} \subset \mathcal{S}_{\text{intern}}`$ is the universe of normalized relative paths, $`\mathcal{I} \subset \mathbb{N}_{64}`$ is the set of allocated filesystem inode numbers, $`\mathcal{D}_{\text{tree}}`$ represents parent directory tree index structures (directory entries and B-tree balances), and $`\mathcal{M}_{\text{inode}} : \mathcal{I} \to \langle \text{size}, \text{mtime}, \text{blocks} \rangle`$ maps inodes to physical block allocation metadata.

  Let $`\text{dir} : \mathcal{P} \to \mathcal{P}`$ denote the parent directory projection function, and let $`\text{inode} : \mathcal{P} \times \mathcal{F} \to \mathcal{I}`$ map a path to its active inode number.

  1. Directory Metadata Contention Formalization:
  Let $`\text{LockMode}(\text{res}, \text{op}) \in \{ \text{None}, \text{SharedRead}, \text{ExclusiveWrite} \}`$ denote the locking requirement on a filesystem resource $`\text{res}`$ during operation $`\text{op}`$.

  For a traditional temporary-sibling-file-and-rename operation $`\text{Op}_{\text{temp\_rename}}(p, B)`$:

$$
  \begin{aligned}
  \text{LockMode}(\text{dir}(p), \text{Op}_{\text{temp\_rename}}) &= \text{ExclusiveWrite} \\
  \text{DirectoryLockContention}(\text{Op}_{\text{temp\_rename}}, N_{\text{workers}}) &\in \Theta(N_{\text{workers}})
  \end{aligned}
$$

  In contrast, the atomic in-place overwrite operation $`\text{Op}_{\text{in\_place}}(p, B)`$ executes directly against the existing file descriptor:

$$
  \begin{aligned}
  \text{LockMode}(\text{dir}(p), \text{Op}_{\text{in\_place}}) &= \text{SharedRead} \\
  \text{LockMode}(\text{inode}(p), \text{Op}_{\text{in\_place}}) &= \text{ExclusiveWrite} \\
  \text{DirectoryLockContention}(\text{Op}_{\text{in\_place}}, N_{\text{workers}}) &\equiv 0
  \end{aligned}
$$

  2. In-Place File Overwrite Semantics:
  For an artifact destined for path $`p \in \mathcal{P}`$ with synthesized content byte sequence $`B \in \Sigma^*`$ where $`\text{FileExists}(p) \equiv \text{true}`$:

$$
  \text{Update}(p, B) = \text{OpenFile}(p, \text{O\_WRONLY} \mid \text{O\_TRUNC}).\text{write}(B)
$$

  3. Inode & Parent Directory Invariance Contract:
  Let $`t`$ denote the timestamp immediately preceding the update operation, and let $`t+1`$ denote the timestamp immediately following successful completion:

$$
  \begin{aligned}
  \text{inode}(p, \mathcal{F}_{t+1}) &= \text{inode}(p, \mathcal{F}_t) \\
  \text{inode}(\text{dir}(p), \mathcal{F}_{t+1}) &= \text{inode}(\text{dir}(p), \mathcal{F}_t) \\
  \mathcal{D}_{\text{tree}}(\text{dir}(p), \mathcal{F}_{t+1}) &= \mathcal{D}_{\text{tree}}(\text{dir}(p), \mathcal{F}_t)
  \end{aligned}
$$

  While target file metadata updates its size and modification timestamp:

$$
  \begin{aligned}
  \text{size}(\text{inode}(p), \mathcal{F}_{t+1}) &= |B| \\
  \text{mtime}(\text{inode}(p), \mathcal{F}_{t+1}) &\ge t
  \end{aligned}
$$

  4. Disjoint Path Parallel Independence Invariant:
  Let $`\mathcal{W} = \{ W_1, W_2, \dots, W_m \}`$ denote $`m`$ worker threads running concurrently on the bounded work-stealing thread pool ($`m \le N_{\text{max\_workers}}`$).
  Each worker $`W_j`$ is assigned a disjoint path subset $`\mathcal{P}_j \subset \mathcal{P}`$:

$$
  \forall j \ne k, \quad \mathcal{P}_j \cap \mathcal{P}_k = \emptyset
$$

  The set of write locks acquired by worker $`W_j`$ during in-place overwrite is restricted strictly to target file inodes:

$$
  \text{WriteLockSet}(W_j) = \{ \text{inode}(p) \mid p \in \mathcal{P}_j \}
$$

  Because paths and inodes are disjoint, concurrent write lock sets are mutually disjoint:

$$
  \forall j \ne k, \quad \text{WriteLockSet}(W_j) \cap \text{WriteLockSet}(W_k) = \emptyset
$$

  yielding zero lock contention, zero thread blocking, and true linear concurrency scaling at the filesystem layer.

  5. Bifurcated Persistence Operator Formulation:
  The complete file persistence operator $`\Phi_{\text{persist}} : (\mathcal{P} \times \Sigma^*) \to \text{Result}(\mathcal{I}, \text{Diagnostic})`$ is defined piecewise:

$$
  \Phi_{\text{persist}}(p, B) = \begin{cases}
  \text{InPlaceOverwrite}(p, B), & \text{if } \text{FileExists}(p) \equiv \text{true} \\
  \text{DirectAtomicCreate}(p, B), & \text{if } \text{FileExists}(p) \equiv \text{false}
  \end{cases}
$$

  where:

$$
  \begin{aligned}
  \text{InPlaceOverwrite}(p, B) &= \text{OpenFile}(p, \text{O\_WRONLY} \mid \text{O\_TRUNC}).\text{write}(B) \\
  \text{DirectAtomicCreate}(p, B) &= \text{OpenFile}(p, \text{O\_WRONLY} \mid \text{O\_CREAT} \mid \text{O\_EXCL}, \text{mode}).\text{write}(B)
  \end{aligned}
$$

  6. Streaming Chunk Decomposition & Bounded Buffer Invariant:
  For an artifact $`B`$ partitioned into $`n = \lceil |B| / B_{\text{max\_chunk\_size}} \rceil`$ sequential byte chunks $`\langle \beta_1, \beta_2, \dots, \beta_n \rangle`$:

$$
  \text{write}(B) = \bigodot_{i=1}^n \text{WriteChunk}(\text{fd}, \beta_i)
$$

  where $`\bigodot`$ denotes sequential I/O composition, and resident memory at any step $`i`$ satisfies:

$$
  \forall i \in \{1, \dots, n\}, \quad M_{\text{buffer}}(i) \le B_{\text{max\_chunk\_size}} = 65{,}536\text{ bytes} \in O(1)
$$

  7. Post-Write Content & Hash Verification Invariant:
  Upon completion of file write and flush operations:

$$
  \text{PostWriteValid}(p, B) \iff (\text{FileSize}(p) = |B|) \wedge (\text{XXH3}_{64}(\text{ReadDiskBytes}(p), \text{seed}_0) = \text{XXH3}_{64}(B, \text{seed}_0))
$$

  8. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):
  Every file persistence transaction binds an immutable deterministic RFC 4122 UUIDv5 identifier:

$$
  \Delta_{\text{persist}}(p) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(A) \mathbin{\Vert} \text{"::FilePersistence::"} \mathbin{\Vert} p)
$$

- **Computational Complexity & Algorithmic Bounds**: Atomic In-Place File Overwrite and Filesystem Metadata Lock Serialization Prevention resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in deterministic linear time $`O(|B_k|)`$ per changed artifact $`A_k`$ and deterministic linear time $`O(N_{\text{bytes}})`$ across the aggregate emission pass of $`K`$ artifacts, where $`N_{\text{bytes}} = \sum_{k=1}^K |B_k|`$ is the total number of synthesized artifact bytes, and strict constant auxiliary memory $`O(1)`$ per active writer sink.

  **Algorithmic Breakdown & Asymptotic Bounds**:
  Let $`K`$ denote the total number of changed artifacts, and let $`N_{\text{bytes}} = \sum_{k=1}^K |B_k|`$ denote total written bytes.
  1. *Destination Path Validation & Status Check Phase*:

$$

     - Querying filesystem metadata (`stat`) executes in $`O(1)`$ amortized operating system system call time:

  2. *File Inode Open & Truncation Phase*:

$$
T_{\text{open}}(p) \in O(1), \quad S_{\text{open}}(p) \in O(1)

  3. *Streaming Chunked Write & Flush Phase*:
     - Writing byte buffer $`B_k`$ in $`64\text{ KB}`$ chunks ($`B_{\text{max\_chunk\_size}}`$) invokes $`\lceil |B_k| / B_{\text{max\_chunk\_size}} \rceil`$ write system calls:

$$
T_{\text{write}}(B_k) \in O(|B_k|), \quad S_{\text{write}}(B_k) \le B_{\text{max\_chunk\_size}} \in O(1)

$$
T_{\text{write\_total}} = \sum_{k=1}^K T_{\text{write}}(B_k) \in O(N_{\text{bytes}})

  4. *Post-Write Size & Hash Verification Phase*:
     - Inspecting post-write file size and streaming the file bytes to compute $`\text{XXH3}_{64}`$ executes in linear time proportional to buffer size:

$$
T_{\text{verify}}(B_k) \in O(|B_k|), \quad S_{\text{verify}}(B_k) \in O(1)
$$

  5. *Parallel Work-Stealing Scaling & Serialization Elimination (Directive 2)*:
     - Under traditional temporary-sibling-and-rename writes, directory lock serialization causes queueing delay scaling as $`O(K \cdot N_{\text{max\_workers}})`$ on directory metadata locks.

$$
T_{\text{parallel}}(N_{\text{bytes}}, N_{\text{max\_workers}}) \in O\left( \frac{N_{\text{bytes}}}{N_{\text{max\_workers}}} + K \right)
$$

     - Auxiliary space overhead across all active worker threads remains strictly bounded:

$$
S_{\text{parallel}}(N_{\text{max\_workers}}) \le N_{\text{max\_workers}} \cdot B_{\text{max\_chunk\_size}} \in O(1)
