### REQ-0073: SysML v2 ItemDefinition (`item def`) & ItemUsage (`item`) Lowering

- **Normative Statement**: The data and flow modeling engine and semantic metamodel lowering pipeline shall formalize SysML v2 `ItemDefinition` (`item def`) declarations as structural classifiers specializing KerML `Structure`, and SysML v2 `ItemUsage` (`item`) declarations as physical, energetic, or informational payloads flowing across interconnection topologies, residing within structural part stores, or passing as functional parameter bindings under explicit value or token identity semantics.

  The compiler shall strictly partition all item definitions into two mutually disjoint semantic classification categories under denotational subtyping semantics:
  1. **Pure Value Payloads ($`\mathcal{I}_{\text{val}}`$)**: Structural item classifiers specializing KerML `DataType` ($`\text{ItemDef} \le \text{DataType}`$). Pure value payloads shall possess immutable, stateless semantics without distinct object identity. Instance equivalence shall be evaluated strictly via structural value congruence ($`a \equiv_{\text{val}} b`$), wherein two instances are equal if and only if all corresponding feature projections evaluate to equivalent values. Value payloads are copyable, combinable, and transmittable across flow boundaries without creating or destroying identity tokens.
  2. **Discrete Physical or Token Payloads ($`\mathcal{I}_{\text{token}}`$)**: Structural item classifiers specializing KerML `Class` ($`\text{ItemDef} \le \text{Class}`$) with extensional identity semantics. Discrete token payloads represent physical matter, discrete energy packets, serialized objects, or transactional tokens tracking an immutable, unique token identity ($`\text{id}_{\text{token}}(e)`$) throughout their lifecycle. Instance equivalence shall be evaluated strictly via extensional token identity ($`u = v \iff \text{id}_{\text{token}}(u) = \text{id}_{\text{token}}(v)`$). Tokens cannot be created ex nihilo or duplicated across split paths without explicit cloning or generation semantics.

  The compiler shall enforce strict disjointness between value payloads and discrete token payloads ($`\llbracket \text{DataType} \rrbracket \cap \llbracket \text{Class} \rrbracket = \emptyset`$). Any `item def` declaration attempting multiple generalization spanning both `DataType` and `Class`, or any attempt to attach mutable state or lifecycle behaviors to a pure value item, shall be deterministically rejected at compile time with structured diagnostic error code `E0200` in accordance with REQ-0191.

  The compiler shall formalize `item` usages as typed feature occurrences bound to an owning classifier context (such as a part definition, action definition, interface definition, port definition, or package). When the multiplicity interval $`\mu(u) = [m_{\min}, m_{\max}]`$ is omitted from an item usage declaration, the lowering engine shall inject the canonical singleton default multiplicity $`\mu(u) = [1, 1]`$. Item usages may declare subsetting (`:>`) or redefinition (`:>>`) relationships conforming to the subtyping rules of REQ-0061 and REQ-0062: the subsetting item usage must preserve co-variant type specialization ($`\tau(u_{\text{sub}}) \le \tau(u_{\text{sup}})`$) and multiplicity interval narrowing ($`\mu(u_{\text{sub}}).m_{\max} \le \mu(u_{\text{sup}}).m_{\max}`$ and $`\mu(u_{\text{sub}}).m_{\min} \le \mu(u_{\text{sup}}).m_{\max}`$). Attempting to type an `item` usage with a non-item classifier (such as a bare behavioral action or raw interface definition) or declaring incompatible subsetting shall emit diagnostic error code `E0200`. Generalization cycles within item definition inheritance graphs ($`D_1 \le D_2 \le \dots \le D_1`$) shall be detected and rejected deterministically with diagnostic error code `E0203`.

  For conservative continuous or discrete flow networks, the compiler shall enforce payload quantity conservation across flow junctions and interconnect topologies. For any junction node where conservative flow items pass without internal net storage accumulation ($`\frac{d S}{dt} = 0`$), the total incoming flow payload throughput must strictly equal the total outgoing flow payload throughput ($`\sum \text{inflow} = \sum \text{outflow}`$). Any unbalanced conservative flow junction lacking explicit source, sink, or accumulation dynamics shall be rejected deterministically at compile time with diagnostic error code `E0202` (or `E0300` in physical metrology contexts).

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered item definition node and item usage node allocated in the contiguous AST arena shall be bound to an immutable, bitwise deterministic RFC 4122 UUIDv5 identifier ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(e))`$) derived from the compiler namespace OID and canonical fully qualified path per REQ-0010. Time-based identifiers are strictly prohibited.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel parsing, lowering, and subtyping validation of item definitions across independent package compilation units shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
  - *Directive 3 (String Interner Memory Allocation Exception)*: String bytes representing item names, documentation tokens, and qualified symbol paths shall be copied into the global symbol interner pool during the initial lexical pass to yield scalar `SymbolId` tokens per REQ-0036, constituting the sole permitted exception to zero-copy memory management.
  - *Directive 4 (Synchronization Token Error Recovery)*: The parser and lowering engine shall implement synchronization token error recovery on declaration and delimiter boundaries (e.g., `;`, `}`, `end`) per REQ-0013 and REQ-0016. Upon encountering a malformed item declaration, the engine shall record diagnostic `E0200`, `E0202`, or `E0203` into the diagnostic sink, bind a typed error sentinel ($`\bot_{\text{item\_def}}`$ or $`\bot_{\text{item\_usage}}`$) to the faulted AST node, and continue processing subsequent declarations without aborting. If accumulated diagnostics reach the sink bound $`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and gracefully halt.
  - *Directive 5 (Panic-Free Release Isolation)*: The lowering engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all valid and malformed inputs per REQ-0011 and REQ-0196. Latency ($`\lt 25\text{ ms}`$ for $`10^4`$ item elements) and peak memory RSS ($`\lt 100\text{ MB}`$ RSS) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `ItemDef_Alpha`, `ItemDef_Beta`, `ItemDef_Val`, `ItemDef_Tok`, `ItemUsage_0`, `ItemUsage_1`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{arena}} \subset \mathbb{N}_{32}`$ denote the universe of 32-bit contiguous arena node handles. The set of item definition nodes $`\mathcal{C}_{\text{item}} \subset \mathcal{V}_{\text{arena}}`$ and the set of item usage nodes $`\mathcal{U}_{\text{item}} \subset \mathcal{V}_{\text{arena}}`$ are disjoint subsets of allocated AST nodes.

  Each item definition $`D \in \mathcal{C}_{\text{item}}`$ is formalized as an 8-tuple:

$$
D = \langle \text{id}_D, \text{name}_D, \kappa_D, \mathcal{S}_D, \mathcal{F}_D, \gamma_D, \Delta_D, \text{span}_D \rangle
$$

  where:

$$
\begin{aligned}
\text{id}_D &\in \mathcal{V}_{\text{arena}} \quad (\text{monotonic 32-bit contiguous arena handle}) \\
\text{name}_D &\in \mathcal{S}_{\text{intern}} \quad (\text{interned scalar symbol identifier}) \\
\kappa_D &\in \{ \text{ValueItem}, \text{TokenItem} \} \quad (\text{classification duality discriminant}) \\
\mathcal{S}_D &\subseteq \mathcal{C}_{\text{item}} \cup \{ \text{Structure}, \text{DataType}, \text{Class} \} \quad (\text{direct supertypes}) \\
\mathcal{F}_D &\subseteq \mathcal{U}_{\text{feat}} \quad (\text{owned feature definitions and usages}) \\
\gamma_D &\in \mathbb{B} \quad (\text{conservative flow payload flag}) \\
\Delta_D &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_D &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance span})
\end{aligned}
$$

  Each item usage $`u \in \mathcal{U}_{\text{item}}`$ is formalized as an 8-tuple:

$$
u = \langle \text{id}_u, \text{name}_u, \text{owner}_u, \tau(u), \mu(u), \mathcal{S}_u, \Delta_u, \text{span}_u \rangle
$$

  where:

$$
\begin{aligned}
\text{id}_u &\in \mathcal{V}_{\text{arena}} \quad (\text{monotonic 32-bit contiguous arena handle}) \\
\text{name}_u &\in \mathcal{S}_{\text{intern}} \cup \{ \bot \} \quad (\text{interned symbol or anonymous usage}) \\
\text{owner}_u &\in \mathcal{V}_{\text{arena}} \quad (\text{enclosing classifier or feature node handle}) \\
\tau(u) &\in \mathcal{C}_{\text{item}} \setminus \{ \bot_{\text{item\_def}} \} \quad (\text{authoritative item definition classifier}) \\
\mu(u) &= [m_{\min}(u), m_{\max}(u)] \subseteq \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \}) \quad (\text{multiplicity interval}) \\
\mathcal{S}_u &\subseteq \mathcal{U}_{\text{item}} \quad (\text{set of directly subsetted item usages}) \\
\Delta_u &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_u &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance span})
\end{aligned}
$$

  KerML Structure Specialization Invariant: Every item definition shall specialize KerML `Structure` in the subtyping partial order $`(\mathcal{K}, \le)`$:

$$
\forall D \in \mathcal{C}_{\text{item}}, \quad D \le \text{Structure}
$$

  Classification Duality Partition Invariant: The universe of item definitions is partitioned into pure value payloads $`\mathcal{I}_{\text{val}}`$ and discrete token payloads $`\mathcal{I}_{\text{token}}`$:

$$
\mathcal{C}_{\text{item}} = \mathcal{I}_{\text{val}} \cup \mathcal{I}_{\text{token}}, \quad \mathcal{I}_{\text{val}} \cap \mathcal{I}_{\text{token}} = \emptyset
$$

  where:

$$
\begin{aligned}
\mathcal{I}_{\text{val}} &= \{ D \in \mathcal{C}_{\text{item}} \mid D \le \text{DataType} \;\wedge\; D \not\le \text{Class} \;\wedge\; \kappa_D = \text{ValueItem} \} \\
\mathcal{I}_{\text{token}} &= \{ D \in \mathcal{C}_{\text{item}} \mid D \le \text{Class} \;\wedge\; D \not\le \text{DataType} \;\wedge\; \kappa_D = \text{TokenItem} \}
\end{aligned}
$$

  Instance Equivalence Invariant:
  1. For pure value items ($`D \in \mathcal{I}_{\text{val}}`$), equivalence over semantic instance denotations $`\llbracket D \rrbracket`$ evaluates via structural value congruence:

$$
\forall a, b \in \llbracket D \rrbracket, \quad a = b \iff a \equiv_{\text{val}} b \iff \left( \forall f \in \mathcal{F}_D, \, \pi_f(a) \equiv_{\text{val}} \pi_f(b) \right)
$$

  2. For discrete token items ($`D \in \mathcal{I}_{\text{token}}`$), equivalence evaluates strictly via unique extensional token identity:

$$
\forall u, v \in \llbracket D \rrbracket, \quad u = v \iff \text{id}_{\text{token}}(u) = \text{id}_{\text{token}}(v)
$$

  Multiplicity Interval Well-Formedness and Default Injection:

$$
\forall u \in \mathcal{U}_{\text{item}}, \quad 0 \le \mu(u).m_{\min} \le \mu(u).m_{\max} \;\wedge\; \mu(u).m_{\max} \ge 1
$$

$$
\text{unspecified}(\mu(u)) \implies \mu(u) = [1, 1]
$$

  Item Usage Subsetting Invariant: For every subsetting declaration $`(u_{\text{sub}}, u_{\text{sup}}) \in \mathcal{R}_{\text{subset\_item}}`$:

$$
\begin{aligned}
\tau(u_{\text{sub}}) &\le \tau(u_{\text{sup}}) \\
\mu(u_{\text{sub}}).m_{\max} &\le \mu(u_{\text{sup}}).m_{\max} \\
\mu(u_{\text{sub}}).m_{\min} &\le \mu(u_{\text{sup}}).m_{\max}
\end{aligned}
$$

  Conservative Flow Kirchhoff Balance Invariant: Let $`\mathcal{N}_{\text{junction}}`$ denote the set of conservative flow junctions, and let $`\mathcal{E}_{\text{in}}(j)`$ and $`\mathcal{E}_{\text{out}}(j)`$ denote incident input and output flow channels carrying an item usage $`u`$ of conservative type $`\tau(u)`$ with $`\gamma_{\tau(u)} \equiv \text{true}`$. In steady-state ($`\frac{d S(j)}{dt} = 0`$):

$$
\forall j \in \mathcal{N}_{\text{junction}}, \quad \sum_{e \in \mathcal{E}_{\text{in}}(j)} Q(e) = \sum_{e \in \mathcal{E}_{\text{out}}(j)} Q(e)
$$

  Generalization Acyclicity Invariant: Let $`G_{\text{item}} = (\mathcal{C}_{\text{item}}, \mathcal{E}_{\text{gen}})`$ be the directed generalization graph where $`(D_a, D_b) \in \mathcal{E}_{\text{gen}} \iff D_b \in \mathcal{S}_{D_a}`$. The graph shall be strictly acyclic:

$$
\forall D \in \mathcal{C}_{\text{item}}, \quad (D, D) \notin \mathcal{E}_{\text{gen}}^+
$$

  Deterministic RFC 4122 UUIDv5 Topological Anchoring:

$$
\begin{aligned}
\forall D \in \mathcal{C}_{\text{item}}, &\quad \Delta_D = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(D)) \\
\forall u \in \mathcal{U}_{\text{item}}, &\quad \Delta_u = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))
\end{aligned}
$$

  Diagnostic Code Trigger Invariants: Violations of metamodel, typing, duality, or conservation constraints deterministically trigger structured diagnostics in accordance with REQ-0191:

$$
\begin{aligned}
(\exists D \in \mathcal{C}_{\text{item}} : D \le \text{DataType} \;\wedge\; D \le \text{Class}) &\implies \text{Diagnostic}(D, \text{DiagnosticCode::E0200}, \text{IncompatibleItemClassificationDuality}) \in \mathcal{D}_{\text{sink}} \\
(\exists u \in \mathcal{U}_{\text{item}} : \tau(u) \not\le \text{Structure}) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{InvalidItemUsageTyping}) \in \mathcal{D}_{\text{sink}} \\
(\exists (u_{\text{sub}}, u_{\text{sup}}) : \tau(u_{\text{sub}}) \not\le \tau(u_{\text{sup}})) &\implies \text{Diagnostic}(u_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{SubsettingTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
(\exists (u_{\text{sub}}, u_{\text{sup}}) : \mu(u_{\text{sub}}).m_{\max} \gt \mu(u_{\text{sup}}).m_{\max}) &\implies \text{Diagnostic}(u_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{SubsettingMultiplicityViolation}) \in \mathcal{D}_{\text{sink}} \\
(\exists j \in \mathcal{N}_{\text{junction}} : \sum Q_{\text{in}} \ne \sum Q_{\text{out}}) &\implies \text{Diagnostic}(j, \text{DiagnosticCode::E0202}, \text{UnbalancedConservativeFlowJunction}) \in \mathcal{D}_{\text{sink}} \\
(\exists D \in \mathcal{C}_{\text{item}} : (D, D) \in \mathcal{E}_{\text{gen}}^+) &\implies \text{Diagnostic}(D, \text{DiagnosticCode::E0203}, \text{CircularItemGeneralization}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: SysML v2 item definition lowering, classification duality partitioning, and item usage subtyping validation execute strictly within Complexity Class $`\mathbf{P}`$.

  **Asymptotic Verification Bounds**: For a model unit containing $`V = |\mathcal{C}_{\text{item}}| + |\mathcal{U}_{\text{item}}|`$ nodes and $`E = |\mathcal{E}_{\text{gen}}| + |\mathcal{R}_{\text{subset\_item}}|`$ edges:
  1. *Item Allocation and Symbol Interning*: Allocating AST nodes into contiguous typed bump arena memory and interning symbol strings into the global symbol interner pool executes in amortized $`O(1)`$ time per node, totaling $`O(V)`$ time.
  2. *Classification Duality Evaluation*: Partitioning an item definition into $`\mathcal{I}_{\text{val}}`$ or $`\mathcal{I}_{\text{token}}`$ executes via scalar discriminant checks or precomputed reachability bitmask checks in deterministic $`O(1)`$ time.
  3. *Subtyping Poset Reachability*: Evaluating $`\tau(u) \le \text{Structure}`$ or $`\tau(u_{\text{sub}}) \le \tau(u_{\text{sup}})`$ executes in $`O(1)`$ time using precomputed subtyping reachability bitsets, or in bounded $`O(h)`$ time where inheritance hierarchy depth $`h \le 32`$.
  4. *Multiplicity Interval Verification*: Validating $`\mu(u).m_{\min} \le \mu(u).m_{\max}`$ and subsetting multiplicity narrowing executes in strictly $`O(1)`$ scalar integer comparisons per usage edge.
  5. *Generalization Cycle Detection (Tarjan's SCC)*: Detecting circular inheritance cycles over $`(\mathcal{C}_{\text{item}}, \mathcal{E}_{\text{gen}})`$ executes in deterministic $`O(V + E)`$ time.
  6. *Conservative Flow Kirchhoff Balance Verification*: For a flow network with $`N_{\text{junc}}`$ junctions and $`E_{\text{flow}}`$ channels, verifying $`\sum Q_{\text{in}} = \sum Q_{\text{out}}`$ requires summing incident flow rates across each junction in $`O(\text{deg}(j))`$ time, executing in total linear time $`O(N_{\text{junc}} + E_{\text{flow}})`$.

  Total sequential lowering and validation time is strictly linear in model complexity:

$$
T_{\text{validate}}(V, E) \in O(V + E)
$$

  **Parallel Work-Stealing Scaling (Architectural Directive 2)**: When subtyping validation across disjoint package scopes is scheduled on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

$$
T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{V + E}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  **Space Complexity & Memory Bounds**: Auxiliary memory is bounded by $`O(V + E)`$ contiguous arena storage. Transitive subtyping bitsets require at most $`O(V \cdot \lceil V / 64 \rceil)`$ bits, reducing to $`O(V)`$ for hierarchical sparse trees. Traversal call stacks are bounded by recursion depth $`O(h) \le 32`$ frames ($`O(1)`$ auxiliary stack space). The diagnostic error sink is bounded by $`O(C_{\text{max\_errors}}) = O(1)`$ allocated memory.

- **Verification & Conformance Criteria**: Deterministic conformance shall be verified by automated test suites operating on synthetic MBSE models containing abstract placeholders (`Package_0`, `ItemDef_Alpha`, `ItemDef_Beta`, `ItemDef_Val`, `ItemDef_Tok`, `ItemUsage_0`, `ItemUsage_1`, `Port_1`, `Flow_A`, `param_x : Real`). Conformance validation shall enforce the following deterministic test gates:
  1. **Canonical `item def` Lowering Gate**: Declare `item def ItemDef_Alpha`. Verify that the lowering engine produces a valid AST node handle, confirms KerML specialization $`\text{ItemDef\_Alpha} \le \text{Structure}`$, assigns a valid RFC 4122 UUIDv5 anchor, and emits zero diagnostics.
  2. **Pure Value Payload Classification Gate**: Declare `item def ItemDef_Val :> DataType`. Assert that the type checker classifies `ItemDef_Val` into $`\mathcal{I}_{\text{val}}`$, confirms value congruence equivalence semantics, verifies immutability, and confirms absence of token identity.
  3. **Discrete Token Payload Classification Gate**: Declare `item def ItemDef_Tok :> Class`. Assert that the type checker classifies `ItemDef_Tok` into $`\mathcal{I}_{\text{token}}`$, binds extensional token identity tracking $`\text{id}_{\text{token}}`$, and enforces token uniqueness.
  4. **Classification Duality Disjointness Violation Gate (`E0200`)**: Attempt to declare an item definition inheriting from both `DataType` and `Class` (`item def ItemDef_Conflict :> DataType, Class`). Assert deterministic rejection with diagnostic error code `E0200` (`IncompatibleItemClassificationDuality`), assignment of error sentinel $`\bot_{\text{item\_def}}`$, and zero compiler panics.
  5. **Canonical `item` Usage Lowering Gate**: Within an owning structure, declare `item ItemUsage_0 : ItemDef_Alpha [1..5]`. Verify valid arena allocation, owner resolution, type binding $`\tau(\text{ItemUsage\_0}) = \text{ItemDef\_Alpha}`$, multiplicity interval $`[1, 5]`$, and deterministic UUIDv5 anchor.
  6. **Default Multiplicity Injection Gate**: Declare `item ItemUsage_1 : ItemDef_Alpha` without explicit multiplicity brackets. Verify that the lowering engine automatically injects the canonical default singleton multiplicity interval $`\mu = [1, 1]`$.
  7. **Item Usage Subsetting Gate (`:>`)**: Declare `item ItemUsage_Sub :> ItemUsage_Sup : ItemDef_Beta [1..2]` where `ItemDef_Beta :> ItemDef_Alpha` and `ItemUsage_Sup` has multiplicity $`[1..5]`$. Verify that co-variant subtyping and multiplicity narrowing succeed with zero diagnostics.
  8. **Item Usage Subsetting Multiplicity Violation Gate (`E0200`)**: Declare `item ItemUsage_Sub :> ItemUsage_Sup` with widened multiplicity $`[0..10]`$ over superset $`[1..5]`$. Assert deterministic compile-time rejection with diagnostic error code `E0200`.
  9. **Invalid Item Usage Typing Gate (`E0200`)**: Attempt to declare an `item` usage typed by a non-item/non-structure classifier (such as a bare behavioral action or raw interface definition). Assert deterministic rejection with diagnostic error code `E0200` (`InvalidItemUsageTyping`).
  10. **Conservative Flow Kirchhoff Balance Gate**: Construct a flow junction with an incoming flow channel carrying conservative item `ItemDef_Alpha` at rate $`Q_{\text{in}} = 10.0`$ and two outgoing flow channels with rates $`Q_{\text{out\_1}} = 6.0`$ and $`Q_{\text{out\_2}} = 4.0`$. Verify that flow conservation evaluates to true with zero diagnostics.
  11. **Unbalanced Conservative Flow Rejection Gate (`E0202`)**: Construct an unbalanced flow junction carrying conservative item `ItemDef_Alpha` with $`Q_{\text{in}} = 10.0`$ and $`Q_{\text{out}} = 8.0`$ without storage accumulation. Assert deterministic compile-time rejection with diagnostic error code `E0202` (`UnbalancedConservativeFlowJunction`).
  12. **Circular Item Generalization Detection Gate (`E0203`)**: Declare a cyclic generalization chain `item def ItemDef_A :> ItemDef_B` and `item def ItemDef_B :> ItemDef_A`. Assert that cycle detection deterministically identifies the recursion and emits diagnostic error code `E0203` (`CircularItemGeneralization`) with exact source byte spans.
  13. **Synchronization Token Recovery & Error Accumulation Gate (Architectural Directive 4)**: Ingest a model file containing 5 distinct malformed item declarations interspersed with valid code. Verify that the lowering engine resynchronizes on delimiter boundaries, accumulates all 5 diagnostics (`E0200`), and halts gracefully with terminal diagnostic `E0199` when the error count reaches $`C_{\text{max\_errors}}`$.
  14. **Deterministic UUIDv5 Anchor Gate (Architectural Directive 1)**: Verify that 100% of lowered item definition and item usage AST nodes bind valid RFC 4122 UUIDv5 identifiers deterministically computed from the compiler namespace OID and canonical fully qualified paths.
  15. **Release Mode Latency & Memory Budget Gate (Architectural Directive 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, assert that lowering and validating $`10^5`$ synthetic item definitions and usages executes in under 25 ms, peak RSS memory remains strictly under 100 MB, and consecutive compilation runs exhibit bitwise determinism with 0-byte diff churn.
