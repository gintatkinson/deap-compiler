### REQ-0188: SMT-LIB2 / Z3 First-Order Constraint Encoding & Proof Framework Generation

- **Normative Statement**: The code generation engine, formal verification backend, and SMT-LIB2 synthesis pipeline of Subsystem 10 shall translate formal abstract syntax tree (AST) constraints, discrete state machine transitions, numerical calculation invariants, parametric operational envelopes, and formal safety contracts into standardized, reproducible SMT-LIB2 (`.smt2`) benchmark scripts targeting first-order Satisfiability Modulo Theories (SMT) automated theorem provers and solvers such as Z3, CVC5, and MathSAT. The compiler shall synthesize syntactically and semantically valid SMT-LIB2 scripts adhering strictly to the SMT-LIB Standard: Version 2.6. The emission backend shall restrict synthesized proof obligations strictly to decidable quantifier-free first-order logic theories, including Quantifier-Free Linear Real Arithmetic (`QF_LRA`), Quantifier-Free Linear Integer Arithmetic (`QF_LIA`), Quantifier-Free with Uninterpreted Functions and Linear Arithmetic (`QF_UFLRA`, `QF_UFLIA`), Quantifier-Free Uninterpreted Functions (`QF_UF`), and Quantifier-Free Fixed-Size Bitvectors (`QF_BV`). If any AST constraint or proof obligation incorporates non-linear arithmetic terms ($`x \cdot y`$` between indeterminate variables), transcendental function applications (`$`\sin, \cos, \exp, \ln`$`), or unsupported alternating quantifiers (`$`\forall, \exists`$), the compiler shall reject the malformed construct and emit diagnostic error code `E0406` or `E0500`.

  The emission engine shall formulate safety and invariant verification obligations using refutational semantics, asserting the conjunction of the system model $`\mathcal{M}_{\text{sys}}`$` and the logical negation of the target safety invariant `$`\neg \mathcal{I}_{\text{safe}}`$, such that proving the unsatisfiability (`UNSAT`) of the conjunction certifies universal satisfaction of the invariant across all admissible system executions ($`\text{UNSAT}(\mathcal{M}_{\text{sys}} \wedge \neg \mathcal{I}_{\text{safe}}) \iff \text{Valid}(\mathcal{I}_{\text{safe}})`$`). The synthesis pipeline shall synthesize dual proof obligations comprising both initial state induction base cases and transition consecution inductive steps, as well as bounded model unrolling scripts (`$`\Phi_k`$) for bounded horizon reachability checks. The backend shall emit standard solver commands, including `(set-logic ...)`, `(set-option :produce-models true)`, `(set-option :produce-proofs true)`, `(check-sat)`, `(get-model)`, and `(get-unsat-core)`.

  Specifically, the code generation engine, verification backend, and SMT-LIB2 synthesis pipeline shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **SMT-LIB Standard Version 2.6 Conformance & Theory Partitioning**:
     - The emitted scripts shall conform strictly to the SMT-LIB Standard Version 2.6 concrete syntax.
     - Every emitted benchmark script shall declare an explicit, minimal background theory logic via `(set-logic <LOGIC>)` matching the underlying constraint algebra:
       * `QF_LRA` for pure real-valued linear systems, flow conservation networks, and continuous operational envelopes.
       * `QF_LIA` for discrete integer state counters, token registers, and discrete step bounds.
       * `QF_UFLRA` / `QF_UFLIA` for hybrid models combining uninterpreted structural relations with linear arithmetic.
       * `QF_BV` for Level 1C Interface Control Document (ICD) bitfield packing, register masks, and fixed-width integer operations.
     - Solver configuration options shall be declared at script initiation:
       `(set-option :produce-models true)`
       `(set-option :produce-unsat-cores true)`
       `(set-info :source "DEAP Sovereign Compiler SMT-LIB2 Verification Backend")`
  2. **Scalar Type & Sort Encoding (`Encode(TypeDecl)`)**:
     - The compiler shall deterministically map AST primitive types, structural sorts, and discrete domains to standard SMT-LIB2 sorts:
       * `Real` $`\longrightarrow`$ `Real`
       * `Integer` $`\longrightarrow`$ `Int`
       * `Boolean` $`\longrightarrow`$ `Bool`
       * Fixed-width bitfield types (`uint8`, `int16`, `uint32`, `uint64`) $`\longrightarrow`$ `(_ BitVec w)` where $`w \in \{8, 16, 32, 64\}`$
       * Discrete state enumerations $`\mathcal{S}_{\text{enum}} = \{ \text{State\_0}, \dots, \text{State\_n} \}`$` `$`\longrightarrow`$ SMT uninterpreted sort `(declare-sort State_Sort 0)` with declared constants `(declare-const State_0 State_Sort)` and pairwise distinctness axiom `(assert (distinct State_0 ... State_n))`.
     - Structural record types and classifiers shall be lowered into uninterpreted sorts with selector functions or algebraic datatypes preserving type safety.
  3. **Variable & Register State Allocation (`Encode(Variable)`)**:
     - State variables, input signals, output flows, and parameters shall be encoded as SMT constants via `(declare-const <id> <sort>)`.
     - For inductive transition proofs, each state variable $`v`$ shall be partitioned into current-step (unprimed) and next-step (primed) variables:
       * Current step: `(declare-const v Real)`
       * Next step: `(declare-const v_prime Real)`
     - For bounded model unrolling of depth $`k_{\text{max}}`$`, the engine shall allocate index-tagged constant families `$`v^{(j)}`$` for each horizon step `$`j \in \{0, \dots, k_{\text{max}}\}`$: `(declare-const v_0 Real)`, `(declare-const v_1 Real)`, etc.
     - Parametric operational envelopes $`[v_{\min}, v_{\max}]`$ (Subsystem 5, REQ-0112) shall be asserted as invariant background constraints:
       `(assert (and (>= v v_min) (<= v v_max)))`
  4. **Behavioral Transitions & Dynamic Relation Encoding (`Encode(Transition)`)**:
     - Discrete state machine transitions (Subsystem 6, REQ-0080, REQ-0120), continuous integration step updates (Subsystem 10, REQ-0179, REQ-0181), and action step contracts shall be lowered into formal transition predicates $`T(s, s')`$.
     - Each transition $`t = \langle s_{\text{src}}, s_{\text{dst}}, G, E, f \rangle`$` with guard condition `$`G(s)`$` and state update assignment `$`s' = f(s)`$ shall be encoded as:
       `(assert (=> (and (= current_state State_src) G_s) (and (= next_state State_dst) (= v_prime f_s))))`
     - Deterministic guard disjointness (REQ-0122) and totality constraints shall be encoded to verify non-overlapping transitions.
  5. **Safety Invariant Negation & Refutational Proof Framing (`Encode(\neg \mathcal{I}_{\text{safe}})`)**:
     - Given system safety invariant $`\mathcal{I}_{\text{safe}}`$`, verification obligations shall assert its negation `$`\neg \mathcal{I}_{\text{safe}}`$:
       `(assert (not I_safe))`
     - The synthesis pipeline shall synthesize two canonical proof obligation configurations:
       * *Inductive Base Case*: Initial system configuration $`I(s_0)`$` conjoined with negated invariant `$`\neg \mathcal{I}_{\text{safe}}(s_0)`$:

```math
\Phi_{\text{base}} = I(s_0) \wedge \neg \mathcal{I}_{\text{safe}}(s_0)
```

       * *Inductive Step (Consecution)*: Valid invariant assumption at state $`s`$` conjoined with system transition `$`T(s, s')`$` and negated invariant at state `$`s'`$:

```math
\Phi_{\text{step}} = \mathcal{I}_{\text{safe}}(s) \wedge T(s, s') \wedge \neg \mathcal{I}_{\text{safe}}(s')
```

     - Universal invariant validity across all reachable states is proven if both $`\Phi_{\text{base}}`$` and `$`\Phi_{\text{step}}`$ are unsatisfiable (`UNSAT`).
  6. **Bounded Model Checking (BMC) Unrolling Script Generation**:
     - For complex concurrent statecharts and multi-step dynamics, the backend shall synthesize bounded unrolling verification scripts of depth $`k \in \{0, \dots, k_{\text{max}}\}`$:

```math
\Phi_{\text{bmc}}^{(k)} = I(s_0) \wedge \left( \bigwedge_{j=0}^{k-1} T(s_j, s_{j+1}) \right) \wedge \left( \bigvee_{j=0}^k \neg \mathcal{I}_{\text{safe}}(s_j) \right)
```

     - If $`\Phi_{\text{bmc}}^{(k)}`$ is `UNSAT` for all $`k \le k_{\text{max}}`$`, no safety violation can occur within `$`k_{\text{max}}`$ discrete steps.
     - If $`\Phi_{\text{bmc}}^{(k)}`$ is `SAT`, the solver synthesizes a concrete counterexample trace accessible via `(get-model)`.
  7. **Syntax Tree Isomorphism & Polish S-Expression Translation**:
     - AST expression nodes shall be translated into SMT-LIB2 prefix S-expressions (`(operator operand_1 operand_2 ...)`), preserving exact syntax tree isomorphism:

```math
\text{AST}(\psi) \cong \text{Parse}_{\text{SMT}}(\text{Emit}(\psi))
```

     - Arithmetic expressions: Addition `(+ a b)`, Subtraction `(- a b)`, Linear Scalar Multiplication `(* c a)` (where $`c`$ is a constant numeric literal).
     - Relational expressions: `(<= a b)`, `(< a b)`, `(>= a b)`, `(> a b)`, `(= a b)`.
     - Boolean expressions: `(and p q ...)`, `(or p q ...)`, `(not p)`, `(=> p q)`, `(xor p q)`.
     - Conditional ternary expressions: `(ite cond then_expr else_expr)`.
     - Parenthesization is syntactically total and unambiguous, eliminating operator precedence errors.
  8. **Decidability Guardrails & Non-Linear Arithmetic Rejection (`E0406` / `E0500`)**:
     - The compliance checker shall inspect AST expression trees prior to emission to verify that constraints reside strictly within decidable fragments.
     - Non-linear multiplication of two or more indeterminate variables ($`v_1 \cdot v_2`$`), division by non-constant expressions (`$`v_1 / v_2`$`), polynomial powers of variables (`$`v^n`$` for `$`n \ge 2`$`), and transcendental functions (`$`\sin, \cos, \tan, \exp, \ln, \log`$) shall be detected and rejected with diagnostic error code `E0406` (`SMTNonLinearUnsupportedTheoryViolation`).
     - Expressions incorporating unbounded existential ($`\exists`$`) or universal (`$`\forall`$) quantifier alternation shall be detected and rejected with diagnostic error code `E0406` (`SMTAlternatingQuantifierViolation`).
  9. **Streaming Artifact Sink & Manifest Persistence**:
     - Emitted `.smt2` verification scripts shall be streamed through the abstract `StreamingArtifactSink` interface (REQ-0177) in bounded memory chunk buffers ($`B_{\text{max\_chunk\_size}} = 65{,}536\text{ bytes}`$`), guaranteeing `$`O(1)`$ auxiliary heap memory overhead.
     - All emitted scripts shall be registered in `CodegenManifest` with XXH3 content fingerprints (REQ-0178) and committed via atomic in-place file replacement (REQ-0189).
  10. **Bijective Source Provenance & Deterministic UUIDv5 Anchors (Directives 1 & 3)**:
      - Every emitted script, declared sort, state variable, assert statement, and proof command shall embed source provenance metadata indicating its originating AST node handle and source file span ($`\langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$) per REQ-0002.
      - Script units and individual proof obligations shall bind deterministic RFC 4122 UUIDv5 anchors derived from the canonical DEAP namespace OID and the obligation fully qualified name ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(M) \mathbin{\Vert} \text{"::SMTLIB2::"} \mathbin{\Vert} \text{ObligationID})`$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
      - Sort names, logic identifiers, variable names, and assertion labels shall be interned into the deduplicated global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
  11. **Bounded Parallelism, Error Recovery & Release Performance (Directives 2, 4 & 5)**:
      - Parallel emission of SMT-LIB2 verification scripts across independent packages, classifiers, state machines, and safety proof obligations shall execute strictly on a bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ (REQ-0012).
      - The synthesis pipeline shall implement synchronization token error recovery on obligation boundaries and assertion commands (REQ-0013, REQ-0016). When non-admissible expressions (`E0406` or `E0500`) are encountered, the engine shall record diagnostics into error sink buffer $`\mathcal{D}_{\text{sink}}`$`, isolate the faulty obligation, and proceed to subsequent obligations. If accumulated errors reach capacity limit `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
      - Script emission latency (strictly under 25 ms for an architectural model containing $`10^4`$ AST nodes / proof constraints) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests (REQ-0011, REQ-0196).
  12. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Part_0`, `State_0`, `State_1`, `Transition_0`, `Invariant_0`, `param_x : Real`, `param_y : Integer`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

  1. Refutational Invariant Verification Equivalence Invariant:
  Let $`\mathcal{M}_{\text{sys}}`$` denote the formal system model transition system, and let `$`\mathcal{I}_{\text{safe}}`$ denote the target safety invariant predicate.
  Universal satisfaction of $`\mathcal{I}_{\text{safe}}`$ across all reachable states is logically equivalent to the unsatisfiability of the conjoined model and negated invariant:

```math
  \text{UNSAT}(\mathcal{M}_{\text{sys}} \wedge \neg \mathcal{I}_{\text{safe}}) \iff \text{Valid}(\mathcal{I}_{\text{safe}})
```

  For mathematical induction over discrete execution steps $`k \in \mathbb{N}`$, verification is partitioned into base and step obligations:

```math
  \begin{aligned}
  \Phi_{\text{base}} &= I(s_0) \wedge \neg \mathcal{I}_{\text{safe}}(s_0) \\
  \Phi_{\text{step}} &= \mathcal{I}_{\text{safe}}(s) \wedge T(s, s') \wedge \neg \mathcal{I}_{\text{safe}}(s')
  \end{aligned}
```

  Inductive soundness guarantees:

```math
  \left( \text{UNSAT}(\Phi_{\text{base}}) \wedge \text{UNSAT}(\Phi_{\text{step}}) \right) \implies \left( \forall k \in \mathbb{N}, \ s_k \models \mathcal{I}_{\text{safe}} \right)
```

  2. Bounded Model Checking (BMC) Unrolling Horizon Invariant:
  For horizon depth $`k_{\text{max}} \in \mathbb{N}_{>0}`$`, the BMC unrolling formula `$`\Phi_{\text{bmc}}^{(k)}`$ is defined as:

```math
  \Phi_{\text{bmc}}^{(k)} = I(s_0) \wedge \left( \bigwedge_{j=0}^{k-1} T(s_j, s_{j+1}) \right) \wedge \left( \bigvee_{j=0}^k \neg \mathcal{I}_{\text{safe}}(s_j) \right)
```

  where:

```math
  \forall k \le k_{\text{max}}, \quad \text{UNSAT}(\Phi_{\text{bmc}}^{(k)}) \implies \text{NoReachableViolationInDepth}(k)
```

  4. Syntax Tree Isomorphism & Polish S-Expression Lowering Invariant:
  Let $`\psi \in \Psi_{\text{invariants}}`$ denote an invariant AST expression.
  The syntax-directed SMT-LIB2 emission function $`\text{Emit}_{\text{SMT}} : \mathcal{V}_{\text{AST}} \to \mathcal{S}_{\text{text}}`$ preserves strict AST isomorphism with the parsed SMT-LIB2 concrete syntax tree:

```math
  \text{AST}(\psi) \cong \text{Parse}_{\text{SMT}}(\text{Emit}_{\text{SMT}}(\psi))
```

  where recursive translation over AST expression nodes satisfies:

```math
  \begin{aligned}
  \text{Emit}_{\text{SMT}}(e_1 \odot e_2) &= \texttt{"("} \mathbin{\Vert} \text{op}(\odot) \mathbin{\Vert} \texttt{" "} \mathbin{\Vert} \text{Emit}_{\text{SMT}}(e_1) \mathbin{\Vert} \texttt{" "} \mathbin{\Vert} \text{Emit}_{\text{SMT}}(e_2) \mathbin{\Vert} \texttt{")"} \\
```

- **Computational Complexity & Algorithmic Bounds**: SMT-LIB2 / Z3 First-Order Constraint Encoding & Proof Framework Generation resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in strictly deterministic linear time $`O(|V_{\text{AST}}| + |E_{\text{AST}}| + N_{\text{bytes}})`$` and linear arena space `$`O(|V_{\text{AST}}| + |E_{\text{AST}}|)`$`, with strict constant auxiliary heap streaming memory `$`O(1)`$` relative to total emitted script byte size `$`N_{\text{bytes}}`$`, where `$`|V_{\text{AST}}|`$` denotes the count of AST nodes, `$`|E_{\text{AST}}|`$` denotes the count of AST edges, and `$`N_{\text{bytes}}`$ denotes the total aggregate size of emitted SMT-LIB2 `.smt2` benchmark script bytes.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 resolves qualitative temporal interval consistency over occurrence lifecycles using Allen's 13 qualitative interval relations via ORD-Horn SMT difference logic in $`O(N^3)`$` polynomial time. In contrast, REQ-0188 synthesizes static SMT-LIB2 script text from pre-validated AST temporal and state constraints in deterministic linear time `$`O(|V_{\text{AST}}| + N_{\text{bytes}})`$ without invoking temporal path consistency propagation or solving interval relations.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses structural allocation, interconnect clustering, and logical channel multiplexing via strongly NP-hard vector bin packing. In contrast, REQ-0188 translates pre-assigned interconnect bindings and operational envelope ranges into flat scalar and bitvector SMT assertions in deterministic $`O(|V_{\text{AST}}|)`$ time without solving multidimensional knapsack packing or capacity optimization problems.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 resolves subtyping lattices and multiple inheritance hierarchies via monotonic C3 linearization in $`O(V + E)`$ time. In contrast, REQ-0188 consumes lowered, concrete primitive types and emits flat SMT sorts and declarations without poset traversal or semilattice operations.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0188 generates refutational proof obligations ($`\Phi_{\text{base}}, \Phi_{\text{step}}`$`) directly from already-synthesized safety invariants in linear `$`O(|V_{\text{AST}}|)`$ time without combinatorial cut-set minimization.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking). In contrast, REQ-0188 generates the unrolled SMT-LIB2 verification script text ($`\Phi_{\text{bmc}}^{(k)}`$`) up to depth `$`k_{\text{max}}`$` in deterministic linear time `$`O(k_{\text{max}} \cdot |V_{\text{AST}}|)`$, leaving the execution of reachability exploration and satisfiability checking to downstream external automated theorem provers.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks via linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0188 translates linear Kirchhoff conservation equations into SMT assertion expressions in $`O(|V_{\text{AST}}|)`$ time without continuous complementarity solving or pivot operations.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs register allocation and basic block scheduling in LUMI IR using Chaitin graph $`K`$-coloring (NP-complete). In contrast, REQ-0188 maps variables to SMT constant declarations without graph coloring, machine register binding, or spilling heuristics.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 formalizes the computational complexity of *solving* formal proof obligations and invariant contract satisfiability via DPLL(T) SMT solvers, which is NP-complete for quantifier-free decidable fragments (QF_LRA, QF_LIA, QF_UF, QF_BV) and undecidable for general first-order logic with non-linear arithmetic. In contrast, REQ-0188 resides strictly in **Complexity Class P**, formalizing the *syntax-directed code generation backend* that lowers AST expressions, transitions, and invariants into formatted SMT-LIB2 S-expression benchmark scripts in deterministic linear time $`O(|V_{\text{AST}}| + N_{\text{bytes}})`$. REQ-0188 enforces syntactic front-end guardrails (rejecting non-linear terms and alternating quantifiers via diagnostic `E0406` or `E0500`) to guarantee that the generated scripts fall strictly within the decidable NP-complete fragments evaluated in REQ-0197, without performing DPLL(T) solver exploration itself.

  **Asymptotic Complexity Analysis**:
  Let $`N_V = |V_{\text{AST}}|`$` denote the number of AST nodes, `$`N_E = |E_{\text{AST}}|`$` denote the number of AST edges, `$`N_{\text{ob}}`$` denote the number of synthesized proof obligations, and `$`N_{\text{bytes}}`$ denote the total emitted SMT-LIB2 script byte size.
  1. *AST Invariant Traversal & Sort Mapping Phase*:
     - Traversing AST classifiers, state transitions, constraints, and parameters to extract mathematical expressions executes in single-pass linear time:

```math
T_{\text{traversal}}(N_V, N_E) \in O(N_V + N_E), \quad S_{\text{traversal}} \in O(N_V + N_E)
```

  2. *Syntactic Admissibility & Degree Inspection Phase*:
     - Inspecting operator nodes to verify linear degree ($`\text{Degree} \le 1`$) and quantifier absence executes in linear time proportional to expression node count:

```math
T_{\text{admissibility}}(N_V) \in O(N_V), \quad S_{\text{admissibility}} \in O(1)
```

  3. *Polish S-Expression Formatting & Tree Isomorphism Phase*:
     - Lowering AST expressions to SMT-LIB2 prefix S-expressions and formatting assertion text produces tokens streamed directly into writer buffers:

```math
T_{\text{format}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{format}} \in O(1)
```

  4. *Streaming Artifact Sink Buffering & Flush (REQ-0177)*:
     - Streaming emitted script chunks through the abstract `StreamingArtifactSink` uses fixed-size chunk buffers bounded by $`B_{\text{max\_chunk\_size}} = 65{,}536\text{ bytes}`$:

```math
M_{\text{streaming}} \le B_{\text{max\_chunk\_size}} \in O(1)
```

     - Total streaming I/O time across $`\lceil N_{\text{bytes}} / B_{\text{max\_chunk\_size}} \rceil`$ flushes executes in deterministic linear time:

```math
T_{\text{io}}(N_{\text{bytes}}) \in O(N_{\text{bytes}})
```

  5. *Aggregate Compilation Unit Complexity*:
     - Summing across all phases yields strictly deterministic linear complexity:

```math
T_{\text{total}} = T_{\text{traversal}} + T_{\text{admissibility}} + T_{\text{format}} + T_{\text{io}} \in O(N_V + N_E + N_{\text{bytes}})
```

     - Total memory footprint resides within contiguous typed bump arena storage:

```math
S_{\text{total}} \in O(N_V + N_E) \text{ (arena)} + O(1) \text{ (heap)}
```

  6. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Distributing proof obligation script generation across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool achieves near-linear speedup:

```math
T_{\text{parallel}}(N_V, N_E, N_{\text{bytes}}, N_{\text{max\_workers}}) \in O\left( \frac{N_V + N_E + N_{\text{bytes}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```
