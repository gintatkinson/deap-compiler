### REQ-0172: Use Cases Projection: Operational Flows, Primary Path & Step Traversal

- **Normative Statement**: The downstream specification projection engine, Use Case synthesizer, and operational flow traversal framework of Subsystem 9 shall extract, construct, and project formal Use Case specifications from compilation unit abstract syntax tree (AST) interaction models, activity graphs, and action definitions. Every synthesized Use Case specification shall model an end-to-end operational workflow comprising an initiating primary actor, zero or more participating supporting actors, formal precondition constraints, formal postcondition guarantees, and an ordered, sequential primary path flow $\langle s_1, s_2, \dots, s_k \rangle$ traversed from step index 1 to $k$. Each constituent step $s_i$ shall correspond directly to an AST action invocation, activity step, or inter-actor message transfer, binding an initiating actor, an action signature, a target entity, and a state delta. The projection engine shall strictly enforce monotonic step index contiguity such that for all $i \in \{1, \dots, k-1\}$, $\text{StepIndex}(s_{i+1}) = \text{StepIndex}(s_i) + 1$, with $\text{StepIndex}(s_1) = 1$. Every synthesized Use Case and action step shall bind an immutable RFC 4122 UUIDv5 identifier and maintain bijective traceability to underlying AST nodes with exact source-mapped lexical provenance spans. If any Use Case defines an empty primary path flow ($k = 0$), contains non-monotonic or non-contiguous step indices, references unresolvable actors or target entities, contains ungrounded placeholder tokens, or exhibits disconnected AST step provenance, the compiler shall fail closed, emit diagnostic error code `E0500`, and halt downstream specification persistence.

  Specifically, the Use Case projection engine and step traversal framework shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Hierarchical Specification Scope & Use Case Extraction**:
     - The compiler shall extract Use Case specifications along the downstream specification hierarchy established in REQ-0160 and REQ-0161: Epics decompose into Features, and Features project Use Cases and User Stories (REQ-0169, REQ-0170).
     - For every projected feature classifier $F \in \mathcal{F}_{\text{proj}}$, the synthesizer shall traverse the compilation unit AST to extract declared operational behaviors, SysML v2 `action def` and action usages (REQ-0078), KerML `Interaction` and `Step` semantics (REQ-0059, REQ-0060), and port message transfers (REQ-0072, REQ-0075, REQ-0149).
     - Each projected Use Case $U \in \mathcal{U}(F)$ shall represent a coherent, goal-oriented operational scenario delivering verified value to an initiating primary actor.
  2. **Actor Role Resolution & Partitioning**:
     - The synthesizer shall identify all actors participating in the Use Case and partition them into two disjoint sets:
       * Primary Actor ($a_{\text{primary}} \in \mathcal{A}$): The unique principal entity that initiates the operational workflow and drives the primary path toward goal satisfaction;
       * Supporting Actors ($\mathcal{A}_{\text{supp}} \subset \mathcal{A}$): Zero or more secondary entities, external systems, hardware devices, or subsystem services that interact with the primary actor or system during step execution ($a_{\text{primary}} \notin \mathcal{A}_{\text{supp}}$).
     - Every participating actor must resolve to a declared AST classifier, part definition (`part def`, REQ-0071), external subsystem interface, or port definition (`port def`, REQ-0072).
     - If an actor reference cannot be resolved in the lexical scope table (REQ-0040, REQ-0041), the compiler shall emit diagnostic error code `E0500` (`UnresolvedActorViolation`).
  3. **Precondition & Postcondition Contract Extraction**:
     - The synthesizer shall extract initial operational conditions into a formal precondition set $\mathbf{P}_{\text{pre}}$ and guaranteed terminal conditions into a formal postcondition set $\mathbf{Q}_{\text{post}}$:
       * Preconditions ($\mathbf{P}_{\text{pre}}$): Logical conjunction of system state predicates, operational envelope boundaries (REQ-0112), and prerequisite interface states that must evaluate to boolean `true` prior to the execution of step $s_1$;
       * Postconditions ($\mathbf{Q}_{\text{post}}$): Logical conjunction of guaranteed terminal state predicates, output flow emissions (REQ-0076, REQ-0148), and invariant commitments verified upon completion of step $s_k$.
     - Precondition and postcondition predicates shall be extracted from SysML v2 constraint blocks (`constraint def`, REQ-0083), assert constraints (`assert constraint`, REQ-0084), and action pre/post specifications (REQ-0066, REQ-0078).
  4. **Primary Path Sequential Step Traversal**:
     - The projection engine shall synthesize the canonical Primary Path (nominal operational flow) $\mathbf{S}_{\text{primary}} = \langle s_1, s_2, \dots, s_k \rangle$ representing the baseline, unobstructed execution path from initial preconditions to successful postconditions.
     - Sequential traversal shall follow control flow edges, activity sequences (REQ-0119), and interaction steps:
       * Sequential steps execute in strict linear succession without unhandled branching;
       * Where the AST interaction graph contains forks, joins, or decision nodes (REQ-0094), the primary path shall follow the designated nominal execution branch, while alternate and exception branches are delegated to REQ-0173;
       * The primary path flow must be non-empty ($k = |\mathbf{S}_{\text{primary}}| \ge 1$) and upper-bounded by $K_{\text{max\_steps}} = 10^3$. An empty primary flow shall trigger diagnostic error code `E0500` (`EmptyPrimaryFlowViolation`).
  5. **Monotonic Step Indexing & Contiguity Invariant**:
     - Every step $s_i \in \mathbf{S}_{\text{primary}}$ shall be assigned an immutable, 1-indexed sequential integer $\text{StepIndex}(s_i) = i$.
     - Step indices must be strictly contiguous:
       $$\text{StepIndex}(s_1) = 1 \quad \wedge \quad \forall i \in \{1, \dots, k-1\}, \quad \text{StepIndex}(s_{i+1}) = \text{StepIndex}(s_i) + 1$$
     - Any duplicate step index, gap in numbering, non-positive index, or out-of-order sequence shall constitute a fatal validation failure triggering diagnostic error code `E0500` (`NonMonotonicStepSequenceViolation`).
  6. **Constituent Step Structural Tuple**:
     - Each step $s_i$ ($i \in \{1, \dots, k\}$) shall be formalized as a fully grounded 8-tuple binding:
       * `Index`: Integer sequence position $i \in \mathbb{N}^+$;
       * `Initiating Actor`: The actor or component dispatching the action or stimulus ($a_{\text{init}} \in \{ a_{\text{primary}} \} \cup \mathcal{A}_{\text{supp}}$);
       * `Action Signature`: The strongly typed operation, behavior invocation, or message exchange signature ($\text{sig} \in \mathcal{S}_{\text{intern}}$);
       * `Target Entity`: The recipient classifier, port, part, or internal service processing the step ($e_{\text{target}} \in \mathcal{V}_{\text{AST}}$);
       * `State Delta`: The formal state vector transformation, output flow item, or effect condition produced by the step ($\delta_{\text{state}} \in \mathcal{S}_{\text{intern}}$);
       * `AST Node Reference`: Contiguous arena node handle to the originating AST action node ($\text{ref}_{\text{act}} \in \mathcal{V}_{\text{AST}}$);
       * `UUIDv5 Anchor`: Deterministic RFC 4122 UUIDv5 identifier ($\Delta_{s_i}$);
       * `Source Provenance`: Exact source-mapped lexical span ($\text{span}_{s_i}$).
     - If any step omits an action signature, target entity, or state delta, the compiler shall emit diagnostic error code `E0500` (`MalformedActionStepViolation`).
  7. **Bijective Traceability & AST Linkage Invariant**:
     - The projection engine shall establish a strict bijective linkage between every synthesized step $s_i \in \mathbf{S}_{\text{primary}}$ and its generating AST action or interaction node:
       $$\tau_{\text{step}} : \mathbf{S}_{\text{primary}} \longleftrightarrow \mathcal{V}_{\text{AST, act}}$$
     - Every step record must store the valid 32-bit arena node handle of its generating AST element.
     - If any step is synthesized without a backing AST node handle, or references a handle outside the active compilation unit, the compiler shall fail closed and emit diagnostic error code `E0500` (`UntracedUseCaseStepViolation`).
  8. **Anti-Placeholder & Grounding Invariant**:
     - All synthesized Use Case titles, actor names, preconditions, postconditions, action signatures, target entities, and state deltas shall consist of fully grounded, concrete expressions and interned symbols.
     - The presence of ungrounded placeholder tokens (including `TODO`, `TBD`, `TBC`, `FIXME`, `PLACEHOLDER`, `N/A`, `???`, `null`, `undefined`) within any Use Case specification shall constitute a fatal validation failure triggering diagnostic error code `E0500` (`UseCasePlaceholderViolation`), or `E0230` when evaluating feature Definition of Done completeness per REQ-0164.
  9. **Deterministic Tabular Markdown Emission**:
     - The Use Case synthesizer shall project canonical Markdown specification tables for each Use Case, structured as follows:
       * Specification Header: Use Case ID, Title, Owning Feature FQN, Primary Actor, Supporting Actors list, Preconditions list, Postconditions list;
       * Primary Path Table Columns: `Step`, `Initiating Actor`, `Action / Message Signature`, `Target Entity`, `State Delta / Effect`, `Traceability Anchor`.
     - In accordance with Charter Invariant 3, Markdown table cells must never contain `$` math delimiters (using plain text exclusively, e.g., `Step 1`, `Actor_0`, `Action_0()`, `State_1`).
     - In accordance with Charter Invariant 4, emitted Markdown tables and text must employ ASCII `--` or `-` exclusively, with zero Unicode em dashes.
  10. **Contiguous Bump Arena Memory Allocation**:
      - All synthesized Use Case descriptors, actor rosters, step records, flow sequences, and verification outcome witnesses shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit arena node handles (REQ-0035).
  11. **Enforcement of the 5 Executive Architectural Directives**:
      - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized Use Case specification $U$, constituent step record $s_i$, primary flow sequence, and verification witness shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the node fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::UseCase::"} \mathbin{\Vert} \text{name}_U)$ for Use Cases; $\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U) \mathbin{\Vert} \text{"::Step::"} \mathbin{\Vert} \text{FormatIndex}(i))$ for steps) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
      - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel extraction of AST interaction models, step sequencing, and Use Case Markdown synthesis across independent features shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $N_{\text{max\_workers}}$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
      - *Directive 3 (String Interner Memory Allocation Exception)*: Actor names, action signatures, target entity handles, state delta expressions, precondition/postcondition clauses, and Use Case narrative titles shall be interned into the deduplicated global symbol interner pool during synthesis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
      - *Directive 4 (Synchronization Token Error Recovery)*: The Use Case projection engine shall implement synchronization token error recovery on action step boundaries (statement delimiters `;` and table row delimiters `|`), Use Case section headers (`###`, `---`), and keyword delimiters (`UseCase:`) in accordance with REQ-0013 and REQ-0016. When step sequence violations or untraced step faults (`E0500`) occur, the engine shall record structured diagnostics into the preallocated error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels ($\bot_{\text{step}}$), and continue processing subsequent steps and Use Cases. If accumulated diagnostics reach capacity limit $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
      - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The Use Case projection engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Synthesis latency (strictly under 25 ms for an architectural model containing $|S_{\text{steps}}| = 10^4$ total action steps) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  12. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Feature_0`, `Feature_1`, `Actor_0`, `Actor_1`, `Actor_Alpha`, `Actor_Beta`, `UseCase_0`, `UseCase_1`, `UseCase_Alpha`, `Step_1`, `Step_2`, `Action_0`, `Action_1`, `Target_0`, `Target_1`, `State_0`, `State_1`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes in contiguous bump arena storage, and let $\mathcal{S}_{\text{intern}}$ denote the deduplicated global symbol interner pool.

  Let $\mathcal{F}_{\text{proj}} \subset \mathcal{V}_{\text{AST}}$ denote the finite set of features projected by Subsystem 9.
  Let $\mathcal{A} \subset \mathcal{V}_{\text{AST}}$ denote the finite universe of declared actor and communicating classifier nodes.
  Let $\mathcal{V}_{\text{AST, act}} \subset \mathcal{V}_{\text{AST}}$ denote the finite set of AST action invocation, activity step, and message transfer nodes.

  Each synthesized Use Case specification $U \in \mathcal{U}(F)$ projected from feature $F \in \mathcal{F}_{\text{proj}}$ is formalized as a 10-tuple:

  $$
  U = \langle \text{id}_U, \text{name}_U, F, a_{\text{primary}}, \mathcal{A}_{\text{supp}}, \mathbf{P}_{\text{pre}}, \mathbf{S}_{\text{primary}}, \mathbf{Q}_{\text{post}}, \Delta_U, \text{span}_U \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_U &\in \mathbb{N}_{32} \quad (\text{contiguous arena Use Case handle}) \\
  \text{name}_U &\in \mathcal{S}_{\text{intern}} \quad (\text{interned Use Case title}) \\
  F &\in \mathcal{F}_{\text{proj}} \quad (\text{owning feature classifier handle}) \\
  a_{\text{primary}} &\in \mathcal{A} \quad (\text{designated primary initiating actor handle}) \\
  \mathcal{A}_{\text{supp}} &\subset \mathcal{A} \quad (\text{finite set of participating supporting actor handles}) \\
  \mathbf{P}_{\text{pre}} &\subset \mathcal{S}_{\text{intern}} \quad (\text{finite set of interned precondition predicate clauses}) \\
  \mathbf{S}_{\text{primary}} &= \langle s_1, s_2, \dots, s_k \rangle \quad (\text{ordered sequence of primary path action steps}, \, k \ge 1) \\
  \mathbf{Q}_{\text{post}} &\subset \mathcal{S}_{\text{intern}} \quad (\text{finite set of interned postcondition guarantee clauses}) \\
  \Delta_U &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_U &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
  $$

  Each primary path action step $s_i \in \mathbf{S}_{\text{primary}}$ ($i \in \{1, \dots, k\}$) is formalized as an 8-tuple:

  $$
  s_i = \langle i, a_{\text{init}}(s_i), \text{sig}(s_i), e_{\text{target}}(s_i), \delta_{\text{state}}(s_i), \text{ref}_{\text{act}}(s_i), \Delta_{s_i}, \text{span}_{s_i} \rangle
  $$

  where:

  $$
  \begin{aligned}
  i &\in \mathbb{N}^+ \quad (\text{1-indexed sequential step position}) \\
  a_{\text{init}}(s_i) &\in \{ a_{\text{primary}} \} \cup \mathcal{A}_{\text{supp}} \quad (\text{initiating actor or component handle}) \\
  \text{sig}(s_i) &\in \mathcal{S}_{\text{intern}} \quad (\text{interned action invocation or message transfer signature}) \\
  e_{\text{target}}(s_i) &\in \mathcal{V}_{\text{AST}} \quad (\text{target entity, recipient port, or receiving classifier handle}) \\
  \delta_{\text{state}}(s_i) &\in \mathcal{S}_{\text{intern}} \quad (\text{interned state delta, output payload, or effect description}) \\
  \text{ref}_{\text{act}}(s_i) &\in \mathcal{V}_{\text{AST, act}} \quad (\text{provenance handle to originating AST action node}) \\
  \Delta_{s_i} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_{s_i} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
  $$

  1. Monotonic Step Indexing & Contiguity Invariant:

  $$
  \text{StepIndex}(s_1) = 1 \quad \wedge \quad \forall i \in \{1, \dots, k-1\}, \quad \text{StepIndex}(s_{i+1}) = \text{StepIndex}(s_i) + 1
  $$

  2. Primary Path Cardinality Bounds:

  $$
  1 \le |\mathbf{S}_{\text{primary}}| \le K_{\text{max\_steps}} \quad \text{where } K_{\text{max\_steps}} = 10^3
  $$

  3. Actor Disjointness & Membership Invariant:

  $$
  a_{\text{primary}} \notin \mathcal{A}_{\text{supp}} \quad \wedge \quad \forall s_i \in \mathbf{S}_{\text{primary}}, \quad a_{\text{init}}(s_i) \in \{ a_{\text{primary}} \} \cup \mathcal{A}_{\text{supp}}
  $$

  4. Operational State Transition & Entailment Invariant:
  Let $\Sigma$ denote the operational state space of feature $F$. Let $\sigma_0 \in \Sigma$ denote the initial system state valuation prior to workflow initiation, and let $\sigma_i \in \Sigma$ denote the intermediate state following execution of step $s_i$.
  The sequence of steps $\mathbf{S}_{\text{primary}}$ induces a deterministic state transition sequence:

  $$
  \sigma_0 \xrightarrow{s_1} \sigma_1 \xrightarrow{s_2} \dots \xrightarrow{s_k} \sigma_k
  $$

  satisfying formal precondition satisfaction and postcondition entailment:

  $$
  \begin{aligned}
  \forall p \in \mathbf{P}_{\text{pre}}, \quad &\text{Eval}(p, \sigma_0) \equiv \text{true} \\
  \forall i \in \{1, \dots, k\}, \quad &\text{ExecStep}(s_i, \sigma_{i-1}, \sigma_i) \equiv \text{true} \\
  \forall q \in \mathbf{Q}_{\text{post}}, \quad &\text{Eval}(q, \sigma_k) \equiv \text{true}
  \end{aligned}
  $$

  5. Bijective Step Traceability Invariant:
  Let $\mathbf{S}_{\text{all}} = \bigcup_{F \in \mathcal{F}_{\text{proj}}} \bigcup_{U \in \mathcal{U}(F)} \{ s \in \mathbf{S}_{\text{primary}}(U) \}$ denote the universe of all synthesized primary path steps across the compilation unit.
  The mapping $\tau_{\text{step}} : \mathbf{S}_{\text{all}} \to \mathcal{V}_{\text{AST, act}}$ defined by $\tau_{\text{step}}(s) = \text{ref}_{\text{act}}(s)$ is a bijection between synthesized steps and source action nodes:

  $$
  |\mathbf{S}_{\text{all}}| = |\mathcal{V}_{\text{AST, act}}|
  $$

  $$
  \forall s_a, s_b \in \mathbf{S}_{\text{all}}, \quad s_a \ne s_b \implies \text{ref}_{\text{act}}(s_a) \ne \text{ref}_{\text{act}}(s_b)
  $$

  $$
  \forall v \in \mathcal{V}_{\text{AST, act}}, \quad \exists ! s \in \mathbf{S}_{\text{all}} \text{ s.t. } \text{ref}_{\text{act}}(s) = v
  $$

  6. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

  $$
  \begin{aligned}
  \forall U \in \mathcal{U}(F), &\quad \Delta_U = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::UseCase::"} \mathbin{\Vert} \text{name}_U) \\
  \forall s_i \in \mathbf{S}_{\text{primary}}(U), &\quad \Delta_{s_i} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U) \mathbin{\Vert} \text{"::Step::"} \mathbin{\Vert} \text{FormatIndex}(i)) \\
  \forall U \in \mathcal{U}(F), &\quad \Delta_{\text{witness}(U)} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U) \mathbin{\Vert} \text{"::UseCaseWitness"})
  \end{aligned}
  $$

  7. Deterministic Diagnostic Trigger Rules (REQ-0191):

  $$
  \begin{aligned}
  |\mathbf{S}_{\text{primary}}(U)| = 0 &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0500}, \text{EmptyPrimaryFlowViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists i : \text{StepIndex}(s_{i+1}) \ne \text{StepIndex}(s_i) + 1 &\implies \text{Diagnostic}(s_{i+1}, \text{DiagnosticCode::E0500}, \text{NonMonotonicStepSequenceViolation}) \in \mathcal{D}_{\text{sink}} \\
  a_{\text{primary}} \notin \mathcal{A} \lor \exists a \in \mathcal{A}_{\text{supp}} : a \notin \mathcal{A} &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0500}, \text{UnresolvedActorViolation}) \in \mathcal{D}_{\text{sink}} \\
  a_{\text{primary}} \in \mathcal{A}_{\text{supp}} &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0500}, \text{ActorRoleCollisionViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists s \in \mathbf{S}_{\text{primary}} : \text{sig}(s) = \bot \lor e_{\text{target}}(s) = \bot &\implies \text{Diagnostic}(s, \text{DiagnosticCode::E0500}, \text{MalformedActionStepViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists s \in \mathbf{S}_{\text{primary}} : \text{ref}_{\text{act}}(s) \notin \mathcal{V}_{\text{AST, act}} &\implies \text{Diagnostic}(s, \text{DiagnosticCode::E0500}, \text{UntracedUseCaseStepViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists U : \text{ContainsPlaceholder}(U) &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0500}, \text{UseCasePlaceholderViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

  8. Fail-Closed Pipeline Halting Invariant:

  $$
  |\mathcal{D}_{\text{sink}} \cap \{ D \mid \text{code}(D) \in \{ \text{E0500}, \text{E0199} \} \}| \gt 0 \implies \text{HaltPipeline}() \land \text{UseCaseArtifactEmissionGate} = \text{BLOCKED}
  $$

- **Computational Complexity & Algorithmic Bounds**: Use Cases Projection: Operational Flows, Primary Path & Step Traversal resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing with strictly deterministic linear asymptotic time complexity $O(|S_{\text{steps}}|)$ over the aggregate count of action steps in the compilation unit, with linear space complexity $O(|S_{\text{steps}}|)$ in contiguous bump arena storage, where $|S_{\text{steps}}| = |\mathcal{V}_{\text{AST, act}}|$.

  **Mathematical Delineation from the 8 NP-Completeness Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 resolves qualitative temporal interval consistency over occurrence lifecycles using Allen's 13 interval relations via ORD-Horn difference logic SMT solving in $O(N^3)$ polynomial time. In contrast, REQ-0172 traverses a single pre-determined, ordered linear sequence of discrete operational steps $\langle s_1, \dots, s_k \rangle$ where each step index increments monotonically by 1, executing in deterministic linear time $O(|S_{\text{steps}}|)$ without temporal constraint propagation, interval intersection solving, or backtracking.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses strongly NP-hard multi-dimensional vector bin packing for structural allocation and logical channel multiplexing. In contrast, REQ-0172 traverses sequential action flows already allocated and linked in the AST, mapping steps to initiating actors and target entities via direct node handle dereferencing without combinatorial resource allocation or knapsack packing.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 formalizes subtyping lattice redefinition and multiple inheritance resolution via C3 linearization in $O(V + E)$ time. In contrast, REQ-0172 operates downstream of type checking and feature resolution, consuming already-typed action steps and classifier references without poset traversal or subtyping join evaluations.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0172 projects nominal operational workflows derived from declared activity models using syntax-directed graph traversal in linear time without combinatorial set covering.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete under Bounded Model Checking unrolling). In contrast, REQ-0172 synthesizes the primary path along a single linear operational workflow without unrolling orthogonal regions, searching exponential state reachability spaces, or exploring combinatorial interleavings.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks via linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0172 generates human-readable and machine-executable specification prose from discrete action steps without solving continuous or piecewise numerical complementarity equations.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs Chaitin graph coloring for SSA register allocation in LUMI IR (NP-complete). In contrast, REQ-0172 operates at the specification projection tier, transforming AST action structures into Use Case Markdown documentation prior to low-level compiler IR lowering.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the satisfiability of first-order invariant contracts via DPLL(T) SMT solvers, which is NP-complete for quantifier-free decidable fragments and undecidable for non-linear arithmetic. In sharp contrast, REQ-0172 performs syntax-directed sequential traversal of declared AST activity models in deterministic linear time $O(|S_{\text{steps}}|)$ without invoking SMT solvers or automated theorem provers.

  **Asymptotic Complexity Analysis**:
  Let $N_U = |\mathcal{U}|$ denote the aggregate count of synthesized Use Cases, let $N_S = |S_{\text{steps}}| = |\mathcal{V}_{\text{AST, act}}|$ denote the total count of operational action steps across all Use Cases ($N_S \ge N_U$), let $N_A = |\mathcal{A}|$ denote the count of declared actors, and let $L$ denote the aggregate byte length of generated Markdown specification tables and text.
  1. *AST Activity & Interaction Traversal Phase*:
     - Traversing the AST action sequences and activity models of each feature visits each action node handle exactly once:
       $$T_{\text{traversal}}(N_S) \in O(N_S), \quad S_{\text{traversal}}(N_S) \in O(1)$$
  2. *Actor Resolution & Role Partitioning*:
     - Partitioning actors into primary and supporting sets and resolving handles against the lexical scope table uses $O(1)$ table lookups per actor:
       $$T_{\text{actor}}(N_A, N_U) \in O(N_A + N_U), \quad S_{\text{actor}}(N_A) \in O(N_A)$$
  3. *Step Sequence Construction & Monotonic Validation*:
     - For each Use Case containing $k$ steps, assigning sequential step indices $1, \dots, k$ and verifying contiguity requires exactly $k - 1$ integer additions and comparisons:
       $$T_{\text{step\_seq}}(k) \in O(k), \quad S_{\text{step\_seq}}(k) \in O(k)$$
     - Summing across all $N_U$ Use Cases:
       $$T_{\text{step\_total}}(N_S) = \sum_{U \in \mathcal{U}} T_{\text{step\_seq}}(k_U) \in O(N_S)$$
  4. *Deterministic UUIDv5 Anchor Computation (Directive 1)*:
     - Computing RFC 4122 UUIDv5 hashes for $N_U$ Use Cases and $N_S$ step records requires a fixed number of SHA-1 digest rounds over bounded topological path strings:
       $$T_{\text{uuid}}(N_U, N_S) \in O(N_U + N_S) = O(N_S)$$
  5. *Markdown Table Formatting & Streaming Emission*:
     - Formatting interned step symbols, actor names, and signatures into canonical Markdown tables and streaming to the downstream artifact sink scales linearly with total output byte length $L$:
       $$T_{\text{emission}}(N_S, L) \in O(N_S + L)$$
