### REQ-0149: Port Definition Rosters & Hierarchical Port Type Binding

- **Normative Statement**: The Level 1C Interface Control Documents (ICD) synthesis engine, port resolution subsystem, and interconnect contract compiler of Subsystem 8 shall automatically generate exhaustive Port Definition Rosters cataloging every declared port definition (`port def`) and port usage (`port`) across all component assemblies, subsystem boundaries, and hierarchical package structures within the sovereign architectural model. The ICD engine shall extract, validate, and document port directionality, structural type bindings, protocol specifications, conjugation states, and recursive nested port features, maintaining deterministic qualified symbol paths and complete structural traceability across all compilation units.

  Specifically, the ICD engine, port resolution framework, and roster generator shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Exhaustive Port Definition & Usage Cataloging**:
     - The compiler shall traverse the abstract syntax tree (AST) stored in contiguous memory bump arena storage and extract the complete set of port definitions ($`\mathcal{P}_{\text{def}}`$) and component port usages ($`\mathcal{P}_{\text{usage}}`$).
     - For every port declaration $`p \in \mathcal{P}_{\text{def}} \cup \mathcal{P}_{\text{usage}}`$, the roster generator shall record:
       - The interned port identifier ($`\text{name}(p) \in \mathcal{S}_{\text{intern}}`$),
       - Fully qualified symbol path ($`\text{FQN}(p)`$),
       - Immediate structural owner ($`\text{owner}(p)`$),
       - Element declaration category ($`\text{kind}(p) \in \{ \text{PortDefinition}, \text{PortUsage} \}`$),
       - Declared transmission directionality ($`\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}`$),
       - Bound structural port type or classifier ($`\tau_{\text{port}}(p) \in \mathcal{V}_{\text{AST}}`$),
       - Bound protocol specification or framing contract ($`\pi_{\text{proto}}(p) \in \Pi_{\text{proto}} \cup \{ \bot \}`$),
       - Conjugation status modifier ($`\text{is\_conjugated}(p) \in \{ \text{true}, \text{false} \}`$),
       - Cardinality multiplicity envelope ($`\mu_p = [l_p, u_p] \subseteq \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \})`$),
       - Ordered sequence of nested port features and sub-ports ($`\text{features}(p)`$),
       - Deterministic RFC 4122 UUIDv5 anchor ($`\Delta_p \in \{0, 1\}^{128}`$),
       - Exact lexical source provenance span ($`\text{span}_p`$).
     - If a port declaration omits a mandatory structural type or specifies an unresolvable type symbol, the compiler shall deterministically emit diagnostic error code `E0500` (`UnresolvedPortTypeBinding`).
  2. **Hierarchical Ownership & Nested Port Tree Containment**:
     - The compiler shall support arbitrary multi-level hierarchical port nesting where a port definition or usage contains one or more child port features ($`p_{\text{child}} \in \text{features}(p_{\text{parent}})`$).
     - The ownership relation $`\text{owner} : \mathcal{P}_{\text{usage}} \to \mathcal{C}_{\text{comp}} \cup \mathcal{P}_{\text{usage}}`$ shall satisfy the strict hierarchical containment invariant:

$$
\forall p_{\text{child}} \in \text{features}(p_{\text{parent}}), \quad \text{owner}(p_{\text{child}}) = p_{\text{parent}}
$$

     - The root ancestor of any port containment hierarchy must terminate at a valid component classifier or subsystem assembly:

$$
\forall p \in \mathcal{P}_{\text{usage}}, \quad \exists k \ge 1 : \text{owner}^k(p) \in \mathcal{C}_{\text{comp}}
$$

     - The transitive closure of the ownership relation $`\text{owner}^+`$ must be strictly irreflexive ($`\forall p, \, \langle p, p \rangle \notin \text{owner}^+`$), precluding self-containment cycles. If a cycle is detected in nested port definitions, the compiler shall halt roster synthesis and emit diagnostic error code `E0500` (`NestedPortContainmentCycle`).
     - If a port usage is declared without a valid owning component classifier or parent port, the compiler shall emit diagnostic error code `E0220` (`UnresolvedPortOwner`).
  3. **Port Directionality Semantics & Directional Validation**:
     - The roster generator shall validate that every port usage binds a valid directional primitive in accordance with REQ-0038:

$$
\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}
$$

     - If a port specifies an unrecognized or ill-formed directionality keyword, the compiler shall reject the declaration with diagnostic error code `E0201` (`InvalidPortDirection`).
     - For composite ports possessing nested sub-ports, the compiler shall ensure directional consistency: an incoming port (`in`) may contain sub-ports whose effective directions are compatible with inbound ingestion, while an outgoing port (`out`) must emit outbound transmissions.
  4. **Conjugation Lowering & Direction Inversion Algebra**:
     - The ICD engine shall implement SysML v2 conjugation lowering (`~`) in accordance with REQ-0063.
     - Conjugation preserves structural type isomorphism while strictly inverting flow directionality:

$$
\text{is\_conjugated}(p) = \text{true} \implies \text{dir}(p) = {\sim}\text{dir}(\text{base\_def}(p))
$$

     - Direction inversion $`{\sim} : \{ \text{In}, \text{Out}, \text{InOut} \} \to \{ \text{In}, \text{Out}, \text{InOut} \}`$ is governed by the algebraic involution:

$$
{\sim}(\text{In}) = \text{Out}, \quad {\sim}(\text{Out}) = \text{In}, \quad {\sim}(\text{InOut}) = \text{InOut}
$$

       satisfying $`{\sim}({\sim}(d)) = d`$ for all $`d \in \{ \text{In}, \text{Out}, \text{InOut} \}`$.
     - When a port usage $`p`$ is declared as conjugated ($`{\sim}T`$), the roster generator shall evaluate the conjugation operator across all nested sub-ports and feature members:

$$
\forall f \in \text{features}(p), \quad \text{dir}(f) = {\sim}\text{dir}(\text{base\_def}(f))
$$

     - Structural data types, payloads, protocol bindings, and operational envelopes of constituent features shall remain invariant under conjugation ($`\tau(f) \cong \tau(\text{base\_def}(f))`$).
     - If conjugation direction inversion fails due to malformed base definitions or conflicting manual direction overrides on conjugated usages, the compiler shall emit diagnostic error code `E0201` (`ConjugationDirectionInversionFailure`).
  5. **Protocol Specification Binding & Interface Contracts**:
     - Each port definition and usage may declare a formal protocol binding $`\pi_{\text{proto}}(p) \in \Pi_{\text{proto}}`$ specifying transport semantics, framing architectures, and protocol state machine contracts.
     - The roster generator shall index protocol bindings, verify protocol compatibility across hierarchical usages, and catalog protocol attributes in the master roster.
     - If two interconnected ports or conjugated port pairs bind incompatible protocol definitions or conflicting framing parameters, the compiler shall emit diagnostic error code `E0500` (`PortProtocolMismatch`).
  6. **Master Port Roster Synthesis & Deterministic Serialization**:
     - The ICD engine shall synthesize the canonical Port Definition Roster table $`\mathcal{R}_{\text{ports}}`$ indexing all port instances.
     - Roster entries shall be deterministically ordered strictly by canonical lexicographical ASCII byte ordering of fully qualified symbol names ($`\prec_{\text{lex}}`$, REQ-0032).
     - The engine shall support multi-format projection:
       - Structured CommonMark Markdown tables for human-readable ICD reports,
       - Machine-readable CSV datasets for tabular ingestion,
       - Lossless JSON/CBOR interchange schemas for downstream toolchains,
       - Contiguous memory bump arena node records for downstream compiler phases (including REQ-0150 Connection Binding Rosters and REQ-0151 Dangling Port Gates).
  7. **Contiguous Bump Arena Allocation & Stable Handle Addressing**:
     - All port roster records, nested feature indices, and type bindings shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
     - Each port record shall be addressable via a stable 32-bit arena node handle ($`\text{id}_p \in \mathbb{N}_{32}`$) in accordance with REQ-0035.
  8. **Deterministic Error Handling & Diagnostic Recovery**:
     - When syntactic, typing, or structural violations occur during port cataloging, the compiler shall emit structured diagnostics adhering to the taxonomy of REQ-0191:
       - `E0201` (`InvalidPortDirection`, `ConjugationDirectionInversionFailure`),
       - `E0220` (`UnresolvedPortOwner`, `DanglingPortDeclaration`),
       - `E0500` (`UnresolvedPortTypeBinding`, `NestedPortContainmentCycle`, `PortProtocolMismatch`, `ConflictingPortBinding`),
       - `E0199` (`MaxDiagnosticLimitExceeded`).
     - In accordance with Architectural Directive 4 (Synchronization Token Error Recovery), upon encountering an invalid port declaration, the engine shall record the diagnostic into the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$, substitute a typed error sentinel ($`\bot_{\text{port}}`$), and resynchronize at the next port delimiter token (`;`, `}`, or table row delimiter `|`) to continue validating subsequent port definitions. If accumulated diagnostics reach capacity $`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
  9. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized port roster record, nested port feature, type binding, and protocol association shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(p))`$) in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel AST traversal, independent package port extraction, and concurrent roster synthesis across modular subsystems shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded dynamic thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Port names, fully qualified symbol identifiers, protocol tokens, and type strings shall be interned into the deduplicated global symbol interner pool during initial lexical analysis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The port roster synthesis engine shall implement synchronization token error recovery on statement delimiters (`;`, `}`) and table row delimiters (`|`). When semantic violations occur (`E0201`, `E0220`, `E0500`), diagnostics shall accumulate in the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$, substitute typed error sentinels ($`\bot_{\text{port}}`$), and continue validating subsequent declarations. If accumulated diagnostics reach capacity $`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The port roster generator shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Roster extraction latency (strictly under 25 ms for models containing $`10^4`$ port declarations) and peak RSS memory (strictly under 100 MB) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  10. **Pure Abstract Schema Invariant**: All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Component_0`, `Component_1`, `Component_Alpha`, `Component_Beta`, `PortDef_0`, `PortDef_1`, `PortDef_Alpha`, `PortDef_Beta`, `Port_0`, `Port_1`, `Port_Alpha`, `Port_Beta`, `Port_Nested`, `Protocol_0`, `Protocol_Alpha`, `Flow_0`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous memory bump arena storage, and let $`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.

  Let $`\mathcal{C}_{\text{comp}} \subset \mathcal{V}_{\text{AST}}`$ denote the universe of component classifiers and composite subsystem assemblies.

  Let $`\mathcal{P}_{\text{def}} \subset \mathcal{V}_{\text{AST}}`$ denote the set of structural port definitions, and let $`\mathcal{P}_{\text{usage}} \subset \mathcal{V}_{\text{AST}}`$ denote the set of structural port usages. The complete universe of ports is defined as $`\mathcal{P} = \mathcal{P}_{\text{def}} \cup \mathcal{P}_{\text{usage}}`$.

  The Port Definition Roster is formalized as an indexed relation:

$$
  \mathcal{R}_{\text{ports}} = \{ \langle p, \text{owner}(p), \text{dir}(p), \tau_{\text{port}}(p), \pi_{\text{proto}}(p), \text{is\_conjugated}(p), \text{features}(p), \Delta_p, \text{span}_p \rangle \mid p \in \mathcal{P} \}
$$

  where each port record $`p \in \mathcal{P}`$ is formalized as an 11-tuple:

$$
  p = \langle \text{id}_p, \text{name}_p, \text{FQN}_p, \text{owner}(p), \text{kind}(p), \text{dir}(p), \tau_{\text{port}}(p), \pi_{\text{proto}}(p), \text{is\_conjugated}(p), \Delta_p, \text{span}_p \rangle

  satisfying:

$$
  \begin{aligned}
  \text{id}_p &\in \mathbb{N}_{32} \quad (\text{contiguous bump arena node handle}) \\
  \text{name}_p &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol name}) \\
  \text{FQN}_p &\in \mathcal{S}_{\text{intern}} \quad (\text{fully qualified topological symbol path}) \\

  1. Directionality Inversion Algebra & Involution:
  Let $`\mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut} \}`$ denote the set of directional primitives. The conjugation inversion operator $`{\sim} : \mathcal{D} \to \mathcal{D}`$ is defined by:

$$
  {\sim}(\text{In}) = \text{Out}, \quad {\sim}(\text{Out}) = \text{In}, \quad {\sim}(\text{InOut}) = \text{InOut}
$$

  The operator $`{\sim}`$ is an algebraic involution over $`\mathcal{D}`$:

$$
  \forall d \in \mathcal{D}, \quad {\sim}({\sim}(d)) = d
$$

  2. Effective Directionality Assignment Invariant:
  For any port usage $`p \in \mathcal{P}_{\text{usage}}`$, let $`\text{base\_def}(p) \in \mathcal{P}_{\text{def}}`$ denote its referenced base port definition. The effective transmission directionality satisfies:

$$
  \text{dir}(p) = \begin{cases}
  \text{dir}(\text{base\_def}(p)), & \text{if } \neg\text{is\_conjugated}(p) \\
  {\sim}\text{dir}(\text{base\_def}(p)), & \text{if } \text{is\_conjugated}(p)
  \end{cases}
$$

  3. Recursive Nested Feature Conjugation Invariant:
  For any port $`p \in \mathcal{P}`$ possessing nested features and sub-ports $`\text{features}(p) = \{ f_1, f_2, \dots, f_m \}`$, conjugation preserves structural type isomorphism while inverting directional causality across all constituent features:

$$
  \forall f \in \text{features}(p), \quad \tau(f) \cong \tau(\text{base\_def}(f)) \quad \wedge \quad \text{dir}(f) = \begin{cases}
  \text{dir}(\text{base\_def}(f)), & \text{if } \neg\text{is\_conjugated}(p) \\
  {\sim}\text{dir}(\text{base\_def}(f)), & \text{if } \text{is\_conjugated}(p)
  \end{cases}
$$

  4. Hierarchical Ownership & Containment Invariant:
  For any nested sub-port $`p_{\text{child}} \in \text{features}(p_{\text{parent}})`$, the ownership relation satisfies:

$$
  \text{owner}(p_{\text{child}}) = p_{\text{parent}} \quad \wedge \quad \left( \text{owner}(p_{\text{parent}}) \in \mathcal{C}_{\text{comp}} \lor \text{owner}(p_{\text{parent}}) \in \mathcal{P} \right)
$$

  and the transitive containment relation $`\text{owner}^+`$ is strictly irreflexive and finite:

$$
  \text{owner}^+ = \bigcup_{k=1}^\infty \text{owner}^k, \quad \forall p \in \mathcal{P}, \, \langle p, p \rangle \notin \text{owner}^+ \quad \wedge \quad \exists k \le d_{\max} : \text{owner}^k(p) \in \mathcal{C}_{\text{comp}}
$$

  where $`d_{\max} \in \mathbb{N}`$ denotes the maximum containment depth across the architectural model.

  5. Bijective Roster Registration & Completeness Invariant:
  Every declared port instance in the compilation unit maps bijectively to exactly one entry in the synthesized Port Definition Roster:

$$
  \forall p \in \mathcal{P}, \quad \exists! r \in \mathcal{R}_{\text{ports}} : \text{id}(r) = \text{id}_p
$$

  ordered strictly by canonical lexicographical symbol path:

$$
  \forall r_a, r_b \in \mathcal{R}_{\text{ports}}, \quad \text{FQN}(r_a) \prec_{\text{lex}} \text{FQN}(r_b) \iff \text{Index}(r_a) \lt \text{Index}(r_b)
$$

$$
T_{\text{extract}}(|P|) \in O(|P|)

  2. *Hierarchical Ownership Resolution & Containment Cycle Checking*:

T_{\text{owner}}(|P|) \in O(|P| \cdot d_{\max}) \subseteq O(|P|)

$$
T_{\text{conj}}(|P|) \in O\left( \sum_{p \in \mathcal{P}} (1 + |\text{features}(p)|) \right) = O(|P|)
