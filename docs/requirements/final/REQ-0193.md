### REQ-0193: Non-Destructive Markdown Parser & Memory-Mapped AST Mutation Engine

- **Normative Statement**: The reverse synchronization engine, non-destructive Markdown parser, memory-mapped diffing backend, and AST mutation engine of Subsystem 11 shall parse, partition, reconcile, and mutate modified CommonMark Markdown specification documents non-destructively, updating schema-mapped entities in place while preserving user-authored prose, notes, formatting, commentary sections, and unmapped textual blocks byte-for-byte intact. The engine shall access on-disk documents via virtual memory mapping abstractions and page-cache primitives, executing byte-level diffing to bypass file write operations when reconciled content matches existing on-disk content byte-for-byte, thereby preserving file modification timestamps (`mtime`), filesystem inodes, and file metadata. When schema-mapped entities exhibit modified attributes or symbol identifiers, the engine shall apply AST mutation deltas $\Delta_{\text{AST}}$ while strictly preventing ungrounded entity injection into the sovereign AST arena $\mathcal{A}$ in accordance with the tri-state reconciliation gate of REQ-0192, emitting diagnostic error code `E0502` upon detection of unauthorized entity declarations.

  Specifically, the reverse synchronization engine, non-destructive Markdown parser, and memory-mapped AST mutation engine shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Lexical Block Partitioning & Exact Span Tracking Architecture**:
     - The non-destructive Markdown parser shall parse an incoming Markdown specification document $D_{\text{orig}}$ into an ordered sequence of contiguous, non-overlapping lexical blocks $\mathcal{B} = \langle B_1, B_2, \dots, B_m \rangle$.
     - Each lexical block $B_i$ shall maintain an exact half-open byte interval $[b_{\text{start}}(B_i), b_{\text{end}}(B_i)) \subset \mathbb{N}$ bounded within the source file buffer, such that the union of all intervals strictly covers the entire document byte range ($[0, |D_{\text{orig}}|)$) with zero gaps and zero overlaps:

       $$
       b_{\text{start}}(B_1) = 0 \quad \wedge \quad b_{\text{end}}(B_m) = |D_{\text{orig}}| \quad \wedge \quad \forall i \in \{1, \dots, m - 1\}, \; b_{\text{end}}(B_i) = b_{\text{start}}(B_{i+1})
       $$

     - The parser shall partition the block sequence into two mutually disjoint, exhaustive subsets: schema-mapped blocks $\mathcal{B}_{\text{schema}}$ and unmapped prose blocks $\mathcal{B}_{\text{prose}}$ ($\mathcal{B} = \mathcal{B}_{\text{schema}} \uplus \mathcal{B}_{\text{prose}}$).
     - Schema-mapped blocks $\mathcal{B}_{\text{schema}}$ comprise entity headings (`#`, `##`, `###`), schema-bound CommonMark tables, formal property bullet items, typed parameter rosters, UUID anchor metadata comments (`<!-- anchor: <uuidv5> -->`), and formal constraint code blocks.
     - Unmapped prose blocks $\mathcal{B}_{\text{prose}}$ comprise human-authored narrative descriptions, developer notes, rationale paragraphs, freeform blockquotes, raw HTML commentary, unmapped diagrams, custom callouts, and inter-block whitespace/delimiter lines.
  2. **Non-Destructive User Prose Protection & Byte-for-Byte Preservation**:
     - When reconciling and re-emitting updated Markdown documents, all user-authored prose blocks $B_i \in \mathcal{B}_{\text{prose}}$ shall be preserved byte-for-byte intact with zero diff churn:

       $$
       \forall B_i \in \mathcal{B}_{\text{prose}}, \quad \text{raw}(B'_i) \equiv \text{raw}(B_i) \quad \wedge \quad \text{SHA256}(B'_i) \equiv \text{SHA256}(B_i)
       $$

     - The non-destructive parser shall retain all idiosyncratic formatting characteristics within user prose blocks, including indentation levels, list marker characters (`*` versus `-`), numbered list numbering schemes, blockquote prefixing (`>`), code fence delimiter syntax (```` ``` ```` versus ```` ```` ````), and exact line break sequences ($\text{SYM}_{\text{LF}}$).
  3. **Memory-Mapped Diffing & Inode Preservation Architecture (REQ-0052)**:
     - The engine shall establish read-only virtual memory views $\mathcal{M}(P)$ over target on-disk Markdown files through platform-agnostic virtual memory mapping abstractions, eliminating unnecessary heap allocations.
     - For each target file path $P$ and candidate updated document buffer $D_{\text{updated}}$, the engine shall inspect file metadata in $O(1)$ constant time. If $\text{FileSize}(P) = |D_{\text{updated}}|$ and the memory-mapped buffer $\mathcal{M}(P)$ matches $D_{\text{updated}}$ byte-for-byte, the engine shall evaluate $\text{ShouldWrite}(P, D_{\text{updated}}) = \text{false}$ and strictly bypass writing to disk.
     - When writing is bypassed, the file modification timestamp (`mtime`), status change timestamp (`ctime`), file permissions (`mode`), and filesystem inode shall remain completely invariant ($\text{mtime}(P, t+1) = \text{mtime}(P, t)$), preventing cascading build toolchain and file-watcher churn.
     - If byte comparison indicates divergence, or if the target file does not exist, the engine shall write $D_{\text{updated}}$ atomically utilizing a temporary sibling staging file and atomic rename operation to prevent partial or torn writes.
  4. **AST Mutation Engine & In-Place Delta Application**:
     - The AST mutation engine shall accept an AST mutation delta $\Delta_{\text{AST}}$ generated from upstream schema compilations or validated user edits.
     - For each schema block $B_i \in \mathcal{B}_{\text{schema}}$, the mutation operator $\text{MutateNode}(B_i, \Delta_{\text{AST}})$ shall apply the delta, updating entity names, properties, constraints, or metadata while preserving local block indentation, table column alignments, and anchor comments.
     - The reconciled document $D_{\text{updated}}$ is synthesized by concatenating updated schema blocks and untouched prose blocks according to their original permutation order:

       $$
       D_{\text{updated}} = \bigoplus_{i=1}^m \text{raw}(B'_i) = \text{raw}(B'_1) \mathbin{\Vert} \text{raw}(B'_2) \mathbin{\Vert} \dots \mathbin{\Vert} \text{raw}(B'_m)
       $$

  5. **Tri-State Reconciliation Gate Integration & Entity Injection Prohibition (REQ-0192)**:
     - The mutation engine shall interface directly with the tri-state reconciliation prose gate of REQ-0192.
     - Renamed entities shall be validated for identifier lexical grammar and scope uniqueness prior to in-place mutation. If an identifier contains illegal characters, whitespace, or conflicts with a sibling entity, the engine shall emit diagnostic error code `E0502` (`InvalidRenamedIdentifierViolation` or `DuplicateRenamedIdentifierViolation`).
     - Any entity declared in a Markdown document lacking a preexisting node handle or anchor identifier in the sovereign AST arena $\mathcal{A}$ shall be classified as an unauthorized prose entity and rejected with diagnostic error code `E0502` (`UnauthorizedProseEntityViolation`), strictly forbidding ungrounded entity injection into the sovereign AST ($|\mathcal{A}_{\text{post}}| \le |\mathcal{A}_{\text{pre}}|$).
  6. **Contiguous Bump Arena Memory Allocation & Node Addressing**:
     - All intermediate block tokens, span descriptors, mutation transactions, and string slices shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
     - Blocks and AST nodes shall be addressed exclusively via compact 32-bit arena node handles (REQ-0035), eliminating raw pointer indirection, heap fragmentation, and cyclic references.
  7. **Bijective Source Provenance & Error Reporting (REQ-0190, REQ-0191)**:
     - Every block $B_i$ shall maintain bijective source provenance back to its Markdown source file byte span $[b_{\text{start}}, b_{\text{end}})$ and resolved coordinates $\langle \ell_{\text{start}}, c_{\text{start}}, \ell_{\text{end}}, c_{\text{end}} \rangle$ in accordance with REQ-0002.
     - Syntax faults, delimiter corruption, and reconciliation failures shall be reported via standardized diagnostics (`E0100`, `E0102`, `E0502`) with rich source-mapped snippets and remediation diff hints per REQ-0190 and REQ-0191.
  8. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every schema-mapped Markdown block, AST node handle, and mutation transaction shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the node fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n) \mathbin{\Vert} \text{"::Block"}))$ in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel parsing, diffing, and reconciliation across multi-document Markdown corpora shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $N_{\text{max\_workers}}$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Block symbol identifiers, entity names, docstrings, and document file paths shall be interned into the deduplicated global symbol interner pool during document parsing in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The Markdown parser shall implement synchronization token error recovery on section headings (`#`, `##`, `###`), table row delimiters (`|`), and block fences (`---`, ````) in accordance with REQ-0013 and REQ-0016. When syntax errors (`E0100`, `E0102`) or unauthorized entities (`E0502`) occur, the parser shall record the diagnostic into preallocated error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels, advance to the next synchronization token, and resume scanning. If accumulated diagnostics reach capacity limit $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: Production parser and mutation engine code shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Parsing and mutation latency (strictly under 25 ms for 10 MB Markdown documents containing $10^4$ blocks) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  9. **Pure Abstract MBSE Placeholder Mandate**:
     - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Entity_0`, `Entity_1`, `Port_1`, `Flow_A`, `param_x : Real`, `Doc_0`, `Block_0`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $D_{\text{orig}}$ denote the source Markdown specification document represented as an ordered sequence of contiguous lexical blocks:

  $$
  D_{\text{orig}} = \langle B_1, B_2, \dots, B_m \rangle
  $$

  where each lexical block $B_i$ is formalized as a 5-tuple:

  $$
  B_i = \langle \text{id}(B_i), [b_{\text{start}}(B_i), b_{\text{end}}(B_i)), \tau(B_i), \text{raw}(B_i), \Delta(B_i) \rangle
  $$

  with compact arena identifier $\text{id}(B_i) \in \mathbb{N}_{32}$, half-open byte span $[b_{\text{start}}(B_i), b_{\text{end}}(B_i)) \subset \mathbb{N}$, block taxonomy type $\tau(B_i) \in \mathcal{T}_{\text{block}}$, raw byte slice $\text{raw}(B_i) \in \Sigma^*$, and deterministic RFC 4122 UUIDv5 anchor $\Delta(B_i) \in \{0, 1\}^{128}$.

  1. Exact Contiguous Partition Covering Invariant:
  The sequence of block byte spans forms a complete, non-overlapping partition of the document byte buffer:

  $$
  \begin{aligned}
  b_{\text{start}}(B_1) &= 0 \\
  b_{\text{end}}(B_m) &= |D_{\text{orig}}| \\
  \forall i \in \{1, \dots, m - 1\}, \quad b_{\text{end}}(B_i) &= b_{\text{start}}(B_{i+1})
  \end{aligned}
  $$

  2. Block Taxonomy Classification Invariant:
  The universe of lexical blocks is partitioned into schema-mapped blocks $\mathcal{B}_{\text{schema}}$ and unmapped prose blocks $\mathcal{B}_{\text{prose}}$:

  $$
  \begin{aligned}
  \mathcal{B}_{\text{schema}} &= \{ B_i \in D_{\text{orig}} \mid \tau(B_i) \in \mathcal{T}_{\text{schema}} \} \\
  \mathcal{B}_{\text{prose}} &= \{ B_i \in D_{\text{orig}} \mid \tau(B_i) \in \mathcal{T}_{\text{prose}} \}
  \end{aligned}
  $$

  satisfying pairwise disjointness and completeness:

  $$
  \mathcal{B}_{\text{schema}} \cap \mathcal{B}_{\text{prose}} = \emptyset \quad \wedge \quad \mathcal{B}_{\text{schema}} \cup \mathcal{B}_{\text{prose}} = \{ B_1, B_2, \dots, B_m \}
  $$

  where:

  $$
  \begin{aligned}
  \mathcal{T}_{\text{schema}} &= \{ \text{EntityHeading}, \text{PropertyTable}, \text{ParameterRoster}, \text{AnchorComment}, \text{ConstraintBlock} \} \\
  \mathcal{T}_{\text{prose}} &= \{ \text{NarrativeParagraph}, \text{NoteBlock}, \text{RationaleQuote}, \text{RawHtmlComment}, \text{WhitespaceDelimiter} \}
  \end{aligned}
  $$

  3. Non-Destructive Reconciliation Operator:
  Let $\Delta_{\text{AST}}$ denote the set of AST mutations to be synchronized. The reconciliation operator $\mathcal{R}_{\text{md}}(D_{\text{orig}}, \Delta_{\text{AST}}) = D_{\text{updated}} = \langle B'_1, B'_2, \dots, B'_m \rangle$ satisfies:

  $$
  B'_i = \begin{cases}
  \text{MutateNode}(B_i, \Delta_{\text{AST}}), & \text{if } B_i \in \mathcal{B}_{\text{schema}} \\
  B_i, & \text{if } B_i \in \mathcal{B}_{\text{prose}}
  \end{cases}
  $$

  4. Byte-for-Byte User Prose Invariance:
  For all unmapped prose blocks, byte content and SHA-256 digests remain strictly invariant:

  $$
  \forall B_i \in \mathcal{B}_{\text{prose}}, \quad \text{raw}(B'_i) \equiv \text{raw}(B_i) \quad \wedge \quad \text{SHA256}(B'_i) \equiv \text{SHA256}(B_i)
  $$

  5. Document Splicing Formulation:
  The serialized updated document $D_{\text{updated}}$ is formed by concatenating the raw byte representations of all reconciled blocks:

  $$
  D_{\text{updated}} = \bigoplus_{i=1}^m \text{raw}(B'_i) = \text{raw}(B'_1) \mathbin{\Vert} \text{raw}(B'_2) \mathbin{\Vert} \dots \mathbin{\Vert} \text{raw}(B'_m)
  $$

  6. Memory-Mapped Diffing & File Write Decision Predicate (REQ-0052):
  Let $P$ denote the canonical target filesystem path and $\mathcal{M}(P)$ denote the read-only memory-mapped view of the existing on-disk file. The emission decision rule evaluates:

  $$
  \text{ShouldWrite}(P, D_{\text{updated}}) = \begin{cases}
  \text{true}, & \text{if } \neg \text{FileExists}(P) \\
  \text{false}, & \text{if } \text{FileExists}(P) \wedge \text{FileSize}(P) = |D_{\text{updated}}| \wedge \mathcal{M}(P) == D_{\text{updated}} \\
  \text{true}, & \text{otherwise}
  \end{cases}
  $$

  7. Timestamp and Metadata Invariance:
  When file write is bypassed, on-disk file metadata and timestamps remain strictly unchanged:

  $$
  \text{ShouldWrite}(P, D_{\text{updated}}) = \text{false} \implies \begin{aligned}
  \text{mtime}(P, t+1) &= \text{mtime}(P, t) \\
  \text{ctime}(P, t+1) &= \text{ctime}(P, t) \\
  \text{inode}(P, t+1) &= \text{inode}(P, t)
  \end{aligned}
  $$

  8. Sovereign AST Non-Injection Invariant:
  Let $\mathcal{A}_{\text{pre}}$ and $\mathcal{A}_{\text{post}}$ denote the sovereign AST arena state before and after reverse synchronization:

  $$
  |\mathcal{A}_{\text{post}}| \le |\mathcal{A}_{\text{pre}}| \quad \wedge \quad \mathcal{A}_{\text{post}} \setminus \mathcal{A}_{\text{pre}} = \emptyset
  $$

  9. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):
  Every schema block binds an immutable RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and its fully qualified topological path:

  $$
  \Delta(B_i) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(B_i) \mathbin{\Vert} \text{"::Block"})
  $$

  10. Deterministic Diagnostic Trigger Rules:
  Diagnostics are deterministically registered into the error sink buffer $\mathcal{D}_{\text{sink}}$:

  $$
  \begin{aligned}
  \exists B_i \in \mathcal{B}_{\text{schema}} : \neg \exists n \in \mathcal{A} \text{ s.t. } \text{id}(B_i) = \text{id}(n) &\implies \text{Diagnostic}(B_i, \text{DiagnosticCode::E0502}, \text{UnauthorizedProseEntityViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists B_i \in D_{\text{orig}} : \text{DelimiterMalformed}(B_i) &\implies \text{Diagnostic}(B_i, \text{DiagnosticCode::E0102}, \text{TableDelimiterBoundaryViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists B_i \in D_{\text{orig}} : \text{SyntaxCorrupted}(B_i) &\implies \text{Diagnostic}(B_i, \text{DiagnosticCode::E0100}, \text{SyntaxCorruptionViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

- **Computational Complexity & Algorithmic Bounds**: Non-Destructive Markdown Parser & Memory-Mapped AST Mutation Engine resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in strictly deterministic linear time bounded by $O(|D_{\text{bytes}}| + |\mathcal{B}| + |\Delta_{\text{AST}}|)$ and strictly deterministic linear space bounded by $O(|D_{\text{bytes}}| + |\mathcal{B}|)$ over document byte size $|D_{\text{bytes}}|$, extracted block count $|\mathcal{B}|$, and AST mutation count $|\Delta_{\text{AST}}|$.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 evaluates temporal consistency over occurrence lifecycles via Allen's 13 qualitative interval relations and ORD-Horn SMT difference logic in $O(N^3)$ polynomial time. In contrast, REQ-0193 performs deterministic contiguous 1D byte-span partitioning and block slicing in $O(|D_{\text{bytes}}|)$ linear time without temporal interval networks, path-consistency algorithms, or constraint satisfaction solvers.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 solves strongly NP-hard vector bin packing for structural allocation and channel multiplexing via First-Fit Decreasing approximations and branch-and-bound integer linear programming. In contrast, REQ-0193 maps contiguous blocks directly into preallocated virtual memory buffers in $O(1)$ amortized time per block without solving multidimensional packing, capacity optimization, or bin assignment problems.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 resolves subtyping lattices, multiple inheritance, and feature redefinition using C3 linearization in $O(V + E)$ time. In contrast, REQ-0193 classifies lexical blocks into schema versus prose partitions without navigating poset lattices, resolving subtyping bounds, or computing linearization orders.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0193 executes deterministic in-place block mutation and string substitution without combinatorial set-covering algorithms.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking). In contrast, REQ-0193 executes sequential lexical scanning and hash verification on Markdown documents without state-space traversal, unrolling, or reachability engines.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks using linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0193 reconciles Markdown blocks and verifies SHA-256 prose digests without physical flow networks or complementarity pivot loops.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs register allocation and SSA basic block scheduling in LUMI IR using Chaitin graph coloring (NP-complete). In contrast, REQ-0193 operates at the document ingestion and reverse-synchronization boundary, decoupled from backend machine registers and IR instruction scheduling.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves satisfiability of first-order invariant contracts via DPLL(T) SMT solvers. In contrast, REQ-0193 enforces deterministic syntactic equality and hash map lookups without first-order theorem proving or quantifier reasoning.

  **Asymptotic Complexity Analysis**:
  Let $N_{\text{bytes}} = |D_{\text{bytes}}|$ denote the Markdown document size in bytes, $N_B = |\mathcal{B}|$ denote the number of partitioned lexical blocks ($N_B \le N_{\text{bytes}}$), $N_{\Delta} = |\Delta_{\text{AST}}|$ denote the number of AST mutation entries, and $N_{\text{prose}}$ denote the number of unmapped prose blocks ($N_{\text{prose}} \le N_B$).
  1. *Lexical Scanning & Contiguous Block Partitioning Phase*:
     - Scanning document bytes to establish block spans $[b_{\text{start}}(B_i), b_{\text{end}}(B_i))$ and categorize block taxonomy types executes in a single linear pass over the byte stream:

       $$
       T_{\text{scan}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{scan}}(N_{\text{bytes}}) \in O(N_B)
       $$

  2. *Virtual Memory Mapping Setup Phase*:
     - Creating read-only virtual memory view $\mathcal{M}(P)$ over on-disk files requires operating system page table registration executing in constant time:

       $$
       T_{\text{mmap}} \in O(1), \quad S_{\text{mmap}} \in O(1)
       $$

  3. *Schema Block In-Place Mutation Phase*:
     - Applying AST mutation delta $\Delta_{\text{AST}}$ across schema blocks $\mathcal{B}_{\text{schema}}$ executes in time proportional to the number of mutation entries:

       $$
       T_{\text{mutate}}(N_B, N_{\Delta}) \in O(N_B + N_{\Delta}), \quad S_{\text{mutate}}(N_{\Delta}) \in O(N_{\Delta})
       $$

  4. *Prose Block SHA-256 Digest Verification Phase*:
     - Hashing and byte-copying unmapped prose blocks $B_i \in \mathcal{B}_{\text{prose}}$ executes in linear time bounded by total prose byte count:

       $$
       T_{\text{prose}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{prose}} \in O(1)
       $$

  5. *Memory-Mapped Diffing & Document Splicing Phase*:
     - Evaluating $\text{ShouldWrite}(P, D_{\text{updated}})$ via short-circuit size check in $O(1)$ and vectorized memory-mapped byte comparison in $O(N_{\text{bytes}})$ time:

       $$
       T_{\text{diff}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{diff}} \in O(1)
       $$

  6. *Aggregate Pipeline Complexity*:
     - Summing across all phases, total execution time is strictly bounded by:

       $$
       T_{\text{total}} \in O(N_{\text{bytes}} + N_B + N_{\Delta})
       $$

     - Total space complexity is strictly $O(N_{\text{bytes}} + N_B + N_{\Delta})$ in contiguous bump arena storage, requiring zero dynamic heap allocations.
  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning independent Markdown specification documents across $N_{\text{max\_workers}}$ threads on a bounded work-stealing thread pool achieves near-linear speedup:

       $$
       T_{\text{parallel}} \in O\left( \frac{N_{\text{bytes}} + N_B + N_{\Delta}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
       $$
