### REQ-0069: KerML Behaviors: Performance, Execution & ActionUsage Semantics

#### 1. Normative Statement

The behavioral lowering and semantic execution engine of Subsystem 4 shall formalize behavioral elements, actions, invocations, and temporal performance occurrences in strict accordance with the OMG Kernel Modeling Language (KerML) and Systems Modeling Language (SysML v2) specifications. In the compiler metamodel lowering pipeline, `Behavior` shall specialize `Class` (and transitively `Classifier` and `Type`), establishing the authoritative classifier definition for discrete, continuous, or composite behaviors. Every execution or occurrence of a behavior over physical or simulated time shall be formalized as a `Performance` occurrence specializing `Occurrence`.

  The lowering engine shall formalize contextual invocations of behaviors within enclosing behavioral or structural scopes as `Step` features specializing `Feature`. In the SysML v2 textual concrete syntax lowering pipeline, `ActionDefinition` constructs (`action def`) shall lower directly to KerML `Behavior` classifiers, and `ActionUsage` constructs (`action`) shall lower directly to KerML `Step` features typed by an authoritative `Behavior` classifier ($`\tau(s) \le_{\text{sub}} \text{Behavior}`$). A step whose declared type does not specialize `Behavior` or whose type cannot be resolved in the lexical symbol table shall be strictly prohibited at compile time, deterministically emitting structured diagnostic error code `E0200` in accordance with the diagnostic taxonomy of REQ-0191.

  Every `Behavior` definition $`B`$` shall declare an ordered collection of parameter features `$`\mathcal{P}_B = \langle p_1, p_2, \dots, p_k \rangle`$`, where each parameter specifies an interned name, an authoritative classifier type `$`\tau(p)`$`, an explicit multiplicity interval `$`\mu(p) = [m_{\min}, m_{\max}]`$` (`$`m_{\min} \le m_{\max}`$`), and an immutable directionality tag `$`\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut}, \text{Return} \}`$. Each `Step` or `ActionUsage` instantiating a behavior shall project sub-features corresponding bijectively to the parameters of its typing behavior. The engine shall enforce strict parameter subtyping conformance on all argument bindings: for an actual argument value or data source $`a`$` bound to parameter `$`p`$`, `$`\tau(a) \le_{\text{sub}} \tau(p)`$ must hold. Any subtyping violation shall deterministically emit diagnostic error code `E0202`. Any directionality violation -- such as assigning a value to an immutable `In` parameter within the behavior body, reading from an unassigned `Out` parameter, or binding an immutable literal to an `Out` or `InOut` parameter -- shall deterministically emit diagnostic error code `E0201`.

  Every performance occurrence $`P`$` instantiated from a behavior or step execution shall execute over a non-degenerate temporal interval `$`[t_{\text{start}}, t_{\text{end}}] \subset \mathbb{R}`$` with `$`t_{\text{start}} \le t_{\text{end}}`$` and occupy a 4D spatio-temporal world-line extent `$`\mathcal{W}(P) \subseteq \mathbb{R}^3 \times [t_{\text{start}}, t_{\text{end}}]`$`. Temporal bounds where `$`t_{\text{start}} \gt t_{\text{end}}`$ shall be rejected with diagnostic error code `E0200`. Each performance $`P`$` shall track a discrete lifecycle state automaton `$`\mathcal{M}_{\text{perf}} = \langle \mathcal{Q}_{\text{perf}}, \Sigma_{\text{event}}, \delta_{\text{perf}}, q_0, \mathcal{F}_{\text{perf}} \rangle`$ over state set:

```math
\mathcal{Q}_{\text{perf}} = \{ \text{Unstarted}, \text{Executing}, \text{Suspended}, \text{Completed}, \text{Terminated} \}
```

  with initial state $`q_0 = \text{Unstarted}`$` for all `$`t \lt t_{\text{start}}`$`, and terminal absorbing states `$`\mathcal{F}_{\text{perf}} = \{ \text{Completed}, \text{Terminated} \}`$. Permitted lifecycle state transitions and evaluation gates are specified as follows:
  1. `Start` transition ($`\text{Unstarted} \xrightarrow{\text{start}} \text{Executing}`$` at `$`t = t_{\text{start}}`$`): Executed if and only if all pre-conditions evaluate to true (`$`\forall \phi \in \mathcal{C}_{\text{pre}}, \phi(s(t_{\text{start}})) \equiv \text{true}`$). If any pre-condition fails, the engine shall record diagnostic error code `E0202`, and the performance shall immediately transition to `Terminated`.
  2. `Suspend` transition ($`\text{Executing} \xrightarrow{\text{suspend}} \text{Suspended}`$): Halts active sub-step execution and captures an intermediate state snapshot.
  3. `Resume` transition ($`\text{Suspended} \xrightarrow{\text{resume}} \text{Executing}`$): Resumes execution from the intermediate state snapshot.
  4. `Complete` transition ($`\text{Executing} \xrightarrow{\text{complete}} \text{Completed}`$` at `$`t = t_{\text{end}}`$`): Executed if and only if all constituent sub-steps have completed successfully and all post-conditions evaluate to true (`$`\forall \psi \in \mathcal{C}_{\text{post}}, \psi(s(t_{\text{start}}), s(t_{\text{end}})) \equiv \text{true}`$). If any post-condition fails, the engine shall record diagnostic error code `E0202`, and the performance shall transition to `Terminated`.
  5. `Terminate` transition ($`\text{Executing} \xrightarrow{\text{terminate}} \text{Terminated}`$` or `$`\text{Suspended} \xrightarrow{\text{terminate}} \text{Terminated}`$): Executed upon contract invariant failure, unhandled runtime exception, or external abort event.
  Any invalid lifecycle transition attempted outside the transition function $`\delta_{\text{perf}}`$ (such as transitioning from `Completed` to `Executing`, or from `Unstarted` directly to `Completed`) shall be strictly rejected, deterministically emitting diagnostic error code `E0201`.

  The engine shall enforce contractual Hoare triples over the system state space $`\Sigma`$:

```math
\{ \text{Pre}(x) \} \quad P \quad \{ \text{Post}(x, y) \}
```

  satisfying $`\forall s \in \Sigma, \text{Pre}(s(t_{\text{start}})) \equiv \text{true} \implies \text{Post}(s(t_{\text{start}}), s(t_{\text{end}})) \equiv \text{true}`$`. Furthermore, for any continuous execution invariant `$`\chi \in \mathcal{C}_{\text{inv}}`$`, the condition `$`\chi(s(t)) \equiv \text{true}`$` must hold for all `$`t \in [t_{\text{start}}, t_{\text{end}}]`$ during the `Executing` state. Any runtime or static violation of an execution invariant shall trigger an immediate transition to `Terminated` and emit diagnostic error code `E0202`.

  For compound behaviors containing constituent steps $`\mathcal{S}_B = \{ s_1, s_2, \dots, s_m \}`$, the engine shall enforce:
  1. Temporal Containment: For every constituent step $`s_i \in \mathcal{S}_B`$`, `$`[t_{\text{start}}(s_i), t_{\text{end}}(s_i)] \subseteq [t_{\text{start}}(P), t_{\text{end}}(P)]`$. A step whose execution interval falls outside the parent performance bounds shall emit diagnostic error code `E0200`.
  2. Causal / Control Precedence: For any explicit precedence edge $`s_i \prec_{\text{step}} s_j`$`, the engine shall enforce non-inversion: `$`t_{\text{end}}(s_i) \le t_{\text{start}}(s_j)`$`. Any observed inversion where `$`t_{\text{end}}(s_i) \gt t_{\text{start}}(s_j)`$ shall emit diagnostic error code `E0201`.
  3. Precedence Acyclicity: The directed step precedence graph $`G_B = (\mathcal{S}_B, \prec_{\text{step}})`$` must form a directed acyclic graph (DAG). Any circular control dependency (`$`s \prec_{\text{step}}^+ s`$) shall be detected via topological cycle detection, emitting diagnostic error code `E0203`.

  In accordance with Architectural Directive 1 and REQ-0010, every lowered `Behavior`, `Performance`, `Step`, `ActionUsage`, `Parameter`, and contract predicate node shall receive an immutable, deterministic RFC 4122 UUIDv5 identifier computed by namespace-hashing the fully qualified symbol path with the canonical compiler namespace OID ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))`$). Time-based UUIDs are strictly banned.
  In accordance with Architectural Directive 2 and REQ-0012, parallel validation and lowering of independent behavior graphs across compilation units shall execute on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$.
  In accordance with Architectural Directive 3 and REQ-0036, scalar symbol tokens for behavior identifiers, step names, parameter labels, and lifecycle states shall be interned into the global symbol interner pool as the sole permitted exception to zero-copy memory management.
  In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the engine shall implement synchronization token error recovery: upon encountering any diagnostic (`E0200`, `E0201`, `E0202`, or `E0203`), the engine shall record the diagnostic with exact source byte spans into the preallocated diagnostic sink $`\mathcal{D}_{\text{sink}}`$`, sever closing back-edges in an overlay graph `$`\mathcal{E}_{\text{overlay}}`$`, assign error sentinels `$`\bot_{\text{type}}`$` to malformed parameters, and continue verifying subsequent steps and behaviors. If accumulated diagnostics reach `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
  In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs, evaluating performance gates (execution latency strictly below 25 ms, peak RSS memory strictly below 100 MB for $`10^5`$ AST nodes) exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests.
  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Behavior_Alpha`, `Behavior_Beta`, `Performance_0`, `Action_0`, `Action_1`, `Step_Alpha`, `Step_Beta`, `Param_In`, `Param_Out`, `param_x : Real`) with zero hardcoded domain concepts.

#### 2. Formal Invariant

Let $`\mathcal{T}_{\text{metamodel}}`$` denote the KerML classifier specialization poset ordered by subtyping relation `$`\le_{\text{sub}}`$. The taxonomic specialization invariants of `Behavior`, `Performance`, and `Step` satisfy:

```math
\begin{aligned}
\text{Behavior} &\le_{\text{sub}} \text{Class} \le_{\text{sub}} \text{Classifier} \le_{\text{sub}} \text{Type} \\
\text{Performance} &\le_{\text{sub}} \text{Occurrence} \\
\text{Step} &\le_{\text{sub}} \text{Feature} \le_{\text{sub}} \text{Type}
\end{aligned}
```

The syntactic lowering equivalence with SysML v2 is formalized as:

```math
\text{ActionDefinition} \equiv \text{Behavior} \;\wedge\; \text{ActionUsage} \equiv \text{Step}
```

Each lowered behavior definition $`B`$ is formalized as a 10-tuple:

```math
B = \langle \text{id}_B, \text{name}_B, \text{owner}_B, \mathcal{P}_B, \mathcal{S}_B, \mathcal{C}_{\text{pre}}, \mathcal{C}_{\text{post}}, \mathcal{C}_{\text{inv}}, \Delta_B, \text{span}_B \rangle
```

where:
- $`\text{id}_B \in \mathbb{N}_{32}`$ is the contiguous arena node handle,
- $`\text{name}_B \in \mathcal{S}_{\text{intern}}`$ is the interned scalar symbol identifier,
- $`\text{owner}_B \in \mathcal{H}_{\text{pkg}} \cup \mathcal{H}_{\text{cls}}`$ is the enclosing namespace or classifier handle,
- $`\mathcal{P}_B = \langle p_1, p_2, \dots, p_k \rangle`$ is the ordered sequence of parameter features,
- $`\mathcal{S}_B = \{ s_1, s_2, \dots, s_m \}`$ is the finite set of constituent step features,
- $`\mathcal{C}_{\text{pre}} = \{ \phi_1, \dots, \phi_u \}`$ is the finite set of contract pre-condition predicates,
- $`\mathcal{C}_{\text{post}} = \{ \psi_1, \dots, \psi_v \}`$ is the finite set of contract post-condition predicates,
- $`\mathcal{C}_{\text{inv}} = \{ \chi_1, \dots, \chi_w \}`$ is the finite set of continuous execution invariants,
- $`\Delta_B \in \Sigma^*`$ is the deterministic RFC 4122 UUIDv5 topological anchor,
- $`\text{span}_B = \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$ is the source lexical provenance.

Each parameter $`p \in \mathcal{P}_B`$ is formalized as:

```math
p = \langle \text{id}_p, \text{name}_p, \tau(p), \mu(p), \text{dir}(p) \rangle
```

where $`\tau(p) \in \mathcal{H}_{\text{type}}`$`, `$`\mu(p) = [m_{\min}(p), m_{\max}(p)] \subseteq \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \})`$` with `$`m_{\min}(p) \le m_{\max}(p)`$`, and `$`\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut}, \text{Return} \}`$.

Each performance occurrence $`P`$` instantiating behavior `$`B`$ is formalized as:

```math
P = \langle \text{id}_P, \text{type}(P), \mathcal{W}(P), [t_{\text{start}}(P), t_{\text{end}}(P)], \sigma_{\text{perf}}, \mathcal{V}_{\text{args}}, \Delta_P \rangle
```

where $`\text{type}(P) = B`$`, `$`\mathcal{W}(P) \subseteq \mathbb{R}^3 \times [t_{\text{start}}(P), t_{\text{end}}(P)]`$ is the 4D world-line extent, and temporal bounds satisfy:

```math
t_{\text{start}}(P) \le t_{\text{end}}(P)
```

The discrete lifecycle state at timestamp $`t \in \mathbb{R}`$ is defined by:

```math
\sigma_{\text{perf}}(t) \in \{ \text{Unstarted}, \text{Executing}, \text{Suspended}, \text{Completed}, \text{Terminated} \}
```

The lifecycle state transition function $`\delta_{\text{perf}} : \mathcal{Q}_{\text{perf}} \times \Sigma_{\text{event}} \to \mathcal{Q}_{\text{perf}}`$ satisfies:

```math
\begin{aligned}
\delta_{\text{perf}}(\text{Unstarted}, \text{start}) &= \begin{cases} \text{Executing} & \text{if } \forall \phi \in \mathcal{C}_{\text{pre}}, \phi(s(t_{\text{start}})) = \text{true} \\ \text{Terminated} & \text{otherwise} \end{cases} \\
\delta_{\text{perf}}(\text{Executing}, \text{suspend}) &= \text{Suspended} \\
\delta_{\text{perf}}(\text{Suspended}, \text{resume}) &= \text{Executing} \\
\delta_{\text{perf}}(\text{Executing}, \text{complete}) &= \begin{cases} \text{Completed} & \text{if } \forall \psi \in \mathcal{C}_{\text{post}}, \psi(s(t_{\text{start}}), s(t_{\text{end}})) = \text{true} \\ \text{Terminated} & \text{otherwise} \end{cases} \\
\delta_{\text{perf}}(q, \text{terminate}) &= \text{Terminated} \quad \forall q \in \{ \text{Executing}, \text{Suspended} \} \\
\delta_{\text{perf}}(q, \alpha) &= q \quad \forall q \in \{ \text{Completed}, \text{Terminated} \}, \; \forall \alpha \in \Sigma_{\text{event}}
\end{aligned}
```

Contractual Hoare triples over state space $`\Sigma`$ satisfy:

```math
\forall s \in \Sigma, \quad \left( \bigwedge_{\phi \in \mathcal{C}_{\text{pre}}} \phi(s(t_{\text{start}})) = \text{true} \right) \implies \left( \bigwedge_{\psi \in \mathcal{C}_{\text{post}}} \psi(s(t_{\text{start}}), s(t_{\text{end}})) = \text{true} \right)
```

Continuous execution invariants satisfy:

```math
\forall t \in [t_{\text{start}}(P), t_{\text{end}}(P)], \quad \sigma_{\text{perf}}(t) = \text{Executing} \implies \left( \bigwedge_{\chi \in \mathcal{C}_{\text{inv}}} \chi(s(t)) = \text{true} \right)
```

For a compound behavior with constituent steps $`\mathcal{S}_B`$`, temporal containment and causal precedence over control graph `$`G_B = (\mathcal{S}_B, \prec_{\text{step}})`$ satisfy:

```math
\forall s \in \mathcal{S}_B, \quad [t_{\text{start}}(s), t_{\text{end}}(s)] \subseteq [t_{\text{start}}(P), t_{\text{end}}(P)]
```

```math
\forall s_i, s_j \in \mathcal{S}_B, \quad s_i \prec_{\text{step}} s_j \implies t_{\text{end}}(s_i) \le t_{\text{start}}(s_j)
```

Precedence graph acyclicity is formalized via transitive closure $`\prec_{\text{step}}^+`$:

```math
\text{IsAcyclic}(G_B) \iff \forall s \in \mathcal{S}_B, \quad \neg(s \prec_{\text{step}}^+ s)
```

Topological scheduling existence invariant:

```math
\text{IsAcyclic}(G_B) \iff \exists \sigma : \mathcal{S}_B \to \{ 1, 2, \dots, |\mathcal{S}_B| \} \quad \text{such that} \quad \forall (s_i, s_j) \in \prec_{\text{step}}, \; \sigma(s_i) \lt \sigma(s_j)
```

Diagnostic Code Binding Invariant: Violations of behavioral typing, temporal bounds, lifecycle state transitions, contract conditions, or precedence acyclicity deterministically trigger structured diagnostic records in accordance with REQ-0191:

```math
\begin{aligned}
\neg(\tau(s) \le_{\text{sub}} \text{Behavior}) &\implies \text{Diagnostic}(s, \text{DiagnosticCode::E0200}, \text{NonBehavioralStepType}) \in \mathcal{D}_{\text{sink}} \\
t_{\text{start}}(s) \gt t_{\text{end}}(s) &\implies \text{Diagnostic}(s, \text{DiagnosticCode::E0200}, \text{InvertedTemporalBounds}) \in \mathcal{D}_{\text{sink}} \\
\neg([t_{\text{start}}(s), t_{\text{end}}(s)] \subseteq [t_{\text{start}}(P), t_{\text{end}}(P)]) &\implies \text{Diagnostic}(s, \text{DiagnosticCode::E0200}, \text{StepTemporalContainmentViolation}) \in \mathcal{D}_{\text{sink}} \\
(q, \alpha) \notin \text{dom}(\delta_{\text{perf}}) &\implies \text{Diagnostic}(P, \text{DiagnosticCode::E0201}, \text{IllegalLifecycleTransition}) \in \mathcal{D}_{\text{sink}} \\
s_i \prec_{\text{step}} s_j \;\wedge\; t_{\text{end}}(s_i) \gt t_{\text{start}}(s_j) &\implies \text{Diagnostic}((s_i, s_j), \text{DiagnosticCode::E0201}, \text{CausalPrecedenceInversion}) \in \mathcal{D}_{\text{sink}} \\
\neg(\tau(a) \le_{\text{sub}} \tau(p)) &\implies \text{Diagnostic}(a, \text{DiagnosticCode::E0202}, \text{ParameterTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists \phi \in \mathcal{C}_{\text{pre}} : \phi(s(t_{\text{start}})) = \text{false} &\implies \text{Diagnostic}(P, \text{DiagnosticCode::E0202}, \text{PreconditionViolation}) \in \mathcal{D}_{\text{sink}} \\
\exists \psi \in \mathcal{C}_{\text{post}} : \psi(s(t_{\text{start}}), s(t_{\text{end}})) = \text{false} &\implies \text{Diagnostic}(P, \text{DiagnosticCode::E0202}, \text{PostconditionViolation}) \in \mathcal{D}_{\text{sink}} \\
\exists \chi \in \mathcal{C}_{\text{inv}}, t \in [t_{\text{start}}, t_{\text{end}}] : \chi(s(t)) = \text{false} &\implies \text{Diagnostic}(P, \text{DiagnosticCode::E0202}, \text{InvariantViolation}) \in \mathcal{D}_{\text{sink}} \\
\exists s \in \mathcal{S}_B : s \prec_{\text{step}}^+ s &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0203}, \text{StepPrecedenceCycle}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Sanitized Overlay Precedence Graph Invariant: To prevent cascading compilation aborts during error recovery, closing cycle back-edges are pruned in the analysis overlay graph $`\mathcal{E}_{\text{overlay}}`$:

```math
\prec_{\text{step}, \text{overlay}} = \prec_{\text{step}} \setminus \{ (u, v) \in \prec_{\text{step}} \mid u \prec_{\text{step}}^+ v \;\wedge\; v \prec_{\text{step}}^+ u \}
```

```math
\text{IsAcyclic}((\mathcal{S}_B, \prec_{\text{step}, \text{overlay}})) \equiv \text{true}
```

Deterministic UUIDv5 and Arena Node Handle Addressing Invariant:

```math
\begin{aligned}
\forall u \in \{ B \} \cup \mathcal{P}_B \cup \mathcal{S}_B \cup \mathcal{C}_{\text{pre}} \cup \mathcal{C}_{\text{post}} \cup \mathcal{C}_{\text{inv}}, \quad \Delta(u) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u)) \\
\forall u \in \{ B \} \cup \mathcal{P}_B \cup \mathcal{S}_B \cup \mathcal{C}_{\text{pre}} \cup \mathcal{C}_{\text{post}} \cup \mathcal{C}_{\text{inv}}, \quad \text{Handle}(u) &= \langle \text{ArenaId}, \text{Offset}_u \rangle \in \mathbb{N}_{32}
\end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

Verification, semantic lowering, and contract checking of KerML behaviors and step executions execute strictly within Complexity Class $`\mathbf{P}`$`. For a behavior `$`B`$` containing `$`V = |\mathcal{S}_B|`$` constituent steps, `$`E = |\prec_{\text{step}}|`$` precedence edges, `$`K = |\mathcal{P}_B|`$` parameters, and `$`C = |\mathcal{C}_{\text{pre}}| + |\mathcal{C}_{\text{post}}| + |\mathcal{C}_{\text{inv}}|`$ contract predicates, algorithmic bounds are established as follows:
  1. Parameter Interface & Argument Conformance: Validating parameter multiplicity bounds, directionality constraints, and argument type conformance ($`\tau(a) \le_{\text{sub}} \tau(p)`$`) via precomputed subtyping lattice lookup tables requires `$`O(1)`$` constant time per parameter, yielding `$`O(K)`$ total time.
  2. Contract Predicate Boundary Evaluation: Evaluating pre-conditions at $`t_{\text{start}}`$`, post-conditions at `$`t_{\text{end}}`$`, and transition guard predicates across discrete step boundaries executes in `$`O(1)`$` evaluation time per predicate, yielding `$`O(C)`$ total time.
  3. Discrete Lifecycle State Transitions: State transitions across $`\delta_{\text{perf}}`$` are evaluated via table lookup in `$`O(1)`$ constant time per event dispatch.
  4. Step Graph Construction & Direct Arena Addressing: Building the adjacency list and in-degree tracking array indexed directly by contiguous 32-bit arena node handle offsets $`\text{Offset}_s \in [0, V-1]`$` executes in `$`O(V + E)`$ time, eliminating dynamic hash table lookups and guaranteeing constant-time graph mutations.
  5. Deterministic Acyclicity & Topological Sort: Cycle detection and topological scheduling via Kahn's algorithm or Tarjan's strongly connected components algorithm processes each step vertex at most twice and each precedence edge exactly once:

```math
T_{\text{topo}}(V, E) = \sum_{s \in \mathcal{S}_B} \left( O(1) + \sum_{s' \in \text{Succ}(s)} O(1) \right) \in O(V + E)
```

  If a cycle is detected, tracing and isolating the cycle path $`\mathcal{P}_{\text{cycle}} = \langle s_1, s_2, \dots, s_p, s_1 \rangle`$` executes in `$`O(V_C + E_C) \subseteq O(V + E)`$ time.
  6. Temporal Containment and Precedence Bounds: Validating $`[t_{\text{start}}(s), t_{\text{end}}(s)] \subseteq [t_{\text{start}}(P), t_{\text{end}}(P)]`$` and `$`t_{\text{end}}(s_i) \le t_{\text{start}}(s_j)`$` requires `$`O(1)`$` scalar interval comparisons per step and precedence edge, executing in `$`O(V + E)`$ total time.
  7. Total Sequential Complexity: Combining all analysis phases, total execution time for behavior $`B`$ is strictly linear with respect to the behavioral AST and dependency graph size:

```math
T_{\text{total}}(V, E, K, C) \in O(K + C + V + E) \subseteq O(V + E) \quad (\text{since } K, C \in O(V))
```

  8. Parallel Work-Stealing Scaling: When $`M`$` independent behaviors `$`\{ B_1, B_2, \dots, B_M \}`$` across disjoint packages are evaluated concurrently on a bounded work-stealing thread pool with worker bound `$`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}} \in O\left( \frac{\sum_{i=1}^M (K_i + C_i + V_i + E_i)}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  9. Space Complexity & Working Memory Bounds: Auxiliary working memory is strictly bounded by $`O(V + E)`$` for adjacency structures, the in-degree count array, and the topological evaluation queue. Memory for the diagnostic sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$`, guaranteeing that total auxiliary memory remains `$`O(V + E)`$ with zero unbounded heap allocations.

#### 4. Verification & Conformance Criteria

Deterministic conformance shall be verified by automated test suites operating on synthetic MBSE models containing abstract placeholders (`Package_0`, `Behavior_Alpha`, `Behavior_Beta`, `Performance_0`, `Action_0`, `Action_1`, `Step_Alpha`, `Step_Beta`, `Step_1`, `Step_2`, `Step_3`, `Param_In`, `Param_Out`, `param_x : Real`). Conformance validation shall enforce the following test gates:
  1. Behavioral Metamodel Typing Gate: Ingest a step `Step_Alpha` typed by a non-behavior classifier `Classifier_Alpha`. Assert that the lowering engine rejects the malformed step and emits structured diagnostic error code `E0200` (`NonBehavioralStepType`). Re-test with `Step_Alpha` typed by `Behavior_Alpha` and assert valid lowering with zero diagnostics.
  2. Temporal Bounds & Containment Gate: Ingest a performance `Performance_0` specifying inverted temporal bounds ($`t_{\text{start}} = 10.0, t_{\text{end}} = 5.0`$) or a constituent step `Step_1` whose execution interval $`[0.0, 15.0]`$` exceeds the parent performance interval `$`[2.0, 10.0]`$. Assert deterministic rejection and emission of structured diagnostic error code `E0200` (`InvertedTemporalBounds` or `StepTemporalContainmentViolation`).
  3. Parameter Directionality Gate: Ingest a behavior `Behavior_Alpha` containing an `In` parameter `Param_In`. Inject an assignment mutation targeting `Param_In` inside the behavior body, or bind an uninitialized `Out` parameter `Param_Out` as an input operand. Assert deterministic rejection and emission of structured diagnostic error code `E0201`.
  4. Discrete Lifecycle Transition Gate: Ingest a synthetic performance test driver that attempts an illegal lifecycle transition (such as transitioning from `Completed` to `Executing`, or from `Unstarted` directly to `Completed`). Assert that the transition is rejected and structured diagnostic error code `E0201` (`IllegalLifecycleTransition`) is emitted.
  5. Pre-condition Contract Gate: Ingest a behavior `Behavior_Alpha` declaring pre-condition $`\phi \equiv (\text{param\_x} \gt 0)`$`. Execute with argument `$`\text{param\_x} = -5`$.
