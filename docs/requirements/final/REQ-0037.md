### REQ-0037: Classifier Definition & Feature Usage Metamodel Typing Relations

- **Normative Statement**: The core metamodel shall enforce a strict formal duality and architectural partition between classifier definitions (`ClassifierDef`) representing reusable, context-independent types and feature usages (`FeatureUsage`) representing contextual, bound occurrences of classifiers within enclosing namespaces. Structural elements in the abstract syntax graph shall belong exclusively to either the classifier definition partition or the feature usage partition, with empty intersection. Every feature usage must bind to an authoritative classifier definition via a typed reference relation $`\tau`$`. An un-typed feature usage (`$`\tau(u) = \bot`$`) or an unresolvable classifier reference shall be strictly prohibited at compile time. In accordance with the subtyping partial order `$`(\mathcal{C}, \le)`$`, if a feature usage `$`u`$` has resolved type `$`\tau(u) = C_{1}`$` and `$`C_{1}`$` specializes `$`C_{2}`$` (`$`C_{1} \le C_{2}`$`), then `$`u`$` shall conform to `$`C_{2}`$`. When a feature usage is bound to a port, parameter, connector end, or contextual slot expecting type `$`C_{\text{target}}`$`, the type checker shall enforce type conformance `$`\tau(u) \le C_{\text{target}}`$`. A feature usage may specialize, override, or redefine features inherited from its classifier definition or ancestor usages strictly in accordance with monotonic covariance rules: (1) type covariance (`$`\tau(u_{\text{redef}}) \le \tau(u_{\text{base}})`$`), (2) multiplicity interval narrowing (`$`[l_{u}, u_{u}] \subseteq [l_{\text{base}}, u_{\text{base}}]`$`), (3) default value envelope containment (`$`v_{\text{default}} \in \text{Domain}(\tau(u_{\text{base}}))`$), and (4) preservation of port directionality and flow interface polarity. Widening multiplicity intervals, contravariant type redefinition, or out-of-bounds default values shall be strictly rejected. Any violation of classifier typing relations, unresolved references, type conformance failures, or illegal non-monotonic feature redefinitions shall deterministically emit structured diagnostic error code `E0200` in accordance with the standardized diagnostic taxonomy of REQ-0191. In accordance with Architectural Directive 5 and total-function error recovery contracts, the type checking engine shall bind a typed error sentinel $`\bot_{\text{type}}`$ to invalid usages upon emitting `E0200`, preventing cascading compiler faults and guaranteeing deterministic, panic-free execution across all inputs.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{structural}}`$` denote the universe of structural AST nodes. The metamodel enforces a disjoint partition into classifier definitions `$`\mathcal{C}`$` and feature usages `$`\mathcal{U}`$:

```math
\mathcal{V}_{\text{structural}} = \mathcal{C} \cup \mathcal{U}, \quad \mathcal{C} \cap \mathcal{U} = \emptyset
```

where the constituent sets are partitioned by discriminant node kind:

```math
\begin{aligned}
\mathcal{C} &= \{ c \in \mathcal{V}_{\text{structural}} \mid \text{kind}(c) = \text{ClassifierDef} \} \\
\mathcal{U} &= \{ u \in \mathcal{V}_{\text{structural}} \mid \text{kind}(u) = \text{FeatureUsage} \}
\end{aligned}
```

Each classifier definition $`C \in \mathcal{C}`$ is formalized as an 8-tuple:

```math
C = \langle \text{id}_{C}, \text{name}_{C}, \mathcal{S}_{C}, \mathcal{F}_{C}, \mathcal{M}_{C}, \mathcal{I}_{C}, \Delta_{C}, \text{span}_{C} \rangle
```

where:

```math
\begin{aligned}
\text{id}_{C} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{C} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\mathcal{S}_{C} &\subseteq \mathcal{C} \quad (\text{direct supertypes / generalizations}) \\
\mathcal{F}_{C} &\subseteq \mathcal{U} \quad (\text{owned feature usages}) \\
\mathcal{M}_{C} &= [m_{\min}, m_{\max}] \subseteq \mathbb{N}_{0} \cup \{ \infty \} \quad (\text{definition multiplicity envelope}) \\
\mathcal{I}_{C} &\subseteq \mathbb{R} \quad (\text{parametric numerical domain / operational envelope}) \\
\Delta_{C} &\in \Sigma^* \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{C} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

Each feature usage $`u \in \mathcal{U}`$ is formalized as a 9-tuple:

```math
u = \langle \text{id}_{u}, \text{name}_{u}, \text{owner}_{u}, \tau(u), \mathcal{R}_{u}, \mu_{u}, v_{\text{default}}, \delta_{u}, \text{span}_{u} \rangle
```

where:

```math
\begin{aligned}
\text{id}_{u} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{u} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_{u} &\in \mathcal{C} \cup \mathcal{U} \quad (\text{enclosing classifier definition or parent usage}) \\
\tau(u) &\in \mathcal{C} \setminus \{ \bot \} \quad (\text{authoritative classifier definition binding}) \\
\mathcal{R}_{u} &\subseteq \mathcal{U} \quad (\text{redefined feature usages}) \\
\mu_{u} &= [l_{u}, u_{u}] \subseteq \mathbb{N}_{0} \cup \{ \infty \} \quad (\text{contextual multiplicity interval}) \\
v_{\text{default}} &\in \text{Domain}(\tau(u)) \cup \{ \bot \} \quad (\text{contextual default value assignment}) \\
\delta_{u} &\in \{ \text{In}, \text{Out}, \text{InOut}, \text{None} \} \quad (\text{port / flow directionality tag}) \\
\text{span}_{u} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

Typing Relation Function: Every valid feature usage $`u \in \mathcal{U}`$ must map to an authoritative classifier definition:

```math
\tau : \mathcal{U} \longrightarrow \mathcal{C}
```

Subtyping Partial Order: The subtyping relation $`(\mathcal{C}, \le)`$` is the reflexive, transitive, and antisymmetric closure over direct generalization declarations `$`\mathcal{S}_{C}`$:

```math
\begin{aligned}
\forall C \in \mathcal{C}, &\quad C \le C \quad (\text{reflexivity}) \\
\forall C_{1}, C_{2}, C_{3} \in \mathcal{C}, &\quad (C_{1} \le C_{2} \wedge C_{2} \le C_{3}) \implies C_{1} \le C_{3} \quad (\text{transitivity}) \\
\forall C_{1}, C_{2} \in \mathcal{C}, &\quad (C_{1} \le C_{2} \wedge C_{2} \le C_{1}) \implies C_{1} = C_{2} \quad (\text{antisymmetry})
\end{aligned}
```

Subtyping Conformance Invariant: A feature usage $`u`$` conforms to a target classifier `$`C_{\text{target}}`$` if and only if its resolved type `$`\tau(u)`$` specializes `$`C_{\text{target}}`$:

```math
\text{ConformsTo}(u, C_{\text{target}}) \iff \tau(u) \le C_{\text{target}}
```

Monotonic Covariance Redefinition Invariant: For any feature usage $`u \in \mathcal{U}`$` that redefines an ancestor feature usage `$`u_{\text{base}} \in \mathcal{R}_{u}`$, the redefinition is valid if and only if all four covariance conditions hold:

```math
\text{ValidRedefinition}(u, u_{\text{base}}) \iff \Phi_{\text{type}}(u, u_{\text{base}}) \wedge \Phi_{\text{mult}}(u, u_{\text{base}}) \wedge \Phi_{\text{env}}(u, u_{\text{base}}) \wedge \Phi_{\text{dir}}(u, u_{\text{base}})
```

where:

```math
\begin{aligned}
\Phi_{\text{type}}(u, u_{\text{base}}) &\iff \tau(u) \le \tau(u_{\text{base}}) \quad (\text{type covariance}) \\
\Phi_{\text{mult}}(u, u_{\text{base}}) &\iff [l_{u}, u_{u}] \subseteq [l_{u_{\text{base}}}, u_{u_{\text{base}}}] \iff (l_{u_{\text{base}}} \le l_{u} \wedge u_{u} \le u_{u_{\text{base}}}) \quad (\text{multiplicity narrowing}) \\
\Phi_{\text{env}}(u, u_{\text{base}}) &\iff (v_{\text{default}}(u) \ne \bot \implies v_{\text{default}}(u) \in \text{Domain}(\tau(u_{\text{base}}))) \quad (\text{value containment}) \\
\Phi_{\text{dir}}(u, u_{\text{base}}) &\iff (\delta_{u_{\text{base}}} \ne \text{None} \implies \delta_{u} = \delta_{u_{\text{base}}}) \quad (\text{directionality invariance})
\end{aligned}
```

Diagnostic Code Trigger Invariant: Any violation of the typing relation, subtyping conformance, or redefinition covariance deterministically triggers diagnostic code `E0200`:

```math
\begin{aligned}
\tau(u) = \bot &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{UntypedFeatureUsage}) \in \mathcal{D} \\
\neg \text{ConformsTo}(u, C_{\text{target}}) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{TypeConformanceViolation}) \in \mathcal{D} \\
\neg \Phi_{\text{type}}(u, u_{\text{base}}) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{IncompatibleTypeRedefinition}) \in \mathcal{D} \\
\neg \Phi_{\text{mult}}(u, u_{\text{base}}) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{WidenedMultiplicityViolation}) \in \mathcal{D} \\
\neg \Phi_{\text{dir}}(u, u_{\text{base}}) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{DirectionalRedefinitionMismatch}) \in \mathcal{D}
\end{aligned}
```

Diagnostic Taxonomy Containment Invariant: All typing diagnostics belong strictly to the Metamodel and Typing family defined in REQ-0191:

```math
\forall D \in \mathcal{D}_{\text{typing}}, \quad \text{code}(D) = \text{DiagnosticCode::E0200} \in \mathcal{E}_{\text{type}}
```

- **Computational Complexity & Algorithmic Bounds**: Classifier definition and feature usage typing validation executes within Complexity Class $`\mathbf{P}`$`. For an AST graph containing `$`|\mathcal{C}|`$` classifier definitions and `$`|\mathcal{U}|`$` feature usages: (1) resolving interned symbol identifiers to arena node handles executes in amortized `$`O(1)`$` time via scoped symbol hash tables, (2) subtyping queries (`$`\tau(u) \le C_{\text{target}}`$`) execute in `$`O(1)`$` time using precomputed topological reachability bitsets or bounded `$`O(h)`$` tree-climbing where inheritance depth `$`h \le 32`$`, (3) multiplicity interval inclusion checks (`$`[l_{u}, u_{u}] \subseteq [l_{\text{base}}, u_{\text{base}}]`$`) execute in strictly `$`O(1)`$` scalar integer comparisons, (4) default value domain validation executes in `$`O(1)`$` scalar range checks, and (5) port directionality comparison executes in `$`O(1)`$` enum checks. For each feature usage redefining at most `$`k_{\text{redef}}`$` ancestor features (`$`k_{\text{redef}} \le 16 = O(1)`$), validating all typing relations across the entire model requires aggregate time:

```math
T(|\mathcal{U}|) = \sum_{u \in \mathcal{U}} O(1 + k_{\text{redef}} \cdot h) = O(|\mathcal{U}|)
```

Total space complexity is strictly bounded by $`O(|\mathcal{C}| + |\mathcal{U}|)`$` arena storage for AST nodes and `$`O(1)`$` auxiliary stack memory per validation pass. The diagnostic sink is bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$` allocated records, maintaining strict `$`O(1)`$ auxiliary heap memory overhead with respect to model size.

- **Verification & Conformance Criteria**: Automated test suites shall verify compliance using synthetic CommonMark and SysML v2 model definitions containing abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Feature_A`, `Feature_B`, `Usage_1`, `Usage_2`, `Port_1`, `param_x : Real`). Conformance shall be validated through the following deterministic test gates: (1) Duality Partitioning Gate: Verify that all structural nodes in the AST are partitioned into $`\mathcal{C}`$` and `$`\mathcal{U}`$ with empty intersection; assert that attempting to instantiate a definition directly as a usage without typing, or declaring a usage as a top-level classifier type, fails with diagnostic code `E0200`. (2) Canonical Typing Resolution Gate: Declare classifier `Classifier_Alpha` and instantiate feature usages `Usage_1 : Classifier_Alpha` and `Usage_2 : Classifier_Alpha`; assert 100% resolution with exact node handle bindings and zero diagnostics. (3) Subtyping Conformance Gate: Declare `Classifier_Beta` specializing `Classifier_Alpha` (`Classifier_Beta :> Classifier_Alpha`); instantiate `Usage_Sub : Classifier_Beta`; verify that passing `Usage_Sub` to an interface slot expecting `Classifier_Alpha` succeeds with $`\text{ConformsTo} = \text{true}`$ and zero diagnostics. (4) Untyped Feature Usage Diagnostic Gate: Ingest a model containing an un-typed feature usage `Usage_Err` with missing or unresolvable classifier type; assert deterministic emission of diagnostic error code `E0200` (`UntypedFeatureUsage`) with exact source byte span and line/column coordinates, substitution of error sentinel $`\bot_{\text{type}}`$, and complete avoidance of panic. (5) Incompatible Subtyping Violation Gate: Bind a feature usage of type `Classifier_Gamma` to an expectation of `Classifier_Alpha` where `Classifier_Gamma` does not specialize `Classifier_Alpha`; assert deterministic emission of diagnostic error code `E0200` (`TypeConformanceViolation`). (6) Monotonic Covariance Multiplicity Narrowing Gate: Declare `Classifier_Alpha` with a feature having multiplicity `[0..10]`; specialize the feature in a usage with narrowed multiplicity `[1..5]`; assert successful validation; attempt to specialize the feature with widened multiplicity `[0..20]` or `[-1..10]`; assert deterministic rejection with diagnostic code `E0200` (`WidenedMultiplicityViolation`). (7) Directional & Flow Invariance Gate: Declare `Port_1 : in Classifier_Alpha`; attempt to redefine `Port_1` as `out Classifier_Alpha` without formal conjugation; assert deterministic rejection with diagnostic code `E0200` (`DirectionalRedefinitionMismatch`). (8) Directive 5 Non-Panicking & Latency Gate: Execute benchmark validation over $`10^5`$ synthetic feature usages in compiled Release mode (`--release`); assert total-function execution with zero panics, execution latency under 25 ms, peak RSS memory under 30 MB, and 0-byte diff churn across consecutive compiler runs.
