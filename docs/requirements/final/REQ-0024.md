### REQ-0024: Tabular Schema Ingestion for Formal Constraints & Operational Envelopes

- **Normative Statement**: The ingestion engine within the Universal Schema Ingestion Engine shall parse CommonMark tabular schemas specifying formal constraints, safety invariants, contract conditions, and operational envelopes into strongly typed `IngestedConstraint` intermediate AST entities. For each data row in a constraint definition table, the parser must extract the unique constraint identifier, owning classifier or component reference, verbatim raw constraint expression text, formal invariant kind (`Assert` versus `Assume`), failure consequence severity tier (`Critical`, `Degraded`, or `Advisory`), and optional operational envelope interval bounds. Front-end table ingestion passes shall operate directly on tokenized table rows resolved via dynamic column binding vectors ($\vec{\beta}$ per REQ-0017), extracting constraint declarations without mutating or re-encoding raw expression byte strings. Constraint expressions shall be preserved verbatim, guaranteeing bitwise-identical lexical byte sequences for downstream Boolean AST parsing (REQ-0138), SMT-LIB2 first-order constraint encoding (REQ-0188), and formal invariant contract proving (REQ-0197). Every ingested constraint entity shall record exact source provenance, including 0-indexed byte offset intervals ($[p_{\text{start}}, p_{\text{end}})$) and 1-indexed line and column coordinates. The ingestion engine shall enforce scoped uniqueness of constraint identifiers within the owning classifier scope: no two constraints under the same owner may share an identical identifier. If an operational envelope column or interval clause is present, the parser shall enforce interval well-formedness: the lower envelope limit $L$ must not exceed the upper envelope limit $U$ ($L \le U$), and degenerate singleton intervals ($L = U$) shall be valid if and only if both bounds are closed. When constraint kind is omitted, it shall default to `Assert`; when severity is omitted, it shall default to `Critical`. Any schema violation--including missing mandatory columns (`id`, `owner`, or `expr`), unrecognized constraint kind or severity tokens, duplicate constraint identifiers within an owner scope, or unescaped delimiter faults--shall deterministically emit structured diagnostic error code `E0102` in accordance with the standardized diagnostic taxonomy of REQ-0191. Inverted operational envelope bounds ($L \gt U$) or malformed numerical envelope syntax shall deterministically emit structured diagnostic error code `E0103`. In accordance with Architectural Directive 4 (Synchronization Token Error Recovery), upon encountering any row-level syntax or semantic error, the parser shall record the localized diagnostic, substitute a typed error sentinel $\bot_{\text{constraint}}$ into the owning classifier AST, and resynchronize at the subsequent row line-break delimiter ($\text{SYM}_{\text{LF}}$) or table boundary without terminating table processing. If accumulated diagnostics reach the bounded capacity limit $C_{\text{max\_errors}}$, the parser shall emit diagnostic error code `E0199` and terminate table processing gracefully. All ingested constraint entities shall be allocated sequentially into contiguous arena storage in accordance with REQ-0009 and REQ-0034. In accordance with Architectural Directive 3, copying string bytes from the input table buffer into the global symbol interner pool for scalar SymbolId tokens during this initial ingestion pass is the sole permitted exception to the zero-copy invariant. In accordance with Architectural Directive 2, multi-table or multi-file parallel constraint ingestion passes shall be scheduled onto a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$. In accordance with Architectural Directive 5, constraint ingestion and validation shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs. All test models, diagnostic messages, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Component_0`, `Constraint_1`, `Constraint_2`, `param_x : Real`, `Envelope_0`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $\mathcal{T}_{\text{constraint}} = (\mathbf{H}, \mathbf{R})$ denote a tabular schema specifying formal constraints and operational envelopes, where $\mathbf{H} = \langle H_0, H_1, \dots, H_{C-1} \rangle$ represents the sequence of $C$ normalized column headers ($1 \le C \le C_{\text{max\_cols}} = 32$) and $\mathbf{R} = \langle R_1, R_2, \dots, R_M \rangle$ represents the ordered sequence of $M$ table rows. Let $\vec{\beta} : \{0, \dots, C-1\} \to \mathcal{K}_{\text{constraint}} \cup \{ \bot \}$ denote the column binding vector mapping column indices to canonical constraint attributes $\mathcal{K}_{\text{constraint}} = \{ \text{id}, \text{owner}, \text{expr}, \text{kind}, \text{severity}, \text{envelope} \}$.

Let $\mathcal{C} = \{ C_1, C_2, \dots, C_M \}$ denote the collection of synthesized `IngestedConstraint` intermediate entities. Each entity $C_i \in \mathcal{C}$ is formalized as a 7-tuple:

$$
C_i = \langle \text{id}_i, \text{owner}_i, \text{expr}_i, \text{kind}_i, \text{severity}_i, \mathcal{I}_i, \text{span}_i \rangle
$$

where the constituent domains and types are defined as:

$$
\begin{aligned}
\text{id}_i &\in \mathcal{S}_{\text{sym}} \quad (\text{sanitized interned constraint identifier}) \\
\text{owner}_i &\in \mathcal{S}_{\text{sym}} \quad (\text{fully qualified owning classifier identifier}) \\
\text{expr}_i &\in \Sigma^* \quad (\text{verbatim raw constraint expression byte string}) \\
\text{kind}_i &\in \mathcal{K}_{\text{kind}} = \{ \text{Assert}, \text{Assume} \} \quad (\text{formal invariant verification kind}) \\
\text{severity}_i &\in \mathcal{V}_{\text{sev}} = \{ \text{Critical}, \text{Degraded}, \text{Advisory} \} \quad (\text{consequence severity tier}) \\
\mathcal{I}_i &\in \mathbb{E} \cup \{ \bot_{\text{env}} \} \quad (\text{optional operational envelope interval}) \\
\text{span}_i &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

Let $\Sigma^*$ denote the byte alphabet. The Verbatim Expression Preservation Invariant mandates that the raw expression string $\text{expr}_i$ must be bitwise identical to the source cell byte slice without mutation, re-encoding, or whitespace stripping:

$$
\text{RawString}(\text{expr}_i) \equiv \text{SourceCellSlice}(R_i, \beta^{-1}(\text{expr}))
$$

The constraint kind domain $\mathcal{K}_{\text{kind}}$ and discrete parsing operator $\text{ParseKind} : (\Sigma^* \cup \{ \bot \}) \to \mathcal{K}_{\text{kind}} \cup \{ \bot_{\text{kind}} \}$ are defined as:

$$
\text{ParseKind}(s) = 
\begin{cases}
\text{Assert}, & \text{if } s = \bot \;\vee\; s = \text{""} \\
\text{Assert}, & \text{if } \eta(s) \in \{ \text{"assert"}, \text{"assertion"}, \text{"invariant"}, \text{"guarantee"}, \text{"ensure"} \} \\
\text{Assume}, & \text{if } \eta(s) \in \{ \text{"assume"}, \text{"assumption"}, \text{"precondition"}, \text{"require"} \} \\
\bot_{\text{kind}}, & \text{otherwise}
\end{cases}
$$

The severity classification domain $\mathcal{V}_{\text{sev}}$ and discrete parsing operator $\text{ParseSeverity} : (\Sigma^* \cup \{ \bot \}) \to \mathcal{V}_{\text{sev}} \cup \{ \bot_{\text{sev}} \}$ are defined as:

$$
\text{ParseSeverity}(s) = 
\begin{cases}
\text{Critical}, & \text{if } s = \bot \;\vee\; s = \text{""} \\
\text{Critical}, & \text{if } \eta(s) \in \{ \text{"critical"}, \text{"fatal"}, \text{"safety\_critical"}, \text{"high"} \} \\
\text{Degraded}, & \text{if } \eta(s) \in \{ \text{"degraded"}, \text{"warning"}, \text{"major"}, \text{"medium"} \} \\
\text{Advisory}, & \text{if } \eta(s) \in \{ \text{"advisory"}, \text{"info"}, \text{"informational"}, \text{"minor"}, \text{"low"} \} \\
\bot_{\text{sev}}, & \text{otherwise}
\end{cases}
$$

The operational envelope domain $\mathbb{E}$ defines boundary limits and boundary openness flags:

$$
\mathcal{I} = \langle L, U, o_L, o_U \rangle \in (\mathbb{R} \cup \{ -\infty \}) \times (\mathbb{R} \cup \{ +\infty \}) \times \mathbb{B} \times \mathbb{B}
$$

The Operational Envelope Ordering Invariant mandates:

$$
\forall C_i \in \mathcal{C}, \quad \mathcal{I}_i \ne \bot_{\text{env}} \implies \text{ValidEnvelope}(\mathcal{I}_i)
$$

where:

$$
\text{ValidEnvelope}(\langle L, U, o_L, o_U \rangle) \iff (L \le U) \;\wedge\; (L = U \implies (\neg o_L \wedge \neg o_U \wedge L \in \mathbb{R}))
$$

Scoped Constraint Identifier Uniqueness Invariant: Within the namespace of any owning parent classifier $O \in \mathcal{S}_{\text{sym}}$, all constraint identifiers must be pairwise distinct:

$$
\forall C_a, C_b \in \mathcal{C}, \quad (C_a.\text{owner} = C_b.\text{owner} \;\wedge\; C_a.\text{id} = C_b.\text{id}) \implies C_a = C_b
$$

Row-to-Entity Ingestion Mapping: The row ingestion operator $\Phi_{\text{constraint}} : \text{Row} \to \text{IngestedConstraint} \cup \{ \bot_{\text{constraint}} \}$ evaluates row $R_i$:

$$
\Phi_{\text{constraint}}(R_i) = 
\begin{cases}
C_i, & \text{if } \text{ValidConstraintRow}(R_i) \\
\bot_{\text{constraint}}, & \text{if } \neg \text{ValidConstraintRow}(R_i)
\end{cases}
$$

Contiguous Arena Allocation Invariant: Entity allocation proceeds sequentially in contiguous memory:

$$
\forall i \in \{1, \dots, M\}, \quad \text{Allocate}(\text{Arena}, C_i) = h_i \in \mathcal{H}_{\text{node}}
$$

satisfying constant stride progression:

$$
\text{Offset}(h_{i+1}) = \text{Offset}(h_i) + \text{sizeof}(\text{IngestedConstraint})
$$

Diagnostic Code Binding Invariant: Syntax and structural invariant violations deterministically trigger structured diagnostic records in accordance with REQ-0191:

$$
\begin{aligned}
\text{Cell}(R_i, \beta^{-1}(\text{id})) = \varepsilon &\implies \text{Diagnostic}(R_i, \beta^{-1}(\text{id}), \text{DiagnosticCode::E0102}, \text{MissingConstraintId}) \in \mathcal{D} \\
\text{Cell}(R_i, \beta^{-1}(\text{owner})) = \varepsilon &\implies \text{Diagnostic}(R_i, \beta^{-1}(\text{owner}), \text{DiagnosticCode::E0102}, \text{MissingOwnerClassifier}) \in \mathcal{D} \\
\text{Cell}(R_i, \beta^{-1}(\text{expr})) = \varepsilon &\implies \text{Diagnostic}(R_i, \beta^{-1}(\text{expr}), \text{DiagnosticCode::E0102}, \text{MissingConstraintExpression}) \in \mathcal{D} \\
\text{ParseKind}(\text{Cell}(R_i, \beta^{-1}(\text{kind}))) = \bot_{\text{kind}} &\implies \text{Diagnostic}(R_i, \beta^{-1}(\text{kind}), \text{DiagnosticCode::E0102}, \text{InvalidConstraintKind}) \in \mathcal{D} \\
\text{ParseSeverity}(\text{Cell}(R_i, \beta^{-1}(\text{severity}))) = \bot_{\text{sev}} &\implies \text{Diagnostic}(R_i, \beta^{-1}(\text{severity}), \text{DiagnosticCode::E0102}, \text{InvalidSeverityClassification}) \in \mathcal{D} \\
\exists k \ne i \text{ s.t. } C_k.\text{owner} = C_i.\text{owner} \wedge C_k.\text{id} = C_i.\text{id} &\implies \text{Diagnostic}(R_i, \beta^{-1}(\text{id}), \text{DiagnosticCode::E0102}, \text{DuplicateConstraintId}) \in \mathcal{D} \\
\mathcal{I}_i \ne \bot_{\text{env}} \wedge \neg \text{ValidEnvelope}(\mathcal{I}_i) &\implies \text{Diagnostic}(R_i, \beta^{-1}(\text{envelope}), \text{DiagnosticCode::E0103}, \text{InvalidEnvelopeBounds}) \in \mathcal{D} \\
|\mathcal{D}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant: All diagnostics emitted by the constraint table parser strictly reside within the Subsystem 2 ingestion error family:

$$
\forall D \in \mathcal{D}_{\text{constraint}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0103}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{ingest}}
$$

- **Computational Complexity & Algorithmic Bounds**: Tabular schema ingestion for formal constraints and operational envelopes executes within Complexity Class $\mathbf{P}$. For an input document of total byte size $N$ containing $R$ constraint data rows and $C$ columns subject to the bounded column limit $C \le C_{\text{max\_cols}} = 32$, processing proceeds in deterministic stages: (1) Header normalization and column binding vector computation $\vec{\beta}$ execute once per table in $O(C) = O(1)$ operations. (2) For each row $R_i$, cell slice extraction via $\vec{\beta}$ executes in $O(C) = O(1)$ operations. (3) Constraint identifier and owner sanitization execute in $O(L_{\text{id}}) = O(1)$ operations for bounded string length $L_{\text{id}} \le 256$, and symbol interning operates in $O(1)$ amortized time. (4) Raw expression extraction preserves the byte slice directly from the input buffer without string copy, allocation, or regex evaluation, requiring $O(1)$ pointer-and-length slice construction operations. (5) Invariant kind parsing $\text{ParseKind}$ and severity parsing $\text{ParseSeverity}$ execute via static enumeration matching in $O(1)$ constant time. (6) Operational envelope parsing and interval consistency validation ($L \le U$) execute in $O(L_{\text{env}}) = O(1)$ scalar comparisons for interval string length $L_{\text{env}} \le 64$. (7) Scoped identifier uniqueness verification performs a hash lookup in a pre-sized 64-bit SymbolId set, executing in $O(1)$ expected amortized time per row. (8) Sequential allocation of the synthesized `IngestedConstraint` entity into contiguous arena storage requires a single pointer bump in $O(1)$ constant time. Thus, aggregate execution time across all $R$ constraint rows is strictly linear:

$$
T(R, N) = \sum_{i=1}^R O(C + L_{\text{id}} + L_{\text{kind}} + L_{\text{sev}} + L_{\text{env}}) + O(N) = O(R) = O(N)
$$

When processing $K$ distinct constraint tables across $N_{\text{max\_workers}}$ threads in a bounded work-stealing thread pool, parallel wall-clock runtime is bounded by $O(\lceil K / N_{\text{max\_workers}} \rceil \cdot R_{\text{max}})$. Auxiliary space complexity is strictly bounded by $O(1)$ stack space per row and $O(C + C_{\text{max\_errors}})$ heap memory overhead for the active column binding buffer and preallocated diagnostic sink, guaranteeing $O(1)$ auxiliary memory overhead relative to input stream length $N$.

- **Verification & Conformance Criteria**: Automated test suites shall verify compliance against synthetic CommonMark schema tables specifying formal constraints and operational envelopes using abstract MBSE entity placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Component_0`, `Constraint_1`, `Constraint_2`, `param_x : Real`, `Envelope_0`). Conformance shall be validated through the following deterministic test gates: (1) Verbatim Expression Preservation Gate: Ingest a canonical constraint table containing complex Boolean expressions, arithmetic comparisons, and logic operators (e.g., `param_x >= 0.0 && param_x <= 100.0`, `param_a + param_b == param_c`, `!(flag_1 && flag_2) || state == State_A`); assert that 100% of raw expression strings in the synthesized `IngestedConstraint` AST entities match source cell byte slices with 0-byte divergence. (2) Kind and Severity Normalization Gate: Validate that constraint kind tokens (`assert`, `assertion`, `invariant`, `guarantee`, `assume`, `assumption`, `precondition`) and severity tokens (`critical`, `fatal`, `degraded`, `warning`, `advisory`, `info`) parse correctly into their respective enum variants; assert that empty cells default to `Assert` and `Critical`. (3) Scoped Identifier Uniqueness Gate: Ingest a table declaring two distinct constraints with identical identifier `Constraint_1` under the same owner `Classifier_Alpha`; assert deterministic emission of diagnostic error code `E0102` reporting duplicate constraint identifier collision, substitution of error sentinel $\bot_{\text{constraint}}$, and continuation of table parsing. (4) Missing Mandatory Column Gate: Ingest test tables omitting mandatory columns (`id`, `owner`, or `expr`); assert deterministic emission of diagnostic error code `E0102` identifying the missing mandatory field and table header source byte span. (5) Operational Envelope Consistency Gate: Ingest constraint rows with explicit operational envelopes across closed, open, and half-open intervals (`[0.0, 100.0]`, `(0.0, 1.0]`, `[-10, 10]`, `[0.0, +inf)`); assert valid extraction into $\mathcal{I}_i$; ingest rows with inverted bounds (e.g., `[100.0, 10.0]`) or open degenerate intervals (`(5.0, 5.0)`); assert deterministic emission of diagnostic error code `E0103` (`InvalidEnvelopeBounds`). (6) Architectural Directive 4 Synchronization Recovery Gate: Ingest a 10-row constraint table where rows 3 and 7 contain deliberate syntax faults (unrecognized kind literal `"unknown_kind"` in row 3, missing expression in row 7); assert that rows 1, 2, 4, 5, 6, 8, 9, 10 parse into valid `IngestedConstraint` AST nodes, rows 3 and 7 substitute typed sentinel $\bot_{\text{constraint}}$, exactly two structured `E0102` diagnostics are recorded, and parsing resynchronizes on row line breaks ($\text{SYM}_{\text{LF}}$) without aborting compilation. (7) Diagnostic Sink Saturation Gate: Ingest a corrupted table containing invalid rows exceeding $C_{\text{max\_errors}}$; assert parsing terminates gracefully with terminal diagnostic error code `E0199`. (8) Architectural Directive 5 Non-Panicking & Release Latency Gate: Execute benchmark stress tests over $10^5$ synthetic constraint declarations in compiled Release mode (`--release`); assert total-function execution with zero panics, processing throughput exceeding $100{,}000$ rows per second, execution latency under 20 ms, peak RSS memory under 25 MB, and 0-byte diff churn across consecutive compiler runs.
