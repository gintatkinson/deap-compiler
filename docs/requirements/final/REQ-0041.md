### REQ-0041: Lexical Scope Lookup & Fully Qualified Path Resolution (`::`)

- **Normative Statement**: The Core Metamodel, Node Arena & AST Graph Engine shall implement a hierarchical lexical scope resolution and path evaluation engine utilizing double-colon scoping (`::`) to resolve identifier references across nested lexical scopes, package boundaries, and imported namespaces. The symbol resolver shall support both unqualified identifier lookups and qualified path resolutions:
  1. Unqualified Lexical Lookup: When an unqualified symbol identifier $\sigma$ is referenced within an active lexical scope $S_{\text{active}}$, the resolver shall search inward-to-outward starting at $S_{\text{active}}$, traversing enclosing ancestor scopes sequentially along the lexical parent chain $\text{parent}(S)$ until the root namespace $S_{\text{root}}$ is reached. The first matching visible symbol declaration encountered along this traversal shall bind to the reference, establishing lexical shadowing where definitions in inner scopes shadow identical identifiers declared in outer enclosing scopes.
  2. Fully Qualified Path Resolution: When a reference specifies a qualified path $p_1::p_2::\dots::p_k$, the resolver shall evaluate the path deterministically. If the path begins with a leading double-colon prefix (`::`), the path is designated as an absolute qualified path, and resolution of the leading segment $p_1$ shall initiate strictly at the root namespace $S_{\text{root}}$. If the path lacks a leading double-colon prefix, it is designated as a relative qualified path, and resolution of $p_1$ shall execute via standard unqualified lexical lookup starting from $S_{\text{active}}$. Each subsequent segment $p_{j}$ ($2 \le j \le k$) shall resolve strictly as a direct member of the namespace or classifier entity bound to the preceding segment $p_{j-1}$.
  3. Visibility Boundary Enforcement: Every symbol declared within a namespace shall possess an explicit or defaulted visibility attribute $v \in \{ \text{Public}, \text{Private}, \text{Protected} \}$. Symbols marked as `Public` shall be accessible from any scope where their enclosing namespace is reachable. Symbols marked as `Private` shall be accessible exclusively from lexical scopes enclosed within their declaring package or namespace boundary, and shall be strictly inaccessible to foreign namespaces unless explicit namespace friendship or re-export declarations are present. Symbols marked as `Protected` shall be accessible exclusively within the declaring classifier and its conforming sub-classifiers. Any attempt to reference an inaccessible private or protected symbol shall be rejected at compile time with structured diagnostic error code `E0200` per REQ-0191.
  4. Namespace Imports & Ambiguity Detection: Scopes may import symbols from external packages via qualified single-item imports or wildcard package imports. Imported symbols shall be registered in an auxiliary imported symbol table. If an unqualified lookup matches multiple imported symbols from distinct packages without a local declaration shadowing them, the resolver shall reject the reference as an ambiguous import conflict with diagnostic error code `E0200`.
  5. Deterministic Node Handles & Architectural Directives: All scope tree nodes, symbol table buckets, and resolved reference bindings shall be allocated sequentially within contiguous bump arena memory in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit arena node handles in accordance with REQ-0035. Every lexical scope and qualified symbol entity must receive an immutable RFC 4122 UUIDv5 identifier generated by hashing the fixed compiler namespace OID with its canonical fully qualified path, adhering to Architectural Directive 1 and REQ-0010. Symbol identifiers, package names, and path segments shall be interned into the global symbol interner pool as scalar `SymbolId` tokens during lexical ingestion, representing the sole permitted exception to zero-copy memory management in accordance with Architectural Directive 3 and REQ-0036. Parallel symbol table construction and scope resolution across independent compilation units shall be dispatched strictly onto a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with Architectural Directive 2 and REQ-0012. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the resolver shall implement synchronization token error recovery: upon encountering an unresolvable symbol or visibility violation (`E0200`), the engine shall record the diagnostic with source byte spans and line/column coordinates, bind an error sentinel handle $\bot_{\text{node}}$, and continue resolving subsequent AST nodes. If accumulated diagnostics reach sink capacity $C_{\text{max\_errors}}$, the compiler shall emit `E0199` and terminate gracefully. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the resolver must enforce a deterministic, non-panicking execution contract with total-function termination across all inputs, evaluating performance gates (< 25 ms execution latency, < 100 MB RSS) exclusively in compiled Release mode (`--release`). All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Package_1`, `Package_Root`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Port_2`, `Feature_A`, `param_x : Real`) with zero domain contamination.

- **Formal Invariant**: Let $\mathcal{S}$ denote the finite set of lexical scopes within the compilation unit AST graph, forming a rooted tree $T_{\text{scope}} = (\mathcal{S}, \mathcal{E}_{\text{scope}})$ rooted at $S_{\text{root}} \in \mathcal{S}$. Each scope $S \in \mathcal{S}$ is formalized as an 8-tuple:

$$
S = \langle \text{id}_S, \text{name}_S, \kappa_S, \text{parent}_S, \mathcal{M}_S, \mathcal{I}_S, \Delta_S, \text{span}_S \rangle
$$

where:

$$
\begin{aligned}
\text{id}_S &\in \mathbb{N}_{32} \quad (\text{contiguous arena scope handle}) \\
\text{name}_S &\in \mathcal{S}_{\text{sym}} \quad (\text{interned scope identifier token}) \\
\kappa_S &\in \{ \text{Global}, \text{Package}, \text{Classifier}, \text{Feature}, \text{Block} \} \quad (\text{scope discriminant kind}) \\
\text{parent}_S &\in \mathcal{S} \cup \{ \bot \} \quad (\text{enclosing lexical parent scope, with } \text{parent}(S_{\text{root}}) = \bot) \\
\mathcal{M}_S &\subseteq \mathcal{E}_{\text{sym}} \quad (\text{locally declared symbol entry mapping}) \\
\mathcal{I}_S &\subseteq \mathcal{E}_{\text{sym}} \quad (\text{imported symbol entries available in scope}) \\
\Delta_S &\in \Sigma^* \quad (\text{deterministic RFC 4122 UUIDv5 topological namespace anchor}) \\
\text{span}_S &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

Each symbol entry $e \in \mathcal{E}_{\text{sym}}$ is formalized as a 4-tuple:

$$
e = \langle \sigma_e, h_e, \text{vis}_e, \text{span}_e \rangle
$$

where $\sigma_e \in \mathcal{S}_{\text{sym}}$ is the interned scalar symbol handle, $h_e \in \mathcal{H}_{\text{node}}$ is the AST node handle in the typed arena, $\text{vis}_e \in \{ \text{Public}, \text{Private}, \text{Protected} \}$ is the visibility discriminant, and $\text{span}_e$ is the lexical coordinate span.

Visibility Conformance Predicate: Let $\text{EnclosingPackage}(x)$ denote the nearest ancestor package scope enclosing entity $x$. Symbol entry $e$ declared in scope $S_{\text{decl}}$ is visible to a lookup originating from caller scope $S_{\text{caller}}$ if and only if:

$$
\text{IsVisible}(e, S_{\text{caller}}) \iff \begin{cases}
\text{true}, & \text{if } e.\text{vis}_e = \text{Public} \\
\text{true}, & \text{if } e.\text{vis}_e = \text{Private} \;\wedge\; \text{EnclosingPackage}(S_{\text{decl}}) = \text{EnclosingPackage}(S_{\text{caller}}) \\
\text{true}, & \text{if } e.\text{vis}_e = \text{Protected} \;\wedge\; \text{ConformsClassifier}(S_{\text{caller}}, S_{\text{decl}}) \\
\text{false}, & \text{otherwise}
\end{cases}
$$

Hierarchical Unqualified Lookup Function: For requested symbol $\sigma \in \mathcal{S}_{\text{sym}}$ starting at scope $S \in \mathcal{S}$ on behalf of caller scope $S_{\text{caller}} \in \mathcal{S}$:

$$
\text{Find}(\sigma, S, S_{\text{caller}}) = \begin{cases}
e.h_e, & \text{if } \exists e \in \mathcal{M}_S : e.\sigma_e = \sigma \;\wedge\; \text{IsVisible}(e, S_{\text{caller}}) \\
\text{FindImported}(\sigma, \mathcal{I}_S, S_{\text{caller}}), & \text{if } (\forall e \in \mathcal{M}_S, e.\sigma_e \ne \sigma) \;\wedge\; \exists ! e \in \mathcal{I}_S : e.\sigma_e = \sigma \;\wedge\; \text{IsVisible}(e, S_{\text{caller}}) \\
\text{Find}(\sigma, S.\text{parent}_S, S_{\text{caller}}), & \text{if } (\forall e \in \mathcal{M}_S, e.\sigma_e \ne \sigma) \;\wedge\; S.\text{parent}_S \ne \bot \\
\bot, & \text{otherwise}
\end{cases}
$$

Qualified Path Resolution: A qualified path $\pi$ is an ordered sequence of interned symbol segment identifiers:

$$
\pi = \langle p_1, p_2, \dots, p_k \rangle, \quad p_j \in \mathcal{S}_{\text{sym}} \quad (1 \le j \le k)
$$

with path classification flag $\alpha \in \{ \text{Absolute}, \text{Relative} \}$. The qualified lookup function $\text{FindQualified}(\pi, \alpha, S_{\text{caller}})$ satisfies:

$$
\text{FindQualified}(\pi, \alpha, S_{\text{caller}}) = \text{ResolveTail}(S_{\text{base}}, 2, k, \pi, S_{\text{caller}})
$$

where the initial base scope $S_{\text{base}}$ is determined by:

$$
S_{\text{base}} = \begin{cases}
\text{LookupChildScope}(S_{\text{root}}, p_1, S_{\text{caller}}), & \text{if } \alpha = \text{Absolute} \\
\text{ScopeOfNode}(\text{Find}(p_1, S_{\text{caller}}, S_{\text{caller}})), & \text{if } \alpha = \text{Relative}
\end{cases}
$$

and successive segments are recursively resolved via direct child membership:

$$
\text{ResolveTail}(S, j, k, \pi, S_{\text{caller}}) = \begin{cases}
S, & \text{if } j \gt k \;\wedge\; S \ne \bot \\
\bot, & \text{if } S = \bot \\
\text{ResolveTail}(\text{LookupChildScope}(S, p_j, S_{\text{caller}}), j + 1, k, \pi, S_{\text{caller}}), & \text{otherwise}
\end{cases}
$$

Lexical Shadowing Invariant: If a symbol $\sigma$ is declared in both an inner scope $S_{\text{inner}}$ and an ancestor scope $S_{\text{ancestor}} = \text{Ancestor}(S_{\text{inner}})$ ($e_1 \in \mathcal{M}_{S_{\text{inner}}}, e_2 \in \mathcal{M}_{S_{\text{ancestor}}}$ with $e_1.\sigma_e = e_2.\sigma_e = \sigma$), unqualified lookup within $S_{\text{inner}}$ deterministically selects the inner declaration:

$$
\text{Find}(\sigma, S_{\text{inner}}, S_{\text{inner}}) = e_1.h_e \ne e_2.h_e
$$

while the shadowed ancestor declaration remains accessible via its fully qualified canonical path:

$$
\text{FindQualified}(\text{FQN}(e_2), \text{Absolute}, S_{\text{inner}}) = e_2.h_e
$$

Bounded Lexical Nesting Depth Invariant: The maximum depth of the lexical scope tree is strictly bounded by constant $D_{\max} = 16$:

$$
\forall S \in \mathcal{S}, \quad \text{Depth}(S) \le D_{\max} = 16
$$

Diagnostic Error Code Trigger Invariants: Failures during lexical scope lookup and path resolution deterministically trigger diagnostic error code `E0200` per REQ-0191:

$$
\begin{aligned}
\text{Find}(\sigma, S_{\text{caller}}, S_{\text{caller}}) = \bot &\implies \text{Diagnostic}(\sigma, \text{DiagnosticCode::E0200}, \text{UnresolvedSymbolReference}) \in \mathcal{D}_{\text{sink}} \\
\text{FindQualified}(\pi, \alpha, S_{\text{caller}}) = \bot &\implies \text{Diagnostic}(\pi, \text{DiagnosticCode::E0200}, \text{UnresolvedQualifiedPath}) \in \mathcal{D}_{\text{sink}} \\
\exists e : e.\sigma_e = \sigma \;\wedge\; \neg\text{IsVisible}(e, S_{\text{caller}}) &\implies \text{Diagnostic}(e, \text{DiagnosticCode::E0200}, \text{InaccessiblePrivateMember}) \in \mathcal{D}_{\text{sink}} \\
\text{AmbiguousImports}(\sigma, \mathcal{I}_S) \gt 1 &\implies \text{Diagnostic}(\sigma, \text{DiagnosticCode::E0200}, \text{AmbiguousImportConflict}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Deterministic RFC 4122 UUIDv5 Topological Anchor Invariant: Every lexical scope entity $S \in \mathcal{S}$ is anchored by a deterministic UUIDv5 identifier derived from the compiler namespace OID and canonical fully qualified path:

$$
\forall S \in \mathcal{S}, \quad \Delta_S = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(S))
$$

- **Computational Complexity & Algorithmic Bounds**: Lexical scope lookup and qualified path resolution execute strictly within Complexity Class $\mathbf{P}$. The algorithmic bounds across operations are formalized as follows:
  1. Unqualified Lexical Lookup Complexity: Traversing the lexical parent chain visits at most $D_{\max} \le 16$ scope ancestors. At each scope $S$, looking up an interned symbol handle $\sigma \in \mathcal{S}_{\text{sym}}$ within the local hash map $\mathcal{M}_S$ executes in amortized $O(1)$ time with zero string comparisons. Consequently, worst-case unqualified lookup time is strictly constant:

$$
T_{\text{unqual}}(\sigma) \le D_{\max} \cdot O(1) = 16 \cdot O(1) \in O(1)
$$

  2. Qualified Path Resolution Complexity: For any qualified path $\pi$ consisting of $k$ segments ($k \le K_{\max} = 16$): resolving the leading segment $p_1$ requires $O(1)$ time (if absolute) or $O(D_{\max}) = O(1)$ time (if relative). Resolving each of the subsequent $k - 1$ child segments requires an $O(1)$ hash table lookup in the member scope of the preceding entity. Therefore, total qualified path evaluation executes in constant time:

$$
T_{\text{qual}}(\pi) \le O(1) + (k - 1) \cdot O(1) \in O(k) \subseteq O(1)
$$

  3. Total AST Model Resolution Complexity: For an entire AST model comprising $N$ symbol references across $V = |\mathcal{V}_{\text{AST}}|$ nodes and $|\mathcal{S}|$ lexical scopes:

$$
T_{\text{total}}(N) = \sum_{i=1}^{N} O(1) \in O(N)
$$

  4. Parallel Scheduling Complexity: Under bounded work-stealing multithreading scheduled over $N_{\text{max\_workers}}$ worker threads for independent compilation units:

$$
T_{\text{parallel}}(N) \in O\left(\frac{N}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}}\right)
$$

  5. Space Complexity: Auxiliary memory overhead for scope resolution is bounded by $O(D_{\max}) = O(1)$ call stack frames and $O(1)$ heap overhead beyond the contiguous arena storage for the AST graph ($O(V)$) and preallocated diagnostic sink ($O(C_{\text{max\_errors}}) = O(1)$).

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic MBSE models (e.g., `Package_0`, `Package_1`, `Package_Root`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Port_2`, `Feature_A`, `param_x : Real`) across the following verification gates:
  1. Lexical Scope Shadowing Gate:
     - Construct a nested synthetic model hierarchy `Package_Root::Package_0::Classifier_Alpha`.
     - Declare symbol `param_x : Real` in `Package_0` and declare a shadowing local symbol `param_x : Integer` inside `Classifier_Alpha`.
     - Assert that unqualified lookup of `param_x` within `Classifier_Alpha` resolves deterministically to the local `Integer` declaration handle.
     - Assert that fully qualified lookup `::Package_Root::Package_0::param_x` within `Classifier_Alpha` resolves to the shadowed `Real` declaration handle.
  2. Fully Qualified Path Resolution Gate:
     - Validate absolute qualified path `::Package_Root::Package_0::Classifier_Alpha` from deeply nested sibling scope `Classifier_Beta`.
     - Validate relative qualified path `Package_0::Classifier_Alpha` from enclosing scope `Package_Root`.
     - Assert 100% resolution success with exact node handle bindings, zero diagnostics, and zero pointer dereference faults.
  3. Private Visibility Boundary Enforcement Gate:
     - Declare private feature `Feature_A` within `Package_0`.
     - Attempt unqualified and qualified access to `Package_0::Feature_A` from foreign sibling `Package_1`.
     - Assert deterministic compile-time rejection emitting diagnostic error code `E0200` (`InaccessiblePrivateMember`) with exact source byte span and line/column coordinates.
     - Assert that access to `Feature_A` from an enclosed child scope `Package_0::Classifier_Alpha` succeeds without diagnostics.
  4. Unresolved Symbol & Qualified Path Diagnostic Gate:
     - Ingest an AST model referencing non-existent unqualified identifier `Classifier_NonExistent` and non-existent qualified path `Package_0::Invalid_Child`.
     - Assert deterministic emission of diagnostic error code `E0200` (`UnresolvedSymbolReference` and `UnresolvedQualifiedPath`).
     - Assert that the resolver binds error sentinel node handle $\bot_{\text{node}}$, preventing cascading compiler aborts.
  5. Ambiguous Import Conflict Gate:
     - Import two separate packages `Package_0` and `Package_1`, where both packages declare and export identical symbol name `Classifier_Alpha`.
     - Reference `Classifier_Alpha` unqualified in the importing scope.
     - Assert deterministic rejection emitting diagnostic error code `E0200` (`AmbiguousImportConflict`) listing both candidate declaration locations.
  6. Scope Nesting Depth Limit Gate:
     - Construct a synthetic model with lexical nesting depth exceeding $D_{\max} = 16$.
     - Assert deterministic emission of diagnostic error code `E0200` (`ScopeNestingDepthExceeded`) with structured error recovery.
  7. Deterministic Non-Panicking & Latency Performance Gate:
     - In compiled Release mode (`--release`), benchmark scope resolution across an AST model containing $10^5$ symbol lookups.
     - Assert total-function execution with zero panics, execution latency strictly under 25 ms, and peak RSS memory strictly under 100 MB per REQ-0011 and REQ-0196.
     - Assert bitwise determinism and 0-byte diff churn across consecutive compiler runs.
