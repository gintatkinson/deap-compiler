### REQ-0179: Continuous-Time Numerical Solvers: Discrete Fixed-Step Euler Integration

- **Normative Statement**: The simulation engine, code emission pipeline, and numerical solver framework of Subsystem 10 shall synthesize discrete fixed-step Forward Euler numerical integration blocks for continuous-time dynamical system models, providing low-overhead baseline simulation capabilities for linear and weakly non-linear dynamics. The compiler shall ingest continuous-time differential equation specifications $`\dot{\mathbf{x}}(t) = f(\mathbf{x}(t), \mathbf{u}(t), t)`$ defined over state vector $`\mathbf{x} \in \mathbb{R}^n`$, input vector $`\mathbf{u} \in \mathbb{R}^m`$, time $`t \in \mathbb{R}`$, and a strictly positive fixed integration timestep $`\Delta t \gt 0`$. The synthesis engine shall lower continuous state equations into discrete recurrence update blocks $`\mathbf{x}_{k+1} = \mathbf{x}_k + \Delta t \cdot f(\mathbf{x}_k, \mathbf{u}_k, t_k)`$, emitting deterministic stepping routines across target backends including LUMI Intermediate Representation (LUMI IR) static single assignment (SSA) basic blocks per REQ-0175, freestanding zero-allocation C++20 classes per REQ-0184, high-integrity embedded MISRA C99 routines per REQ-0185, and verification test harnesses. The engine shall verify static numerical stability bounds, timestep positivity ($`\Delta t \gt 0`$), dimension conformance ($`\dim(\mathbf{x}) = \dim(f) = n`$, $`\dim(\mathbf{u}) = m`$), and float finite-domain bounds ($`\forall i, \, x_{i, k} \notin \{ \text{NaN}, \pm\infty \}`$). If timestep $`\Delta t \le 0`$, if state or input dimensions mismatch, if linear system eigenvalues violate the absolute stability disc, or if numerical overflow or NaN values occur, the compiler shall fail closed and emit diagnostic error code `E0500`.

  Specifically, the simulation engine, code emission pipeline, and numerical solver framework shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Continuous Dynamical System Ingestion & State Vector Architecture**:
     - The compiler shall ingest continuous-time ordinary differential equations (ODEs), linear continuous state-space models ($`\dot{\mathbf{x}} = \mathbf{A}\mathbf{x} + \mathbf{B}\mathbf{u}`$, $`\mathbf{y} = \mathbf{C}\mathbf{x} + \mathbf{D}\mathbf{u}`$), and non-linear continuous vector fields $`f : \mathbb{R}^n \times \mathbb{R}^m \times \mathbb{R} \to \mathbb{R}^n`$ declared in SysML v2 / KerML behavioral packages.
     - The engine shall extract state variable roster $`\mathbf{X} = \langle x_1, x_2, \dots, x_n \rangle`$ of dimension $`n = \dim(\mathbf{x}) \ge 1`$, input variable roster $`\mathbf{U} = \langle u_1, u_2, \dots, u_m \rangle`$ of dimension $`m = \dim(\mathbf{u}) \ge 0`$, and state derivative vector expression $`\dot{\mathbf{X}} = \langle \dot{x}_1, \dot{x}_2, \dots, \dot{x}_n \rangle`$.
     - Dimension conformance: The compiler shall verify that the dimension of the derivative vector expression exactly equals the state vector dimension ($`\dim(f) = \dim(\mathbf{x}) = n`$). If a dimension mismatch is detected, the compiler shall emit diagnostic error code `E0500` (`StateDimensionMismatchViolation`).
     - Input conformance: If the continuous model specifies input matrix $`\mathbf{B} \in \mathbb{R}^{n \times m}`$, the compiler shall verify that input vector $`\mathbf{u}`$ conforms to dimension $`m`$. If an input dimension mismatch is detected, the compiler shall emit diagnostic error code `E0500` (`InputDimensionMismatchViolation`).
     - Initial conditions: The continuous model shall bind an initial state vector $`\mathbf{x}_0 \in \mathbb{R}^n`$ at simulation epoch $`t_0 \in \mathbb{R}`$. If any initial state component is undefined or non-finite, the compiler shall emit diagnostic error code `E0500` (`InitialConditionInvalidViolation`).
  2. **Discrete Fixed-Step Forward Euler Recurrence Synthesis**:
     - For a configured fixed integration timestep $`\Delta t \gt 0`$, the synthesis engine shall lower continuous state differential equations into discrete-time recurrence difference equations:

$$
\mathbf{x}_{k+1} = \mathbf{x}_k + \Delta t \cdot f(\mathbf{x}_k, \mathbf{u}_k, t_k), \quad t_{k+1} = t_k + \Delta t
$$

     - For linear continuous state-space dynamics $`\dot{\mathbf{x}} = \mathbf{A}\mathbf{x} + \mathbf{B}\mathbf{u}`$, the synthesized recurrence block shall evaluate:

$$
\mathbf{x}_{k+1} = (\mathbf{I}_n + \Delta t \cdot \mathbf{A}) \mathbf{x}_k + \Delta t \cdot \mathbf{B} \mathbf{u}_k
$$

     - Timestep positivity verification: The integration timestep $`\Delta t`$ must be strictly positive ($`\Delta t \gt 0`$). If $`\Delta t \le 0`$ or $`\Delta t`$ is non-finite, the compiler shall fail closed and emit diagnostic error code `E0500` (`NonPositiveTimestepViolation`).
     - Stepping function synthesis: The compiler shall synthesize both a single-step evaluation kernel (`StepEuler`) and a multi-step trajectory iterator (`SimulateEuler`) accepting initial state $`\mathbf{x}_0`$, input sequence $`\langle \mathbf{u}_0, \mathbf{u}_1, \dots, \mathbf{u}_{K-1} \rangle`$, and total step count $`K = \lfloor (t_{\text{final}} - t_0) / \Delta t \rfloor`$.
  3. **Local and Global Truncation Error Bounds & Convergence Rates**:
     - The compiler shall document and enforce the theoretical error properties of Forward Euler integration:
       - *Local Truncation Error (LTE)*: For sufficiently smooth trajectories with bounded second derivative ($`\sup \|\ddot{\mathbf{x}}(t)\| \le M_2`$), the local truncation error per step satisfies:

$$
\mathbf{d}_{k+1} = \mathbf{x}(t_{k+1}) - (\mathbf{x}(t_k) + \Delta t \cdot f(\mathbf{x}(t_k), \mathbf{u}(t_k), t_k)) = \frac{1}{2} \Delta t^2 \cdot \ddot{\mathbf{x}}(\xi_k) \in \mathcal{O}(\Delta t^2)
$$

       - *Global Truncation Error (GTE)*: For Lipschitz-continuous derivative functions satisfying $`\|f(\mathbf{x}_1) - f(\mathbf{x}_2)\| \le L \|\mathbf{x}_1 - \mathbf{x}_2\|`$, the accumulated global error across $`K`$ steps over interval $`[t_0, t_{\text{final}}]`$ satisfies:

$$
\|\mathbf{e}_K\| = \|\mathbf{x}(t_K) - \mathbf{x}_K\| \le \frac{M_2}{2 L} \left( e^{L(t_{\text{final}} - t_0)} - 1 \right) \Delta t \in \mathcal{O}(\Delta t)
$$

       - Convergence rate: Forward Euler exhibits first-order numerical convergence ($`\mathcal{O}(\Delta t)`$). Halving the integration timestep $`\Delta t \to \Delta t / 2`$ shall approximately halve the global integration error on non-stiff systems.
  4. **Linear Stability & Region of Absolute Stability Verification**:
     - For linear dynamics $`\dot{\mathbf{x}} = \mathbf{A}\mathbf{x}`$ with system matrix $`\mathbf{A} \in \mathbb{R}^{n \times n}`$, discrete state evolution follows the transition matrix $`\mathbf{\Phi}(\Delta t) = \mathbf{I}_n + \Delta t \cdot \mathbf{A}`$.
     - Asymptotic numerical stability requires that all eigenvalues of $`\mathbf{\Phi}(\Delta t)`$ lie within the closed unit disc of the complex plane:

$$
\forall \lambda \in \text{eig}(\mathbf{A}), \quad |1 + \lambda \Delta t| \le 1
$$

     - The region of absolute stability for Forward Euler in the complex plane $`\mathbb{C}`$ is the closed disc of radius 1 centered at $`-1`$:

$$
\mathcal{S}_{\text{Euler}} = \{ z \in \mathbb{C} \mid |1 + z| \le 1 \}
$$

     - Real negative eigenvalues: For real poles $`\lambda_i = -\sigma_i`$ ($`\sigma_i \gt 0`$), stability requires:

$$
0 \lt \Delta t \le \frac{2}{\sigma_i} = \frac{2}{|\text{Re}(\lambda_i)|}
$$

     - Spectral radius invariant: The spectral radius of the transition matrix must satisfy:

$$
\rho(\mathbf{I}_n + \Delta t \cdot \mathbf{A}) \le 1
$$

     - Undamped oscillator instability: For undamped conservative systems possessing purely imaginary eigenvalues $`\lambda_i = \pm i \omega_i`$ ($`\omega_i \ne 0`$), the stability factor evaluates to:

$$
|1 \pm i \omega_i \Delta t| = \sqrt{1 + \omega_i^2 \Delta t^2} \gt 1 \quad \forall \Delta t \gt 0
$$

       Forward Euler is unconditionally unstable for purely imaginary eigenvalues. The compiler shall detect undamped oscillation models at compile time and emit diagnostic error code `E0500` (`UndampedOscillatorInstabilityViolation`), warning that energy will artificially grow exponentially.
     - Compile-time static stability check: When system matrix $`\mathbf{A}`$ and timestep $`\Delta t`$ are statically known, the compiler shall compute or bound $`\rho(\mathbf{I}_n + \Delta t \cdot \mathbf{A})`$. If $`\rho \gt 1`$, the compiler shall emit diagnostic error code `E0500` (`NumericalInstabilityViolation`).
  5. **Finite Precision Arithmetic & Floating-Point Sanitization**:
     - Numerical computations shall execute in IEEE 754 double-precision 64-bit binary floating-point format (`binary64`, `f64`).
     - Runtime validation assertion: In synthesized simulation stepping code, the solver block shall verify at each integration step $`k`$:

$$
\forall i \in \{1, \dots, n\}, \quad \text{isfinite}(x_{i, k}) \equiv \text{true} \quad \wedge \quad |x_{i, k}| \le X_{\text{max}}
$$

       where $`X_{\text{max}} = 10^{300}`$ is the numerical divergence ceiling.
     - If any state component diverges to $`\pm\infty`$ or evaluates to NaN, the stepping routine shall trap the condition, abort trajectory propagation, and return diagnostic error code `E0500` (`NumericalDivergenceViolation`).
  6. **Multi-Target Code Generation Across Backend Sinks**:
     - *LUMI Intermediate Representation (REQ-0175, REQ-0176)*: The compiler shall synthesize discrete Euler stepping routines as LUMI IR functions containing SSA basic blocks, vector multiply-add instructions, and control flow loops without dynamic heap allocations.
     - *Freestanding C++20 (REQ-0184)*: The compiler shall emit freestanding header-only C++20 solver classes utilizing `std::array<double, N>` state containers, `constexpr` dimension parameters, and `noexcept` step methods.
     - *Embedded MISRA C99 (REQ-0185)*: The compiler shall emit high-integrity MISRA C99 functions operating on caller-provided static buffers with strictly bounded loop iterations and zero heap allocation.
     - *Streaming Persistence (REQ-0177, REQ-0178, REQ-0189)*: Emitted solver code files shall be written via bounded streaming sinks ($`\le 64\text{ KB}`$ chunk buffers), fingerprinted via XXH3 64-bit hashing, and recorded in `CodegenManifest`.
  7. **Strict Idempotency, Zero Diff Churn & Source Provenance**:
     - Re-running code generation with identical AST differential models shall produce identical solver source code byte-for-byte, guaranteeing 0-byte diff churn (REQ-0003, REQ-0032).
     - Every synthesized solver block, state variable, differential equation, and configuration parameter shall maintain bijective source provenance back to its originating SysML v2 / KerML AST node handle and source file byte span ($`\langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$) in accordance with REQ-0002.
  8. **Contiguous Bump Arena Memory Allocation & Node Addressing**:
     - All in-memory continuous solver descriptors, state variable metadata, differential equation expressions, and simulation step configurations shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
     - Solver structures shall be referenced exclusively by compact 32-bit arena node handles (REQ-0035), prohibiting internal raw heap pointers and reference cycles.
  9. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized solver block, continuous dynamical model definition, state variable, and simulation trajectory descriptor shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the entity fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(S) \mathbin{\Vert} \text{"::EulerSolver::"} \mathbin{\Vert} \text{name}_S)`$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel trajectory batch simulations, multi-scenario Monte Carlo evaluations, and parallel parameter sweeps across independent initial conditions shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: State variable names, parameter identifiers, unit annotations, and solver function names shall be interned into the deduplicated global symbol interner pool during model ingestion in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The solver parser and differential equation lowering pipeline shall implement synchronization token error recovery on statement delimiters (`;`), equation boundaries, and block delimiters (`}`) in accordance with REQ-0013 and REQ-0016. If an equation syntax or typing error occurs (`E0500`), the engine shall record a diagnostic into the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$, substitute typed error sentinels ($`\bot_{\text{ode}}`$), and proceed to parse subsequent equations. If accumulated diagnostics reach capacity limit $`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The numerical solver synthesis and simulation engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Solver code generation and simulation execution latency (strictly under 25 ms for synthesizing and evaluating $`10^4`$ simulation steps across $`n = 100`$ state variables) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  10. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Solver_Euler_0`, `State_Alpha`, `State_Beta`, `param_dt : Real`, `param_x0 : Real`, `Port_0`, `Flow_0`, `Matrix_A`, `Matrix_B`, `Trajectory_0`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

$$
  S = \langle \text{id}_S, \mathbf{X}, \mathbf{U}, f, \mathbf{A}, \mathbf{B}, \Delta t, \mathbf{x}_0, \Delta_S, \text{span}_S \rangle

$$

  1. Discrete Fixed-Step Forward Euler Recurrence Invariant:
  For step index $`k \in \{0, 1, \dots, K-1\}`$ with simulation epoch $`t_k = t_0 + k \Delta t`$:

$$
  \mathbf{x}_{k+1} = \mathbf{x}_k + \Delta t \cdot f(\mathbf{x}_k, \mathbf{u}_k, t_k)
$$

  For linear continuous systems with $`\mathbf{A} \ne \bot`$ and $`\mathbf{B} \ne \bot`$:

$$
  \mathbf{x}_{k+1} = (\mathbf{I}_n + \Delta t \cdot \mathbf{A}) \mathbf{x}_k + \Delta t \cdot \mathbf{B} \mathbf{u}_k
$$

  2. Local Truncation Error (LTE) Bound:
  Let $`\mathbf{x}^*(t)`$ denote the exact analytical solution of $`\dot{\mathbf{x}} = f(\mathbf{x}, \mathbf{u}, t)`$ passing through $`\mathbf{x}_k`$ at $`t_k`$. The local truncation error $`\mathbf{d}_{k+1}`$ satisfies:

$$
  \mathbf{d}_{k+1} = \mathbf{x}^*(t_k + \Delta t) - (\mathbf{x}_k + \Delta t \cdot f(\mathbf{x}_k, \mathbf{u}_k, t_k)) = \frac{1}{2} \Delta t^2 \cdot \ddot{\mathbf{x}}^*(\xi_k), \quad \xi_k \in [t_k, t_k + \Delta t]
$$

$$
  \|\mathbf{d}_{k+1}\| \le \frac{M_2}{2} \Delta t^2 \in \mathcal{O}(\Delta t^2)
$$

  where $`M_2 = \sup_{t \in [t_0, t_{\text{final}}]} \|\ddot{\mathbf{x}}^*(t)\|`$.

  3. Global Truncation Error (GTE) Bound:
  Let $`L = \sup_{\mathbf{x}_1 \ne \mathbf{x}_2} \frac{\|f(\mathbf{x}_1, \mathbf{u}, t) - f(\mathbf{x}_2, \mathbf{u}, t)\|}{\|\mathbf{x}_1 - \mathbf{x}_2\|}`$ denote the Lipschitz constant of $`f`$. The cumulative global error $`\mathbf{e}_K = \mathbf{x}^*(t_K) - \mathbf{x}_K`$ at step $`K`$ satisfies:

$$
  \|\mathbf{e}_K\| \le \frac{M_2}{2 L} \left( e^{L(t_K - t_0)} - 1 \right) \Delta t \in \mathcal{O}(\Delta t)
$$

  4. Region of Absolute Stability Invariant:
  Let $`\mathcal{S}_{\text{Euler}} \subset \mathbb{C}`$ denote the region of absolute stability:

$$
  \mathcal{S}_{\text{Euler}} = \{ z \in \mathbb{C} \mid |1 + z| \le 1 \}
$$

  For linear dynamics with system matrix $`\mathbf{A} \in \mathbb{R}^{n \times n}`$, numerical stability requires:

$$
  \forall \lambda \in \text{eig}(\mathbf{A}), \quad |1 + \lambda \Delta t| \le 1
$$

  The spectral radius of the discrete transition matrix $`\mathbf{\Phi} = \mathbf{I}_n + \Delta t \cdot \mathbf{A}`$ satisfies:

$$
  \rho(\mathbf{I}_n + \Delta t \cdot \mathbf{A}) = \max_{\lambda \in \text{eig}(\mathbf{A})} |1 + \lambda \Delta t| \le 1
$$

  For real negative eigenvalues $`\lambda_i = -\sigma_i`$ ($`\sigma_i \gt 0`$):

$$
  |1 - \sigma_i \Delta t| \le 1 \iff 0 \lt \Delta t \le \frac{2}{\sigma_i}
$$

  For complex conjugate pairs $`\lambda_{1, 2} = -\sigma \pm i \omega`$ ($`\sigma \gt 0`$):

$$
  |1 + (-\sigma \pm i \omega) \Delta t|^2 \le 1 \iff (1 - \sigma \Delta t)^2 + (\omega \Delta t)^2 \le 1 \iff \Delta t \le \frac{2 \sigma}{\sigma^2 + \omega^2}
$$

  For purely imaginary eigenvalues $`\lambda = \pm i \omega`$ ($`\omega \ne 0`$):

$$
  |1 \pm i \omega \Delta t|^2 = 1 + \omega^2 \Delta t^2 \gt 1 \quad \forall \Delta t \gt 0
$$

  5. Finite State Domain & Floating-Point Sanitization:
  For every simulated step $`k \in \{0, 1, \dots, K\}`$:

$$
  \forall i \in \{1, \dots, n\}, \quad \neg \text{isnan}(x_{i, k}) \wedge \neg \text{isinf}(x_{i, k}) \wedge |x_{i, k}| \le X_{\text{max}}
$$

  6. Dimension and Timestep Invariants:

$$
  \Delta t \gt 0 \quad \wedge \quad \dim(\mathbf{x}_k) = \dim(\mathbf{x}_0) = \dim(f) = n \quad \wedge \quad \dim(\mathbf{u}_k) = m
$$

  **Asymptotic Complexity Analysis**:
  Let $`n = \dim(\mathbf{x})`$ denote the continuous state dimension, $`m = \dim(\mathbf{u})`$ denote the input dimension, and $`K = \lfloor (t_{\text{final}} - t_0) / \Delta t \rfloor`$ denote the total simulation step count.
  1. *Single-Step Vector Recurrence Evaluation Phase*:
     - For a general non-linear vector field $`f(\mathbf{x}_k, \mathbf{u}_k, t_k)`$ with arithmetic evaluation complexity $`C_f`$:

$$
T_{\text{step\_ode}}(n) \in O(n + C_f), \quad S_{\text{step\_ode}}(n) \in O(n)
$$

     - For a dense linear state-space system ($`\mathbf{A} \in \mathbb{R}^{n \times n}`$, $`\mathbf{B} \in \mathbb{R}^{n \times m}`$), matrix-vector multiplication $`\mathbf{A}\mathbf{x}`$ requires $`n^2`$ multiplications and $`n(n-1)`$ additions, $`\mathbf{B}\mathbf{u}`$ requires $`n \cdot m`$ multiplications, and vector updates require $`2n`$ additions:

$$
T_{\text{step\_linear}}(n, m) \in O(n^2 + n \cdot m), \quad S_{\text{step\_linear}}(n) \in O(n)
$$

     - For a sparse linear system with $`nnz(\mathbf{A})`$ non-zero entries, the step complexity reduces to:

$$
T_{\text{step\_sparse}}(n, m) \in O(nnz(\mathbf{A}) + n \cdot m), \quad S_{\text{step\_sparse}}(n) \in O(n)
$$

  2. *Compile-Time Stability Analysis Phase*:
     - When system matrix $`\mathbf{A}`$ is statically provided, computing all $`n`$ eigenvalues via standard QR iteration requires $`O(n^3)`$ floating-point operations:

$$
T_{\text{stability}}(n) \in O(n^3), \quad S_{\text{stability}}(n) \in O(n^2)
$$

     - Validating the absolute stability condition $`|1 + \lambda_i \Delta t| \le 1`$ across all $`n`$ computed eigenvalues executes in $`O(n)`$ checks.
  3. *Multi-Step Trajectory Horizon Simulation Phase*:
     - Propagating state vector $`\mathbf{x}`$ across $`K`$ consecutive timesteps requires:

$$
T_{\text{trajectory}}(K, n, m) \in O(K \cdot (n^2 + n \cdot m))
$$

     - In-place simulation (updating state vector in place without trajectory history) executes in constant auxiliary space $`S_{\text{aux}} \in O(n)`$.
     - Full trajectory recording over $`K`$ steps consumes $`S_{\text{trajectory}} \in O(K \cdot n)`$ space. When streaming sink persistence (REQ-0177) is employed, resident memory overhead remains strictly bounded by $`O(1)`$ relative to total steps $`K`$.
  4. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning a batch of $`M_{\text{sim}}`$ independent trajectory simulations (such as parameter sweeps or Monte Carlo scenarios) across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool achieves near-linear speedup:

$$
T_{\text{batch}}(M_{\text{sim}}, K, n, N_{\text{max\_workers}}) \in O\left( \frac{M_{\text{sim}} \cdot K \cdot n}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$
