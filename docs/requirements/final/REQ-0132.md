### REQ-0132: Extraneous Node Detection & Dead Code Elimination in Safety Contexts

#### 1. Normative Statement

The safety compiler, dead code analyzer, and abstract syntax tree (AST) pruning engine of Subsystem 7 shall detect, isolate, report, and eliminate extraneous AST nodes and unreferenced behaviors that lack valid traceability paths to verified mission requirements or safe operational states across the 7-tier bipartite traceability directed acyclic graph (DAG) $`\mathcal{G}_{\text{trace}} = (\mathcal{V}_{\text{trace}}, \mathcal{E}_{\text{trace}})`$.

  Specifically, the safety compiler, reachability solver, and pruning engine shall strictly enforce the following structural, algebraic, and operational invariants:
  1. **Universal Root-to-Leaf Traceability Grounding**:
     - The compiler shall designate Tier 1 Mission Requirements ($`T_1 = \mathcal{R}_{\text{mission}} \subset \mathcal{V}_{\text{trace}}`$`) as the authoritative root requirement set `$`\mathcal{R}_{\text{root}}`$.
     - An AST node or traceability vertex $`v \in \mathcal{V}_{\text{trace}}`$` is classified as traceable and justified if and only if there exists a directed reachability path from at least one root requirement `$`r \in \mathcal{R}_{\text{root}}`$` to `$`v`$` in `$`\mathcal{G}_{\text{trace}}`$:

```math
\text{Reachable}(\mathcal{R}_{\text{root}}, v) \equiv \text{true}
```

     - Any vertex $`v \in \mathcal{V}_{\text{trace}}`$` lacking a forward directed path from `$`\mathcal{R}_{\text{root}}`$` (`$`\text{Reachable}(\mathcal{R}_{\text{root}}, v) \equiv \text{false}`$`) shall be classified as an extraneous node belonging to `$`\mathcal{V}_{\text{extraneous}} = \{ v \in \mathcal{V}_{\text{trace}} \mid \neg\text{Reachable}(\mathcal{R}_{\text{root}}, v) \}`$.
  2. **Unreferenced & Unreachable Behavioral Node Detection**:
     - Within behavioral AST models (hierarchical state machines, action step sequences, activity flows, and calculation expressions), the safety analyzer shall detect:
       a) Unreachable states: states in a hierarchical state machine that have no valid incoming transitions from the initial pseudostate or any reachable operational state;
       b) Dead transitions: transitions whose guards evaluate to false identically ($`\forall \mathbf{x} \in \mathcal{X}, g(\mathbf{x}) \equiv \text{false}`$), or whose source states belong to the unreachable state set;
       c) Unreferenced actions and methods: action definitions, action usages, or calculation definitions that are never invoked in any execution path originating from system lifecycle entry hooks or mission operational scenarios;
       d) Dead code in realization modules ($`T_6 = \mathcal{M}_{\text{code}}`$): basic blocks or instructions in intermediate representation or code ASTs that have no control-flow reachability from declared entry points.
  3. **Dual Operating Modes (Strict Safety Audit vs. Dead Code Elimination)**:
     - The compiler shall support two deterministic operational modes configurable via safety profile configuration:
       * *Strict Safety Audit Mode* (`strict_safety_audit = true`, mandated for high-integrity regulatory baselines including DO-178C DAL-A/B, ISO 26262 ASIL-D, and IEC 61508 SIL-3 per REQ-0144): The compiler shall treat any extraneous node or dead behavioral construct as an unverified unintended functionality violation, rejecting compilation at compile time with diagnostic error code `E0400` (`ExtraneousNodeDetected`, `UnreachableStateDetected`, `DeadTransitionDetected`, or `UnreferencedBehaviorDetected`).
       * *Dead Code Elimination (DCE) Mode* (`dce_pruning = true`): The compiler shall record structured diagnostic warnings for all detected extraneous nodes, cleanly prune them from the active AST graph, construct the pruned active graph $`\mathcal{G}_{\text{active}} = (\mathcal{V}_{\text{active}}, \mathcal{E}_{\text{active}})`$` where `$`\mathcal{V}_{\text{active}} = \mathcal{V}_{\text{trace}} \setminus \mathcal{V}_{\text{extraneous}}`$`, and restrict all downstream code generation, simulation models, and ICD exports to `$`\mathcal{G}_{\text{active}}`$, guaranteeing that zero unverified constructs are emitted.
  4. **Preservation of Safety-Critical Invariants**:
     - Elements linked to safety invariants ($`T_5 = \mathcal{I}_{\text{safety}}`$), run-time assurance mechanisms (RTA per REQ-0141), or control barrier functions (CBF per REQ-0143) must be strictly verified for root grounding.
     - If any declared safety invariant $`v \in T_5`$` lacks a valid reachability path from `$`\mathcal{R}_{\text{root}}`$, the compiler shall immediately emit diagnostic error code `E0400` (`UngroundedSafetyInvariant`). Under no circumstance shall dead code elimination silently prune an active safety barrier or mitigation mechanism without raising a compile-time diagnostic.
  5. **Deterministic Dead Code Manifest (`DeadCodeManifest`)**:
     - In both audit and DCE modes, the compiler shall synthesize an immutable, machine-readable manifest (`DeadCodeManifest`, persisting to `.pipeline/dead-code-manifest.json`) recording every detected extraneous element, including its deterministic RFC 4122 UUIDv5 anchor, fully qualified name, source file byte span, node kind, and dead code category (`UnallocatedClassifier`, `OrphanPort`, `UnreachableState`, `DeadTransition`, `UnreferencedAction`).
  6. **The 5 Executive Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every AST node, traceability vertex, extraneous element record, pruned edge, and dead code manifest entry shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(v))`$) in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel reachability traversals across independent packages, concurrent dead state evaluation in orthogonal statecharts, and parallel manifest serialization shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Node identifiers, fully qualified name segments, category labels, and diagnostic strings shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The safety compiler shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When extraneous node violations occur (`E0400`), diagnostics shall accumulate in the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{node}}`$`, `$`\bot_{\text{dce}}`$`), and continue validating subsequent declarations. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The extraneous node detection and dead code elimination pipeline shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($`\lt 25\text{ ms}`$` for `$`10^4`$` nodes and `$`5 \times 10^4`$` edges) and peak RSS memory (`$`\lt 100\text{ MB}`$) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Part_Alpha`, `Part_Dead_0`, `Port_1`, `Port_Dead_0`, `Invariant_0`, `Module_Realization_0`, `Witness_0`, `State_Init`, `State_Operational`, `State_Unreachable_0`, `Transition_Dead_0`, `Action_Step_0`, `Action_Unreferenced_0`, `Req_Mission_0`, `Req_Mission_1`, `Req_System_0`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage. Let `$`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.

  Let $`\mathcal{G}_{\text{trace}} = (\mathcal{V}_{\text{trace}}, \mathcal{E}_{\text{trace}})`$ denote the 7-tier bipartite traceability DAG:

```math
  \mathcal{V}_{\text{trace}} = \bigcup_{i=1}^7 T_i, \quad T_j \cap T_k = \emptyset \quad (\forall j \ne k)
```

  where:

```math
  \begin{aligned}
  T_1 &= \mathcal{R}_{\text{mission}} \quad (\text{Mission Requirements / Root Requirements } \mathcal{R}_{\text{root}}) \\
  T_2 &= \mathcal{R}_{\text{system}} \quad (\text{System Requirements}) \\
  T_3 &= \mathcal{C}_{\text{arch}} \quad (\text{Architectural Classifiers \& Parts}) \\
  T_4 &= \mathcal{P}_{\text{port}} \quad (\text{Ports \& Interfaces}) \\
  T_5 &= \mathcal{I}_{\text{safety}} \quad (\text{Safety Invariants}) \\
  T_6 &= \mathcal{M}_{\text{code}} \quad (\text{Realization Code \& LUMI IR Blocks}) \\
  T_7 &= \mathcal{W}_{\text{verify}} \quad (\text{Verification Witnesses})
  \end{aligned}
```

  Adjacent-tier directed edge relation:

```math
  \mathcal{E}_{\text{trace}} \subseteq \bigcup_{i=1}^6 (T_i \times T_{i+1})
```

  1. Directed Path and Reachability Formulation:
  A directed path $`\text{Path}_{\mathcal{G}_{\text{trace}}}(u, v)`$` from `$`u`$` to `$`v`$` is a sequence of vertices `$`\langle x_0, x_1, \dots, x_k \rangle`$` such that `$`x_0 = u`$`, `$`x_k = v`$`, `$`k \ge 0`$`, and `$`(x_{j-1}, x_j) \in \mathcal{E}_{\text{trace}}`$` for all `$`j \in \{1, \dots, k\}`$.
  Reachability from the root mission requirement set $`\mathcal{R}_{\text{root}} = T_1`$` to any vertex `$`v \in \mathcal{V}_{\text{trace}}`$ is formalized as:

```math
  \text{Reachable}(\mathcal{R}_{\text{root}}, v) \iff \exists r \in \mathcal{R}_{\text{root}} : \exists \text{Path}_{\mathcal{G}_{\text{trace}}}(r, v)
```

  2. Extraneous Node Set and Active Node Set Partitioning:

```math
  \begin{aligned}
  \mathcal{V}_{\text{extraneous}} &= \{ v \in \mathcal{V}_{\text{trace}} \mid \neg\text{Reachable}(\mathcal{R}_{\text{root}}, v) \} \\
  \mathcal{V}_{\text{active}} &= \{ v \in \mathcal{V}_{\text{trace}} \mid \text{Reachable}(\mathcal{R}_{\text{root}}, v) \equiv \text{true} \}
  \end{aligned}
```

  satisfying exact disjoint partition:

```math
  \mathcal{V}_{\text{trace}} = \mathcal{V}_{\text{active}} \uplus \mathcal{V}_{\text{extraneous}}, \quad \mathcal{V}_{\text{active}} \cap \mathcal{V}_{\text{extraneous}} = \emptyset
```

  3. Behavioral State Reachability & Dead Transition Invariants:
  For any hierarchical state machine $`M = \langle \mathcal{S}, s_0, \Sigma_{\text{event}}, \delta, \mathcal{S}_{\text{final}} \rangle`$` owned by an architectural classifier `$`c \in \mathcal{C}_{\text{arch}}`$`, the reachable state set `$`\mathcal{S}_{\text{reach}}`$ is inductively defined:

```math
  \begin{aligned}
  s_0 &\in \mathcal{S}_{\text{reach}} \\
  s \in \mathcal{S}_{\text{reach}} \land \exists e \in \Sigma_{\text{event}}, \exists g : \delta(s, e, g) = s' \land \text{Sat}(g) &\implies s' \in \mathcal{S}_{\text{reach}}
  \end{aligned}
```

  The dead state set is:

```math
  \mathcal{S}_{\text{dead}} = \mathcal{S} \setminus \mathcal{S}_{\text{reach}} = \{ s \in \mathcal{S} \mid s \notin \mathcal{S}_{\text{reach}} \}
```

  A transition $`t = \langle s_{\text{src}}, e, g, \alpha, s_{\text{tgt}} \rangle \in \delta`$` is dead if and only if its source state is dead or its guard condition `$`g`$ is unsatisfiable:

```math
  \text{Dead}(t) \iff (s_{\text{src}} \in \mathcal{S}_{\text{dead}}) \lor (\forall \mathbf{x} \in \mathcal{X}, \, g(\mathbf{x}) \equiv \text{false})
```

```math
  \delta_{\text{dead}} = \{ t \in \delta \mid \text{Dead}(t) \equiv \text{true} \}
```

  4. Unreferenced Action Step Invariant:
  For the set of declared action steps and behaviors $`\mathcal{A}_{\text{actions}}`$:

```math
  \mathcal{A}_{\text{reach}} = \{ a \in \mathcal{A}_{\text{actions}} \mid \exists r \in \mathcal{R}_{\text{root}} : r \rightsquigarrow_{\text{call}} a \}
```

```math
  \mathcal{A}_{\text{dead}} = \mathcal{A}_{\text{actions}} \setminus \mathcal{A}_{\text{reach}}
```

  5. Active Graph Induced Subgraph & DCE Emission Invariant:
  In dead code elimination mode, the active subgraph $`\mathcal{G}_{\text{active}} = (\mathcal{V}_{\text{active}}, \mathcal{E}_{\text{active}})`$ is defined by:

```math
  \mathcal{E}_{\text{active}} = \mathcal{E}_{\text{trace}} \cap (\mathcal{V}_{\text{active}} \times \mathcal{V}_{\text{active}}) = \{ (u, v) \in \mathcal{E}_{\text{trace}} \mid u \in \mathcal{V}_{\text{active}} \land v \in \mathcal{V}_{\text{active}} \}
```

  The set of emitted code, simulation, and interface artifacts $`\mathcal{V}_{\text{emit}}`$ satisfies:

```math
  \mathcal{V}_{\text{emit}} \subseteq \mathcal{V}_{\text{active}} \implies \mathcal{V}_{\text{emit}} \cap \mathcal{V}_{\text{extraneous}} = \emptyset
```

  6. Dead Code Manifest Record Formulation:
  The dead code manifest $`\mathcal{M}_{\text{dead}}`$ is formalized as:

```math
  \mathcal{M}_{\text{dead}} = \{ \langle \Delta_v, \text{FQN}(v), \kappa_{\text{dead}}(v), \text{span}_v \rangle \mid v \in \mathcal{V}_{\text{extraneous}} \cup \mathcal{S}_{\text{dead}} \cup \delta_{\text{dead}} \cup \mathcal{A}_{\text{dead}} \}
```

  where:

```math
  \begin{aligned}
  \Delta_v &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(v)) \in \Sigma^{36} \\
  \text{FQN}(v) &\in \mathcal{S}_{\text{intern}} \\
  \kappa_{\text{dead}}(v) &\in \{ \text{UnallocatedClassifier}, \text{OrphanPort}, \text{UnreachableState}, \text{DeadTransition}, \text{UnreferencedAction} \} \\
  \text{span}_v &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle
  \end{aligned}
```

  7. Deterministic Diagnostic Trigger Rules (REQ-0191):

```math
  \begin{aligned}
  \sigma_{\text{mode}} = \text{StrictSafety} \land \exists v \in \mathcal{V}_{\text{trace}} : \neg\text{Reachable}(\mathcal{R}_{\text{root}}, v) &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0400}, \text{ExtraneousNodeDetected}) \in \mathcal{D}_{\text{sink}} \\
  \sigma_{\text{mode}} = \text{StrictSafety} \land \exists s \in \mathcal{S} : s \in \mathcal{S}_{\text{dead}} &\implies \text{Diagnostic}(s, \text{DiagnosticCode::E0400}, \text{UnreachableStateDetected}) \in \mathcal{D}_{\text{sink}} \\
  \sigma_{\text{mode}} = \text{StrictSafety} \land \exists t \in \delta : \text{Dead}(t) &\implies \text{Diagnostic}(t, \text{DiagnosticCode::E0400}, \text{DeadTransitionDetected}) \in \mathcal{D}_{\text{sink}} \\
  \sigma_{\text{mode}} = \text{StrictSafety} \land \exists a \in \mathcal{A}_{\text{actions}} : a \in \mathcal{A}_{\text{dead}} &\implies \text{Diagnostic}(a, \text{DiagnosticCode::E0400}, \text{UnreferencedBehaviorDetected}) \in \mathcal{D}_{\text{sink}} \\
  \exists v \in T_5 : \neg\text{Reachable}(\mathcal{R}_{\text{root}}, v) &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0400}, \text{UngroundedSafetyInvariant}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  8. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
  \begin{aligned}
  \forall v \in \mathcal{V}_{\text{trace}}, &\quad \Delta_v = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(v)) \\
  \forall e = (u, v) \in \mathcal{E}_{\text{trace}}, &\quad \Delta_e = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{FQN}(v)) \\
  \forall m \in \mathcal{M}_{\text{dead}}, &\quad \Delta_m = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(m))
  \end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

Extraneous node detection, behavioral dead state exploration, and active graph pruning reside strictly in **Complexity Class P** (Deterministic Polynomial Time).

  **Mathematical Delineation from Algorithmic Bounds NP-4, NP-5, and NP-8**:
  In safety analysis and formal verification, certain combinatorial reasoning problems incur exponential or PSPACE bounds:
  - Under Algorithmic Bound NP-4 (REQ-0135), computing minimal hazard cut-sets and minimal hitting sets of safety constraints is NP-complete, requiring greedy logarithmic approximations ($`|C_{\text{greedy}}| \le (1 + \ln |H|) \cdot |C^*|`$) or bounded Min-Unsat solvers.
  - Under Algorithmic Bound NP-5 (REQ-0124), reachability analysis in arbitrary orthogonal concurrent statecharts is PSPACE-complete, requiring Bounded Model Checking (BMC) with a maximum unrolling depth $`k \le k_{\text{max}}`$.
  - Under Algorithmic Bound NP-8 (REQ-0197), invariant contract satisfiability over general arithmetic theories is NP-complete (QF_LRA / QF_LIA) or undecidable.
  In sharp contrast, REQ-0132 does not solve an optimization problem, concurrent interleaved product state exploration, or arithmetic SMT satisfiability. REQ-0132 performs forward graph reachability over the finite 7-tier bipartite traceability DAG $`\mathcal{G}_{\text{trace}}`$` and local behavioral control-flow graphs. Breadth-first search (BFS) or depth-first search (DFS) over a directed graph executes in deterministic linear time `$`O(V + E)`$ without combinatorial search or backtracking.

  **Asymptotic Complexity Analysis**:
  Let $`V = |\mathcal{V}_{\text{trace}}|`$` denote the total number of traceability nodes across all 7 tiers, and let `$`E = |\mathcal{E}_{\text{trace}}|`$` denote the total number of traceability edges. Let `$`S_{\text{total}} = \sum_{M} |\mathcal{S}_M|`$` and `$`\delta_{\text{total}} = \sum_{M} |\delta_M|`$` denote the total states and transitions across all behavioral state machines. Let `$`A = |\mathcal{A}_{\text{actions}}|`$ denote the total number of action invocations.
  1. *Root-to-Leaf Traceability Reachability Traversal (BFS / DFS)*:
     The compiler initializes a boolean visited bitset of size $`V`$` to false and enqueues all root mission requirements `$`r \in \mathcal{R}_{\text{root}} = T_1`$. A standard FIFO queue visits each reachable node and examines each outgoing edge at most once:

```math
     T_{\text{reach}}(V, E) \in O(V + E)
```

  2. *Extraneous Node Identification & Partitioning*:
     Scanning the visited bitset of size $`V`$` partitions nodes into `$`\mathcal{V}_{\text{active}}`$` and `$`\mathcal{V}_{\text{extraneous}}`$:

```math
     T_{\text{partition}}(V) \in O(V)
```

  3. *Behavioral Statechart Reachability & Dead Transition Detection*:
     For each state machine, reachability from initial pseudostate $`s_0`$ traverses states and transitions once:

```math
     T_{\text{state}}(S_{\text{total}}, \delta_{\text{total}}) \in O(S_{\text{total}} + \delta_{\text{total}})
```

  4. *Behavioral Action Reachability*:
     Traversing the call graph of action invocations from system entry points visits each action step once:

```math
     T_{\text{action}}(A) \in O(A)
```

  5. *Active Graph Induced Subgraph Construction & Pruning*:
     Filtering edges $`\mathcal{E}_{\text{trace}}`$` to retain only those where both endpoints belong to `$`\mathcal{V}_{\text{active}}`$ takes:

```math
     T_{\text{prune}}(E) \in O(E)
```

  6. *Dead Code Manifest Serialization*:
     Constructing and serializing entries for all $`K = |\mathcal{V}_{\text{extraneous}}| + |\mathcal{S}_{\text{dead}}| + |\delta_{\text{dead}}| + |\mathcal{A}_{\text{dead}}|`$ detected elements executes in:

```math
     T_{\text{manifest}}(K) \in O(K) \subseteq O(V + S_{\text{total}} + \delta_{\text{total}} + A)
```

  7. *Aggregate Worst-Case Time Complexity*:
     Summing all phases:

```math
     T_{\text{total}} \in O(V + E + S_{\text{total}} + \delta_{\text{total}} + A)
```

     The algorithm is strictly linear in the total size of the traceability graph and behavioral models, operating deterministically without backtracking or unbounded recursion.
  8. *Parallel Work-Stealing Scaling (Directive 2)*:
     When verifying $`P`$` independent packages or decoupled subsystem models across `$`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool:

```math
     T_{\text{parallel}} \in O\left( \frac{V + E + S_{\text{total}} + \delta_{\text{total}} + A}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  9. *Space Complexity & Arena Memory Bounds*:
     Traceability nodes, edges, active subgraphs, and manifest entries reside in contiguous bump arena storage, consuming $`O(V + E)`$` bytes. Visited bitsets and FIFO queues require `$`O(V + S_{\text{total}})`$` bits. The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ capacity.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Part_Alpha`, `Part_Dead_0`, `Port_1`, `Port_Dead_0`, `Invariant_0`, `Module_Realization_0`, `Witness_0`, `State_Init`, `State_Operational`, `State_Unreachable_0`, `Transition_Dead_0`, `Action_Step_0`, `Action_Unreferenced_0`, `Req_Mission_0`, `Req_Mission_1`, `Req_System_0`, `Flow_A`, `param_x : Real`) across the following 17 verification gates:

  1. **Canonical Fully Grounded Traceability Gate**: Ingest synthetic model `Package_0` declaring a complete grounded traceability thread: mission requirement `Req_Mission_0` ($`T_1`$), system requirement `Req_System_0` ($`T_2`$), architectural classifier `Classifier_Alpha` ($`T_3`$), directed port `Port_1` ($`T_4`$), safety invariant `Invariant_0` ($`T_5`$), realization module `Module_Realization_0` ($`T_6`$), and verification witness `Witness_0` ($`T_7`$`). Verify that all nodes are evaluated as reachable from `$`\mathcal{R}_{\text{root}}`$`, the extraneous node set is empty (`$`\mathcal{V}_{\text{extraneous}} = \emptyset`$), and zero diagnostics are emitted.
  2. **Extraneous Classifier Detection Gate (`E0400`)**: Ingest `Package_0` with `Req_Mission_0` and two architectural classifiers: `Classifier_Alpha` (realizing `Req_System_0` refined from `Req_Mission_0`) and `Classifier_Beta` (completely unlinked to any requirement). In strict safety mode, assert that `Classifier_Beta` is detected as extraneous and rejected at compile time with diagnostic error code `E0400` (`ExtraneousNodeDetected`), citing its fully qualified name `Package_0::Classifier_Beta` and source code byte span.
  3. **Extraneous Sub-Part Detection Gate (`E0400`)**: Declare architectural classifier `Classifier_Alpha` containing child part `Part_Dead_0` that lacks any allocation, connection, or requirement trace. In strict safety mode, assert deterministic compile-time rejection with diagnostic error code `E0400` (`ExtraneousNodeDetected`), identifying `Part_Dead_0`.
  4. **Extraneous Port and Interface Detection Gate (`E0400`)**: Declare directed port `Port_Dead_0` on `Classifier_Alpha` that participates in zero connection usages, zero flow allocations, and zero requirement specifications. In strict safety mode, assert deterministic compile-time rejection with diagnostic error code `E0400` (`ExtraneousNodeDetected`).
  5. **Unreachable Statechart State Detection Gate (`E0400`)**: Ingest state machine `StateMachine_Alpha` containing initial state `State_Init`, active state `State_Operational`, and isolated state `State_Unreachable_0` having zero incoming transitions from `State_Init`. Assert deterministic detection of `State_Unreachable_0` as an unreachable state, triggering diagnostic error code `E0400` (`UnreachableStateDetected`) in strict safety mode.
  6. **Dead Transition Detection Gate (`E0400`)**: Ingest a statechart transition `Transition_Dead_0` originating from `State_Operational` with guard expression identically equal to false (`param_x > 0 && param_x < 0`). Assert deterministic compile-time rejection with diagnostic error code `E0400` (`DeadTransitionDetected`).
  7. **Unreferenced Action Step Detection Gate (`E0400`)**: Declare action definition `Action_Unreferenced_0` in `Package_0` that is never invoked in any activity sequence, transition effect, or operational scenario. In strict safety mode, assert deterministic compile-time rejection with diagnostic error code `E0400` (`UnreferencedBehaviorDetected`).
  8. **Strict Safety Audit Mode Gate (`E0400`)**: Configure the compiler with `strict_safety_audit = true`. Ingest a model containing 1 extraneous architectural classifier. Assert that compilation halts with a non-zero exit code and diagnostic `E0400` (`ExtraneousNodeDetected`), prohibiting code generation.
  9. **Dead Code Elimination (DCE) Pruning Gate**: Configure the compiler with `dce_pruning = true`. Ingest a model containing 2 valid grounded classifiers and 1 extraneous classifier. Verify that the compiler successfully completes compilation, prunes the extraneous classifier from the active AST, and produces downstream code generation containing strictly the 2 valid classifiers with zero unverified constructs.
  10. **Active Graph Induced Subgraph Consistency Gate**: Following DCE pruning on a model with extraneous nodes, verify that $`\mathcal{G}_{\text{active}} = (\mathcal{V}_{\text{active}}, \mathcal{E}_{\text{active}})`$` contains zero dangling edges (`$`\forall (u, v) \in \mathcal{E}_{\text{active}}, u \in \mathcal{V}_{\text{active}} \land v \in \mathcal{V}_{\text{active}}`$) and zero references to pruned handles.
