### REQ-0162: Epics Projection: System Architecture Diagrams & Streaming Artifact Sink Interface

- **Normative Statement**: The downstream projection engine, architecture diagram synthesizer, and streaming artifact emission framework of Subsystem 9 shall synthesize system-level UML class and component architecture diagrams within Epic specifications, illustrating structural containment, subsystem boundaries, and interconnected interfaces, while emitting all generated projection artifacts directly through an abstract streaming artifact sink interface that guarantees strict $O(1)$ streaming memory overhead relative to total emitted documentation size. The projection engine shall traverse the Single Source of Truth (SSOT) AST model, extract structural containment trees and topological interconnect multigraphs scoped to each Epic partition, format these relationships into deterministic architecture diagrams (including Mermaid class and component diagrams), and stream the resulting specification artifacts directly to downstream writer sinks without buffering unbounded document collections in resident memory. If diagram extraction encounters unresolved endpoints, dangling references, phantom edges lacking AST backing, or if streaming sink write operations fail, the compiler shall fail closed and emit diagnostic error code `E0500`.

  Specifically, the downstream projection engine, diagram synthesizer, and streaming artifact emission framework shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Epic Scoping & System Architecture Decomposition**:
     - The compiler shall partition the system architectural model into high-level Epic specifications in accordance with REQ-0161, mapping top-level packages, subsystem assemblies, and capability definitions into coherent documentation scopes.
     - For each Epic specification, the projection engine shall extract the scoped structural subgraph containing all package definitions (`package`, REQ-0070), part definitions and usages (`part def`, `part`, REQ-0021, REQ-0071), port definitions and directed usages (`port def`, `port`, REQ-0022, REQ-0072), item definitions and item usages (`item def`, `item`, REQ-0073), connection definitions and connection usages (`connection def`, `connection`, REQ-0025, REQ-0074), and interface definitions and usages (`interface def`, `interface`, REQ-0075) declared within or allocated to the Epic.
     - The engine shall preserve structural containment hierarchies (packages containing subsystems, subsystems containing component parts, parts containing child parts and boundary ports), establishing clear visual and syntactic containment boundaries.
  2. **Dual System Architecture Diagram Synthesis**:
     - The projection engine shall synthesize two complementary architecture diagram representations within each Epic specification:
       - *UML Class Architecture Diagrams*: Depicting structural classifier hierarchies, subtyping and specialization relationships (`:>`, REQ-0061), feature redefinition relationships (`:>>`, REQ-0062), and composite association topologies among structural classifiers within the Epic scope.
       - *Component Architecture Diagrams / Block Definition Diagrams*: Depicting structural instance topologies, nested subsystem containment boundaries, directed boundary ports (`in`, `out`, `inout`, REQ-0038, REQ-0072), and interconnected interface flows (REQ-0076, REQ-0148).
     - Diagram syntax shall be emitted in standard declarative formats, primarily GitHub-Flavored Markdown embedded Mermaid blocks (`classDiagram`, `flowchart TD`, `flowchart LR`, `graph TD`, `graph LR`), with deterministic node identifier sanitization per REQ-0019 to prevent syntax errors.
  3. **Surjective & Sound Diagram Projection (Zero Phantom Edges)**:
     - The diagram synthesizer shall enforce strict soundness: every visual diagram edge $(u, v)$ rendered in an architecture diagram must correspond to an actual connection or structural containment relation in the underlying AST:

       $$
       \forall (u, v) \in E_{\text{diagram}}, \quad \exists c \in \text{Connections}(\text{AST}) \cup \text{Containments}(\text{AST}) \quad \text{such that } \text{endpoints}(c) = \{u, v\}
       $$

     - The synthesizer shall enforce completeness: all valid connections and direct containment relations between nodes within the Epic scope must be rendered without omission.
     - Under no circumstances shall the projection engine fabricate or infer phantom edges that do not exist in the AST model.
     - If an edge references an unresolved node handle, a dangling endpoint, or a connection lacking an AST entity, the compiler shall halt projection and emit diagnostic error code `E0500` (`PhantomDiagramEdgeViolation` or `UnresolvedDiagramEndpoint`).
  4. **Abstract Streaming Artifact Sink Interface**:
     - Emission of all Epic projection documents (incorporating YAML frontmatter, Markdown prose, requirement allocation tables, traceability matrices, and embedded architecture diagrams) shall execute strictly through an abstract `StreamingArtifactSink` interface.
     - The streaming sink interface shall accept incremental string slices and byte buffers via a chunk emission function:

       $$
       \text{WriteChunk}(\Sigma_{\text{sink}}, \beta) \implies M_{\text{buffer}}(\Sigma_{\text{sink}}) \le B_{\text{max\_chunk\_size}}
       $$

       where $B_{\text{max\_chunk\_size}}$ is a fixed compile-time buffer threshold (default 64 KB, i.e., $65{,}536$ bytes).
     - The streaming sink interface guarantees strict constant memory overhead upper bounds:

       $$
       M_{\text{streaming\_sink}} \le O(1) \quad \text{relative to emitted artifact size } |A|
       $$

     - Specification documents shall be streamed incrementally to downstream writer sinks (such as filesystem file descriptors, ring buffers, stdout streams, or cryptographic content fingerprinters per REQ-0178) without accumulating or buffering unbounded multi-megabyte document strings in resident memory.
     - If a sink write operation fails (such as an I/O device error or memory-mapped buffer write fault), the compiler shall fail closed and emit diagnostic error code `E0500` (`SinkWriteError`).
  5. **Deterministic Qualified-Name Sorting & Zero Diff Churn (REQ-0003, REQ-0032)**:
     - All diagram vertices (classes, components, ports) and edges (containment links, associations, connectors) shall be ordered deterministically based on canonical lexicographical ASCII byte ordering of fully qualified symbol names ($\prec_{\text{lex}}$, REQ-0032) or deterministic topological dependency DAG order (REQ-0048).
     - Deterministic serialization guarantees bitwise reproducibility and 0-byte diff churn across repeated compiler invocations when source inputs remain unchanged.
  6. **Contiguous Memory Bump Arena Storage & Node Handles (REQ-0009, REQ-0034, REQ-0035)**:
     - All intermediate projection models, diagram descriptors, vertex rosters, edge collections, and sink configuration structures shall be allocated sequentially into contiguous typed bump arena storage, referenced by stable 32-bit arena node handles.
  7. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized Epic document, architecture diagram instance, component block, interface connector, and generated projection artifact shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the node fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel projection of multiple Epic specifications and concurrent diagram synthesis across independent subsystems or compilation units shall execute strictly on a centralized, bounded work-stealing thread pool with worker upper bound $N_{\text{max\_workers}}$ in accordance with REQ-0012. Unbounded dynamic thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Epic identifiers, subsystem names, component symbols, port names, interface labels, and diagram node aliases shall be interned into the deduplicated global symbol interner pool during lexical analysis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The projection engine and streaming sink shall implement synchronization token error recovery on markdown structural section headers (`#`, `##`), statement delimiters (`;`), and table row delimiters (`|`) in accordance with REQ-0013 and REQ-0016. When diagram generation or sink write errors occur (`E0500`), the engine shall record structured diagnostics into the preallocated error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels ($\bot_{\text{projection}}$), and continue projecting subsequent sections and Epics. If accumulated diagnostics reach capacity limit $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The downstream projection engine and streaming artifact sink shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Projection latency (strictly under 25 ms for $|V| + |E| = 10^4$ graph elements) and peak RSS memory (strictly under 100 MB) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  8. **Pure Abstract MBSE Placeholder Mandate**:
     - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Subsystem_0`, `Subsystem_1`, `Part_0`, `Part_1`, `Port_Src`, `Port_Tgt`, `Channel_0`, `Channel_1`, `Flow_A`, `Flow_B`, `Connection_0`, `Epic_0`, `Epic_1`, `Sink_0`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes in contiguous bump arena storage, and let $\mathcal{S}_{\text{intern}}$ denote the deduplicated global symbol interner pool.

  An Epic specification projection is formalized as a 7-tuple:

  $$
  \mathcal{P}_{\text{epic}} = \langle \text{id}_{\text{epic}}, \text{scope}, \mathcal{D}_{\text{class}}, \mathcal{D}_{\text{comp}}, \Sigma_{\text{sink}}, \Delta_{\text{epic}}, \text{span}_{\text{epic}} \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_{\text{epic}} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{scope} &\subseteq \mathcal{V}_{\text{AST}} \quad (\text{subsystem or package classifier AST scope}) \\
  \mathcal{D}_{\text{class}} &= \langle V_{\text{class}}, E_{\text{class}} \rangle \quad (\text{projected UML class architecture diagram}) \\
  \mathcal{D}_{\text{comp}} &= \langle V_{\text{comp}}, E_{\text{comp}} \rangle \quad (\text{projected component architecture diagram}) \\
  \Sigma_{\text{sink}} &= \langle B_{\text{max\_chunk\_size}}, \mu_{\text{write}}, M_{\text{buffer}} \rangle \quad (\text{streaming artifact sink descriptor}) \\
  \Delta_{\text{epic}} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_{\text{epic}} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance span})
  \end{aligned}
  $$

  1. Diagram Soundness & Zero Phantom Edge Invariant:
  For every diagram edge $(u, v)$ rendered in the projected architecture:

  $$
  \forall (u, v) \in E_{\text{class}} \cup E_{\text{comp}}, \quad \exists c \in \text{Connections}(\text{AST}) \cup \text{Containments}(\text{AST}) \quad \text{such that } \text{endpoints}(c) = \{u, v\}
  $$

  and every vertex rendered in the diagram maps bijectively to a valid AST node handle within the Epic scope:

  $$
  \forall u \in V_{\text{class}} \cup V_{\text{comp}}, \quad \exists n \in \mathcal{V}_{\text{AST}} \cap \text{scope} \quad \text{such that } \text{handle}(u) = n
  $$

  2. Structural Containment & Connection Relation Decomposition:
  Structural containment edges represent parent-child ownership hierarchies:

  $$
  \text{Containments}(\text{AST}) = \{ (p, c) \in \mathcal{V}_{\text{AST}} \times \mathcal{V}_{\text{AST}} \mid c \in \text{Children}(p) \}
  $$

  Topological connection edges represent declared interface bindings and connectors:

  $$
  \text{Connections}(\text{AST}) = \{ (s, t) \in \mathcal{V}_{\text{AST}} \times \mathcal{V}_{\text{AST}} \mid \exists \text{conn} \in \mathcal{C}, \, \text{source}(\text{conn}) = s \wedge \text{target}(\text{conn}) = t \}
  $$

  3. Streaming Artifact Sink Memory Overhead Invariant:
  For an emitted specification artifact $A$ of total byte length $|A| \in \mathbb{N}_0$, resident streaming buffer memory is strictly upper-bounded by a constant threshold:

  $$
  M_{\text{streaming\_sink}} \le O(1) \quad \text{relative to emitted artifact size } |A|
  $$

  Specifically, for any chunk emission operation $\text{WriteChunk}(\Sigma_{\text{sink}}, \beta)$:

  $$
  \forall \beta \subseteq A, \quad |\beta| \le B_{\text{max\_chunk\_size}} \implies M_{\text{buffer}}(\Sigma_{\text{sink}}) \le B_{\text{max\_chunk\_size}}
  $$

  where $B_{\text{max\_chunk\_size}} = 65{,}536 \text{ bytes}$ ($64\text{ KB}$), ensuring resident memory overhead is decoupled from the total emitted document size:

  $$
  \lim_{|A| \to \infty} \frac{M_{\text{buffer}}(\Sigma_{\text{sink}})}{|A|} = 0
  $$

  4. Deterministic Canonical Ordering & Zero Diff Churn Invariant:
  Let $\prec_{\text{canon}}$ denote the canonical total ordering defined over AST handles by lexicographical ASCII comparison of fully qualified names in $\mathcal{S}_{\text{intern}}$:

  $$
  u \prec_{\text{canon}} v \iff \text{FQN}(u) \prec_{\text{lex}} \text{FQN}(v)
  $$

  Every diagram serialization sequence $\mathbf{S}_V = \langle u_1, u_2, \dots, u_m \rangle$ and $\mathbf{S}_E = \langle e_1, e_2, \dots, e_k \rangle$ satisfies strict monotonic ordering:

  $$
  \begin{aligned}
  1 \le i \lt j \le m &\implies u_i \prec_{\text{canon}} u_j \\
  1 \le i \lt j \le k &\implies \text{Key}(e_i) \prec_{\text{canon}} \text{Key}(e_j)
  \end{aligned}
  $$

  guaranteeing 0-byte diff churn across idempotent compilation runs:

  $$
  \text{Emit}(\mathcal{P}_{\text{epic}}^{(1)}) = \text{Emit}(\mathcal{P}_{\text{epic}}^{(2)})
  $$

  5. Diagnostic Trigger Rules (REQ-0191):

  $$
  \begin{aligned}
  \exists (u, v) \in E_{\text{diagram}} : \neg\exists c \in \text{AST}_{\text{edges}} \text{ with } \text{endpoints}(c) = \{u, v\} &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0500}, \text{PhantomDiagramEdgeViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists u \in V_{\text{diagram}} : \text{handle}(u) \notin \mathcal{V}_{\text{AST}} &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0500}, \text{UnresolvedDiagramEndpoint}) \in \mathcal{D}_{\text{sink}} \\
  \text{WriteFailure}(\Sigma_{\text{sink}}) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0500}, \text{SinkWriteError}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

  6. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

  $$
  \begin{aligned}
  \Delta_{\text{epic}} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\text{epic})) \\
  \Delta_{\text{diagram}}(\mathcal{D}) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\text{epic}) \mathbin{\Vert} \text{"::Diagram::"} \mathbin{\Vert} \text{Kind}(\mathcal{D})) \\
  \Delta_{\text{artifact}} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\text{epic}) \mathbin{\Vert} \text{"::Artifact::Markdown"})
  \end{aligned}
  $$

- **Computational Complexity & Algorithmic Bounds**: System architecture diagram synthesis and streaming artifact emission reside strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in deterministic linear time $O(|V| + |E| + |A|)$ and strict constant auxiliary streaming memory $O(1)$ relative to emitted documentation byte length $|A|$, where $|V|$ denotes the number of structural nodes (packages, subsystems, parts, ports), $|E|$ denotes the number of structural containment and interconnection edges within the Epic scope, and $|A|$ denotes the total emitted artifact size in bytes.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 addresses qualitative temporal interval consistency over occurrence lifecycles using Allen's 13 qualitative interval relations, requiring ORD-Horn difference logic SMT solving in $O(N^3)$ polynomial time. In contrast, REQ-0162 performs spatial and structural architecture diagram projection without temporal interval reasoning, executing in linear $O(|V| + |E|)$ graph extraction time.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses structural allocation, interconnect clustering, and logical channel multiplexing via strongly NP-hard vector bin packing. In contrast, REQ-0162 operates downstream of allocation on already-bound interconnect topologies, visualizing existing structural relations without bin packing or partitioning search.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 resolves subtyping lattices and multiple inheritance hierarchies via monotonic C3 linearization in $O(V + E)$ time. In contrast, REQ-0162 renders class inheritance and component containment edges directly from pre-linearized AST relations without resolving posets or type semilattices.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0162 synthesizes structural architecture views, traversing AST containment trees without combinatorial cut-set optimization.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 addresses orthogonal discrete state machine reachability, deadlock, and livelock (PSPACE-complete / NP-complete under bounded model checking). In contrast, REQ-0162 emits static class and component architecture diagrams; behavioral state machine projections are handled downstream in REQ-0163.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks via linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0162 streams diagram syntax without solving continuous linear or complementary flow network equations.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs register allocation and basic block scheduling in LUMI IR using Chaitin graph coloring (NP-complete). In contrast, REQ-0162 operates on high-level MBSE specifications and markdown documentation sinks, prior to backend compiler intermediate representations.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the satisfiability of first-order invariant contracts via DPLL(T) SMT solvers. In contrast, REQ-0162 executes closed-form deterministic string formatting and chunk streaming without invoking SMT solvers.

  **Algorithmic Breakdown & Asymptotic Bounds**:
  1. *AST Scoping & Graph Extraction Phase*:
     - The projection engine performs a breadth-first search (BFS) or depth-first search (DFS) over the AST starting from the Epic root package handle.
     - Each structural vertex $u \in V$ and edge $e \in E$ within the Epic scope is visited exactly once:

       $$
       T_{\text{extract}}(|V|, |E|) \in O(|V| + |E|)
       $$

     - Visited node handles are tracked using a compact bitset in contiguous bump arena storage, requiring $O(|V|)$ bits of auxiliary space.
  2. *Canonical Sorting Phase (REQ-0032)*:
     - Nodes and edges are sorted into canonical order using interned symbol identifier comparisons:

       $$
       T_{\text{sort}}(|V|, |E|) \in O(|V| \log |V| + |E| \log |E|)
       $$

     - Because symbol strings are deduplicated and interned into $\mathcal{S}_{\text{intern}}$ per REQ-0036, identifier comparison is performed in $O(1)$ scalar time per element pair, avoiding string scanning overhead.
  3. *Diagram Formatting & Chunk Streaming Phase*:
     - The engine serializes Mermaid diagram lines and Markdown prose into a preallocated chunk buffer of size $B_{\text{max\_chunk\_size}} = 64\text{ KB}$.
     - When the chunk buffer fills, `WriteChunk` flushes bytes directly to the underlying streaming sink in $O(1)$ amortized time per chunk flush:

       $$
       T_{\text{stream}}(|A|) \in O(|A|)
       $$

     - Total execution time across all phases is strictly linear:

       $$
       T_{\text{total}}(|V|, |E|, |A|) \in O(|V| \log |V| + |E| \log |E| + |A|) \subseteq O(|V| + |E| + |A|)
       $$

  4. *Space Complexity & Streaming Memory Bound*:
     - The streaming artifact sink interface buffers at most $B_{\text{max\_chunk\_size}}$ bytes in resident RAM at any instant:

       $$
       M_{\text{buffer}} \le B_{\text{max\_chunk\_size}} = 64\text{ KB} \in O(1)
       $$

     - Total resident heap overhead remains strictly $O(1)$ regardless of whether the emitted documentation artifact size $|A|$ is $10\text{ KB}$, $10\text{ MB}$, or $10\text{ GB}$.
     - Intermediate graph traversal structures reside in preallocated bump arena storage, requiring strictly $O(|V| + |E|)$ arena memory with zero dynamic heap allocations.
  5. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Independent Epic projections across distinct subsystems are partitioned across worker threads on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$:

       $$
       T_{\text{parallel}}(|V|, |E|, |A|, N_{\text{max\_workers}}) \in O\left( \frac{|V| + |E| + |A|}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
       $$

     - Thread isolation ensures zero lock contention, data-race freedom, and deterministic bitwise identical outputs across threads.
