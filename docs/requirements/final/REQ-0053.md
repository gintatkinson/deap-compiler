### REQ-0053: Tombstone Pruning Engine for Renamed & Orphaned AST Nodes

- **Normative Statement**: The compiler core metamodel, abstract syntax tree (AST) graph engine, and persistence subsystem shall maintain a centralized, content-addressed manifest of all generated artifacts (`CodegenManifest`) and execute automated tombstone pruning (`prune_tombstones`) during each compilation cycle to detect, unregister, and cleanly unlink all obsolete and orphaned output files resulting from the deletion, renaming, or structural relocation of model entities (including packages, classifiers, part definitions, port definitions, item definitions, action definitions, constraint definitions, and downstream specification projections). When any model element is deleted or renamed between successive compilation passes, the persistence engine shall compute the exact set difference between the set of previously manifested artifact paths $\mathcal{A}_{\text{manifest}}$ and the set of actively generated artifact paths $\mathcal{A}_{\text{active}}$, deriving the exact tombstone pruning set $\mathcal{T}_{\text{prune}} = \mathcal{A}_{\text{manifest}} \setminus \mathcal{A}_{\text{active}}$.

  For every path $f \in \mathcal{T}_{\text{prune}}$, the engine shall enforce strict filesystem path confinement invariants: the target path must resolve strictly within the configured workspace output root directory $\mathcal{W}_{\text{out}}$, must contain zero directory traversal prefixes (`..`), must not traverse symlinks leading outside $\mathcal{W}_{\text{out}}$, and must not collide with protected compiler source files or configuration manifests. If an unconfined or illegal target path is detected, the engine shall record structured diagnostic record `E0200` per REQ-0191 and bypass unlinking of that path without panicking.

  Upon validating path confinement, the pruning engine shall atomically unlink each orphaned file from the filesystem. If an orphaned file has already been removed externally, the unlinking operation must proceed idempotently as a successful no-op. If filesystem permission faults (`EACCES`, `EPERM`) or I/O locks (`EBUSY`) prevent unlinking, the engine shall record structured diagnostic record `E0200` per REQ-0191 into the diagnostic sink and continue pruning subsequent tombstones in accordance with Architectural Directive 4, REQ-0013, and REQ-0016. If accumulated errors reach the error sink limit $C_{\text{max\_errors}}$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.

  Following the removal of each file $f \in \mathcal{T}_{\text{prune}}$, the engine shall recursively evaluate and delete empty parent directories ($\text{CleanEmptyParentDirs}(\text{Parent}(f))$), ascending the directory hierarchy and removing ancestor directories that contain zero remaining files and zero subdirectories, terminating recursion strictly upon reaching a non-empty directory or the generation output root boundary $\mathcal{W}_{\text{out}}$.

  Upon completion of tombstone pruning, the persistence engine shall atomically synchronize and write the updated manifest $\mathcal{A}_{\text{manifest}}^{\text{updated}} = \mathcal{A}_{\text{active}}$ to disk using atomic temporary file renaming in accordance with REQ-0189, ensuring that the workspace working tree contains zero residual orphan files and that the on-disk manifest strictly matches active compilation output. Every recorded artifact entry in `CodegenManifest` shall bind the normalized relative path to the originating AST node's deterministic RFC 4122 UUIDv5 identifier ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))$) per Architectural Directive 1 and REQ-0010, its 64-bit content hash, and its byte length. Multi-threaded tombstone pruning across independent output directory trees shall be scheduled on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with Architectural Directive 2 and REQ-0012. Scalar path tokens and namespace segment identifiers shall be interned into the global symbol interner pool in accordance with Architectural Directive 3 and REQ-0036. The tombstone pruning engine must enforce Architectural Directive 5, guaranteeing a total, deterministic, non-panicking execution contract across all inputs; execution latency (< 25 ms) and peak memory RSS (< 100 MB for $10^5$ tracked artifact paths) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196. All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Part_0`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $\mathcal{W}_{\text{out}}$ denote the canonical workspace output root directory path. Let $\mathcal{P}_{\text{rel}}$ denote the universe of canonical normalized relative filesystem paths:

$$
\mathcal{P}_{\text{rel}} = \{ p \in \Sigma^* \mid \neg\text{HasTraversalPrefix}(p) \;\wedge\; \text{NormalizePath}(p) = p \}
$$

The absolute filesystem path resolution function $\text{Resolve}(\mathcal{W}_{\text{out}}, p)$ satisfies strict workspace output confinement:

$$
\forall p \in \mathcal{P}_{\text{rel}}, \quad \text{IsDescendant}(\text{Resolve}(\mathcal{W}_{\text{out}}, p), \mathcal{W}_{\text{out}}) \equiv \text{true}
$$

Let $\mathcal{M}$ denote the centralized persistence manifest (`CodegenManifest`):

$$
\mathcal{M} = \{ \langle p, u, h_{\text{xxh3}}, s_{\text{bytes}}, t_{\text{epoch}} \rangle \mid p \in \mathcal{P}_{\text{rel}}, \, u \in \mathcal{U}_{\text{UUIDv5}}, \, h_{\text{xxh3}} \in \{0, 1\}^{64}, \, s_{\text{bytes}} \in \mathbb{N}_0, \, t_{\text{epoch}} \in \mathbb{N}_0 \}
$$

where:
- $p \in \mathcal{P}_{\text{rel}}$ is the normalized relative target file path,
- $u = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(v))$ is the deterministic RFC 4122 UUIDv5 identifier of the originating AST node $v \in \mathcal{V}_{\text{AST}}$,
- $h_{\text{xxh3}} = \text{XXH3}_{64}(B)$ is the 64-bit content hash of the generated artifact byte buffer $B$,
- $s_{\text{bytes}} = |B|$ is the artifact byte length,
- $t_{\text{epoch}}$ is the compilation cycle monotonic timestamp.

The path projection operator $\pi_{\text{path}}(\mathcal{M})$ extracts the set of relative paths registered in manifest $\mathcal{M}$:

$$
\pi_{\text{path}}(\mathcal{M}) = \{ p \in \mathcal{P}_{\text{rel}} \mid \exists \langle p, u, h, s, t \rangle \in \mathcal{M} \}
$$

Let $\mathcal{A}_{\text{manifest}} = \pi_{\text{path}}(\mathcal{M}_{\text{prev}})$ denote the set of artifact paths recorded in the manifest from the preceding compilation pass, and let $\mathcal{A}_{\text{active}} \subset \mathcal{P}_{\text{rel}}$ denote the set of active artifact paths generated in the current compilation pass.

Tombstone Set Identification Invariant: The set of orphaned artifact paths to prune $\mathcal{T}_{\text{prune}}$ satisfies exact set difference:

$$
\mathcal{T}_{\text{prune}} = \mathcal{A}_{\text{manifest}} \setminus \mathcal{A}_{\text{active}} = \{ p \in \mathcal{A}_{\text{manifest}} \mid p \notin \mathcal{A}_{\text{active}} \}
$$

Classifier Deletion and Renaming Inductive Invariant: Let $\mathcal{V}_{\text{AST}}^{(k-1)}$ and $\mathcal{V}_{\text{AST}}^{(k)}$ denote the AST node sets in compilation cycles $k-1$ and $k$. For any classifier node $c \in \mathcal{V}_{\text{AST}}^{(k-1)}$, let $\text{Artifacts}(c) \subset \mathcal{P}_{\text{rel}}$ denote the generated files derived from $c$. If $c$ is deleted ($c \notin \mathcal{V}_{\text{AST}}^{(k)}$) or renamed to $c' \in \mathcal{V}_{\text{AST}}^{(k)}$ with $\text{FQN}(c') \ne \text{FQN}(c)$:

$$
\forall p \in \text{Artifacts}(c), \quad p \notin \mathcal{A}_{\text{active}} \implies p \in \mathcal{T}_{\text{prune}}
$$

Safe Idempotent Unlinking Operator: The unlinking operator $\text{UnlinkFile} : \mathcal{P}_{\text{rel}} \to \mathbb{B}$ satisfies:

$$
\text{UnlinkFile}(p) = \begin{cases}
\text{true}, & \text{if } \neg\text{FileExists}(\text{Resolve}(\mathcal{W}_{\text{out}}, p)) \\
\text{true}, & \text{if } \text{Unlink}(\text{Resolve}(\mathcal{W}_{\text{out}}, p)) = \text{OK} \\
\text{false}, & \text{if } \text{Unlink}(\text{Resolve}(\mathcal{W}_{\text{out}}, p)) = \text{Err}(e)
\end{cases}
$$

Recursive Empty Parent Directory Pruning Invariant: Let $\text{Parent}(d)$ denote the parent directory of path $d$, and let $\text{Entries}(d)$ denote the set of directory entries in $d$. The directory pruning function $\text{CleanEmptyParentDirs} : \mathcal{P}_{\text{dir}} \to \mathbb{N}_0$ is defined inductively:

$$
\text{CleanEmptyParentDirs}(d) = \begin{cases}
0, & \text{if } d = \mathcal{W}_{\text{out}} \;\vee\; \neg\text{DirExists}(d) \\
0, & \text{if } |\text{Entries}(d)| \gt 0 \\
1 + \text{CleanEmptyParentDirs}(\text{Parent}(d)), & \text{if } |\text{Entries}(d)| = 0 \;\wedge\; \text{Rmdir}(d) = \text{OK}
\end{cases}
$$

Post-Pruning Working Tree Cleanliness Invariant: Following pruning, the working tree contains zero residual files from removed model elements and zero empty ancestor directories within $\mathcal{W}_{\text{out}}$:

$$
\forall p \in \mathcal{T}_{\text{prune}}, \quad \text{FileExists}(\text{Resolve}(\mathcal{W}_{\text{out}}, p)) \equiv \text{false}
$$

$$
\forall d \subset \mathcal{W}_{\text{out}}, \quad \text{DirExists}(d) \implies |\text{Entries}(d)| \gt 0
$$

Manifest Synchronization Invariant: Following pruning, the updated on-disk manifest records strictly the active artifact set:

$$
\begin{aligned}
\pi_{\text{path}}(\mathcal{M}_{\text{updated}}) &\equiv \mathcal{A}_{\text{active}} \\
\pi_{\text{path}}(\mathcal{M}_{\text{updated}}) \cap \mathcal{T}_{\text{prune}} &= \emptyset
\end{aligned}
$$

Deterministic UUIDv5 and Content Digest Invariant: Every entry in the persisted manifest binds a deterministic RFC 4122 UUIDv5 anchor and XXH3 content digest:

$$
\forall \langle p, u, h, s, t \rangle \in \mathcal{M}, \quad u = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(v)) \;\wedge\; h = \text{XXH3}_{64}(\text{ReadBytes}(p))
$$

Diagnostic Code Binding Invariant: Filesystem permission violations, unconfined path traversals, or manifest deserialization corruptions deterministically trigger structured diagnostics in accordance with REQ-0191:

$$
\begin{aligned}
\neg\text{IsDescendant}(\text{Resolve}(\mathcal{W}_{\text{out}}, p), \mathcal{W}_{\text{out}}) &\implies \text{Diagnostic}(p, \text{DiagnosticCode::E0200}, \text{UnsafePathTraversalViolation}) \in \mathcal{D}_{\text{sink}} \\
\text{Unlink}(\text{Resolve}(\mathcal{W}_{\text{out}}, p)) = \text{Err}(e) &\implies \text{Diagnostic}(p, \text{DiagnosticCode::E0200}, \text{TombstoneUnlinkFailure}) \in \mathcal{D}_{\text{sink}} \\
\text{Deserialize}(\text{ManifestBytes}) = \text{Err}(e) &\implies \text{Diagnostic}(\text{ManifestPath}, \text{DiagnosticCode::E0200}, \text{ManifestDeserializationFailure}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant: All emitted diagnostics strictly belong to the Subsystem 3 metamodel and typing family:

$$
\forall d \in \mathcal{D}_{\text{tombstone}}, \quad \text{code}(d) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}}
$$

- **Computational Complexity & Algorithmic Bounds**: The tombstone pruning engine executes strictly within Complexity Class $\mathbf{P}$. For a previous manifest containing $N_{\text{prev}} = |\mathcal{A}_{\text{manifest}}|$ artifact entries and a current compilation pass generating $N_{\text{act}} = |\mathcal{A}_{\text{active}}|$ active entries, algorithmic bounds are established as follows:
  1. Manifest Deserialization & Hash Set Construction: Deserializing the previous manifest from disk executes in deterministic linear time $O(N_{\text{prev}})$. Inserting all $N_{\text{act}}$ active path strings into an open-addressing hash set requires $O(N_{\text{act}})$ amortized time, with each path hash computation taking $O(|p|)$ time.
  2. Set Difference Evaluation: Computing $\mathcal{T}_{\text{prune}} = \mathcal{A}_{\text{manifest}} \setminus \mathcal{A}_{\text{active}}$ queries each path $p \in \mathcal{A}_{\text{manifest}}$ against the active hash set, requiring $O(1)$ expected lookup time per path and total expected time $O(N_{\text{prev}})$. When paths are maintained in lexicographically sorted arrays, set difference executes via a two-pointer merge traversal in deterministic $O(N_{\text{prev}} + N_{\text{act}})$ time without dynamic hashing overhead.
  3. Unlink Execution: For $K = |\mathcal{T}_{\text{prune}}|$ identified tombstones ($0 \le K \le N_{\text{prev}}$), issuing unlinking operations requires $O(K)$ filesystem operations, each executing in $O(1)$ time on standard operating system filesystems.
  4. Recursive Empty Parent Directory Pruning: For each unlinked file $f \in \mathcal{T}_{\text{prune}}$, directory inspection ascends at most $D_{\text{max}}$ directory hierarchy levels, where $D_{\text{max}} \le 32$ is the maximum directory depth within the output root $\mathcal{W}_{\text{out}}$. Checking entry count $|\text{Entries}(d)|$ and removing empty directories via `rmdir` takes $O(1)$ time per directory level. With visited-set directory memoization, each directory node in the pruned tree is processed at most once, bounding total directory cleanup time to $O(K + |\mathcal{D}_{\text{pruned}}|)$ where $|\mathcal{D}_{\text{pruned}}| \le K \cdot D_{\text{max}}$.
  5. Manifest Serialization: Persisting the updated manifest containing $N_{\text{act}}$ entries to disk executes in deterministic linear time $O(N_{\text{act}})$.

  Total sequential execution time across all pruning stages is strictly linear:

$$
T_{\text{total}}(N_{\text{prev}}, N_{\text{act}}, K, D_{\text{max}}) \in O(N_{\text{prev}} + N_{\text{act}} + K \cdot D_{\text{max}}) \subseteq O(N_{\text{prev}} + N_{\text{act}})
$$

  Parallel Work-Stealing Scaling: When unlinking operations across disjoint directory partitions are scheduled across $N_{\text{max\_workers}}$ threads in the bounded work-stealing pool:

$$
T_{\text{parallel}} \in O\left( \frac{N_{\text{prev}} + N_{\text{act}} + K \cdot D_{\text{max}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  Space Complexity & Memory Bounds: Auxiliary working memory is strictly bounded by $O((N_{\text{prev}} + N_{\text{act}}) \cdot \bar{L}_{\text{path}})$, where $\bar{L}_{\text{path}}$ is the average path length ($\le 256\text{ bytes}$). Call stack recursion depth for directory cleanup is strictly bounded by $O(D_{\text{max}}) \le 32$ stack frames ($O(1)$ auxiliary stack space).

- **Verification & Conformance Criteria**: Deterministic conformance shall be verified by automated test suites operating on synthetic MBSE models containing abstract placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Part_0`, `Port_1`, `Flow_A`, `param_x : Real`). Conformance validation shall enforce the following test gates:
  1. Classifier Rename Tombstone Pruning Gate: Ingest an initial model containing `Package_0::Classifier_Alpha` generating 3 target artifacts (`Package_0/Classifier_Alpha.sysml`, `Package_0/Classifier_Alpha.hpp`, `Package_0/Classifier_Alpha.cpp`). Rename `Package_0::Classifier_Alpha` to `Package_0::Classifier_Beta` in the source model and re-compile. Assert that:
     - The pruning engine identifies the 3 obsolete files in $\mathcal{T}_{\text{prune}}$.
     - All 3 obsolete files are cleanly unlinked from disk ($\text{FileExists} \equiv \text{false}$).
     - The 3 new files for `Classifier_Beta` are present on disk.
     - The updated manifest contains strictly the active paths for `Classifier_Beta` with zero references to `Classifier_Alpha`.
  2. Classifier Deletion & Recursive Directory Pruning Gate: Ingest a model containing an isolated nested package hierarchy `Package_0::SubPackage_1::Classifier_Gamma` generating files within directory `generated/Package_0/SubPackage_1/`. Delete `Classifier_Gamma` from the AST model and re-compile. Assert that:
     - All generated files for `Classifier_Gamma` are unlinked.
     - Subdirectory `generated/Package_0/SubPackage_1/` is deleted because it becomes empty.
     - If `Package_0/` contains active files from other classifiers (e.g., `Classifier_Alpha`), assert that `generated/Package_0/` is preserved.
  3. Manifest Bijective Synchronization Gate: Execute compilation passes across varying AST configurations. Assert that across 100% of test runs:
     - $\pi_{\text{path}}(\mathcal{M}_{\text{updated}}) \equiv \mathcal{A}_{\text{active}}$.
     - $\pi_{\text{path}}(\mathcal{M}_{\text{updated}}) \cap \mathcal{T}_{\text{prune}} = \emptyset$.
     - The on-disk manifest JSON/CBOR digest matches the in-memory active set digest byte-for-byte.
  4. Idempotent Safe Unlinking Gate: Prior to executing tombstone pruning, manually delete an artifact in $\mathcal{T}_{\text{prune}}$ to simulate external deletion. Assert that `prune_tombstones` executes idempotently without raising errors or crashing on missing files (`ENOENT`).
  5. Path Confinement & Traversal Rejection Gate: Inject a malformed entry into `CodegenManifest` referencing a path with traversal prefixes (`../../etc/shadow`). Assert that the engine detects the boundary violation, emits structured diagnostic record `E0200` (`UnsafePathTraversalViolation`), and refuses to issue an unlink call against the unconfined path.
  6. Filesystem Error Recovery Gate (Architectural Directive 4): Simulate a filesystem permission restriction (`EACCES` / read-only file) on an orphaned file in $\mathcal{T}_{\text{prune}}$. Assert that:
     - The engine records structured diagnostic record `E0200` (`TombstoneUnlinkFailure`) containing the path and error reason into the diagnostic sink.
     - The engine continues unlinking remaining valid tombstones without aborting compilation or panicking.
     - When accumulated errors reach $C_{\text{max\_errors}}$, assert graceful termination with terminal code `E0199`.
  7. Deterministic UUIDv5 Anchor Gate (Architectural Directive 1): Assert that 100% of manifest records bind valid RFC 4122 UUIDv5 identifiers derived from the compiler namespace and fully qualified paths per REQ-0010.
  8. Bounded Work-Stealing Parallelism Gate (Architectural Directive 2): Benchmark multi-threaded tombstone pruning across $10^4$ files using $N_{\text{max\_workers}}$ threads; assert zero race conditions, data-race freedom, and bitwise identical manifest output compared to single-threaded execution.
  9. Release Mode Latency & Memory Budget Gate (Architectural Directive 5): In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, assert that pruning $10^4$ tombstones executes in under 25 ms and peak RSS memory remains strictly under 100 MB.
  10. Bitwise Determinism & Zero Diff Churn Gate: Re-run compilation on an unmodified model AST. Assert that the tombstone set is strictly empty ($\mathcal{T}_{\text{prune}} = \emptyset$), zero unlinking syscalls are executed, and the on-disk manifest exhibits 0-byte diff churn.
