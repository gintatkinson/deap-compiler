### REQ-0071: SysML v2 PartDefinition (`part def`) & PartUsage (`part`) Lowering

- **Normative Statement**: The structural compiler, semantic metamodel lowering engine, and abstract syntax tree (AST) graph engine shall formalize SysML v2 part definitions (`part def`, `PartDefinition`) and part usages (`part`, `PartUsage`) into strongly typed, compositely owned structural elements anchored within the core KerML classifier subtyping lattice $(\mathcal{K}, \le)$.

  The lowering engine shall strictly enforce the following normative operational specifications across all part definition and part usage declarations:
  1. **Metamodel Classifier Specialization & Disjointness**:
     - `PartDefinition` shall specialize KerML `Structure`, which transitively specializes KerML `Class`, `Classifier`, and `Type` ($\text{PartDef} \le \text{Structure} \le \text{Class} \le \text{Classifier} \le \text{Type}$).
     - `PartDefinition` shall represent an extensional identity-bearing classifier ($\llbracket \text{PartDef} \rrbracket \subset \mathcal{O}_{\text{entities}}$) and shall be strictly disjoint from identity-free value types ($\llbracket \text{PartDef} \rrbracket \cap \llbracket \text{DataType} \rrbracket = \emptyset$). Any model element declaring a `part def` that specializes or inherits from a `DataType` shall be deterministically rejected at compile time with structured diagnostic error code `E0200` in accordance with REQ-0191.
     - `PartDefinition` elements shall serve as reusable, parameterizable structural types possessing extensional identity, internal state, owned directed ports, owned sub-parts, attributes, behavioral actions, state machines, and formal constraints.
  2. **PartUsage Composite Feature Semantics & Existential Lifetime**:
     - Every `part` usage declaration shall lower into a `PartUsage` AST node specializing KerML `Feature` and SysML v2 `ItemUsage`, with the composite ownership flag set strictly to true ($\text{is\_composite}(u) \equiv \text{true}$).
     - Composite ownership shall establish an existential lifetime dependency binding between the owning classifier instance $x \in \llbracket \text{owner}(u) \rrbracket$ and the feature instance projection $y \in \pi_{u}(x)$: destruction, deallocation, or lifecycle termination of the containing parent instance $x$ shall unconditionally cause the destruction, deallocation, or termination of all owned constituent part instances $y$.
     - **Exclusive Single-Ownership Invariant (Anti-Aliasing)**: At any point during system execution or semantic simulation, every composite part instance $y$ shall belong to at most one composite parent instance ($\forall y \in \mathcal{O}_{\text{part}}, |\text{owning\_composite}(y)| \le 1$). Shared or aliased composite ownership across multiple distinct parent instances shall be strictly prohibited; non-composite structural references must be declared as reference usages rather than composite part usages. Violation of exclusive composite ownership shall trigger diagnostic error code `E0200`.
  3. **Multiplicity Interval Normalization & Default Semantics**:
     - When a `part` usage is declared without an explicit multiplicity specification, the compiler shall automatically assign an exact singleton multiplicity interval $\mu(u) = [1, 1]$ ($m_{\min} = 1, m_{\max} = 1$).
     - Explicit multiplicity declarations (`[m_min..m_max]`) shall be validated for well-formedness: $0 \le m_{\min} \le m_{\max}$, where $m_{\max} \in \mathbb{N}_{0} \cup \{ \infty \}$. Invalid multiplicity ranges where $m_{\min} \gt m_{\max}$ shall be rejected deterministically with diagnostic error code `E0200`.
  4. **Hierarchical Sub-Assembly Containment & Graph Acyclicity**:
     - Part definitions and composite part usages shall form a hierarchical sub-assembly containment graph $G_{\text{contain}} = (\mathcal{D}_{\text{part}}, \mathcal{E}_{\text{contain}})$, where a directed edge $(D_{1}, D_{2}) \in \mathcal{E}_{\text{contain}}$ exists if $D_{1}$ owns a composite part usage $u$ typed by $D_{2}$ ($\tau(u) = D_{2}$).
     - **No Infinite Physical Containment Cycles**: The sub-assembly containment graph shall be verified for cycle-freedom across all containment paths with non-zero lower multiplicity ($m_{\min} \ge 1$). If there exists a circular containment cycle $D_{1} \to D_{2} \to \dots \to D_{k} \to D_{1}$ where every participating edge has lower multiplicity $m_{\min} \ge 1$, the model specifies an impossible infinite physical recursion and shall be rejected deterministically with diagnostic error code `E0203` (`CircularCompositeContainment`).
     - Every lowered `PartUsage` node in the contiguous AST arena shall maintain an immutable, direct handle to its enclosing parent classifier or composite part, providing deterministic $O(1)$ upward parent navigation without linear tree search.
  5. **Subtyping, Subsetting (`:>`), and Redefinition (`:>>`) Invariants**:
     - When a part usage subsets an inherited part usage ($u_{\text{sub}} :> u_{\text{sup}}$), the type of the subsetting part usage must specialize or equal the type of the subsetted part usage ($\tau(u_{\text{sub}}) \le \tau(u_{\text{sup}})$), and the multiplicity interval must preserve value-set inclusion ($\mu(u_{\text{sub}}).m_{\max} \le \mu(u_{\text{sup}}).m_{\max}$ and $\mu(u_{\text{sub}}).m_{\min} \le \mu(u_{\text{sup}}).m_{\max}$) in accordance with REQ-0061.
     - When a part usage redefines an inherited part usage ($u_{\text{redef}} :>> u_{\text{orig}}$), the redefining part usage shall replace the feature slot within the specializing context, satisfying type co-variance ($\tau(u_{\text{redef}}) \le \tau(u_{\text{orig}})$) and multiplicity tightening ($\mu(u_{\text{redef}}) \subseteq \mu(u_{\text{orig}})$) in accordance with REQ-0062 and algorithmic bound NP-3. Incompatible types or widened multiplicity envelopes shall be rejected with diagnostic error code `E0200`.
  6. **Owned Structural Constituents & Port Binding**:
     - A `PartDefinition` may feature owned directed ports (`port`), internal connections (`connection`, `connect`), attributes (`attribute`), behavioral actions (`action`), state machines (`state`), and constraints (`constraint`, `assert constraint`). All owned ports within a composite part usage shall have their fully qualified hierarchical paths bound deterministically to enable inter-part interface connections across sub-assemblies.
  7. **Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered `PartDefinition` and `PartUsage` node shall be assigned a bitwise deterministic RFC 4122 UUIDv5 identifier derived from the canonical compiler namespace OID and its fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(e))$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel AST lowering, type resolution, and containment cycle detection across independent package units shall execute exclusively on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Allocation Exception)*: String bytes representing part names, type identifiers, and symbol tokens shall be copied from the source buffer into the global symbol interner pool during the initial lexical pass to generate scalar `SymbolId` tokens in accordance with REQ-0036, representing the sole permitted exception to the zero-copy arena allocation invariant.
     - *Directive 4 (Synchronization Token Error Recovery)*: The part definition parser and validator shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`), recording structured diagnostic records (`E0200`, `E0203`) into the diagnostic sink $\mathcal{D}_{\text{sink}}$ and continuing semantic analysis across remaining declarations. If accumulated errors reach the error sink bound $C_{\text{max\_errors}}$, the compiler shall emit terminal diagnostic `E0199` and gracefully terminate.
     - *Directive 5 (Panic-Free Release Isolation)*: The lowering engine shall enforce a deterministic, non-panicking execution contract with total-function error handling across all valid and invalid inputs, binding a typed error sentinel $\bot_{\text{part}}$ to malformed nodes. Performance latency ($\lt 25\text{ ms}$ for $10^4$ part declarations) and peak RSS memory ($\lt 100\text{ MB}$ RSS) performance gates shall be verified exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
     - *Domain Purity & Synthetic Placeholders*: All diagnostic messages, test models, and documentation shall strictly use synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `PartDef_Alpha`, `PartDef_Beta`, `PartDef_Gamma`, `PartDef_Delta`, `Part_0`, `Part_1`, `Part_Sub`, `Port_1`, `Port_2`, `Flow_A`, `param_x : Real`), with zero hardcoded domain concepts and zero non-ASCII em dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes within the contiguous node arena. The set of part definitions $\mathcal{D}_{\text{part}} \subset \mathcal{V}_{\text{AST}}$ and part usages $\mathcal{U}_{\text{part}} \subset \mathcal{V}_{\text{AST}}$ are partitioned by discriminant classifier and feature kinds:

$$
\text{Kind} \in \{ \text{PartDefinition}, \text{PartUsage} \}
$$

Each part definition $D \in \mathcal{D}_{\text{part}}$ is formalized as a 7-tuple:

$$
D = \langle \text{id}_{D}, \text{name}_{D}, \mathcal{S}_{D}, \mathcal{F}_{D}, \mu(D), \Delta_{D}, \text{span}_{D} \rangle
$$

where:

$$
\begin{aligned}
\text{id}_{D} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{D} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\mathcal{S}_{D} &\subseteq \mathcal{K} \quad (\text{direct supertypes specializing Structure}) \\
\mathcal{F}_{D} &\subseteq \mathcal{U}_{\text{feat}} \quad (\text{owned feature definitions and usages}) \\
\mu(D) &= [m_{\min}(D), m_{\max}(D)] \subseteq \mathbb{N}_{0} \times (\mathbb{N}_{0} \cup \{ \infty \}) \quad (\text{classifier multiplicity envelope}) \\
\Delta_{D} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{D} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

Each part usage $u \in \mathcal{U}_{\text{part}}$ is formalized as a 10-tuple:

$$
u = \langle \text{id}_{u}, \text{name}_{u}, \text{owner}_{u}, \tau(u), \mu(u), \text{comp}_{u}, \mathcal{S}_{u}, \mathcal{R}_{u}, \Delta_{u}, \text{span}_{u} \rangle
$$

where:

$$
\begin{aligned}
\text{id}_{u} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{u} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_{u} &\in \mathcal{K} \quad (\text{owning classifier or parent composite part}) \\
\tau(u) &\in \mathcal{D}_{\text{part}} \cup \{ \bot_{\text{part}} \} \quad (\text{bound part definition type}) \\
\mu(u) &= [m_{\min}(u), m_{\max}(u)] \subseteq \mathbb{N}_{0} \times (\mathbb{N}_{0} \cup \{ \infty \}) \quad (\text{multiplicity interval}) \\
\text{comp}_{u} &\in \{ \text{true} \} \quad (\text{strict composite ownership flag}) \\
\mathcal{S}_{u} &\subseteq \mathcal{U}_{\text{part}} \quad (\text{subsetted part usages}) \\
\mathcal{R}_{u} &\subseteq \mathcal{U}_{\text{part}} \quad (\text{redefined part usages}) \\
\Delta_{u} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{u} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

Metamodel Specialization Hierarchy: In the SysML v2 metamodel, `PartDefinition` inherits structural and stateful classification through KerML:

$$
\text{PartDef} \le \text{Structure} \le \text{Class} \le \text{Classifier} \le \text{Type}
$$

Disjointness Invariant: `PartDefinition` instances are extensional identity-bearing entities, strictly disjoint from value types:

$$
\llbracket \text{PartDef} \rrbracket \subseteq \llbracket \text{Structure} \rrbracket \subseteq \mathcal{O}_{\text{entities}}, \quad \llbracket \text{PartDef} \rrbracket \cap \llbracket \text{DataType} \rrbracket = \emptyset
$$

Composite Ownership Relation: The composite ownership relation $\mathcal{C}_{\text{part}} \subset \mathcal{D}_{\text{part}} \times \mathcal{U}_{\text{part}}$ associates each part definition with its owned composite part usages:

$$
\mathcal{C}_{\text{part}} = \{ (D, u) \in \mathcal{D}_{\text{part}} \times \mathcal{U}_{\text{part}} \mid u \in \mathcal{F}_{D} \wedge \text{comp}_{u} \equiv \text{true} \}
$$

Existential Lifetime Binding Invariant: For every composite part usage $(D, u) \in \mathcal{C}_{\text{part}}$, the destruction of any instance $x$ of $D$ unconditionally implies the destruction of all instance projections $y \in \pi_{u}(x)$:

$$
\forall (D, u) \in \mathcal{C}_{\text{part}}, \quad \forall x \in \llbracket D \rrbracket : \text{Destroy}(x) \implies \left( \forall y \in \pi_{u}(x), \, \text{Destroy}(y) \right)
$$

Exclusive Single-Ownership (Anti-Aliasing) Invariant: Every composite part instance belongs to at most one composite parent instance across the execution universe:

$$
\forall y \in \mathcal{O}_{\text{part}}, \quad \left| \{ x \in \mathcal{O}_{\text{entities}} \mid y \in \text{composite\_parts}(x) \} \right| \le 1
$$

Default Multiplicity Invariant: When omitted from the source specification, the multiplicity interval $\mu(u)$ defaults to the exact singleton interval:

$$
\text{unspecified}(\mu(u)) \implies \mu(u) = [1, 1] \iff (m_{\min}(u) = 1 \;\wedge\; m_{\max}(u) = 1)
$$

Multiplicity Well-Formedness Invariant: Every part usage multiplicity interval must satisfy lower and upper bound consistency:

$$
\forall u \in \mathcal{U}_{\text{part}}, \quad 0 \le \mu(u).m_{\min} \le \mu(u).m_{\max}
$$

Hierarchical Sub-Assembly Containment Graph: Let $G_{\text{contain}} = (\mathcal{D}_{\text{part}}, \mathcal{E}_{\text{contain}})$ denote the directed containment graph where:

$$
(D_{1}, D_{2}) \in \mathcal{E}_{\text{contain}} \iff \exists u \in \mathcal{F}_{D_{1}} : (u \in \mathcal{U}_{\text{part}} \wedge \tau(u) = D_{2})
$$

Non-Zero Lower Multiplicity Containment Subgraph: Let $\mathcal{E}_{\text{contain}, \ge 1} \subseteq \mathcal{E}_{\text{contain}}$ denote the set of containment edges where the child part usage mandates non-zero lower multiplicity:

$$
(D_{1}, D_{2}) \in \mathcal{E}_{\text{contain}, \ge 1} \iff \exists u \in \mathcal{F}_{D_{1}} : (u \in \mathcal{U}_{\text{part}} \wedge \tau(u) = D_{2} \wedge \mu(u).m_{\min} \ge 1)
$$

Acyclicity Invariant (No Infinite Physical Containment Recursion): The transitive closure $\mathcal{E}_{\text{contain}, \ge 1}^{+}$ must be strictly irreflexive:

$$
\forall D \in \mathcal{D}_{\text{part}}, \quad (D, D) \notin \mathcal{E}_{\text{contain}, \ge 1}^{+}
$$

Parent Navigation Invariant: Upward parent navigation from any part usage $u$ to its owning classifier node is direct and constant time:

$$
\forall u \in \mathcal{U}_{\text{part}}, \quad \text{parent}(u) = \text{owner}_{u} \in \mathbb{N}_{32}
$$

Subsetting and Redefinition Invariants: Lowered subsetting and redefinition relations between part usages must preserve co-variant subtyping and multiplicity narrowing:

$$
\begin{aligned}
\forall (u_{\text{sub}}, u_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, &\quad (\tau(u_{\text{sub}}) \le \tau(u_{\text{sup}})) \wedge (\mu(u_{\text{sub}}).m_{\max} \le \mu(u_{\text{sup}}).m_{\max}) \wedge (\mu(u_{\text{sub}}).m_{\min} \le \mu(u_{\text{sup}}).m_{\max}) \\
\forall (u_{\text{redef}}, u_{\text{orig}}) \in \mathcal{R}_{\text{redef}}, &\quad (\tau(u_{\text{redef}}) \le \tau(u_{\text{orig}})) \wedge (\mu(u_{\text{redef}}) \subseteq \mu(u_{\text{orig}}))
\end{aligned}
$$

Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1): Every lowered part definition and part usage node is deterministically hashed from the canonical compiler namespace OID and its fully qualified topological path:

$$
\begin{aligned}
\forall D \in \mathcal{D}_{\text{part}}, &\quad \Delta_{D} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(D)) \\
\forall u \in \mathcal{U}_{\text{part}}, &\quad \Delta_{u} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))
\end{aligned}
$$

Diagnostic Trigger Rules: Violations of metamodel typing, containment acyclicity, or multiplicity envelopes deterministically trigger compiler diagnostics in accordance with REQ-0191:

$$
\begin{aligned}
\exists D \in \mathcal{D}_{\text{part}} : D \le \text{DataType} &\implies \text{Diagnostic}(D, \text{DiagnosticCode::E0200}, \text{PartDefDataTypeSpecializationViolation}) \in \mathcal{D}_{\text{sink}} \\
\exists D \in \mathcal{D}_{\text{part}} : (D, D) \in \mathcal{E}_{\text{contain}, \ge 1}^{+} &\implies \text{Diagnostic}(D, \text{DiagnosticCode::E0203}, \text{CircularCompositeContainment}) \in \mathcal{D}_{\text{sink}} \\
\exists u \in \mathcal{U}_{\text{part}} : \mu(u).m_{\min} \gt \mu(u).m_{\max} &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{InvalidMultiplicityInterval}) \in \mathcal{D}_{\text{sink}} \\
\exists (u_{\text{sub}}, u_{\text{sup}}) \in \mathcal{R}_{\text{subset}} : \tau(u_{\text{sub}}) \not\le \tau(u_{\text{sup}}) &\implies \text{Diagnostic}(u_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{IncompatiblePartSubsettingType}) \in \mathcal{D}_{\text{sink}} \\
\exists (u_{\text{redef}}, u_{\text{orig}}) \in \mathcal{R}_{\text{redef}} : \tau(u_{\text{redef}}) \not\le \tau(u_{\text{orig}}) &\implies \text{Diagnostic}(u_{\text{redef}}, \text{DiagnosticCode::E0200}, \text{IncompatiblePartRedefinitionType}) \in \mathcal{D}_{\text{sink}} \\
\exists u \in \mathcal{U}_{\text{part}} : \tau(u) \notin \mathcal{D}_{\text{part}} \cup \{ \bot_{\text{part}} \} &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{UnresolvedPartTypeReference}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant: All emitted diagnostic codes strictly belong to the Metamodel and Typing family and Ingestion error limit family:

$$
\forall d \in \mathcal{D}_{\text{part}}, \quad \text{code}(d) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0203}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{ingest}}
$$

- **Computational Complexity & Algorithmic Bounds**: Part definition and part usage lowering, containment cycle detection, and subtyping validation execute strictly within Complexity Class $\mathbf{P}$.

  For an abstract model containing $V_{D} = |\mathcal{D}_{\text{part}}|$ part definitions, $V_{u} = |\mathcal{U}_{\text{part}}|$ part usages, $V = V_{D} + V_{u}$ total AST nodes, and $E = |\mathcal{E}_{\text{contain}}| + |\mathcal{E}_{\text{gen}}|$ graph edges:
  1. *Contiguous Arena Allocation & Interning*: Allocating $V$ AST nodes in contiguous arena storage requires $O(V)$ time with $O(1)$ amortized allocation per node. Interning symbol names and qualified paths into the global symbol interner pool requires $O(\sum |\text{name}|)$ byte hashing operations.
  2. *Containment Graph Construction & Cycle Detection*: Constructing the sub-assembly containment graph $G_{\text{contain}}$ and identifying circular containment cycles over $\mathcal{E}_{\text{contain}, \ge 1}$ using Tarjan's Strongly Connected Components (SCC) algorithm or depth-first search (DFS) with 3-color vertex marking executes in deterministic $O(V_{D} + |\mathcal{E}_{\text{contain}}|)$ time and $O(V_{D})$ auxiliary working space.
  3. *Parent Navigation*: Resolving the containing parent classifier or composite part from any child part usage executes in strictly $O(1)$ time via direct arena handle dereference.
  4. *Subtyping, Subsetting, and Redefinition Conformance*: In accordance with algorithmic bound NP-3, classifier inheritance is structured as a monotonic meet-semilattice resolved via deterministic C3 linearization. Subtyping queries $\tau(u_{\text{sub}}) \le \tau(u_{\text{sup}})$ execute in $O(1)$ time using precomputed reachability bitsets. Multiplicity interval comparisons execute in $O(1)$ scalar integer operations per edge.
  5. *Total Sequential Lowering Complexity*: The complete sequential lowering and semantic verification pipeline across all part definitions and usages executes in linear time:

$$
T_{\text{validate}}(V, E) \in O(V + E)
$$

  6. *Parallel Work-Stealing Scaling (Directive 2)*: When independent packages and sub-assembly hierarchies are parsed and validated across $N_{\text{max\_workers}}$ threads in the bounded work-stealing pool:

$$
T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{V + E}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  7. *Space Complexity & Memory Bounds*: Arena node storage requires strictly $O(V)$ contiguous memory. Adjacency lists for the containment graph require $O(V_{D} + |\mathcal{E}_{\text{contain}}|)$ memory. Call stack recursion depth during hierarchical tree traversal is strictly bounded by assembly depth $h \le 64$ frames ($O(1)$ auxiliary stack space). The diagnostic sink is bounded by $O(C_{\text{max\_errors}}) = O(1)$ allocated records.

- **Verification & Conformance Criteria**: Automated test suites shall verify deterministic conformance using synthetic SysML v2 model definitions containing purely abstract MBSE placeholders (`Package_0`, `Package_1`, `PartDef_Alpha`, `PartDef_Beta`, `PartDef_Gamma`, `PartDef_Delta`, `Part_0`, `Part_1`, `Part_Sub`, `Port_1`, `Port_2`, `Flow_A`, `param_x : Real`). Conformance validation shall enforce the following deterministic test gates:

  1. **Metamodel Specialization Hierarchy Gate**: Ingest a model declaring `part def PartDef_Alpha;`. Assert that `PartDef_Alpha` specializes KerML `Structure` and `Class`, is an extensional entity, has `is_composite = false` at the definition level, and emits zero diagnostics.

Assert that the lowering engine deterministically detects the disjointness violation, emits structured diagnostic error code `E0200` (`PartDefDataTypeSpecializationViolation`) with exact source byte spans, binds sentinel $\bot_{\text{part}}$, and halts downstream lowering without panicking.
  3. **Composite Feature Ownership & Existential Lifetime Gate**: Declare `part def PartDef_Beta { part part_0 : PartDef_Alpha; }`. Assert that `part_0` has `is_composite = true`, binds existential lifetime to parent instance `PartDef_Beta`, and records owning classifier handle `id(PartDef_Beta)`.
  4. **Default Multiplicity Singleton Gate**: Ingest a part usage declaration without explicit multiplicity: `part part_0 : PartDef_Alpha;`. Assert that the compiler normalizes the multiplicity interval to exact singleton $\mu(\text{part\_0}) = [1, 1]$.
  5. **Explicit Multiplicity Range Gate**: Ingest `part part_0 [2..4] : PartDef_Alpha;` and `part part_1 [0..*] : PartDef_Beta;`. Assert lowered multiplicity intervals $\mu(\text{part\_0}) = [2, 4]$ and $\mu(\text{part\_1}) = [0, \infty]$. Ingest an invalid inverted interval `part part_err [5..2] : PartDef_Alpha;`; assert deterministic rejection with diagnostic code `E0200` (`InvalidMultiplicityInterval`).
  6. **Exclusive Single-Ownership Anti-Aliasing Gate**: Ingest an assembly model attempting composite aliasing where a single composite part instance is assigned to multiple containing parents. Assert deterministic rejection with diagnostic code `E0200`.
  7. **Sub-Assembly Hierarchical Containment & $O(1)$ Parent Navigation Gate**: Construct a 10-level nested assembly hierarchy ($P_{9}$ inside $P_{8} \dots$ inside $P_{0}$). Assert that traversing parent handles from the deepest leaf to root executes in strictly $O(1)$ steps per edge without global AST searching.
  8. **Circular Composite Containment Detection Gate (`E0203`)**: Declare a mutual composite containment cycle with non-zero lower multiplicity:
     - `part def PartDef_Alpha { part part_b : PartDef_Beta [1..1]; }`
     - `part def PartDef_Beta { part part_a : PartDef_Alpha [1..1]; }`
     Assert that the cycle detector identifies the recursive loop, emits diagnostic error code `E0203` (`CircularCompositeContainment`) highlighting both participating part definitions, and halts gracefully without infinite loop or stack overflow.
  9. **Optional Recursive Containment Permissibility Gate**: Declare a recursive part definition with optional lower multiplicity ($m_{\min} = 0$): `part def PartDef_Tree { part sub_tree : PartDef_Tree [0..2]; }`. Assert that because $m_{\min} = 0$, the structure represents a finite inductive tree rather than an infinite physical recursion, and is validated successfully with zero diagnostics.
  10. **Part Subsetting Gate (`:>`)**: Declare `part def PartDef_Super { part part_sup : PartDef_Alpha [0..5]; }`. In specializing `part def PartDef_Sub :> PartDef_Super`, declare `part part_sub :> part_sup : PartDef_Beta [1..3];` where `PartDef_Beta :> PartDef_Alpha`. Assert successful validation of co-variant type specialization and multiplicity narrowing. Declare a contravariant or disjoint type; assert rejection with diagnostic code `E0200` (`IncompatiblePartSubsettingType`).
  11. **Part Redefinition Gate (`:>>`)**: Declare `part redefines part_sup : PartDef_Beta [1..3];`. Assert slot replacement, subtyping co-variance, and multiplicity tightening. Incompatible types trigger diagnostic code `E0200` (`IncompatiblePartRedefinitionType`).

Verify that the lowering engine resynchronizes at each statement delimiter, accumulates all four `E0200` diagnostics with precise source spans, and halts gracefully with terminal diagnostic `E0199` when the error count reaches $C_{\text{max\_errors}}$.
  13. **Deterministic UUIDv5 Anchor Gate (Directive 1)**: Verify that 100% of lowered part definition and part usage AST nodes bind valid RFC 4122 UUIDv5 identifiers computed deterministically from the canonical compiler namespace OID and fully qualified symbol paths across repeated compilations.
