### REQ-0122: Deterministic Transition Guard Disjointness Verification ($`G_1 \wedge G_2 \equiv \text{false}`$)

#### 1. Normative Statement

The spatio-temporal dynamics and discrete state machine solver of Subsystem 6 shall statically analyze, verify, and enforce deterministic transition guard disjointness across all outgoing transitions originating from every state vertex within discrete hierarchical and flat state machines.

  Specifically, the transition conflict resolution engine, guard verification pipeline, and integrated SMT decision procedure shall strictly enforce the following structural, algebraic, and algorithmic requirements:
  1. **Trigger Equivalence Partitioning & Outgoing Transition Scope**:
     - For every state vertex $`s \in \mathcal{S}_{\text{states}}`$` in a lowered state machine AST, the compiler shall partition all outgoing transitions `$`\mathcal{T}_{\text{out}}(s) = \{ t \in \mathcal{T} \mid s \in \mathcal{S}_{\text{src}}(t) \}`$` into mutually disjoint equivalence classes grouped by identical event trigger symbols `$`e \in \mathcal{E}_{\text{event}} \cup \{ \epsilon \}`$` (where `$`\epsilon`$ denotes the completion trigger for triggerless transitions):

```math
       \mathcal{T}_{s, e} = \{ t \in \mathcal{T}_{\text{out}}(s) \mid e_{\text{trigger}}(t) = e \}
```

     - If an event trigger equivalence class contains at most one transition ($`|\mathcal{T}_{s, e}| \le 1`$`), the outgoing transition path on event `$`e`$ is trivially deterministic, requiring zero pairwise disjointness checks.
     - If an equivalence class contains two or more sibling transitions ($`|\mathcal{T}_{s, e}| \ge 2`$`), the compiler shall conduct exhaustive pairwise guard disjointness verification across all `$`\binom{|\mathcal{T}_{s, e}|}{2}`$ transition pairs.
  2. **Strict Guard Mutual Exclusion & Unsatisfiability Contract**:
     - For every pair of distinct sibling transitions $`t_1, t_2 \in \mathcal{T}_{s, e}`$` (`$`t_1 \ne t_2`$`) originating from the same source state on identical trigger `$`e`$`, the compiler shall verify that their normalized guard predicates `$`\overline{G}(t_1)`$` and `$`\overline{G}(t_2)`$` are mutually disjoint, such that their logical conjunction evaluates to identically false across the entire data state space `$`\mathcal{X}`$:

```math
       \text{UNSAT}(\overline{G}(t_1) \land \overline{G}(t_2)) \iff \neg \exists \mathbf{x} \in \mathcal{X} \text{ such that } (\overline{G}(t_1)(\mathbf{x}) = \text{true} \land \overline{G}(t_2)(\mathbf{x}) = \text{true})
```

       where $`\mathcal{X} = \prod_{k=1}^m \mathbb{D}_k`$ denotes the valuation space of all active state machine variables, attributes, parameters, and event payload fields.
     - An omitted guard expression on any transition $`t`$` shall be canonically normalized to the tautological true predicate: `$`\overline{G}(t) \equiv \text{true}`$. Consequently:
       * If two sibling transitions sharing the same trigger both omit guard conditions, they unconditionally conflict; the compiler shall deterministically reject the declaration with diagnostic error code `E0400` (`NonDisjointTransitionGuards`).
       * If one transition has an omitted guard ($`\overline{G} \equiv \text{true}`$`) and a sibling transition specifies a satisfiable guard `$`G_{\text{sub}}`$`, their conjunction evaluates to `$`G_{\text{sub}}`$, which is satisfiable; the compiler shall deterministically reject the pair with diagnostic error code `E0400` (`NonDisjointTransitionGuards`), requiring the modeler to provide an explicit mutually exclusive guard (such as $`\neg G_{\text{sub}}`$).
  3. **Syntactic Theory Admissibility & Decidable SMT Fragment Gate (NP-8 / REQ-0197)**:
     - In accordance with Algorithmic Bound NP-8 (REQ-0197), automated transition guard disjointness verification shall be strictly restricted to decidable quantifier-free first-order theories and propositional logic:
       * Propositional Logic (`PROP`) over Boolean variables.
       * Quantifier-Free Linear Real Arithmetic (`QF_LRA`) over rational and real scalar variables.
       * Quantifier-Free Linear Integer Arithmetic (`QF_LIA`) over integer and discrete variables.
       * Quantifier-Free Uninterpreted Functions with Equality (`QF_UF`).
     - Prior to SMT encoding, the compiler shall execute a syntactic admissibility traversal over every guard AST expression:
       * Guard expressions containing non-linear polynomial multiplication terms between variables ($`x \cdot y`$`), transcendental functions (`$`\sin, \cos, \tan, \exp, \ln`$), or division by non-constant expressions shall be rejected at compile time with diagnostic error code `E0406` (`NonAdmissibleGuardTheory`).
       * Guard expressions introducing first-order existential or universal quantifiers ($`\exists, \forall`$) shall be rejected at compile time with diagnostic error code `E0406` (`NonAdmissibleGuardTheory`).
     - Guard expressions must strictly evaluate to scalar `Boolean` type within the typing environment ($`\tau(g) \equiv \text{Boolean}`$). Guard expressions evaluating to non-boolean types shall be rejected with diagnostic error code `E0202` (`InvalidGuardType`) per REQ-0191.
  4. **Integrated SMT-LIB2 Decision Procedure & Bounded Step Budget ($`\kappa_{\text{guard}}`$)**:
     - For all non-trivial guard pairs ($`t_1, t_2`$`), the compiler shall lower the conjunction formula `$`\phi = \overline{G}(t_1) \land \overline{G}(t_2)`$ into canonical SMT-LIB2 assertions and invoke an integrated DPLL(T) decision procedure.
     - The decision procedure shall be constrained by an explicit compile-time operational step budget $`\kappa_{\text{guard}}`$` (bounded by default to `$`100{,}000`$ conflict/resolution steps):
       * *Unsatisfiable Result ($`\text{UNSAT}`$`)*: The solver generates a formal proof witness `$`\Pi_{\text{proof}}`$, certifying that no simultaneous activation exists. The transition pair is marked deterministically verified with zero diagnostics.
       * *Satisfiable Result ($`\text{SAT}`$`)*: The solver extracts a satisfying assignment model `$`\mathbf{x}_{\text{cex}} \in \mathcal{X}`$ serving as a concrete counterexample witness. The compiler shall emit structured diagnostic error code `E0400` (`NonDisjointTransitionGuards`), embedding the counterexample variable valuation, conflicting transition handles, and source byte spans.
       * *Timeout / Step Bound Exceeded*: If the internal solver step counter $`N_{\text{step}}`$` exceeds `$`\kappa_{\text{guard}}`$ without reaching a conclusive SAT or UNSAT verdict, the compiler shall abort the check deterministically and emit diagnostic error code `E0406` (`GuardSolverStepLimitExceeded`).
  5. **Hierarchical Statechart Conflict Precedence Interaction**:
     - In hierarchical statecharts possessing nested composite states, transition enabledness conflict resolution shall strictly follow the inner-first depth priority rule established in REQ-0080:
       * If two enabled transitions originate from states at different hierarchy depths ($`\text{Depth}(s_1) \ne \text{Depth}(s_2)`$), the transition originating from the deeper child state takes absolute precedence, rendering guard evaluation for the ancestor transition irrelevant.
       * Guard disjointness verification governed by REQ-0122 applies strictly to conflicting sibling transitions originating from the same source state vertex at identical hierarchy depth ($`\text{Depth}(s_1) = \text{Depth}(s_2)`$) sharing identical trigger events.
  6. **Fast-Path Interval Arithmetic Pre-Filter**:
     - To optimize compilation throughput, the compiler shall execute an initial lightweight polynomial-time interval intersection check on single-variable linear bound constraints (e.g., $`x \in [a, b]`$` vs `$`x \in [c, d]`$`, or `$`x \lt k`$` vs `$`x \ge k`$):
       * If the interval domains of the two guards are proven disjoint via constant-time interval arithmetic ($`[a, b] \cap [c, d] = \emptyset`$`), disjointness is certified immediately in `$`O(1)`$ time without dispatching the full DPLL(T) solver.
       * Multivariate constraints or non-convex boolean combinations that cannot be discharged by the interval pre-filter are routed directly to the integrated SMT-LIB2 decision procedure.
  7. **Executive Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every transition AST node, guard expression node, SMT proof obligation record, and counterexample witness artifact shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel guard disjointness checking across independent state vertices, state machine containers, and compilation packages shall execute exclusively on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Allocation Exception)*: Transition identifiers, state names, event symbols, guard variable tokens, and SMT assertion labels shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The dynamics solver shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When semantic violations occur (`E0400`, `E0406`, `E0202`), diagnostics shall accumulate in the error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{guard}}`$`, `$`\bot_{\text{trans}}`$`), and continue validating subsequent state and transition declarations. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Isolation)*: The transition guard verification pipeline shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($`\lt 25\text{ ms}`$` for benchmark models of `$`10^3`$` guard pairs) and peak RSS memory (`$`\lt 100\text{ MB}`$) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `StateMachine_Alpha`, `StateMachine_Beta`, `State_Alpha`, `State_Beta`, `State_Gamma`, `State_Root`, `State_A`, `State_B`, `State_C`, `Transition_1`, `Transition_2`, `Transition_3`, `Event_0`, `Event_1`, `Guard_1`, `Guard_2`, `param_x : Real`, `param_y : Integer`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous bump arena storage.

  Let $`\mathcal{S}_{\text{states}} \subset \mathcal{V}_{\text{AST}}`$` denote the finite set of state vertices within enclosing state machine `$`M`$`, and let `$`\mathcal{T} \subset \mathcal{V}_{\text{AST}}`$ denote the finite set of lowered transitions.

  Each lowered transition $`t \in \mathcal{T}`$ is formalized as an 8-tuple:

```math
  t = \langle \text{id}_t, s_{\text{src}}(t), s_{\text{tgt}}(t), e_{\text{trigger}}(t), g_{\text{guard}}(t), a_{\text{effect}}(t), \Delta_t, \text{span}_t \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_t &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  s_{\text{src}}(t), s_{\text{tgt}}(t) &\in \mathcal{S}_{\text{states}} \quad (\text{source and target state handles}) \\
  e_{\text{trigger}}(t) &\in \mathcal{E}_{\text{event}} \cup \{ \epsilon \} \quad (\text{event trigger symbol or completion sentinel } \epsilon) \\
  g_{\text{guard}}(t) &\in \mathcal{G}_{\text{expr}} \cup \{ \bot_{\text{none}} \} \quad (\text{optional Boolean guard expression}) \\
  a_{\text{effect}}(t) &\in \mathcal{A}_{\text{action}} \cup \{ \emptyset \} \quad (\text{optional transition effect action}) \\
  \Delta_t &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_t &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
  \end{aligned}
```

  Outgoing Transition Set & Trigger Equivalence Partitioning:

```math
  \mathcal{T}_{\text{out}}(s) = \{ t \in \mathcal{T} \mid s_{\text{src}}(t) = s \}
```

```math
  \mathcal{T}_{\text{out}}(s) = \bigcup_{e \in \mathcal{E}(s)} \mathcal{T}_{s, e}, \quad \text{where } \mathcal{T}_{s, e} = \{ t \in \mathcal{T}_{\text{out}}(s) \mid e_{\text{trigger}}(t) = e \}
```

```math
  \forall e_1, e_2 \in \mathcal{E}(s), \quad e_1 \ne e_2 \implies \mathcal{T}_{s, e_1} \cap \mathcal{T}_{s, e_2} = \emptyset
```

  Canonical Guard Predicate Normalization:

```math
  \overline{G}(t) = \begin{cases}
  g_{\text{guard}}(t) & \text{if } g_{\text{guard}}(t) \ne \bot_{\text{none}} \\
  \text{true} & \text{if } g_{\text{guard}}(t) = \bot_{\text{none}}
  \end{cases}
```

  Deterministic Guard Disjointness Invariant:

```math
  \forall s \in \mathcal{S}_{\text{states}}, \; \forall e \in \mathcal{E}(s), \; \forall t_1, t_2 \in \mathcal{T}_{s, e}, \quad t_1 \ne t_2 \implies \text{UNSAT}(\overline{G}(t_1) \land \overline{G}(t_2))
```

  Satisfiability and Counterexample Witness Formulation:

```math
  \text{UNSAT}(G_1 \land G_2) \iff \neg \exists \mathbf{x} \in \mathcal{X} \text{ such that } (G_1(\mathbf{x}) = \text{true} \land G_2(\mathbf{x}) = \text{true})
```

```math
  \text{SAT}(G_1 \land G_2) \iff \exists \mathbf{x}_{\text{cex}} \in \mathcal{X} \text{ such that } (G_1(\mathbf{x}_{\text{cex}}) = \text{true} \land G_2(\mathbf{x}_{\text{cex}}) = \text{true})
```

  Syntactic Theory Admissibility Invariant (NP-8 / REQ-0197):

```math
  \text{Admissible}(G) \iff \text{Theory}(G) \in \{ \text{PROP}, \text{QF\_LRA}, \text{QF\_LIA}, \text{QF\_UF} \} \land \text{Quantifiers}(G) = \emptyset
```

  DPLL(T) Decision Procedure & Step Budget Invariant:

```math
  \text{SMTSolve}(\phi, \kappa_{\text{guard}}) \longrightarrow \{ \text{UNSAT}(\Pi_{\text{proof}}), \text{SAT}(\mathbf{x}_{\text{cex}}), \text{Timeout}(\kappa_{\text{guard}}) \}
```

```math
  N_{\text{step}} = \text{Steps}(\text{SMTSolve}(\phi)) \le \kappa_{\text{guard}}
```

  Deterministic Diagnostic Emission Invariant (REQ-0191):

```math
  \begin{aligned}
  \exists t_1, t_2 \in \mathcal{T}_{s, e}, t_1 \ne t_2 \land \text{SAT}(\overline{G}(t_1) \land \overline{G}(t_2)) &\implies \text{Diagnostic}(\langle t_1, t_2 \rangle, \text{DiagnosticCode::E0400}, \text{NonDisjointTransitionGuards}) \in \mathcal{D}_{\text{sink}} \\
  \exists t \in \mathcal{T} : \neg \text{Admissible}(g_{\text{guard}}(t)) &\implies \text{Diagnostic}(t, \text{DiagnosticCode::E0406}, \text{NonAdmissibleGuardTheory}) \in \mathcal{D}_{\text{sink}} \\
  N_{\text{step}} \gt \kappa_{\text{guard}} &\implies \text{Diagnostic}(\langle t_1, t_2 \rangle, \text{DiagnosticCode::E0406}, \text{GuardSolverStepLimitExceeded}) \in \mathcal{D}_{\text{sink}} \\
  \tau(g_{\text{guard}}(t)) \not\equiv \text{Boolean} &\implies \text{Diagnostic}(t, \text{DiagnosticCode::E0202}, \text{InvalidGuardType}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
  \forall t \in \mathcal{T}, \quad \Delta_t = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(t))
```

#### 3. Computational Complexity & Algorithmic Bounds

Deciding transition guard disjointness ($`\text{UNSAT}(G_1 \land G_2)`$`) over arbitrary quantifier-free first-order logic formulas resides in **Complexity Class co-NP-complete** (the complement of satisfiability in **Complexity Class NP-complete** per Algorithmic Bound **NP-8**, REQ-0197). For single-variable interval inequality constraints, the fast-path pre-filter resides in **Complexity Class P** (constant time `$`O(1)`$).

  **Mathematical Delineation & Algorithmic Bounds (NP-8)**:
  1. *Complexity Class Partitioning*:
     - Deciding satisfiability of propositional formulas (`PROP`) or quantifier-free linear integer arithmetic formulas (`QF_LIA`) is NP-complete. Consequently, deciding mutual exclusion (validity of $`\neg(G_1 \land G_2)`$`, equivalent to `$`\text{UNSAT}(G_1 \land G_2)`$) is co-NP-complete.
     - For quantifier-free linear real arithmetic (`QF_LRA`), satisfiability of conjunctions of linear inequalities is solvable in polynomial time via linear programming (Khachiyan / Karmarkar algorithms), but general disjunctive boolean combinations remain NP-complete (co-NP-complete for unsatisfiability).
     - Non-linear arithmetic fragments are undecidable or in PSPACE; hence, the compiler enforces strict syntactic theory admissibility via REQ-0197, rejecting non-linear expressions with diagnostic `E0406`.
  2. *Transition Partitioning Complexity*:
     Partitioning $`E = |\mathcal{T}|`$` transitions into trigger equivalence classes `$`\mathcal{T}_{s, e}`$` across `$`V = |\mathcal{S}_{\text{states}}|`$ states via interned symbol handles executes in deterministic linear time:

```math
     T_{\text{partition}}(V, E) \in O(V + E)
```

  3. *Pairwise Verification Count*:
     For each state vertex $`s`$` and trigger event `$`e`$, the number of pairwise guard comparisons is given by:

```math
     M_{\text{pairs}} = \sum_{s \in \mathcal{S}_{\text{states}}} \sum_{e \in \mathcal{E}(s)} \binom{|\mathcal{T}_{s, e}|}{2} = \sum_{s \in \mathcal{S}_{\text{states}}} \sum_{e \in \mathcal{E}(s)} \frac{|\mathcal{T}_{s, e}| (|\mathcal{T}_{s, e}| - 1)}{2}
```

     In well-formed MBSE state machines, the branching factor per trigger is small ($`|\mathcal{T}_{s, e}| \le K_{\text{branch}} \le 8`$`), ensuring `$`\binom{|\mathcal{T}_{s, e}|}{2} \le 28 \in O(1)`$`. Across the entire state machine, the total number of verified pairs satisfies `$`M_{\text{pairs}} \le \frac{K_{\text{branch}} - 1}{2} E \in O(E)`$.
  4. *Fast-Path Interval Check Complexity*:
     For 1D single-variable interval inequalities, testing whether $`[a_1, b_1] \cap [a_2, b_2] = \emptyset`$ involves at most 2 scalar comparisons:

```math
     T_{\text{fast\_check}}(t_1, t_2) \in O(1)
```

  5. *Syntactic Admissibility Check*:
     Validating that a guard expression of size $`|G|`$ contains no non-linear terms or quantifiers traverses the expression AST in linear time:

```math
     T_{\text{admiss}}(|G|) \in O(|G|)
```

  6. *Bounded SMT Decision Procedure under Step Cutoff $`\kappa_{\text{guard}}`$*:
     For guard pairs requiring SMT solving, the DPLL(T) solver execution cost is strictly capped by the operational step cutoff $`\kappa_{\text{guard}} \le 100{,}000`$:

```math
     T_{\text{smt\_pair}}(t_1, t_2) \in O(\kappa_{\text{guard}} \cdot (|G(t_1)| + |G(t_2)|))
```

     Because $`\kappa_{\text{guard}}`$ is an invariant constant, the per-pair worst-case execution is strictly bounded, completely preventing solver divergence or unbounded compilation hangs.
  7. *Aggregate Worst-Case Time Complexity*:
     Combining all evaluation stages, the total sequential compile-time complexity is bounded by:

```math
     T_{\text{total}}(V, E, \kappa_{\text{guard}}) \in O\left( V + E + \sum_{(t_1, t_2) \in \text{Pairs}} \kappa_{\text{guard}} \cdot (|G(t_1)| + |G(t_2)|) \right)
```

  8. *Parallel Work-Stealing Scaling (Directive 2)*:
     When evaluating $`P`$` independent state vertices or decoupled state machines across `$`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool:

```math
     T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{T_{\text{total}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  9. *Space Complexity & Arena Memory Bounds*:
     Allocations for transition tuples, guard expression ASTs, SMT assertion formulas, and counterexample models are maintained in contiguous bump arena storage, requiring $`O(V + E + \sum |G|)`$` bytes. Internal SMT solver trail memory is bounded by `$`O(\kappa_{\text{guard}} \cdot (|G_1| + |G_2|))`$` bytes. The diagnostic sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ capacity.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Package_1`, `StateMachine_Alpha`, `StateMachine_Beta`, `State_Alpha`, `State_Beta`, `State_Gamma`, `State_Root`, `State_A`, `State_B`, `State_C`, `Transition_1`, `Transition_2`, `Transition_3`, `Event_0`, `Event_1`, `Guard_1`, `Guard_2`, `param_x : Real`, `param_y : Integer`) across the following 18 verification gates:

  1. **Canonical Disjoint Guard Conformance Gate**: Declare state `State_A` with two outgoing transitions `Transition_1` (target `State_B`, trigger `Event_0`, guard `param_x < 0.0`) and `Transition_2` (target `State_C`, trigger `Event_0`, guard `param_x >= 0.0`). Assert that the SMT decision procedure proves unsatisfiability of $`(\text{param\_x} \lt 0.0 \land \text{param\_x} \ge 0.0)`$ with zero diagnostics emitted.
  2. **Overlapping Guard Detection Gate (`E0400`)**: Declare state `State_A` with two outgoing transitions sharing trigger `Event_0` with overlapping guards: `param_x <= 10.0` and `param_x >= 5.0`. Assert deterministic compile-time rejection with diagnostic error code `E0400` (`NonDisjointTransitionGuards`), verifying that the emitted diagnostic contains a valid counterexample witness valuation (e.g., $`\text{param\_x} = 7.5`$) and points to the exact byte spans of both transitions.
  3. **Sibling Multi-Transition Pairwise Disjointness Gate**: Declare state `State_A` with three outgoing transitions on trigger `Event_0` partitioned into three disjoint ranges: `param_x < 0.0`, `param_x >= 0.0 && param_x < 10.0`, and `param_x >= 10.0`. Assert that all $`\binom{3}{2} = 3`$ pairwise checks succeed and compile with zero diagnostics.
  4. **Pairwise Conflict Isolation Gate (`E0400`)**: Declare state `State_A` with three outgoing transitions on trigger `Event_0` where pairs $`(t_1, t_2)`$` and `$`(t_1, t_3)`$` are disjoint, but pair `$`(t_2, t_3)`$` overlaps. Assert that the verification engine isolates the exact conflicting pair `$`(t_2, t_3)`$ and emits diagnostic error code `E0400` targeting precisely `Transition_2` and `Transition_3`.
  5. **Omitted Guard Implicit True Overlap Gate (`E0400`)**: Declare two transitions on trigger `Event_0` where `Transition_1` specifies guard `param_x > 0.0` and `Transition_2` omits the guard clause. Assert that the compiler normalizes the omitted guard to $`\overline{G} \equiv \text{true}`$`, detects overlap at `$`\text{param\_x} = 1.0`$, and deterministically emits diagnostic error code `E0400` (`NonDisjointTransitionGuards`).
  6. **Dual Omitted Guard Conflict Gate (`E0400`)**: Declare two sibling transitions on trigger `Event_0` where both transitions omit guard clauses. Assert that both guards normalize to $`\text{true}`$, triggering an immediate deterministic compile-time rejection with diagnostic error code `E0400` (`NonDisjointTransitionGuards`).
  7. **Independent Distinct Event Trigger Gate**: Declare state `State_A` with two transitions having identical guard `param_x >= 0.0`, but distinct triggers `Event_0` and `Event_1`. Assert that the transitions belong to separate trigger equivalence classes ($`\mathcal{T}_{s, \text{Event\_0}} \cap \mathcal{T}_{s, \text{Event\_1}} = \emptyset`$), requiring zero disjointness checks and emitting zero diagnostics.
  8. **Completion Transition (Triggerless) Disjointness Gate**: Declare state `State_A` with two triggerless completion transitions ($`e = \epsilon`$) having guards `param_x < 5.0` and `param_x >= 5.0`. Assert that completion transitions are grouped into $`\mathcal{T}_{s, \epsilon}`$, verified for disjointness, and accepted with zero diagnostics.
  9. **Fast-Path Interval Arithmetic Pre-Filter Gate**: Declare two transitions with single-variable linear bounds `param_x in [0.0, 4.0]` and `param_x in [5.0, 10.0]`. Verify that the fast-path interval pre-filter certifies disjointness in $`O(1)`$ constant time without invoking the DPLL(T) SMT solver engine.
  10. **Counterexample Witness Extraction Gate (`E0400`)**: Ingest overlapping guards `param_x + param_y == 10` and `param_x - param_y == 0` over integer variables. Assert that the SMT solver proves satisfiability and synthesizes the exact counterexample valuation $`\mathbf{x}_{\text{cex}} = \{ \text{param\_x} \mapsto 5, \text{param\_y} \mapsto 5 \}`$ within the structured diagnostic payload.
  11. **Non-Linear Arithmetic Rejection Gate (`E0406`)**: Declare a transition guard containing non-linear term `param_x * param_y > 1.0`. Assert that the syntactic admissibility gate rejects the expression prior to solver invocation, emitting diagnostic error code `E0406` (`NonAdmissibleGuardTheory`).
  12. **Alternating Quantifier Rejection Gate (`E0406`)**: Declare a transition guard expression containing an explicit first-order quantifier `exists y : Real (y > param_x)`. Assert deterministic compile-time rejection with diagnostic error code `E0406` (`NonAdmissibleGuardTheory`).
  13. **SMT Step Budget Cutoff Enforcement Gate (`E0406`)**: Ingest a synthetic combinatorial guard formula configured under a restricted test budget $`\kappa_{\text{guard}} = 20`$. Assert that when solver operations reach the cutoff without a conclusive SAT or UNSAT result, compilation aborts deterministically with diagnostic error code `E0406` (`GuardSolverStepLimitExceeded`).
  14. **Non-Boolean Guard Type Conformance Gate (`E0202`)**: Declare a transition with guard expression `param_x + 1.0` evaluating to scalar `Real`. Assert deterministic compile-time rejection with diagnostic error code `E0202` (`InvalidGuardType`).
  15. **Hierarchical Depth Precedence Bypass Gate**: Ingest composite state `CompositeState_1` containing child state `State_Sub_1`. Declare transition $`t_{\text{child}}`$ exiting `State_Sub_1` and transition $`t_{\text{parent}}`$ exiting `CompositeState_1` on identical trigger `Event_0` with identical guards `param_x > 0.0`.
