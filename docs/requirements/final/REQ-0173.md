### REQ-0173: Use Cases Projection: Alternate Flows & Exception Handler Branching

#### 1. Normative Statement

The downstream specification projection engine, Use Case synthesizer, and behavioral flow validator of Subsystem 9 shall extract, formalize, and project Alternate Flows and Exception Flows branching from specific primary flow step indices for every Use Case specification synthesized from the compilation unit abstract syntax tree (AST). For each generated Use Case modeling an end-to-end operational sequence derived from AST interaction definitions and activity models (REQ-0172), the projection engine shall deterministically synthesize all operational contingency branches, alternative execution sequences, communication loss handlers, observation interface anomaly handlers, and safety-critical exception branches.

  Every branch descriptor must explicitly anchor to a valid 1-indexed primary flow step index $`k`$` satisfying `$`1 \le k \le \text{Length}(\text{PrimaryFlow})`$`. If any branch specifies an invalid branch point (`$`k \lt 1`$` or `$`k \gt \text{Length}(\text{PrimaryFlow})`$), the compiler shall fail closed and emit diagnostic error code `E0232` (`InvalidUseCaseBranchPointViolation`).

  The compiler shall formally distinguish and enforce distinct structural invariants across two disjoint branch classifications:
  1. **Alternate Flows**: Provide alternative operational trajectories to achieve nominal operational goals or partial mission objectives under benign operational variations. An alternate flow shall either rejoin the primary flow at a subsequent step index $`j \gt k`$`, or conclude at a verified alternative nominal postcondition state (`$`s_{\text{terminal}} \in S_{\text{nominal\_term}}`$`). Rejoining at an earlier or identical step index (`$`j \le k`$`) or targeting a non-existent step index (`$`j \gt \text{Length}(\text{PrimaryFlow}) + 1`$) without explicit iteration constructs shall cause the compiler to fail closed and emit diagnostic error code `E0232` (`InvalidAlternateRejoinTargetViolation`).
  2. **Exception Flows**: Provide deterministic anomaly mitigation trajectories to handle operational contingencies, communication losses, observation interface anomalies, sensor or actuator faults, and external hazard triggers. Every exception flow branch must terminate in a verified failsafe state $`s_{\text{terminal}} \in S_{\text{failsafe}} \subseteq S_{\text{states}}`$`. If an exception branch terminates in an undefined state, an unverified state, or any active operational state outside the formal failsafe state set `$`S_{\text{failsafe}}`$, the compiler shall fail closed and emit diagnostic error code `E0232` (`NonFailsafeExceptionTerminationViolation`).

  Specifically, the downstream Use Case projection engine, scenario synthesizer, and behavioral flow validator shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Use Case Scope & Flow Model Extraction**:
     - The projection engine shall scan the compilation unit AST for all interaction definitions (KerML `Interaction`, REQ-0059), action usages (`ActionUsage`, REQ-0069), behavioral statecharts (`state def`, REQ-0079), transition usages (`transition`, REQ-0080), and hazard scenarios (REQ-0135, REQ-0137).
     - For every projected Use Case entity $`U`$`, the engine shall establish a single canonical Primary Flow sequence `$`P = \langle s_1, s_2, \dots, s_n \rangle`$` where each step `$`s_i`$ corresponds to an AST action invocation, state transition, or inter-actor message transfer conforming to REQ-0172.
     - For every decision junction, conditional branch, guard condition, error transition, or safety fallback declared along the primary path, the engine shall synthesize a corresponding branch descriptor $`B \in \mathcal{B}_U`$.
  2. **Mandatory Branch Contract Schema**:
     - Every branch descriptor $`B \in \mathcal{B}_U`$ shall be formalized as a 9-tuple:

```math
       B = \langle \text{id}_B, \text{name}_B, \kappa_{\text{branch}}(B), k_B, \phi_{\text{cond}}(B), \mathbf{b}_B, s_{\text{term}}(B), j_{\text{rejoin}}(B), \Delta_B \rangle
```

     - The branch kind $`\kappa_{\text{branch}}(B) \in \{ \text{Alternate}, \text{Exception} \}`$ defines the semantic classification of the branch.
     - The branch anchor index $`k_B \in \mathbb{N}^+`$ identifies the exact step in the primary flow from which execution diverges.
     - The branch condition $`\phi_{\text{cond}}(B)`$ defines a deterministic boolean guard expression evaluated over domain attributes and interface observations.
     - The branch step sequence $`\mathbf{b}_B = \langle b_1, \dots, b_m \rangle`$` with `$`m \ge 1`$ defines the ordered sequence of action steps executed within the branch.
     - The terminal state $`s_{\text{term}}(B)`$ defines the concluding system state upon branch execution completion.
     - The rejoin index $`j_{\text{rejoin}}(B) \in \mathbb{N}^+ \cup \{ \bot \}`$` defines the target step index in the primary flow where execution resumes, or null (`$`\bot`$) if the branch terminates without rejoining.
     - The document anchor $`\Delta_B \in \{0, 1\}^{128}`$ provides an immutable deterministic RFC 4122 UUIDv5 identifier.
  3. **Branch Point Step Index Verification ($`1 \le k \le n`$)**:
     - The compiler shall statically verify that every branch anchor index $`k_B`$` lies within the valid closed interval `$`[1, n]`$`, where `$`n = \text{Length}(P)`$ is the total step count of the primary flow.
     - Branch anchors specifying $`k_B = 0`$`, negative indices, or indices strictly greater than `$`n`$` (`$`k_B \gt n`$) shall trigger fatal diagnostic error code `E0232` (`InvalidUseCaseBranchPointViolation`).
  4. **Failsafe State Set Verification & Attestation ($`s_{\text{term}} \in S_{\text{failsafe}}`$)**:
     - For every exception branch ($`\kappa_{\text{branch}}(B) = \text{Exception}`$`), the compiler shall verify that the terminal state `$`s_{\text{term}}(B)`$` belongs to the set of verified failsafe states `$`S_{\text{failsafe}} \subseteq S_{\text{states}}`$ defined in the system statechart (REQ-0079, REQ-0125).
     - Failsafe states must represent verified quiescent, safe-stop, emergency-shutdown, isolated, or degraded operational modes that guarantee hazard mitigation per the STPA safety constraints (REQ-0137) and Run-Time Assurance policies (REQ-0141).
     - Any exception flow terminating in a non-failsafe state, a transitional state, or null ($`\bot`$) shall trigger fatal diagnostic error code `E0232` (`NonFailsafeExceptionTerminationViolation`).
     - Exception flows must never specify a rejoin step ($`j_{\text{rejoin}}(B) = \bot`$). An exception branch declaring a non-null rejoin step shall trigger diagnostic error code `E0232` (`InvalidExceptionRejoinViolation`).
  5. **Alternate Flow Forward Progress & Rejoin Contracts**:
     - For every alternate flow ($`\kappa_{\text{branch}}(B) = \text{Alternate}`$), the flow must either:
       a. Rejoin the primary flow at a target step index $`j_{\text{rejoin}}`$` strictly greater than the branch anchor (`$`j_{\text{rejoin}} \gt k_B`$), guaranteeing forward progress; or
       b. Terminate at an alternative nominal postcondition state ($`s_{\text{term}} \in S_{\text{nominal\_term}}`$) satisfying the Use Case completion criteria.
     - Backward rejoin targets ($`j_{\text{rejoin}} \le k_B`$) that induce uncontrolled infinite looping shall be rejected with diagnostic error code `E0232` (`InvalidAlternateRejoinTargetViolation`).
     - Rejoin targets exceeding the terminal step index plus one ($`j_{\text{rejoin}} \gt n + 1`$) shall be rejected with diagnostic error code `E0232` (`InvalidAlternateRejoinTargetViolation`).
  6. **Branch Step Sequence Specification & Sub-Step Monotonicity**:
     - Every branch must declare at least one discrete action step ($`m = |\mathbf{b}_B| \ge 1`$`). An empty branch step sequence (`$`m = 0`$) shall trigger fatal diagnostic error code `E0232` (`EmptyBranchSequenceViolation`).
     - Each branch sub-step $`b_l`$` (`$`l \in \{1, \dots, m\}`$) shall specify an initiating actor, an action signature, a target entity, and a resulting state delta.
     - Sub-steps within a branch diverging from primary step $`k`$` shall be indexed monotonically using canonical hierarchical numbering: `$`k.\text{a}.1, k.\text{a}.2, \dots, k.\text{a}.m`$` for alternate flows, and `$`k.\text{e}.1, k.\text{e}.2, \dots, k.\text{e}.m`$ for exception flows.
  7. **Deterministic Branch Condition Disjointness**:
     - All branch condition expressions $`\phi_{\text{cond}}(B)`$ shall be parsed into structured `ConstraintExpr` AST nodes (REQ-0138).
     - Condition expressions must type-check strictly to boolean type (`Boolean`). Non-boolean conditions shall trigger diagnostic error code `E0232` (`MalformedBranchConditionViolation`).
     - If multiple branches diverge from the identical primary step $`k`$` under the identical branch kind, their branch conditions must be pairwise mutually disjoint (`$`\phi_1 \land \phi_2 \equiv \text{false}`$) to prevent non-deterministic branching in accordance with REQ-0122. Satisfiable condition overlap shall trigger diagnostic error code `E0232` (`NonDeterministicBranchOverlapViolation`).
  8. **Grounding & Anti-Placeholder Invariant**:
     - All branch names, conditions, sub-step descriptions, actor handles, and terminal state identifiers must be grounded and concrete.
     - Banned placeholder tokens (`TODO`, `TBD`, `TBC`, `FIXME`, `PLACEHOLDER`, `<placeholder>`, `N/A`, `???`, `null`, `undefined`) are strictly prohibited in branch definitions. The presence of any banned placeholder token triggers fatal diagnostic error code `E0232` (`PlaceholderInBranchViolation`).
  9. **Deterministic Tabular Markdown Emission**:
     - Use Case projections shall emit canonical Markdown specification tables summarizing all alternate and exception flows.
     - Table columns shall provide: `Branch ID`, `Branch Kind`, `Branch Point Step`, `Branch Condition`, `Terminal State / Rejoin`, `Failsafe Attestation`.
     - Table rows shall be ordered deterministically by primary step anchor index $`k`$, followed by branch kind (`Alternate` before `Exception`), followed by interned branch identifier ($`\prec_{\text{canon}}`$, REQ-0032).
     - In accordance with Charter Invariant 3, Markdown table cells must never contain `$` math delimiters (using plain text, e.g., `Step 3`, `Alternate`, `Exception`, `State_Failsafe_0`, `True`).
     - In accordance with Charter Invariant 4, emitted Markdown tables and prose must use ASCII `--` or `-` exclusively, with zero Unicode em dashes.
  10. **Contiguous Bump Arena Storage & Node Handles**:
      - All synthesized Use Case descriptors, primary flow steps, branch records, condition expressions, sub-step sequences, and verification witnesses shall be allocated sequentially in contiguous typed bump arena storage (REQ-0009, REQ-0034), referenced by stable 32-bit arena node handles (REQ-0035).
  11. **Enforcement of the 5 Executive Architectural Directives**:
      - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized Use Case, primary flow step, alternate flow, exception flow, branch sub-step, and verification witness shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs (UUIDv1, UUIDv6, UUIDv7) and pseudo-random UUIDs (UUIDv4) are strictly banned across all compiler passes.
      - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel extraction, branch validation, and Markdown table projection across independent Use Cases shall execute strictly on a centralized, bounded work-stealing thread pool with worker upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
      - *Directive 3 (String Interner Memory Allocation Exception)*: Branch identifiers, condition expression strings, state labels, actor names, and sub-step descriptions shall be interned into the deduplicated global symbol interner pool during lexical analysis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
      - *Directive 4 (Synchronization Token Error Recovery)*: The Use Case projection engine shall implement synchronization token error recovery on Use Case section delimiters (`###`), statement delimiters (`;`, `}`), and table row delimiters (`|`) in accordance with REQ-0013 and REQ-0016. When branch validation violations (`E0232`) occur, the engine shall record structured diagnostics into the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{branch}}`$`), and continue validating subsequent branches and Use Cases. If accumulated diagnostics reach capacity limit `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
      - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The Use Case projection engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency (strictly under 25 ms for an architectural model containing $`10^4`$ branch elements across projected Use Cases) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  12. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Actor_0`, `Actor_1`, `UseCase_0`, `UseCase_1`, `Flow_Primary`, `Flow_Alt_0`, `Flow_Except_0`, `Step_0`, `Step_1`, `State_0`, `State_1`, `State_Failsafe_0`, `State_Failsafe_1`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage, and let `$`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.

  Let $`\text{OID}_{\text{DEAP}} \in \{0, 1\}^{128}`$ denote the fixed 128-bit RFC 4122 namespace UUID constant in canonical big-endian network byte order.

  Let $`\mathcal{U}_{\text{proj}} \subset \mathcal{V}_{\text{AST}}`$ denote the finite set of Use Cases projected by Subsystem 9.
  For each Use Case $`U \in \mathcal{U}_{\text{proj}}`$, its specification model is formalized as a 9-tuple:

```math
  U = \langle \text{id}_U, \text{name}_U, \text{Actors}_U, \text{Pre}_U, P_U, \mathcal{B}_U, \text{Post}_U, \Delta_U, \text{span}_U \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_U &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_U &\in \mathcal{S}_{\text{intern}} \quad (\text{interned Use Case symbol identifier}) \\
  \text{Actors}_U &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of participating actor handles}) \\
  \text{Pre}_U &\subset \mathcal{V}_{\text{AST}} \quad (\text{set of formal precondition expression handles}) \\
  P_U &= \langle s_1, s_2, \dots, s_n \rangle \quad (\text{ordered sequence of primary flow steps, } n \ge 1) \\
  \mathcal{B}_U &= \{ B_1, B_2, \dots, B_p \} \quad (\text{finite set of alternate and exception branch descriptors}) \\
  \text{Post}_U &\subset \mathcal{V}_{\text{AST}} \quad (\text{set of formal postcondition expression handles}) \\
  \Delta_U &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_U &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
```

  Each primary flow step $`s_i \in P_U`$` (`$`i \in \{1, \dots, n\}`$) is formalized as a 7-tuple:

```math
  s_i = \langle i, a_{\text{init}}(s_i), \sigma_{\text{act}}(s_i), e_{\text{target}}(s_i), \delta_{\text{state}}(s_i), \Delta_{s_i}, \text{span}_{s_i} \rangle
```

  where $`i = \text{StepIndex}(s_i)`$`, `$`a_{\text{init}}(s_i) \in \text{Actors}_U`$`, `$`\sigma_{\text{act}}(s_i) \in \mathcal{V}_{\text{AST}}`$` is the action signature, `$`e_{\text{target}}(s_i) \in \mathcal{V}_{\text{AST}}`$` is the target entity, `$`\delta_{\text{state}}(s_i)`$` is the state delta, and `$`\Delta_{s_i} \in \{0, 1\}^{128}`$ is the deterministic UUIDv5 anchor.

  Each branch descriptor $`B \in \mathcal{B}_U`$ is formalized as a 10-tuple:

```math
  B = \langle \text{id}_B, \text{name}_B, \kappa_{\text{branch}}(B), k_B, \phi_{\text{cond}}(B), \mathbf{b}_B, s_{\text{term}}(B), j_{\text{rejoin}}(B), \Delta_B, \text{span}_B \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_B &\in \mathbb{N}_{32} \quad (\text{contiguous arena branch handle}) \\
  \text{name}_B &\in \mathcal{S}_{\text{intern}} \quad (\text{interned branch symbol identifier}) \\
  \kappa_{\text{branch}}(B) &\in \{ \text{Alternate}, \text{Exception} \} \quad (\text{branch semantic classification}) \\
  k_B &\in \mathbb{N}^+ \quad (\text{1-indexed primary flow branch anchor step}) \\
  \phi_{\text{cond}}(B) &\in \mathcal{V}_{\text{AST}} \quad (\text{deterministic boolean guard condition handle}) \\
  \mathbf{b}_B &= \langle b_1, b_2, \dots, b_m \rangle \quad (\text{ordered sequence of branch sub-steps, } m \ge 1) \\
  s_{\text{term}}(B) &\in \mathcal{V}_{\text{AST}} \cup \{ \bot \} \quad (\text{terminal state classifier handle or null}) \\
  j_{\text{rejoin}}(B) &\in \mathbb{N}^+ \cup \{ \bot \} \quad (\text{primary flow rejoin step index or null}) \\
  \Delta_B &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_B &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
```

  Each branch sub-step $`b_l \in \mathbf{b}_B`$` (`$`l \in \{1, \dots, m\}`$) is formalized as a 6-tuple:

```math
  b_l = \langle l, a_{\text{init}}(b_l), \sigma_{\text{act}}(b_l), e_{\text{target}}(b_l), \Delta_{b_l}, \text{span}_{b_l} \rangle
```

  where $`l = \text{SubStepIndex}(b_l)`$` satisfies `$`1 \le l \le m`$.

  1. Branch Point Step Index Validity Invariant:
  Every branch anchor index $`k_B`$ must reference a valid step in the primary flow sequence:

```math
  \forall U \in \mathcal{U}_{\text{proj}}, \quad \forall B \in \mathcal{B}_U, \quad 1 \le k_B \le \text{Length}(P_U)
```

  2. Exception Flow Failsafe Termination Invariant:
  Every exception branch must terminate in a verified failsafe state belonging to the system failsafe state roster, with zero primary flow rejoin:

```math
  \forall B \in \mathcal{B}_U \text{ s.t. } \kappa_{\text{branch}}(B) = \text{Exception}, \quad s_{\text{term}}(B) \in S_{\text{failsafe}} \subseteq S_{\text{states}}(U) \quad \wedge \quad j_{\text{rejoin}}(B) = \bot
```

  where:

```math
  S_{\text{failsafe}} = \{ s \in S_{\text{states}}(U) \mid \text{IsVerifiedFailsafe}(s) \equiv \text{true} \}
```

  3. Alternate Flow Forward Progress & Rejoin Contract Invariant:
  Every alternate branch must either rejoin the primary flow strictly forward of the branch anchor point, or terminate in a valid nominal completion state:

```math
  \forall B \in \mathcal{B}_U \text{ s.t. } \kappa_{\text{branch}}(B) = \text{Alternate}, \quad (j_{\text{rejoin}}(B) \in \{ k_B + 1, \dots, \text{Length}(P_U) + 1 \}) \lor (s_{\text{term}}(B) \in S_{\text{nominal\_term}})
```

  4. Branch Sub-Step Non-Emptiness & Monotonicity Invariant:
  Every branch step sequence must contain at least one step and maintain strict contiguous indexing:

```math
  \forall B \in \mathcal{B}_U, \quad |\mathbf{b}_B| = m \ge 1 \quad \wedge \quad \forall l \in \{1, \dots, m\}, \, \text{SubStepIndex}(b_l) = l
```

  5. Deterministic Branch Condition Disjointness Invariant:
  Concurrent branches diverging from the identical primary step under the identical branch kind must have mutually disjoint guard expressions:

```math
  \forall B_1, B_2 \in \mathcal{B}_U \text{ s.t. } B_1 \ne B_2 \land \kappa_{\text{branch}}(B_1) = \kappa_{\text{branch}}(B_2) \land k_{B_1} = k_{B_2}, \quad \phi_{\text{cond}}(B_1) \land \phi_{\text{cond}}(B_2) \equiv \text{false}
```

  and every condition must type-check to boolean type:

```math
  \forall B \in \mathcal{B}_U, \quad \text{Type}(\phi_{\text{cond}}(B)) = \tau_{\text{bool}} \land \text{IsSideEffectFree}(\phi_{\text{cond}}(B)) \equiv \text{true}
```

  6. Grounding & Anti-Placeholder Invariant:
  All symbols, condition expressions, step descriptions, and state identifiers within branch descriptors must be free of banned placeholder tokens:

```math
  \forall w \in \text{Tokens}(B), \quad \text{UpperCase}(w) \notin \Sigma_{\text{banned}}
```

  where:

```math
  \Sigma_{\text{banned}} = \{ \text{"TODO"}, \text{"TBD"}, \text{"TBC"}, \text{"FIXME"}, \text{"PLACEHOLDER"}, \text{"<placeholder>"}, \text{"N/A"}, \text{"???"}, \text{"null"}, \text{"undefined"} \}
```

  7. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):
  Every Use Case, branch descriptor, sub-step node, and verification witness shall bind an immutable RFC 4122 UUIDv5 identifier:

```math
  \begin{aligned}
  \Delta_U &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U)) \\
  \Delta_B &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U) \mathbin{\Vert} \text{"::Branch::"} \mathbin{\Vert} \text{name}_B) \\
  \Delta_{b_l} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U) \mathbin{\Vert} \text{"::Branch::"} \mathbin{\Vert} \text{name}_B \mathbin{\Vert} \text{"::Step::"} \mathbin{\Vert} \text{ToString}(l)) \\
  \Delta_{\text{witness}(U)} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(U) \mathbin{\Vert} \text{"::BranchVerificationWitness"})
  \end{aligned}
```

  8. Deterministic Diagnostic Trigger Rules (REQ-0191):

```math
  \begin{aligned}
  (k_B \lt 1 \lor k_B \gt \text{Length}(P_U)) &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0232}, \text{InvalidUseCaseBranchPointViolation}) \in \mathcal{D}_{\text{sink}} \\
  (\kappa_{\text{branch}}(B) = \text{Exception} \land s_{\text{term}}(B) \notin S_{\text{failsafe}}) &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0232}, \text{NonFailsafeExceptionTerminationViolation}) \in \mathcal{D}_{\text{sink}} \\
  (\kappa_{\text{branch}}(B) = \text{Exception} \land j_{\text{rejoin}}(B) \ne \bot) &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0232}, \text{InvalidExceptionRejoinViolation}) \in \mathcal{D}_{\text{sink}} \\
  (\kappa_{\text{branch}}(B) = \text{Alternate} \land j_{\text{rejoin}}(B) \ne \bot \land (j_{\text{rejoin}}(B) \le k_B \lor j_{\text{rejoin}}(B) \gt \text{Length}(P_U) + 1)) &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0232}, \text{InvalidAlternateRejoinTargetViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathbf{b}_B| = 0 &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0232}, \text{EmptyBranchSequenceViolation}) \in \mathcal{D}_{\text{sink}} \\
  \text{Type}(\phi_{\text{cond}}(B)) \ne \tau_{\text{bool}} &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0232}, \text{MalformedBranchConditionViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists B_1 \ne B_2 : k_{B_1} = k_{B_2} \land \kappa_{\text{branch}}(B_1) = \kappa_{\text{branch}}(B_2) \land \text{SAT}(\phi_1 \land \phi_2) &\implies \text{Diagnostic}(B_1, \text{DiagnosticCode::E0232}, \text{NonDeterministicBranchOverlapViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists w \in \text{Tokens}(B) : \text{UpperCase}(w) \in \Sigma_{\text{banned}} &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0232}, \text{PlaceholderInBranchViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

Use Cases Projection: Alternate Flows & Exception Handler Branching resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in strictly deterministic linear time $`O(|B_{\text{branches}}| + |S_{\text{steps}}|)`$` per Use Case `$`U`$`, and `$`O(|\mathcal{V}_{\text{AST}}|)`$` across the entire compilation unit, where `$`|B_{\text{branches}}| = |\mathcal{B}_U|`$` is the total number of alternate and exception branches and `$`|S_{\text{steps}}| = \sum_{B \in \mathcal{B}_U} |\mathbf{b}_B|`$ is the aggregate branch sub-step count.

  **Mathematical Delineation from the 8 NP-Completeness Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 resolves qualitative temporal interval consistency over occurrence lifecycles using Allen's 13 qualitative interval relations via ORD-Horn SMT difference logic in $`O(N^3)`$` polynomial time. In contrast, REQ-0173 evaluates static discrete step indices (`$`1 \le k_B \le n`$`) and verifies terminal state set containment (`$`s_{\text{term}} \in S_{\text{failsafe}}`$`) in strictly deterministic `$`O(1)`$ operations per branch without temporal interval constraint propagation.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses strongly NP-hard vector bin packing for structural allocation and interconnect channel multiplexing. In contrast, REQ-0173 projects branching operational narratives from AST interaction graphs without multidimensional knapsack packing or channel bandwidth optimization.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 formalizes subtyping lattice redefinition and multiple inheritance resolution via monotonic C3 linearization in $`O(V + E)`$ time. In contrast, REQ-0173 operates on pre-linearized state and interaction classifiers, performing scalar index comparisons and boolean guard syntax checks.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0173 binds pre-synthesized safety constraints and hazard mitigations to exception branches, verifying that terminal state handles match precomputed elements of $`S_{\text{failsafe}}`$ without set covering.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking). In contrast, REQ-0173 operates at the downstream Use Case projection boundary, formalizing narrative Alternate and Exception flows and verifying local branch point bounds prior to and independent of state space reachability exploration.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks via linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0173 validates discrete operational branch structures without solving continuous Kirchhoff flow networks or complementary inequalities.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs register allocation and basic block scheduling in LUMI IR using Chaitin graph coloring (NP-complete). In contrast, REQ-0173 synthesizes downstream Use Case specification documents within Subsystem 9, decoupled from backend IR registers and basic block instruction schedules.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the satisfiability of first-order invariant contracts via DPLL(T) SMT solvers. In contrast, REQ-0173 evaluates quantifier-free boolean guard expressions and verifies ground set membership in $`O(1)`$ operations per branch without calling external SMT solvers.

  **Asymptotic Complexity Analysis**:
  Let $`N_U = |\mathcal{U}_{\text{proj}}|`$` denote the number of Use Cases, `$`n = \text{Length}(P_U)`$` denote the primary flow step count, `$`N_B = |\mathcal{B}_U|`$` denote the branch descriptor count, and `$`M_B = \sum_{B \in \mathcal{B}_U} |\mathbf{b}_B|`$ denote the aggregate branch sub-step count.
  1. *Branch Point Step Index Validation Phase*:
     - For each branch $`B \in \mathcal{B}_U`$`, validating the inequality `$`1 \le k_B \le n`$ requires exactly two integer comparison operations:

```math
T_{\text{index}}(B) \in O(1), \quad S_{\text{index}}(B) \in O(1)
```

  2. *Terminal State Set Containment Phase*:
     - Testing membership $`s_{\text{term}}(B) \in S_{\text{failsafe}}`$ against a pre-indexed bitset or hash table of arena state handles requires constant time:

```math
T_{\text{terminal}}(B) \in O(1), \quad S_{\text{terminal}}(B) \in O(1)
```

  3. *Alternate Flow Forward Rejoin Evaluation Phase*:
     - For alternate flows declaring rejoin index $`j_{\text{rejoin}}`$`, verifying `$`k_B \lt j_{\text{rejoin}} \le n + 1`$ requires two integer comparisons:

```math
T_{\text{rejoin}}(B) \in O(1), \quad S_{\text{rejoin}}(B) \in O(1)
```

  4. *Branch Sub-Step Sequence Traversal Phase*:
     - Traversing sub-step sequence $`\mathbf{b}_B = \langle b_1, \dots, b_m \rangle`$ to validate actor handles, action signatures, and sub-step indices visits each sub-step exactly once:

```math
T_{\text{steps}}(B) \in O(m), \quad S_{\text{steps}}(B) \in O(1)
```

  5. *Deterministic Symbol Sorting & Table Emission*:
     - Sorting $`N_B`$` branches by primary step anchor `$`k_B`$` and interned symbol identifier requires comparison sort in `$`O(N_B \log N_B)`$ or linear radix sort on 32-bit `SymbolId` tokens in $`O(N_B)`$ time.
     - Emitting canonical Markdown table rows streams directly to the artifact sink in linear time proportional to table row count:

```math
T_{\text{emission}}(N_B) \in O(N_B)
```

  6. *Aggregate Use Case Execution Time*:
     - Summing across all branches and sub-steps for Use Case $`U`$:

```math
T_{\text{total}}(U) = \sum_{B \in \mathcal{B}_U} (T_{\text{index}}(B) + T_{\text{terminal}}(B) + T_{\text{rejoin}}(B) + T_{\text{steps}}(B)) + T_{\text{emission}}(N_B) \in O(N_B + M_B)
```

     - Across the entire compilation unit containing $`N_U`$ Use Cases:

```math
T_{\text{unit}} = \sum_{U \in \mathcal{U}_{\text{proj}}} O(N_B(U) + M_B(U)) \subseteq O(|\mathcal{V}_{\text{AST}}|)
```

  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning independent Use Cases across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool achieves:

```math
T_{\text{parallel}}(N_{\text{total}}, N_{\text{max\_workers}}) \in O\left( \frac{N_{\text{total}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

       guaranteeing thread isolation, data-race freedom, and deterministic bitwise identical outputs.
  8. *Space Complexity & Arena Memory Bounds*:
     - All branch descriptors, sub-step tuples, condition expression trees, and verification witness records reside in contiguous typed bump arena storage. Space consumption is strictly $`O(N_B + M_B) = O(|\mathcal{V}_{\text{AST}}|)`$, requiring zero auxiliary heap allocations outside the preallocated arena.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Actor_0`, `Actor_1`, `UseCase_0`, `UseCase_1`, `Flow_Primary`, `Flow_Alt_0`, `Flow_Except_0`, `Step_0`, `Step_1`, `State_0`, `State_1`, `State_Failsafe_0`, `State_Failsafe_1`, `param_x : Real`) across the following 16 verification gates:

  1. **Canonical Valid Alternate Flow Branch Gate (Pass)**: Ingest synthetic model `Package_0` declaring Use Case `UseCase_0` with 5 primary steps ($`n = 5`$). Configure alternate flow `Flow_Alt_0` branching from step $`k = 2`$`, executing 2 sub-steps, and rejoining at step `$`j = 4`$` (`$`4 \gt 2`$). Verify that branch projection succeeds, validates forward progress, and emits the canonical Markdown table with zero diagnostics emitted.
  2. **Canonical Valid Exception Flow Branch Gate (Pass)**: Ingest synthetic model declaring Use Case `UseCase_0` with primary step $`k = 3`$.   3. **Branch Point Lower Bound Out-of-Bounds Rejection Gate (`E0232`)**: Ingest synthetic model declaring Use Case `UseCase_1` where branch `Flow_Alt_0` specifies branch point index $`k = 0`$` (`$`k \lt 1`$).
