### REQ-0065: KerML Expressions: Expression, Literal, OperatorExpression & Invocations

- **Normative Statement**: The expression lowering engine and semantic type checker of Subsystem 4 shall transform all KerML textual and tabular expressions into an immutable, strongly typed abstract syntax tree (AST) evaluation structure rooted in the KerML `Expression` metaclass. In accordance with the OMG Kernel Modeling Language (KerML) specification, `Expression` shall specialize `Step` (and by extension `Feature`, `Classifier`, and `Type`), formalizing every expression as a computational performance step that yields a typed evaluation result projected through an authoritative `result` output parameter feature ($`p_{\text{result}}`$).

  The expression lowering engine shall ingest, resolve, and type-check four canonical families of expressions:
  1. **Literal Expressions (`LiteralExpression`)**: The engine shall lower primitive constant values into immutable literal AST nodes:
     - `LiteralBoolean`: boolean constants (`true`, `false`) typed by the standard `Boolean` classifier.
     - `LiteralInteger`: signed 64-bit integer values ($`n \in [-2^{63}, 2^{63}-1]`$) typed by the standard `Integer` classifier.
     - `LiteralReal`: 64-bit IEEE 754 floating-point or rational values typed by the standard `Real` classifier.
     - `LiteralString`: UTF-8 character string values typed by the standard `String` classifier. In accordance with Architectural Directive 3 and REQ-0036, literal string byte slices shall be interned into the global deduplicated symbol interner pool during lexical ingest as the sole permitted exception to zero-copy memory management.
     - `LiteralInfinity`: unbounded multiplicity sentinel (`*`) typed by `UnlimitedNatural`.
     - `NullExpression`: the absent or empty reference sentinel ($`\bot_{\text{val}}`$) typed by the standard bottom type `Nothing` ($`\bot_{\text{type}}`$).
  2. **Feature Reference & Member Navigation Expressions**:
     - Bare identifier expressions $`x`$` shall be resolved within the local lexical scope chain `$`\Gamma`$. Resolving an undefined or out-of-scope identifier shall be strictly prohibited at compile time, deterministically emitting diagnostic error code `E0200`.
     - Member feature access expressions $`E.f`$` shall verify that the target expression `$`E`$` evaluates to a classifier type possessing an accessible feature named `$`f`$. Accessing an undefined feature, or violating feature visibility and encapsulation boundaries, shall deterministically emit diagnostic error code `E0200`.
  3. **Operator Expressions (`OperatorExpression`)**:
     - The engine shall support prefix, postfix, binary infix, and ternary conditional operators, mapping operator symbols to standard library operator function definitions or built-in primitives.
     - Unary operators shall include arithmetic negation (`-`), positive assertion (`+`), logical complement (`not`, `!`), and bitwise inversion (`~`).
     - Binary operators shall include arithmetic operations (`+`, `-`, `*`, `/`, `%`, `^`), relational comparisons (`==`, `!=`, `<`, `<=`, `>`, `>=`), logical connectives (`and`, `or`, `xor`, `implies`), and collection indexing (`[]`).
     - Conditional expressions shall evaluate ternary selection (`if E_cond then E_then else E_else`), requiring that $`E_{\text{cond}}`$ evaluates to `Boolean` and unifying the branch result types via the least common supertype (join $`\vee`$) in the subtyping semilattice.
     - The type checker shall enforce strict operator signature matching: for binary operator $`\odot`$`, operand types `$`(T_1, T_2)`$` must conform to the domain of the operator signature `$`\text{dom}(\text{op}_\odot)`$. Operands violating signature conformance shall be rejected with diagnostic error code `E0200`.
     - Static division by literal zero ($`E / 0`$) in constant expressions shall be detected at compile time, deterministically emitting diagnostic error code `E0200`.
  4. **Invocation Expressions (`InvocationExpression`)**:
     - The engine shall lower function calls and behavioral step invocations $`E_{\text{callee}}(a_1, a_2, \dots, a_k)`$, binding positional and named argument expressions to formal parameters of the target callable entity.
     - Invoking an unresolved target, a non-callable classifier, or passing an invalid argument count shall deterministically emit diagnostic error code `E0200`.
     - The type checker shall enforce directional information flow and subtyping conformance for each argument-to-parameter binding $`(a_i, p_i)`$:
       * For an `In` parameter ($`\delta(p_i) = \text{In}`$`), the argument expression must be readable and its type must specialize or equal the declared parameter type (`$`\tau(a_i) \le \tau(p_i)`$).
       * For an `Out` parameter ($`\delta(p_i) = \text{Out}`$`), the argument expression must be an assignable lvalue reference, and the parameter type must specialize or equal the argument type (`$`\tau(p_i) \le \tau(a_i)`$). Binding an immutable literal, constant value, or compound operator expression to an `Out` parameter shall deterministically emit diagnostic error code `E0201`.
       * For an `InOut` parameter ($`\delta(p_i) = \text{InOut}`$`), the argument expression must be an assignable lvalue reference, and its type must be identical to the declared parameter type (`$`\tau(a_i) \equiv \tau(p_i)`$). Binding an immutable literal or unassignable expression to an `InOut` parameter shall deterministically emit diagnostic error code `E0201`.
       * Any argument subtyping failure violating parameter type bounds shall deterministically emit diagnostic error code `E0200`.

  **Referential Transparency & Purity**: Pure expressions shall be strictly referentially transparent and side-effect free: evaluation of a pure expression must preserve the state of the evaluation store ($`\sigma_{\text{post}} \equiv \sigma_{\text{pre}}`$`). For any identical valuation of free variables in environment `$`\Gamma`$`, evaluating a pure expression must deterministically produce an identical value denotation. The compiler shall perform deterministic constant folding over pure expressions whose operands are known at compile time. Circular dependencies among constant expressions (`$`E_1 \to E_2 \to \dots \to E_1`$) shall be detected via topological cycle detection, deterministically emitting diagnostic error code `E0203`.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered expression node, literal node, operator expression node, and invocation node in the AST shall receive an immutable, deterministic RFC 4122 UUIDv5 identifier computed by namespace-hashing the canonical compiler namespace OID with the node fully qualified topological path and expression discriminant handle per REQ-0010.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel type checking, constant expression folding, and AST validation across independent functions, classifiers, and compilation units shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
  - *Directive 3 (String Interner Allocation Exception)*: String literal content and identifier symbol names shall be interned into the global deduplicated symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
  - *Directive 4 (Synchronization Token Error Recovery)*: Upon encountering expression typing failures (`E0200`), operator signature mismatches (`E0200`), parameter directionality violations (`E0201`), or constant dependency cycles (`E0203`), the engine shall record structured diagnostics with exact source byte spans into the preallocated diagnostic sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute an error sentinel node `$`\bot_{\text{expr}}`$` (with type `$`\bot_{\text{type}}`$), and resynchronize on expression and delimiter boundaries (e.g., `,`, `;`, `)`, `]`), continuing to verify subsequent expressions without aborting compilation until $`C_{\text{max\_errors}}`$` is reached. If accumulated diagnostics reach `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
  - *Directive 5 (Panic-Free Release Isolation)*: The expression lowering engine shall enforce a deterministic, non-panicking execution contract with total-function error handling across all valid and malformed inputs (including division by zero, cyclic definitions, and deep recursion). Latency (< 25 ms) and peak RSS memory (< 100 MB for $`10^5`$ expression AST nodes) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from standard CI logic tests per REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Function_Alpha`, `Function_Beta`, `Expression_1`, `Literal_1`, `Feature_A`, `Step_Alpha`, `param_x : Real`), with zero domain contamination, zero banned crate names, and zero Unicode em dashes.

- **Formal Invariant**: The KerML metamodel hierarchy formalizes `Expression` as a specialization of `Step` within the subtyping meet-semilattice:

```math
\text{Expression} \le_{\text{sub}} \text{Step} \le_{\text{sub}} \text{Feature} \le_{\text{sub}} \text{Type}
```

Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes. Each expression node `$`E \in \mathcal{E}_{\text{expr}} \subset \mathcal{V}_{\text{AST}}`$ is formalized as an 8-tuple:

```math
E = \langle \text{id}_E, \kappa_E, \tau(E), \mu(E), \text{Children}_E, \Delta_E, \text{span}_E, \pi_{\text{pure}} \rangle
```

where:

```math
\begin{aligned}
\text{id}_E &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\kappa_E &\in \{ \text{Literal}, \text{FeatureRef}, \text{MemberAccess}, \text{UnaryOp}, \text{BinaryOp}, \text{Conditional}, \text{Invocation} \} \quad (\text{discriminant kind}) \\
\tau(E) &\in \mathcal{T} \setminus \{ \emptyset \} \quad (\text{inferred or declared classifier type in subtyping meet-semilattice}) \\
\mu(E) &= [m_{\min}(E), m_{\max}(E)] \subseteq \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \}) \quad (\text{multiplicity interval of result}) \\
\text{Children}_E &\in \mathbb{N}_{32}^* \quad (\text{ordered sequence of child operand or argument node handles}) \\
\Delta_E &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
\text{span}_E &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance}) \\
\pi_{\text{pure}} &\in \{ \text{Pure}, \text{Impure} \} \quad (\text{referential transparency and purity flag})
\end{aligned}
```

Let $`\Gamma : \mathcal{S}_{\text{intern}} \to \mathcal{T}`$` denote the typing environment mapping variable and feature symbols to types. Let `$`\sigma \in \Sigma_{\text{store}}`$` denote the evaluation store mapping memory/state locations to values in semantic universe `$`\mathcal{U}_{\text{val}}`$. The evaluation denotation is formalized as:

```math
\text{eval} : (\mathcal{E}_{\text{expr}} \times \Sigma_{\text{store}}) \longrightarrow (\mathcal{U}_{\text{val}} \times \Sigma_{\text{store}})
```

Denotational Soundness Invariant: Under typing environment $`\Gamma`$`, if expression `$`E`$` is typed with classifier `$`T`$`, then evaluating `$`E`$` under store `$`\sigma`$` yields a value within the semantic denotation of `$`T`$:

```math
\Gamma \vdash E : T \implies \forall \sigma \in \Sigma_{\text{store}}, \quad \text{let } (v, \sigma') = \text{eval}(E, \sigma) \text{ in } v \in \llbracket T \rrbracket
```

Referential Transparency & Purity Invariant: For any pure expression $`E`$` (`$`\pi_{\text{pure}}(E) = \text{Pure}`$`), evaluation causes zero observable side effects on store `$`\sigma`$, and identical variable environments yield identical values:

```math
\begin{aligned}
\forall \sigma \in \Sigma_{\text{store}}, \quad \text{eval}(E, \sigma) = (v, \sigma') &\implies \sigma' \equiv \sigma \\
\forall \sigma_1, \sigma_2 \in \Sigma_{\text{store}}, \quad (\forall x \in \text{FreeVars}(E), \; \sigma_1(x) = \sigma_2(x)) &\implies \pi_1(\text{eval}(E, \sigma_1)) = \pi_1(\text{eval}(E, \sigma_2))
\end{aligned}
```

Literal Expression Typing Axioms: Primitive literals evaluate directly to standard library scalar types:

```math
\begin{aligned}
\frac{b \in \{ \text{true}, \text{false} \}}{\Gamma \vdash \text{LiteralBoolean}(b) : \text{Boolean}} &\qquad
\frac{n \in [-2^{63}, 2^{63}-1]}{\Gamma \vdash \text{LiteralInteger}(n) : \text{Integer}} \\
\frac{r \in \mathbb{R}}{\Gamma \vdash \text{LiteralReal}(r) : \text{Real}} &\qquad
\frac{s \in \mathcal{S}_{\text{intern}}}{\Gamma \vdash \text{LiteralString}(s) : \text{String}} \\
\frac{}{\Gamma \vdash \text{LiteralInfinity}(*) : \text{UnlimitedNatural}} &\qquad
\frac{}{\Gamma \vdash \text{NullExpression} : \bot_{\text{type}}}
\end{aligned}
```

Feature Reference & Member Access Typing Rules:

```math
\begin{aligned}
\frac{(x \mapsto T) \in \Gamma}{\Gamma \vdash \text{FeatureRef}(x) : T} &\qquad
\frac{\Gamma \vdash E : C \quad f \in \text{Features}(C) \quad \tau(f) = T_f}{\Gamma \vdash \text{MemberAccess}(E, f) : T_f}
\end{aligned}
```

Operator Expression Typing Rules: For unary operator $`\odot_{\text{un}} \in \{ +, -, \neg, \sim \}`$` and binary operator `$`\odot_{\text{bin}} \in \{ +, -, *, /, \%, \land, \lor, \oplus, \implies, ==, !=, \lt, \le, \gt, \ge \}`$:

```math
\begin{aligned}
\frac{\Gamma \vdash E : T \quad T \in \text{dom}(\text{op}_{\odot_{\text{un}}})}{\Gamma \vdash \odot_{\text{un}} E : \text{codom}(\text{op}_{\odot_{\text{un}}})} &\qquad
\frac{\Gamma \vdash E_1 : T_1 \quad \Gamma \vdash E_2 : T_2 \quad (T_1, T_2) \in \text{dom}(\text{op}_{\odot_{\text{bin}}})}{\Gamma \vdash E_1 \odot_{\text{bin}} E_2 : \text{codom}(\text{op}_{\odot_{\text{bin}}})}
\end{aligned}
```

Conditional Ternary Expression Typing Rule:

```math
\frac{\Gamma \vdash E_{\text{cond}} : \text{Boolean} \quad \Gamma \vdash E_{\text{then}} : T_1 \quad \Gamma \vdash E_{\text{else}} : T_2 \quad T_1 \vee T_2 \ne \top_{\text{type}}}{\Gamma \vdash (\text{if } E_{\text{cond}} \text{ then } E_{\text{then}} \text{ else } E_{\text{else}}) : T_1 \vee T_2}
```

Invocation Expression Parameter Directionality & Typing Invariant: Let callable entity $`F`$` declare parameter sequence `$`(p_1, p_2, \dots, p_k)`$` with types `$`\tau(p_i)`$`, directions `$`\delta(p_i) \in \{ \text{In}, \text{Out}, \text{InOut} \}`$`, and result type `$`T_{\text{ret}}`$`. An invocation `$`E = \text{Invocation}(F, (a_1, a_2, \dots, a_k))`$ is valid if and only if arity and directional bindings hold:

```math
\text{ValidInvocation}(F, (a_1, \dots, a_k)) \iff (|A| = k) \wedge \bigwedge_{i=1}^k \text{ValidArgBinding}(a_i, p_i)
```

where:

```math
\text{ValidArgBinding}(a_i, p_i) \iff \begin{cases}
(\tau(a_i) \le \tau(p_i)) \wedge \text{IsReadable}(a_i), & \text{if } \delta(p_i) = \text{In} \\
(\tau(p_i) \le \tau(a_i)) \wedge \text{IsAssignableLValue}(a_i), & \text{if } \delta(p_i) = \text{Out} \\
(\tau(a_i) \equiv \tau(p_i)) \wedge \text{IsReadable}(a_i) \wedge \text{IsAssignableLValue}(a_i), & \text{if } \delta(p_i) = \text{InOut}
\end{cases}
```

Invocation Expression Typing Rule:

```math
\frac{\Gamma \vdash F : (p_1, \dots, p_k) \to T_{\text{ret}} \quad \text{ValidInvocation}(F, (a_1, \dots, a_k))}{\Gamma \vdash \text{Invocation}(F, (a_1, \dots, a_k)) : T_{\text{ret}}}
```

Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
\forall E \in \mathcal{E}_{\text{expr}}, \quad \Delta_E = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(E) \mathbin{\Vert} \text{Discriminant}(\kappa_E) \mathbin{\Vert} \text{id}_E)
```

Diagnostic Code Trigger Invariant: Any violation of identifier resolution, feature access, operator signature matching, division by zero, argument binding, directionality, or constant dependency cycles deterministically triggers structured diagnostics in accordance with REQ-0191:

```math
\begin{aligned}
(\kappa_E = \text{FeatureRef}(x) \wedge x \notin \text{dom}(\Gamma)) &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0200}, \text{UnresolvedIdentifier}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_E = \text{MemberAccess}(E_0, f) \wedge f \notin \text{Features}(\tau(E_0))) &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0200}, \text{UnresolvedFeature}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_E = \text{BinaryOp}(\odot, E_1, E_2) \wedge (\tau(E_1), \tau(E_2)) \notin \text{dom}(\text{op}_\odot)) &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0200}, \text{IncompatibleOperandTypes}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_E = \text{BinaryOp}(/, E_1, E_2) \wedge \text{IsZeroLiteral}(E_2)) &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0200}, \text{DivisionByZero}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_E = \text{Invocation}(F, A) \wedge |A| \ne |P_F|) &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0200}, \text{ArgumentCountMismatch}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_E = \text{Invocation}(F, A) \wedge \exists i : \neg(\tau(a_i) \le \tau(p_i)) \wedge \delta(p_i) = \text{In}) &\implies \text{Diagnostic}(a_i, \text{DiagnosticCode::E0200}, \text{ArgumentTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_E = \text{Invocation}(F, A) \wedge \exists i : \neg\text{IsAssignableLValue}(a_i) \wedge \delta(p_i) \in \{ \text{Out}, \text{InOut} \}) &\implies \text{Diagnostic}(a_i, \text{DiagnosticCode::E0201}, \text{ParameterDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
(E_1 \to^+ E_1 \text{ in constant expression dependency DAG}) &\implies \text{Diagnostic}(E_1, \text{DiagnosticCode::E0203}, \text{CircularExpressionDependency}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Diagnostic Taxonomy Containment Invariant: All diagnostics emitted by the expression lowering and type checking engine strictly belong to the Metamodel and Typing family and Ingestion error limit family:

```math
\forall D \in \mathcal{D}_{\text{expr}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0201}, \text{DiagnosticCode::E0203}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{ingest}}
```

- **Computational Complexity & Algorithmic Bounds**: Expression AST construction, type checking, and constant evaluation execute strictly within Complexity Class $`\mathbf{P}`$`. For an expression tree or expression forest containing `$`N = |\mathcal{E}_{\text{expr}}|`$` nodes across `$`M`$ functions or classifiers:

  1. **Arena Allocation & Node Handle Addressing**: Allocating each expression AST node in contiguous bump arena storage and interning string literal values executes in amortized $`O(1)`$` time and `$`O(1)`$` auxiliary space per node. Total allocation time is `$`O(N)`$.
  2. **Scoped Symbol Resolution**: Resolving bare identifiers and feature names via hierarchical lexical scope tables executes in $`O(1)`$` expected time per lookup using scoped hash maps, or in bounded `$`O(d_{\text{scope}})`$` time where lexical nesting depth `$`d_{\text{scope}} \le 16 = O(1)`$.
  3. **Bottom-Up Type Inference & Operator Overload Resolution**: Type inference executes via a single bottom-up post-order traversal over the expression DAG. For each node $`u \in \mathcal{E}_{\text{expr}}`$` with arity `$`k = |\text{Children}_u|`$:
     - Primitive literal typing: executes in strictly $`O(1)`$ constant time.
     - Operator signature matching: tests candidate operator overloads $`k_{\text{op}} \le 8 = O(1)`$`, where each candidate requires `$`O(1)`$` subtyping checks via precomputed reachability bitsets or `$`O(h)`$` tree-climbing with bounded inheritance depth `$`h \le 32 = O(1)`$.
     - Invocation argument checking: requires $`k`$` subtyping checks and `$`k`$` lvalue bitfield tests in `$`O(k)`$ time.
     Summing across all $`N`$ nodes in the expression AST:

```math
T_{\text{infer}}(N) = \sum_{u \in \mathcal{E}_{\text{expr}}} O(1 + |\text{Children}_u| + k_{\text{op}}) = O(N)
```

  4. **Constant Expression Folding & Acyclicity**: Evaluating pure constant expressions and detecting circular evaluation dependencies over $`N_{\text{const}}`$` constant nodes with `$`E_{\text{const}}`$ dependency edges executes via Tarjan's strongly connected components algorithm or Kahn's topological sort in deterministic linear time:

```math
T_{\text{const}}(N_{\text{const}}, E_{\text{const}}) \in O(N_{\text{const}} + E_{\text{const}}) \subseteq O(N)
```

  5. **Total Sequential Complexity**: Total sequential execution time for lowering, type inference, and constant evaluation over $`N`$ expression nodes is strictly linear:

```math
T_{\text{total}}(N) \in O(N)
```

  6. **Parallel Work-Stealing Scaling (Architectural Directive 2)**: When partitioned across $`M`$` independent functions or compilation units on a bounded work-stealing thread pool with worker bound `$`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}}(N, N_{\text{max\_workers}}) \in O\left( \frac{N}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  7. **Space Complexity & Memory Bounds**: Auxiliary memory is strictly bounded by $`O(N)`$` contiguous bump arena storage for AST nodes and relationship edges. Traversal call stacks are bounded by tree depth `$`O(h_{\text{tree}}) \le 64`$` frames (`$`O(1)`$` auxiliary stack space), or eliminated using iterative traversal queues. The diagnostic error sink is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ allocated memory.

- **Verification & Conformance Criteria**: Deterministic conformance shall be verified by automated test suites operating on synthetic MBSE models containing abstract placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Function_Alpha`, `Function_Beta`, `Expression_1`, `Literal_1`, `Feature_A`, `Step_Alpha`, `param_x : Real`). Conformance validation shall enforce the following test gates:

  1. **Primitive Literal Ingestion & Typing Gate**: Ingest expressions containing `LiteralBoolean` (`true`, `false`), `LiteralInteger` (`42`, `-100`), `LiteralReal` (`3.14159`, `-0.001`), `LiteralString` (`"symbol_token"`), `LiteralInfinity` (`*`), and `NullExpression` (`null`). Assert that the type checking engine infers exact types `Boolean`, `Integer`, `Real`, `String`, `UnlimitedNatural`, and `Nothing` with zero diagnostics emitted.
  2. **Feature Reference & Scoped Navigation Gate**: Declare `Classifier_Alpha` possessing feature `param_x : Real`. In an expression within `Classifier_Alpha`, reference bare identifier `param_x` and member access `Classifier_Alpha.param_x`. Assert 100% resolution to feature arena handles and inferred type `Real`. Ingest an expression referencing undefined identifier `param_z` or non-existent member `Classifier_Alpha.param_missing`; assert deterministic compilation rejection with diagnostic code `E0200` (`UnresolvedIdentifier` and `UnresolvedFeature`).
  3. **Binary & Unary Operator Signature Conformance Gate**: Ingest valid operator expressions: `param_x + 5.0` (`Real`), `n - 1` (`Integer`), `!flag` (`Boolean`), and `param_x <= 10.0` (`Boolean`). Assert successful type inference and zero diagnostics. Ingest invalid operator applications: `"string_val" + 42` and `true && 3.14`; assert deterministic compilation rejection with diagnostic code `E0200` (`IncompatibleOperandTypes`).
  4. **Static Division by Literal Zero Gate**: Ingest constant expressions containing division by literal zero: `param_x / 0.0` and `100 / 0`. Assert deterministic compile-time detection and rejection with diagnostic code `E0200` (`DivisionByZero`) and exact source byte spans.
  5. **Conditional Ternary Expression Type Unification Gate**: Ingest conditional expression `if flag then param_x else 0.0`. Assert condition type `Boolean` and unified branch type `Real`. Ingest conditional expression with non-boolean condition `if 42 then 1 else 2`; assert deterministic rejection with diagnostic code `E0200`. Ingest branches with disjoint, non-unifiable types where least common supertype is `Any` or exceeds bounded lattice join; assert deterministic rejection with diagnostic code `E0200`.
  6. **Invocation Parameter Arity & Subtyping Conformance Gate**: Declare function `Function_Alpha(param_1 : Integer, param_2 : Real) : Boolean`. Ingest call `Function_Alpha(42, 3.14)`; assert successful type inference yielding `Boolean`. Ingest call with arity mismatch `Function_Alpha(42)`; assert deterministic rejection with diagnostic code `E0200` (`ArgumentCountMismatch`). Ingest call with argument type mismatch `Function_Alpha("invalid", 3.14)`; assert deterministic rejection with diagnostic code `E0200` (`ArgumentTypeMismatch`).
  7. **Invocation Parameter Directionality & LValue Gate**: Declare function `Function_Beta(in param_in : Integer, out param_out : Integer, inout param_inout : Integer) : Boolean`. Verify that passing an immutable literal `10` or expression `param_x + 1` to `param_in` succeeds with zero diagnostics. Attempt to pass immutable literal `10` or compound expression `param_x + 1` to `param_out` or `param_inout`; assert deterministic rejection with diagnostic code `E0201` (`ParameterDirectionMismatch`). Pass a mutable feature reference `Feature_A` to `param_out` and `param_inout`; assert successful validation.
  8. **Referential Transparency & Store Invariance Gate**: Evaluate pure expression `Expression_1` under store $`\sigma`$`. Assert that post-evaluation store `$`\sigma_{\text{post}} \equiv \sigma_{\text{pre}}`$, and assert that repeated evaluations under identical variable bindings yield bitwise identical value results with zero observable side effects.
  9. **Constant Folding & Circular Dependency Detection Gate (`E0203`)**: Ingest foldable constant expressions (`2 + 3 * 4`); assert compile-time reduction to literal `14`. Inject a circular constant expression dependency chain ($`c_1 = c_2 + 1, c_2 = c_1 * 2`$); assert that topological cycle detection isolates the cycle, emits diagnostic error code `E0203` (`CircularExpressionDependency`), and provides an ordered cycle traceback path with accurate source byte spans.
  10. **Synchronization Token Error Recovery Gate (Architectural Directive 4)**: Ingest an expression block containing 5 distinct typing, operator, and directionality faults interspersed with valid expressions.
