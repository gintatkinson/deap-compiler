### REQ-0197: NP-8: Formal Proof Obligations & Invariant Contract Satisfiability via Decidable SMT Fragments

- **Normative Statement**: The formal verification engine, proof obligation synthesizer, and SMT constraint satisfiability solver pipeline of Subsystem 12 shall extract, synthesize, and discharge formal mathematical proof obligations from architectural model invariants, contract assertions, operational envelopes, statechart transition guards, and formal safety properties. The verification engine shall enforce strict syntactic guardrails restricting all synthesized proof obligations strictly to decidable Satisfiability Modulo Theories (SMT) fragments: Quantifier-Free Linear Real Arithmetic (`QF_LRA`), Quantifier-Free Linear Integer Arithmetic (`QF_LIA`), Quantifier-Free Uninterpreted Functions (`QF_UF`), and their combinations (`QF_UFLRA`, `QF_UFLIA`).

  The compiler shall evaluate proof obligations using refutational semantics, asserting the conjunction of the system model hypothesis $`\Phi_{\text{hyp}}`$ and the logical negation of the target invariant property $`\neg \psi_{\text{concl}}`$, such that establishing unsatisfiability certifies universal invariant validity ($`\text{UNSAT}(\Phi_{\text{hyp}} \wedge \neg \psi_{\text{concl}}) \iff (\Phi_{\text{hyp}} \models \psi_{\text{concl}})`$). If any proof obligation, invariant contract, or state transition constraint incorporates non-linear arithmetic terms ($`x \cdot y`$ where both terms are indeterminate variables, division by indeterminate expressions $`x / y`$, polynomial variable powers $`x^n`$ for $`n \ge 2`$, or transcendental function applications such as $`\sin, \cos, \tan, \exp, \ln, \log`$) or unrestricted alternating quantifiers ($`\forall, \exists`$), the compiler shall reject the compilation unit at the syntactic front-end and emit diagnostic error code `E0406`.

  The verification engine shall execute solver exploration under an explicit, deterministic conflict step cutoff $`\kappa_{\text{smt}}`$, where $`\kappa_{\text{smt}} \le 100{,}000`$ conflict steps. If the solver exploration exceeds $`\kappa_{\text{smt}}`$ without establishing satisfiability or unsatisfiability, the verification engine shall abort the search deterministically and emit diagnostic error code `E0406`. If refutational satisfiability is established ($`\text{SAT}`$), indicating that a system execution path violates the invariant contract, the verification engine shall extract a concrete counterexample valuation model and emit diagnostic error code `E0406`. If unsatisfiability is established ($`\text{UNSAT}`$), the engine shall certify contract satisfaction and extract a minimal unsatisfiable core proof witness.

  Specifically, the formal verification engine and SMT constraint pipeline shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Syntactic Guardrails & Decidable Fragment Partitioning (`Admissible(\phi)`)**:
     - The verification engine shall inspect all AST invariant expressions, contract assertions, pre/post-conditions, and operational envelope boundaries prior to solver dispatch.
     - Proof obligations shall be partitioned into explicit decidable SMT background logics:
       * `QF_LRA`: For continuous physical variables, flow conservation equations, and rational metric bounds.
       * `QF_LIA`: For discrete state counters, clock ticks, integer capacities, and finite sequence indices.
       * `QF_UF`: For uninterpreted structural associations, classifier hierarchies, and abstract functional mappings.
       * `QF_UFLRA` / `QF_UFLIA`: For hybrid models combining uninterpreted structural relations with linear real or integer arithmetic.
     - Any constraint violating decidability requirements by introducing non-linear arithmetic or quantifiers shall be rejected at the syntactic front-end with diagnostic `E0406` (`SMTNonLinearUnsupportedTheoryViolation` or `SMTAlternatingQuantifierViolation`).
  2. **Refutational Invariant Verification & Inductive Soundness**:
     - System safety invariants and contract assertions shall be proven via refutation:

$$
\Phi_{\text{refute}} = \Phi_{\text{hyp}} \wedge \neg \psi_{\text{concl}}
$$

     - Universal validity of property $`\psi_{\text{concl}}`$ under hypothesis $`\Phi_{\text{hyp}}`$ is certified if and only if $`\Phi_{\text{refute}}`$ is provably unsatisfiable:

$$
\text{UNSAT}(\Phi_{\text{refute}}) \iff (\Phi_{\text{hyp}} \models \psi_{\text{concl}})
$$

     - For state machine dynamics and inductive occurrence sequences, the engine shall synthesize dual proof obligations:
       * *Inductive Base Case*: Initial system configuration $`I(s_0)`$ conjoined with negated invariant $`\neg \mathcal{I}(s_0)`$: $`\Phi_{\text{base}} = I(s_0) \wedge \neg \mathcal{I}(s_0)`$.
       * *Inductive Consecution Step*: Valid invariant assumption at state $`s`$ conjoined with transition relation $`T(s, s')`$ and negated invariant at successor state $`s'`$: $`\Phi_{\text{step}} = \mathcal{I}(s) \wedge T(s, s') \wedge \neg \mathcal{I}(s')`$.
       * Inductive soundness certifies invariant satisfaction across all reachable states: $`(\text{UNSAT}(\Phi_{\text{base}}) \wedge \text{UNSAT}(\Phi_{\text{step}})) \implies (\forall k \in \mathbb{N}, \ s_k \models \mathcal{I})`$.
  3. **Bounded Model Checking (BMC) Horizon Unrolling**:
     - For bounded temporal verification and multi-step statecharts, the verification engine shall formulate bounded unrolling scripts of horizon depth $`k \in \{0, \dots, k_{\text{max}}\}`$:

$$
\Phi_{\text{bmc}}^{(k)} = I(s_0) \wedge \left( \bigwedge_{j=0}^{k-1} T(s_j, s_{j+1}) \right) \wedge \left( \bigvee_{j=0}^k \neg \mathcal{I}(s_j) \right)
$$

     - Proving $`\Phi_{\text{bmc}}^{(k)}`$ unsatisfiable for all $`k \le k_{\text{max}}`$ certifies that no safety violation can manifest within $`k_{\text{max}}`$ execution steps.
  4. **DPLL(T) Architecture & Nelson-Oppen Theory Combination**:
     - Satisfiability Modulo Theories shall be decided via an integrated DPLL(T) / CDCL(T) solving engine combining a Conflict-Driven Clause Learning (CDCL) boolean SAT engine with dedicated convex theory solvers ($`T`$-solvers).
     - Theory solvers shall include:
       * Simplex algorithm for linear inequalities over the reals (`QF_LRA`).
       * Branch-and-bound with Gomory cutting planes over Simplex relaxations for integer linear arithmetic (`QF_LIA`).
       * Congruence closure over directed acyclic graphs for equality with uninterpreted functions (`QF_UF`).
     - Statically disjoint theories shall be combined using Nelson-Oppen equality sharing over purified shared variable interfaces.
  5. **Deterministic Conflict Step Budget ($`\kappa_{\text{smt}} \le 100{,}000`$)**:
     - In accordance with Algorithmic Bound NP-8, proof obligation satisfiability is NP-complete for quantifier-free decidable fragments. To guarantee bounded compile-time throughput and prevent exponential solver stagnation, the verification engine shall enforce an explicit step cutoff $`\kappa_{\text{smt}}`$ (default $`\kappa_{\text{smt}} = 100{,}000`$ conflict steps).
     - Every CDCL conflict analysis step, lemma learning iteration, and theory conflict derivation shall increment a deterministic monotonic counter $`N_{\text{conflicts}}`$.
     - If $`N_{\text{conflicts}} \gt \kappa_{\text{smt}}`$, the verification engine shall abort execution deterministically and emit diagnostic error code `E0406` (`SMTSolverStepLimitExceeded`), reporting the unproven obligation ID, active decision depth, and conflict budget cutoff.
  6. **Proof Witnesses & Counterexample Synthesis**:
     - When an obligation is proven unsatisfiable (`UNSAT`), the engine shall extract a deterministic proof witness $`\mathcal{W}_{\text{proof}}`$ comprising the minimal unsatisfiable core of asserted lemmas, certifying contract correctness.
     - When an obligation is satisfiable (`SAT`), the engine shall extract a concrete counterexample model $`\mathcal{M}_{\text{counter}}`$ mapping variables to concrete values that refute the contract assertion, emitting diagnostic error code `E0406` (`ContractInvariantViolation`) with source spans of the violated contract.

Time-based UUIDs are strictly banned.
     - Every proof obligation shall retain exact source lexical provenance spans ($`\langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$) mapping back to the originating AST invariant declaration per REQ-0002.
  8. **Bounded Work-Stealing Parallelism (Directive 2)**:

  10. **Synchronization Token Error Recovery (Directive 4)**:

      - When non-linear terms (`E0406`), quantifier violations (`E0406`), solver timeouts (`E0406`), or contract refutation failures (`E0406`) occur, the engine shall record diagnostics into error sink buffer $`\mathcal{D}_{\text{sink}}`$, substitute typed error sentinels ($`\bot_{\text{proof}}`$), and proceed to validate subsequent proof obligations.

$$

  1. *Syntactic front-end restriction*: All expressions are restricted strictly to decidable quantifier-free linear fragments (`QF_LRA`, `QF_LIA`, `QF_UF`, `QF_UFLRA`, `QF_UFLIA`), rejecting non-linear terms ($`x \cdot y`$) and alternating quantifiers ($`\forall, \exists`$) via diagnostic `E0406`.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 addresses qualitative temporal consistency over occurrence lifecycles using Allen's 13 interval relations, solved via ORD-Horn path consistency in $`O(N^3)`$ polynomial time and SMT difference logic with step cutoff $`\kappa_{\text{temporal}}`$. In contrast, NP-8 (REQ-0197) resolves general quantifier-free first-order linear assertions over real and integer arithmetic and uninterpreted functions using DPLL(T) theory solvers beyond pairwise difference bounds.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses structural allocation, interconnect clustering, and logical channel multiplexing via strongly NP-hard multi-dimensional vector bin packing solved by First-Fit Decreasing (FFD) approximation and 0-1 ILP with cutoff $`\kappa_{\text{alloc}}`$. In contrast, NP-8 verifies logical and numerical invariant contracts via DPLL(T) satisfiability without geometric packing, bin capacity optimization, or matrix cuts.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 formalizes subtyping lattice redefinition, multiple inheritance, and feature subsetting via C3 linearization in deterministic $`O(V + E)`$ time. In contrast, NP-8 solves symbolic satisfiability of first-order invariant expressions using SAT-based boolean abstraction combined with convex linear theory reasoning over model attributes and states.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions with logarithmic approximation factors. In contrast, NP-8 verifies invariant preservation and pre/post-condition entailment across system transitions without combinatorial hypergraph transversals or fault tree minimization.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking). In contrast, NP-8 verifies single-step inductive consecution $`\mathcal{I}(s) \wedge T(s, s') \implies \mathcal{I}(s')`$ and individual contract invariants via DPLL(T) satisfiability without multi-step orthogonal reachability unrolling.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched piecewise conservative flow networks using linear complementarity problems (LCP/MCP) and Lemke pivoting (NP-complete). In contrast, NP-8 decides boolean combinations of linear inequalities and uninterpreted function equalities without pivoting tableaus, continuous conductances, or complementary variable pairing.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 performs register allocation and basic block instruction scheduling in LUMI IR using Chaitin graph $`K`$-coloring (NP-complete). In contrast, NP-8 operates on mathematical logic proof obligations rather than machine register interference graphs or basic block instruction DAGs.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 is the primary anchor requirement formalized herein. It governs formal proof obligations and invariant contract satisfiability via decidable SMT fragments. While general first-order theorem proving with non-linear arithmetic is undecidable, REQ-0197 establishes tractability by restricting theories to decidable quantifier-free fragments (QF_LRA, QF_LIA, QF_UF) where satisfiability is NP-complete, and enforcing an explicit conflict step cutoff $`\kappa_{\text{smt}} \le 100{,}000`$ to prevent exponential solver divergence.

$$

T_{\text{total}}(P, N_V, \kappa_{\text{smt}}) \in O\left( N_V + \sum_{i=1}^P \min(2^{N_i}, \kappa_{\text{smt}}) \cdot T_{\text{theory}}(N_i) \right)
