### REQ-0026: Tabular Schema Ingestion for Behaviors, Actions & State Transitions

- **Normative Statement**: The ingestion engine within the Universal Schema Ingestion Engine shall parse tabular schemas defining behavioral actions, activities, and discrete state transitions into intermediate `IngestedAction` and `IngestedTransition` entities within the compilation unit Abstract Syntax Tree (AST). The ingestion engine must extract behavioral action identifiers, owning component or classifier definitions, behavioral action kinds (`Action`, `Activity`, `OpaqueAction`), typed input parameters, typed output parameters, trigger event specifications, guard condition predicates, precondition constraints, and postcondition constraints. In addition, when a tabular schema defines discrete state transitions, the ingestion engine shall extract source state references, target state references, transition trigger events, transition guard conditions, and transition effect actions. Dynamic semantic header normalization shall bind table columns order-independently to canonical behavioral attributes in accordance with REQ-0017. All behavioral action, state, and parameter identifiers shall be sanitized and normalized according to the identifier rules specified in REQ-0019. The ingestion parser shall parse comma-separated or semicolon-separated parameter specification strings into ordered sequences of typed parameter pairs $`(p_i, \tau_i)`$` for inputs and `$`(q_j, \tau_j)`$ for outputs, verifying that parameter names within each parameter set are pairwise distinct and that input and output parameter sets are mutually disjoint. The parser must validate that declared parameter types reference valid scalar types or resolvable classifier symbols. Precondition and postcondition expressions shall be tokenized and captured as structured constraint expressions. For state transitions, the ingestion engine shall enforce statechart endpoint validity: both the source state and the target state must reference resolvable state identifiers declared within the state scope of the owning classifier or state machine. If an action or transition row violates schema invariants--including missing mandatory identifiers, missing owner references, malformed parameter syntax, duplicate parameter identifiers, missing transition endpoints, or unresolvable state references--the ingestion engine shall construct a structured diagnostic record binding diagnostic error code `E0102` (table row delimiter or entity mapping failure) in accordance with the standardized diagnostic taxonomy of REQ-0191. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the ingestion engine shall implement synchronization token error recovery on row line break delimiter boundaries ($`\text{SYM}_{\text{LF}}`$), logging the structured `E0102` diagnostic, substituting a typed error sentinel ($`\bot_{\text{action}}`$` or `$`\bot_{\text{trans}}`$`), and resuming ingestion at the subsequent table row without aborting the compilation pass. If accumulated diagnostics reach the bounded error sink capacity limit `$`C_{\text{max\_errors}}`$, the parser must emit diagnostic error code `E0199` and terminate table processing gracefully. All extracted behavioral entities shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, yielding deterministic node handles with stable relative offsets. In accordance with Architectural Directive 3 and REQ-0036, copying string bytes from the input table buffer into the global symbol interner pool for scalar symbol tokens during this initial ingestion pass is the sole permitted exception to the zero-copy invariant. Multi-table or multi-file parallel ingestion passes shall be scheduled strictly onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with Architectural Directive 2 and REQ-0012. In accordance with Architectural Directive 5, the behavioral ingestion engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs. All test models, diagnostics, and illustrative examples shall strictly utilize synthetic abstract MBSE placeholders (e.g., `Package_0`, `Classifier_Alpha`, `StateMachine_0`, `State_Source`, `State_Target`, `Action_1`, `Event_Alpha`, `param_x : Real`, `guard_cond_0`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $`\mathcal{T}_{\text{behavior}} = (\mathbf{H}, \mathbf{R})`$` denote a tabular schema specifying behaviors, actions, or state transitions, where `$`\mathbf{H} = \langle H_0, H_1, \dots, H_{C-1} \rangle`$` represents the sequence of `$`C`$` normalized column headers (`$`1 \le C \le 32`$`) and `$`\mathbf{R} = \langle R_1, R_2, \dots, R_M \rangle`$` represents the ordered sequence of `$`M`$` table rows. Let `$`\vec{\beta} : \{0, \dots, C-1\} \to \mathcal{K}_{\text{behavior}} \cup \{ \bot \}`$ denote the column binding vector mapping column indices to canonical behavioral attributes:

```math
\mathcal{K}_{\text{behavior}} = \{ \text{id}, \text{owner}, \text{kind}, \text{inputs}, \text{outputs}, \text{trigger}, \text{guard}, \text{pre}, \text{post}, \text{source}, \text{target}, \text{effect} \}
```

Each behavioral action row $`R_i \in \mathbf{R}`$ is lowered into an `IngestedAction` entity modeled as an 8-tuple:

```math
A_i = \langle \text{id}_i, \text{owner}_i, \mathcal{I}_i, \mathcal{O}_i, e_{\text{trigger}, i}, g_{\text{guard}, i}, \mathcal{P}_{\text{pre}, i}, \mathcal{P}_{\text{post}, i} \rangle
```

where:
- $`\text{id}_i \in \mathcal{S}_{\text{sym}}`$ is the interned scalar symbol handle representing the unique action identifier,
- $`\text{owner}_i \in \mathcal{S}_{\text{sym}} \cup \mathcal{H}_{\text{node}}`$ is the owning classifier or state machine handle,
- $`\mathcal{I}_i`$ is the ordered set of typed input parameters:

```math
\mathcal{I}_i = \{ (p_{i, k}, \tau_{i, k}) \mid 1 \le k \le m \}
```

- $`\mathcal{O}_i`$ is the ordered set of typed output parameters:

```math
\mathcal{O}_i = \{ (q_{i, j}, \tau_{i, j}') \mid 1 \le j \le k \}
```

- $`e_{\text{trigger}, i} \in \mathcal{S}_{\text{sym}} \cup \{ \bot \}`$ is the optional trigger event symbol,
- $`g_{\text{guard}, i} \in \mathcal{E}_{\text{expr}} \cup \{ \bot \}`$ is the optional guard predicate handle,
- $`\mathcal{P}_{\text{pre}, i} = \{ \phi_{\text{pre}, 1}, \dots, \phi_{\text{pre}, u} \} \subset \mathcal{E}_{\text{expr}}`$ is the set of precondition constraint expression handles,
- $`\mathcal{P}_{\text{post}, i} = \{ \psi_{\text{post}, 1}, \dots, \psi_{\text{post}, v} \} \subset \mathcal{E}_{\text{expr}}`$ is the set of postcondition constraint expression handles.

Parameter Uniqueness and Disjointness Invariant: Parameter identifiers within input and output sets must be pairwise distinct and mutually disjoint:

```math
\begin{aligned}
\forall a, b \in \{1, \dots, m\}, \quad a \ne b &\implies p_{i, a} \ne p_{i, b} \\
\forall c, d \in \{1, \dots, k\}, \quad c \ne d &\implies q_{i, c} \ne q_{i, d} \\
\{ p_{i, 1}, \dots, p_{i, m} \} &\cap \{ q_{i, 1}, \dots, q_{i, k} \} = \emptyset
\end{aligned}
```

State Transition Binding Invariant: For table rows defining discrete state transitions within a state machine or statechart, each transition entity $`T_j`$ is formalized as a 5-tuple:

```math
T_j = \langle s_{\text{source}, j}, s_{\text{target}, j}, e_{\text{trigger}, j}, g_{\text{guard}, j}, A_{\text{effect}, j} \rangle
```

where:
- $`s_{\text{source}, j} \in \mathcal{S}_{\text{sym}}`$ is the source state identifier,
- $`s_{\text{target}, j} \in \mathcal{S}_{\text{sym}}`$ is the target state identifier,
- $`e_{\text{trigger}, j} \in \mathcal{S}_{\text{sym}} \cup \{ \bot \}`$ is the transition trigger event symbol,
- $`g_{\text{guard}, j} \in \mathcal{E}_{\text{expr}} \cup \{ \bot \}`$ is the transition guard predicate,
- $`A_{\text{effect}, j} \in \mathcal{H}_{\text{node}} \cup \mathcal{S}_{\text{sym}} \cup \{ \bot \}`$ is the optional effect action handle executed upon transition firing.

State Transition Endpoint Scope Invariant: For all transitions $`T_j`$, the source and target states must be elements of the state set defined by the owning classifier or state machine:

```math
\forall T_j \in \mathcal{T}_{\text{trans}}, \quad s_{\text{source}, j} \in \text{States}(\text{owner}_j) \quad \wedge \quad s_{\text{target}, j} \in \text{States}(\text{owner}_j)
```

where the state scope $`\text{States}(M)`$` is defined over all declared state nodes within machine `$`M`$:

```math
\text{States}(M) = \{ s \in \mathcal{S}_{\text{sym}} \mid \text{DeclaredState}(s, M) \}
```

Deterministic Guard Disjointness Invariant: Transitions originating from the same source state under identical trigger events must have non-overlapping guard conditions to ensure deterministic execution:

```math
(s_{\text{source}, a} = s_{\text{source}, b} \;\wedge\; e_{\text{trigger}, a} = e_{\text{trigger}, b} \;\wedge\; a \ne b) \implies (g_{\text{guard}, a} \wedge g_{\text{guard}, b} \equiv \text{false})
```

Contiguous Arena Allocation Invariant: Ingested action and transition entities allocate sequentially into contiguous bump arena memory:

```math
\forall i \in \{1, \dots, M\}, \quad \text{Allocate}(\text{Arena}, A_i) = h_i \in \mathcal{H}_{\text{node}}
```

satisfying constant-stride address progression:

```math
\text{Offset}(h_{i+1}) = \text{Offset}(h_i) + \text{sizeof}(\text{IngestedAction})
```

Diagnostic Code Binding Invariant: Ingestion faults deterministically generate structured diagnostic records bound to diagnostic error code `E0102` (or `E0199` upon error sink saturation) per REQ-0191:

```math
\begin{aligned}
\text{Cell}(R_i, C_{\text{id}}) = \bot \;\vee\; \text{Cell}(R_i, C_{\text{id}}) = \varepsilon &\implies \text{Diagnostic}(R_i, C_{\text{id}}, \text{DiagnosticCode::E0102}, \text{MissingActionIdentifier}) \in \mathcal{D} \\
\text{Cell}(R_i, C_{\text{owner}}) = \bot \;\vee\; \text{Cell}(R_i, C_{\text{owner}}) = \varepsilon &\implies \text{Diagnostic}(R_i, C_{\text{owner}}, \text{DiagnosticCode::E0102}, \text{MissingOwnerClassifier}) \in \mathcal{D} \\
\text{MalformedParams}(\text{Cell}(R_i, C_{\text{params}})) &\implies \text{Diagnostic}(R_i, C_{\text{params}}, \text{DiagnosticCode::E0102}, \text{MalformedParameterSignature}) \in \mathcal{D} \\
(\exists a \ne b : p_a = p_b) \;\vee\; (\exists c \ne d : q_c = q_d) &\implies \text{Diagnostic}(R_i, C_{\text{params}}, \text{DiagnosticCode::E0102}, \text{DuplicateParameterIdentifier}) \in \mathcal{D} \\
\text{IsTransition}(R_i) \wedge (s_{\text{source}} = \bot \;\vee\; s_{\text{target}} = \bot) &\implies \text{Diagnostic}(R_i, C_{\text{states}}, \text{DiagnosticCode::E0102}, \text{MissingTransitionEndpoints}) \in \mathcal{D} \\
\text{IsTransition}(R_i) \wedge (s_{\text{source}} \notin \text{States}(M) \;\vee\; s_{\text{target}} \notin \text{States}(M)) &\implies \text{Diagnostic}(R_i, C_{\text{states}}, \text{DiagnosticCode::E0102}, \text{UnresolvedStateEndpoint}) \in \mathcal{D} \\
|\mathcal{D}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Diagnostic Taxonomy Containment Invariant: Emitted diagnostics strictly reside within the Subsystem 2 ingestion family:

```math
\forall D \in \mathcal{D}_{\text{behavior}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{ingest}}
```

- **Computational Complexity & Algorithmic Bounds**: Tabular schema ingestion for behaviors, actions, and state transitions executes within Complexity Class $`\mathbf{P}`$`. For an input document of total byte size `$`N`$` containing `$`R`$` behavioral table rows and `$`C`$` columns (`$`1 \le C \le C_{\text{max\_cols}} = 32`$`), lexical scanning and table line break delimiter detection advance monotonically without backtracking in `$`O(N)`$` operations. Dynamic semantic header normalization and column binding vector computation `$`\vec{\beta}`$` execute once per table in `$`O(C) = O(1)`$` constant time. For each row `$`R_i`$`, cell string extraction and identifier sanitization operate in `$`O(L_{\text{cell}})`$` time bounded by `$`L_{\text{cell}} \le 256`$`, establishing an `$`O(1)`$` bound per cell. Parameter signature parsing evaluates comma-separated or semicolon-separated tokens across at most `$`P_{\text{max}} \le 32`$` parameter declarations; splitting, trimming, and extracting `$`(p_k, \tau_k)`$` pairs executes in `$`O(m + k) = O(1)`$` time. Symbol interning of action names, parameter identifiers, and type references operates in `$`O(1)`$` amortized time per token using a preallocated symbol table. State transition endpoint verification checks `$`s_{\text{source}}, s_{\text{target}} \in \text{States}(\text{owner})`$` via constant-time hash set lookups over the pre-indexed state scope of the owning classifier, executing in `$`O(1)`$` expected time per transition row. Entity construction and allocation into the contiguous typed bump arena require a single pointer bump operation in `$`O(1)`$` constant time. Aggregate sequential execution time across all `$`R`$ behavioral rows is strictly bounded by:

```math
T(R, N) \in O(N) = O(R \cdot C) = O(R)
```

When processing $`K`$` distinct behavioral tables across `$`N_{\text{max\_workers}}`$` threads on a bounded work-stealing thread pool, parallel wall-clock runtime is bounded by `$`O(\lceil K / N_{\text{max\_workers}} \rceil \cdot R_{\text{max}})`$`. Auxiliary space complexity is strictly bounded by `$`O(1)`$` per row, with total storage bounded by `$`O(R)`$` for node arena allocations and `$`O(C_{\text{max\_errors}}) = O(1)`$ for preallocated diagnostic records, guaranteeing zero unbounded heap allocations.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic CommonMark schema tables specifying abstract MBSE behaviors, actions, and state transitions using generic placeholders (e.g., `Package_0`, `Classifier_Alpha`, `StateMachine_0`, `State_Source`, `State_Target`, `State_Idle`, `State_Active`, `Action_1`, `Activity_Alpha`, `Event_Trigger_0`, `param_x : Real`, `param_y : Integer`, `guard_cond_0`, `pre_cond_1`, `post_cond_1`). Conformance shall be validated through the following 10 deterministic test gates:
  1. Canonical Behavioral Action Ingestion Gate: Ingest a synthetic CommonMark table specifying behavioral actions (`Action_0`, `Action_1`, `Activity_Alpha`) across owning classifiers (`Classifier_Alpha`, `Classifier_Beta`) with typed inputs (`param_in_1 : Real`, `param_in_2 : Integer`), typed outputs (`param_out : Real`), trigger events (`Event_Trigger_0`), guard predicates (`guard_cond_0`), and pre/postconditions (`pre_cond_1`, `post_cond_1`); assert that 100% of rows lower into valid `IngestedAction` AST nodes allocated in contiguous bump arena memory with stable offset progression.
  2. State Transition Table Ingestion Gate: Ingest a synthetic table specifying discrete state transitions (`Transition_0`, `Transition_1`) between defined states (`State_Source`, `State_Target`, `State_Idle`, `State_Active`) with trigger events (`Event_Start`, `Event_Reset`), guard conditions (`guard_flag_0`), and effect actions (`Action_Notify`); assert 100% extraction into valid `IngestedTransition` entities with correct source and target state bindings.
  3. Parameter Signature Extraction Gate: Validate parsing of parameter strings across varied syntax formats (e.g., `param_a : Real, param_b : Integer`, `result : Boolean`, and empty cell $`\bot`$` defaulting to `$`\emptyset`$); assert that parameter identifiers, directions, and type handles match expected AST structures and that input and output parameter sets are disjoint.
  4. Parameter Syntax & Collision Diagnostic Gate: Ingest behavioral rows containing malformed parameter strings (e.g., missing type annotations, invalid identifier tokens) or duplicate parameter names within a signature; assert deterministic emission of diagnostic error code `E0102` (`MalformedParameterSignature` or `DuplicateParameterIdentifier`), substitution of sentinel $`\bot_{\text{action}}`$, and continuous parsing of subsequent rows.
  5. Missing Mandatory Attributes Gate: Ingest table rows omitting mandatory attributes (action identifier `id` or owning classifier `owner`); assert deterministic emission of diagnostic error code `E0102` (`MissingActionIdentifier` or `MissingOwnerClassifier`).
  6. Transition Endpoint Scope Gate: Ingest transition rows declaring state endpoints that do not belong to the state scope of the owning state machine (e.g., $`s_{\text{source}} \notin \text{States}(\text{owner})`$); assert deterministic emission of diagnostic error code `E0102` (`UnresolvedStateEndpoint`).
  7. Directive 4 Synchronization Token Error Recovery Gate: Ingest a 10-row behavioral table containing deliberate syntax corruption on rows 3 and 7 (e.g., unclosed delimiters, malformed parameter lists); assert that rows 1, 2, 4, 5, 6, 8, 9, 10 are completely extracted into canonical AST entities, exactly two `E0102` diagnostic records are logged, and the parser resumes cleanly at row line break delimiters ($`\text{SYM}_{\text{LF}}`$).
  8. Diagnostic Error Sink Saturation Gate: Ingest a table with continuous syntax faults exceeding $`C_{\text{max\_errors}}`$; assert that the parser terminates gracefully with diagnostic error code `E0199` without process abort or memory exhaustion.
  9. Directive 5 Total Function & Release Mode Latency Gate: Fuzz testing over $`10^4`$ pathological tabular inputs (including high-entropy unicode text, truncated rows, null bytes, and empty tables) shall assert total-function execution with zero panics or crashes. In compiled Release mode (`--release`), benchmark execution shall assert throughput $`\ge 100{,}000`$ rows per second, total per-table latency within the 25 ms compiler execution budget, and peak RSS memory under 100 MB.
  10. Bitwise Determinism Gate: Assert that compiling identical behavioral schema tables across independent compilation passes and varied thread pool configurations yields 100% bitwise identical AST representations with 0-byte diff churn.
