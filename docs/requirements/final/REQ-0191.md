### REQ-0191: Standardized Compiler Diagnostic Taxonomy, Source-Mapping & Recovery Architecture

- **Normative Statement**: The compiler diagnostic engine, diagnostic catalog, source-mapping framework, and error recovery coordinator of Subsystem 11 shall partition all compiler diagnostics into a standardized, mutually disjoint architectural taxonomy spanning five distinct numeric ranges: Ingestion and Lexical errors (`E0100`--`E0199`), Metamodel and Typing errors (`E0200`--`E0299`), Metrology and Flow Conservation errors (`E0300`--`E0399`), Spatio-Temporal, State Machine and Formal Safety errors (`E0400`--`E0499`), and Backend, Intermediate Representation Emission, Downstream Projections and Reverse-Synchronization errors (`E0500`--`E0599`). The diagnostic engine shall attach precise source-mapping spans, half-open byte intervals, 1-indexed line and column coordinates, severity tiers, and machine-readable automated diagnostic recovery suggestions across all error families. The compiler shall strictly prohibit unstructured, non-standardized, or domain-contaminated error codes.

  Specifically, the compiler diagnostic engine, diagnostic catalog, and recovery coordinator shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Standardized 5-Family Diagnostic Partition Taxonomy & Numerical Ranges**:
     - The universal compiler diagnostic catalog $`\mathcal{E}`$ shall be partitioned into exactly five mutually disjoint, gap-free numeric subranges indexed by 3-digit numeric codes:
       - Family 1: Ingestion & Lexer (`E0100`--`E0199`), covering Subsystem 1 and Subsystem 2. Representative diagnostics include `E0100` (Platform/bootstrap invariant violation), `E0102` (CommonMark table delimiter boundary fault), `E0103` (Tabular schema attribute/type/envelope parse error), `E0104` (Topological connection / port binding syntax error), and `E0199` (Diagnostic saturation limit reached).
       - Family 2: Metamodel & Typing (`E0200`--`E0299`), covering Subsystem 3, Subsystem 4, and Subsystem 9. Representative diagnostics include `E0200` (Metamodel lowering/grammar syntax error), `E0201` (Port directionality mismatch / invariant violation), `E0202` (Flow payload type or stream rate multiplicity violation), `E0203` (Metamodel inheritance cycle / circular dependency), `E0220` (Interface symmetry / dangling port error), `E0230` (Feature 3-layer Definition of Done structural violation), `E0231` (Isolated class / containment hierarchy violation), `E0232` (Use case alternate flow branching violation), and `E0299` (Metamodel arena capacity / identifier lookup failure).
       - Family 3: Metrology & Conservation (`E0300`--`E0399`), covering Subsystem 5 and Subsystem 8. Representative diagnostics include `E0300` (Rational vector space dimensional homogeneity violation in additive expressions), `E0301` (SI unit mismatch across interconnect signal flows), and `E0399` (Flow conservation network incidence matrix singularity / unresolvable Kirchhoff balance).
       - Family 4: Dynamics, State & Safety (`E0400`--`E0499`), covering Subsystem 6, Subsystem 7, Subsystem 8, and Subsystem 12. Representative diagnostics include `E0400` (Allen interval algebra temporal inconsistency / cyclic causal precedence), `E0406` (Non-linear proof obligation rejected / unhandled SMT theory), `E0440` (Failsafe default value domain validity assertion violation), `E0442` (Logical channel bandwidth utilization budget exceeded), `E0443` (Rate Monotonic Scheduling schedulability bound violation), `E0444` (Earliest Deadline First dynamic deadline violation), `E0451` (Worst-Case Execution Time interconnect latency path violation), and `E0499` (Traceability gate failure / STPA safety hazard invariant violation).
       - Family 5: Backend, Projections & Reverse-Synchronization (`E0500`--`E0599`), covering Subsystem 8, Subsystem 9, Subsystem 10, and Subsystem 11. Representative diagnostics include `E0500` (LUMI IR lowering / code generation violation / static memory layout breach), `E0502` (Bidirectional reverse-sync prose gate violation / protected markdown block divergence), and `E0599` (Artifact streaming sink / manifest persistence failure).
     - The taxonomy shall satisfy exact partition completeness ($`\bigcup_{i=1}^5 \mathcal{E}_i = \mathcal{E}`$`) and pairwise disjointness (`$`\mathcal{E}_i \cap \mathcal{E}_j = \emptyset`$` for all `$`i \ne j`$).
  2. **Bijective Source-Mapping Spans & Lexical Coordinate Architecture**:
     - Every diagnostic record $`D`$` shall capture a primary source span `$`\text{span}_{\text{primary}}`$` defined by a half-open byte interval `$`[b_{\text{start}}, b_{\text{end}})`$ bounded within the source buffer byte length:

```math
0 \le b_{\text{start}} \le b_{\text{end}} \le |B_{\text{source}}|
```

     - The diagnostic engine shall resolve byte offsets into 1-indexed human-readable coordinates:

```math
\langle \text{line}_{\text{start}}, \text{col}_{\text{start}}, \text{line}_{\text{end}}, \text{col}_{\text{end}} \rangle
```

     - Coordinate resolution shall query a precomputed line feed byte offset table $`\mathcal{L}_{\text{offsets}}`$` using binary search, achieving `$`O(\log |\mathcal{L}_{\text{offsets}}|)`$ temporal bound per diagnostic without rescanning source text.
     - The diagnostic engine shall support secondary highlight spans with label annotations ($`\mathcal{S}_{\text{secondary}}`$) to contextualize multi-location relationships (such as previous symbol declarations, opposing interface ports, or conflicting interval bounds).
  3. **Diagnostic Severity Tiers & Exit Status Contract**:
     - Every diagnostic record shall bind exactly one severity tier from the strictly ordered set:

```math
\mathcal{S}_{\text{tier}} = \{ \text{Fatal}, \text{Error}, \text{Warning}, \text{Info}, \text{Hint} \}
```

     - The severity tiers shall adhere to the filtering lattice:

```math
\text{Fatal} \succ \text{Error} \succ \text{Warning} \succ \text{Info} \succ \text{Hint}
```

     - Pass/Fail Execution Contract: If the accumulated diagnostic sink $`\mathcal{D}_{\text{sink}}`$` contains any diagnostic with severity `$`\text{Fatal}`$` or `$`\text{Error}`$`, the compiler shall fail closed and terminate with a non-zero exit status (`$`1`$).
     - Diagnostics with severity $`\text{Warning}`$`, `$`\text{Info}`$`, or `$`\text{Hint}`$` shall not alter exit status `$`0`$ unless the strict compiler flag `-Werror` is asserted, in which case any $`\text{Warning}`$` diagnostic triggers non-zero exit status (`$`1`$).
  4. **Machine-Readable Remediation Suggestions & Diff Replacement Architecture**:
     - Every diagnostic record $`D \in \mathcal{E}`$ shall bind an automated recovery suggestion mapping:

```math
\mu(D) = \langle [b_{\text{patch\_start}}, b_{\text{patch\_end}}), B_{\text{replacement}}, \kappa_{\text{conf}} \rangle
```

     - The replacement byte buffer $`B_{\text{replacement}}`$ shall provide machine-applicable suggested diff replacements enabling automated or interactive remediation.
     - The applicability confidence $`\kappa_{\text{conf}}`$ shall be categorized into:
       - `MachineApplicable`: Deterministic, unambiguous replacement that is mathematically guaranteed to resolve the diagnostic without altering semantics;
       - `MaybeIncorrect`: Heuristic suggestion that resolves the structural violation but requires engineer verification;
       - `HasPlaceholders`: Remediation containing synthetic abstract placeholders requiring user-supplied parameters.
     - Remediation diffs shall be serializable to standard unified diff patches and Language Server Protocol text edits (`WorkspaceEdit`).
  5. **Synchronization Token Error Recovery & Bounded Accumulation (Directive 4)**:
     - The compiler diagnostic engine and ingestion pipeline shall enforce Synchronization Token Error Recovery on structural delimiter boundaries $`\Sigma_{\text{sync}}`$ (statement semicolons `;`, closing braces `}`, markdown table row delimiters `|`, package delimiters `::`, and entity closing blocks) in accordance with REQ-0013 and REQ-0016.
     - When a syntax or semantic violation occurs, the engine shall record the diagnostic into preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, advance the lexer/parser cursor to the next synchronization token `$`\sigma \in \Sigma_{\text{sync}}`$, and resume AST construction.
     - Monotonic Error Accumulation: The error sink $`\mathcal{D}_{\text{sink}}`$` shall accumulate diagnostics up to a compile-time configurable upper bound `$`C_{\text{max\_errors}} \ge 100`$.
     - Diagnostic Saturation Gate: When $`|\mathcal{D}_{\text{sink}}| = C_{\text{max\_errors}}`$, the engine shall immediately synthesize and append terminal diagnostic `E0199` (`DiagnosticSaturationLimitReached`) and halt compilation gracefully, preventing runaway memory consumption and infinite cascading error reports.
  6. **Contextual Snippet Rendering & Dual Output Formats**:
     - Terminal Human-Readable Renderer: The diagnostic engine shall render formatted ASCII diagnostic blocks containing:
       - ANSI-highlighted severity badges (`error[E0201]`, `warning[E0442]`);
       - Workspace-relative file URI and coordinate header (`--> schema/package_0.sysml:14:8`);
       - Line number gutter and source text preview lines;
       - Primary caret underline (`^^^^`) identifying the exact fault span;
       - Secondary label pointers (`---- conflicting definition here`);
       - Remediation diff block (`help: replace with 'in'`);
     - Machine-Readable JSON/CBOR Stream: For headless CLI, language servers, and autonomous multi-agent pipelines, diagnostics shall be serializable to a canonical JSON array of structured diagnostic objects with zero byte loss.
  7. **Contiguous Bump Arena Memory Allocation & Node Addressing**:
     - All diagnostic descriptors, source span intervals, secondary annotation lists, and remediation patch buffers shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
     - Diagnostic entities shall be referenced exclusively by compact 32-bit arena node handles (REQ-0035), completely prohibiting raw heap pointers and cyclic reference graphs.
  8. **Deterministic Sorting & Deduplication Invariant**:
     - Prior to terminal emission or serialization, diagnostics in $`\mathcal{D}_{\text{sink}}`$ shall be deduplicated to eliminate identical error reports at the same source span.
     - Emitted diagnostics shall be sorted deterministically by source path, start byte offset, severity rank, and diagnostic error code in accordance with REQ-0003, ensuring 0-byte diff churn across consecutive compiler runs.
  9. **Reverse-Synchronization Prose Gate Binding (REQ-0192)**:
     - Diagnostic `E0502` shall be strictly bound to prose protection violations, tri-state reconciliation failures, and AST-to-prose divergence during reverse synchronization passes.
  10. **Enforcement of the 5 Executive Architectural Directives**:
      - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every diagnostic definition, catalog entry, and emitted diagnostic instance shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the fully qualified error descriptor ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(p) \mathbin{\Vert} \text{"::Diagnostic::"} \mathbin{\Vert} \text{code}(D) \mathbin{\Vert} \text{span}(D))`$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
      - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel multi-file diagnostic linting, syntax verification, and formatted diagnostic serialization shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
      - *Directive 3 (String Interner Memory Allocation Exception)*: Source file paths, diagnostic message strings, error symbols, and suggested replacement tokens shall be interned into the deduplicated global symbol interner pool during diagnostic emission in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
      - *Directive 4 (Synchronization Token Error Recovery)*: Enforce delimiter-based resynchronization, accumulation in $`\mathcal{D}_{\text{sink}}`$` up to capacity `$`C_{\text{max\_errors}}`$, and emission of terminal diagnostic `E0199` on saturation.
      - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: Production diagnostic engine code shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling and structured error propagation. Diagnostic emission latency (strictly under 25 ms for an architectural model containing $`10^4`$` AST nodes / `$`10^3`$ diagnostics) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  11. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Flow_A`, `param_x : Real`, `State_0`, `State_1`, `Step_0`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{E}`$ denote the universal set of compiler diagnostics supported by the compiler diagnostic catalog.
  All compiler diagnostics $`e \in \mathcal{E}`$ are partitioned into five mutually disjoint architectural ranges:

```math
\begin{aligned}
\mathcal{E}_{\text{ingest}} &= \{ e \in \mathcal{E} \mid 100 \le \text{code}(e) \le 199 \} \\
\mathcal{E}_{\text{type}} &= \{ e \in \mathcal{E} \mid 200 \le \text{code}(e) \le 299 \} \\
\mathcal{E}_{\text{metrology}} &= \{ e \in \mathcal{E} \mid 300 \le \text{code}(e) \le 399 \} \\
\mathcal{E}_{\text{dynamics}} &= \{ e \in \mathcal{E} \mid 400 \le \text{code}(e) \le 499 \} \\
\mathcal{E}_{\text{backend}} &= \{ e \in \mathcal{E} \mid 500 \le \text{code}(e) \le 599 \}
\end{aligned}
```

  satisfying partition completeness:

```math
\mathcal{E} = \mathcal{E}_{\text{ingest}} \cup \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{metrology}} \cup \mathcal{E}_{\text{dynamics}} \cup \mathcal{E}_{\text{backend}}
```

  and pairwise disjointness:

```math
\forall j, k \in \{ \text{ingest}, \text{type}, \text{metrology}, \text{dynamics}, \text{backend} \}, \quad j \ne k \implies \mathcal{E}_j \cap \mathcal{E}_k = \emptyset
```

  1. Diagnostic Record Formalization:
  An emitted diagnostic record $`D`$ is formalized as a 9-tuple:

```math
D = \langle \text{id}_D, c, s, p, \text{span}_{\text{primary}}, \mathcal{S}_{\text{secondary}}, \mu, \sigma, \Delta_D \rangle
```

  where:

```math
\begin{aligned}
\text{id}_D &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
c &\in [100, 599] \subset \mathbb{N} \quad (\text{standardized diagnostic error code}) \\
s &\in \{ \text{Fatal}, \text{Error}, \text{Warning}, \text{Info}, \text{Hint} \} \quad (\text{severity tier}) \\
p &\in \mathcal{S}_{\text{intern}} \quad (\text{workspace-relative canonical source path}) \\
\text{span}_{\text{primary}} &\in \mathcal{I}_{\text{span}} \quad (\text{primary source highlight span}) \\
\mathcal{S}_{\text{secondary}} &\subset \mathcal{I}_{\text{span}} \times \mathcal{S}_{\text{intern}} \quad (\text{finite set of secondary label annotations}) \\
\mu &\in \mathcal{T}_{\text{remediation}} \quad (\text{machine-readable suggested remediation patch}) \\
\sigma &\in \Sigma_{\text{sync}} \quad (\text{synchronization recovery token}) \\
\Delta_D &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor per REQ-0010})
\end{aligned}
```

  2. Source Coordinate & Half-Open Byte Interval Invariant:
  Each source span descriptor $`\text{span} \in \mathcal{I}_{\text{span}}`$ is defined as:

```math
\text{span} = \langle [b_{\text{start}}, b_{\text{end}}), \text{line}_{\text{start}}, \text{col}_{\text{start}}, \text{line}_{\text{end}}, \text{col}_{\text{end}} \rangle
```

  satisfying the boundary invariants:

```math
\begin{aligned}
0 \le b_{\text{start}} &\le b_{\text{end}} \le |B_{\text{source}}| \\
1 \le \text{line}_{\text{start}} &\le \text{line}_{\text{end}} \\
1 \le \text{col}_{\text{start}}, &\quad 1 \le \text{col}_{\text{end}}
\end{aligned}
```

  Let $`\mathcal{L}_{\text{offsets}} = [l_0, l_1, \dots, l_M]`$` denote the strictly increasing array of byte offsets corresponding to newline characters (`$`\text{SYM}_{\text{LF}}`$`) in the source buffer (`$`l_0 = 0`$`, `$`l_m \lt l_{m+1}`$).
  The line and column coordinates for any byte offset $`b \in [0, |B_{\text{source}}|]`$ evaluate deterministically:

```math
\begin{aligned}
\text{line}(b) &= \max \{ k \in \{1, \dots, M+1\} \mid l_{k-1} \le b \} \\
\text{col}(b) &= (b - l_{\text{line}(b)-1}) + 1
\end{aligned}
```

  3. Automated Remediation Mapping Invariant:
  Every diagnostic binds an automated recovery suggestion mapping:

```math
\mu : \mathcal{E} \to \mathcal{T}_{\text{remediation}}
```

  where a remediation record is formalized as:

```math
\mathcal{T}_{\text{remediation}} = \langle [b_{\text{patch\_start}}, b_{\text{patch\_end}}), B_{\text{replacement}}, \kappa_{\text{conf}} \rangle
```

  satisfying:

```math
0 \le b_{\text{patch\_start}} \le b_{\text{patch\_end}} \le |B_{\text{source}}|
```

```math
B_{\text{replacement}} \in \Sigma^*, \quad \kappa_{\text{conf}} \in \{ \text{MachineApplicable}, \text{MaybeIncorrect}, \text{HasPlaceholders} \}
```

  Applying remediation patch $`\mu(D)`$` to source buffer `$`B_{\text{source}}`$ transforms the byte sequence:

```math
\text{Apply}(\mu(D), B_{\text{source}}) = B_{\text{source}}[0 \dots b_{\text{patch\_start}}-1] \mathbin{\Vert} B_{\text{replacement}} \mathbin{\Vert} B_{\text{source}}[b_{\text{patch\_end}} \dots |B_{\text{source}}|-1]
```

  4. Error Accumulation & Saturation State Evolution (Directive 4):
  Let $`\mathcal{D}_k`$` denote the set of accumulated diagnostics at compilation step `$`k`$.
  The error accumulation state transition function evolves monotonically:

```math
\mathcal{D}_{k+1} = \begin{cases}
\mathcal{D}_k \cup \{ D_{k+1} \}, & \text{if } |\mathcal{D}_k| \lt C_{\text{max\_errors}} \\
\mathcal{D}_k \cup \{ D_{\text{term}} \}, & \text{if } |\mathcal{D}_k| = C_{\text{max\_errors}} \wedge \text{code}(D_{\text{term}}) = \text{E0199} \\
\mathcal{D}_k, & \text{if } |\mathcal{D}_k| \gt C_{\text{max\_errors}}
\end{cases}
```

  guaranteeing bounded heap allocation with saturation limit:

```math
C_{\text{max\_errors}} \ge 100, \quad |\mathcal{D}_{\text{sink}}| \le C_{\text{max\_errors}} + 1
```

  5. Severity Filtering Lattice & Exit Code Formulation:
  Let $`s(D)`$` denote the severity tier of diagnostic `$`D`$.
  The compiler process exit status evaluates deterministically:

```math
\text{ExitCode}(\mathcal{D}_{\text{sink}}) = \begin{cases}
1, & \text{if } \exists D \in \mathcal{D}_{\text{sink}} : s(D) \in \{ \text{Fatal}, \text{Error} \} \\
1, & \text{if } \exists D \in \mathcal{D}_{\text{sink}} : s(D) = \text{Warning} \wedge \text{Flag}_{\text{Werror}} \equiv \text{true} \\
0, & \text{otherwise}
\end{cases}
```

  6. Deterministic RFC 4122 UUIDv5 Diagnostic Anchor (Directive 1):
  Every diagnostic record binds a deterministic UUIDv5 identifier:

```math
\Delta_D = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, p \mathbin{\Vert} \text{"::Diagnostic::"} \mathbin{\Vert} \text{to\_string}(c) \mathbin{\Vert} \text{to\_string}(b_{\text{start}}) \mathbin{\Vert} \text{to\_string}(b_{\text{end}}))
```

  7. Deterministic Total Ordering Invariant:
  Diagnostics within $`\mathcal{D}_{\text{sink}}`$` are ordered deterministically by relation `$`\prec`$:

```math
D_a \prec D_b \iff \begin{aligned}
&(p_a \lt p_b) \vee \\
&(p_a = p_b \wedge b_{\text{start}, a} \lt b_{\text{start}, b}) \vee \\
&(p_a = p_b \wedge b_{\text{start}, a} = b_{\text{start}, b} \wedge b_{\text{end}, a} \lt b_{\text{end}, b}) \vee \\
&(p_a = p_b \wedge b_{\text{start}, a} = b_{\text{start}, b} \wedge b_{\text{end}, a} = b_{\text{end}, b} \wedge c_a \lt c_b)
\end{aligned}
```

  8. Representative Diagnostic Rules & Error Taxonomy Mappings:

```math
\begin{aligned}
\text{DelimFault}(\text{tok}) &\implies D(E0102, \text{Error}, \text{span}(\text{tok}), \text{DelimRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{TypeSyntaxErr}(\tau) &\implies D(E0103, \text{Error}, \text{span}(\tau), \text{TypeRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{PortMismatch}(p_1, p_2) &\implies D(E0201, \text{Error}, \text{span}(p_1), \text{PortInvertRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{Cycles}(\mathcal{G}_{\text{type}}) \ne \emptyset &\implies D(E0203, \text{Error}, \text{span}(\text{node}), \text{CycleBreakRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{HomogeneityErr}(e_1, e_2) &\implies D(E0300, \text{Error}, \text{span}(e_1), \text{UnitConvertRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{TemporalInconsistent}(\mathcal{A}) &\implies D(E0400, \text{Error}, \text{span}(\mathcal{A}), \text{AllenIntervalRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{NonLinearSMT}(\phi) &\implies D(E0406, \text{Error}, \text{span}(\phi), \text{LinearizeRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{ReverseSyncConflict}(blk) &\implies D(E0502, \text{Error}, \text{span}(blk), \text{ProseProtectRecovery}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies D(E0199, \text{Fatal}, \text{span}_{\text{eof}}, \text{HaltRecovery}) \in \mathcal{D}_{\text{sink}}
\end{aligned}
```

- **Computational Complexity & Algorithmic Bounds**: Standardized Compiler Diagnostic Taxonomy, Source-Mapping & Recovery Architecture resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in strictly deterministic linear time $`O(|B_{\text{source}}| + |\mathcal{D}_{\text{sink}}| \log |\mathcal{D}_{\text{sink}}|)`$` and linear space `$`O(|B_{\text{source}}| + |\mathcal{D}_{\text{sink}}|)`$` over the source buffer length `$`|B_{\text{source}}|`$` and aggregate accumulated diagnostic count `$`|\mathcal{D}_{\text{sink}}|`$.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 resolves temporal interval consistency over occurrence lifecycles using Allen's 13 qualitative interval relations via ORD-Horn SMT difference logic in $`O(N^3)`$ polynomial time. In contrast, REQ-0191 provides diagnostic reporting and taxonomy classification for temporal violations (such as `E0400`) in $`O(1)`$ constant time per diagnostic record, without performing interval algebra path consistency propagation or constraint satisfaction solving.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses strongly NP-hard vector bin packing for structural allocation and interconnect channel multiplexing. In contrast, REQ-0191 assigns integer error codes to the 5-family taxonomy via simple interval membership checks in $`O(1)`$ operations, requiring zero multi-dimensional knapsack solvers or branch-and-bound searches.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 formalizes subtyping lattice redefinition and multiple inheritance resolution via C3 linearization in $`O(V + E)`$ time. In contrast, REQ-0191 consumes already-resolved AST typing diagnostics (`E0200`--`E0299`) and formats error traces without traversing poset hierarchies or constructing class precedence lists.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0191 accumulates safety violation diagnostics (`E0499`) in a preallocated linear buffer and executes deterministic deduplication in $`O(|\mathcal{D}| \log |\mathcal{D}|)`$ time, without combinatorial hitting set minimization.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking). In contrast, REQ-0191 formats and emits diagnostics produced by state solvers in $`O(1)`$ operations per state violation, without exploring state-space Cartesian product explosions or unrolling transition relations.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks using linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0191 records metrology and flow conservation diagnostics (`E0300`--`E0399`) and resynchronizes on lexical tokens in $`O(1)`$ steps without continuous Kirchhoff flow network matrix pivoting.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 formalizes global register allocation (Chaitin Graph $`K`$`-Coloring, NP-complete) and basic block scheduling in LUMI IR. In contrast, REQ-0191 allocates diagnostic records sequentially in contiguous bump arena storage in `$`O(1)`$ amortized time per record, requiring zero interference graph coloring or register spilling algorithms.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves satisfiability of first-order invariant contracts via DPLL(T) SMT solvers. In contrast, REQ-0191 formats proof rejection diagnostics (`E0406`) into structured error messages and remediation suggestions in linear time proportional to formula string length, without performing symbolic reasoning or SAT/SMT search.

  **Asymptotic Complexity Analysis**:
  Let $`N_B = |B_{\text{source}}|`$` denote the source file byte length, `$`N_L = |\mathcal{L}_{\text{offsets}}|`$` denote the number of lines, `$`N_D = |\mathcal{D}_{\text{sink}}|`$` denote the number of accumulated diagnostics (`$`N_D \le C_{\text{max\_errors}} + 1`$`), and `$`N_{\text{bytes}}`$ denote total formatted diagnostic output bytes.
  1. *Newline Offset Index Construction Phase*:
     - Scanning the source buffer once to populate the newline byte offset index $`\mathcal{L}_{\text{offsets}}`$ executes in deterministic linear time:

```math
T_{\text{index}}(N_B) \in O(N_B), \quad S_{\text{index}} \in O(N_L)
```

  2. *Diagnostic Creation & Taxonomy Classification Phase*:
     - Classifying an error code $`c`$ into its corresponding architectural family requires at most 5 range comparisons, executing in strictly constant time:

```math
T_{\text{classify}} \in O(1), \quad S_{\text{classify}} \in O(1)
```

  3. *Coordinate Resolution Phase (Binary Search)*:
     - Deriving $`\langle \text{line}, \text{col} \rangle`$` coordinates from byte offset `$`b`$` via binary search on `$`\mathcal{L}_{\text{offsets}}`$ executes in logarithmic time:

```math
T_{\text{coord}}(N_L) \in O(\log N_L), \quad S_{\text{coord}} \in O(1)
```

     - For $`N_D`$` diagnostics, total coordinate resolution time is `$`O(N_D \log N_L)`$.
  4. *Monotonic Accumulation & Deduplication Phase*:
     - Appending each diagnostic to contiguous arena storage executes in $`O(1)`$ time.
     - Sorting diagnostics by canonical relation $`\prec`$ for deterministic deduplication executes in:

```math
T_{\text{sort}}(N_D) \in O(N_D \log N_D), \quad S_{\text{sort}} \in O(N_D)
```

     - Because $`N_D`$` is bounded by constant `$`C_{\text{max\_errors}} + 1`$` (e.g., `$`101`$`), `$`T_{\text{sort}}`$` is bounded by a small constant `$`O(1)`$.
  5. *Automated Remediation Diff Generation Phase*:
     - Synthesizing replacement byte buffers and computing diff text executes in linear time proportional to replacement size:

```math
T_{\text{patch}} \in O(|B_{\text{replacement}}|)
```

  6. *Contextual ASCII & JSON Rendering Phase*:
     - Rendering formatted terminal snippets or serializing JSON streams executes in deterministic linear time:

```math
T_{\text{render}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{render}} \in O(N_{\text{bytes}})
```

  7. *Aggregate System Complexity*:
     - Summing across all phases, total wall-clock runtime is bounded by:

```math
T_{\text{total}} \in O(N_B + N_D \log N_L + N_D \log N_D + N_{\text{bytes}})
```

     - Total space complexity is strictly $`O(N_B + N_D + N_{\text{bytes}})`$ in contiguous bump arena storage, requiring zero individual heap allocations.
  8. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning multi-file diagnostic linting and formatted text rendering across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool achieves near-linear speedup:

```math
T_{\text{parallel}} \in O\left( \frac{N_B + N_D \log N_D + N_{\text{bytes}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```
