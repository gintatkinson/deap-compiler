### REQ-0195: Unified Headless CLI Architecture & Deterministic Subcommand Interface

- **Normative Statement**: The command-line interface entry point, argument parser, subcommand dispatcher, stream serialization controller, and execution supervisor of Subsystem 12 shall provide a unified, headless command-line interface (CLI) executing deterministic subcommands with standard Unix exit codes, bijectively partitioned standard output (`stdout`) and standard error (`stderr`) streams, and structured JSON output streams for fully automated continuous integration, autonomous multi-agent swarm dispatch, and batch compilation pipelines. The compiler CLI shall enforce complete decoupling from interactive terminal (TTY) devices, strictly eliminating interactive prompts, paging interruptions, terminal control escape sequences, and terminal dimension queries during execution. The CLI entry point shall act as a pure deterministic mapping over the argument token vector $\mathbf{a} \in \mathcal{A}_{\text{args}}$ and isolated execution environment $\mathbf{e} \in \mathcal{E}_{\text{env}}$, guaranteeing bitwise identical output payloads and identical exit codes across repeated invocations on identical inputs.

  Specifically, the compiler CLI architecture, subcommand dispatch engine, and stream formatting pipeline shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Deterministic Subcommand Dispatch Architecture**:
     - The CLI shall expose a canonical set of deterministic subcommands:
       - `compile`: Ingests source schema units, constructs metamodel ASTs, executes type and dimensional verification, lowers to intermediate representation, and persists generated artifacts;
       - `check`: Ingests source units and executes lexical, syntactic, metamodel typing, and physical conservation validation without writing downstream code artifacts;
       - `slice`: Ingests source units and extracts context-bounded AST subgraphs (`query_slice`) with explicit dependency envelopes for token-isolated subagent dispatch in accordance with REQ-0049 and REQ-0050;
       - `emit`: Parses and lowers input schemas, emitting canonical SysML v2 textual models (`schema/model.sysml`) with deterministic qualified-name symbol sorting in accordance with REQ-0031 and REQ-0032;
       - `sync`: Executes bidirectional reverse-sync prose gate reconciliation in accordance with REQ-0192, verifying prose section hash invariance and preventing divergence;
       - `export`: Emits downstream projections including Level 1C Interface Control Document tables (REQ-0145), BDD Gherkin user stories (REQ-0169), and code generation manifests (REQ-0178).
     - Subcommand dispatch shall be strictly order-independent with respect to flag positioning, matching subcommand tokens via deterministic symbol interner lookups.
  2. **Standard Unix Exit Code Contract**:
     - The CLI execution supervisor shall terminate exclusively with standard Unix exit codes:
       - Exit Code `0` (`Success`): Compilation or subcommand execution completed successfully with zero fatal errors and zero errors ($|\mathcal{D}_{\text{fatal}}| = 0 \wedge |\mathcal{D}_{\text{error}}| = 0$);
       - Exit Code `1` (`CompilationFailure`): Semantic validation, invariant check, or compilation failed with one or more fatal or error diagnostics ($|\mathcal{D}_{\text{fatal}}| + |\mathcal{D}_{\text{error}}| \gt 0$), or one or more warning diagnostics when strict warning escalation (`-Werror` or `--strict`) is asserted;
       - Exit Code `2` (`UsageOrInvocationError`): Command-line argument syntax error, unknown subcommand, unrecognized option flag, or missing mandatory path parameter.
     - Unhandled panics, segmentation faults, and abnormal abort signals (`SIGABRT`, `SIGSEGV`, `SIGILL`) are strictly prohibited across all exit paths in accordance with REQ-0011.
  3. **Bijective Stream Partitioning & TTY Decoupling**:
     - The CLI shall strictly segregate machine-readable payload data and compiler diagnostic reporting across the standard process output streams:
       - Standard Output (`stdout`): Dedicated exclusively to primary command output payloads, including serialized AST slices, canonical SysML v2 models, generated code manifests, and structured JSON telemetry. When redirected to a pipe or file, `stdout` shall emit purely the requested payload without diagnostic contamination;
       - Standard Error (`stderr`): Dedicated exclusively to structured compiler diagnostics, source-mapped error snippets, progress milestones, and execution summaries.
     - Headless Execution Guarantee: The CLI shall never query terminal dimensions (`ioctl(TIOCGWINSZ)`), spawn interactive pagers (`less`, `more`), or emit terminal cursor control sequences (`\x1b[...`) unless explicitly requested via `--color=always`. In default and headless pipeline environments, all diagnostic text shall be rendered in clean, printable ASCII.
  4. **Structured JSON Output Stream Contract (`--format=json`)**:
     - When the CLI is invoked with `--format=json` or `--format=cbor`, standard output shall emit a canonical, machine-readable JSON root object containing:
       - `schema_version`: String identifying the canonical JSON CLI schema version;
       - `subcommand`: Interned string token of the executed subcommand;
       - `exit_code`: Integer exit code (`0`, `1`, or `2`);
       - `execution_id`: Deterministic RFC 4122 UUIDv5 anchor string (Directive 1);
       - `metrics`: Object detailing wall-clock latency in microseconds, peak memory RSS in bytes, input file count, and AST node count;
       - `artifacts`: Array of emitted artifact records containing relative file path, byte length, and XXH3 64-bit content digest (REQ-0178);
       - `diagnostics`: Array of structured diagnostic objects conforming to the 5-family taxonomy of REQ-0191.
  5. **Standard Input (`stdin`) Pipeline Composability**:
     - The CLI shall support reading schema models from standard input when a hyphen (`-`) is supplied as the input path argument (e.g., `cat input_0.sysml | deap compile -`).
     - Standard input streaming shall integrate with the bounded streaming artifact sink interface (REQ-0177), processing input bytes in bounded chunks without loading unbounded streams into contiguous unmanaged heap memory.
  6. **Contiguous Arena Memory Storage & Node Handle Addressing**:
     - All CLI argument token descriptors, parsed flag collections, subcommand dispatch routes, and output stream buffers shall reside in contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
     - Entities shall be addressed exclusively via stable 32-bit arena node handles (REQ-0035), prohibiting raw pointers and cyclic heap graph allocations.
  7. **Deterministic Sorting & Output Stream Reproducibility**:
     - Serialized JSON keys, diagnostic arrays, symbol manifests, and artifact rosters emitted by the CLI shall be sorted deterministically in lexicographical order.
     - Consecutive executions of the CLI on identical schema models under identical arguments shall produce bitwise identical byte streams on both `stdout` and `stderr` ($\Delta \text{Stream} \equiv 0$).
  8. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every CLI execution session, output manifest, and generated telemetry record shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID, the canonical subcommand string, and the cryptographic content digest of input schemas ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{Cmd} \mathbin{\Vert} \text{"::CLI::"} \mathbin{\Vert} \text{XXH3}_{64}(\text{Inputs}))$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel compilation passes, multi-file validation, AST slicing, and artifact emission shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $N_{\text{max\_workers}}$ (configured via `--jobs <N>`) in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Subcommand tokens, option flag names, argument values, source file paths, and environment variable keys shall be copied from argv into the global deduplicated symbol interner pool during CLI argument parsing in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The CLI execution supervisor shall enforce Synchronization Token Error Recovery across multiple input files and compilation passes (REQ-0013, REQ-0016), accumulating diagnostics in preallocated error sink $\mathcal{D}_{\text{sink}}$ up to capacity $C_{\text{max\_errors}}$, emitting terminal diagnostic `E0199` on saturation.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: Production CLI binaries shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Compilation latency (strictly under 25 ms for models up to 10,000 AST nodes) and peak RSS memory (strictly under 100 MB RSS) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  9. **Pure Abstract MBSE Placeholder Mandate**:
     - All CLI diagnostic messages, usage examples, test suites, and schema references shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Flow_A`, `param_x : Real`, `Subcommand_0`, `Model_0`, `input_0.sysml`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{A}_{\text{args}} = \bigcup_{k=1}^\infty (\Sigma^*)^k$ denote the set of all finite command-line argument token sequences $\mathbf{a} = \langle a_0, a_1, \dots, a_{k-1} \rangle$, and let $\mathcal{E}_{\text{env}} = \langle \mathcal{F}_{\text{fs}}, \mathcal{P}_{\text{cwd}}, \mathcal{V}_{\text{env}}, \mathcal{S}_{\text{stdin}} \rangle$ denote the execution environment tuple comprising filesystem state $\mathcal{F}_{\text{fs}}$, current working directory path $\mathcal{P}_{\text{cwd}}$, process environment variables $\mathcal{V}_{\text{env}}$, and standard input stream $\mathcal{S}_{\text{stdin}}$.

  The CLI entry point is formalized as a pure total deterministic function:

$$
\text{CLI} : \mathcal{A}_{\text{args}} \times \mathcal{E}_{\text{env}} \longrightarrow \langle \text{ExitCode}, \text{Stdout}, \text{Stderr} \rangle
$$

  1. Subcommand Argument Parsing & Dispatch:
  The argument parsing operator $\text{ParseArgs} : \mathcal{A}_{\text{args}} \to \text{Result}(\langle \text{Cmd}, \Omega_{\text{flags}}, \mathcal{P}_{\text{in}}, \mathcal{P}_{\text{out}} \rangle, D_{\text{cli}})$ extracts the subcommand and options:

$$
\text{Dispatch}(\mathbf{a}) = \begin{cases}
\langle \text{Cmd}, \Omega_{\text{flags}}, \mathcal{P}_{\text{in}}, \mathcal{P}_{\text{out}} \rangle, & \text{if } \text{ValidSyntax}(\mathbf{a}) \equiv \text{true} \\
\langle \bot_{\text{cmd}}, \emptyset, \emptyset, \emptyset \rangle, & \text{if } \text{ValidSyntax}(\mathbf{a}) \equiv \text{false}
\end{cases}
$$

  where:

$$
\text{Cmd} \in \{ \text{compile}, \text{check}, \text{slice}, \text{emit}, \text{sync}, \text{export}, \text{help}, \text{version} \}
$$

$$
\Omega_{\text{flags}} \subset \{ \text{Flag}_{\text{format}}, \text{Flag}_{\text{Werror}}, \text{Flag}_{\text{jobs}}, \text{Flag}_{\text{slice\_depth}}, \text{Flag}_{\text{quiet}} \}
$$

  2. Deterministic Unix Exit Code Evaluation:
  Let $\mathcal{D}_{\text{sink}}$ denote the set of accumulated diagnostics generated during execution, partitioned by severity tier $\mathcal{S}_{\text{tier}} = \{ \text{Fatal}, \text{Error}, \text{Warning}, \text{Info}, \text{Hint} \}$:

$$
\begin{aligned}
\mathcal{D}_{\text{fatal}} &= \{ d \in \mathcal{D}_{\text{sink}} \mid \text{severity}(d) = \text{Fatal} \} \\
\mathcal{D}_{\text{error}} &= \{ d \in \mathcal{D}_{\text{sink}} \mid \text{severity}(d) = \text{Error} \} \\
\mathcal{D}_{\text{warning}} &= \{ d \in \mathcal{D}_{\text{sink}} \mid \text{severity}(d) = \text{Warning} \}
\end{aligned}
$$

  The exit code is evaluated deterministically by the piecewise total function:

$$
\text{ExitCode}(\mathbf{a}, \mathbf{e}) = \begin{cases}
0, & \text{if } \text{ValidSyntax}(\mathbf{a}) \wedge |\mathcal{D}_{\text{fatal}}| = 0 \wedge |\mathcal{D}_{\text{error}}| = 0 \wedge (|\mathcal{D}_{\text{warning}}| = 0 \vee \neg \text{Flag}_{\text{Werror}}) \\
1, & \text{if } \text{ValidSyntax}(\mathbf{a}) \wedge (|\mathcal{D}_{\text{fatal}}| + |\mathcal{D}_{\text{error}}| \gt 0 \vee (|\mathcal{D}_{\text{warning}}| \gt 0 \wedge \text{Flag}_{\text{Werror}})) \\
2, & \text{if } \neg \text{ValidSyntax}(\mathbf{a}) \vee \text{UnknownSubcommand}(\mathbf{a}) \vee \text{MissingRequiredArg}(\mathbf{a})
\end{cases}
$$

  3. Stream Partitioning & Serialization:
  Let $\mathcal{O}_{\text{stdout}}$ and $\mathcal{O}_{\text{stderr}}$ denote the stream formatting operators parameterized by output format flag $\tau_{\text{fmt}} \in \{ \text{Text}, \text{JSON}, \text{CBOR} \}$:

$$
\begin{aligned}
\text{Stdout}(\mathbf{a}, \mathbf{e}) &= \mathcal{O}_{\text{stdout}}(\text{ResultPayload}, \tau_{\text{fmt}}) \\
\text{Stderr}(\mathbf{a}, \mathbf{e}) &= \mathcal{O}_{\text{stderr}}(\mathcal{D}_{\text{sink}}, \tau_{\text{fmt}})
\end{aligned}
$$

  For structured JSON formatting ($\tau_{\text{fmt}} = \text{JSON}$):

$$
\text{Stdout}(\mathbf{a}, \mathbf{e}) = \text{SerializeJSON}\left( \left\langle \text{schema\_version}, \text{Cmd}, \text{ExitCode}, \Delta_{\text{exec}}, \mathcal{M}_{\text{telemetry}}, \mathcal{A}_{\text{manifest}} \right\rangle \right)
$$

$$
\text{Stderr}(\mathbf{a}, \mathbf{e}) = \text{SerializeJSON}\left( \mathcal{D}_{\text{sink}} \right)
$$

  4. Headless & TTY Independence Invariant:
  Let $\text{IsTTY}(\sigma) \in \{0, 1\}$ denote the terminal device binding predicate for stream $\sigma \in \{ \text{stdin}, \text{stdout}, \text{stderr} \}$.
  The CLI execution invariant requires identical output strings regardless of terminal presence:

$$
\forall \sigma \in \{ \text{stdin}, \text{stdout}, \text{stderr} \}, \quad \forall \tau \in \{0, 1\}, \quad \text{CLI}(\mathbf{a}, \mathbf{e} \mid \text{IsTTY}(\sigma) = \tau) \equiv \text{CLI}(\mathbf{a}, \mathbf{e} \mid \text{IsTTY}(\sigma) = 0)
$$

  Interactive terminal input queries evaluate to identically zero:

$$
\text{InteractivePrompts}(\text{CLI}) \equiv 0
$$

  5. Bitwise Reproducibility & Zero Diff Churn Invariant:
  For any two independent compilation executions with identical argument vectors $\mathbf{a}_1 = \mathbf{a}_2$ and identical environment inputs $\mathbf{e}_1 = \mathbf{e}_2$:

$$
\begin{aligned}
\text{ExitCode}(\mathbf{a}_1, \mathbf{e}_1) &= \text{ExitCode}(\mathbf{a}_2, \mathbf{e}_2) \\
\text{Stdout}(\mathbf{a}_1, \mathbf{e}_1) &= \text{Stdout}(\mathbf{a}_2, \mathbf{e}_2) \\
\text{Stderr}(\mathbf{a}_1, \mathbf{e}_1) &= \text{Stderr}(\mathbf{a}_2, \mathbf{e}_2)
\end{aligned}
$$

  6. Deterministic RFC 4122 UUIDv5 Execution Anchor Invariant (Directive 1):
  Every CLI invocation session binds an immutable deterministic RFC 4122 UUIDv5 identifier:

$$
\Delta_{\text{exec}} = \text{UUIDv5}\left( \text{OID}_{\text{DEAP}}, \, \text{to\_string}(\text{Cmd}) \mathbin{\Vert} \text{"::CLI::"} \mathbin{\Vert} \text{to\_string}\left( \text{XXH3}_{64}\left( \bigodot_{p \in \mathcal{P}_{\text{in}}} \text{ReadBytes}(p) \right) \right) \right)
$$

  7. Bounded Work-Stealing Parallel Concurrency Invariant (Directive 2):
  Let $N_{\text{workers}}$ denote the worker thread pool allocation:

$$
N_{\text{workers}} = \begin{cases}
\max\left( 1, \min\left( \text{Flag}_{\text{jobs}}, N_{\text{max\_workers}} \right) \right), & \text{if } \text{Flag}_{\text{jobs}} \text{ is supplied} \\
\min\left( N_{\text{cpus}}, N_{\text{max\_workers}} \right), & \text{otherwise}
\end{cases}
$$

  guaranteeing strict worker thread bounds:

$$
1 \le N_{\text{workers}} \le N_{\text{max\_workers}} \lt \infty
$$

  8. Diagnostic Saturation & Terminal Recovery Invariant (Directive 4):
  Let $\mathcal{D}_k$ denote the set of accumulated diagnostics at compilation step $k$:

$$
\mathcal{D}_{k+1} = \begin{cases}
\mathcal{D}_k \cup \{ D_{k+1} \}, & \text{if } |\mathcal{D}_k| \lt C_{\text{max\_errors}} \\
\mathcal{D}_k \cup \{ D_{\text{term}} \}, & \text{if } |\mathcal{D}_k| = C_{\text{max\_errors}} \wedge \text{code}(D_{\text{term}}) = \text{E0199} \\
\mathcal{D}_k, & \text{if } |\mathcal{D}_k| \gt C_{\text{max\_errors}}
\end{cases}
$$

  9. Representative Diagnostic Trigger Mappings (REQ-0191):

$$
\begin{aligned}
\neg \text{ValidSyntax}(\mathbf{a}) &\implies D(\text{E0100}, \text{Error}, \text{span}(\mathbf{a}), \text{UsageHelpRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{UnknownSubcommand}(\mathbf{a}) &\implies D(\text{E0100}, \text{Error}, \text{span}(\mathbf{a}), \text{CommandListRecovery}) \in \mathcal{D}_{\text{sink}} \\
\neg \text{FileExists}(p) &\implies D(\text{E0100}, \text{Error}, \text{span}(p), \text{FilePathRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{TableDelimiterFault}(t) &\implies D(\text{E0102}, \text{Error}, \text{span}(t), \text{DelimRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{MetamodelCycle}(\mathcal{G}) &\implies D(\text{E0203}, \text{Error}, \text{span}(\mathcal{G}), \text{CycleBreakRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{DimensionIncompatible}(u_1, u_2) &\implies D(\text{E0300}, \text{Error}, \text{span}(u_1), \text{UnitConvertRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{TemporalInconsistent}(\mathcal{T}) &\implies D(\text{E0400}, \text{Error}, \text{span}(\mathcal{T}), \text{IntervalRecovery}) \in \mathcal{D}_{\text{sink}} \\
\text{ProseDivergence}(b) &\implies D(\text{E0502}, \text{Error}, \text{span}(b), \text{ProseProtectRecovery}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies D(\text{E0199}, \text{Fatal}, \text{span}_{\text{eof}}, \text{HaltRecovery}) \in \mathcal{D}_{\text{sink}}
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Unified Headless CLI Architecture and Deterministic Subcommand Interface resides strictly in **Complexity Class P** (Deterministic Polynomial Time), executing in strictly deterministic linear time $O(K + N_{\text{bytes}})$ and linear space $O(K + N_{\text{bytes}})$ over the aggregate command-line argument token length $K = \sum_{i=0}^{k-1} |a_i|$ and the total serialized stream output bytes $N_{\text{bytes}}$, adding strictly under $1.0\text{ ms}$ of wall-clock infrastructure latency overhead to the compiler pipeline.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 resolves temporal interval consistency over occurrence lifecycles using Allen's 13 qualitative interval relations via ORD-Horn SMT difference logic in $O(N^3)$ polynomial time. In contrast, REQ-0195 parses CLI arguments, dispatches subcommands, and formats exit status in $O(K)$ linear time, delegating temporal solving to Subsystem 6 without constructing temporal constraint graphs or executing interval path consistency propagation.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses strongly NP-hard vector bin packing for structural allocation and interconnect channel multiplexing. In contrast, REQ-0195 processes allocation flags (such as `--jobs` or `--slice-depth`) via direct scalar integer parsing in $O(1)$ operations, requiring zero multi-dimensional knapsack formulations or branch-and-bound searches.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 formalizes subtyping lattice redefinition and multiple inheritance resolution via monotonic C3 linearization in $O(V + E)$ time. In contrast, REQ-0195 handles command-line arguments and routes exit codes without traversing metamodel poset hierarchies or evaluating subtyping relationships.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions. In contrast, REQ-0195 invokes safety analysis as an opaque compiler phase, serializing emitted safety reports to `stdout` in linear time proportional to output size without computing minimal set covers.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes discrete state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking). In contrast, REQ-0195 operates as a headless CLI supervisor, executing deterministic process dispatch without state-space Cartesian product exploration or transition relation unrolling.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched conservative flow networks using linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0195 ingests file paths and formats structured streams in $O(1)$ amortized steps per token without formulating matrix complementarity equations.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 formalizes global register allocation (Chaitin Graph $K$-Coloring, NP-complete) and basic block scheduling in LUMI IR. In contrast, REQ-0195 manages process lifecycle, stream redirection, and exit codes in linear time $O(K)$, completely downstream of intermediate representation register allocation.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves the satisfiability of first-order invariant contracts via DPLL(T) SMT solvers. In contrast, REQ-0195 wraps backend solver invocations with deterministic timeout bounds and formats verification results into structured JSON records without performing symbolic quantifier elimination or first-order logic reasoning.

  **Algorithmic Breakdown & Asymptotic Bounds**:
  Let $K = \sum_{i=0}^{k-1} |a_i|$ denote total CLI argument byte length, $N_{\text{units}} = |\mathcal{P}_{\text{in}}|$ denote input compilation unit count, $N_{\text{diag}} = |\mathcal{D}_{\text{sink}}|$ denote accumulated diagnostic count ($N_{\text{diag}} \le C_{\text{max\_errors}} + 1$), and $N_{\text{bytes}}$ denote total formatted output bytes.
  1. *Command-Line Token Lexing & Flag Extraction Phase*:
     - Lexing $k$ argument tokens and matching flag identifiers against pre-interned strings in contiguous arena storage executes in linear time:
       $$T_{\text{lex}}(K) \in O(K), \quad S_{\text{lex}}(K) \in O(K)$$
  2. *Subcommand Route Dispatch Phase*:
     - Resolving subcommand token $\text{Cmd}$ via static dispatch lookup executes in strictly constant time:
       $$T_{\text{disp}} \in O(1), \quad S_{\text{disp}} \in O(1)$$
  3. *Work-Stealing Parallel Task Scheduling Phase (Directive 2)*:
     - Partitioning $N_{\text{units}}$ input compilation units across $N_{\text{workers}}$ threads on a bounded work-stealing thread pool incurs scheduling overhead:
       $$T_{\text{sched}} \in O\left( \frac{N_{\text{units}}}{N_{\text{workers}}} + \log N_{\text{workers}} \right), \quad S_{\text{sched}} \in O(N_{\text{workers}})$$
  4. *Diagnostic Accumulation & Exit Status Resolution Phase*:
     - Sifting $N_{\text{diag}}$ accumulated diagnostics to determine severity extrema executes in deterministic linear time:
       $$T_{\text{sift}}(N_{\text{diag}}) \in O(N_{\text{diag}}), \quad S_{\text{sift}} \in O(1)$$
     - Because $N_{\text{diag}}$ is strictly bounded by constant $C_{\text{max\_errors}} + 1$ (e.g., $101$), $T_{\text{sift}}$ evaluates to strictly constant time $O(1)$.
  5. *Structured Stream Formatting & Serialization Phase*:
     - Serializing output payloads to JSON or CBOR streams on `stdout` and diagnostic summaries on `stderr` executes in deterministic linear time:
       $$T_{\text{serialize}}(N_{\text{bytes}}) \in O(N_{\text{bytes}}), \quad S_{\text{serialize}} \in O(N_{\text{bytes}})$$
  6. *Aggregate CLI Infrastructure Bound*:
     - Summing across all CLI phases, the total wall-clock latency overhead $T_{\text{cli}}$ introduced by the CLI entry point satisfies:
       $$T_{\text{cli}} \in O(K + N_{\text{bytes}})$$
     - Empirical and formal profiling confirms $T_{\text{cli}} \lt 1.0\text{ ms}$, ensuring that CLI infrastructure consumes less than 4% of the 25 ms compilation latency budget specified in REQ-0011 and REQ-0196.
