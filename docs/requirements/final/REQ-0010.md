### REQ-0010: Deterministic RFC 4122 UUIDv5 Topological Namespace Hashing

- **Normative Statement**: The compiler platform shall generate all synthetic entity identifiers, specification document anchors (including Epics, Features, User Stories, and Use Cases), intermediate representation node handles, and downstream artifact unique keys exclusively via deterministic RFC 4122 UUIDv5 namespace hashing. In accordance with Architectural Directive 1, all references to time-based UUIDs (such as UUIDv1, UUIDv6, or UUIDv7) and pseudo-random UUIDs (such as UUIDv4) are strictly prohibited across all compiler passes, preventing entropy injection and preserving bitwise reproducibility and cryptographic Merkle root digests. The hashing engine shall take as input a fixed compiler namespace UUID constant ($`\text{NS}_{\text{DEAP}}`$`) and the canonical fully qualified topological path string of the entity (`$`\mathcal{N}_{\text{topological}}`$), structured from the hierarchical AST containment hierarchy (e.g., `Package_0::Subsystem_Alpha::Classifier_Beta`). Canonical topological path strings shall strictly use uniform scope delimiters (`::`), case-sensitive ASCII representation, and abstract entity naming without host-dependent or absolute filesystem path prefixes, file system mount roots, or runtime process descriptors. The UUIDv5 computation shall compute the SHA-1 cryptographic digest of the concatenation of the 16 namespace UUID octets in network byte order and the UTF-8 encoded canonical path string. The resulting 160-bit digest shall be truncated and transformed into a 128-bit UUID by setting the version field bits (the four most significant bits of octet 6) to $`0101_2`$` (Version 5) and the variant field bits (the two most significant bits of octet 8) to `$`10_2`$ (RFC 4122 / Leach-Salz variant). All emitted string representations shall conform to the canonical 36-character hyphenated lowercase hexadecimal format (`8-4-4-4-12`). Identifiers must remain strictly invariant across execution environments, CPU architectures, endianness, host operating systems, filesystem mount points, thread allocations within the bounded work-stealing pool, and physical build timestamps.

- **Formal Invariant**: Let $`\text{NS}_{\text{DEAP}} \in \{0, 1\}^{128}`$` denote the fixed 128-bit RFC 4122 namespace UUID constant in canonical big-endian network byte order. Let `$`\mathcal{N}_{\text{topological}}(v) \in \Sigma^*`$` denote the canonical fully qualified topological path of an AST node or specification element `$`v \in \mathcal{V}`$, constructed hierarchically:

```math
\mathcal{N}_{\text{topological}}(v) = p_0 \mathbin{::} p_1 \mathbin{::} \dots \mathbin{::} \text{Name}(v)
```

where each $`p_i`$` is a sanitized identifier token and `$`::`$` is the canonical scope delimiter. Let `$`\text{Bytes}(\cdot)`$` denote the UTF-8 byte serialization function, and let `$`\mathbin{\Vert}`$ denote byte sequence concatenation. The 160-bit SHA-1 hash digest is given by:

```math
H(v) = \text{SHA1}(\text{NS}_{\text{DEAP}} \mathbin{\Vert} \text{Bytes}(\mathcal{N}_{\text{topological}}(v))) = (h_0, h_1, \dots, h_{19}) \in (\mathbb{Z}_{256})^{20}
```

The RFC 4122 UUIDv5 octet sequence $`U(v) = (u_0, u_1, \dots, u_{15}) \in (\mathbb{Z}_{256})^{16}`$ is defined by:

```math
\begin{aligned}
u_i &= h_i \quad \forall i \in \{0, \dots, 15\} \setminus \{6, 8\} \\
u_6 &= (h_6 \mathbin{\&} 0\text{x0F}) \mathbin{|} 0\text{x50} \\
u_8 &= (h_8 \mathbin{\&} 0\text{x3F}) \mathbin{|} 0\text{x80}
\end{aligned}
```

The generated identifier satisfies the RFC 4122 Version 5 and Leach-Salz Variant invariants:

```math
\text{Version}(U) = (u_6 \gg 4) = 5, \quad \text{Variant}(U) = (u_8 \gg 6) = 2
```

Let $`\text{Hex}_2(b)`$` denote the two-character lowercase hexadecimal encoding of octet `$`b \in \mathbb{Z}_{256}`$`. The canonical 36-character string representation `$`\text{Str}(U)`$ satisfies:

```math
\begin{aligned}
\text{Str}(U) &= \text{Hex}_2(u_0)\text{Hex}_2(u_1)\text{Hex}_2(u_2)\text{Hex}_2(u_3) \mathbin{-} \text{Hex}_2(u_4)\text{Hex}_2(u_5) \mathbin{-} \text{Hex}_2(u_6)\text{Hex}_2(u_7) \\
&\quad \mathbin{-} \text{Hex}_2(u_8)\text{Hex}_2(u_9) \mathbin{-} \text{Hex}_2(u_{10})\dots\text{Hex}_2(u_{15})
\end{aligned}
```

Environmental Invariance Invariant: let $`\mathcal{E} = (\text{Host}, \text{Timestamp}, \text{MountPath}, \text{ThreadID}, \text{Arch})`$` denote the execution runtime context. For any two contexts `$`\mathcal{E}_1, \mathcal{E}_2`$:

```math
\forall v \in \mathcal{V}, \quad U(v; \mathcal{E}_1) = U(v; \mathcal{E}_2)
```

Expressed in terms of partial derivatives over environmental parameters:

```math
\frac{\partial U}{\partial \text{Host}} = 0, \quad \frac{\partial U}{\partial \text{Timestamp}} = 0, \quad \frac{\partial U}{\partial \text{MountPath}} = 0, \quad \frac{\partial U}{\partial \text{ThreadID}} = 0, \quad \frac{\partial U}{\partial \text{Arch}} = 0
```

Cryptographic Collision Resistance Invariant: for distinct canonical topological paths $`\mathcal{N}_1 \neq \mathcal{N}_2`$:

```math
\forall \mathcal{N}_1, \mathcal{N}_2 \in \Sigma^*, \quad \mathcal{N}_1 \neq \mathcal{N}_2 \implies \Pr(U(\mathcal{N}_1) = U(\mathcal{N}_2)) \le 2^{-128}
```

Bijective Determinism Invariant: for any two AST nodes $`v_1, v_2 \in \mathcal{V}`$:

```math
\mathcal{N}_{\text{topological}}(v_1) = \mathcal{N}_{\text{topological}}(v_2) \iff U(v_1) = U(v_2)
```

- **Computational Complexity & Algorithmic Bounds**: The RFC 4122 UUIDv5 generation pipeline executes within Complexity Class $`\mathbf{P}`$`. For a canonical path string `$`\mathcal{N}_{\text{topological}}`$` of byte length `$`L = |\text{Bytes}(\mathcal{N}_{\text{topological}})|`$`, SHA-1 hashing processes `$`16 + L`$` bytes across `$`\lceil (L + 16 + 9) / 64 \rceil`$` fixed 512-bit compression blocks, executing in deterministic linear time `$`O(L) = O(|\mathcal{N}_{\text{topological}}|)`$`. Truncation, version/variant bitwise masking, and formatting into 16-byte raw octets or 36-character ASCII hexadecimal strings execute in strictly `$`O(1)`$` time. For an entire AST graph `$`\mathcal{A} = (\mathcal{V}, \mathcal{E})`$` comprising `$`V = |\mathcal{V}|`$` nodes and total qualified path character length `$`L_{\text{total}} = \sum_{v \in \mathcal{V}} |\mathcal{N}_{\text{topological}}(v)|`$`, computing UUIDv5 identifiers for all nodes using cached prefix path strings executes in deterministic time `$`O(V + L_{\text{total}}) = O(N)`$`, where `$`N`$` is the total schema token length. Auxiliary memory consumption per calculation is bounded by `$`O(1)`$` stack space for the 160-bit SHA-1 state and 16-byte UUID output buffer, with scratch buffer allocation bounded by `$`O(L_{\max})`$` where `$`L_{\max} = \max_{v \in \mathcal{V}} |\mathcal{N}_{\text{topological}}(v)|`$, eliminating dynamic heap allocations.

- **Verification & Conformance Criteria**: Automated test suites shall verify compliance against standard RFC 4122 test vectors and compiler synthetic namespace fixtures. Conformance testing across multiple operating systems, CPU architectures, filesystem mount locations, and randomized thread pool scheduling orders must assert 100% bitwise identity of emitted UUID string representations. Structural verification shall assert that for 100% of generated identifiers: (1) version bits satisfy $`(u_6 \mathbin{\&} 0\text{xF0}) == 0\text{x50}`$`, (2) variant bits satisfy `$`(u_8 \mathbin{\&} 0\text{xC0}) == 0\text{x80}`$, and (3) formatted strings match canonical lowercase pattern `^[0-9a-f]{8}-[0-9a-f]{4}-5[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`. If any compiler component attempts to generate or ingest a time-based UUID (UUIDv1, UUIDv6, UUIDv7) or pseudo-random UUID (UUIDv4), encounters an un-sanitized path containing host-absolute filesystem paths, or detects a hash collision ($`\mathcal{N}_1 \neq \mathcal{N}_2`$` with `$`U(\mathcal{N}_1) = U(\mathcal{N}_2)`$), the compiler shall immediately abort compilation and emit diagnostic error code `E0100` detailing the offending AST node handle, path string, and invalid or conflicting UUID bytes.
