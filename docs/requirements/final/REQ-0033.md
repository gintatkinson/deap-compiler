### REQ-0033: Multi-File Cryptographic Digest Computation (`.pipeline/schema-digest.json`)

- **Normative Statement**: The ingestion engine within the Universal Schema Ingestion Engine shall compute, record, verify, and persist a multi-file cryptographic manifest for all discovered schema input source files and the emitted canonical textual SysML v2 model (`schema/model.sysml`). The manifest shall be serialized as a canonical JSON document and written atomically to `.pipeline/schema-digest.json`. The multi-file cryptographic digest engine shall operate strictly in accordance with the following prescriptive requirements:
  1. Input Scope and Discovery: The ingestion engine shall assemble the complete finite set of input schema files $\mathcal{F}_{\text{inputs}}$ across the workspace, encompassing all CommonMark tabular schemas (`.md`), Protocol Buffer specifications (`.proto`), OMG Interface Definition Language files (`.idl`), OpenAPI schemas (`.json`, `.yaml`), XML Schema Definitions and Architecture Description Language models (`.xsd`, `.adl`), and native SysML v2 source files (`.sysml`), alongside the compiler-synthesized canonical textual model `schema/model.sysml`.
  2. Per-File Digest Tuple Attributes: For every file $F_i \in \mathcal{F}_{\text{manifest}}$, the ingestion engine shall compute and record a deterministic 5-tuple digest entry comprising:
     - Workspace-Relative Canonical Path ($P_i$): A normalized ASCII relative path resolved from the workspace root (per REQ-0004) utilizing exclusively forward-slash (`/`) directory delimiters without redundant `./` prefixes or trailing slashes.
     - Cryptographic Content Hash ($H_i$): A 256-bit Secure Hash Algorithm 2 (SHA-256 conforming to FIPS 180-4) digest rendered strictly as a 64-character lowercase hexadecimal string.
     - Byte Size ($S_i$): An exact 64-bit unsigned integer ($u64$) indicating the total byte count $|F_i|$ of the file on disk.
     - Line Count ($L_i$): An exact 64-bit unsigned integer ($u64$) representing the count of line break delimiter tokens ($\text{SYM}_{\text{LF}}$, ASCII byte `0x0A`) contained within the file content buffer.
     - Synthesized AST Entity Count ($N_i$): An exact 64-bit unsigned integer ($u64$) indicating the number of lowered intermediate schema IR entities (`IngestedPackage`, `IngestedPart`, `IngestedPort`, `IngestedAction`, `IngestedAttr`, `IngestedConnection`, `IngestedClassifierDef`, and `IngestedConstraint`) synthesized from that individual schema file during the ingestion pass (or the total AST entity count for `schema/model.sysml`).
  3. Deterministic Lexicographical Entry Ordering: Prior to computing the composite root digest and serializing the manifest to disk, all file entries must be sorted strictly in ascending ASCII lexicographical byte order based on their workspace-relative path $P_i$. Unsorted, random, or filesystem-traversal-dependent ordering is strictly prohibited, guaranteeing 100% bitwise reproducibility and zero git diff churn in accordance with REQ-0003 and REQ-0032.
  4. Composite Root Digest Computation: The engine shall compute an aggregate 256-bit SHA-256 composite root digest ($\mathcal{H}_{\text{root}}$) over the deterministic, delimiter-separated concatenation of all sorted per-file digest entries. In accordance with Architectural Directive 1 and REQ-0010, the engine shall derive a deterministic RFC 4122 UUIDv5 identifier ($\text{UUID}_{\text{manifest}}$) for the compilation manifest using a fixed namespace OID ($\text{OID}_{\text{DEAP}}$) and the composite root hash string.
  5. Deterministic Non-Volatile Serialization: The manifest JSON document shall serialize strictly deterministic metadata fields (`schema_version: "1.0.0"`, `manifest_uuid`, `composite_hash`, and `entries`). Ephemeral execution artifacts, machine-dependent absolute filesystem paths, operating system user names, process identifiers, and wall-clock timestamps are strictly prohibited from the manifest body to preserve bitwise determinism and eliminate diff churn across machines and CI runners.
  6. Atomic File Persistence Contract: The ingestion engine shall ensure crash-consistent and corruption-free persistence by writing the serialized manifest to a temporary staging file located within the same filesystem directory (`.pipeline/schema-digest.json.tmp.<pid>`), issuing a filesystem synchronization flush (`fsync`), and atomically renaming the temporary file over the destination path `.pipeline/schema-digest.json` using atomic filesystem rename semantics. Direct in-place partial writes to `.pipeline/schema-digest.json` are strictly forbidden. The engine shall ensure the parent directory `.pipeline/` is created deterministically if absent.
  7. Incremental Manifest Cache Invalidation and Model Reuse: Upon invocation, the ingestion engine shall evaluate the validity of any pre-existing `.pipeline/schema-digest.json` cache file against the live workspace state:
     - Cache Hit: If the manifest file exists, parses cleanly as valid JSON conforming to the schema, contains an entry set matching the current workspace input files bijectively, and exhibits identical cryptographic hashes ($H_i$) and byte sizes ($S_i$) across all entries, the engine shall register a cache hit, skip re-parsing of input schema sources, reuse the pre-compiled AST model from memory or cache, and bypass textual re-emission of `schema/model.sysml` in accordance with REQ-0006, REQ-0051, and REQ-0052.
     - Cache Miss: If any input schema file is modified (even by a single byte), added, or deleted, or if the manifest is missing or invalid, the engine shall register a cache miss, invalidate downstream AST caches, trigger a full ingestion and lowered AST generation pass, re-emit `schema/model.sysml`, and atomically overwrite `.pipeline/schema-digest.json`.
  8. Contiguous Bump Arena Storage and String Interning: All in-memory manifest data structures, file path buffers, and digest node descriptors shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034. In accordance with Architectural Directive 3 and REQ-0036, copying string bytes from the file path strings and SHA-256 hexadecimal representations into the global symbol interner pool for scalar `SymbolId` tokens is permitted as a valid zero-copy exception.
  9. Bounded Work-Stealing Parallelism: Parallel multi-file SHA-256 hash computation, line counting, and byte size verification across $M$ schema files shall be scheduled strictly onto a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with Architectural Directive 2 and REQ-0012. Manual or unbounded thread spawning is strictly banned.
  10. Error Recovery and Diagnostic Code Binding: In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, filesystem access failures, unreadable input files, write failures, or corrupted manifest files shall trigger structured diagnostics adhering to the Subsystem 2 taxonomy:
      - If any input schema file cannot be accessed or read due to filesystem I/O faults or permission restrictions, the engine shall record a structured diagnostic with diagnostic error code `E0100` (`InputSchemaFileReadFailure`) per REQ-0191.
      - If writing or atomically renaming `.pipeline/schema-digest.json` fails due to filesystem permissions or disk saturation, the engine shall record diagnostic error code `E0100` (`ManifestWriteFailure`).
      - If an existing `.pipeline/schema-digest.json` file is syntactically malformed, truncated, or exhibits schema structural corruption, the engine shall record diagnostic error code `E0102` (`MalformedDigestManifestSyntax`), discard the corrupted cache file, and proceed with clean compilation.
      - If accumulated diagnostics reach the configured sink limit $C_{\text{max\_errors}}$, the engine shall emit diagnostic error code `E0199` and terminate ingestion gracefully.
  11. Total Non-Panicking Contract and Release Gate: In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the cryptographic digest engine shall operate under a total, deterministic, non-panicking execution contract across all inputs (including zero-byte files, huge files, missing paths, and corrupted cache JSON). Execution latency (< 25 ms for 1,000 files) and peak RSS memory (< 100 MB) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests.
  12. Zero Domain Contamination: The digest engine, test fixtures, diagnostic messages, and illustrative examples shall operate exclusively on abstract MBSE formalisms using synthetic placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Component_Beta`, `Port_1`, `Flow_A`, `param_x : Real`, `schema/model.sysml`, `schema/Schema_Alpha.proto`, `schema/Table_Beta.md`), with zero hardcoded domain concepts and zero mock data.

- **Formal Invariant**: Let $\mathcal{F}_{\text{manifest}}$ denote the unified finite set of files subject to cryptographic digest tracking:

$$
\mathcal{F}_{\text{manifest}} = \mathcal{F}_{\text{inputs}} \cup \{ \text{"schema/model.sysml"} \}
$$

where $\mathcal{F}_{\text{inputs}} = \{ F_1, F_2, \dots, F_M \}$ represents the finite set of schema input source files discovered within the compilation workspace.

For each file $F_i \in \mathcal{F}_{\text{manifest}}$, its cryptographic digest tuple is formalized as:

$$
\text{Digest}(F_i) = \langle P_i, H_i, S_i, L_i, N_i \rangle
$$

where:

$$
\begin{aligned}
P_i &= \text{RelPath}(F_i, \text{Root}_{\text{ws}}) \in \mathcal{P}_{\text{rel}} \\
H_i &= \text{Hex}(\text{SHA256}(F_i)) \in \Sigma_{\text{hex}}^{64} \\
S_i &= |F_i| \in \mathbb{N}_0 \\
L_i &= \text{Lines}(F_i) \in \mathbb{N}_0 \\
N_i &= |\text{Entities}(F_i)| \in \mathbb{N}_0
\end{aligned}
$$

with $\Sigma_{\text{hex}} = \{ \text{'0'}, \dots, \text{'9'}, \text{'a'}, \dots, \text{'f'} \}$.

Deterministic Lexicographical Ordering Invariant:
Let $\mathcal{D}_{\text{manifest}} = \langle \text{Digest}(F_1), \text{Digest}(F_2), \dots, \text{Digest}(F_K) \rangle$ be the ordered sequence of digest entries for all $K = |\mathcal{F}_{\text{manifest}}|$ tracked files:

$$
\forall i \in \{1, \dots, K-1\}, \quad P_i \prec_{\text{lex}} P_{i+1}
$$

where $\prec_{\text{lex}}$ denotes standard lexicographical byte comparison over normalized ASCII path strings:

$$
s_a \prec_{\text{lex}} s_b \iff \exists j \ge 0 : (\forall k \lt j, s_a[k] = s_b[k]) \wedge (s_a[j] \lt s_b[j])
$$

Composite Root Digest Invariant:
The aggregate composite root hash $\mathcal{H}_{\text{root}} \in \Sigma_{\text{hex}}^{64}$ is computed over the deterministic concatenation of all lexicographically ordered per-file digest tuples:

$$
\mathcal{H}_{\text{root}} = \text{Hex}\left( \text{SHA256}\left( \bigoplus_{i=1}^K \left( P_i \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} H_i \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} \text{Dec}(S_i) \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} \text{Dec}(L_i) \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} \text{Dec}(N_i) \mathbin{\Vert} \text{SYM}_{\text{LF}} \right) \right) \right)
$$

where $\text{SYM}_{\text{DELIM}}$ denotes the unit separator delimiter token (`0x1F`), $\text{Dec}(n)$ denotes the canonical base-10 ASCII string representation of integer $n$, and $\text{SYM}_{\text{LF}}$ denotes the line break delimiter (`0x0A`).

Deterministic Manifest UUIDv5 Invariant:
In accordance with Architectural Directive 1 and REQ-0010, the unique compilation manifest identifier is derived strictly via RFC 4122 UUIDv5 hashing:

$$
\text{UUID}_{\text{manifest}} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \mathcal{H}_{\text{root}})
$$

Manifest Document Structure Invariant:
The serialized manifest document $\mathcal{J}_{\text{manifest}}$ conforms to the canonical JSON schema:

$$
\mathcal{J}_{\text{manifest}} = \left\{
\begin{aligned}
&\text{"schema\_version"}: \text{"1.0.0"}, \\
&\text{"manifest\_uuid"}: \text{UUID}_{\text{manifest}}, \\
&\text{"composite\_hash"}: \mathcal{H}_{\text{root}}, \\
&\text{"entries"}: [ \text{Entry}_1, \text{Entry}_2, \dots, \text{Entry}_K ]
\end{aligned}
\right\}
$$

where each entry $\text{Entry}_i$ is defined as:

$$
\text{Entry}_i = \left\{
\begin{aligned}
&\text{"path"}: P_i, \\
&\text{"sha256"}: H_i, \\
&\text{"byte\_size"}: S_i, \\
&\text{"line\_count"}: L_i, \\
&\text{"entity\_count"}: N_i
\end{aligned}
\right\}
$$

Atomic File Persistence Invariant:
Let $\text{TmpPath} = \text{".pipeline/schema-digest.json.tmp."} \mathbin{\Vert} \text{Dec}(\text{PID})$. Atomic manifest persistence to disk satisfies:

$$
\text{PersistManifest}(\mathcal{J}_{\text{manifest}}) \implies \text{Write}(\text{TmpPath}, \mathcal{J}_{\text{manifest}}) \;\wedge\; \text{FSync}(\text{TmpPath}) \;\wedge\; \text{AtomicRename}(\text{TmpPath}, \text{".pipeline/schema-digest.json"})
$$

Manifest Cache Invalidation and Model Reuse Invariant:
Let $\mathcal{M}_{\text{cached}}$ denote the deserialized manifest loaded from disk, and $\mathcal{M}_{\text{active}}$ denote the live workspace manifest computed during the scan. The cache validation predicate $\Psi_{\text{cache}}$ satisfies:

$$
\Psi_{\text{cache}}(\mathcal{M}_{\text{cached}}, \mathcal{M}_{\text{active}}) \iff \left( \mathcal{M}_{\text{cached}}.\text{composite\_hash} = \mathcal{M}_{\text{active}}.\text{composite\_hash} \;\wedge\; |\mathcal{M}_{\text{cached}}.\text{entries}| = |\mathcal{M}_{\text{active}}.\text{entries}| \right)
$$

Conditional execution satisfies:

$$
\Psi_{\text{cache}}(\mathcal{M}_{\text{cached}}, \mathcal{M}_{\text{active}}) \implies \text{ReuseCachedModel}(\mathcal{A}_{\text{cached}}) \;\wedge\; \text{BypassTextualEmission}()
$$

$$
\neg \Psi_{\text{cache}}(\mathcal{M}_{\text{cached}}, \mathcal{M}_{\text{active}}) \implies \text{TriggerFullIngestion}() \;\wedge\; \text{PersistManifest}(\mathcal{M}_{\text{active}})
$$

Contiguous Arena Allocation Invariant:
All manifest entry structures are stored sequentially in contiguous typed bump arena memory:

$$
\forall i \in \{1, \dots, K-1\}, \quad \text{Offset}(\text{Handle}_{i+1}) = \text{Offset}(\text{Handle}_i) + \text{sizeof}(\text{DigestEntry})
$$

Diagnostic Code Binding Invariant:
I/O errors, write faults, and corrupted cache files deterministically emit structured diagnostics in accordance with REQ-0191:

$$
\begin{aligned}
\text{IOReadError}(F_i) &\implies \text{Diagnostic}(P_i, \text{DiagnosticCode::E0100}, \text{InputSchemaFileReadFailure}) \in \mathcal{D} \\
\text{IOWriteError}(\text{".pipeline/schema-digest.json"}) &\implies \text{Diagnostic}(\text{".pipeline/schema-digest.json"}, \text{DiagnosticCode::E0100}, \text{ManifestWriteFailure}) \in \mathcal{D} \\
\text{MalformedJSON}(\mathcal{J}_{\text{disk}}) &\implies \text{Diagnostic}(\text{".pipeline/schema-digest.json"}, \text{DiagnosticCode::E0102}, \text{MalformedDigestManifestSyntax}) \in \mathcal{D} \\
|\mathcal{D}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant:
All emitted diagnostic records strictly reside within the Subsystem 2 ingestion family:

$$
\forall D \in \mathcal{D}_{\text{digest}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0100}, \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{ingest}}
$$

- **Computational Complexity & Algorithmic Bounds**: Multi-file cryptographic digest computation executes strictly within Complexity Class $\mathbf{P}$. For an ingestion workspace comprising $K = |\mathcal{F}_{\text{manifest}}|$ tracked files with aggregate byte size $B = \sum_{i=1}^K |F_i|$, the engine evaluates through the following deterministic algorithmic bounds:
  1. Workspace Discovery & Path Normalization: Traversing workspace directories to discover $K$ schema files and computing normalized relative paths of maximum path length $L_P \le L_{\text{max}} = 1024$ executes in $O(K \cdot L_{\text{max}}) = O(K)$ deterministic time.
  2. SHA-256 Content Hashing: Each file $F_i$ of size $B_i = |F_i|$ is processed in 64-byte blocks via the standard SHA-256 Merkle-Damgard compression function, requiring $\lceil B_i / 64 \rceil$ block transformations. Each block executes in $O(1)$ constant time (64 rounds of bitwise logic), yielding exact $O(B_i)$ deterministic linear time per file and aggregate hashing time:

$$
O\left( \sum_{i=1}^K B_i \right) = O(B)
$$

  3. Single-Pass Line Counting: Scanning file $F_i$ for line break delimiters ($\text{SYM}_{\text{LF}}$) is performed in a single streaming pass concurrently with hashing, consuming $O(B_i)$ operations without additional I/O passes.
  4. AST Entity Counting: Counting synthesized intermediate AST entities $N_i$ is maintained via an integer counter incremented during AST lowering in $O(1)$ constant time per synthesized node, requiring $O(N_i) \le O(B_i)$ total operations.
  5. Deterministic Lexicographical Sorting: Sorting the sequence of $K$ digest entries lexicographically by path $P_i$ executes via deterministic merge sort or introsort in $O(K \log K \cdot L_{\text{max}}) = O(K \log K)$ operations.
  6. Composite Root Hash Computation: Delimiter-separated concatenation of $K$ sorted digest entries produces a binary buffer of length $O(K \cdot L_{\text{entry}})$, where $L_{\text{entry}} \le 256$ bytes. Computing the SHA-256 hash over this buffer takes $O(K)$ linear time.
  7. Deterministic UUIDv5 Synthesis: Executing SHA-1 hashing over the 64-character composite root hash string takes strict $O(1)$ constant time.
  8. Atomic Manifest Serialization and I/O: Serializing $K$ digest entries to canonical JSON format and writing the buffer to disk with an atomic rename syscall executes in $O(K \cdot L_{\text{entry}}) = O(K)$ deterministic time.
  9. Parallel Work-Stealing Bounds: When processing $K$ files across $N_{\text{max\_workers}}$ threads in a bounded work-stealing thread pool (Directive 2, REQ-0012), parallel wall-clock runtime is bounded by:

$$
T_{\text{parallel}} \in O\left( \frac{B}{N_{\text{max\_workers}}} + \max_{1 \le i \le K} B_i + K \log K \right)
$$

  Total sequential execution time is strictly bounded by $O(B + K \log K) = O(B)$ deterministic linear time in aggregate input byte size $B$ (since $K \log K \ll B$ for real-world MBSE compilation units). Auxiliary space complexity is strictly bounded by $O(K)$ in bump arena storage for manifest records and $O(1)$ state per thread (a 96-byte SHA-256 streaming buffer), ensuring zero unbounded heap memory growth. Directory traversal call stack depth is bounded by $D_{\text{dir}} \le 32$, requiring $O(D_{\text{dir}}) = O(1)$ auxiliary stack space.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic MBSE schemas using abstract placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Component_Beta`, `Port_1`, `Flow_A`, `param_x : Real`, `schema/model.sysml`, `schema/Schema_Alpha.proto`, `schema/Table_Beta.md`). Conformance shall be validated through the following deterministic test gates:
  1. Multi-File Digest Generation Gate: Ingest an abstract MBSE model composed of multiple input schema files (`schema/Table_0.md`, `schema/Schema_1.proto`, `schema/Interface_2.idl`, `schema/model.sysml`); assert that `.pipeline/schema-digest.json` is generated with valid JSON structure, matching SHA-256 hex strings, exact byte counts, line counts, and AST entity counts.
  2. Canonical Lexicographical Ordering Gate: Randomize the discovery order of input files prior to ingestion; assert that `.pipeline/schema-digest.json` entries are sorted strictly in ascending ASCII lexicographical byte order by relative path $P_i$, yielding bit-for-bit identical JSON files and identical composite root hashes across permutations.
  3. Single-Byte Invalidation Gate: Mutate exactly one byte in an arbitrary schema input file (e.g., `schema/Table_0.md`); assert that its per-file SHA-256 hash changes, the composite root hash $\mathcal{H}_{\text{root}}$ changes, the cache check evaluates to false, and complete manifest regeneration is triggered.
  4. Line Count and AST Count Accuracy Gate: Append an empty newline to an input schema file without adding declarations; assert that `line_count` increases by 1 while `entity_count` remains constant. Add a new component declaration; assert that `entity_count` increments by the exact number of synthesized AST nodes.
  5. Atomic File Replacement Gate: Verify that writing `.pipeline/schema-digest.json` creates a temporary file `.pipeline/schema-digest.json.tmp.<pid>` and issues an atomic filesystem rename syscall, ensuring that concurrent readers never observe partial, empty, or truncated manifest states.
  6. Manifest Cache Hit Gate: Execute consecutive compilation invocations without modifying any schema files; assert that the cache validation predicate $\Psi_{\text{cache}}$ evaluates to true, file parsing and lowering passes are skipped, and the pre-compiled AST model is reused with zero diff churn.
  7. File Addition and Deletion Invalidation Gate: Introduce a new schema file (`schema/Extra_3.md`) or remove an existing schema file from the workspace; assert that the manifest verification detects the cardinality or path mismatch, invalidates the cache, and triggers a full recompilation.
  8. Deterministic UUIDv5 Gate: Verify that the `manifest_uuid` recorded in `.pipeline/schema-digest.json` matches the deterministic RFC 4122 UUIDv5 hash of $\mathcal{H}_{\text{root}}$ under $\text{OID}_{\text{DEAP}}$ across repeated executions and independent platforms.
  9. File I/O Error and Write Fault Gate: Simulate an unreadable input schema file due to read permission revocation; assert deterministic emission of diagnostic error code `E0100` (`InputSchemaFileReadFailure`). Simulate a read-only `.pipeline/` directory; assert deterministic emission of diagnostic error code `E0100` (`ManifestWriteFailure`).
  10. Corrupted Manifest Recovery Gate: Write corrupted or truncated JSON content into `.pipeline/schema-digest.json`; assert that the ingestion engine detects the syntax error, emits diagnostic error code `E0102` (`MalformedDigestManifestSyntax`), discards the corrupted cache, and regenerates a valid manifest.
  11. Total Function and Panic-Free Execution Gate (Directive 5): Stress testing across 10,000 edge cases (including zero-byte empty files, 100 MB synthetic files, deep directory structures, null bytes, and unicode characters) shall verify total-function termination with zero panics or uncaught exceptions.
  12. Release Mode Latency Gate (Directive 5): Multi-file digest computation latency shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests, asserting throughput exceeding $500$ MB/s for hashing, execution latency under 25 ms for 1,000 files, and peak RSS memory under 100 MB.
  13. Bitwise Determinism Gate: Repeated compilation passes over identical schema inputs across single-threaded and multi-threaded ($N_{\text{max\_workers}} = 8$) configurations shall generate bit-for-bit identical `.pipeline/schema-digest.json` artifacts with zero diff churn.
