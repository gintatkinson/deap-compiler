### REQ-0043: Multi-File Module Ingestion & Directory-to-Namespace Hierarchy Mapping

- **Normative Statement**: The Core Metamodel, Node Arena & AST Graph Engine shall support multi-file compilation models partitioned across arbitrary hierarchical directory trees, deterministically mapping relative filesystem directory paths to nested SysML package namespaces. For every compilation unit file ingested from beneath the designated workspace schema root directory ($`\mathcal{R}_{\text{schema}}`$), the compiler shall decompose the normalized relative file path into an ordered sequence of directory path segments and automatically bind the file's top-level declarations to an enclosing leaf package namespace whose fully qualified name corresponds strictly to the PascalCase-normalized directory segment hierarchy.

  The multi-file module ingestion engine shall enforce the following normative operational rules:
  1. Deterministic Directory-to-Namespace Mapping: A source file situated at relative path $`p_1 / p_2 / \dots / p_k / \text{file\_name}.\text{ext}`$` shall deterministically map to the canonical package namespace `$`\text{PascalCase}(p_1) :: \text{PascalCase}(p_2) :: \dots :: \text{PascalCase}(p_k)`$`. If a file resides directly in the schema root directory (`$`k = 0`$), it shall automatically bind to a designated root package namespace (`RootPackage`).
  2. Idempotent Implicit Package Synthesis: If any intermediate or enclosing package namespace along the prefix chain $`\bigodot_{j=1}^i \text{PascalCase}(p_j)`$` (`$`1 \le i \le k`$) does not pre-exist in the AST graph, the compiler shall automatically synthesize an intermediate package container node in contiguous bump arena storage with deterministic parent-child hierarchy linkages. Multiple files residing within the same directory or sharing common directory prefixes shall resolve to identical synthesized package node handles without duplicate node creation.
  3. File-to-Package Ownership Containment: All top-level model elements (classifiers, parts, ports, connections, actions, constraints) declared within an ingested file shall be registered as owned members of the resolved leaf package container node.
  4. Explicit Package Declaration Reconciliation: If a source file contains an explicit top-level package declaration, the declared package namespace must either be identical to the directory-derived leaf namespace or represent an explicit child subpackage nested within the directory-derived leaf namespace. Any explicit package declaration specifying an incompatible, disjoint, or conflicting package root that contradicts the filesystem directory path shall be rejected at compile time with structured diagnostic error code `E0200` per REQ-0191.
  5. Directory Segment Normalization & Collision Detection: Each filesystem directory segment shall be normalized to a valid PascalCase identifier by partitioning on word delimiters (underscores, hyphens, and whitespace), capitalizing initial alphanumeric characters, and concatenating word tokens. If two distinct sibling directory paths within the same parent folder normalize to identical PascalCase identifiers (e.g., `module_a` and `module-a`), or if a directory segment contains invalid non-alphanumeric characters that cannot be normalized to a legal identifier, the compiler shall halt invalid mapping and deterministically emit diagnostic error code `E0200`.
  6. Maximum Nesting Depth Enforcement: The compiler shall enforce a strict upper bound on directory nesting depth $`D_{\max} = 16`$`. Ingestion of any source file whose directory path nesting exceeds `$`D_{\max}`$ levels shall be rejected with diagnostic error code `E0200`.

  In accordance with Architectural Directive 1 and REQ-0010, every synthesized or declared package node must receive a deterministic RFC 4122 UUIDv5 identifier computed by hashing the namespace OID and the fully qualified package name. In accordance with Architectural Directive 2 and REQ-0012, filesystem directory traversal, path normalization, and file module discovery shall be parallelized across independent directory subtrees strictly via a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$, guaranteeing thread isolation and lock-free deterministic aggregation. In accordance with Architectural Directive 3 and REQ-0036, interning directory segment strings, normalized PascalCase identifiers, and fully qualified package path strings into the global symbol interner pool to produce scalar `SymbolId` tokens represents the sole permitted exception to zero-copy memory management. All synthesized package nodes and containment edges shall reside in contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, addressed via stable 32-bit node handles per REQ-0035. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the module ingestion engine shall implement synchronization token error recovery: upon encountering a path sanitization fault, namespace collision, or invalid package declaration, the engine shall record a structured diagnostic record, resynchronize on file boundaries, and continue ingesting remaining compilation units; if accumulated diagnostics reach the sink capacity limit $`C_{\text{max\_errors}}`$, the compiler shall emit diagnostic error code `E0199` and terminate processing gracefully. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the multi-file module ingestion engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs, evaluating performance gates (< 25 ms latency, < 100 MB RSS) exclusively in compiled Release mode (`--release`). All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Package_1`, `Package_Alpha`, `Module_A`, `Module_B`, `Unit_0`, `Unit_1`, `Classifier_Alpha`, `Classifier_Beta`, `Part_0`, `Port_1`, `Flow_A`, `param_x : Real`) with zero domain contamination.

- **Formal Invariant**: Let $`\mathcal{W}`$` denote the compilation workspace, anchored by schema root directory `$`\mathcal{R}_{\text{schema}}`$`. Let `$`\mathcal{F}_{\text{comp}}`$` denote the finite set of multi-file compilation units discovered beneath `$`\mathcal{R}_{\text{schema}}`$.

  For each source file $`f \in \mathcal{F}_{\text{comp}}`$`, let `$`P_{\text{abs}}(f)`$` denote its absolute filesystem path, and let `$`P_{\text{rel}}(f)`$` denote its normalized relative path with respect to `$`\mathcal{R}_{\text{schema}}`$:

```math
  P_{\text{rel}}(f) = \text{NormalizePath}(\text{PathRelative}(\mathcal{R}_{\text{schema}}, P_{\text{abs}}(f)))
```

  The relative path $`P_{\text{rel}}(f)`$` is decomposed into an ordered sequence of `$`k`$ directory path segments and a terminal filename:

```math
  P_{\text{rel}}(f) = p_1 / p_2 / \dots / p_k / \text{file\_name}.\text{ext}
```

  where $`k \in \mathbb{N}_0`$` denotes directory nesting depth (`$`0 \le k \le D_{\max} = 16`$`), each `$`p_i \in \Sigma^+`$` represents a directory path segment, `$`\text{file\_name} \in \Sigma^+`$` is the base file identifier, and `$`\text{ext} \in \{ \text{"sysml"}, \text{"kerml"}, \text{"md"}, \text{"yaml"}, \text{"json"} \}`$ is the recognized compilation unit file extension.

  The identifier normalization function $`\text{PascalCase} : \Sigma^+ \to \Sigma^+`$ maps sanitized directory segment strings to canonical PascalCase identifier strings:

```math
  \text{PascalCase}(s) = \bigoplus_{w \in \text{Words}(s)} (\text{ToUpper}(\text{Head}(w)) \mathbin{\Vert} \text{Tail}(w))
```

  where $`\text{Words}(s)`$` partitions segment `$`s`$` by word-delimiter characters (underscores, hyphens, and whitespace), `$`\text{Head}(w)`$` extracts the initial character, `$`\text{Tail}(w)`$` extracts the remaining characters in lowercase, and `$`\mathbin{\Vert}`$ denotes string concatenation.

  The directory-to-namespace mapping function $`\Omega_{\text{ns}} : \Sigma^* \to \mathcal{S}_{\text{intern}}`$ evaluates as:

```math
  \Omega_{\text{ns}}(P_{\text{rel}}(f)) = \begin{cases}
  \text{SymbolId}(\text{PascalCase}(p_1) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \dots \mathbin{\Vert} \text{PascalCase}(p_k)), & \text{if } k \ge 1 \\
  \text{SymbolId}(\text{"RootPackage"}), & \text{if } k = 0
  \end{cases}
```

  Implicit Package Creation Invariant:
  Let $`\mathcal{A}`$` denote the compilation AST graph, and let `$`\text{Packages}(\mathcal{A})`$` denote the set of package container nodes allocated in typed bump arena storage. For every file `$`f \in \mathcal{F}_{\text{comp}}`$` with decomposed directory segments `$`\langle p_1, \dots, p_k \rangle`$, the compiler guarantees the existence of all intermediate package container nodes along the prefix chain:

```math
  \forall i \in \{1, \dots, k\}, \quad \exists! P_i \in \text{Packages}(\mathcal{A}) \quad \text{such that} \quad \text{FQN}(P_i) = \bigodot_{j=1}^i \text{PascalCase}(p_j)
```

  where $`\bigodot_{j=1}^i s_j = s_1 \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \dots \mathbin{\Vert} s_i`$.
  If package container $`P_i`$` does not pre-exist in `$`\text{Packages}(\mathcal{A})`$`, the compiler synthesizes intermediate package container node `$`P_i`$ deterministically into contiguous bump arena storage with hierarchical parent-child linkage:

```math
  \text{Parent}(P_i) = \begin{cases}
  P_{i-1}, & \text{if } i \gt 1 \\
  \text{LookupPackage}(\mathcal{A}, \text{SymbolId}(\text{"RootPackage"})), & \text{if } i = 1
  \end{cases}
```

  Each lowered or synthesized package node $`P \in \text{Packages}(\mathcal{A})`$ is formalized as an 8-tuple:

```math
  P = \langle \text{id}, \text{name}, \text{parent}, \text{FQN}, \mathcal{M}_{\text{owned}}, \Delta_{\text{uuid}}, \kappa_{\text{synth}}, \text{span} \rangle
```

  where:
  - $`\text{id} \in \mathbb{U}_{32}`$ is the contiguous arena slot handle (REQ-0034, REQ-0035),
  - $`\text{name} \in \mathcal{S}_{\text{intern}}`$ is the interned segment symbol handle (REQ-0036),
  - $`\text{parent} \in \mathbb{U}_{32} \cup \{ \bot \}`$ is the handle of the enclosing parent package node,
  - $`\text{FQN} \in \mathcal{S}_{\text{intern}}`$ is the interned fully qualified package namespace string,
  - $`\mathcal{M}_{\text{owned}} \subseteq \mathbb{U}_{32}`$ is the ordered collection of owned member AST element handles,
  - $`\Delta_{\text{uuid}} \in \mathbb{U}_{128}`$ is the deterministic RFC 4122 UUIDv5 topological anchor (Directive 1, REQ-0010),
  - $`\kappa_{\text{synth}} \in \{ \text{SynthesizedImplicit}, \text{DeclaredExplicit} \}`$ is the package origin provenance tag,
  - $`\text{span} = \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle`$ is the lexical source provenance coordinate.

  Deterministic RFC 4122 UUIDv5 Anchor Invariant:
  For every package node $`P \in \text{Packages}(\mathcal{A})`$:

```math
  \Delta_{\text{uuid}}(P) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(P))
```

  File-to-Package Containment Invariant:
  Let $`\text{TopLevelDeclarations}(f) \subset \mathcal{V}_{\text{AST}}`$` denote the set of top-level AST element declarations parsed from source file `$`f \in \mathcal{F}_{\text{comp}}`$`. Every top-level declaration within file `$`f`$` is owned by the resolved leaf package `$`P_k = \text{LookupPackage}(\mathcal{A}, \Omega_{\text{ns}}(P_{\text{rel}}(f)))`$:

```math
  \forall e \in \text{TopLevelDeclarations}(f), \quad \text{Owner}(e) = P_k \;\wedge\; \text{id}(e) \in \mathcal{M}_{\text{owned}}(P_k)
```

  Explicit Package Declaration Reconciliation Invariant:
  Let $`\text{DeclaredPackage}(f)`$` denote the optional package namespace explicitly declared within source file `$`f`$. If an explicit declaration is present, it must conform to the directory-derived leaf namespace:

```math
  \text{ValidNamespaceBinding}(f) \iff \begin{cases}
  \text{true}, & \text{if } \text{DeclaredPackage}(f) = \bot \\
  \text{true}, & \text{if } \text{DeclaredPackage}(f) = \Omega_{\text{ns}}(P_{\text{rel}}(f)) \\
  \text{true}, & \text{if } \text{IsSubpackageOf}(\text{DeclaredPackage}(f), \Omega_{\text{ns}}(P_{\text{rel}}(f))) \\
  \text{false}, & \text{otherwise}
  \end{cases}
```

  Namespace Collision Detection Invariant:
  Let $`p_a, p_b \in \Sigma^+`$ be distinct filesystem directory segments residing within the same parent directory path:

```math
  (p_a \ne p_b \;\wedge\; \text{PascalCase}(p_a) = \text{PascalCase}(p_b)) \implies \text{Diagnostic}(p_b, \text{DiagnosticCode::E0200}, \text{NamespaceCollision}) \in \mathcal{D}_{\text{sink}}
```

  Diagnostic Code Binding Invariant:
  Any violation of multi-file module ingestion or directory-to-namespace mapping triggers structured diagnostic error code `E0200` per REQ-0191:

```math
  \begin{aligned}
  k \gt D_{\max} &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0200}, \text{NestingDepthExceeded}) \in \mathcal{D}_{\text{sink}} \\
  \exists i \in [1, k] : \neg\text{ValidIdentifier}(\text{PascalCase}(p_i)) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0200}, \text{InvalidPathSegment}) \in \mathcal{D}_{\text{sink}} \\
  \neg\text{ValidNamespaceBinding}(f) &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0200}, \text{NamespacePathDiscrepancy}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  Diagnostic Taxonomy Containment Invariant:
  All module ingestion and namespace mapping diagnostics belong strictly to the Metamodel and Typing error family defined in REQ-0191:

```math
  \forall D \in \mathcal{D}_{\text{module}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0199} \} \subset (\mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{ingest}})
```

- **Computational Complexity & Algorithmic Bounds**: Multi-file module ingestion and directory-to-namespace hierarchy mapping execute strictly within Complexity Class $`\mathbf{P}`$. The algorithmic bounds across data structures and execution phases are formalized as follows:
  1. Path Relative Normalization & Decomposition: For a file compilation unit $`f`$` with relative path `$`P_{\text{rel}}(f)`$`, path canonicalization and segment tokenization execute in `$`O(|P_{\text{rel}}(f)|)`$ deterministic time, requiring a single linear scan over the path byte sequence without recursive filesystem re-traversals.
  2. PascalCase Normalization: Normalizing a directory segment $`p_i`$` of character length `$`|p_i|`$` requires `$`O(|p_i|)`$` time. Across all `$`k`$` segments where `$`\sum_{i=1}^k |p_i| \le |P_{\text{rel}}(f)|`$`, the total normalization time is `$`O(|P_{\text{rel}}(f)|)`$ with zero heap allocation outside the symbol interner.
  3. Intermediate Package Lookup & Synthesis: Package lookup and insertion into the AST package trie or scoped symbol hash table requires $`O(1)`$ amortized time per segment level via interned scalar `SymbolId` handles. For a directory hierarchy of depth $`k \le D_{\max} = 16`$`, package resolution and synthesis requires `$`O(k) \subseteq O(D_{\max}) = O(1)`$ worst-case time per file.
  4. Aggregate Ingestion Complexity: For a multi-file workspace containing $`M = |\mathcal{F}_{\text{comp}}|`$` compilation units with aggregate relative path byte length `$`L = \sum_{f \in \mathcal{F}_{\text{comp}}} |P_{\text{rel}}(f)|`$, constructing the complete package namespace forest executes in deterministic linear time:

```math
  T(M, L) = \sum_{f \in \mathcal{F}_{\text{comp}}} O(|P_{\text{rel}}(f)| + k_f) \in O(L + M) \subseteq O(V + E)
```

  where $`V = |\text{Packages}(\mathcal{A})| + M`$` is the total count of synthesized package and file compilation unit nodes, and `$`E`$ is the total count of parent-child package hierarchy and file containment edges.
  5. Parallel Work-Stealing Scalability: When distributed across a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

```math
  T_{\text{parallel}}(M, L) \in O\left(\frac{L + M}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}}\right)
```

  6. Space Complexity: Auxiliary memory consumption is strictly bounded by $`O(V + E)`$` contiguous bump arena storage for package nodes and `$`O(S_{\text{intern}})`$` for deduplicated interned path symbols. Stack memory is bounded by `$`O(D_{\max}) = O(1)`$` during path traversal. The preallocated diagnostic sink buffer requires `$`O(C_{\text{max\_errors}}) = O(1)`$ heap memory, guaranteeing zero dynamic heap reallocation during compilation passes.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (e.g., `Package_0`, `Package_1`, `Package_Alpha`, `Module_A`, `Module_B`, `Unit_0`, `Unit_1`, `Classifier_Alpha`, `Classifier_Beta`, `Part_0`, `Port_1`, `Flow_A`, `param_x : Real`) across the following verification gates:
  1. Canonical Directory-to-Namespace Mapping Gate: Ingest a multi-file project containing relative paths:
     - `schema/package_alpha/module_beta/unit_gamma/element_delta.sysml`: verify automatic binding to package `PackageAlpha::ModuleBeta::UnitGamma`.
     - `schema/package_0/module_1/unit_2/part_0.sysml`: verify automatic binding to package `Package0::Module1::Unit2`.
     - `schema/model_root.sysml` (at schema root $`k = 0`$): verify automatic binding to `RootPackage`.
     - Assert that all top-level declarations within each file are owned by their respective leaf package container node with zero diagnostics emitted.
  2. Intermediate Package Node Synthesis & Idempotence Gate: Ingest 10 source files residing within the identical leaf directory `schema/package_0/module_a/unit_b/` and 5 sibling files in `schema/package_0/module_a/unit_c/`:
     - Assert that exactly one package node is allocated for `Package0`, exactly one for `Package0::ModuleA`, exactly one for `Package0::ModuleA::UnitB`, and exactly one for `Package0::ModuleA::UnitC`.
     - Verify that all 10 files in `unit_b` share the identical leaf package node handle $`\text{id}(P_{\text{UnitB}})`$, and all intermediate package nodes exhibit correct parent-child handle pointers.
  3. Deep Directory Nesting Gate: Ingest a synthetic model hierarchy with directory nesting depth $`k = 8`$` (deeply nested `$`> 5`$` levels) and `$`k = 16`$` (`$`D_{\max}`$ boundary):
     - Assert 100% successful ingestion and accurate hierarchical package binding without name collisions.
     - Ingest a file situated at nesting depth $`k = 17`$` (`$`k \gt D_{\max} = 16`$); assert deterministic rejection with diagnostic error code `E0200` (`NestingDepthExceeded`).
  4. Directory Name Sanitization & Namespace Collision Gate:
     - Create two distinct sibling directories `schema/package_0/module_alpha/` and `schema/package_0/module-alpha/` under common parent `package_0`. Assert that both normalize to `ModuleAlpha`, triggering deterministic detection of collision and emitting diagnostic error code `E0200` (`NamespaceCollision`).
     - Create a directory containing illegal characters (e.g., `schema/package_0/mod@ule!/`); assert deterministic rejection with diagnostic error code `E0200` (`InvalidPathSegment`).
  5. Explicit Package Declaration Reconciliation Gate:
     - In file `schema/package_0/module_a/unit_b/part_0.sysml`, declare explicit package `package Package0::ModuleA::UnitB;`; assert successful reconciliation with zero diagnostics.
     - In file `schema/package_0/module_a/unit_b/part_0.sysml`, declare explicit subpackage `package Package0::ModuleA::UnitB::SubUnit;`; assert successful creation of child package `SubUnit` under leaf package `Package0::ModuleA::UnitB`.
     - In file `schema/package_0/module_a/unit_b/part_0.sysml`, declare conflicting package `package OtherRoot::ConflictingModule;`; assert compile-time failure with diagnostic error code `E0200` (`NamespacePathDiscrepancy`).
  6. Deterministic RFC 4122 UUIDv5 & Arena Storage Gate:
     - Verify that every synthesized package node receives an RFC 4122 UUIDv5 identifier computed via $`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(P))`$.
     - Recompile the multi-file project across 10 repeated independent executions; assert bitwise identical UUIDv5 hashes, arena node handles, and symbol identifiers with 0-byte diff churn.
  7. Synchronization Token Error Recovery & Sink Capacity Gate:
     - Ingest a multi-file workspace containing 15 files with 5 files residing in malformed or colliding directory paths.
     - Assert that the ingestion engine records all 5 structured diagnostic records with diagnostic error code `E0200`, resynchronizes on file boundaries, and successfully ingests the 10 valid files without premature termination.
     - Inject malformed files exceeding sink capacity $`C_{\text{max\_errors}}`$; assert graceful termination with diagnostic error code `E0199`.
  8. Deterministic Non-Panicking Execution & Performance Gate:
     - Ingest malformed directory structures (cyclical symlinks, path traversal attempts `../../`, empty directory names, non-UTF8 paths); assert total-function termination with zero panics or segmentation faults.
     - In compiled Release mode (`--release`), benchmark multi-file ingestion across a synthetic workspace comprising $`10^4`$ files distributed over a 6-level directory hierarchy; assert total execution latency strictly below 25 ms and peak RSS memory strictly below 100 MB in accordance with REQ-0011 and REQ-0196.
