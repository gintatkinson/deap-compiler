### REQ-0077: SysML v2 AllocationDefinition (`allocation def`) & AllocationUsage Lowering

- **Normative Statement**: The Core Metamodel, Node Arena & AST Graph Engine and SysML v2 / KerML metamodel lowering engine shall formalize allocation definitions (`AllocationDefinition`, denoted by `allocation def`) and allocation usages (`AllocationUsage`, denoted by `allocation` or `allocate ... to ...`) as a strongly typed, bipartite mapping relation from source domain model elements to target domain model elements. In the SysML v2 taxonomic hierarchy, `AllocationDefinition` shall specialize `ConnectionDefinition` (which transitively specializes KerML `AssociationStructure`, `Classifier`, and `Relationship`), and `AllocationUsage` shall specialize `ConnectionUsage` (which transitively specializes KerML `Connector`, `Feature`, and `Relationship`).

  The compiler shall strictly enforce that allocations represent a directed bipartite relation between disjoint model partitions. Let $V_S$ denote the source domain node set (comprising behavioral actions, activities, performances, or logical step usages $\mathcal{V}_{\text{action}}$) and $V_T$ denote the target domain node set (comprising structural classifiers, physical part usages, component assemblies, or execution platform nodes $\mathcal{V}_{\text{struct}}$). The lowering engine shall enforce bipartite domain disjointness:

  $$
  V_S \cap V_T = \emptyset
  $$

  Every allocation usage $U_{\text{alloc}}$ shall bind a source element $u_{\text{src}} \in V_S$ to a target element $u_{\text{tgt}} \in V_T$. Cross-domain inversion (such as allocating a structural classifier to a behavioral action) or allocation declarations between incompatible metamodel element kinds shall be strictly rejected at compile time with diagnostic error code `E0200` in accordance with the standardized diagnostic taxonomy of REQ-0191.

  Reflexive allocation declarations ($u_{\text{src}} = u_{\text{tgt}}$) shall be strictly forbidden. The compiler shall verify that no model element is allocated to itself, emitting diagnostic error code `E0200` upon detecting any reflexive allocation statement.

  The lowering engine shall statically verify Interface and Port Allocation Consistency. When an action or behavioral element $a \in V_S$ is allocated to a structural classifier or component $c \in V_T$, the interaction boundary of $a$ must be completely and consistently realized by the interface boundary of $c$. The compiler shall verify that for every external interaction port $p_a \in \text{Ports}(a)$, there exists a uniquely mapped, compatible interaction port $p_c \in \text{Ports}(c)$ satisfying two structural typing conditions:
  1. **Directional Flow Polarity Preservation**: The flow directionality $\delta(p)$ of the structural port must match the flow directionality of the action port ($\delta(p_c) = \delta(p_a)$ for $\delta \in \{ \text{In}, \text{Out}, \text{InOut} \}$).
  2. **Co-variant Payload Type Conformance**: The payload data or item type of the action port must specialize or equal the payload type of the structural port ($\tau(p_a) \le \tau(p_c)$) within the subtyping meet-semilattice $(\mathcal{T}, \le, \wedge)$.

  If an allocated action $a$ contains an external port that cannot be mapped to a compatible port on structural component $c$, or if a mapped port violates directional polarity or payload subtyping conformance, the lowering engine shall record diagnostic error code `E0200`.

  Every `AllocationUsage` shall declare an explicit or defaulted multiplicity interval $\mu(U) = [m_{\min}, m_{\max}]$ governing allocation realization bounds. The compiler shall verify interval well-formedness $0 \le m_{\min} \le m_{\max}$ and $m_{\max} \ge 1$. Subsetting (`:>`) or redefinition (`:>>`) of allocation usages shall enforce monotonic upper bound narrowing ($\mu(U_{\text{sub}}).m_{\max} \le \mu(U_{\text{sup}}).m_{\max}$) and lower bound feasibility ($\mu(U_{\text{sub}}).m_{\min} \le \mu(U_{\text{sup}}).m_{\max}$) per REQ-0061 and REQ-0062. Multiplicity interval violations or non-monotonic redefinitions shall trigger diagnostic error code `E0200`.

  Multi-tier allocation chains (such as allocating behavioral actions to logical components, and subsequently allocating logical components to physical execution platform nodes) establish a directed allocation dependency multigraph. The lowering engine shall construct the global allocation dependency graph $G_{\text{alloc}} = (V_{\text{all}}, E_{\text{alloc}})$ and verify that its transitive closure $E_{\text{alloc}}^+$ is irreflexive. Static circular allocation dependencies ($v_1 \mapsto v_2 \mapsto \dots \mapsto v_1$) shall be detected via topological cycle detection algorithms and rejected at compile time with diagnostic error code `E0203`.

  **Algorithmic Bound NP-2 Disambiguation**: In general systems engineering, multi-dimensional structural allocation, channel multiplexing, and hardware resource bin packing under capacity constraints is strongly NP-hard (governed by NP-2 in REQ-0147 via First-Fit Decreasing heuristics and branch-and-bound cutoffs). In contrast, the syntactic and semantic metamodel lowering, bipartite classification, port consistency verification, and acyclicity checking specified in REQ-0077 operates strictly on declared allocation relationships and static interface signatures, executing deterministically in linear polynomial time without backtracking.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered `AllocationDefinition` and `AllocationUsage` AST node and allocation relation edge shall be assigned a deterministic RFC 4122 UUIDv5 identifier computed from namespace-hashing the fully qualified topological paths of the endpoints with the canonical DEAP compiler namespace OID per REQ-0010.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel verification of independent allocation definitions, bipartite partitions, and port consistency across packages shall execute on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ per REQ-0012.
  - *Directive 3 (String Interner Memory Allocation Exception)*: Scalar allocation names, role names, and endpoint identifier symbols shall be interned into the global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
  - *Directive 4 (Synchronization Token Error Recovery)*: The lowering engine shall implement synchronization token error recovery on statement and delimiter boundaries (`;`, `}`, `end`). Upon detecting an invalid allocation declaration (bipartite domain violation, reflexive allocation, port mismatch `E0200`, or cyclic dependency `E0203`), the engine shall record structured diagnostics into the compiler diagnostic sink, bind an error sentinel $\bot_{\text{alloc}}$, and continue verifying subsequent declarations. If accumulated diagnostics reach $C_{\text{max\_errors}}$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
  - *Directive 5 (Panic-Free Release Isolation)*: The compiler engine shall enforce a total-function, panic-free execution contract across all valid and malformed inputs. Execution latency ($\lt 25\text{ ms}$ for $10^4$ allocations) and peak memory RSS ($\lt 100\text{ MB}$ RSS) performance gates shall be evaluated strictly in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `AllocationDef_Alpha`, `AllocationDef_Beta`, `AllocationUsage_1`, `AllocationUsage_2`, `Action_A`, `Action_B`, `Part_X`, `Part_Y`, `Port_In`, `Port_Out`, `Classifier_Alpha`, `Classifier_Beta`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: The KerML and SysML v2 subtyping poset $(\text{Classifiers}, \le)$ formalizes `AllocationDefinition` and `AllocationUsage` within the classifier and feature taxonomies:

  $$
  \begin{aligned}
  \text{AllocationDefinition} &\le \text{ConnectionDefinition} \le \text{AssociationStructure} \le \text{Classifier} \\
  \text{AllocationDefinition} &\le \text{Relationship} \le \text{Element} \\
  \text{AllocationUsage} &\le \text{ConnectionUsage} \le \text{Connector} \le \text{Feature} \\
  \text{AllocationUsage} &\le \text{Relationship} \le \text{Element}
  \end{aligned}
  $$

  Each allocation definition $D_{\text{alloc}} \in \mathcal{C}_{\text{alloc\_def}}$ is formalized as an 8-tuple:

  $$
  D_{\text{alloc}} = \langle \text{id}_D, \text{name}_D, \mathcal{S}_D, \mathcal{E}_{\text{src}}, \mathcal{E}_{\text{tgt}}, \Phi_D, \Delta_D, \text{span}_D \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_D &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_D &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
  \mathcal{S}_D &\subseteq \mathcal{C}_{\text{alloc\_def}} \quad (\text{direct supertype allocation definitions}) \\
  \mathcal{E}_{\text{src}} &\in \mathcal{C} \quad (\text{source endpoint classifier type constraint}) \\
  \mathcal{E}_{\text{tgt}} &\in \mathcal{C} \quad (\text{target endpoint classifier type constraint}) \\
  \Phi_D &\in \text{ConstraintExpr} \cup \{ \top \} \quad (\text{formal allocation invariant predicate}) \\
  \Delta_D &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_D &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
  \end{aligned}
  $$

  Each allocation usage $U_{\text{alloc}} \in \mathcal{U}_{\text{alloc}}$ is formalized as a 10-tuple:

  $$
  U_{\text{alloc}} = \langle \text{id}_U, \text{name}_U, \text{owner}_U, \tau(U), u_{\text{src}}, u_{\text{tgt}}, \mu(U), \mathcal{M}_{\text{port}}, \Delta_U, \text{span}_U \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_U &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_U &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
  \text{owner}_U &\in \mathcal{V}_{\text{AST}} \quad (\text{enclosing model or package namespace context}) \\
  \tau(U) &\subseteq \mathcal{C}_{\text{alloc\_def}} \setminus \{ \emptyset \} \quad (\text{allocation definition types bound via FeatureTyping}) \\
  u_{\text{src}} &\in V_S \quad (\text{allocated source element node handle}) \\
  u_{\text{tgt}} &\in V_T \quad (\text{allocated target element node handle}) \\
  \mu(U) &= [m_{\min}(U), m_{\max}(U)] \subseteq \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \}) \quad (\text{multiplicity interval}) \\
  \mathcal{M}_{\text{port}} &\subseteq \text{Ports}(u_{\text{src}}) \times \text{Ports}(u_{\text{tgt}}) \quad (\text{interaction port mapping relation}) \\
  \Delta_U &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_U &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
  \end{aligned}
  $$

  Let $\mathcal{V}_{\text{AST}}$ be partitioned into disjoint domain node sets $V_S$ (source behavioral actions $\mathcal{V}_{\text{action}}$) and $V_T$ (target structural classifiers $\mathcal{V}_{\text{struct}}$):

  $$
  V_S \cap V_T = \emptyset
  $$

  The global allocation graph $G_{\text{alloc}} = (V_S \cup V_T, E_{\text{alloc}})$ satisfies the strict bipartite mapping property:

  $$
  \forall (s, t) \in E_{\text{alloc}}, \quad s \in V_S \;\wedge\; t \in V_T \;\wedge\; s \ne t \;\wedge\; t \notin V_S
  $$

  Irreflexivity Invariant: No element may be allocated to itself:

  $$
  \forall v \in V_S \cup V_T, \quad (v, v) \notin E_{\text{alloc}}
  $$

  Interface and Port Allocation Consistency Invariant: For every allocated pair $(s, t) \in E_{\text{alloc}}$, every external interaction port $p_s \in \text{Ports}(s)$ must possess a unique mapped counterpart $p_t \in \text{Ports}(t)$ preserving directionality and satisfying payload type specialization:

  $$
  \forall p_s \in \text{Ports}(s), \quad \exists ! p_t \in \text{Ports}(t) : (p_s, p_t) \in \mathcal{M}_{\text{port}} \;\wedge\; \delta(p_t) = \delta(p_s) \;\wedge\; \tau(p_s) \le \tau(p_t)
  $$

  Multiplicity Bounds Well-Formedness Invariant: Declared multiplicity intervals must be valid and non-empty:

  $$
  \forall U \in \mathcal{U}_{\text{alloc}}, \quad 0 \le \mu(U).m_{\min} \le \mu(U).m_{\max} \;\wedge\; (\mu(U).m_{\max} \ge 1 \vee \mu(U).m_{\max} = 0)
  $$

  Dependency Acyclicity Invariant: The transitive closure $E_{\text{alloc}}^+$ of the allocation graph must be irreflexive:

  $$
  \forall v \in V_S \cup V_T, \quad (v, v) \notin E_{\text{alloc}}^+
  $$

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

  $$
  \begin{aligned}
  \Delta_D &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(D_{\text{alloc}})) \\
  \Delta_U &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u_{\text{src}}) \mathbin{\Vert} \text{\_allocated\_to\_} \mathbin{\Vert} \text{FQN}(u_{\text{tgt}}))
  \end{aligned}
  $$

  Diagnostic Code Trigger Invariant: Violations of bipartite domain boundaries, reflexive allocation, port interface consistency, multiplicity bounds, or acyclicity deterministically trigger structured diagnostics in accordance with REQ-0191:

  $$
  \begin{aligned}
  (s \notin V_S \vee t \notin V_T) &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0200}, \text{AllocationDomainViolation}) \in \mathcal{D}_{\text{sink}} \\
  s = t &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0200}, \text{ReflexiveAllocationViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists p_s \in \text{Ports}(s) : \neg\text{CompatiblePort}(p_s, \mathcal{M}_{\text{port}}(p_s)) &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0200}, \text{AllocationPortMismatch}) \in \mathcal{D}_{\text{sink}} \\
  \mu(U).m_{\min} \gt \mu(U).m_{\max} &\implies \text{Diagnostic}(U, \text{DiagnosticCode::E0200}, \text{AllocationMultiplicityViolation}) \in \mathcal{D}_{\text{sink}} \\
  (v, v) \in E_{\text{alloc}}^+ &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0203}, \text{CircularAllocationDependency}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

  Diagnostic Taxonomy Containment Invariant: All emitted allocation diagnostics strictly belong to the Metamodel and Typing family and Ingestion error limit family:

  $$
  \forall d \in \mathcal{D}_{\text{alloc}}, \quad \text{code}(d) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0203}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{ingest}}
  $$

- **Computational Complexity & Algorithmic Bounds**: Lowering and static semantic verification of `AllocationDefinition` and `AllocationUsage` elements execute strictly within Complexity Class $\mathbf{P}$.

  **Relation to Algorithmic Bound NP-2**: While optimal resource allocation and channel multiplexing under multi-dimensional knapsack and vector bin packing constraints is strongly NP-hard (governed by NP-2 in REQ-0147 via First-Fit Decreasing heuristics and branch-and-bound search), static metamodel lowering and verification in REQ-0077 operates strictly over declared bipartite mapping relations and concrete interface port signatures. Under this restriction, allocation verification reduces to bipartite domain tagging, port signature matching, and directed graph cycle detection, executing in deterministic polynomial time without backtracking.

  **Asymptotic Verification Complexity**: For an AST model containing $|V_S|$ source nodes, $|V_T|$ target nodes, $V = |V_S| + |V_T|$ total candidate nodes, and $E = |E_{\text{alloc}}|$ declared allocation edges:
  1. *Node Allocation & Interning*: Allocating allocation definitions and usages in contiguous arena storage and interning symbol strings requires amortized $O(1)$ time per node, totaling $O(V + E)$ time.
  2. *Bipartite Domain Disjointness & Irreflexivity*: For each allocation edge $(s, t) \in E_{\text{alloc}}$, verifying domain tags $s \in V_S$, $t \in V_T$, and non-reflexivity $s \ne t$ requires strictly $O(1)$ scalar tag and handle comparisons, totaling $O(E)$ time.
  3. *Interface Port Allocation Consistency*: For each allocation edge $(s, t)$, verifying that each port $p_s \in \text{Ports}(s)$ maps to a corresponding port $p_t \in \text{Ports}(t)$ requires looking up interned port names and verifying directionality ($\delta(p_c) = \delta(p_a)$) and subtyping ($\tau(p_a) \le \tau(p_c)$). With precomputed reachability bitsets for subtyping queries ($O(1)$ per query) and bounded port count $K_{\text{ports}} \le 64 = O(1)$ per classifier, checking all ports for an edge executes in $O(K_{\text{ports}}) = O(1)$ time, totaling $O(E)$ time across the model.
  4. *Multiplicity Bounds Validation*: Checking $0 \le m_{\min}(U) \le m_{\max}(U)$ executes in $O(1)$ integer comparisons per usage, totaling $O(E)$ time.
  5. *Acyclicity Verification (Tarjan's SCC / DFS)*: Detecting circular allocation dependency chains over the directed graph $(V, E_{\text{alloc}})$ executes in deterministic $O(V + E)$ time and $O(V)$ auxiliary stack space.

  Total sequential verification time across all allocation definitions and usages is strictly linear in the size of the allocation graph:

  $$
  T_{\text{validate}}(V, E) \in O(|V| + |E_{\text{alloc}}|)
  $$

  **Parallel Work-Stealing Scaling (Architectural Directive 2)**: When allocation lowering and interface verification across independent package scopes is scheduled on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$:

  $$
  T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{|V| + |E_{\text{alloc}}|}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
  $$

  **Space Complexity & Memory Bounds**: Auxiliary working memory is strictly bounded by $O(|V| + |E_{\text{alloc}}|)$ for contiguous arena storage and bipartite graph adjacency representations. Traversal recursion depth is bounded by hierarchy depth $h \le 32$ ($O(1)$ stack memory). The diagnostic error sink is bounded by $O(C_{\text{max\_errors}}) = O(1)$ allocated records.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models containing abstract placeholders (`Package_0`, `AllocationDef_Alpha`, `AllocationDef_Beta`, `AllocationUsage_1`, `AllocationUsage_2`, `Action_A`, `Action_B`, `Part_X`, `Part_Y`, `Port_In`, `Port_Out`, `Classifier_Alpha`, `Classifier_Beta`, `param_x : Real`). Conformance validation shall enforce the following test gates:

  1. **Canonical Allocation Lowering Gate**: Declare behavioral action `Action_A` and structural part `Part_X`. Declare `allocate Action_A to Part_X`. Assert successful lowering into contiguous arena storage, valid arena node handles, valid bipartite edge construction, and zero diagnostic emissions.
  2. **Bipartite Cross-Domain Inversion Gate (`E0200`)**: Attempt to declare an inverted allocation allocating structural part `Part_X` to behavioral action `Action_A`, or an allocation between two incompatible element kinds. Assert deterministic compile-time rejection with structured diagnostic error code `E0200` (`AllocationDomainViolation`), assignment of error sentinel $\bot_{\text{alloc}}$, and zero panics.
  3. **Reflexive Allocation Prohibition Gate (`E0200`)**: Attempt to declare a reflexive allocation allocating an element to itself (`allocate Action_A to Action_A` or `allocate Part_X to Part_X`). Assert deterministic compile-time rejection with diagnostic error code `E0200` (`ReflexiveAllocationViolation`).
  4. **Interface Port Directionality and Compatibility Gate**: Declare `Action_A` with ports `Port_In : in Classifier_Alpha` and `Port_Out : out Classifier_Beta`. Declare `Part_X` with matching ports `Port_In : in Classifier_Alpha` and `Port_Out : out Classifier_Beta`. Allocate `Action_A` to `Part_X`; assert successful compilation. In a second test, declare `Part_X` with inverted directionality `Port_In : out Classifier_Alpha`; assert deterministic compile-time rejection with diagnostic error code `E0200` (`AllocationPortMismatch`).
  5. **Port Payload Subtyping Conformance Gate**: Declare `Action_A` with port `Port_Out : out Classifier_Beta` where `Classifier_Beta :> Classifier_Alpha`. Declare `Part_X` with port `Port_Out : out Classifier_Alpha`. Assert successful subtyping conformance ($\tau(p_a) \le \tau(p_c)$) with zero diagnostics. In an opposing test, declare incompatible disjoint types; assert deterministic rejection with diagnostic error code `E0200` (`AllocationPortMismatch`).
  6. **Missing Port Mapping Completeness Gate (`E0200`)**: Declare `Action_A` with an unmapped external port `Port_Extra : in Classifier_Alpha` that is absent from target component `Part_X`. Assert deterministic compilation rejection with diagnostic error code `E0200` (`AllocationPortMismatch`) identifying the unmapped port.
  7. **Allocation Multiplicity Bounds Well-Formedness Gate (`E0200`)**: Declare an allocation usage with inverted multiplicity `[5..2]` ($m_{\min} \gt m_{\max}$). Assert deterministic compile-time rejection with diagnostic error code `E0200` (`AllocationMultiplicityViolation`).
  8. **Circular Allocation Dependency Detection Gate (`E0203`)**: Construct a synthetic multi-tier circular allocation chain ($e_1 \mapsto e_2 \mapsto e_3 \mapsto e_1$). Assert deterministic cycle detection via Tarjan's SCC/DFS, emission of diagnostic error code `E0203` (`CircularAllocationDependency`) identifying the cycle path, and graceful recovery.
  9. **Allocation Definition Specialization Gate (`:>`)**: Declare `allocation def AllocationDef_Alpha`. Declare specializing `allocation def AllocationDef_Beta :> AllocationDef_Alpha` covariantly refining source and target endpoint types. Assert successful AST lowering and type conformance with zero diagnostics.
  10. **Synchronization Token Recovery & Error Accumulation Gate (Architectural Directive 4)**: Ingest a model unit containing 5 distinct malformed allocation declarations (bipartite domain inversion, reflexive allocation, missing port mapping, inverted multiplicity) separated by delimiter tokens. Assert that the lowering engine resynchronizes on token boundaries, accumulates all 5 `E0200` diagnostics with precise source spans, and when the error count reaches $C_{\text{max\_errors}}$, emits terminal diagnostic `E0199` and halts gracefully.
  11. **Deterministic UUIDv5 Topological Identity Gate (Architectural Directive 1)**: Verify that 100% of lowered `AllocationDefinition` and `AllocationUsage` AST nodes and edges bind valid RFC 4122 UUIDv5 identifiers computed from the fixed DEAP namespace OID and canonical fully qualified paths, asserting bitwise identical digests and 0-byte diff churn across repeated compilation runs.
  12. **Bounded Work-Stealing Parallelism Gate (Architectural Directive 2)**: Ingest a model containing 50 packages with $10^4$ allocation definitions and usages across $N_{\text{max\_workers}}$ threads; assert data-race freedom, deterministic AST output, and identical node ordering compared to single-threaded compilation.
  13. **Release Mode Latency & Memory Budget Gate (Architectural Directive 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, verify that lowering and validating $10^4$ synthetic allocation definitions and usages executes in under 25 ms, peak RSS memory remains strictly under 100 MB, zero panics occur, and 0-byte diff churn is preserved.
