### REQ-0168: Feature Class Diagram Emission with Ancestor Containment & No Isolated Classes

- **Normative Statement**: The downstream specification projection engine, class diagram synthesizer, and structural relationship validator of Subsystem 9 shall synthesize declarative Mermaid class diagrams (`classDiagram`) for every Feature specification projected from the sovereign compilation unit AST. For each projected Feature, the diagram synthesizer shall extract and render complete ancestor containment hierarchies spanning from the root container (such as the top-level Package or Subsystem) down to every constituent feature node (including part definitions, item usages, ports, actions, and states) and shall statically verify that zero disconnected or isolated classes are emitted in the resulting diagram. If any class vertex $v$ exhibits an undirected degree of zero ($\text{degree}(v) = 0$), or if the diagram multigraph $\mathcal{G}$ is partitioned into multiple disconnected components ($|\pi_0(\mathcal{G})| \gt 1$), or if any ancestor containment path is truncated or broken, the compiler shall fail closed, emit diagnostic error code `E0231` (`IsolatedClassInDiagramViolation` or `DisconnectedFeatureClassDiagramViolation`), and halt downstream persistence for the offending feature artifact.

  Specifically, the Feature class diagram synthesis engine and structural connectivity validator shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Feature Scope & Class Diagram Boundary**:
     - For every feature classifier $F \in \mathcal{F}_{\text{proj}}$ established in the feature dependency DAG (REQ-0160, REQ-0161), the downstream projection engine shall generate a dedicated UML class diagram artifact rendered in standard Mermaid `classDiagram` syntax.
     - The class diagram scope shall encapsulate all domain state classifiers, part usages, and structural typing definitions formalized in Feature Layer 1 (REQ-0165), behavioral operations and state machine entities formalized in Feature Layer 2 (REQ-0166), and interface endpoints formalized in Feature Layer 3 (REQ-0167).
     - Each constituent entity within the Feature shall be mapped to a distinct class diagram vertex $v \in \mathcal{V}(F)$, with attributes and operation signatures rendered as internal class members according to standard UML formatting.
  2. **Ancestor Containment Hierarchy Synthesis**:
     - To prevent contextual detachment in downstream documentation, the projection engine shall compute the complete upward ancestor containment chain $\pi(c_k) = \langle c_0, c_1, \dots, c_k \rangle$ from the root container $c_0 \in \mathcal{V}(F)$ (the root package or enclosing subsystem) down to every target entity $c_k \in \mathcal{C}_{\text{target}}(F)$.
     - Intermediate ancestor containers along the path $\pi(c_k)$ (enclosing packages, parent subsystems, composite assemblies, and owner parts) that reside outside the local feature boundary shall be projected as contextual ancestor classes within $\mathcal{V}(F)$.
     - For every adjacent pair $(c_i, c_{i+1})$ along the ancestor containment path, the synthesizer shall emit a structural composition relationship using Mermaid composition syntax ($c_i *-- c_{i+1}$), establishing an unbroken structural spine from the root container to each feature component.
  3. **No Isolated Classes & Global Connectivity Invariant**:
     - Following diagram multigraph extraction, the compiler shall perform static topological inspection of the diagram multigraph $\mathcal{G}(F) = (\mathcal{V}(F), \mathcal{E}(F))$.
     - *Zero Degree Zero Classes*: The engine shall verify that every emitted class vertex $v \in \mathcal{V}(F)$ has an undirected degree of at least one ($\text{degree}(v) \ge 1$). Zero isolated, unlinked, or dangling class nodes are permitted.
     - *Weak Graph Connectivity*: The engine shall verify that the underlying undirected graph $\mathcal{G}_{\text{undir}}(F)$ is connected ($|\pi_0(\mathcal{G}_{\text{undir}}(F))| = 1$). No feature class diagram shall be partitioned into disjoint subgraphs or unlinked clusters.
     - If any vertex $v \in \mathcal{V}(F)$ has $\text{degree}(v) = 0$, or if $\mathcal{G}(F)$ is disconnected into multiple components ($|\pi_0(\mathcal{G}_{\text{undir}}(F))| \gt 1$), or if any ancestor containment path is truncated, the compiler shall fail closed, emit diagnostic error code `E0231` (`IsolatedClassInDiagramViolation` or `DisconnectedFeatureClassDiagramViolation`), and halt downstream persistence for the offending feature artifact.
  4. **Relationship Typing & Syntax Mapping**:
     - Structural containment relationships shall be rendered as Mermaid composition edges: `c_parent *-- c_child : contains`.
     - Classifier inheritance and subtyping relationships (conforming to REQ-0061) shall be rendered as Mermaid generalization edges: `c_sub --|> c_super : specializes`.
     - Interface realization contracts (conforming to REQ-0075) shall be rendered as Mermaid realization edges: `c_impl ..|> c_iface : realizes`.
     - Directed port bindings, item flows (conforming to REQ-0076, REQ-0148), and cross-classifier associations shall be rendered as directed association edges: `c_src --> c_tgt : flow`.
     - Every diagram edge $e \in \mathcal{E}(F)$ must correspond bijectively to an existing AST relationship (conforming to the zero phantom edge invariant in REQ-0162). Fabricated or phantom edges are strictly prohibited.
  5. **Identifier Sanitization & Deterministic Canonical Sorting**:
     - All class names, member identifiers, and relation labels in the Mermaid output shall be sanitized in accordance with REQ-0019, replacing syntax-breaking delimiters and non-alphanumeric characters with underscores (`_`).
     - Vertices and edges shall be serialized in strictly deterministic canonical order based on the 32-bit `SymbolId` comparison of interned fully qualified names ($\prec_{\text{canon}}$, REQ-0032), guaranteeing bitwise reproducibility and 0-byte diff churn across idempotent compilation runs (REQ-0003).
  6. **Contiguous Bump Arena Storage & Node Handle Addressing**:
     - All intermediate graph vertices, edge lists, containment paths, and verification result records shall be allocated within contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit arena node handles (REQ-0035).
  7. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized Feature class diagram $\mathcal{G}(F)$, constituent class vertex $v \in \mathcal{V}(F)$, relationship edge $e \in \mathcal{E}(F)$, and connectivity verification witness shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))$) in accordance with REQ-0010 and REQ-0159. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel extraction of containment paths, concurrent synthesis of class diagrams, and multigraph connectivity verification across independent Features and packages shall execute strictly on a centralized, bounded work-stealing thread pool with worker upper bound $N_{\text{max\_workers}}$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Class names, package identifiers, attribute strings, operation signatures, and diagram relationship labels shall be interned into the deduplicated global symbol interner pool during lexical analysis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The class diagram synthesizer and graph validator shall implement synchronization token error recovery on Feature definition boundaries (`###`), YAML frontmatter fences (`---`), and Mermaid block boundaries (`classDiagram`) in accordance with REQ-0013 and REQ-0016. When isolated class or disconnected diagram violations (`E0231`) occur, the engine shall record structured diagnostics into the preallocated error sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinels ($\bot_{\text{diagram}}$), and continue validating subsequent Feature specifications. If accumulated diagnostics reach capacity limit $C_{\text{max\_errors}}$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The Feature class diagram projection engine and graph connectivity validator shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency (strictly under 25 ms for $|V| + |E| = 10^4$ graph elements) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  8. **Pure Abstract MBSE Placeholder Mandate**:
     - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Subsystem_0`, `Subsystem_1`, `Component_0`, `Component_1`, `Feature_0`, `Feature_1`, `Part_0`, `Part_1`, `Port_0`, `Port_1`, `Flow_A`, `Flow_B`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{V}_{\text{AST}}$ denote the universe of allocated AST nodes in contiguous bump arena storage, and let $\mathcal{S}_{\text{intern}}$ denote the deduplicated global symbol interner pool.
  Let $\mathcal{F}_{\text{proj}} \subset \mathcal{V}_{\text{AST}}$ denote the set of projected feature specifications.

  For each feature $F \in \mathcal{F}_{\text{proj}}$, its emitted class diagram multigraph is formalized as a 7-tuple:

  $$
  \mathcal{G}(F) = \langle \text{id}_{\mathcal{G}}, F, \mathcal{V}(F), \mathcal{E}(F), r_F, \Delta_{\mathcal{G}(F)}, \text{span}_{\mathcal{G}(F)} \rangle
  $$

  where:

  $$
  \begin{aligned}
  \text{id}_{\mathcal{G}} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  F &\in \mathcal{F}_{\text{proj}} \quad (\text{owning feature specification handle}) \\
  \mathcal{V}(F) &\subset \mathbb{N}_{32} \quad (\text{finite set of class diagram vertices allocated in arena}) \\
  \mathcal{E}(F) &\subset \mathbb{N}_{32} \times \mathbb{N}_{32} \times \mathcal{K}_{\text{rel}} \quad (\text{finite multiset of diagram relationship edges}) \\
  r_F &\in \mathcal{V}(F) \quad (\text{unique root container vertex handle}) \\
  \Delta_{\mathcal{G}(F)} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_{\mathcal{G}(F)} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
  $$

  The relationship kind space $\mathcal{K}_{\text{rel}}$ is defined as:

  $$
  \mathcal{K}_{\text{rel}} = \{ \text{Composition}, \text{Aggregation}, \text{Inheritance}, \text{Realization}, \text{Association}, \text{Dependency} \}
  $$

  Each vertex $v \in \mathcal{V}(F)$ represents a structural classifier or container and is formalized as a 6-tuple:

  $$
  v = \langle \text{id}_v, \text{name}_v, \kappa_v, \mathcal{M}_v, \Delta_v, \text{span}_v \rangle
  $$

  where $\text{name}_v \in \mathcal{S}_{\text{intern}}$, $\kappa_v \in \{ \text{RootContainer}, \text{Subsystem}, \text{Package}, \text{FeatureClassifier}, \text{Part}, \text{Port}, \text{Action}, \text{State} \}$, $\mathcal{M}_v = \langle \mathcal{A}_v, \mathcal{O}_v \rangle$ encapsulates internal attributes and operations, and $\Delta_v \in \{0, 1\}^{128}$ is the deterministic RFC 4122 UUIDv5 anchor.

  Each edge $e \in \mathcal{E}(F)$ is formalized as a 5-tuple:

  $$
  e = \langle \text{src}(e), \text{tgt}(e), \text{rel}(e), \Delta_e, \text{span}_e \rangle
  $$

  where $\text{src}(e), \text{tgt}(e) \in \mathcal{V}(F)$, $\text{rel}(e) \in \mathcal{K}_{\text{rel}}$, and $\Delta_e \in \{0, 1\}^{128}$.

  1. Degree Definitions:
  For every vertex $v \in \mathcal{V}(F)$, the incoming degree $\text{indegree}(v)$, outgoing degree $\text{outdegree}(v)$, and total undirected degree $\text{degree}(v)$ are defined as:

  $$
  \begin{aligned}
  \text{indegree}(v) &= |\{ e \in \mathcal{E}(F) \mid \text{tgt}(e) = v \}| \\
  \text{outdegree}(v) &= |\{ e \in \mathcal{E}(F) \mid \text{src}(e) = v \}| \\
  \text{degree}(v) &= \text{indegree}(v) + \text{outdegree}(v)
  \end{aligned}
  $$

  2. Zero Isolated Classes Invariant:
  Every class vertex rendered in the diagram must have an undirected degree of at least one:

  $$
  \forall F \in \mathcal{F}_{\text{proj}}, \quad \forall v \in \mathcal{V}(F), \quad \text{degree}(v) \ge 1
  $$

  3. Underlying Undirected Graph & Weak Connectivity Invariant:
  Let $\mathcal{G}_{\text{undir}}(F) = (\mathcal{V}(F), \mathcal{E}_{\text{undir}}(F))$ denote the undirected multigraph induced by $\mathcal{G}(F)$, where:

  $$
  \mathcal{E}_{\text{undir}}(F) = \{ \{u, v\} \mid \exists e \in \mathcal{E}(F) : (\text{src}(e) = u \land \text{tgt}(e) = v) \lor (\text{src}(e) = v \land \text{tgt}(e) = u) \}
  $$

  The class diagram multigraph must form a single connected component:

  $$
  \text{IsConnected}(\mathcal{G}(F)) \iff |\pi_0(\mathcal{G}_{\text{undir}}(F))| = 1
  $$

  Equivalently, between any two distinct vertices in $\mathcal{V}(F)$, there must exist an undirected path in $\mathcal{G}_{\text{undir}}(F)$:

  $$
  \forall u, v \in \mathcal{V}(F), \quad u \ne v \implies \exists \mathbf{p} = \langle w_0, w_1, \dots, w_m \rangle \text{ s.t. } w_0 = u \land w_m = v \land (\forall j \in \{0, \dots, m-1\}, \, \{w_j, w_{j+1}\} \in \mathcal{E}_{\text{undir}}(F))
  $$

  4. Root Container Dominance & Ancestor Containment Path Completeness:
  There exists a unique designated root container $r_F \in \mathcal{V}(F)$ satisfying:

  $$
  \exists! r_F \in \mathcal{V}(F) \text{ s.t. } \kappa(r_F) = \text{RootContainer} \quad \wedge \quad \text{indegree}_{\text{comp}}(r_F) = 0
  $$

  where $\text{indegree}_{\text{comp}}(v) = |\{ e \in \mathcal{E}(F) \mid \text{tgt}(e) = v \land \text{rel}(e) = \text{Composition} \}|$.

  Let $\mathcal{C}_{\text{target}}(F) \subset \mathcal{V}(F)$ denote the set of target constituent entities belonging to feature $F$. For every target entity $c_k \in \mathcal{C}_{\text{target}}(F)$, let $\pi(c_k) = \langle c_0, c_1, \dots, c_k \rangle$ be the canonical containment path from root container $c_0 = r_F$ down to $c_k$ in the compilation unit AST. The class diagram multigraph must contain every directed composition edge along the path:

  $$
  \forall c_k \in \mathcal{C}_{\text{target}}(F), \quad \forall i \in \{0, \dots, k-1\}, \quad (c_i, c_{i+1}) \in \mathcal{E}(F) \quad \wedge \quad \text{rel}((c_i, c_{i+1})) = \text{Composition} \quad (c_i *-- c_{i+1})
  $$

  5. Soundness & Zero Phantom Edge Invariant (REQ-0162):
  Every edge rendered in the class diagram must correspond to an authoritative structural relationship in the compilation unit AST:

  $$
  \forall e \in \mathcal{E}(F), \quad \exists \rho \in \text{ASTRelationships} \quad \text{such that } \text{endpoints}(\rho) = \{ \text{handle}(\text{src}(e)), \text{handle}(\text{tgt}(e)) \} \quad \wedge \quad \text{kind}(\rho) = \text{rel}(e)
  $$

  6. Deterministic Diagnostic Trigger Rules (REQ-0191):
  If an isolated class is detected, or if the diagram graph is disconnected, or if an ancestor containment path is truncated, diagnostic error code `E0231` shall be emitted into the preallocated error sink buffer $\mathcal{D}_{\text{sink}}$:

  $$
  \begin{aligned}
  \exists v \in \mathcal{V}(F) : \text{degree}(v) = 0 &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0231}, \text{IsolatedClassInDiagramViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\pi_0(\mathcal{G}_{\text{undir}}(F))| \gt 1 &\implies \text{Diagnostic}(\mathcal{G}(F), \text{DiagnosticCode::E0231}, \text{DisconnectedFeatureClassDiagramViolation}) \in \mathcal{D}_{\text{sink}} \\
  \exists c_k \in \mathcal{C}_{\text{target}}(F), \, \exists i \in \{0, \dots, k-1\} : (c_i, c_{i+1}) \notin \mathcal{E}(F) &\implies \text{Diagnostic}(c_k, \text{DiagnosticCode::E0231}, \text{BrokenAncestorContainmentPathViolation}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
  $$

  7. Fail-Closed Pipeline Halting Invariant:

  $$
  |\mathcal{D}_{\text{sink}} \cap \{ D \mid \text{code}(D) \in \{ \text{E0231}, \text{E0199} \} \}| \gt 0 \implies \text{HaltPipeline}() \land \text{ArtifactEmissionGate} = \text{BLOCKED}
  $$

  8. Deterministic RFC 4122 UUIDv5 Identification Invariant (Directive 1):

  $$
  \begin{aligned}
  \Delta_{\mathcal{G}(F)} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::ClassDiagram"}) \\
  \forall v \in \mathcal{V}(F), \quad \Delta_v &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::ClassDiagram::Vertex::"} \mathbin{\Vert} \text{name}_v(v)) \\
  \forall e \in \mathcal{E}(F), \quad \Delta_e &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::ClassDiagram::Edge::"} \mathbin{\Vert} \text{name}_v(\text{src}(e)) \mathbin{\Vert} \text{"->"} \mathbin{\Vert} \text{name}_v(\text{tgt}(e))) \\

  \end{aligned}
  $$

  9. Deterministic Canonical Ordering & 0-Byte Diff Churn Invariant (REQ-0003, REQ-0032):
  Let $\prec_{\text{canon}}$ denote the total ordering over interned symbols by 32-bit `SymbolId` token:

  $$
  \begin{aligned}
  u \prec_{\text{canon}} v &\iff \text{SymbolId}(\text{name}_v(u)) \lt \text{SymbolId}(\text{name}_v(v)) \\
  e_1 \prec_{\text{canon}} e_2 &\iff \langle \text{SymbolId}(\text{name}_v(\text{src}(e_1))), \text{SymbolId}(\text{name}_v(\text{tgt}(e_1))) \rangle \prec_{\text{lex}} \langle \text{SymbolId}(\text{name}_v(\text{src}(e_2))), \text{SymbolId}(\text{name}_v(\text{tgt}(e_2))) \rangle
  \end{aligned}
  $$

  Every serialization sequence of vertices $\mathbf{S}_{\mathcal{V}}$ and edges $\mathbf{S}_{\mathcal{E}}$ satisfies strict monotonic ordering under $\prec_{\text{canon}}$, guaranteeing bitwise identical output across compilation runs:

  $$
  \text{Emit}(\mathcal{G}^{(1)}(F)) = \text{Emit}(\mathcal{G}^{(2)}(F))
  $$

  **Asymptotic Complexity Analysis**:
  Let $|V| = |\mathcal{V}(F)|$ denote the number of class vertices, $|E| = |\mathcal{E}(F)|$ denote the number of relationship edges, and $|A|$ denote the byte length of the emitted Mermaid class diagram.
  1. *Containment Path Traversal & Ancestor Chain Construction*:
     Extracting the upward ancestor path for each target entity $c_k \in \mathcal{C}_{\text{target}}(F)$ traverses AST parent links. In a tree of height $h$, each lookup takes $O(h)$ steps. Since each AST node has at most one parent in the namespace containment tree, and visited ancestor nodes are memoized in contiguous bump arena storage, the total cost to extract and union all ancestor paths for feature $F$ is strictly bounded by $O(|V|)$ operations:
     $$T_{\text{containment}}(|V|) \in O(|V|)$$
  2. *Graph Construction & Edge Resolution*:
     Constructing the vertex roster and inserting structural containment, specialization, and association edges takes $O(|V| + |E|)$ operations. Each vertex and edge record is appended to a contiguous slice in the bump arena:
     $$T_{\text{graph\_build}}(|V|, |E|) \in O(|V| + |E|)$$
  3. *Vertex Degree Evaluation*:
     Computing incoming and outgoing degree counts requires iterating over the edge list once and incrementing degree counters stored in an array indexed by vertex handle. For $|E|$ edges, this executes in strictly $O(|E|)$ time, followed by an $O(|V|)$ scan to verify $\text{degree}(v) \ge 1$:
     $$T_{\text{degree}}(|V|, |E|) \in O(|V| + |E|)$$
  4. *Weak Connectivity Verification (BFS / DFS)*:
     Evaluating the number of connected components $|\pi_0(\mathcal{G}_{\text{undir}}(F))|$ on the undirected multigraph via Breadth-First Search (BFS) or Depth-First Search (DFS) visits each vertex and edge at most twice. Total time complexity is strictly linear:
     $$T_{\text{connectivity}}(|V|, |E|) \in O(|V| + |E|)$$
     Alternatively, using Disjoint Set Union (DSU) with path compression and union by rank, connectivity verification executes in $O((|V| + |E|) \alpha(|V|))$ time, where $\alpha$ is the inverse Ackermann function ($\alpha(n) \le 4$ for all practical inputs), which is virtually linear.
  5. *Deterministic Symbol Sorting (REQ-0032)*:
     Sorting $|V|$ vertices and $|E|$ edges by 32-bit `SymbolId` token requires comparison sorting in $O(|V| \log |V| + |E| \log |E|)$ time, or linear radix sorting in $O(|V| + |E|)$ time:
     $$T_{\text{sort}}(|V|, |E|) \in O(|V| \log |V| + |E| \log |E|)$$
  6. *Mermaid Serialization & Text Streaming (REQ-0162)*:
     Emitting Mermaid `classDiagram` syntax, class definitions, member attributes, and formatted relationship arrows streams directly to the artifact sink in time proportional to the total emitted diagram byte length $|A|$:
     $$T_{\text{emission}}(|A|) \in O(|A|)$$
  7. *Aggregate Sequential Execution Time*:
     The total time complexity across all phases is strictly linear:
     $$T_{\text{total}}(|V|, |E|, |A|) = T_{\text{containment}} + T_{\text{graph\_build}} + T_{\text{degree}} + T_{\text{connectivity}} + T_{\text{sort}} + T_{\text{emission}} \in O(|V| + |E| + |A|)$$
     Across an entire compilation unit containing $|\mathcal{F}_{\text{proj}}|$ features:
     $$T_{\text{unit}} = \sum_{F \in \mathcal{F}_{\text{proj}}} O(|V_F| + |E_F| + |A_F|) \in O(|\mathcal{V}_{\text{AST}}|)$$
  8. *Space Complexity & Arena Memory Bounds*:
     All graph representations, vertex rosters, edge slices, and visitor bitsets are allocated in contiguous bump arena storage, requiring strictly $O(|V| + |E|)$ bytes. Intermediate string tokens are interned into the global symbol pool. Diagnostic buffer capacity is bounded by $O(C_{\text{max\_errors}}) = O(1)$. Auxiliary heap allocation is strictly $O(1)$.
  9. *Parallel Work-Stealing Scaling (Directive 2)*:
     When synthesizing and verifying independent feature class diagrams across $N_{\text{max\_workers}}$ threads on a bounded work-stealing thread pool:
     $$T_{\text{parallel}}(|V|, |E|, |A|, N_{\text{max\_workers}}) \in O\left( \frac{|V| + |E| + |A|}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)$$
     guaranteeing thread isolation, data-race freedom, and deterministic bitwise identical outputs.
