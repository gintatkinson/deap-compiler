### REQ-0004: Workspace Sovereignty & Dynamic Relative Path Resolution

- **Normative Statement**: The compiler platform shall operate in a completely self-contained, sovereign repository architecture wherein all filesystem operations, cross-module schema imports, model fragment references, configuration lookups, and generated output artifact paths resolve dynamically using canonical workspace-relative paths derived from an authenticated repository root. The compiler must discover the workspace root $`\mathcal{R}`$ dynamically at runtime by searching parent directories upward from the current working directory for the nearest sovereign repository marker, or by accepting an explicit root path supplied via command-line invocation arguments. All path resolution operations shall strictly enforce boundary containment: every resolved path must reside strictly within the directory hierarchy rooted at $`\mathcal{R}`$. The compiler must reject any path reference that attempts directory traversal outside $`\mathcal{R}`$ (such as parent traversal sequences `..`, absolute filesystem paths, drive letter prefixes, user home directory expansions, symbolic links targeting external locations, and network URIs). The compiler shall guarantee bitwise determinism and zero environment leakage: all synthesized intermediate representations, abstract syntax trees, and output artifacts must be bit-for-bit identical regardless of the absolute filesystem path where the repository workspace is mounted on disk, strictly forbidding absolute machine paths, user names, hostnames, or build-environment paths from appearing in generated outputs.

- **Formal Invariant**: Let $`\mathcal{R}`$ denote the sovereign repository root path determined dynamically at runtime. Let $`\mathcal{P}_{\text{rel}}`$ denote the set of normalized relative paths defined over $`\mathcal{R}`$, and let $`\bowtie`$ denote canonical path concatenation. Every resolved filesystem path $`P`$ satisfies:

$$
P = \mathcal{R} \bowtie p_{\text{rel}}, \quad \text{where } p_{\text{rel}} \in \mathcal{P}_{\text{rel}}
$$

Boundary Containment Invariant: For every accessed or resolved path $`P`$, the canonicalized path $`\text{Canonicalize}(P)`$ must satisfy strict prefix containment within the repository subtree:

$$
\text{PrefixOf}(\mathcal{R}, \text{Canonicalize}(P)) \equiv \text{true} \quad \wedge \quad \text{Canonicalize}(P) \in \text{Subtree}(\mathcal{R})
$$

Prohibited Path Rejection: Let $`\mathcal{P}_{\text{invalid}}`$ denote the set of all path strings attempting directory traversal beyond $`\mathcal{R}`$, specifying absolute machine roots, or referencing external network protocols. Any attempted resolution of $`p \in \mathcal{P}_{\text{invalid}}`$ fails deterministically:

$$
\forall p \in \mathcal{P}_{\text{invalid}}, \quad \text{Resolve}(p, \mathcal{R}) = \bot \implies \text{Diagnostic}(p) = \text{E0100}
$$

Bitwise Determinism Invariance Across Distinct Workspace Mount Locations: Let $`\mathcal{I}`$ denote an identical set of input schema specifications, and let $`\mathcal{R}_A`$ and $`\mathcal{R}_B`$ denote two distinct workspace mount root paths on disk ($`\mathcal{R}_A \neq \mathcal{R}_B`$). Let $`\mathcal{C}(\mathcal{I}, \mathcal{R})`$ denote the complete set of compiled output artifacts generated by compiler execution $`\mathcal{C}`$ within workspace root $`\mathcal{R}`$. The resulting cryptographic digests satisfy:

$$
\text{SHA256}(\mathcal{C}(\mathcal{I}, \mathcal{R}_A)) \equiv \text{SHA256}(\mathcal{C}(\mathcal{I}, \mathcal{R}_B))
$$

Absolute Path Non-Leakage Invariant: For every compiled output artifact $`a \in \text{Artifacts}(\mathcal{C}(\mathcal{I}, \mathcal{R}))`$ and for every absolute path string representation $`\text{PathString}(\mathcal{R})`$ of repository root $`\mathcal{R}`$:

$$
\forall a \in \text{Artifacts}(\mathcal{C}(\mathcal{I}, \mathcal{R})), \quad \text{ContainsSubstring}(a, \text{PathString}(\mathcal{R})) \equiv \text{false}
$$

Relative Path Normalization Idempotence: For all $`p_{\text{rel}} \in \mathcal{P}_{\text{rel}}`$, the normalization operator satisfies:

$$
\text{Normalize}(\text{Normalize}(p_{\text{rel}})) = \text{Normalize}(p_{\text{rel}})
$$

- **Computational Complexity & Algorithmic Bounds**: Dynamic path resolution and validation execute within Complexity Class $`\mathbf{P}`$. Upward workspace root discovery executes in $`O(D)`$ time, where $`D`$ represents the directory nesting depth between the working directory and the filesystem root ($`D \le D_{\max}`$, with bounded constant $`D_{\max} = 64`$). Path normalization, lexical component parsing, and canonicalization execute in deterministic linear time $`O(|P|)`$ with respect to the character length $`|P|`$ of the path string, performing zero recursive filesystem traversal. Boundary prefix containment verification executes in $`O(|P|)`$ string comparison time. Cryptographic digest verification executes in $`O(M)`$ time where $`M`$ is the total byte size of generated artifacts. Auxiliary space complexity is bounded by $`O(|P|)`$ for canonical path representation buffers.

- **Verification & Conformance Criteria**: Compliance shall be verified through deterministic automated test suites. The compiler shall be executed on identical input schemas across two distinct workspace mount directories on independent filesystems, asserting that the Merkle tree root digests and individual SHA256 artifact digests are identical with 0-byte difference. Automated binary and textual scanners shall inspect 100% of generated output artifacts, debug symbols, and serialized AST files to verify that no instance of the absolute workspace mount path $`\text{PathString}(\mathcal{R})`$ or machine-specific home directory appears in any output file. Negative conformance test suites shall supply invalid path inputs containing parent traversals (`../../`), root paths (`/etc/`, `C:\`), home expansions (`~`), and external network schemes (`http://`); in every instance, the compiler shall halt execution and emit diagnostic error code `E0100` citing the offending path token and source location span.
