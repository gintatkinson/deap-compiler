### REQ-0081: SysML v2 EntryAction, DoAction & ExitAction State Lifecycle Hooks

#### 1. Normative Statement

The Core Metamodel, Node Arena & AST Graph Engine, SysML v2 / KerML metamodel lowering engine, and discrete state machine solver shall formalize state lifecycle actions (`entry`, `do`, `exit`) as temporal occurrence hooks bound to state activation, execution, and deactivation intervals. In the KerML and SysML v2 metamodel hierarchy, state elements (`StateDefinition` and `StateUsage`) specialize KerML `Behavior` (which transitively specializes `Class`, `Classifier`, and `OccurrenceDefinition` / `OccurrenceUsage`), representing identity-bearing spatio-temporal behaviors. Each state lifecycle hook (`EntryActionUsage`, `DoActionUsage`, `ExitActionUsage`) shall specialize KerML `ActionUsage` (which specializes `Feature`, `Step`, and `OccurrenceUsage`), representing a featured behavioral action executed in the context of the owning state.

  The compiler shall enforce that for any state $`S`$`, each lifecycle action category possesses an explicit or defaulted multiplicity bounded by `$`[0..1]`$ (at most one entry action, at most one do activity, and at most one exit action per state). Compound or sequenced action statements within a lifecycle block shall be lowered into an enclosing composite sequence action (`ActionUsage` with sequential steps). Declaring duplicate un-sequenced hooks of the same category within a single state usage without composite encapsulation shall be rejected deterministically at compile time with diagnostic error code `E0200` (`DuplicateLifecycleActionHook`), adhering to the standardized diagnostic taxonomy of REQ-0191.

  Every state lifecycle hook must be typed by a valid `ActionDefinition`, `Behavior`, or anonymous behavioral expression conforming to KerML `Behavior` ($`\tau(A) \le \text{Behavior}`$). Binding a lifecycle hook to a structural data type, value type, interface definition, or port definition without behavior shall be rejected at compile time with diagnostic error code `E0200` (`InvalidLifecycleActionTyping`).

  The state machine engine shall map every state residence to a bounded temporal interval $`\mathcal{T}_S = [t_{\text{entry}}(S), t_{\text{exit}}(S)] \subset \mathbb{R} \cup \{ -\infty, +\infty \}`$`, subject to the strict monotonic ordering constraint `$`t_{\text{entry}}(S) \le t_{\text{exit}}(S)`$`. Any state specification defining an inverted temporal interval where `$`t_{\text{entry}} \gt t_{\text{exit}}`$ shall be rejected at compile time with diagnostic error code `E0200` (`InvalidStateResidenceInterval`).

  The execution lifecycle of an active state $`S`$ shall strictly enforce a 3-phase temporal execution sequence:
  1. **State Activation & Entry Action ($`A_{\text{entry}}`$`)**: Executed immediately upon entering state `$`S`$` at `$`t_{\text{entry}}(S)`$`. The temporal extent of the entry action `$`[t_{\text{start}}(A_{\text{entry}}), t_{\text{end}}(A_{\text{entry}})]`$` satisfies `$`t_{\text{start}}(A_{\text{entry}}) = t_{\text{entry}}(S)`$`. Entry action execution shall be atomic, run-to-completion, and strictly non-preemptible. In discrete logical time, execution occurs as an instantaneous step transition (`$`\Delta t = t_{\text{end}}(A_{\text{entry}}) - t_{\text{start}}(A_{\text{entry}}) = 0`$`). External trigger events arriving during entry execution shall be buffered into the state machine event queue and shall not preempt `$`A_{\text{entry}}`$.
  2. **State Residence & Do Activity ($`A_{\text{do}}`$`)**: Initiated strictly upon the successful completion of `$`A_{\text{entry}}`$` (`$`t_{\text{start}}(A_{\text{do}}) \ge t_{\text{end}}(A_{\text{entry}})`$`) and executed during state residence. The temporal extent `$`[t_{\text{start}}(A_{\text{do}}), t_{\text{end}}(A_{\text{do}})]`$` satisfies `$`t_{\text{start}}(A_{\text{do}}) \le t_{\text{end}}(A_{\text{do}}) \le t_{\text{exit}}(S)`$`. Unlike entry and exit actions, `$`A_{\text{do}}`$ is interruptible and preemptible:
     - *Autonomous Completion*: If $`A_{\text{do}}`$ completes execution before an outgoing transition triggers, its status transitions to `Completed` at $`t_{\text{comp}} \le t_{\text{exit}}(S)`$`, and the engine shall post an internal state completion event `$`\varepsilon_{\text{complete}}(S)`$` to the event queue, enabling anonymous completion transitions originating from `$`S`$.
     - *Transition Preemption & Immediate Abort*: When an outgoing transition $`T_{\text{out}}`$` originating from state `$`S`$` (or an ancestor composite state) triggers and evaluates its guard condition to true at time `$`t_{\text{fire}}`$`, active execution of `$`A_{\text{do}}`$` shall be aborted immediately (`$`t_{\text{end}}(A_{\text{do}}) = t_{\text{fire}}`$, status transitions to `Aborted`). All ongoing sub-actions and child occurrences spawned by $`A_{\text{do}}`$` shall be terminated recursively prior to invoking `$`A_{\text{exit}}`$.
  3. **State Deactivation & Exit Action ($`A_{\text{exit}}`$`)**: Executed upon state deactivation, invoked strictly after `$`A_{\text{do}}`$` has either completed autonomously or been aborted (`$`t_{\text{start}}(A_{\text{exit}}) \ge t_{\text{end}}(A_{\text{do}})`$`). The temporal extent `$`[t_{\text{start}}(A_{\text{exit}}), t_{\text{end}}(A_{\text{exit}})]`$` satisfies `$`t_{\text{end}}(A_{\text{exit}}) \le t_{\text{exit}}(S)`$`. Exit action execution shall be atomic, run-to-completion, and strictly non-preemptible (`$`\Delta t = t_{\text{end}}(A_{\text{exit}}) - t_{\text{start}}(A_{\text{exit}}) = 0`$ in logical time). The exit action must complete execution before the transition effect action of the firing transition is invoked.

  In hierarchical statecharts, transition firing between source state $`S_{\text{src}}`$` and target state `$`S_{\text{tgt}}`$` with Least Common Ancestor `$`\text{LCA}(S_{\text{src}}, S_{\text{tgt}})`$ shall strictly execute the following ordered ladder:
  1. *Ascending Exit Ladder*: Bottom-up from $`S_{\text{src}}`$` through enclosing composite states up to (but not including) `$`\text{LCA}`$`: abort active `$`A_{\text{do}}`$`, execute `$`A_{\text{exit}}`$ to completion, and deactivate the state.
  2. *Transition Effect Action*: Execute the transition effect action $`A_{\text{effect}}`$ to completion.
  3. *Descending Entry Ladder*: Top-down from immediately below $`\text{LCA}`$` through enclosing composite states to `$`S_{\text{tgt}}`$`: activate the state, execute `$`A_{\text{entry}}`$` to completion, and initiate `$`A_{\text{do}}`$.

  For self-transitions:
  - *External Self-Transition* ($`S \to S`$`): Exits state `$`S`$` (aborts `$`A_{\text{do}}`$`, executes `$`A_{\text{exit}}`$`), executes the transition effect action, and re-enters state `$`S`$` (executes `$`A_{\text{entry}}`$`, initiates `$`A_{\text{do}}`$).
  - *Internal Transition* on state $`S`$`: Evaluates guard conditions and executes the transition effect action in-place without invoking `$`A_{\text{exit}}`$` or `$`A_{\text{entry}}`$`, and without preempting or aborting `$`A_{\text{do}}`$.

  All state lifecycle action nodes shall be stored in contiguous bump arena storage per REQ-0009 and REQ-0034, addressed via stable 32-bit arena node handles per REQ-0035. Every lowered lifecycle action AST node must receive a deterministic RFC 4122 UUIDv5 identifier computed by namespace-hashing the node fully qualified topological path with the canonical compiler namespace OID in accordance with Architectural Directive 1 and REQ-0010. Scalar symbol identifiers for action names, hook keywords (`entry`, `do`, `exit`), and state identifiers shall be interned into the global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management in accordance with Architectural Directive 3.

  In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the lowering engine shall implement synchronization token error recovery on declaration and delimiter boundaries (`;`, `}`, `end`). Upon detecting an invalid lifecycle hook declaration, typing mismatch (`E0200`), duplicate hook kind (`E0200`), or inverted temporal interval (`E0200`), the engine shall record structured diagnostics into the diagnostic sink, bind an error sentinel $`\bot_{\text{action}}`$`, and continue processing subsequent declarations. If accumulated diagnostics reach the sink capacity limit `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.

  Parallel lowering and validation of state lifecycle hooks across independent package units and statechart scopes shall execute on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$` in accordance with Architectural Directive 2 and REQ-0012. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the state lifecycle engine shall enforce a deterministic, non-panicking execution contract with total-function termination across all inputs; performance latency (`$`\lt 25\text{ ms}`$` for `$`10^4`$` state lifecycle hooks) and peak memory RSS (`$`\lt 100\text{ MB}`$ RSS) performance gates shall be verified exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests. All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `State_Alpha`, `State_Beta`, `State_Parent`, `State_Child1`, `State_Child2`, `Action_Entry`, `Action_Do`, `Action_Exit`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts and mock data.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes. Let `$`\mathcal{S}_{\text{state}} \subset \mathcal{V}_{\text{AST}}`$` denote the set of state usage and state definition nodes. Let `$`\mathcal{A}_{\text{hook}} \subset \mathcal{V}_{\text{AST}}`$` denote the set of state lifecycle action hook nodes. Let `$`\mathcal{B}_{\text{action}} \subset \mathcal{V}_{\text{AST}}`$ denote the set of behavioral action definitions and expressions.

  The lifecycle hook category is formalized by the enumeration:

```math
\text{HookKind} \in \{ \text{EntryHook}, \text{DoHook}, \text{ExitHook} \}
```

  Each state node $`S \in \mathcal{S}_{\text{state}}`$ is formalized as a 7-tuple:

```math
S = \langle \text{id}_S, \text{name}_S, \text{parent}_S, \mathcal{H}_S, \mathcal{T}_S, \Delta_S, \text{span}_S \rangle
```

  where:

```math
\begin{aligned}
\text{id}_S &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_S &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{parent}_S &\in \mathcal{S}_{\text{state}} \cup \{ \bot \} \quad (\text{hierarchical enclosing state or root}) \\
\mathcal{H}_S &\subseteq \mathcal{A}_{\text{hook}} \quad (\text{set of declared lifecycle action hooks}) \\
\mathcal{T}_S &= [t_{\text{entry}}(S), t_{\text{exit}}(S)] \subset \mathbb{R} \cup \{ -\infty, +\infty \} \quad (\text{state residence temporal interval}) \\
\Delta_S &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_S &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

  Each lifecycle action hook $`A \in \mathcal{A}_{\text{hook}}`$ is formalized as an 8-tuple:

```math
A = \langle \text{id}_A, \text{kind}_A, \text{owner}_A, \tau(A), \mathcal{T}_A, \sigma(A), \Delta_A, \text{span}_A \rangle
```

  where:

```math
\begin{aligned}
\text{id}_A &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{kind}_A &\in \{ \text{EntryHook}, \text{DoHook}, \text{ExitHook} \} \quad (\text{hook category}) \\
\text{owner}_A &\in \mathcal{S}_{\text{state}} \quad (\text{featuring owning state node}) \\
\tau(A) &\in \mathcal{B}_{\text{action}} \setminus \{ \bot_{\text{type}} \} \quad (\text{bound behavior or action definition type}) \\
\mathcal{T}_A &= [t_{\text{start}}(A), t_{\text{end}}(A)] \subset \mathbb{R} \cup \{ -\infty, +\infty \} \quad (\text{temporal execution extent}) \\
\sigma(A) &\in \{ \text{Pending}, \text{Executing}, \text{Completed}, \text{Aborted} \} \quad (\text{dynamic execution status}) \\
\Delta_A &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_A &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

  For any state $`S \in \mathcal{S}_{\text{state}}`$, let the hook selector projections be:

```math
\begin{aligned}
\text{entry}(S) &= \{ A \in \mathcal{H}_S \mid \text{kind}_A = \text{EntryHook} \} \\
\text{do}(S) &= \{ A \in \mathcal{H}_S \mid \text{kind}_A = \text{DoHook} \} \\
\text{exit}(S) &= \{ A \in \mathcal{H}_S \mid \text{kind}_A = \text{ExitHook} \}
\end{aligned}
```

  Hook Multiplicity Invariant: At most one action hook of each category is declared per state:

```math
\forall S \in \mathcal{S}_{\text{state}}, \quad |\text{entry}(S)| \le 1 \;\wedge\; |\text{do}(S)| \le 1 \;\wedge\; |\text{exit}(S)| \le 1
```

  Classifier Type Conformance Invariant: Every lifecycle action hook must be typed by a classifier specializing KerML `Behavior`:

```math
\forall A \in \mathcal{A}_{\text{hook}}, \quad \tau(A) \le \text{Behavior} \;\wedge\; \tau(A) \ne \bot_{\text{type}}
```

  Temporal Interval Well-Formedness Invariant: State residence intervals and hook execution intervals must be non-inverted:

```math
\forall S \in \mathcal{S}_{\text{state}}, \quad t_{\text{entry}}(S) \le t_{\text{exit}}(S)
```

```math
\forall A \in \mathcal{A}_{\text{hook}}, \quad t_{\text{start}}(A) \le t_{\text{end}}(A)
```

  State Lifecycle Temporal Ordering Invariant: For any state $`S \in \mathcal{S}_{\text{state}}`$` with entry action `$`A_{\text{entry}} \in \text{entry}(S)`$`, do activity `$`A_{\text{do}} \in \text{do}(S)`$`, and exit action `$`A_{\text{exit}} \in \text{exit}(S)`$`, during state residence interval `$`[t_{\text{entry}}(S), t_{\text{exit}}(S)]`$:

```math
t_{\text{entry}}(S) \le t_{\text{start}}(A_{\text{entry}}) \le t_{\text{end}}(A_{\text{entry}}) \le t_{\text{start}}(A_{\text{do}}) \le t_{\text{end}}(A_{\text{do}}) \le t_{\text{start}}(A_{\text{exit}}) \le t_{\text{end}}(A_{\text{exit}}) \le t_{\text{exit}}(S)
```

  Atomicity and Non-Preemptibility Invariant: Let $`\text{Preemptible} : \mathcal{A}_{\text{hook}} \to \{ \text{true}, \text{false} \}`$ be the preemption predicate:

```math
\text{Preemptible}(A) = \begin{cases}
\text{false} & \text{if } \text{kind}_A \in \{ \text{EntryHook}, \text{ExitHook} \} \\
\text{true} & \text{if } \text{kind}_A = \text{DoHook}
\end{cases}
```

  In discrete logical time, entry and exit actions execute as atomic run-to-completion step transitions:

```math
\begin{aligned}
\forall A \in \text{entry}(S), \quad t_{\text{start}}(A) = t_{\text{entry}}(S) &\implies t_{\text{end}}(A) = t_{\text{start}}(A) \\
\forall A \in \text{exit}(S), \quad t_{\text{end}}(A) = t_{\text{exit}}(S) &\implies t_{\text{start}}(A) = t_{\text{end}}(A)
\end{aligned}
```

  Transition Preemption Invariant for Do Activity: Let $`T = (S, S_{\text{tgt}}, e, g, a)`$` be an enabled outgoing transition firing at time `$`t_{\text{fire}} \in [t_{\text{entry}}(S), t_{\text{exit}}(S)]`$`. If `$`\exists A \in \text{do}(S)`$` such that `$`\sigma(A) = \text{Executing}`$` at `$`t_{\text{fire}}`$:

```math
\begin{aligned}
\sigma(A) &\gets \text{Aborted} \\
t_{\text{end}}(A) &= t_{\text{fire}} \\
\forall A_{\text{sub}} \in \text{sub\_occurrences}(A), \quad \sigma(A_{\text{sub}}) &\gets \text{Aborted} \\
\forall A_{\text{exit}} \in \text{exit}(S), \quad t_{\text{start}}(A_{\text{exit}}) &\ge t_{\text{fire}}
\end{aligned}
```

  Do Activity Autonomous Completion Invariant: If $`A \in \text{do}(S)`$` terminates execution at `$`t_{\text{comp}} \lt t_{\text{exit}}(S)`$ without transition preemption:

```math
\sigma(A) \gets \text{Completed} \;\wedge\; t_{\text{end}}(A) = t_{\text{comp}} \implies \text{PostEvent}(\varepsilon_{\text{complete}}(S), t_{\text{comp}})
```

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Architectural Directive 1): Every state lifecycle action hook AST node binds a deterministic UUIDv5 identifier:

```math
\forall A \in \mathcal{A}_{\text{hook}}, \quad \Delta_A = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(A))
```

  Diagnostic Code Trigger Invariants: Violations of hook multiplicity, behavior classifier typing, temporal interval ordering, or temporal containment deterministically trigger diagnostic error codes per REQ-0191:

```math
\begin{aligned}
\exists S \in \mathcal{S}_{\text{state}} : (|\text{entry}(S)| \gt 1 \vee |\text{do}(S)| \gt 1 \vee |\text{exit}(S)| \gt 1) &\implies \text{Diagnostic}(S, \text{DiagnosticCode::E0200}, \text{DuplicateLifecycleActionHook}) \in \mathcal{D}_{\text{sink}} \\
\exists A \in \mathcal{A}_{\text{hook}} : \tau(A) \not\le \text{Behavior} &\implies \text{Diagnostic}(A, \text{DiagnosticCode::E0200}, \text{InvalidLifecycleActionTyping}) \in \mathcal{D}_{\text{sink}} \\
\exists S \in \mathcal{S}_{\text{state}} : t_{\text{entry}}(S) \gt t_{\text{exit}}(S) &\implies \text{Diagnostic}(S, \text{DiagnosticCode::E0200}, \text{InvalidStateResidenceInterval}) \in \mathcal{D}_{\text{sink}} \\
\exists S \in \mathcal{S}_{\text{state}}, \exists A \in \mathcal{H}_S : (t_{\text{start}}(A) \lt t_{\text{entry}}(S) \vee t_{\text{end}}(A) \gt t_{\text{exit}}(S)) &\implies \text{Diagnostic}(A, \text{DiagnosticCode::E0200}, \text{LifecycleTemporalContainmentViolation}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

  Diagnostic Taxonomy Containment Invariant: Emitted diagnostics strictly belong to the Metamodel and Typing family and Ingestion error limit family:

```math
\forall d \in \mathcal{D}_{\text{lifecycle}}, \quad \text{code}(d) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{ingest}}
```

#### 3. Computational Complexity & Algorithmic Bounds

Lowering, static semantic verification, and execution scheduling of state lifecycle action hooks execute strictly within Complexity Class $`\mathbf{P}`$.

  **Relation to Algorithmic Bounds NP-1 and NP-5**:
  - *Relation to NP-1 (Temporal Consistency, REQ-0117)*: While temporal consistency across unconstrained qualitative interval networks is NP-complete, lifecycle action intervals in REQ-0081 are strictly ordered in a predefined sequential chain ($`t_{\text{entry}} \le \tau_{\text{start}}(A_{\text{entry}}) \le \tau_{\text{end}}(A_{\text{entry}}) \le \tau_{\text{start}}(A_{\text{do}}) \le \tau_{\text{end}}(A_{\text{do}}) \le \tau_{\text{start}}(A_{\text{exit}}) \le \tau_{\text{end}}(A_{\text{exit}}) \le t_{\text{exit}}`$). This constraint eliminates temporal backtracking and enables deterministic polynomial-time validation via scalar boundary comparisons.
  - *Relation to NP-5 (Orthogonal State Reachability, REQ-0124)*: While global reachability and deadlock analysis in orthogonal state machines is PSPACE-complete (or NP-complete for bounded unrolling), REQ-0081 governs the deterministic local lifecycle hook execution contract for individual states and hierarchical entry/exit ladders. Phase dispatch executes in deterministic $`O(1)`$ time per active state configuration without exploring the Cartesian product state space.

  **Asymptotic Verification & Scheduling Bounds**:
  1. *State Lifecycle Scheduling Bound*: State lifecycle dispatch executes in deterministic $`O(1)`$ time per phase transition:
     - Entry hook trigger: $`O(1)`$ time.
     - Do activity status update (`Pending` $`\to`$ `Executing`): $`O(1)`$ time.
     - Transition preemption abort signaling: $`O(1)`$ time.
     - Exit hook trigger: $`O(1)`$ time.
  2. *Hierarchical State Ladder Traversal*: For a statechart with maximum nesting depth $`d = \text{depth}(S)`$`, computing the Least Common Ancestor (`$`\text{LCA}`$`) and walking the ascending exit and descending entry state ladders requires `$`O(d)`$` pointer traversals. Under the architectural depth bound `$`d \le d_{\max} \le 32`$`, hierarchical ladder traversal evaluates in `$`O(1)`$ constant time.
  3. *Static Model Lowering & Validation*: For an AST model containing $`V_S = |\mathcal{S}_{\text{state}}|`$` state nodes and `$`V_A = |\mathcal{A}_{\text{hook}}|`$ lifecycle hook nodes:
     - Node allocation in contiguous arena storage and symbol interning requires amortized $`O(1)`$` time per node, totaling `$`O(V_S + V_A)`$ time.
     - Hook multiplicity checking ($`|\text{entry}(S)| \le 1`$`, `$`|\text{do}(S)| \le 1`$`, `$`|\text{exit}(S)| \le 1`$`) executes in `$`O(1)`$` integer comparisons per state, totaling `$`O(V_S)`$ time.
     - Classifier typing validation ($`\tau(A) \le \text{Behavior}`$`) executes in `$`O(1)`$` tag comparisons per hook, totaling `$`O(V_A)`$ time.
     - Static temporal ordering validation executes in $`O(1)`$` scalar checks per state, totaling `$`O(V_S)`$ time.

  Total sequential verification time across all state lifecycle elements is strictly linear:

```math
T_{\text{validate}}(V_S, V_A) \in O(V_S + V_A)
```

  **Parallel Work-Stealing Scaling (Architectural Directive 2)**: When lowering and validating state lifecycle hooks across independent package scopes on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}}(V_S, V_A, N_{\text{max\_workers}}) \in O\left( \frac{V_S + V_A}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  **Space Complexity & Memory Bounds**: Auxiliary working memory for state and hook AST nodes in contiguous bump arena storage is bounded by $`O(V_S + V_A)`$`. Call stack depth during hierarchical state ladder dispatch is bounded by `$`O(d) \le 32`$` (`$`O(1)`$` stack memory). The diagnostic error sink is bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ allocated records.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models containing abstract placeholders (`Package_0`, `State_Alpha`, `State_Beta`, `State_Parent`, `State_Child1`, `State_Child2`, `Action_Entry`, `Action_Do`, `Action_Exit`, `Port_1`, `Flow_A`, `param_x : Real`). Conformance validation shall enforce the following test gates:

  1. **Canonical State Lifecycle Lowering Gate**: Declare `State_Alpha` containing `entry Action_Entry`, `do Action_Do`, and `exit Action_Exit`. Assert 100% resolution into contiguous bump arena storage, valid 32-bit arena node handles, correct hook kind classifications, and zero diagnostic emissions.
  2. **Lifecycle Hook Multiplicity Gate (`E0200`)**: Declare `State_Alpha` containing two un-sequenced `entry` action declarations. Assert deterministic compile-time rejection with structured diagnostic error code `E0200` (`DuplicateLifecycleActionHook`), assignment of error sentinel $`\bot_{\text{action}}`$, and zero panics.
  3. **Lifecycle Action Type Conformance Gate (`E0200`)**: Declare a pure structural value type `DataType_Value`. Attempt to declare `State_Alpha` with `entry : DataType_Value`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`InvalidLifecycleActionTyping`) and exact source byte spans.
  4. **Entry Action Atomic Run-To-Completion Gate**: In a simulated statechart stepper, transition into `State_Alpha`. Assert that `Action_Entry` executes to completion in discrete logical time ($`\Delta t = 0`$), status transitions to `Completed`, and external events arriving during entry execution remain buffered without triggering preemption.
  5. **Exit Action Atomic Run-To-Completion Gate**: In a simulated statechart stepper, trigger an outgoing transition out of `State_Alpha`. Assert that `Action_Exit` executes to completion in discrete logical time ($`\Delta t = 0`$), status transitions to `Completed`, and execution completes before the transition effect action begins.
  6. **Do Activity Preemption on Transition Firing Gate**: Execute `State_Alpha` with active `Action_Do` in status `Executing`. Trigger an outgoing transition $`T : \text{State\_Alpha} \to \text{State\_Beta}`$. Assert that `Action_Do` is immediately aborted ($`t_{\text{end}}(A_{\text{do}}) = t_{\text{fire}}`$, status transitions to `Aborted`), its sub-occurrences terminate, and `Action_Exit` executes before transition effect dispatch.
  7. **Do Activity Autonomous Completion and Event Gate**: Execute `State_Alpha` with `Action_Do` configured to complete in 5 time units. Advance simulation by 5 time units without triggering transitions. Assert that `Action_Do` transitions to `Completed`, posts completion event $`\varepsilon_{\text{complete}}(\text{State\_Alpha})`$, and triggers an anonymous completion transition into `State_Beta`.
  8. **Hierarchical State Transition Ladder Gate**: Declare composite `State_Parent` containing `State_Child1`, and external `State_Target`. Trigger transition $`T : \text{State\_Child1} \to \text{State\_Target}`$. Assert that the execution trace strictly matches the sequence: abort `State_Child1.do`, execute `State_Child1.exit`, abort `State_Parent.do`, execute `State_Parent.exit`, execute $`T.a_{\text{effect}}`$, execute `State_Target.entry`, initiate `State_Target.do`.
  9. **Internal vs External Self-Transition Invariant Gate**: In `State_Alpha`, execute an external self-transition $`T_{\text{ext}} : \text{State\_Alpha} \to \text{State\_Alpha}`$; assert invocation of `Action_Exit`, transition effect, and `Action_Entry`. In contrast, execute an internal transition $`T_{\text{int}}`$ on `State_Alpha`; assert execution of the transition effect while `Action_Do` remains active and neither `Action_Exit` nor `Action_Entry` is invoked.
