### REQ-0113: Static Boundary Value Analysis & Parametric Tolerance Envelope Verification

#### 1. Normative Statement

The physical metrology, interval constraint evaluation, and parametric verification engine of Subsystem 5 shall perform static boundary value analysis (BVA) over parametric constraint intervals, operational tolerances, and derived transfer functions across all abstract syntax tree (AST) nodes. The metrology engine shall verify that tolerance envelopes around declared operational parameters satisfy design safety envelopes and operational boundary limits at compile time, guaranteeing that no admissible perturbation of input parameters causes an output signal or derived state to escape declared safety boundaries.

  Specifically, the metrology verification pipeline shall strictly enforce the following structural, algebraic, interval-arithmetic, and diagnostic invariants:
  1. **Parametric Tolerance Envelopes & Input Hyperbox Formulation**:
     - Each input parameter or operating signal $`x_i`$` (`$`i \in \{1, \dots, k\}`$`) in a parametric model or constraint block may be declared with a nominal operating value `$`x_{i,0}`$` and a symmetric tolerance `$`\delta_i \ge 0`$` (such that `$`x_i \in [x_{i,0} - \delta_i, x_{i,0} + \delta_i]`$`) or an asymmetric tolerance pair `$`(\delta_i^-, \delta_i^+) \in \mathbb{R}_{\ge 0}^2`$ defining the closed bounded interval:

```math
\mathcal{I}(x_i) = [x_{i,\min}, x_{i,\max}] = [x_{i,0} - \delta_i^-, x_{i,0} + \delta_i^+] \subset \mathbb{R}
```

     - The multi-dimensional input tolerance space for a $`k`$`-ary parametric transfer function or constraint relation `$`y = f(x_1, \dots, x_k)`$ shall be formalized as the Cartesian product hyper-rectangle (tolerance box):

```math
\mathcal{B} = \prod_{i=1}^k \mathcal{I}(x_i) = [x_{1,\min}, x_{1,\max}] \times \dots \times [x_{k,\min}, x_{k,\max}] \subset \mathbb{R}^k
```

     - Any tolerance specification exhibiting negative deviations ($`\delta_i \lt 0`$`, `$`\delta_i^- \lt 0`$`, or `$`\delta_i^+ \lt 0`$`) or inverted interval bounds (`$`x_{i,\min} \gt x_{i,\max}`$) shall be deterministically rejected at compile time with diagnostic error code `E0301` (`MalformedIntervalBounds`).
  2. **Static Boundary Value Analysis & Extremum Range Evaluation**:
     - For every output signal, derived quantity, or constraint expression $`y = f(\mathbf{x}) = f(x_1, \dots, x_k)`$, the metrology engine shall compute or conservatively bound the extreme response range:

```math
\mathcal{R}_y = f(\mathcal{B}) = \{ f(\mathbf{x}) \in \mathbb{R} \mid \mathbf{x} \in \mathcal{B} \} = [y_{\min}, y_{\max}]
```

       where:

```math
y_{\min} = \inf_{\mathbf{x} \in \mathcal{B}} f(\mathbf{x}), \quad y_{\max} = \sup_{\mathbf{x} \in \mathcal{B}} f(\mathbf{x})
```

     - The engine shall evaluate response extrema using deterministic techniques determined by the algebraic structure of $`f`$:
       * *Affine & Linear Expressions*: For linear combinations $`f(\mathbf{x}) = c_0 + \sum_{i=1}^k c_i x_i`$`, the extrema occur strictly at hyperbox vertices and shall be evaluated in `$`O(k)`$ operations via closed-form interval arithmetic:

```math
y_{\min} = c_0 + \sum_{i=1}^k \min(c_i x_{i,\min}, c_i x_{i,\max}), \quad y_{\max} = c_0 + \sum_{i=1}^k \max(c_i x_{i,\min}, c_i x_{i,\max})
```

       * *Monotonic Non-Linear Functions*: For expressions where partial derivatives preserve sign across $`\mathcal{B}`$` (`$`\frac{\partial f}{\partial x_i} \ge 0`$` or `$`\frac{\partial f}{\partial x_i} \le 0`$` for all `$`\mathbf{x} \in \mathcal{B}`$`), the extrema shall be computed directly by evaluating opposing boundary corner vertices in `$`O(k)`$ evaluations.
       * *General Algebraic Expressions*: For general rational and algebraic expressions, the compiler shall compute a certified conservative outer interval enclosure $`[y_{\min}^{\text{IA}}, y_{\max}^{\text{IA}}] \supseteq f(\mathcal{B})`$ using natural interval arithmetic (IA) and first-order affine arithmetic (AA) to bound the interval dependency effect.
       * *Bounded Vertex Enumeration*: For low-dimensional non-monotonic polynomial expressions with $`k \le k_{\text{eval}}`$` (where `$`k_{\text{eval}} \le 8`$`), the engine shall perform boundary vertex evaluation across the `$`2^k`$` vertices of `$`\mathcal{B}`$` augmented with critical boundary stationary points (`$`\nabla f = \mathbf{0}`$).
  3. **Design Safety Envelope Containment Verification**:
     - Each derived signal or output attribute $`y`$ subject to verification shall declare a design safety envelope defined by a closed target interval:

```math
\mathcal{E}_{\text{safe}} = [Y_{\text{lower\_limit}}, Y_{\text{upper\_limit}}] \subset \mathbb{R}
```

     - Containment Mandate: The metrology engine shall statically verify that the response envelope is fully contained within the design safety envelope:

```math
[y_{\min}, y_{\max}] \subseteq [Y_{\text{lower\_limit}}, Y_{\text{upper\_limit}}] \iff (y_{\min} \ge Y_{\text{lower\_limit}} \wedge y_{\max} \le Y_{\text{upper\_limit}})
```

     - If conservative interval arithmetic produces an enclosure $`[y_{\min}^{\text{IA}}, y_{\max}^{\text{IA}}]`$` satisfying `$`[y_{\min}^{\text{IA}}, y_{\max}^{\text{IA}}] \subseteq \mathcal{E}_{\text{safe}}`$, the containment condition is certified unconditionally.
     - Any parametric model where the response envelope breaches the safety envelope ($`y_{\min} \lt Y_{\text{lower\_limit}}`$` or `$`y_{\max} \gt Y_{\text{upper\_limit}}`$) shall be deterministically rejected at compile time with diagnostic error code `E0301` (`ToleranceEnvelopeViolation`).
  4. **Dimensional Homogeneity & Physical Metrology in $`\mathbb{Q}^7`$**:
     - In accordance with REQ-0098 and REQ-0101, all parameters, tolerances, output signals, and safety bounds must possess formal dimension vectors in the 7-dimensional rational vector space $`\mathbb{Q}^7`$` over the canonical ISQ base dimensions `$`\{ [M], [L], [T], [I], [\Theta], [N], [J] \}`$.
     - Parameter Tolerance Homogeneity: For every parameter $`x_i`$`, its nominal value `$`x_{i,0}`$` and tolerances `$`\delta_i, \delta_i^-, \delta_i^+`$ must share identically equal dimension vectors:

```math
\mathbf{d}(x_i) \equiv \mathbf{d}(\delta_i^-) \equiv \mathbf{d}(\delta_i^+) \in \mathbb{Q}^7
```

     - Output Expression Dimensional Propagation: The inferred dimension vector of the output expression $`\mathbf{d}(f(\mathbf{x}))`$` must match the declared dimension of output signal `$`y`$:

```math
\mathbf{d}(y) \equiv \mathbf{d}(f(x_1, \dots, x_k))
```

     - Safety Limit Homogeneity: The lower limit $`Y_{\text{lower\_limit}}`$` and upper limit `$`Y_{\text{upper\_limit}}`$ must possess dimension vectors identical to the output signal:

```math
\mathbf{d}(Y_{\text{lower\_limit}}) \equiv \mathbf{d}(Y_{\text{upper\_limit}}) \equiv \mathbf{d}(y)
```

     - Any dimensional discrepancy detected during tolerance definition or safety boundary verification shall be deterministically rejected at compile time with diagnostic error code `E0300` (`DimensionalMismatch`).
  5. **Commensurable Unit Conversion & Exact Rational Scaling**:
     - When parameter tolerances or safety limits are declared using measurement units disparate from the base signal (e.g., nominal value in metres, tolerance in millimetres; or safety limit in kilopascals, output in pascals), the compiler shall verify unit commensurability ($`\mathbf{d}_A \equiv \mathbf{d}_B`$).
     - The engine shall normalize all intervals to coherent SI base units by applying exact rational conversion scale factors $`c_u \in \mathbb{Q}^+`$. Floating-point approximations in conversion scale factors are strictly prohibited.
     - Irreducible rational fractions $`\frac{p}{q}`$` (`$`p \in \mathbb{Z}`$`, `$`q \in \mathbb{Z}^+`$`, `$`\gcd(|p|, q) = 1`$) shall be preserved throughout interval arithmetic operations.
  6. **Robustness Margins & Critical Boundary Point Reporting**:
     - Upon successful verification ($`[y_{\min}, y_{\max}] \subseteq \mathcal{E}_{\text{safe}}`$), the compiler shall compute and record deterministic robustness margins:

```math
\mu_{\text{lower}} = y_{\min} - Y_{\text{lower\_limit}} \ge 0, \quad \mu_{\text{upper}} = Y_{\text{upper\_limit}} - y_{\max} \ge 0
```

     - The compiler shall record the witness input parameter configurations $`\mathbf{x}_{\text{worst},\min}, \mathbf{x}_{\text{worst},\max} \in \mathcal{B}`$` that produce `$`y_{\min}`$` and `$`y_{\max}`$, embedding them into downstream verification witness artifacts and SMT proof obligations per REQ-0131 and REQ-0188.
  7. **Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every tolerance envelope, boundary value analysis obligation, and synthesized tolerance assertion AST node shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier hashed from the compiler namespace OID and the node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel AST traversal, interval evaluation, and BVA checks across independent packages, classifiers, and constraint blocks shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Parameter names, attribute symbols, unit tokens, and signal handles shall be interned into the deduplicated global string interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The parser and BVA evaluator shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When semantic violations occur (`E0300`, `E0301`), diagnostics shall accumulate into error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{dim}}`$`, `$`\bot_{\text{interval}}`$`, `$`\bot_{\text{val}}`$`), and continue auditing subsequent parameters. If accumulated diagnostics reach `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Isolation)*: The BVA engine shall enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($`\lt 25\text{ ms}`$`) and peak RSS memory (`$`\lt 100\text{ MB}`$` for `$`10^5`$ parametric tolerance constraints) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Signal_Alpha`, `Signal_Beta`, `param_x : Real`, `param_y : Real`, `Tolerance_1`, `Envelope_Alpha`, `Envelope_Beta`, `Quantity_1`, `Quantity_2`, `Port_1`, `Port_2`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage, and let `$`\mathcal{E}_{\text{tol}} \subset \mathcal{V}_{\text{AST}}`$ denote the set of parametric tolerance constraint AST nodes.

  The 7-dimensional physical quantity dimension space is formalized as a rational vector space over the field $`\mathbb{Q}`$:

```math
\mathbb{Q}^7 = \{ \mathbf{d} = (\alpha, \beta, \gamma, \delta, \epsilon, \zeta, \eta) \mid \alpha, \beta, \gamma, \delta, \epsilon, \zeta, \eta \in \mathbb{Q} \}
```

  where coordinate positions correspond to the canonical ISQ basis $`\mathcal{B} = \{ [M], [L], [T], [I], [\Theta], [N], [J] \}`$.

  An operational parameter tolerance interval $`\mathcal{I}(x_i) \subset \mathbb{R}`$` for parameter `$`x_i`$` with nominal value `$`x_{i,0}`$` and asymmetric tolerances `$`\delta_i^-, \delta_i^+ \ge 0`$ is formalized as:

```math
\mathcal{I}(x_i) = [x_{i,\min}, x_{i,\max}] = [x_{i,0} - \delta_i^-, x_{i,0} + \delta_i^+]
```

  The input tolerance hyperbox $`\mathcal{B} \subset \mathbb{R}^k`$` across `$`k`$` independent parameters `$`\mathbf{x} = (x_1, \dots, x_k)`$ is formalized as:

```math
\mathcal{B} = \prod_{i=1}^k \mathcal{I}(x_i) = \{ \mathbf{x} \in \mathbb{R}^k \mid \forall i \in \{1, \dots, k\}, \; x_{i,\min} \le x_i \le x_{i,\max} \}
```

  Each parametric tolerance verification node $`T \in \mathcal{E}_{\text{tol}}`$ is formalized as a 12-tuple:

```math
T = \langle \text{id}_T, \text{name}_T, f_T, \mathbf{x}_T, \mathcal{B}_T, y_T, \mathcal{E}_{\text{safe}, T}, \mathbf{d}_T, u_T, \Delta_T, \text{span}_T, \mu_T \rangle
```

  where:

```math
\begin{aligned}
\text{id}_T &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_T &\in \mathcal{S}_{\text{intern}} \quad (\text{interned tolerance constraint identifier}) \\
f_T &: \mathbb{R}^k \to \mathbb{R} \quad (\text{parametric transfer function or expression AST handle}) \\
\mathbf{x}_T &= (x_1, \dots, x_k) \quad (\text{vector of participating input parameter handles}) \\
\mathcal{B}_T &\subset \mathbb{R}^k \quad (\text{input parameter tolerance hyperbox}) \\
y_T &\in \mathcal{V}_{\text{AST}} \quad (\text{derived output signal or attribute handle}) \\
\mathcal{E}_{\text{safe}, T} &= [Y_{\text{lower\_limit}}, Y_{\text{upper\_limit}}] \subset \mathbb{R} \quad (\text{target design safety envelope}) \\
\mathbf{d}_T &\in \mathbb{Q}^7 \cup \{ \bot_{\text{dim}} \} \quad (\text{inferred physical dimension vector}) \\
u_T &\in \mathcal{U} \cup \{ \bot_{\text{unit}} \} \quad (\text{associated coherent measurement unit}) \\
\Delta_T &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_T &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance}) \\
\mu_T &= \langle \mu_{\text{lower}}, \mu_{\text{upper}} \rangle \in \mathbb{R}^2 \quad (\text{computed robustness clearance margins})
\end{aligned}
```

  Natural Interval Arithmetic (IA) Primitive Operators over Closed Real Intervals $`[a, b], [c, d] \subset \mathbb{R}`$:

```math
\begin{aligned}
{}[a, b] + [c, d] &= [a + c, b + d] \\
{}[a, b] - [c, d] &= [a - d, b - c] \\
{}[a, b] \cdot [c, d] &= [\min(ac, ad, bc, bd), \max(ac, ad, bc, bd)] \\
\frac{1}{[c, d]} &= \left[ \frac{1}{d}, \frac{1}{c} \right], \quad 0 \notin [c, d] \\
\frac{[a, b]}{[c, d]} &= [a, b] \cdot \frac{1}{[c, d]}, \quad 0 \notin [c, d]
\end{aligned}
```

  Extremum Response Range Formulation:

```math
y_{\min} = \min_{\mathbf{x} \in \mathcal{B}} f(\mathbf{x}), \quad y_{\max} = \max_{\mathbf{x} \in \mathcal{B}} f(\mathbf{x})
```

  Closed-Form Extrema for Linear / Affine Models ($`f(\mathbf{x}) = c_0 + \sum_{i=1}^k c_i x_i`$):

```math
\begin{aligned}
y_{\min} &= c_0 + \sum_{i=1}^k \min(c_i x_{i,\min}, c_i x_{i,\max}) = c_0 + \sum_{i=1}^k \left( \frac{c_i (x_{i,\max} + x_{i,\min}) - |c_i| (x_{i,\max} - x_{i,\min})}{2} \right) \\
y_{\max} &= c_0 + \sum_{i=1}^k \max(c_i x_{i,\min}, c_i x_{i,\max}) = c_0 + \sum_{i=1}^k \left( \frac{c_i (x_{i,\max} + x_{i,\min}) + |c_i| (x_{i,\max} - x_{i,\min})}{2} \right)
\end{aligned}
```

  Conservative Enclosure via Natural Interval Extension $`F_{\text{IA}}(\mathcal{B})`$:

```math
[y_{\min}, y_{\max}] \subseteq F_{\text{IA}}(\mathcal{I}(x_1), \dots, \mathcal{I}(x_k)) = [y_{\min}^{\text{IA}}, y_{\max}^{\text{IA}}]
```

  Design Safety Envelope Containment Invariant:

```math
[y_{\min}, y_{\max}] \subseteq [Y_{\text{lower\_limit}}, Y_{\text{upper\_limit}}] \iff (y_{\min} \ge Y_{\text{lower\_limit}} \wedge y_{\max} \le Y_{\text{upper\_limit}})
```

  Robustness Clearance Margins Invariant:

```math
\begin{aligned}
\mu_{\text{lower}} &= y_{\min} - Y_{\text{lower\_limit}} \ge 0 \\
\mu_{\text{upper}} &= Y_{\text{upper\_limit}} - y_{\max} \ge 0
\end{aligned}
```

  Dimensional Homogeneity Invariants in $`\mathbb{Q}^7`$:

```math
\begin{aligned}
\forall i \in \{1, \dots, k\}, &\quad \mathbf{d}(x_{i,0}) \equiv \mathbf{d}(\delta_i^-) \equiv \mathbf{d}(\delta_i^+) \equiv \mathbf{d}(x_i) \\
\mathbf{d}(y) &\equiv \mathbf{d}(f(x_1, \dots, x_k)) \\
\mathbf{d}(Y_{\text{lower\_limit}}) &\equiv \mathbf{d}(Y_{\text{upper\_limit}}) \equiv \mathbf{d}(y)
\end{aligned}
```

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Architectural Directive 1):

```math
\forall T \in \mathcal{E}_{\text{tol}}, \quad \Delta_T = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(T))
```

  Diagnostic Trigger Rules: In accordance with REQ-0191, dimensional, structural, and tolerance envelope violations deterministically emit structured diagnostic records into error sink buffer $`\mathcal{D}_{\text{sink}}`$:

```math
\begin{aligned}
(\exists i : \mathbf{d}(x_i) \not\equiv \mathbf{d}(\delta_i^-) \lor \mathbf{d}(x_i) \not\equiv \mathbf{d}(\delta_i^+)) &\implies \text{Diagnostic}(T, \text{DiagnosticCode::E0300}, \text{DimensionalMismatch}) \in \mathcal{D}_{\text{sink}} \\
(\mathbf{d}(y) \not\equiv \mathbf{d}(Y_{\text{lower\_limit}}) \lor \mathbf{d}(y) \not\equiv \mathbf{d}(Y_{\text{upper\_limit}})) &\implies \text{Diagnostic}(T, \text{DiagnosticCode::E0300}, \text{DimensionalMismatch}) \in \mathcal{D}_{\text{sink}} \\
(\exists i : x_{i,\min} \gt x_{i,\max} \lor \delta_i^- \lt 0 \lor \delta_i^+ \lt 0) &\implies \text{Diagnostic}(T, \text{DiagnosticCode::E0301}, \text{MalformedIntervalBounds}) \in \mathcal{D}_{\text{sink}} \\
Y_{\text{lower\_limit}} \gt Y_{\text{upper\_limit}} &\implies \text{Diagnostic}(T, \text{DiagnosticCode::E0301}, \text{MalformedIntervalBounds}) \in \mathcal{D}_{\text{sink}} \\
(y_{\min} \lt Y_{\text{lower\_limit}} \lor y_{\max} \gt Y_{\text{upper\_limit}}) &\implies \text{Diagnostic}(T, \text{DiagnosticCode::E0301}, \text{ToleranceEnvelopeViolation}) \in \mathcal{D}_{\text{sink}} \\
(\exists i : \mathbf{d}(x_i) = \bot_{\text{dim}}) &\implies \mathbf{d}_T = \bot_{\text{dim}} \quad (\text{cascade diagnostic suppressed}) \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

Static boundary value analysis, parametric tolerance envelope evaluation, and design safety containment verification execute strictly within Complexity Class $`\mathbf{P}`$.

  For an MBSE compilation model containing $`N_{\text{tol}}`$` parametric tolerance constraint definitions, where each constraint evaluates a transfer expression with `$`K`$` AST expression nodes over `$`k`$ bounded input parameters:
  1. *Single Interval Arithmetic Operation*:
     - Performing basic interval operations ($`+`$`, `$`-`$`, `$`\cdot`$`, `$`/`$`) over closed real intervals requires between 2 and 4 floating-point or rational operations, executing in deterministic `$`O(1)`$ time:

```math
T_{\text{op}} \in O(1)
```

  2. *Natural Interval Expression Evaluation*:
     - Evaluating the natural interval extension $`F_{\text{IA}}(\mathcal{B})`$` over an expression tree of size `$`K`$ traverses each AST node exactly once in post-order, executing in deterministic linear time:

```math
T_{\text{expr\_ia}}(K) \in O(K)
```

  3. *Linear / Affine Closed-Form Bounding*:
     - For linear and affine transfer functions $`f(\mathbf{x}) = c_0 + \sum_{i=1}^k c_i x_i`$`, evaluating the exact global extrema over hyperbox `$`\mathcal{B}`$` computes `$`k`$ scalar bounds, executing in deterministic linear time:

```math
T_{\text{affine}}(k) \in O(k)
```

  4. *Monotonic Corner Evaluation*:
     - For expressions verified to be monotonic with respect to all $`k`$` parameters, evaluating `$`f(\mathbf{x})`$` at the two diametrically opposed extreme corner vertices requires exactly 2 evaluations of an expression of size `$`K`$:

```math
T_{\text{mono}}(k, K) \in O(K)
```

  5. *Bounded Vertex Enumeration*:
     - For low-dimensional non-monotonic polynomial expressions with $`k \le k_{\text{eval}}`$` (where `$`k_{\text{eval}} \le 8`$`), evaluating all `$`2^k`$` boundary corner vertices requires at most `$`2^{k_{\text{eval}}} \cdot K = O(K)`$` operations since `$`k_{\text{eval}}`$ is a hardcoded compiler constant bound:

```math
T_{\text{vertex\_eval}}(k, K) \le 2^{k_{\text{eval}}} \cdot O(K) \in O(K)
```

  6. *Dimensional Homogeneity & Safety Containment Check*:
     - Checking dimensional equality in $`\mathbb{Q}^7`$` requires 7 scalar rational equality comparisons per parameter and output bound (`$`O(k)`$).
     - Comparing response extrema against safety limits ($`y_{\min} \ge Y_{\text{lower\_limit}}`$` and `$`y_{\max} \le Y_{\text{upper\_limit}}`$`) requires exactly 2 scalar comparisons, executing in `$`O(1)`$ time:

```math
T_{\text{containment}} \in O(1)
```

  7. *Aggregate Sequential Compilation Complexity*:
     - Verifying all $`N_{\text{tol}}`$` parametric tolerance constraints across a model with maximum expression size `$`K`$` and parameter count `$`k`$ executes in deterministic linear time and space:

```math
T_{\text{total}}(N_{\text{tol}}, K, k) \in O(N_{\text{tol}} \cdot (K + k))
```

  8. *Parallel Work-Stealing Scaling (Architectural Directive 2)*:
     - Distributing BVA checks across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool over independent packages or constraint blocks exhibits near-linear speedup:

```math
T_{\text{parallel}}(N_{\text{tol}}, K, k, N_{\text{max\_workers}}) \in O\left( \frac{N_{\text{tol}} \cdot (K + k)}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  9. *Space Complexity & Memory Bounds*:
     - Contiguous arena storage for tolerance constraint nodes, interval descriptors, and synthesized assertion AST nodes is strictly bounded by $`O(N_{\text{tol}} \cdot (K + k))`$ bytes.
     - Deduplicated string interner memory is bounded by the number of unique parameter, unit, and signal identifier tokens.
     - Diagnostic buffer memory is strictly bounded by $`O(C_{\text{max\_errors}}) = O(1)`$.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Signal_Alpha`, `Signal_Beta`, `param_x : Real`, `param_y : Real`, `Tolerance_1`, `Envelope_Alpha`, `Envelope_Beta`, `Quantity_1`, `Quantity_2`, `Port_1`, `Port_2`) across the following verification gates:

  1. **Nominal Operating Point Feasibility Gate**: Ingest a synthetic model declaring an output signal $`y = f(x_1, \dots, x_k)`$` and safety envelope `$`\mathcal{E}_{\text{safe}} = [Y_{\text{lower\_limit}}, Y_{\text{upper\_limit}}]`$`. Assert that the compiler verifies the nominal operating point `$`y_0 = f(\mathbf{x}_0) \in \mathcal{E}_{\text{safe}}`$ and generates zero diagnostics.
  2. **Symmetric Tolerance Interval Ingestion Gate**: Ingest an input parameter declaration with nominal value $`x_{1,0} = 10.0`$` and symmetric tolerance `$`\delta_1 = 0.5`$`. Assert that the compiler constructs interval `$`\mathcal{I}(x_1) = [9.5, 10.5]`$ with exact rational boundary representation.
  3. **Asymmetric Tolerance Interval Gate**: Ingest an input parameter declaration with nominal value $`x_{1,0} = 100.0`$`, lower tolerance `$`\delta_1^- = 2.0`$`, and upper tolerance `$`\delta_1^+ = 5.0`$`. Assert that the compiler constructs interval `$`\mathcal{I}(x_1) = [98.0, 105.0]`$.
  4. **Linear Affine Monotonic Extremum Gate**: Ingest a linear transfer function $`y = 3 x_1 - 2 x_2 + 5`$` with `$`x_1 \in [1.0, 3.0]`$` and `$`x_2 \in [2.0, 4.0]`$`.
