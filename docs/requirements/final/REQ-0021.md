### REQ-0021: Tabular Schema Ingestion for Structural Parts & Component Assemblies

- **Normative Statement**: The ingestion engine shall parse tabular schemas specifying structural parts and component assemblies into `IngestedPart` intermediate entities. For each data row in a component definition table, the parser must extract the part definition or usage name, the classifier type reference, the multiplicity interval $`\langle l, u \rangle`$, the structural containment hierarchy, and any owned property or attribute sets. Part identifiers shall be sanitized and normalized in accordance with the identifier validation rules defined in REQ-0019. The ingestion engine shall parse multiplicity interval strings into bounded integer pairs $`\langle l, u \rangle \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})`$, enforcing $`0 \le l \le u`$ with upper bound $`u \ge 1`$. When multiplicity is omitted or represented as an empty cell ($`M = \bot`$), the parser must apply the default multiplicity interval $`\langle 1, 1 \rangle`$. The engine must extract structural containment hierarchies representing component composition, sub-assembly aggregation, and internal part nesting. Structural containment shall form a strictly acyclic directed forest across all part entities: no component entity may directly or transitively contain its own ancestor. If a containment cycle or multiple-parent conflict is detected, the parser must construct a structured diagnostic record binding diagnostic error code `E0102` (metamodel structural containment violation) per REQ-0191. If a row contains malformed multiplicity syntax, inverted bounds ($`l \gt u`$), or negative integers, the parser shall emit diagnostic error code `E0103` (numerical envelope and multiplicity syntax failure). If mandatory columns (part name or classifier type) are missing, the parser shall emit diagnostic error code `E0102`. All extracted `IngestedPart` entities shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, yielding deterministic node handles with stable relative addresses. In accordance with Architectural Directive 3 and REQ-0036, copying string bytes from the input table buffer into the global symbol interner pool for scalar symbol tokens during this initial ingestion pass is the sole permitted exception to the zero-copy invariant. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the ingestion engine shall implement synchronization token error recovery on row delimiter boundaries ($`\text{SYM}_{\text{LF}}`$), logging structured diagnostics, substituting a typed sentinel error node $`\bot_{\text{part}}`$, and resuming ingestion at the next row boundary rather than aborting compilation. Multi-table or multi-file parallel ingestion passes shall be scheduled strictly onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with Architectural Directive 2 and REQ-0012. The ingestion engine must strictly adhere to Architectural Directive 5, enforcing a total, deterministic, non-panicking execution contract across all inputs. All test models, diagnostic messages, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Assembly_0`, `Subsystem_1`, `Component_Alpha`, `Part_1`, `Classifier_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $`\mathcal{T}_{\text{part}} = (\mathbf{H}, \mathbf{R})`$ denote a tabular schema specifying structural parts and component assemblies, where $`\mathbf{H} = \langle H_0, H_1, \dots, H_{C-1} \rangle`$ represents the sequence of $`C`$ normalized column headers ($`1 \le C \le 32`$) and $`\mathbf{R} = \langle R_1, R_2, \dots, R_M \rangle`$ represents the ordered sequence of $`M`$ table rows. Each row $`R_i = \langle c_{i, 0}, c_{i, 1}, \dots, c_{i, C-1} \rangle`$ defines a structural component entity.

Let $`\mathcal{P} = \{ P_1, P_2, \dots, P_M \}`$ denote the collection of synthesized `IngestedPart` intermediate entities. Each entity $`P_i \in \mathcal{P}`$ is formalized as a 6-tuple:

$$
P_i = \langle \text{id}_i, \text{name}_i, \text{type}_i, \text{mult}_i, \text{parent}_i, \mathcal{A}_i \rangle
$$

where:
- $`\text{id}_i \in \mathcal{H}_{\text{node}}`$ is the deterministic typed node handle allocated within the bump arena,
- $`\text{name}_i \in \mathcal{S}_{\text{sym}}`$ is the interned scalar symbol handle representing the sanitized part identifier,
- $`\text{type}_i \in \mathcal{S}_{\text{sym}} \cup \mathcal{H}_{\text{node}}`$ is the classifier type handle specifying the component definition,
- $`\text{mult}_i = \langle l_i, u_i \rangle \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})`$ is the parsed multiplicity interval,
- $`\text{parent}_i \in \mathcal{H}_{\text{node}} \cup \{ \bot \}`$ is the optional node handle referencing the immediate owning parent entity,
- $`\mathcal{A}_i = \{ (k_1, v_1), \dots, (k_n, v_n) \}`$ is the set of owned attribute and property key-value bindings.

Let $`\Sigma^*`$ denote the byte string alphabet. The multiplicity parsing function $`\text{ParseMultiplicity} : (\Sigma^* \cup \{ \bot \}) \longrightarrow (\mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})) \cup \{ \bot_{\text{mult}} \}`$ is defined as:

$$
\text{ParseMultiplicity}(M) = 
\begin{cases}
\langle 1, 1 \rangle, & \text{if } M = \bot \;\vee\; M = \text{""} \\
\langle k, k \rangle, & \text{if } M = \text{Str}(k) \;\wedge\; k \in \mathbb{N}_0 \\
\langle 0, \infty \rangle, & \text{if } M = \text{"*"} \\
\langle l, u \rangle, & \text{if } M = \text{"[}l\text{..}u\text{]"} \;\wedge\; l, u \in \mathbb{N}_0 \;\wedge\; l \le u \\
\langle l, \infty \rangle, & \text{if } M = \text{"[}l\text{..*]"} \;\wedge\; l \in \mathbb{N}_0 \\
\bot_{\text{mult}}, & \text{otherwise}
\end{cases}
$$

Bounded Multiplicity Invariant: Every valid parsed multiplicity interval satisfies:

$$
\forall P_i \in \mathcal{P}, \quad \text{mult}_i = \langle l_i, u_i \rangle \implies (0 \le l_i \le u_i \;\wedge\; u_i \ge 1)
$$

Default Multiplicity Invariant: When multiplicity is unspecified or empty:

$$
M = \bot \implies \text{ParseMultiplicity}(M) = \langle 1, 1 \rangle
$$

Let $`G_{\text{contain}} = (\mathcal{P}, \mathcal{E}_{\text{contain}})`$ denote the structural containment directed graph, where directed edges $`(P_p, P_c) \in \mathcal{E}_{\text{contain}}`$ represent parent-to-child composition:

$$
(P_p, P_c) \in \mathcal{E}_{\text{contain}} \iff \text{parent}(P_c) = \text{id}(P_p)
$$

Acyclic Forest Invariant: Containment hierarchy forms an acyclic directed forest over all component definitions:

$$
\text{ContainsPart}(P_{\text{parent}}, P_{\text{child}}) \implies P_{\text{child}} \notin \text{Ancestors}(P_{\text{parent}})
$$

Equivalently, the transitive closure $`\mathcal{E}_{\text{contain}}^+`$ is strictly irreflexive:

$$
\forall P \in \mathcal{P}, \quad (P, P) \notin \mathcal{E}_{\text{contain}}^+
$$

Unique Immediate Parent Invariant: Each component usage has at most one immediate structural parent:

$$
\forall P_c \in \mathcal{P}, \quad |\{ P_p \in \mathcal{P} \mid (P_p, P_c) \in \mathcal{E}_{\text{contain}} \}| \le 1
$$

Root Assembly Partition: The set of root assembly nodes $`\mathcal{P}_{\text{root}} \subseteq \mathcal{P}`$ is defined as:

$$
\mathcal{P}_{\text{root}} = \{ P \in \mathcal{P} \mid \text{parent}(P) = \bot \}
$$

inducing a disjoint tree decomposition of the component forest:

$$
\mathcal{P} = \biguplus_{r \in \mathcal{P}_{\text{root}}} V(T_r)
$$

Contiguous Arena Allocation Invariant: Entity allocation proceeds sequentially in contiguous bump arena memory:

$$
\forall i \in \{1, \dots, M\}, \quad \text{Allocate}(\text{Arena}, P_i) = h_i \in \mathcal{H}_{\text{node}}
$$

satisfying constant stride progression:

$$
\text{Offset}(h_{i+1}) = \text{Offset}(h_i) + \text{sizeof}(\text{IngestedPart})
$$

Diagnostic Code Binding Invariant: Syntax and structural invariant violations trigger structured diagnostic records in accordance with REQ-0191:

$$
\begin{aligned}
\text{ParseMultiplicity}(M_i) = \bot_{\text{mult}} &\implies \text{Diagnostic}(R_i, C_{\text{mult}}, \text{DiagnosticCode::E0103}, \text{InvalidMultiplicitySyntax}) \in \mathcal{D} \\
l_i \gt u_i &\implies \text{Diagnostic}(R_i, C_{\text{mult}}, \text{DiagnosticCode::E0103}, \text{InvertedMultiplicityRange}) \in \mathcal{D} \\
(P_i, P_i) \in \mathcal{E}_{\text{contain}}^+ &\implies \text{Diagnostic}(R_i, C_{\text{parent}}, \text{DiagnosticCode::E0102}, \text{ContainmentCycleDetected}) \in \mathcal{D} \\
|\{ P_p \mid (P_p, P_i) \in \mathcal{E}_{\text{contain}} \}| \gt 1 &\implies \text{Diagnostic}(R_i, C_{\text{parent}}, \text{DiagnosticCode::E0102}, \text{MultipleParentConflict}) \in \mathcal{D} \\
\text{name}_i = \bot \;\vee\; \text{type}_i = \bot &\implies \text{Diagnostic}(R_i, 0, \text{DiagnosticCode::E0102}, \text{MissingMandatoryPartAttribute}) \in \mathcal{D}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant: Emitted diagnostics strictly reside within the ingestion error family:

$$
\forall D \in \mathcal{D}_{\text{part\_table}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0103} \} \subset \mathcal{E}_{\text{ingest}}
$$

- **Computational Complexity & Algorithmic Bounds**: The tabular part schema ingestion engine executes within Complexity Class $`\mathbf{P}`$. For an input table comprising $`R`$ data rows and $`C`$ columns subject to the bounded column limit $`C \le 32`$, cell extraction, identifier sanitization, and header binding vector application execute in $`O(R \cdot C) = O(R)`$ deterministic time. Multiplicity interval parsing evaluates bounded string slices of length $`L_M \le 32`$, executing in $`O(L_M) = O(1)`$ constant time per row, totaling $`O(R)`$ operations across the table. Insertion into the contiguous typed bump arena requires a single pointer bump operation, executing in strict $`O(1)`$ constant time per row and $`O(R)`$ total time. Symbol interning of part names and classifier types operates in $`O(L)`$ time where string length $`L \le 256`$, achieving $`O(1)`$ amortized time per row using a preallocated symbol table. Structural containment hierarchy validation and cycle detection execute over the containment digraph $`G_{\text{contain}} = (V, E)`$ where $`|V| = R`$ and $`|E| \le R`$ (since each node has in-degree at most 1). Verifying that incoming parent edges do not introduce cycles executes in deterministic $`O(V + E) = O(R)`$ linear time using single-pass depth-first search or Tarjan topological sorting. When processing $`K`$ distinct component tables across $`N_{\text{max\_workers}}`$ threads in a bounded work-stealing pool, parallel wall-clock runtime is bounded by $`O(\lceil K / N_{\text{max\_workers}} \rceil \cdot R_{\text{max}})`$. Total sequential execution time is strictly bounded by $`O(R)`$ deterministic linear time in the number of rows, or $`O(N)`$ linear time in total input byte size $`N`$. Auxiliary space complexity is strictly bounded by $`O(R)`$ for node arena allocations and $`O(1)`$ stack space per row, guaranteeing zero unbounded heap allocations.

- **Verification & Conformance Criteria**: Automated verification suites shall assert 100% extraction precision and structural validity across synthetic CommonMark tables specifying abstract MBSE component hierarchies (e.g., `Package_0`, `Assembly_0`, `Subsystem_1`, `Component_Alpha`, `Part_1`, `Part_2`, `Classifier_A`, `param_x : Real`). Conformance shall be validated through the following deterministic gates:
  1. Full Table Lowering Gate: Ingest a canonical 50-row component definition table; assert that 100% of rows lower into valid `IngestedPart` AST nodes allocated within the bump arena, with node handles preserving stable offsets.
  2. Multiplicity Syntax & Boundary Gate: Validate that multiplicity intervals across all supported formats (`1`, `[1]`, `[0..1]`, `[1..*]`, `[2..5]`, `*`, and empty cell $`M = \bot`$) parse into correct integer bounds $`\langle l, u \rangle`$, and that empty cells default to $`\langle 1, 1 \rangle`$.
  3. Multiplicity Error Diagnostic Gate: Ingest tables containing malformed multiplicity tokens (e.g., `[5..2]`, `[-1..3]`, `[alpha..beta]`, `[1..`); assert that the engine logs structured diagnostic records binding error code `E0103` with exact line, column, and byte coordinates, substitutes sentinel $`\bot_{\text{mult}}`$, and continues parsing.
  4. Containment Forest Verification Gate: Ingest a multi-level component hierarchy table (e.g., root assembly `Assembly_0` owning `Subsystem_1`, which in turn owns `Part_1` and `Part_2`); assert that the constructed AST reflects the exact containment tree, parent handles match expected ancestor IDs, and the root set $`\mathcal{P}_{\text{root}}`$ is correctly identified.
  5. Containment Cycle Detection Gate: Ingest a table with deliberate circular containment references (e.g., `Part_A` containing `Part_B` while `Part_B` contains `Part_A`, or self-containment `Part_A` containing `Part_A`); assert that cycle detection identifies the invalid edge in $`O(R)`$ time, emits diagnostic error code `E0102`, and rejects the edge without infinite loops or stack overflow.
  6. Multiple Parenting Gate: Ingest a table declaring two distinct parents for a single component instance; assert emission of diagnostic error code `E0102`.
  7. Synchronization Token Error Recovery Gate: Ingest a 10-row test table containing deliberate syntax corruption in rows 3 and 7; assert that rows 1, 2, 4, 5, 6, 8, 9, 10 are completely extracted, exactly two structured diagnostics are emitted, and the parser resumes cleanly at row delimiters.
  8. Total Non-Panicking Contract Gate: Fuzz testing with empty files, truncated rows, random UTF-8 sequences, and deeply nested paths shall verify 100% total-function termination with zero unhandled panics or crashes.
  9. Release Mode Latency Gate: Ingestion latency and throughput shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests, asserting throughput exceeding $`10^5`$ rows/s and total per-table latency within the 25 ms compiler execution budget.
  10. Bitwise Determinism Gate: Repeated compilation passes across multiple platforms and thread pool configurations shall assert 0-byte diff churn in synthesized AST structures.
