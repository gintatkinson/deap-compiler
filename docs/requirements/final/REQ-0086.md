### REQ-0086: SysML v2 SatisfyRequirementUsage (`satisfy requirement`) Traceability

#### 1. Normative Statement

The SysML v2 / KerML metamodel lowering engine, semantic type checker, and traceability analysis pipeline of Subsystem 4 shall formalize SysML v2 satisfy requirement usages (`SatisfyRequirementUsage`, declared via keywords `satisfy requirement` or `satisfy ... by ...`) as strongly typed directed realization dependencies linking structural components, physical parts, behavioral actions, ports, connections, or item flows to requirement definitions (`RequirementDefinition`, `requirement def`) or requirement usages (`RequirementUsage`, `requirement`). In the SysML v2 metamodel taxonomy, `SatisfyRequirementUsage` shall specialize `RequirementUsage` and `AssertConstraintUsage` (and transitively KerML `Feature`, `Step`, and `Relationship`), establishing verified bipartite satisfaction edges and compliance matrices within the compiler's core AST and traceability graph.

  The lowering engine and semantic analyzer must statically verify and enforce the following structural, typing, and traceability invariants for every lowered satisfy requirement usage:
  1. **Metamodel Specialization & Semantic Dual Typing**: In accordance with the OMG SysML v2 specification, `SatisfyRequirementUsage` specializes both `RequirementUsage` and `AssertConstraintUsage`, and transitively specializes KerML `Feature`, `Step`, and `Relationship`. Every satisfy usage shall establish an explicit realization assertion that a satisfying model element fulfills the contractual intent, operational envelope, and assume-guarantee invariants of a target requirement.
  2. **Bipartite Realization Domain & Endpoint Binding**: The lowering engine shall partition candidate model entities into two distinct domains: the realization element domain $`V_E`$` (comprising structural parts, components, behavioral actions, activities, ports, connections, and item flows `$`\mathcal{V}_{\text{realization}}`$`) and the requirement domain `$`V_R`$` (comprising requirement definitions and requirement usages `$`\mathcal{V}_{\text{req}}`$). The satisfy relationship shall strictly enforce bipartite domain disjointness:

```math
  V_E \cap V_R = \emptyset
```

  Every `SatisfyRequirementUsage` shall bind exactly one realization element $`e \in V_E`$ (the `satisfyingFeature` or subject realization) to exactly one requirement element $`r \in V_R`$ (the `satisfiedRequirement`). Any attempt to declare a satisfy relationship targeting an element outside $`V_R`$` (such as attempting to satisfy a structural part or an unconstrained classifier) or specifying an invalid realization source outside `$`V_E`$ shall be strictly rejected at compile time with diagnostic error code `E0200` in accordance with the standardized diagnostic taxonomy of REQ-0191.
  3. **Reflexive and Inverted Satisfaction Prohibition**: The compiler shall strictly forbid reflexive satisfaction declarations ($`e = r`$`), where an element asserts satisfaction of itself, as well as inverted satisfaction declarations (`$`r \xrightarrow{\text{satisfies}} e`$, where a requirement claims to satisfy a structural component). Detecting reflexive or inverted satisfaction declarations shall immediately trigger diagnostic error code `E0200`.
  4. **Subject Classifier Type Conformance**: SysML v2 requirement definitions and usages declare an optional or mandatory subject parameter specifying the classifier type of the entity that must satisfy the requirement (e.g., `subject s : Classifier_Alpha;`). During metamodel lowering, the semantic type checker shall verify that the classifier type $`\tau(e)`$` of the satisfying realization element `$`e`$` conforms to or specializes the declared subject type `$`\tau(\text{subject}_r)`$` within the KerML subtyping meet-semilattice (`$`\tau(e) \le_{\text{sub}} \tau(\text{subject}_r)`$). If the realization element's type does not specialize the requirement's subject classifier, the compiler shall reject the declaration at compile time with diagnostic error code `E0200`.
  5. **Contextual Scope Resolution & Anonymous Shorthand**: The lowering engine shall support both explicit endpoint declarations and contextual shorthand syntax:
     - Explicit syntax: `satisfy requirement Req_1 by Part_Alpha;` or `satisfy Req_1 by Part_Alpha;` binds the declared target requirement and the explicitly referenced realization element.
     - Implicit/scoped syntax: when declared directly inside a classifier, part, or action definition body (e.g., `part Part_Alpha { satisfy requirement Req_1; }`), the enclosing classifier or feature handle shall be automatically resolved as the implicit satisfying element ($`e = \text{owner}(\text{usage})`$).
     Unresolvable requirement names, ambiguous references, or missing features within lexical scope shall trigger diagnostic error code `E0200`.
  6. **Bipartite Traceability Graph Construction & Bi-directional Indices**: The compiler shall construct a global bipartite realization graph $`G_{\text{trace}} = (V_E \cup V_R, E_{\text{sat}})`$. To enable instantaneous bi-directional traceability lookups across compiler passes, the engine shall maintain:
     - Forward satisfaction mapping: $`\text{ForwardSat}(e) = \{ r \in V_R \mid (e, r) \in E_{\text{sat}} \}`$
     - Backward satisfaction mapping: $`\text{BackwardSat}(r) = \{ e \in V_E \mid (e, r) \in E_{\text{sat}} \}`$
     The compiler shall synthesize downstream compliance matrices linking each requirement to its satisfying realization elements, their fully qualified names, and their verification statuses.
  7. **Traceability Coverage Metric & Orphan Requirement Detection**: The compiler shall compute the exact system requirement satisfaction coverage:

```math
  \text{Coverage}(V_R) = \frac{|\{ r \in V_R \mid \exists e \in V_E, (e, r) \in E_{\text{sat}} \}|}{|V_R|}
```

  An orphan requirement is defined as any requirement $`r \in V_R`$` with an in-degree of zero in the bipartite realization graph (`$`\text{deg}^{-}(r) = 0`$`, meaning `$`\text{BackwardSat}(r) = \emptyset`$`). When completeness validation is enabled, the compiler shall enforce 100% coverage (`$`\text{Coverage}(V_R) = 1.0`$). Every detected orphan requirement shall be reported with diagnostic error code `E0200`, identifying the unfulfilled requirement and its source byte span.
  8. **Satisfaction Dependency Acyclicity Invariant**: While $`G_{\text{trace}}`$` is bipartite between `$`V_E`$` and `$`V_R`$`, multi-tier satisfaction chains (where a satisfying component itself introduces derived requirements, or nested satisfy delegations occur across abstraction tiers) establish an extended dependency multigraph `$`G_{\text{sat\_all}} = (V_{\text{all}}, E_{\text{sat\_all}})`$`. The compiler shall verify that the transitive closure `$`E_{\text{sat\_all}}^+`$` is irreflexive. Any cyclic satisfaction dependency (`$`u_1 \to u_2 \to \dots \to u_1`$) shall be detected via topological cycle detection algorithms and rejected with diagnostic error code `E0203`.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered `SatisfyRequirementUsage` AST node and every satisfaction edge $`(e, r) \in E_{\text{sat}}`$` shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier computed by namespace-hashing the fully qualified symbol path with the canonical DEAP compiler namespace OID per REQ-0010: `$`\Delta_{\text{sat}} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(e) \mathbin{\Vert} \text{\_satisfies\_} \mathbin{\Vert} \text{FQN}(r))`$.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel lowering, bipartite partition validation, subject type checking, and orphan detection across independent compilation packages shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
  - *Directive 3 (String Interner Allocation Exception)*: Interning satisfy usage names, requirement identifiers, realization element names, and qualified path strings into the global symbol interner pool per REQ-0036 is the sole permitted exception to zero-copy memory management.
  - *Directive 4 (Synchronization Token Error Recovery)*: The lowering engine shall implement synchronization token error recovery on statement and delimiter boundaries (`;`, `}`, `end`) per REQ-0013 and REQ-0016. Upon detecting an invalid satisfy target, missing subject type conformance (`E0200`), cyclic dependency (`E0203`), or orphan requirement, the engine shall record the diagnostic into the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, bind an error sentinel `$`\bot_{\text{sat}}`$`, and continue verifying subsequent declarations. If accumulated diagnostics reach `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
  - *Directive 5 (Panic-Free Release Isolation)*: The lowering engine shall enforce a total-function, panic-free execution contract across all valid and malformed inputs. Execution latency ($`\lt 25\text{ ms}`$` for `$`10^4`$` satisfaction edges) and peak memory RSS (`$`\lt 100\text{ MB}`$ RSS) performance gates shall be evaluated strictly in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Part_Alpha`, `Part_Beta`, `Action_Alpha`, `Action_Beta`, `Req_1`, `Req_2`, `ReqDef_Alpha`, `ReqDef_Beta`, `SatisfyUsage_1`, `SatisfyUsage_2`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{T}_{\text{metamodel}}`$` denote the KerML classifier specialization poset ordered by subtyping relation `$`\le_{\text{sub}}`$. The specialization hierarchy of `SatisfyRequirementUsage` within the metamodel is formalized as:

```math
  \begin{aligned}
  \text{SatisfyRequirementUsage} &\le_{\text{sub}} \text{RequirementUsage} \le_{\text{sub}} \text{Usage} \le_{\text{sub}} \text{Feature} \\
  \text{SatisfyRequirementUsage} &\le_{\text{sub}} \text{AssertConstraintUsage} \le_{\text{sub}} \text{ConstraintUsage} \le_{\text{sub}} \text{Predicate} \\
  \text{SatisfyRequirementUsage} &\le_{\text{sub}} \text{Relationship} \le_{\text{sub}} \text{Element}
  \end{aligned}
```

  Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage. Let `$`V_E \subset \mathcal{V}_{\text{AST}}`$` denote the realization element node set (structural parts, components, behavioral actions, activities, ports, connections, and item flows `$`\mathcal{V}_{\text{realization}}`$`), and let `$`V_R \subset \mathcal{V}_{\text{AST}}`$ denote the requirement node set (`RequirementDefinition` and `RequirementUsage`).

  Each satisfy requirement usage $`U_{\text{sat}} \in \mathcal{U}_{\text{sat}}`$ is formalized as a 7-tuple:

```math
  U_{\text{sat}} = \langle \text{id}_{\text{sat}}, \text{name}_{\text{sat}}, \text{owner}_{\text{sat}}, e_{\text{real}}, r_{\text{req}}, \Delta_{\text{sat}}, \text{span}_{\text{sat}} \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_{\text{sat}} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_{\text{sat}} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
  \text{owner}_{\text{sat}} &\in \mathcal{V}_{\text{AST}} \quad (\text{enclosing namespace or classifier handle}) \\
  e_{\text{real}} &\in V_E \quad (\text{satisfying realization element handle}) \\
  r_{\text{req}} &\in V_R \quad (\text{satisfied requirement handle}) \\
  \Delta_{\text{sat}} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
  \text{span}_{\text{sat}} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
  \end{aligned}
```

  Bipartite Domain Disjointness Invariant: The realization element set and the requirement node set are strictly disjoint:

```math
  V_E \cap V_R = \emptyset
```

  Bipartite Realization Graph Invariant: The global bipartite realization graph is defined as $`G_{\text{trace}} = (V_E \cup V_R, E_{\text{sat}})`$` where the edge relation `$`E_{\text{sat}}`$ binds realization elements to requirements:

```math
  E_{\text{sat}} = \{ (e_{\text{real}}(u), r_{\text{req}}(u)) \mid u \in \mathcal{U}_{\text{sat}} \} \subseteq V_E \times V_R
```

  Directed Satisfaction Invariant: Every satisfaction edge represents a directed realization dependency:

```math
  \forall (e, r) \in E_{\text{sat}}, \quad e \in V_E \;\wedge\; r \in V_R \;\wedge\; e \ne r
```

```math
  e \xrightarrow{\text{satisfies}} r
```

  Irreflexivity Invariant: No element may satisfy itself:

```math
  \forall v \in V_E \cup V_R, \quad (v, v) \notin E_{\text{sat}}
```

  Subject Classifier Type Conformance Invariant: For each requirement $`r \in V_R`$`, let `$`\text{subject}(r)`$` denote its declared subject feature with classifier type `$`\tau(\text{subject}(r)) \in \mathcal{C} \cup \{ \top \}`$`. For every satisfaction edge `$`(e, r) \in E_{\text{sat}}`$:

```math
  \tau(\text{subject}(r)) \ne \top \implies \tau(e) \le_{\text{sub}} \tau(\text{subject}(r))
```

  Bi-directional Adjacency Lookup Invariant: Forward and backward index maps partition incident satisfaction edges:

```math
  \begin{aligned}
  \text{ForwardSat}(e) &= \{ r \in V_R \mid (e, r) \in E_{\text{sat}} \} \\
  \text{BackwardSat}(r) &= \{ e \in V_E \mid (e, r) \in E_{\text{sat}} \}
  \end{aligned}
```

  Traceability Coverage Metric & Orphan Requirement Invariant: Traceability coverage over requirement set $`V_R`$ is evaluated as:

```math
  \text{Coverage}(V_R) = \begin{cases}
  1.0 & \text{if } |V_R| = 0 \\
  \displaystyle \frac{|\{ r \in V_R \mid \exists e \in V_E, (e, r) \in E_{\text{sat}} \}|}{|V_R|} & \text{if } |V_R| \gt 0
  \end{cases}
```

  The set of orphan requirements is defined as:

```math
  \text{Orphans}(V_R) = \{ r \in V_R \mid \text{BackwardSat}(r) = \emptyset \} = \{ r \in V_R \mid \text{deg}^{-}(r) = 0 \}
```

  Under full completeness validation, complete coverage requires zero orphans:

```math
  \text{Coverage}(V_R) = 1.0 \iff \text{Orphans}(V_R) = \emptyset
```

  Multi-Tier Satisfaction Chain Acyclicity Invariant: Let $`G_{\text{sat\_all}} = (V_{\text{all}}, E_{\text{sat\_all}})`$` denote the extended satisfaction and delegation dependency multigraph. Its transitive closure `$`E_{\text{sat\_all}}^+`$ must be irreflexive:

```math
  \forall v \in V_{\text{all}}, \quad (v, v) \notin E_{\text{sat\_all}}^+
```

  Deterministic RFC 4122 UUIDv5 Topological Anchor Invariant (Directive 1):

```math
  \forall u \in \mathcal{U}_{\text{sat}}, \quad \Delta_{\text{sat}}(u) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(e_{\text{real}}(u)) \mathbin{\Vert} \text{\_satisfies\_} \mathbin{\Vert} \text{FQN}(r_{\text{req}}(u)))
```

  Diagnostic Code Trigger Invariants per REQ-0191:

```math
  \begin{aligned}
  (e \notin V_E \vee r \notin V_R) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{InvalidSatisfyEndpoint}) \in \mathcal{D}_{\text{sink}} \\
  e = r &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{ReflexiveSatisfyViolation}) \in \mathcal{D}_{\text{sink}} \\
  (\tau(\text{subject}(r)) \ne \top \;\wedge\; \tau(e) \not\le_{\text{sub}} \tau(\text{subject}(r))) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}, \text{SubjectTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
  (r \in \text{Orphans}(V_R) \;\wedge\; \text{EnforceCompleteness}) &\implies \text{Diagnostic}(r, \text{DiagnosticCode::E0200}, \text{OrphanRequirementViolation}) \in \mathcal{D}_{\text{sink}} \\
  (v, v) \in E_{\text{sat\_all}}^+ &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0203}, \text{CircularSatisfactionDependency}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

Metamodel lowering, bipartite graph construction, subject type checking, compliance matrix synthesis, and orphan requirement detection execute strictly within Complexity Class $`\mathbf{P}`$.

  The operational complexity bounds are formalized across eight algorithmic dimensions:
  1. *AST Arena Allocation & Symbol Interning*: Allocating each `SatisfyRequirementUsage` node in contiguous bump arena storage and interning identifier symbol strings executes in amortized $`O(1)`$` time and `$`O(1)`$` auxiliary heap space per node, requiring `$`O(|V_E| + |V_R| + |\mathcal{U}_{\text{sat}}|)`$ operations in total across compilation units.
  2. *Bipartite Domain & Endpoint Binding Validation*: Verifying that each satisfaction usage binds $`e \in V_E`$`, `$`r \in V_R`$`, and satisfies irreflexivity `$`e \ne r`$` requires strictly `$`O(1)`$` scalar comparisons per edge, executing in `$`O(|E_{\text{sat}}|)`$ total time.
  3. *Subject Classifier Type Conformance Checking*: Checking whether the classifier type $`\tau(e)`$` conforms to `$`\tau(\text{subject}(r))`$` (`$`\tau(e) \le_{\text{sub}} \tau(\text{subject}(r))`$`) takes `$`O(1)`$` time using precomputed reachability bitsets or ancestor arrays in the KerML subtyping poset. Across all `$`|E_{\text{sat}}|`$` edges, this check runs in `$`O(|E_{\text{sat}}|)`$ total time.
  4. *Bipartite Traceability Graph Construction & Bi-directional Indexing*: Constructing the bipartite realization graph $`G_{\text{trace}} = (V_E \cup V_R, E_{\text{sat}})`$` and populating forward adjacency table `$`\text{ForwardSat}`$` and backward adjacency table `$`\text{BackwardSat}`$` executes in deterministic `$`O(|V_E| + |V_R| + |E_{\text{sat}}|)`$ time.
  5. *Traceability Coverage & Orphan Detection*: Evaluating $`\text{Coverage}(V_R)`$` and identifying all orphan requirements `$`\text{Orphans}(V_R)`$` requires scanning the in-degrees or backward adjacency lists of all requirement nodes in `$`V_R`$`. Since each requirement node is visited once and each incident edge is traversed once, orphan detection executes in deterministic `$`O(|V_R| + |E_{\text{sat}}|)`$ time.
  6. *Compliance Matrix Synthesis*: Emitting the tabular traceability / compliance matrix of dimensions $`|V_R| \times |\text{MaxSatisfying}|`$` traverses all edges in `$`E_{\text{sat}}`$` and formats row records, executing in deterministic `$`O(|V_R| + |E_{\text{sat}}|)`$ time.
  7. *Multi-Tier Satisfaction Chain Acyclicity Checking*: Evaluating acyclicity over the extended satisfaction dependency multigraph $`G_{\text{sat\_all}} = (V_{\text{all}}, E_{\text{sat\_all}})`$` using Tarjan's strongly connected components algorithm or Kahn's topological sort executes in deterministic `$`O(|V_{\text{all}}| + |E_{\text{sat\_all}}|)`$` time and `$`O(|V_{\text{all}}|)`$ stack space.
  8. *Aggregate Sequential Verification Complexity*: For a compilation model containing $`|V_E|`$` realization elements, `$`|V_R|`$` requirements, and `$`|E_{\text{sat}}|`$ declared satisfaction relationships:

```math
  T_{\text{validate}}(V_E, V_R, E_{\text{sat}}) \in O(|V_E| + |V_R| + |E_{\text{sat}}|)
```

  **Parallel Work-Stealing Scaling (Architectural Directive 2)**: When satisfy lowering, endpoint verification, and orphan detection across independent compilation packages is scheduled onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

```math
  T_{\text{parallel}}(V_E, V_R, E_{\text{sat}}, N_{\text{max\_workers}}) \in O\left( \frac{|V_E| + |V_R| + |E_{\text{sat}}|}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  **Space Complexity & Working Memory Bounds**: Auxiliary working memory is strictly bounded by $`O(|V_E| + |V_R| + |E_{\text{sat}}|)`$` for contiguous arena storage, node index tables, and compact adjacency vectors. Traversal recursion depth during cycle detection is bounded by hierarchy depth `$`h \le 32`$` (`$`O(1)`$` stack memory). The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ preallocated memory records.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models using pure abstract placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Part_Alpha`, `Part_Beta`, `Action_Alpha`, `Action_Beta`, `Req_1`, `Req_2`, `ReqDef_Alpha`, `ReqDef_Beta`, `SatisfyUsage_1`, `SatisfyUsage_2`, `Port_1`, `Flow_A`, `param_x : Real`). Conformance validation shall enforce the following test gates:

  1. **Canonical `satisfy requirement` Lowering Gate**: Declare requirement `Req_1 : ReqDef_Alpha` and structural part `Part_Alpha : Classifier_Alpha`. Lower `satisfy requirement Req_1 by Part_Alpha;`. Assert successful lowering into contiguous bump arena storage, valid arena node handle, creation of directed satisfaction edge $`(\text{Part\_Alpha}, \text{Req\_1}) \in E_{\text{sat}}`$, valid forward and backward index lookups, and zero diagnostics.
  2. **Implicit Enclosing Scope Satisfy Gate**: Inside `part Part_Beta : Classifier_Alpha { satisfy requirement Req_1; }`, assert that the compiler automatically resolves `Part_Beta` as the satisfying realization element $`e`$`, synthesizes directed satisfaction edge `$`(\text{Part\_Beta}, \text{Req\_1})`$, and completes with zero diagnostics.
  3. **Behavioral Action Satisfaction Gate**: Declare action `action Action_Alpha : Classifier_Alpha` and requirement `Req_2`. Lower `satisfy Req_2 by Action_Alpha;`. Assert that behavioral step/action realization elements are accepted within $`V_E`$`, establishing valid satisfaction edge `$`(\text{Action\_Alpha}, \text{Req\_2})`$ with zero diagnostics.
  4. **Invalid Endpoint & Cross-Domain Rejection Gate (`E0200`)**: Attempt to declare `satisfy Part_Beta by Part_Alpha;` (where the target element is a structural part rather than a requirement) or `satisfy Req_1 by Real;` (where the source element is an uninstantiable primitive scalar type). Assert deterministic compile-time rejection with structured diagnostic error code `E0200` (`InvalidSatisfyEndpoint`), assignment of error sentinel $`\bot_{\text{sat}}`$, and zero panics.
  5. **Reflexive and Inverted Satisfaction Prohibition Gate (`E0200`)**: Attempt to declare `satisfy Req_1 by Req_1;` (reflexive self-satisfaction) or `satisfy Part_Alpha by Req_1;` (inverted satisfaction claiming a requirement satisfies a structural part). Assert deterministic compile-time rejection with diagnostic error code `E0200` (`ReflexiveSatisfyViolation` or `InvalidSatisfyEndpoint`).
  6. **Subject Classifier Type Conformance Gate (`E0200`)**: Declare `requirement def ReqDef_Alpha { subject s : Classifier_Alpha; }`. Declare `part Part_Alpha : Classifier_Alpha` and `part Part_Beta : Classifier_Beta` where `Classifier_Beta` does not specialize `Classifier_Alpha`. Lower `satisfy Req_1 by Part_Alpha;` (assert PASS). In a second test, lower `satisfy Req_1 by Part_Beta;` and assert deterministic compile-time rejection with diagnostic error code `E0200` (`SubjectTypeMismatch`).
  7. **Traceability Coverage & Orphan Requirement Detection Gate (`E0200`)**: Declare a package with requirements `Req_1`, `Req_2`, and `Req_3`, but only satisfy `Req_1` and `Req_2`. Assert that coverage evaluates to $`\text{Coverage}(V_R) = 2/3`$. When completeness validation is enabled, assert that orphan requirement `Req_3` is detected in deterministic $`O(|V_R| + |E_{\text{sat}}|)`$ time and flagged with diagnostic error code `E0200` (`OrphanRequirementViolation`) with exact source byte span.
  8. **Deterministic Compliance Matrix Synthesis Gate**: Ingest a model containing multiple requirements and satisfying parts and actions. Verify that the compiler generates a deterministic compliance matrix mapping every requirement $`r \in V_R`$` to its list of satisfying elements `$`\mathbf{E}_r`$ with satisfaction status (`Satisfied`, `Unsatisfied`), ordered deterministically by interned qualified names.
  9. **Circular Satisfaction Chain Detection Gate (`E0203`)**: Construct a synthetic multi-tier satisfaction chain with circular delegation or dependencies ($`u_1 \to u_2 \to u_3 \to u_1`$). Assert deterministic cycle detection via Tarjan's SCC/DFS, emission of diagnostic error code `E0203` (`CircularSatisfactionDependency`) identifying the cycle path, and graceful recovery.
  10. **Synchronization Token Recovery & Error Accumulation Gate (Architectural Directive 4)**: Ingest a model unit containing 5 distinct malformed satisfy statements (invalid endpoint, reflexive satisfy, subject type mismatch, orphan requirement, circular dependency) separated by delimiter tokens. Assert that the lowering engine resynchronizes on token boundaries, accumulates all 5 `E0200` and `E0203` diagnostics with precise source spans, and when the error count reaches $`C_{\text{max\_errors}}`$, emits terminal diagnostic `E0199` and halts gracefully.
  11. **Deterministic RFC 4122 UUIDv5 Topological Identity Gate (Architectural Directive 1)**: Verify that 100% of lowered `SatisfyRequirementUsage` AST nodes and satisfaction edges bind valid RFC 4122 UUIDv5 identifiers computed from the fixed DEAP namespace OID and canonical fully qualified paths, asserting bitwise identical digests and 0-byte diff churn across repeated compilation runs.
  12. **Bounded Work-Stealing Parallelism Gate (Architectural Directive 2)**: Ingest a model containing 50 packages with $`10^4`$` requirements and satisfy usages across `$`N_{\text{max\_workers}}`$ threads; assert data-race freedom, deterministic AST output, and identical node ordering compared to single-threaded compilation.
  13. **Release Mode Latency & Memory Budget Gate (Architectural Directive 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, verify that lowering, bipartite graph construction, and orphan detection for $`10^4`$ synthetic requirements and satisfy usages executes in under 25 ms, peak RSS memory remains strictly under 100 MB, zero panics occur, and 0-byte diff churn is preserved.
