### REQ-0084: SysML v2 AssertConstraintUsage (`assert constraint`) Lowering

- **Normative Statement**: The KerML/SysML v2 metamodel lowering engine, semantic type checker, and safety verification synthesis engine shall formalize SysML v2 assert constraint usages (`assert constraint`, `AssertConstraintUsage`) into strongly typed, non-negotiable invariant assertions specializing KerML `ConstraintUsage` and KerML `Invariant`. Every `AssertConstraintUsage` shall bind an invariant Boolean predicate expression $`\Phi`$ to a containing classifier definition context (such as `part def`, `item def`, `action def`, or `state def`) or package, asserting temporal invariance $`\square \Phi`$ universally across all reachable execution traces and operational states of the system.

  The compiler shall strictly enforce the following structural, semantic, and typing invariants during assert constraint lowering:
  1. **Metamodel Classifier Specialization & Invariant Semantics**: In the SysML v2 / KerML metamodel hierarchy, `AssertConstraintUsage` specializes `ConstraintUsage`, which in turn specializes KerML `Feature` and `Predicate` with a Boolean codomain ($`\text{AssertConstraintUsage} \le \text{ConstraintUsage} \le \text{Predicate} \le \text{Function} \longrightarrow \mathbb{B}`$). An assert constraint usage shall have the Boolean assertion flag set strictly to true ($`\text{is\_asserted} \equiv \text{true}`$). The evaluated type of the asserted predicate expression $`\Phi`$ must statically unify with standard primitive type `Boolean`. Any assert constraint declaration whose expression yields a non-Boolean type shall be rejected at compile time with diagnostic error code `E0200` in accordance with REQ-0191.
  2. **Parameter Directionality & Functional Purity**: All formal parameters of the referenced constraint definition or synthesized anonymous constraint must declare or default to `In` directionality ($`\text{dir}(p_i) = \text{In}`$). Declaring `Out` or `InOut` parameters within an asserted constraint shall be rejected at compile time with diagnostic error code `E0201`. In accordance with functional purity invariants, constraint evaluation shall produce zero state mutation or side effects ($`\Delta \text{State} \equiv \emptyset`$). Any assignment, mutable state modification, or invocation of non-functional behavioral actions within an assert constraint body shall be rejected at compile time with diagnostic error code `E0200`.
  3. **Parameter Binding & Subtyping Conformance**: An `AssertConstraintUsage` $`ACU`$ referencing a constraint definition $`CD = \tau(ACU)`$ shall bind actual argument expressions $`\mathbf{A}_{ACU} = (a_1, \dots, a_m)`$ to formal parameters $`\mathbf{P}_{CD} = (p_1, \dots, p_k)`$. The compiler shall verify that:
     - The number of actual argument bindings matches the parameter arity of the referenced constraint definition ($`|\mathbf{A}_{ACU}| = |\mathbf{P}_{CD}|`$). Any arity mismatch shall trigger diagnostic error code `E0200`.
     - For each argument binding $`a_i`$ bound to parameter $`p_i`$, the argument type $`\tau(a_i)`$ must specialize or equal parameter type $`\tau(p_i)`$ in the subtyping semilattice ($`\tau(a_i) \le \tau(p_i)`$). Argument type incompatibility shall trigger diagnostic error code `E0200`.
     - Actual argument expressions must be read-accessible in the invocation context. Passing write-only ports or uninitialized out-parameters as constraint arguments shall trigger diagnostic error code `E0201`.
  4. **Anonymous & Shorthand Assert Constraint Lowering**: When a model declares an anonymous assert constraint block (`assert constraint { <expr> }` or `assert { <expr> }`), the lowering engine shall synthesize an anonymous `ConstraintDefinition` node in contiguous arena storage, project all free variables referenced within `<expr>` as synthetic formal `In` parameters, bind them to the corresponding features in the featuring scope, and emit a synthetic `AssertConstraintUsage` node with $`\text{is\_asserted} \equiv \text{true}`$ linked to the generated definition.
  5. **Constraint Call Graph Acyclicity**: The lowering engine shall construct a directed dependency graph $`\mathcal{G}_{\text{c\_dep}} = (\mathcal{CD}, \mathcal{R}_{\text{c\_dep}})`$ tracking invocations between constraint definitions within assert constraint bodies. Circular invocations ($`CD_1 \to CD_2 \to \dots \to CD_1`$) shall be strictly prohibited and detected via topological cycle detection, emitting diagnostic error code `E0203`.
  6. **Dual Synthesis Obligations (Compile-Time Proof & Runtime Monitor)**:
     - **Compile-Time SMT Proof Obligation Synthesis**: For every `AssertConstraintUsage`, the compiler shall synthesize a formal first-order logic proof obligation in quantifier-free SMT-LIB2 format in decidable theories (such as QF_LRA, QF_LIA, and QF_UF per REQ-0188 and REQ-0197). The proof obligation asserts that the conjunction of the reachable state space / transition relation $`\text{Reachable}(\sigma)`$ and the negation of the invariant predicate $`\neg \Phi`$ is unsatisfiable:

$$
       \text{Reachable}(\sigma) \wedge \neg \Phi \implies \text{UNSAT}
$$

       If the solver determines that $`\text{Reachable}(\sigma) \wedge \neg \Phi`$ is satisfiable ($`\text{SAT}`$), the compiler shall emit diagnostic error code `E0200` with the counterexample state trace coordinates and source span.
     - **Continuous Runtime Safety Monitor Synthesis**: For simulation, testing, and multi-target code generation (Subsystems 10 and 12), the compiler shall lower each `AssertConstraintUsage` into a synchronous, zero-allocation safety monitor function $`\mathcal{M}_{\text{monitor}}(\sigma_t)`$. The monitor shall evaluate $`\Phi(\sigma_t) \equiv \text{true}`$ at every discrete execution step, simulation time step, or state transition $`\sigma_t \to \sigma_{t+1}`$ in deterministic $`O(1)`$ time with strictly zero heap allocation. If $`\Phi(\sigma_t)`$ evaluates to `false`, the monitor shall synchronously trigger a deterministic failsafe containment action (such as transitioning to a predefined safe state or safe shutdown handler) without panicking.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered `AssertConstraintUsage` and synthesized `ConstraintDefinition` AST node shall be assigned a deterministic RFC 4122 UUIDv5 identifier generated by namespace-hashing the fully qualified symbol path (e.g., `Package_0::Classifier_Alpha::AssertConstraint_1`) with the canonical compiler namespace OID per REQ-0010. Time-based UUIDs are strictly prohibited.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel AST lowering, type verification, and formal proof obligation generation across distinct compilation packages shall execute exclusively on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
  - *Directive 3 (String Interner Allocation Exception)*: Scalar constraint identifiers, parameter names, and qualified path tokens shall be interned into the global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
  - *Directive 4 (Synchronization Token Error Recovery)*: The lowering engine shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`) per REQ-0013 and REQ-0016. Upon encountering an invalid constraint body (`E0200`), parameter direction mismatch (`E0201`), or cyclic dependency (`E0203`), the engine shall record the diagnostic into error sink $`\mathcal{D}_{\text{sink}}`$, substitute error sentinel node $`\bot_{\text{assert}}`$, and resynchronize on the next declaration delimiter without aborting compilation. If accumulated diagnostics reach threshold $`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
  - *Directive 5 (Panic-Free Release Isolation)*: The lowering engine and synthesized runtime monitors shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling across all inputs. Performance latency ($`\lt 25\text{ ms}`$) and peak memory RSS ($`\lt 100\text{ MB}`$ for $`10^5`$ assert constraint nodes) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `AssertConstraint_1`, `AssertConstraint_2`, `ConstraintDef_Alpha`, `param_x : Real`, `param_y : Real`, `attr_a : Real`, `attr_b : Real`, `state_0`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes within the contiguous node arena. Let $`\mathcal{ACU} \subset \mathcal{V}_{\text{AST}}`$ denote the set of assert constraint usage nodes, and let $`\mathcal{CD} \subset \mathcal{V}_{\text{AST}}`$ denote the set of constraint definition nodes.

  Each assert constraint usage $`ACU \in \mathcal{ACU}`$ is formalized as an 8-tuple:

$$
ACU = \langle \text{id}_{ACU}, \text{name}_{ACU}, \text{owner}_{ACU}, \tau(ACU), \mathbf{A}_{ACU}, \text{is\_asserted}, \Delta_{ACU}, \text{span}_{ACU} \rangle
$$

  where:

$$
\begin{aligned}
\text{id}_{ACU} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{ACU} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_{ACU} &\in \mathcal{C} \cup \mathcal{P}_{\text{pkg}} \quad (\text{featuring classifier definition or package}) \\
\tau(ACU) &\in \mathcal{CD} \cup \{ \bot_{\text{assert}} \} \quad (\text{bound constraint definition handle}) \\
\mathbf{A}_{ACU} &= (a_1, \dots, a_m) \in \mathcal{E}_{\text{expr}}^m \quad (\text{actual argument expressions}) \\
\text{is\_asserted} &\in \{ \text{true} \} \quad (\text{mandatory invariant assertion flag}) \\
\Delta_{ACU} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{ACU} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

  Subtyping Hierarchy Invariant: An `AssertConstraintUsage` specializes `ConstraintUsage`, which specializes KerML `Predicate` and `Function` with a Boolean codomain:

$$
\text{AssertConstraintUsage} \le \text{ConstraintUsage} \le \text{Predicate} \le \text{Function} \longrightarrow \mathbb{B}
$$

  Predicate Codomain & Typing Invariant: The evaluated predicate expression $`\Phi = e_{\tau(ACU)}`$ must statically yield primitive type `Boolean`:

$$
\Phi_{\text{codomain}}(ACU) \iff \tau(e_{\tau(ACU)}) \equiv \text{Boolean}
$$

  Temporal Invariance Specification: Let $`\mathcal{M}`$ denote the formal state machine or transition system of context classifier $`\text{owner}_{ACU}`$, and let $`\text{Traces}(\mathcal{M})`$ denote the set of all admissible execution traces $`\sigma = (\sigma_0, \sigma_1, \dots)`$. The assert constraint specifies temporal invariance:

$$
\square \Phi \iff \forall \sigma \in \text{Traces}(\mathcal{M}), \quad \forall t \ge 0 : \llbracket \Phi \rrbracket(\sigma_t) \equiv \text{true}
$$

  Dual Synthesis Obligations:
  1. Compile-Time SMT Proof Obligation Invariant:

$$
\Phi_{\text{proof}}(ACU) \iff \text{UNSAT}\left( \text{Reachable}(\sigma) \wedge \neg \llbracket \Phi \rrbracket(\sigma) \right)
$$

  2. Continuous Runtime Safety Monitor Invariant:

$$
\forall \sigma_t \in \Sigma, \quad \mathcal{M}_{\text{monitor}}(\sigma_t) = \begin{cases} \sigma_t & \text{if } \llbracket \Phi \rrbracket(\sigma_t) \equiv \text{true} \\ \text{Failsafe}(\sigma_t) & \text{if } \llbracket \Phi \rrbracket(\sigma_t) \equiv \text{false} \end{cases}
$$

  where runtime memory allocation is strictly zero dynamic heap bytes:

$$
\text{Alloc}(\mathcal{M}_{\text{monitor}}) \equiv 0
$$

  Parameter Directionality & Purity Invariant: All formal parameters of the referenced constraint must be directional `In` parameters, and predicate evaluation produces zero state mutation:

$$
\forall p \in \mathbf{P}_{\tau(ACU)}, \quad \text{dir}(p) = \text{In}
$$

$$
\forall \sigma \in \Sigma, \quad \llbracket e_{\tau(ACU)} \rrbracket(\sigma) = \langle v, \sigma \rangle \quad \text{where } v \in \mathbb{B}
$$

  Parameter Binding & Subtyping Conformance Invariant: For every assert constraint usage $`ACU \in \mathcal{ACU}`$ referencing definition $`CD = \tau(ACU)`$, the argument vector $`\mathbf{A}_{ACU} = (a_1, \dots, a_m)`$ must match parameter vector $`\mathbf{P}_{CD} = (p_1, \dots, p_k)`$ in arity and satisfy subtyping conformance:

$$
\Phi_{\text{binding}}(ACU) \iff (m = k) \wedge \left( \bigwedge_{i=1}^k (\tau(a_i) \le \tau(p_i)) \wedge \text{IsReadable}(a_i) \right)
$$

  Constraint Call Graph Acyclicity Invariant: The transitive closure of the constraint invocation relation $`\mathcal{R}_{\text{c\_dep}}^+`$ must be irreflexive:

$$
\forall CD \in \mathcal{CD}, \quad (CD, CD) \notin \mathcal{R}_{\text{c\_dep}}^+
$$

  Deterministic RFC 4122 UUIDv5 Topological Identity Invariant:

$$
\forall ACU \in \mathcal{ACU}, \quad \Delta_{ACU} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(ACU))
$$

  Diagnostic Trigger Rules: Violations of predicate codomain, parameter directionality, argument type binding, call graph acyclicity, or compile-time invariant refutation deterministically emit structured diagnostics per REQ-0191:

$$
\begin{aligned}
\neg \Phi_{\text{codomain}}(ACU) &\implies \text{Diagnostic}(ACU, \text{DiagnosticCode::E0200}, \text{NonBooleanConstraintBody}) \in \mathcal{D}_{\text{sink}} \\
\exists p \in \mathbf{P}_{\tau(ACU)} : \text{dir}(p) \ne \text{In} &\implies \text{Diagnostic}(p, \text{DiagnosticCode::E0201}, \text{InvalidConstraintParameterDirection}) \in \mathcal{D}_{\text{sink}} \\
|\mathbf{A}_{ACU}| \ne |\mathbf{P}_{\tau(ACU)}| &\implies \text{Diagnostic}(ACU, \text{DiagnosticCode::E0200}, \text{ParameterArityMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists i \in \{1, \dots, k\} : \tau(a_i) \not\le \tau(p_i) &\implies \text{Diagnostic}(a_i, \text{DiagnosticCode::E0200}, \text{ArgumentTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
(CD, CD) \in \mathcal{R}_{\text{c\_dep}}^+ &\implies \text{Diagnostic}(CD, \text{DiagnosticCode::E0203}, \text{CircularConstraintDependency}) \in \mathcal{D}_{\text{sink}} \\
\text{SAT}(\text{Reachable}(\sigma) \wedge \neg \llbracket \Phi \rrbracket(\sigma)) &\implies \text{Diagnostic}(ACU, \text{DiagnosticCode::E0200}, \text{AssertConstraintCompileTimeRefuted}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Lowering, semantic type checking, AST construction, and runtime monitor code generation execute strictly within Complexity Class $`\mathbf{P}`$. Formal proof obligation verification over quantifier-free first-order theories (QF_LRA, QF_LIA, QF_UF) belongs to Complexity Class $`\mathbf{NP}`$-complete (bounded by algorithmic bound NP-8 per REQ-0197), with solver search bounded by timeout cutoff $`\kappa_{\text{smt}}`$.

  The operational complexity bounds are formalized as follows:
  1. *AST Arena Allocation & Symbol Interning*: Allocating each `AssertConstraintUsage` and synthesized `ConstraintDefinition` node into contiguous arena storage and interning symbol identifiers requires amortized $`O(1)`$ time and $`O(1)`$ auxiliary heap space.
  2. *Predicate Expression Type Checking*: Validating Boolean codomain $`\tau(e_{\tau(ACU)}) \equiv \text{Boolean}`$ traverses the predicate expression tree in deterministic $`O(|\Phi|)`$ time, where $`|\Phi|`$ denotes the number of AST nodes in the expression tree.
  3. *Parameter Binding & Subtyping Conformance*: For each assert constraint usage binding $`k`$ parameters, verifying arity and checking subtyping conformance $`\tau(a_i) \le \tau(p_i)`$ executes in $`O(k)`$ time. Since parameter count is bounded by language design ($`k \le 16 = O(1)`$), binding verification requires $`O(1)`$ time per assert constraint usage.
  4. *Constraint Dependency Acyclicity Checking*: Evaluating acyclicity over call graph $`\mathcal{G}_{\text{c\_dep}} = (\mathcal{CD}, \mathcal{R}_{\text{c\_dep}})`$ using Tarjan's strongly connected components algorithm or Kahn's topological sort executes in deterministic $`O(|\mathcal{CD}| + |\mathcal{R}_{\text{c\_dep}}|)`$ time.
  5. *SMT Proof Obligation Encoding*: Generating equisatisfiable Tseitin clauses or SMT-LIB2 format assertions executes in linear $`O(|\Phi|)`$ time.
  6. *Runtime Safety Monitor Execution*: Evaluating lowered constraint expression $`\Phi(\sigma_t)`$ at every discrete execution step executes in deterministic $`O(1)`$ time with strictly $`O(0)`$ dynamic heap memory allocations.
  7. *Aggregate Compilation Unit Complexity*: For a compilation unit containing $`N = |\mathcal{CD}|`$ constraint definitions and $`M = |\mathcal{ACU}|`$ assert constraint usages with total expression size $`E_{\text{nodes}} = \sum_{j=1}^M |\Phi_j|`$:

$$
T_{\text{validate}}(N, M, E_{\text{nodes}}) \in O(N + M + E_{\text{nodes}} + |\mathcal{R}_{\text{c\_dep}}|)
$$

  8. *Parallel Work-Stealing Scaling (Architectural Directive 2)*: When assert constraint validation across disjoint compilation packages is scheduled onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

$$
T_{\text{parallel}}(N, M, N_{\text{max\_workers}}) \in O\left( \frac{N + M + E_{\text{nodes}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  9. *Memory Bounds*: Auxiliary memory is bounded by $`O(N + M + E_{\text{nodes}})`$ arena storage for lowered AST nodes. Runtime monitor call stacks are bounded by expression tree depth $`O(d_{\max})`$ where $`d_{\max} \le 64 = O(1)`$ frames. Diagnostic sink memory is strictly bounded by $`O(C_{\text{max\_errors}}) = O(1)`$ allocated records.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `AssertConstraint_1`, `AssertConstraint_2`, `ConstraintDef_Alpha`, `param_x : Real`, `param_y : Real`, `attr_a : Real`, `attr_b : Real`, `state_0`) across the following verification gates:
  1. **Canonical `assert constraint` Usage Lowering Gate**: Define `constraint def ConstraintDef_Alpha { in param_x : Real; in param_y : Real; param_x <= param_y; }` and instantiate `assert constraint AssertConstraint_1 : ConstraintDef_Alpha { in param_x = attr_a; in param_y = attr_b; }` within `Classifier_Alpha`.   2. **Boolean Codomain Static Type Enforcement Gate (`E0200`)**: Declare an assert constraint whose body expression evaluates to a non-Boolean type (such as an arithmetic sum `attr_a + attr_b` producing `Real`).   3. **Parameter Arity & Subtyping Conformance Gate (`E0200`)**: Instantiate `ConstraintDef_Alpha` within an assert constraint with missing arguments (arity 1 instead of 2) or with incompatible argument types (passing a `String` literal where `Real` is expected).   4. **Parameter Directionality Enforcement Gate (`E0201`)**: Declare an assert constraint referencing a constraint definition with an `out` or `inout` parameter. Assert deterministic rejection at compile time with diagnostic error code `E0201` (`InvalidConstraintParameterDirection`).
  5. **Anonymous Assert Constraint Lowering Gate**: Declare an anonymous assert constraint usage `assert constraint { attr_a <= attr_b }` within `Classifier_Alpha`. Assert that the lowering engine synthesizes an anonymous `ConstraintDefinition` node, synthesizes two `In` parameters for `attr_a` and `attr_b`, binds them correctly, and produces a valid `AssertConstraintUsage` AST node with zero diagnostics.
  6. **Functional Purity & Side-Effect Freedom Gate (`E0200`)**: Attempt to include a state-mutating assignment (such as `attr_a = param_x`) or an impure behavioral invocation within an assert constraint body. Assert deterministic compile-time rejection with diagnostic error code `E0200`.

  8. **Compile-Time SMT Proof Obligation Synthesis Gate**: Ingest a model with an assert constraint `assert constraint { attr_a >= 0.0 }` alongside state machine transition invariants enforcing `attr_a >= 1.0`.   9. **Compile-Time Invariant Counterexample Refutation Gate (`E0200`)**: Ingest a model where state machine transitions permit a state $`\sigma`$ with `attr_a == -1.0` while asserting `assert constraint { attr_a >= 0.0 }`.   10. **Zero-Allocation Runtime Safety Monitor Synthesis Gate**: Emit code for an assert constraint and verify that the synthesized runtime monitor function $`\mathcal{M}_{\text{monitor}}(\sigma_t)`$ executes in deterministic $`O(1)`$ time with zero dynamic heap allocations.
  11. **Continuous Step Invariant Evaluation & Failsafe Trigger Gate**: In a simulation or test runner environment, ground attributes such that $`\Phi(\sigma_t)`$ evaluates to `false`. Verify that the synthesized runtime monitor synchronously triggers a failsafe containment transition to `state_0` without panicking.
  12. **Synchronization Token Error Recovery Gate (Architectural Directive 4)**: Ingest a model unit containing 5 distinct malformed assert constraint declarations interspersed with valid code.
