### REQ-0058: KerML Association, AssociationStructure & Link Semantics

- **Normative Statement**: The semantic lowering engine and core metamodel shall formalize multi-ary relational constructs as `Association` and `AssociationStructure` classifiers possessing $`k \ge 2`$ participant end features (`AssociationEnd`), establishing relational constraints, directional navigability, and fiber cardinality bounds over instantiated `Link` tuples. Structural and behavioral relationships within the abstract syntax tree (AST) graph shall represent associations as first-class classifiers specializing both `Classifier` and `Relationship` in accordance with the OMG Kernel Modeling Language (KerML) specification.

  Every `Association` definition shall declare an arity $`k \ge 2`$` corresponding to its ordered collection of participant end features `$`\mathcal{E}_A = (e_1, e_2, \dots, e_k)`$`. An association definition declaring fewer than 2 participant ends (`$`k \lt 2`$) shall be strictly rejected at compile time with diagnostic error code `E0200`. Each participant end feature $`e_i`$` must specify: (1) a participant classifier type `$`C_i = \tau(e_i)`$`, (2) a declared multiplicity interval `$`\mu_i = [l_i, u_i]`$` with `$`l_i \in \mathbb{N}_0`$` and `$`u_i \in \mathbb{N}_0 \cup \{ \infty \}`$` satisfying `$`l_i \le u_i`$` and `$`u_i \ge 1`$`, (3) a navigability designation `$`\text{nav}_i \in \{ \text{Navigable}, \text{NonNavigable} \}`$`, and (4) an interned role symbol name `$`\text{name}_{e_i} \in \mathcal{S}_{\text{intern}}`$.

  An instantiated `Link` $`L`$` shall represent an extensional tuple of participant instances `$`(o_1, o_2, \dots, o_k)`$` classified by an association `$`A`$`. The type checking engine shall verify that every participant instance `$`o_i`$` conforms to its corresponding participant classifier type under the subtyping partial order: `$`\tau(o_i) \le C_i`$` for all `$`i \in \{1, \dots, k\}`$. Any type mismatch, un-typed participant instance, or unbound participant slot shall deterministically trigger diagnostic error code `E0200`.

  The semantic validation engine shall enforce fiber cardinality bounds over the set of instantiated links $`\llbracket A \rrbracket`$`. For binary associations (`$`k = 2`$`), for each participant instance `$`x \in \llbracket C_1 \rrbracket`$`, the cardinality of its relational fiber `$`\{ L \in \llbracket A \rrbracket \mid \pi_1(L) = x \}`$`, projected onto end 2 via `$`\pi_2`$`, must satisfy `$`l_2 \le |\pi_2(\text{Fiber}_1(x))| \le u_2`$`; symmetrically, for each `$`y \in \llbracket C_2 \rrbracket`$`, the fiber projected onto end 1 must satisfy `$`l_1 \le |\pi_1(\text{Fiber}_2(y))| \le u_1`$`. For general `$`k`$`-ary associations (`$`k \ge 2`$`), for any participant instance `$`x \in \llbracket C_j \rrbracket`$` at end position `$`j`$`, the projected fiber on any target end `$`i \ne j`$` must satisfy `$`l_i \le |\{ \pi_i(L) \mid L \in \llbracket A \rrbracket \wedge \pi_j(L) = x \}| \le u_i`$. If any participant instance violates its declared multiplicity lower bound or upper bound, the compiler shall emit diagnostic error code `E0200`.

  An `AssociationStructure` shall specialize both `Association` and `Structure` (which specializes `Class`), unifying relational classification with internal structural decomposition, identity persistence, and behavioral occurrence lifecycles. An `AssociationStructure` shall possess both participant end features ($`k \ge 2`$) and owned structural features (internal attributes, ports, operations, and nested associations). Each instantiated link of an `AssociationStructure` shall maintain a distinct object identity handle and deterministic RFC 4122 UUIDv5 identifier, enabling stateful properties, life-cycle transitions, and performance steps to be bound directly to relational occurrences.

  The metamodel shall expose relational navigation operators for all ends marked $`\text{nav}_i = \text{Navigable}`$`. If end `$`e_i`$` is non-navigable from participant `$`C_j`$`, expressions attempting compile-time or run-time traversal along `$`e_j \to e_i`$ shall be rejected with diagnostic error code `E0200`. Associations may specify relational invariant constraints $`\Phi_A`$` that must be satisfied by all links in `$`\llbracket A \rrbracket`$.

  An association $`A_{\text{sub}}`$` may specialize an association `$`A_{\text{base}}`$` (`$`A_{\text{sub}} \le A_{\text{base}}`$`) strictly under monotonic covariance rules: (1) arity invariance (`$`k_{\text{sub}} = k_{\text{base}}`$`), (2) participant end type covariance (`$`\tau(e_i^{\text{sub}}) \le \tau(e_i^{\text{base}})`$` for all `$`i`$`), (3) multiplicity interval narrowing (`$`\mu_i^{\text{sub}} \subseteq \mu_i^{\text{base}}`$`), and (4) navigability preservation (`$`\text{nav}_i^{\text{base}} = \text{Navigable} \implies \text{nav}_i^{\text{sub}} = \text{Navigable}`$). Any non-monotonic specialization or widening redefinition shall trigger diagnostic error code `E0200`.

  In accordance with Architectural Directive 1 and REQ-0010, every `Association`, `AssociationStructure`, and `Link` definition or occurrence shall be anchored by a deterministic RFC 4122 UUIDv5 identifier computed from the DEAP compiler namespace OID and its canonical fully qualified path. In accordance with Architectural Directive 2 and REQ-0012, validation of link topologies and multiplicity bounds across large instance graphs shall execute on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$`. In accordance with Architectural Directive 3 and REQ-0036, all association names, role identifiers, and end symbols shall be interned into the global symbol interner pool during lexical ingest as the sole exception to zero-copy arena allocation. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the association lowering engine shall implement synchronization token error recovery on record and delimiter boundaries, recording structured diagnostics into the compiler diagnostic sink and resuming parsing on subsequent declarations; if accumulated errors reach `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully. In accordance with Architectural Directive 5, REQ-0011, and REQ-0196, the association compiler engine shall enforce a deterministic, non-panicking execution contract with total-function error handling; performance gates (latency < 25 ms, peak memory RSS < 100 MB for $`10^5`$ links) shall be evaluated strictly in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests. All test fixtures, diagnostic messages, and illustrative examples shall strictly use synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Classifier_Delta`, `Association_A`, `AssocStruct_B`, `Link_1`, `End_1`, `End_2`, `param_x : Real`), with zero domain-specific concepts or mock data.

- **Formal Invariant**: The KerML subtyping poset $`(\text{Classifiers}, \le)`$ formalizes `Association` and `AssociationStructure` within the classifier taxonomy:

```math
\begin{aligned}
\text{Association} &\le \text{Classifier} \le \text{Type} \\
\text{Association} &\le \text{Relationship} \le \text{Element} \\
\text{AssociationStructure} &\le \text{Association} \\
\text{AssociationStructure} &\le \text{Structure} \le \text{Class} \le \text{Classifier}
\end{aligned}
```

Each association definition $`A`$ is formalized as a 7-tuple:

```math
A = \langle \text{id}_A, \text{name}_A, \mathcal{E}_A, \mathcal{S}_A, \Phi_A, \Delta_A, \text{span}_A \rangle
```

where:

```math
\begin{aligned}
\text{id}_A &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_A &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\mathcal{E}_A &= (e_1, e_2, \dots, e_k) \quad (\text{ordered sequence of participant ends}, \; k \ge 2) \\
\mathcal{S}_A &\subseteq \mathcal{C}_{\text{assoc}} \quad (\text{direct super-associations}) \\
\Phi_A &\in \text{ConstraintExpr} \cup \{ \top \} \quad (\text{formal relational invariant predicate}) \\
\Delta_A &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
\text{span}_A &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

Each participant end feature $`e_i \in \mathcal{E}_A`$ is formalized as a 6-tuple:

```math
e_i = \langle \text{id}_{e_i}, \text{name}_{e_i}, C_i, \mu_i, \text{nav}_i, \text{span}_{e_i} \rangle
```

where:

```math
\begin{aligned}
\text{id}_{e_i} &\in \mathbb{N}_{32} \quad (\text{contiguous arena feature handle}) \\
\text{name}_{e_i} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned role name}) \\
C_i &= \tau(e_i) \in \mathcal{C} \quad (\text{participant classifier type}) \\
\mu_i &= [l_i, u_i] \subseteq \mathbb{N}_0 \cup \{ \infty \} \quad (\text{multiplicity interval}, \; l_i \le u_i \wedge u_i \ge 1) \\
\text{nav}_i &\in \{ \text{Navigable}, \text{NonNavigable} \} \quad (\text{directional navigability flag}) \\
\text{span}_{e_i} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

Arity Invariant: Every association must possess at least two participant end features:

```math
\text{Arity}(A) = |\mathcal{E}_A| = k \ge 2
```

Extensional Link Tuple Invariant: Each link instance $`L`$` instantiated from association `$`A`$ is an extensional tuple:

```math
L = \langle \text{id}_L, A, (o_1, o_2, \dots, o_k), \Delta_L \rangle \in \llbracket A \rrbracket
```

with end projection operator $`\pi_i(L) = o_i`$. Type conformance requires that every participant instance conforms to its declared end type:

```math
\forall i \in \{1, \dots, k\}, \quad \pi_i(L) \in \llbracket C_i \rrbracket \iff \tau(\pi_i(L)) \le C_i
```

Fiber Cardinality Invariant: For any participant instance $`x \in \llbracket C_j \rrbracket`$` at end position `$`j \in \{1, \dots, k\}`$`, the relational fiber of `$`x`$` over end `$`j`$ is defined as:

```math
\text{Fiber}_j(x) = \{ L \in \llbracket A \rrbracket \mid \pi_j(L) = x \}
```

For every target participant end $`i \in \{1, \dots, k\} \setminus \{ j \}`$`, the projection of `$`\text{Fiber}_j(x)`$` onto end `$`i`$ must satisfy declared multiplicity interval bounds:

```math
\forall j \in \{1, \dots, k\}, \; \forall x \in \llbracket C_j \rrbracket, \; \forall i \in \{1, \dots, k\} \setminus \{ j \}: \quad l_i \le |\pi_i(\text{Fiber}_j(x))| \le u_i
```

For binary associations ($`k = 2`$), the fiber cardinality invariant evaluates over both projection directions:

```math
\begin{aligned}
\forall x \in \llbracket C_1 \rrbracket, &\quad l_2 \le |\{ o_2 \in \llbracket C_2 \rrbracket \mid (x, o_2) \in \llbracket A \rrbracket \}| \le u_2 \\
\forall y \in \llbracket C_2 \rrbracket, &\quad l_1 \le |\{ o_1 \in \llbracket C_1 \rrbracket \mid (o_1, y) \in \llbracket A \rrbracket \}| \le u_1
\end{aligned}
```

Navigability Projection Invariant: The relational traversal operator $`\text{Nav}_{j \to i} : \llbracket C_j \rrbracket \to \mathcal{P}(\llbracket C_i \rrbracket) \cup \{ \bot \}`$ is defined as:

```math
\text{Nav}_{j \to i}(x) = \begin{cases}
\{ \pi_i(L) \mid L \in \llbracket A \rrbracket \wedge \pi_j(L) = x \}, & \text{if } \text{nav}_i = \text{Navigable} \\
\bot, & \text{if } \text{nav}_i = \text{NonNavigable}
\end{cases}
```

AssociationStructure Dual Semantics Invariant: An `AssociationStructure` $`S \in \mathcal{C}_{\text{assoc\_struct}}`$ extends relational association semantics with structural composition and behavioral execution:

```math
S = \langle \text{id}_S, \text{name}_S, \mathcal{E}_S, \mathcal{F}_S, \mathcal{B}_S, \mathcal{S}_S, \Phi_S, \Delta_S, \text{span}_S \rangle
```

where $`|\mathcal{E}_S| \ge 2`$`, `$`\mathcal{F}_S \subseteq \mathcal{U}`$` represents owned structural features, and `$`\mathcal{B}_S`$ represents owned behavioral steps. Each instantiated link of an `AssociationStructure` exhibits both extensional tuple semantics and intensional identity:

```math
\llbracket S \rrbracket \subseteq \left( \prod_{i=1}^k \llbracket C_i \rrbracket \right) \times \text{StateSpace}(\mathcal{F}_S) \times \text{Lifecycle}(\mathcal{B}_S)
```

```math
\forall L_1, L_2 \in \llbracket S \rrbracket, \quad L_1 = L_2 \iff \text{id}(L_1) = \text{id}(L_2)
```

Monotonic Association Specialization Invariant: Specialization $`A_{\text{sub}} \le A_{\text{base}}`$ holds if and only if arity, type covariance, multiplicity narrowing, and navigability preservation are simultaneously satisfied:

```math
\text{ValidAssocSpecialization}(A_{\text{sub}}, A_{\text{base}}) \iff \Psi_{\text{arity}} \wedge \Psi_{\text{type}} \wedge \Psi_{\text{mult}} \wedge \Psi_{\text{nav}}
```

where:

```math
\begin{aligned}
\Psi_{\text{arity}} &\iff |\mathcal{E}_{A_{\text{sub}}}| = |\mathcal{E}_{A_{\text{base}}}| = k \\
\Psi_{\text{type}} &\iff \forall i \in \{1, \dots, k\}, \; \tau(e_i^{\text{sub}}) \le \tau(e_i^{\text{base}}) \\
\Psi_{\text{mult}} &\iff \forall i \in \{1, \dots, k\}, \; [l_i^{\text{sub}}, u_i^{\text{sub}}] \subseteq [l_i^{\text{base}}, u_i^{\text{base}}] \iff (l_i^{\text{base}} \le l_i^{\text{sub}} \wedge u_i^{\text{sub}} \le u_i^{\text{base}}) \\
\Psi_{\text{nav}} &\iff \forall i \in \{1, \dots, k\}, \; (\text{nav}_i^{\text{base}} = \text{Navigable} \implies \text{nav}_i^{\text{sub}} = \text{Navigable})
\end{aligned}
```

Deterministic UUIDv5 Anchor Invariant (Directive 1):

```math
\Delta_A = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(A)) \;\wedge\; \Delta_L = \text{UUIDv5}(\Delta_A, \text{CanonicalLinkTuple}(L))
```

Diagnostic Code Binding Invariant: Violations of association definitions, link typing, multiplicity bounds, navigability, or specialization deterministically trigger structured diagnostics in accordance with REQ-0191:

```math
\begin{aligned}
|\mathcal{E}_A| \lt 2 &\implies \text{Diagnostic}(A, \text{DiagnosticCode::E0200}, \text{InsufficientAssociationEnds}) \in \mathcal{D}_{\text{sink}} \\
\exists i \in \{1, \dots, k\} : \neg(\tau(o_i) \le C_i) &\implies \text{Diagnostic}(L, \text{DiagnosticCode::E0200}, \text{LinkEndTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists x \in \llbracket C_j \rrbracket : |\pi_i(\text{Fiber}_j(x))| \notin [l_i, u_i] &\implies \text{Diagnostic}(x, \text{DiagnosticCode::E0200}, \text{AssociationMultiplicityViolation}) \in \mathcal{D}_{\text{sink}} \\
\text{Nav}_{j \to i}(x) = \bot \wedge \text{AccessAttempted}(j, i) &\implies \text{Diagnostic}(j, \text{DiagnosticCode::E0200}, \text{NonNavigableEndAccessViolation}) \in \mathcal{D}_{\text{sink}} \\
\neg\text{ValidAssocSpecialization}(A_{\text{sub}}, A_{\text{base}}) &\implies \text{Diagnostic}(A_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{InvalidAssociationSpecialization}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Diagnostic Taxonomy Invariant: All emitted association diagnostics belong strictly to the Subsystem 4 metamodel and typing family:

```math
\forall D \in \mathcal{D}_{\text{assoc}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}}
```

- **Computational Complexity & Algorithmic Bounds**: The association lowering and link verification engine executes strictly within Complexity Class $`\mathbf{P}`$`. For an AST containing `$`|A|`$` association definitions, `$`|\mathcal{E}|`$` participant ends, `$`N`$` participant instances, and `$`M = |\llbracket A \rrbracket|`$ instantiated link tuples, algorithmic bounds are established as follows:

  1. Association Definition Validation: Verifying arity $`k \ge 2`$`, role symbol interned lookups, and resolving participant classifier types `$`C_i = \tau(e_i)`$` via lexical scope tables requires `$`O(k)`$` time per association. With bounded practical arity (`$`k \le k_{\max} = 16 = O(1)`$`), validating all association definitions requires deterministic `$`O(|A|)`$ time.
  2. Association Specialization & Redefinition (NP-3 Context): Validating subtyping covariance and multiplicity narrowing between $`A_{\text{sub}}`$` and `$`A_{\text{base}}`$` requires `$`O(k)`$` comparisons. In the presence of multiple inheritance posets, subtyping reachability queries execute in `$`O(1)`$` time via precomputed reachability bitsets or `$`O(h)`$` bounded tree-climbing (`$`h \le 32`$`), resolving C3 linearization without backtracking in deterministic `$`O(V + E)`$ time per NP-3.
  3. Link Participant Type Conformance: Validating $`k`$` participant end instances `$`\tau(o_i) \le C_i`$` for each link requires `$`O(k)`$` subtyping checks. Across `$`M`$` instantiated links, total type conformance checking requires deterministic `$`O(M \cdot k) = O(M)`$ time.
  4. Fiber Multiplicity Bounds Verification: Grouping $`M`$` links by participant instances across end projections executes in expected `$`O(M)`$` time using open-addressing hash maps, or deterministic `$`O(M \log M)`$` time using two-pass radix sort. Checking fiber cardinalities against interval bounds `$`[l_i, u_i]`$` requires `$`O(1)`$` scalar integer comparisons per participant fiber. For `$`N`$` distinct participant instances, aggregate fiber verification requires `$`O(M + N)`$ time.
  5. Navigability and Invariant Checking: Querying navigability flags requires $`O(1)`$` enum lookups. Evaluating relational invariant expressions `$`\Phi_A`$` over links executes in `$`O(M \cdot |\Phi_A|)`$ time.

  Aggregate sequential execution time across all association validation stages is strictly linear:

```math
T_{\text{total}}(|A|, M, N) \in O(|A| + M + N) \subseteq O(|A| + M)
```

  Parallel Work-Stealing Scaling (Architectural Directive 2): When partitioned across $`N_{\text{max\_workers}}`$ threads in the bounded work-stealing pool:

```math
T_{\text{parallel}} \in O\left( \frac{|A| + M}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  Space Complexity & Memory Bounds: Association and link AST nodes are allocated within contiguous bump arenas, consuming strictly $`O(|A| \cdot k + M \cdot k)`$` memory. Auxiliary stack frames during recursive type checking are bounded by maximum inheritance depth `$`O(h) \le 32`$` (`$`O(1)`$` auxiliary stack space). The diagnostic sink is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ allocated records.

- **Verification & Conformance Criteria**: Automated test suites shall verify compliance using synthetic CommonMark and SysML v2 / KerML model definitions containing abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Classifier_Delta`, `Association_A`, `AssocStruct_B`, `Link_1`, `End_1`, `End_2`, `param_x : Real`). Conformance validation shall enforce the following test gates:

  1. Multi-Ary Association End Arity Gate: Ingest a model defining `Association_Invalid` with $`k = 1`$ participant end; assert deterministic compilation failure with diagnostic error code `E0200` (`InsufficientAssociationEnds`). Ingest binary association `Association_A` ($`k = 2`$) and ternary association `Association_Ternary` ($`k = 3`$); assert 100% successful parse and AST construction with zero diagnostics.
  2. Link Participant Type Conformance Gate: Declare `Association_A` over participant classifiers `Classifier_Alpha` and `Classifier_Beta`. Instantiate `Link_1` binding valid instances $`o_1 : \text{Classifier\_Alpha}`$` and `$`o_2 : \text{Classifier\_Beta}`$; assert valid typing. Instantiate `Link_2` binding $`o_1 : \text{Classifier\_Alpha}`$` and `$`o_3 : \text{Classifier\_Gamma}`$ where `Classifier_Gamma` does not specialize `Classifier_Beta`; assert deterministic compilation rejection with diagnostic code `E0200` (`LinkEndTypeMismatch`) containing exact source byte spans and line/column coordinates.
  3. Bidirectional Navigability Traversal Gate: Declare `Association_A` with end `End_1` marked `Navigable` and end `End_2` marked `NonNavigable`. Formulate a navigational expression traversing from `End_2` to `End_1`; assert resolution succeeds. Formulate a navigational expression traversing from `End_1` to `End_2`; assert compiler rejection with diagnostic error code `E0200` (`NonNavigableEndAccessViolation`).
  4. Fiber Multiplicity Envelope & Cardinality Gate: Declare `Association_A` between `Classifier_Alpha` and `Classifier_Beta` with multiplicity interval $`\mu_2 = [1, 3]`$ on `Classifier_Beta`:
     - Test Case 4a (Lower bound violation): Instantiate an instance $`x \in \llbracket \text{Classifier\_Alpha} \rrbracket`$ with 0 associated links; assert rejection with diagnostic `E0200` (`AssociationMultiplicityViolation`).
     - Test Case 4b (Valid interval): Link $`x`$` to 2 distinct instances in `$`\llbracket \text{Classifier\_Beta} \rrbracket`$; assert valid compilation with zero diagnostics.
     - Test Case 4c (Upper bound violation): Link $`x`$` to 4 distinct instances in `$`\llbracket \text{Classifier\_Beta} \rrbracket`$; assert rejection with diagnostic `E0200` (`AssociationMultiplicityViolation`).
  5. AssociationStructure Dual Semantics Gate: Declare `AssocStruct_B` connecting `Classifier_Alpha` and `Classifier_Beta`, possessing an internal property `param_x : Real` and an internal operation `Action_1`. Assert that `AssocStruct_B` is lowered as a subtype of both `Association` and `Structure`. Instantiate links of `AssocStruct_B`; assert that each link possesses both relational endpoints and individual object identity with stateful attribute bindings.
  6. Monotonic Association Specialization Gate: Declare `Association_Sub` specializing `Association_A` (`Association_Sub :> Association_A`). Specialize end types covariantly and narrow multiplicity from `[0..10]` to `[1..5]`; assert successful validation. In a second test, widen multiplicity to `[0..20]` or declare a non-conforming end type; assert deterministic rejection with diagnostic code `E0200` (`InvalidAssociationSpecialization`).
  7. Deterministic UUIDv5 Anchor Gate (Architectural Directive 1): Compute RFC 4122 UUIDv5 digests for `Association_A`, `AssocStruct_B`, and instantiated links across independent compilation runs. Assert bitwise 128-bit identity and Merkle root stability per REQ-0010.
  8. Bounded Work-Stealing Parallelism Gate (Architectural Directive 2): Benchmark multi-threaded link type checking and fiber validation over $`10^5`$` links across `$`N_{\text{max\_workers}}`$ threads in the bounded work-stealing thread pool; assert zero race conditions, data-race freedom, and bitwise identical diagnostic logs compared to single-threaded execution.
  9. Synchronization Token Error Recovery Gate (Architectural Directive 4): Inject multiple malformed association declarations and invalid link tuples within a single compilation unit. Assert that the lowering engine resynchronizes on delimiter boundaries, records all diagnostics into the compiler diagnostic sink without panicking, and cleanly halts with terminal code `E0199` upon reaching $`C_{\text{max\_errors}}`$.
  10. Non-Panicking Release Mode & Latency Budget Gate (Architectural Directive 5): In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, verify that checking $`10^5`$ links executes in under 25 ms and peak RSS memory remains strictly under 100 MB with zero panics.
