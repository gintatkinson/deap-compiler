### REQ-0012: Bounded Work-Stealing Parallelism & Thread Isolation

- **Normative Statement**: All multi-threaded compiler operations--including parallel schema ingestion, multi-file AST parsing, concurrent AST graph traversals, STPA Cartesian product hazard tensor expansions, temporal reachability evaluations, and downstream artifact code generation--shall execute exclusively through a centralized, bounded work-stealing thread pool. Parallel task execution shall be strictly bounded by an upper worker limit $`N_{\text{workers}} = \min(C_{\text{logical}}, N_{\text{max\_workers}})`$, where $`C_{\text{logical}} \in \mathbb{N}_{\ge 1}`$ is the detected host logical CPU core count and $`N_{\text{max\_workers}} \in \mathbb{N}_{\ge 1}`$ is a configurable runtime worker ceiling. The compiler runtime shall strictly prohibit unbounded, ad-hoc, or manual operating system thread creation. Worker threads must operate in complete memory isolation without shared mutable state across thread boundaries; all concurrent tasks shall access shared data via immutable references or frozen AST views, and all task-local mutations shall remain confined to thread-local arenas or task-private accumulators. Parallel reductions and task aggregations must enforce deterministic combination ordering such that scheduling interleavings never induce non-deterministic AST mutations or artifact diff churn.

- **Formal Invariant**: Let $`P_{\text{workers}}`$ denote the active worker thread pool initialized by the compiler runtime. Let $`C_{\text{logical}}`$ denote the host logical CPU core count and $`N_{\text{max\_workers}}`$ denote the configured maximum worker thread limit. The active worker thread pool cardinality satisfies the strict bounded ceiling:

$$
|P_{\text{workers}}| = N_{\text{workers}} = \min(C_{\text{logical}}, N_{\text{max\_workers}}) \le N_{\text{max\_workers}}
$$

Let $`\mathcal{T}_{\text{spawned}}`$ denote the set of all operating system threads instantiated by the compiler execution process, and let $`N_{\text{coord}} \in \{0, 1\}`$ denote the master coordination thread. The total spawned thread invariant enforces:

$$
|\mathcal{T}_{\text{spawned}}| \le |P_{\text{workers}}| + N_{\text{coord}}
$$

Let $`\text{Memory}(\tau)`$ denote the set of memory addresses accessed by worker thread $`\tau \in P_{\text{workers}}`$ during the execution of task $`w \in \mathcal{W}`$. Let $`\text{Writes}(\tau) \subseteq \text{Memory}(\tau)`$ and $`\text{Reads}(\tau) \subseteq \text{Memory}(\tau)`$ denote the write-set and read-set of worker $`\tau`$, respectively. Concurrency safety and thread isolation satisfy pairwise memory disjointness for all distinct concurrent workers $`\tau_i \neq \tau_j \in P_{\text{workers}}`$:

$$
\begin{aligned}
\text{Writes}(\tau_i) \cap \text{Writes}(\tau_j) &= \emptyset \\
\text{Writes}(\tau_i) \cap \text{Reads}(\tau_j) &= \emptyset \\
\text{Reads}(\tau_i) \cap \text{Writes}(\tau_j) &= \emptyset
\end{aligned}
$$

The global shared mutable state invariant across the thread pool asserts:

$$
\text{SharedMutableState}(P_{\text{workers}}) = \bigcup_{\tau_i \neq \tau_j} \left( \text{Writes}(\tau_i) \cap \text{Memory}(\tau_j) \right) = \emptyset
$$

Workloads are partitioned into data-parallel tasks enqueued into worker-local double-ended deques $`Q_i = \langle w_{i,1}, \dots, w_{i,m} \rangle`$ for each worker $`\tau_i \in P_{\text{workers}}`$. Local task execution and remote work-stealing satisfy the deque operational rules:

$$
\begin{aligned}
\text{LocalExecution}(\tau_i) &: \quad Q_i \neq \emptyset \implies \text{PopBottom}(Q_i) \\
\text{StealRule}(\tau_i) &: \quad Q_i = \emptyset \implies \text{StealTop}(Q_j), \quad j \neq i, \; Q_j \neq \emptyset
\end{aligned}
$$

Let $`\mathcal{G}_{\text{comp}} = (\mathcal{V}_{\text{tasks}}, \mathcal{E}_{\text{dep}})`$ be the directed acyclic graph of compilation tasks, and let $`\Pi(\mathcal{G}_{\text{comp}})`$ denote the set of all valid topological execution schedules. Let $`\mathcal{O}(\pi)`$ denote the final serialized AST or generated artifact under schedule $`\pi \in \Pi(\mathcal{G}_{\text{comp}})`$. The concurrency schedule independence invariant guarantees bitwise deterministic reproducibility:

$$
\forall \pi_1, \pi_2 \in \Pi(\mathcal{G}_{\text{comp}}), \quad \mathcal{O}(\pi_1) = \mathcal{O}(\pi_2)
$$

- **Computational Complexity & Algorithmic Bounds**: Work-stealing scheduling executes within Complexity Class $`\mathbf{P}`$. For any parallel computation directed acyclic graph with total sequential work $`T_1`$ and critical-path span $`T_\infty`$, the bounded work-stealing scheduler achieves an expected execution time:

$$
T_P \le \frac{T_1}{P} + O(T_\infty)
$$

where $`P = |P_{\text{workers}}| = \min(C_{\text{logical}}, N_{\text{max\_workers}})`$. Local deque push and pop operations execute in deterministic $`O(1)`$ time. Remote work-stealing attempts execute in $`O(1)`$ lock-free atomic compare-and-swap time per attempt, with the total number of steal attempts bounded by $`O(P \cdot T_\infty)`$ with high probability. Space complexity is strictly bounded by $`O(P \cdot S_1)`$, where $`S_1`$ is the peak stack and task-local memory consumption of a sequential execution, preventing unbounded memory expansion.

- **Verification & Conformance Criteria**: Concurrency auditing harnesses shall verify that the number of operating system threads instantiated by the compiler never exceeds $`N_{\text{workers}} + N_{\text{coord}}`$. Static analysis and type-level safety bounds shall verify that zero shared mutable references cross worker thread boundaries. Dynamic stress testing across synthetic MBSE schemas shall execute multi-threaded compilation under randomized thread pool capacities ($`P \in \{1, 2, 4, 8, 16\}`$) and randomized thread scheduling delays, asserting 100% bitwise parity of emitted AST graphs and downstream artifacts against a single-threaded reference run. If any component attempts to spawn an unmanaged thread, if worker thread allocation exceeds $`N_{\text{max\_workers}}`$, or if concurrent data race or non-deterministic reduction variance is detected, the compiler shall halt immediately and emit diagnostic error code `E0100` detailing the offending thread identifier, active worker count, and violation telemetry.
