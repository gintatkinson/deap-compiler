### REQ-0013: Synchronization Token Error Recovery Architecture

- **Normative Statement**: All front-end schema and language parsers within the compiler platform--including CommonMark tabular schema parsers, OMG SysML v2 and KerML textual grammar parsers, OMG IDL parsers, Protocol Buffer parsers, OpenAPI parsers, and XML/ADL structural parsers--shall implement a formal Synchronization Token Error Recovery architecture. Rather than aborting compilation upon the first encountered syntax error, lexical fault, or delimiter mismatch, front-end parsers must capture a structured diagnostic record, discard invalid tokens up to the nearest designated synchronization token boundary, unwind the parser state to an enclosing synchronizing grammar production, and resume parsing to accumulate multiple localized diagnostics per file in a single compilation pass. Error recovery operations must execute under a total, deterministic, non-panicking execution contract with zero panics or unhandled exceptions. The parser shall enforce strictly monotonic forward stream progress, advancing the token stream pointer beyond the current fault index on every recovery action to eliminate livelocks and infinite recovery loops. The parser must implement cascading error suppression by suppressing secondary diagnostic emissions occurring within a bounded token proximity window $`\delta \le 3`$` following a synchronization event when attributable to recovery realignment ambiguity. The diagnostic sink shall enforce a bounded capacity limit `$`C_{\text{max\_errors}}`$ per compilation unit, gracefully concluding the parse pass and emitting diagnostic `E0199` when the threshold is reached to prevent denial of service from degenerate inputs.

- **Formal Invariant**: Let $`T = \langle t_0, t_1, \dots, t_{N-1} \rangle`$` denote the ordered sequence of input lexical tokens of length `$`N = |T|`$`, terminated by an explicit end-of-file token `$`t_{\text{EOF}} = t_N`$`. Let `$`\mathcal{R}`$` denote the set of grammar production scopes, and let `$`\mathcal{T}_{\text{sync}}(R)`$` define the designated set of synchronization tokens for active grammar rule `$`R \in \mathcal{R}`$`. For statement scopes, `$`\mathcal{T}_{\text{sync}}(R)`$ includes statement terminators (`;`), block closing delimiters (`}`, `]`, `)`), or line break tokens ($`\text{SYM}_{\text{LF}}`$`); for tabular schema records, `$`\mathcal{T}_{\text{sync}}(R)`$` includes record delimiters (`$`\text{SYM}_{\text{LF}}`$, table row boundary markers `|`).

Upon encountering a syntax fault at token stream position $`k \in \{0, \dots, N-1\}`$` while in parse stack state `$`S_k \in \mathcal{S}_{\text{parser}}`$, the token skipping operator is defined as:

```math
\text{SkipUntil}(\mathcal{T}_{\text{sync}}(R), k) = \{ t_i \mid k \le i \lt m, \; t_m \in \mathcal{T}_{\text{sync}}(R) \cup \{ t_{\text{EOF}} \} \}
```

where $`m`$` is the minimal index satisfying `$`m \ge k`$` and `$`t_m \in \mathcal{T}_{\text{sync}}(R) \cup \{ t_{\text{EOF}} \}`$. Parser state unwinding yields a valid enclosing recovery state:

```math
S_{\text{recovered}} = \text{UnwindStack}(S_k, t_m)
```

The Monotonic Forward Stream Progress Invariant mandates that the stream position at step $`t+1`$` strictly exceeds the stream position at step `$`t`$:

```math
\forall t, \quad \text{StreamPosition}_{t+1} \gt \text{StreamPosition}_t
```

where the updated stream pointer satisfies:

```math
\text{StreamPosition}_{t+1} = 
\begin{cases}
m + 1, & \text{if } t_m \in \mathcal{T}_{\text{sync}}(R) \\
N, & \text{if } t_m = t_{\text{EOF}}
\end{cases}
```

Strict monotonicity guarantees bounded termination without infinite loops:

```math
\forall \sigma \in \text{ParseExecutions}, \quad \text{Steps}(\sigma) \le N + 1
```

Let $`\tau_{\text{last}} \in \mathbb{N}`$` denote the token stream position of the most recent synchronization recovery event. For any subsequent syntax error detected at token index `$`j \gt \tau_{\text{last}}`$, cascading error suppression evaluates:

```math
\text{EmitDecision}(j, \tau_{\text{last}}) = 
\begin{cases}
\text{Suppress}, & \text{if } j - \tau_{\text{last}} \le \delta \\
\text{Record}, & \text{if } j - \tau_{\text{last}} \gt \delta
\end{cases}
```

where $`\delta \in \mathbb{N}`$` satisfies `$`\delta \le 3`$.

Let $`\mathcal{D}_t`$` denote the set of accumulated diagnostics at step `$`t`$`. For a detected error `$`D_k = \langle \text{code}_k, \text{span}(t_k), \text{expected}_k, \text{actual}(t_k) \rangle`$, diagnostic sink accumulation satisfies:

```math
\mathcal{D}_{t+1} = 
\begin{cases}
\mathcal{D}_t \cup \{ D_k \}, & \text{if } \text{EmitDecision}(k, \tau_{\text{last}}) = \text{Record} \;\wedge\; |\mathcal{D}_t| \lt C_{\text{max\_errors}} \\
\mathcal{D}_t, & \text{otherwise}
\end{cases}
```

Bounded Sink Capacity Invariant:

```math
|\mathcal{D}| \le C_{\text{max\_errors}}
```

Diagnostic Taxonomy Containment Invariant: Every generated ingestion diagnostic satisfies the taxonomy partitioning defined in REQ-0191:

```math
\forall D_k \in \mathcal{D}, \quad \text{code}(D_k) \in \mathcal{E}_{\text{ingest}} = \{ e \in \mathcal{E} \mid 100 \le \text{code}(e) \le 199 \}
```

- **Computational Complexity & Algorithmic Bounds**: The synchronization token error recovery engine executes within Complexity Class $`\mathbf{P}`$`. Because token skipping is strictly monotonic forward (`$`\text{StreamPosition}_{t+1} \gt \text{StreamPosition}_t`$`), every token `$`t_i \in T`$` is visited at most `$`O(1)`$` times during linear scanning, preserving `$`O(N)`$` worst-case time complexity across the entire token stream of length `$`N = |T|`$`. Parse stack unwinding across `$`K`$` recovery operations requires at most `$`O(K \cdot H_{\text{max}})`$` operations, where `$`H_{\text{max}}`$` is the bounded constant parse stack depth (`$`H_{\text{max}} \le 256`$`), ensuring that stack adjustments execute in `$`O(N)`$` total time. Cascading suppression lookups execute in `$`O(1)`$` constant time per error event via scalar distance subtraction. Total parser execution time is strictly bounded by `$`O(N)`$`. Auxiliary space complexity is bounded by `$`O(H_{\text{max}} + C_{\text{max\_errors}})`$ for maintaining the parser stack and the bounded diagnostic sink.

- **Verification & Conformance Criteria**: Automated parser test suites shall verify compliance against synthetic malformed MBSE schema documents containing multiple independent syntax errors across distinct scopes. For a test input with $`K`$` independent syntax faults separated by valid synchronization tokens (where `$`K \lt C_{\text{max\_errors}}`$`), the test harness shall assert that the parser emits exactly `$`K`$` structured diagnostics in a single compilation pass without terminating prematurely. Conformance checks shall assert that every emitted diagnostic binds an appropriate diagnostic code in the `$`\mathcal{E}_{\text{ingest}}`$ range: `E0100` for general grammar syntax violations, `E0102` for tabular row delimiter synchronization failures, `E0103` for malformed attribute/type records, or `E0104` for invalid connection topology syntax. Pathological inputs containing consecutive malformed tokens, infinite-loop hazard patterns, and trailing unclosed blocks must terminate deterministically within at most $`N + 1`$` parser steps. Inputs exceeding `$`C_{\text{max\_errors}}`$ faults must halt parsing at threshold capacity and emit diagnostic code `E0199`. Injected secondary syntax faults within distance $`\delta \le 3`$ of a synchronization boundary must be suppressed, asserting that zero spurious cascading errors appear in the diagnostic output. Determinism is verified by executing the error recovery suite across multiple runs, asserting bitwise identical diagnostic output and zero diff churn.
