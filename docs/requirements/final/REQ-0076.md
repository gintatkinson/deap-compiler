### REQ-0076: SysML v2 ItemFlow (`flow`) & Streaming Direction Lowering

- **Normative Statement**: The SysML v2 and KerML metamodel lowering engine shall formalize `flow` usages (`ItemFlow` / `FlowUsage`) as directed streaming transfers of matter, energy, or data payloads traversing connectors between port endpoints. The compiler shall lower each `flow` declaration into a KerML `Step` and `OccurrenceUsage` entity in the contiguous arena storage, enforcing streaming directional compatibility, payload item subtyping covariance, transmission rate multiplicity interval bounds, and physical channel bandwidth capacities.

  The lowering engine shall strictly enforce the following normative provisions across all lowered item flow declarations:
  1. **Metamodel Lowering & KerML Step Specialization**: SysML v2 `flow` usages shall be lowered to specialize KerML `Step` and `OccurrenceUsage` metamodel constructs within the contiguous arena. Each lowered item flow AST node shall maintain explicit handles to its source port endpoint ($p_{\text{src}}$), target port endpoint ($p_{\text{tgt}}$), bound payload item classifier type ($I_{\text{payload}}$), streaming rate multiplicity envelope ($R_{\text{flow}}$), and associated connector or interconnect channel ($C_{\text{conn}}$).
  2. **Streaming Directional Compatibility Invariants**: The compiler shall statically verify that endpoint port usages possess effective directions compatible with the directed transfer:
     - The source port $p_{\text{src}}$ must be capable of emitting items: its effective direction shall satisfy $\text{dir}(p_{\text{src}}) \in \{ \text{Out}, \text{InOut} \}$. If the source port has effective direction `In` or `None`, the compiler shall reject the flow declaration and emit diagnostic error code `E0201` (`FlowSourceDirectionMismatch`).
     - The target port $p_{\text{tgt}}$ must be capable of ingesting items: its effective direction shall satisfy $\text{dir}(p_{\text{tgt}}) \in \{ \text{In}, \text{InOut} \}$. If the target port has effective direction `Out` or `None`, the compiler shall reject the flow declaration and emit diagnostic error code `E0201` (`FlowTargetDirectionMismatch`).
     - For bidirectional ports where both endpoints have effective direction `InOut`, the item flow declaration shall establish the directed streaming orientation from source to target.
  3. **Item Payload Typing and Subtyping Covariance**: Every item flow must designate or infer an authoritative payload item classifier type $I_{\text{payload}} \in \mathcal{T}$. In accordance with Algorithmic Bound NP-3, the compiler shall verify that $I_{\text{payload}}$ specializes or conforms to the payload types declared on both the source port ($\text{payload\_type}(p_{\text{src}})$) and the target port ($\text{payload\_type}(p_{\text{tgt}})$) within the subtyping meet-semilattice $(\mathcal{T}, \le, \wedge)$:
     $$I_{\text{payload}} \le \text{payload\_type}(p_{\text{src}}) \;\wedge\; I_{\text{payload}} \le \text{payload\_type}(p_{\text{tgt}})$$
     This invariant guarantees that any item emitted by the source conforms to the declared flow payload specification, and any item transported across the flow can be safely ingested by the target port. If $I_{\text{payload}}$ violates subtyping covariance with either endpoint, or if their meet evaluates to the bottom type $\bot_{\text{type}}$, the lowering engine shall reject the flow declaration with diagnostic error code `E0202` (`FlowItemTypeIncompatibility`).
  4. **Streaming Rate Multiplicity Bounds and Channel Capacity**: The flow declaration may specify a streaming transmission rate multiplicity interval $R_{\text{flow}} = [r_{\min}, r_{\max}]$ in occurrences or transfers per second (Hz). The type checking engine shall verify:
     - *Multiplicity Envelope Well-Formedness*: The rate interval must be non-negative and well-formed ($0 \le r_{\min} \le r_{\max}$ in $\mathbb{R}_{\ge 0} \times (\mathbb{R}_{\ge 0} \cup \{ \infty \})$). Inverted intervals ($r_{\min} \gt r_{\max}$) or negative bounds ($r_{\min} \lt 0$) shall be rejected with diagnostic error code `E0202` (`MalformedFlowRateMultiplicity`).
     - *Individual Channel Capacity*: Peak throughput $\Theta(F) = r_{\max} \cdot \text{size}(I_{\text{payload}})$ shall not exceed the designated connector or channel bandwidth capacity $\text{Capacity}(C)$ ($\Theta(F) \le \text{Capacity}(C)$). Overflows shall trigger diagnostic error code `E0202` (`FlowRateCapacityOverflow`).
     - *Multiplexed Channel Capacity*: If multiple concurrent item flows traverse the same connector or interconnect channel $C$, cumulative peak throughput shall not exceed channel capacity ($\sum_{F \in \text{Flows}(C)} \Theta(F) \le \text{Capacity}(C)$). Aggregate capacity violations shall trigger diagnostic error code `E0202` (`AggregateFlowCapacityOverflow`).
  5. **Scope Resolution and Endpoint Visibility**: Source and target endpoints $p_{\text{src}}$ and $p_{\text{tgt}}$ must resolve to visible port usages within the common enclosing component or accessible across peer component boundaries via deterministic $O(1)$ scope symbol table lookup. Dangling, unresolvable, or out-of-scope port references shall be rejected with diagnostic error code `E0200` (`FlowEndpointResolutionError`).
  6. **Algorithmic Bound NP-3 Integration**: In arbitrary partially ordered sets (posets), general multiple-inheritance subtyping and feature redefinition is NP-complete. To guarantee polynomial tractability, the compiler shall enforce that all classifier inheritance graphs form a monotonic meet-semilattice and resolve multiple inheritance precedence using deterministic C3 linearization without backtracking. Under this restriction, subtyping constraint checking over flow payload types reduces to monotonic poset reachability, solvable in deterministic $O(1)$ time per query.
  7. **Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered item flow AST node shall be assigned a deterministic RFC 4122 UUIDv5 identifier generated by namespace-hashing the fully qualified names of the flow, source port, and target port with the canonical compiler namespace OID per REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel lowering and validation of independent item flows across component packages shall execute on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ per REQ-0012.
     - *Directive 3 (String Interner Allocation Exception)*: Scalar item flow identifiers, port path segments, and classifier symbols shall be interned into the global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The lowering engine shall implement synchronization token error recovery per REQ-0013 and REQ-0016. Upon detecting a direction mismatch (`E0201`), payload type incompatibility (`E0202`), rate violation (`E0202`), or resolution failure (`E0200`), the engine shall record the diagnostic into $\mathcal{D}_{\text{sink}}$, substitute an error sentinel $\bot_{\text{flow}}$, and resynchronize at the next delimiter token. If accumulated diagnostics reach $C_{\text{max\_errors}}$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
     - *Directive 5 (Panic-Free Release Isolation)*: The lowering engine shall enforce a total-function, panic-free execution contract across all valid and malformed inputs. Execution latency ($\lt 25\text{ ms}$) and peak memory RSS ($\lt 100\text{ MB}$ for $10^5$ item flows) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.
     - *Domain Purity*: All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Port_1`, `Port_2`, `Port_Src`, `Port_Tgt`, `Flow_0`, `Flow_1`, `Item_0`, `Item_1`, `Conn_0`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $\mathcal{D}$ denote the discrete closed port direction domain:

$$
\mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut}, \text{None} \}
$$

Let $\mathcal{E}_{\text{flow}}$ denote the universe of lowered item flow AST entities. Each item flow entity $F \in \mathcal{E}_{\text{flow}}$ is formalized as an 11-tuple:

$$
F = \langle \text{id}_F, \text{name}_F, \text{owner}_F, p_{\text{src}}, p_{\text{tgt}}, I_{\text{payload}}, R_{\text{flow}}, C_{\text{conn}}, \Delta_F, \text{span}_F, \sigma_F \rangle
$$

where:

$$
\begin{aligned}
\text{id}_F &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_F &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_F &\in \mathcal{C} \quad (\text{enclosing classifier definition handle}) \\
p_{\text{src}} &\in \mathcal{V}_{\text{port}} \quad (\text{source port endpoint handle}) \\
p_{\text{tgt}} &\in \mathcal{V}_{\text{port}} \quad (\text{target port endpoint handle}) \\
I_{\text{payload}} &\in \mathcal{T} \setminus \{ \bot_{\text{type}} \} \quad (\text{bound payload item classifier type}) \\
R_{\text{flow}} &= [r_{\min}, r_{\max}] \subseteq \mathbb{R}_{\ge 0} \times (\mathbb{R}_{\ge 0} \cup \{ \infty \}) \quad (\text{rate multiplicity interval}) \\
C_{\text{conn}} &\in \mathcal{E}_{\text{conn}} \cup \{ \bot_{\text{conn}} \} \quad (\text{underlying connector handle}) \\
\Delta_F &\in \Sigma^* \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_F &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance coordinate}) \\
\sigma_F &\in \{ \text{Valid}, \bot_{\text{flow}} \} \quad (\text{lowering status sentinel})
\end{aligned}
$$

KerML Metamodel Lowering Specialization Invariant: SysML v2 `ItemFlow` specializes KerML `Step` and `OccurrenceUsage`:

$$
\begin{aligned}
\text{ItemFlow} &\le \text{Step} \le \text{Feature} \\
\text{ItemFlow} &\le \text{OccurrenceUsage} \le \text{OccurrenceDefinition}
\end{aligned}
$$

Streaming Directional Compatibility Invariant: The source port $p_{\text{src}}$ must emit and the target port $p_{\text{tgt}}$ must ingest:

$$
\Phi_{\text{dir}}(F) \iff \left( \text{dir}(p_{\text{src}}) \in \{ \text{Out}, \text{InOut} \} \right) \;\wedge\; \left( \text{dir}(p_{\text{tgt}}) \in \{ \text{In}, \text{InOut} \} \right)
$$

Item Payload Subtyping Covariance Invariant: In the bounded subtyping meet-semilattice $(\mathcal{T}, \le, \wedge)$, the transferred item payload type $I_{\text{payload}}$ must specialize or equal the payload types of both port endpoints:

$$
\Phi_{\text{payload}}(F) \iff \left( I_{\text{payload}} \le \text{payload\_type}(p_{\text{src}}) \right) \;\wedge\; \left( I_{\text{payload}} \le \text{payload\_type}(p_{\text{tgt}}) \right)
$$

Equivalently, expressed via the greatest lower bound (meet) operator $\wedge$:

$$
\Phi_{\text{payload}}(F) \iff \left( I_{\text{payload}} \wedge \text{payload\_type}(p_{\text{src}}) = I_{\text{payload}} \right) \;\wedge\; \left( I_{\text{payload}} \wedge \text{payload\_type}(p_{\text{tgt}}) = I_{\text{payload}} \right)
$$

Rate Multiplicity Well-Formedness Invariant: The transmission rate interval $R_{\text{flow}} = [r_{\min}, r_{\max}]$ must be non-negative and monotonically ordered:

$$
\Phi_{\text{rate}}(F) \iff \left( 0 \le r_{\min} \right) \;\wedge\; \left( r_{\min} \le r_{\max} \right)
$$

Payload Wire and Memory Footprint Size Function: The deterministic payload size function $\text{size} : \mathcal{T} \to \mathbb{N}_{> 0}$ evaluates the byte representation:

$$
\text{size}(\tau) = \begin{cases}
1, & \text{if } \tau \in \{ \text{Boolean}, \text{Int8}, \text{UInt8} \} \\
2, & \text{if } \tau \in \{ \text{Int16}, \text{UInt16} \} \\
4, & \text{if } \tau \in \{ \text{Int32}, \text{UInt32}, \text{Float32} \} \\
8, & \text{if } \tau \in \{ \text{Int64}, \text{UInt64}, \text{Float64} \} \\
\sum_{f \in \text{features}(\tau)} u_f \cdot \text{size}(\tau(f)), & \text{if } \tau \in \mathcal{T}_{\text{composite}} \text{ with features } f \text{ having upper multiplicity } u_f
\end{cases}
$$

Peak Transmission Throughput Function: For item flow $F$, peak transmission throughput $\Theta(F)$ in bytes per second is defined as:

$$
\Theta(F) = r_{\max} \cdot \text{size}(I_{\text{payload}})
$$

Connector Bandwidth Capacity Invariant: For an individual item flow $F$ traversing connector $C \in \mathcal{E}_{\text{conn}}$ with capacity $\text{Capacity}(C) \in \mathbb{R}_{\ge 0} \cup \{ \infty \}$:

$$
\Phi_{\text{cap}}(F, C) \iff \Theta(F) \le \text{Capacity}(C)
$$

For an interconnect connector $C$ multiplexing a set of concurrent item flows $\mathcal{E}_{\text{flow}}(C) = \{ F_1, F_2, \dots, F_k \}$:

$$
\Phi_{\text{agg\_cap}}(C) \iff \sum_{F \in \mathcal{E}_{\text{flow}}(C)} \Theta(F) \le \text{Capacity}(C)
$$

Scope Visibility and Endpoint Resolution Invariant: Both endpoint ports must resolve to visible port usages within the enclosing scope:

$$
\Phi_{\text{scope}}(F) \iff \left( p_{\text{src}} \in \text{VisiblePorts}(\text{owner}_F) \right) \;\wedge\; \left( p_{\text{tgt}} \in \text{VisiblePorts}(\text{owner}_F) \right)
$$

Universal Item Flow Well-Formedness Invariant:

$$
\text{ValidItemFlow}(F) \iff \Phi_{\text{dir}}(F) \wedge \Phi_{\text{payload}}(F) \wedge \Phi_{\text{rate}}(F) \wedge \Phi_{\text{cap}}(F, C_{\text{conn}}) \wedge \Phi_{\text{scope}}(F)
$$

Deterministic RFC 4122 UUIDv5 Identification Invariant (Architectural Directive 1): Each lowered item flow entity $F$ is identified by a deterministic UUIDv5:

$$
\Delta_F = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"\_flow\_"} \mathbin{\Vert} \text{FQN}(p_{\text{src}}) \mathbin{\Vert} \text{"->"} \mathbin{\Vert} \text{FQN}(p_{\text{tgt}}))
$$

Diagnostic Code Binding Invariant: Any violation of directional compatibility, payload subtyping, rate bounds, capacity limits, or scope visibility deterministically triggers structured diagnostics in accordance with REQ-0191:

$$
\begin{aligned}
\neg \Phi_{\text{scope}}(F) &\implies \text{Diagnostic}(F, \text{DiagnosticCode::E0200}, \text{FlowEndpointResolutionError}) \in \mathcal{D}_{\text{sink}} \\
\text{dir}(p_{\text{src}}) \notin \{ \text{Out}, \text{InOut} \} &\implies \text{Diagnostic}(p_{\text{src}}, \text{DiagnosticCode::E0201}, \text{FlowSourceDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
\text{dir}(p_{\text{tgt}}) \notin \{ \text{In}, \text{InOut} \} &\implies \text{Diagnostic}(p_{\text{tgt}}, \text{DiagnosticCode::E0201}, \text{FlowTargetDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
\neg \Phi_{\text{payload}}(F) &\implies \text{Diagnostic}(F, \text{DiagnosticCode::E0202}, \text{FlowItemTypeIncompatibility}) \in \mathcal{D}_{\text{sink}} \\
\neg \Phi_{\text{rate}}(F) &\implies \text{Diagnostic}(F, \text{DiagnosticCode::E0202}, \text{MalformedFlowRateMultiplicity}) \in \mathcal{D}_{\text{sink}} \\
\neg \Phi_{\text{cap}}(F, C) &\implies \text{Diagnostic}(F, \text{DiagnosticCode::E0202}, \text{FlowRateCapacityOverflow}) \in \mathcal{D}_{\text{sink}} \\
\neg \Phi_{\text{agg\_cap}}(C) &\implies \text{Diagnostic}(C, \text{DiagnosticCode::E0202}, \text{AggregateFlowCapacityOverflow}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant: All diagnostics emitted by the item flow lowering engine strictly belong to the Metamodel and Typing family and Ingestion error limit family:

$$
\forall d \in \mathcal{D}_{\text{flow}}, \quad \text{code}(d) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0201}, \text{DiagnosticCode::E0202}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{ingest}}
$$

- **Computational Complexity & Algorithmic Bounds**: Item flow lowering, directional validation, payload subtyping conformance, and rate multiplicity checking execute strictly within Complexity Class $\mathbf{P}$.

  **Algorithmic Bound NP-3 Formulation**: In unconstrained partially ordered sets (posets) with arbitrary multiple inheritance, structural subtyping and feature specialization satisfiability is NP-complete. The DEAP compiler eliminates backtracking and combinatorial explosion by enforcing two structural constraints:
  1. The type hierarchy forms a monotonic meet-semilattice $(\mathcal{T}, \le, \wedge)$ with unique greatest lower bounds.
  2. Multiple inheritance linearization is resolved via the deterministic C3 linearization algorithm, guaranteeing a total topological ordering for every classifier in $O(V + E)$ time.

  **Asymptotic Verification Complexity**: For an abstract model containing $V = |\mathcal{V}_{\text{port}}|$ port instances, $E = |\mathcal{E}_{\text{flow}}|$ item flows, and $K = |\mathcal{E}_{\text{conn}}|$ connectors:
  1. *Scope & Port Handle Resolution*: Resolving interned symbol identifiers for source and target ports executes in $O(1)$ constant time per flow via interned hash table lookups.
  2. *Directional Compatibility Evaluation*: Verifying $\text{dir}(p_{\text{src}}) \in \{ \text{Out}, \text{InOut} \}$ and $\text{dir}(p_{\text{tgt}}) \in \{ \text{In}, \text{InOut} \}$ evaluates two 2-bit discriminant lookups in strictly $O(1)$ constant time with zero heap allocations.
  3. *Payload Subtyping Conformance*: Evaluating $I_{\text{payload}} \le \text{payload\_type}(p_{\text{src}})$ and $I_{\text{payload}} \le \text{payload\_type}(p_{\text{tgt}})$ executes in $O(1)$ constant time via precomputed reachability bitsets or in bounded $O(h)$ time where inheritance tree depth $h \le 32$.
  4. *Rate Multiplicity Bounds & Throughput Capacity*: Validating rate intervals ($0 \le r_{\min} \le r_{\max}$) and computing peak throughput $\Theta(F) = r_{\max} \cdot \text{size}(I_{\text{payload}}) \le \text{Capacity}(C)$ executes in $O(1)$ scalar floating-point and integer operations.
  5. *Aggregate Connector Capacity Evaluation*: Summing peak throughputs across multiplexed flows for connector $C$ executes in $O(|\mathcal{E}_{\text{flow}}(C)|)$ time.

  Total sequential verification time across all item flows and connectors is strictly linear in the size of the flow graph:

$$
T_{\text{validate}}(V, E, K) = \sum_{F \in \mathcal{E}_{\text{flow}}} O(1) + \sum_{C \in \mathcal{E}_{\text{conn}}} O(|\mathcal{E}_{\text{flow}}(C)|) \in O(V + E + K) \subseteq O(V + E)
$$

  **Parallel Work-Stealing Scaling (Architectural Directive 2)**: When item flow validation across disjoint component packages is scheduled on a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$:

$$
T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{V + E}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  **Space Complexity & Memory Bounds**: Auxiliary memory is bounded by $O(V + E)$ arena storage for AST nodes and flow edges. Precomputed reachability bitsets require at most $O(V \cdot \lceil V / 64 \rceil)$ bits, reducing to $O(V)$ for hierarchical sparse trees. Traversal call stacks are bounded by recursion depth $O(h) \le 32$ frames ($O(1)$ auxiliary stack memory). The diagnostic error sink is bounded by $O(C_{\text{max\_errors}}) = O(1)$ preallocated memory.
