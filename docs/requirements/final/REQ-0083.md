### REQ-0083: SysML v2 ConstraintDefinition (`constraint def`) & ConstraintUsage Lowering

- **Normative Statement**: The KerML/SysML v2 metamodel lowering engine and semantic type checker shall formalize `constraint def` (ConstraintDefinition) and `constraint` (ConstraintUsage) AST elements as strongly typed Boolean predicate functions specializing KerML `Predicate` and `Function`. Every `ConstraintDefinition` shall define an invariant, parameterized logical proposition over an ordered vector of formal parameters $`\mathbf{p} = (p_1, \dots, p_k)`$` whose predicate expression body `$`e_{CD}`$ must evaluate to `true` across all admissible system configurations.

  The compiler shall enforce the following structural, semantic, and typing invariants during constraint lowering:
  1. **Predicate Specialization & Boolean Codomain Enforcement**: In the KerML metamodel hierarchy, `ConstraintDefinition` specializes `Predicate`, which in turn specializes `Function` with a mandatory Boolean result codomain ($`\text{ConstraintDefinition} \le \text{Predicate} \le \text{Function} \longrightarrow \mathbb{B}`$`). The body of a constraint definition shall consist of one or more Boolean expressions whose logical conjunction constitutes the constraint predicate `$`e_{CD}`$`. The semantic type checker shall statically verify that the evaluated type of `$`e_{CD}`$ unifies with the standard primitive type `Boolean`. Any constraint definition whose body expression yields a non-Boolean type shall be strictly rejected at compile time with diagnostic error code `E0200` in accordance with REQ-0191.
  2. **Parameter Directionality & Immutability**: All formal parameters of a `ConstraintDefinition` must declare or default to `In` directionality ($`\text{dir}(p_i) = \text{In}`$). Declaring `Out` or `InOut` parameters within a constraint definition shall be strictly rejected at compile time with diagnostic error code `E0201`. In accordance with functional purity invariants, formal parameters shall be immutable within the predicate expression body, and constraint evaluation shall produce zero state mutation or side effects ($`\Delta \text{State} \equiv \emptyset`$). Any assignment, mutable state access, or invocation of non-functional behaviors within a constraint body shall be rejected with diagnostic error code `E0200`.
  3. **ConstraintUsage Parameter Binding & Type Conformance**: A `ConstraintUsage` represents the contextual application or feature instantiation of a constraint within an enclosing classifier definition (e.g., `part def`, `item def`, `action def`, or `state def`) or package. Every `ConstraintUsage` $`CU`$ shall bind its formal parameters to actual argument expressions or accessible features within its featuring scope. The compiler shall verify that:
     - The number of actual argument bindings matches the parameter arity of the referenced constraint definition ($`|\mathbf{a}_{CU}| = |\mathbf{p}_{CD}|`$). Any arity mismatch shall trigger diagnostic error code `E0200`.
     - For each argument binding $`a_i`$` bound to formal parameter `$`p_i`$`, the argument type `$`\tau(a_i)`$` must specialize or equal the parameter type `$`\tau(p_i)`$` in the subtyping semilattice (`$`\tau(a_i) \le \tau(p_i)`$). Argument type incompatibility shall trigger diagnostic error code `E0200`.
     - Actual argument expressions must be read-accessible in the invocation context. Passing write-only ports or uninitialized out-parameters as constraint arguments shall trigger diagnostic error code `E0201`.
  4. **Anonymous & Shorthand Constraint Lowering**: When a model declares an anonymous constraint block (`constraint { <expr> }`), the lowering engine shall synthesize an implicit, anonymous `ConstraintDefinition` node in contiguous bump arena storage, project all free variables referenced within `<expr>` as synthetic formal `In` parameters, bind them to the corresponding features in the featuring scope, and emit a synthetic `ConstraintUsage` node linked to the generated definition.
  5. **Constraint Call Graph Acyclicity**: The lowering engine shall construct a directed dependency graph $`\mathcal{G}_{\text{c\_dep}} = (\mathcal{CD}, \mathcal{R}_{\text{c\_dep}})`$` tracking invocations between constraint definitions. Mutual recursion or cyclic invocations (`$`CD_1 \to CD_2 \to \dots \to CD_1`$) shall be strictly prohibited and detected via topological cycle detection, emitting diagnostic error code `E0203`.
  6. **Evaluation & Violation Semantics**: For any admissible operational state configuration $`\sigma \in \Sigma_{\text{valid}}`$`, evaluating the lowered constraint expression over grounded argument valuations `$`\sigma(\mathbf{a}_{CU})`$` shall yield `$`\llbracket CU \rrbracket(\sigma) \equiv \text{true}`$. When a constraint evaluates to `false` during static symbolic evaluation or simulation stepping, the compiler or simulation runtime shall emit a structured constraint violation event binding the failing parameter coordinates and source span.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered `ConstraintDefinition` and `ConstraintUsage` AST node shall be assigned a deterministic RFC 4122 UUIDv5 identifier generated by namespace-hashing the fully qualified symbol path (e.g., `Package_0::Classifier_Alpha::Constraint_1`) with the canonical compiler namespace OID per REQ-0010.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel lowering and semantic type checking of independent constraint definitions and usages across distinct compilation units shall execute on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
  - *Directive 3 (String Interner Allocation Exception)*: Scalar constraint identifiers, parameter names, and qualified path tokens shall be interned into the global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
  - *Directive 4 (Synchronization Token Error Recovery)*: The lowering engine shall implement synchronization token error recovery per REQ-0013 and REQ-0016. Upon encountering an invalid constraint body (`E0200`), parameter direction mismatch (`E0201`), or cyclic dependency (`E0203`), the engine shall record the diagnostic into the error sink, substitute an error sentinel node $`\bot_{\text{type}}`$`, and resynchronize on the next declaration delimiter without aborting compilation. If accumulated diagnostics reach `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
  - *Directive 5 (Panic-Free Release Isolation)*: The lowering engine shall enforce a total-function, panic-free execution contract across all valid and malformed inputs. Execution latency ($`\lt 25\text{ ms}`$`) and peak memory RSS (`$`\lt 100\text{ MB}`$` for `$`10^5`$ constraint nodes) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `ConstraintDef_Alpha`, `ConstraintDef_Beta`, `ConstraintUsage_1`, `ConstraintUsage_2`, `param_x : Real`, `param_y : Real`, `attr_a : Real`, `attr_b : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage. Let `$`\mathcal{CD} \subset \mathcal{V}_{\text{AST}}`$` denote the set of constraint definition nodes, and let `$`\mathcal{CU} \subset \mathcal{V}_{\text{AST}}`$ denote the set of constraint usage nodes.

  Each constraint definition $`CD \in \mathcal{CD}`$ is formalized as an 8-tuple:

```math
CD = \langle \text{id}_{CD}, \text{name}_{CD}, \text{owner}_{CD}, \mathbf{P}_{CD}, e_{CD}, \kappa_{CD}, \Delta_{CD}, \text{span}_{CD} \rangle
```

  where:

```math
\begin{aligned}
\text{id}_{CD} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{CD} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_{CD} &\in \mathcal{C} \cup \mathcal{P}_{\text{pkg}} \quad (\text{owning classifier definition or package}) \\
\mathbf{P}_{CD} &= (p_1, \dots, p_k) \in \mathcal{V}_{\text{param}}^k \quad (\text{ordered sequence of formal parameter handles}) \\
e_{CD} &\in \mathcal{E}_{\text{expr}} \quad (\text{predicate expression root node handle}) \\
\kappa_{CD} &\in \{ \text{Named}, \text{Anonymous} \} \quad (\text{definition syntactic form}) \\
\Delta_{CD} &\in \Sigma^* \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{CD} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

  Each formal parameter $`p_i \in \mathbf{P}_{CD}`$ is formalized as:

```math
p_i = \langle \text{id}_{p_i}, \text{name}_{p_i}, \tau(p_i), \mu(p_i), \text{dir}(p_i) \rangle
```

  where $`\text{dir}(p_i) \equiv \text{In}`$`, `$`\tau(p_i) \in \mathcal{T} \setminus \{ \bot_{\text{type}} \}`$`, and `$`\mu(p_i) = [m_{\min}, m_{\max}]`$.

  Each constraint usage $`CU \in \mathcal{CU}`$ is formalized as a 7-tuple:

```math
CU = \langle \text{id}_{CU}, \text{name}_{CU}, \text{owner}_{CU}, \tau(CU), \mathbf{A}_{CU}, \Delta_{CU}, \text{span}_{CU} \rangle
```

  where:

```math
\begin{aligned}
\text{id}_{CU} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{CU} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_{CU} &\in \mathcal{C} \quad (\text{featuring classifier definition}) \\
\tau(CU) &\in \mathcal{CD} \quad (\text{referenced constraint definition handle}) \\
\mathbf{A}_{CU} &= (a_1, \dots, a_m) \in \mathcal{E}_{\text{expr}}^m \quad (\text{actual argument expressions}) \\
\Delta_{CU} &\in \Sigma^* \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{CU} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

  Predicate Codomain & Specialization Invariant: A constraint definition specializes KerML `Function` with a Boolean codomain $`\mathbb{B} = \{ \text{false}, \text{true} \}`$:

```math
\text{ConstraintDef} \le \text{Predicate} \le \text{Function} \longrightarrow \mathbb{B}
```

```math
\Phi_{\text{codomain}}(CD) \iff \tau(e_{CD}) \equiv \text{Boolean}
```

  Parameter Directionality & Purity Invariant: All formal parameters must be strictly directional input parameters, and expression evaluation produces no state mutation:

```math
\forall p \in \mathbf{P}_{CD}, \quad \text{dir}(p) = \text{In}
```

```math
\forall \sigma \in \Sigma, \quad \llbracket e_{CD} \rrbracket(\sigma) = \langle v, \sigma \rangle \quad \text{where } v \in \mathbb{B}
```

  Parameter Binding & Subtyping Conformance Invariant: For every constraint usage $`CU \in \mathcal{CU}`$` referencing definition `$`CD = \tau(CU)`$`, the argument vector `$`\mathbf{A}_{CU} = (a_1, \dots, a_m)`$` must match the parameter vector `$`\mathbf{P}_{CD} = (p_1, \dots, p_k)`$ in arity and satisfy subtyping conformance:

```math
\Phi_{\text{binding}}(CU, CD) \iff (m = k) \wedge \left( \bigwedge_{i=1}^k (\tau(a_i) \le \tau(p_i)) \wedge \text{IsReadable}(a_i) \right)
```

  Admissible Configuration Invariant: For any constraint usage $`CU`$` and valid state configuration `$`\sigma \in \Sigma_{\text{valid}}`$` with grounded parameter valuations `$`\sigma(\mathbf{A}_{CU}) = (\sigma(a_1), \dots, \sigma(a_k))`$:

```math
\forall \sigma \in \Sigma_{\text{valid}}, \quad \llbracket CU \rrbracket(\sigma) \equiv \llbracket e_{\tau(CU)} \rrbracket\left( [p_i \mapsto \sigma(a_i)]_{i=1}^k \right) \equiv \text{true}
```

  Constraint Call Graph Acyclicity Invariant: Let $`\mathcal{R}_{\text{c\_dep}} \subset \mathcal{CD} \times \mathcal{CD}`$` denote the binary invocation relation where `$`(CD_1, CD_2) \in \mathcal{R}_{\text{c\_dep}}`$` if expression `$`e_{CD_1}`$` directly or transitively references `$`CD_2`$`. The transitive closure `$`\mathcal{R}_{\text{c\_dep}}^+`$ must be irreflexive:

```math
\forall CD \in \mathcal{CD}, \quad (CD, CD) \notin \mathcal{R}_{\text{c\_dep}}^+
```

  Deterministic RFC 4122 UUIDv5 Topological Identity Invariant:

```math
\begin{aligned}
\forall CD \in \mathcal{CD}, \quad \Delta_{CD} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(CD)) \\
\forall CU \in \mathcal{CU}, \quad \Delta_{CU} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(CU))
\end{aligned}
```

  Diagnostic Trigger Invariants: Violations of predicate codomain, parameter directionality, argument type binding, or dependency acyclicity deterministically emit structured diagnostics per REQ-0191:

```math
\begin{aligned}
\neg \Phi_{\text{codomain}}(CD) &\implies \text{Diagnostic}(CD, \text{DiagnosticCode::E0200}, \text{NonBooleanConstraintBody}) \in \mathcal{D}_{\text{sink}} \\
\exists p \in \mathbf{P}_{CD} : \text{dir}(p) \ne \text{In} &\implies \text{Diagnostic}(p, \text{DiagnosticCode::E0201}, \text{InvalidConstraintParameterDirection}) \in \mathcal{D}_{\text{sink}} \\
|\mathbf{A}_{CU}| \ne |\mathbf{P}_{\tau(CU)}| &\implies \text{Diagnostic}(CU, \text{DiagnosticCode::E0200}, \text{ParameterArityMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists i \in \{1, \dots, k\} : \tau(a_i) \not\le \tau(p_i) &\implies \text{Diagnostic}(a_i, \text{DiagnosticCode::E0200}, \text{ArgumentTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
(CD, CD) \in \mathcal{R}_{\text{c\_dep}}^+ &\implies \text{Diagnostic}(CD, \text{DiagnosticCode::E0203}, \text{CircularConstraintDependency}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

- **Computational Complexity & Algorithmic Bounds**: Lowering and type verification of `ConstraintDefinition` and `ConstraintUsage` AST nodes executes strictly within Complexity Class $`\mathbf{P}`$.

  The operational complexity bounds are formalized as follows:
  1. *AST Arena Allocation & Symbol Interning*: Allocating each `ConstraintDefinition`, `ConstraintUsage`, and `Parameter` node into contiguous bump arena storage and interning symbol identifiers requires amortized $`O(1)`$` time and `$`O(1)`$ auxiliary heap space.
  2. *Predicate Expression Type Checking*: Validating the Boolean codomain $`\tau(e_{CD}) \equiv \text{Boolean}`$` traverses the predicate expression tree in deterministic `$`O(|e_{CD}|)`$` time, where `$`|e_{CD}|`$ denotes the number of AST nodes in the expression tree.
  3. *Parameter Binding & Subtyping Conformance*: For each constraint usage binding $`k`$` parameters, verifying arity and checking subtyping conformance `$`\tau(a_i) \le \tau(p_i)`$` executes in `$`O(k)`$` time. Since parameter count is bounded by language design (`$`k \le 16 = O(1)`$`), binding verification requires `$`O(1)`$ time per constraint usage.
  4. *Constraint Dependency Acyclicity Checking*: Evaluating acyclicity over the call graph $`\mathcal{G}_{\text{c\_dep}} = (\mathcal{CD}, \mathcal{R}_{\text{c\_dep}})`$` using Tarjan's strongly connected components algorithm or Kahn's topological sort executes in deterministic `$`O(|\mathcal{CD}| + |\mathcal{R}_{\text{c\_dep}}|)`$ time.
  5. *Grounded Parameter Evaluation*: Evaluating a lowered constraint expression $`e_{CD}`$` over a grounded parameter valuation vector `$`\sigma(\mathbf{a}_{CU})`$` executes in `$`O(|e_{CD}|)`$` stack operations, requiring strictly `$`O(1)`$ stack operations per constraint expression node.
  6. *Aggregate Compilation Unit Complexity*: For a compilation unit containing $`N = |\mathcal{CD}|`$` constraint definitions and `$`M = |\mathcal{CU}|`$` constraint usages with total expression size `$`E_{\text{nodes}} = \sum_{j=1}^N |e_{CD_j}|`$:

```math
T_{\text{validate}}(N, M, E_{\text{nodes}}) \in O(N + M + E_{\text{nodes}} + |\mathcal{R}_{\text{c\_dep}}|)
```

  7. *Parallel Work-Stealing Scaling (Architectural Directive 2)*: When constraint validation across disjoint compilation packages is scheduled onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}}(N, M, N_{\text{max\_workers}}) \in O\left( \frac{N + M + E_{\text{nodes}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  8. *Memory Bounds*: Auxiliary memory is bounded by $`O(N + M + E_{\text{nodes}})`$` arena storage for lowered AST nodes. Expression evaluation call stacks are bounded by expression tree depth `$`O(d_{\max})`$` where `$`d_{\max} \le 64 = O(1)`$` frames. The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ allocated memory.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `ConstraintDef_Alpha`, `ConstraintDef_Beta`, `ConstraintUsage_1`, `ConstraintUsage_2`, `param_x : Real`, `param_y : Real`, `attr_a : Real`, `attr_b : Real`) across the following verification gates:
  1. **Canonical `constraint def` & `constraint` Usage Lowering Gate**: Define `constraint def ConstraintDef_Alpha { in param_x : Real; in param_y : Real; param_x <= param_y; }` and instantiate `constraint ConstraintUsage_1 : ConstraintDef_Alpha { in param_x = attr_a; in param_y = attr_b; }` within `Classifier_Alpha`. Assert 100% lowering into contiguous bump arena storage, valid parameter bindings, and zero diagnostics emitted.
  2. **Boolean Codomain Static Type Enforcement Gate (`E0200`)**: Declare a constraint definition whose body expression evaluates to a non-Boolean type (e.g., an arithmetic sum `param_x + param_y` producing `Real`). Assert deterministic rejection at compile time with diagnostic error code `E0200` (`NonBooleanConstraintBody`) and assignment of the error sentinel $`\bot_{\text{type}}`$.
  3. **Parameter Arity & Subtyping Conformance Gate (`E0200`)**: Instantiate `ConstraintDef_Alpha` with missing arguments (arity 1 instead of 2) or with incompatible argument types (passing a `String` literal where `Real` is expected). Assert deterministic rejection with diagnostic error code `E0200` (`ParameterArityMismatch` or `ArgumentTypeMismatch`).
  4. **Parameter Directionality Enforcement Gate (`E0201`)**: Declare a constraint definition with an `out` or `inout` parameter (e.g., `out param_z : Real`). Assert deterministic rejection at compile time with diagnostic error code `E0201` (`InvalidConstraintParameterDirection`).
  5. **Anonymous Constraint Expression Lowering Gate**: Declare an anonymous constraint usage `constraint { attr_a <= attr_b }` within `Classifier_Alpha`. Assert that the lowering engine synthesizes an anonymous `ConstraintDefinition` node with `Anonymous` discriminant kind, synthesizes two `In` parameters for `attr_a` and `attr_b`, binds them correctly, and produces valid AST nodes with zero diagnostics.
  6. **Functional Purity & Side-Effect Freedom Gate (`E0200`)**: Attempt to include a state-mutating assignment (e.g., `attr_a = param_x`) or an impure behavioral invocation within a constraint definition body. Assert deterministic compile-time rejection with diagnostic error code `E0200`.
  7. **Circular Constraint Dependency Detection Gate (`E0203`)**: Declare mutually recursive constraint definitions where `ConstraintDef_Alpha` invokes `ConstraintDef_Beta` and `ConstraintDef_Beta` invokes `ConstraintDef_Alpha`. Assert that topological cycle detection identifies the cycle and emits diagnostic error code `E0203` (`CircularConstraintDependency`) with exact source byte spans for all participating definitions.
  8. **Grounded Evaluation & Violation Event Gate**: In a simulation or test runner environment, ground parameters `attr_a = 5.0` and `attr_b = 3.0` for `ConstraintDef_Alpha` (asserting `param_x <= param_y`). Assert that evaluation yields `false` and triggers a structured constraint violation event identifying the failing coordinates `(param_x=5.0, param_y=3.0)`.
  9. **Synchronization Token Error Recovery & Error Accumulation Gate (Architectural Directive 4)**: Ingest a model unit containing 5 distinct malformed constraint declarations interspersed with valid code. Verify that the lowering engine resynchronizes on delimiter boundaries, accumulates all 5 `E0200` and `E0201` diagnostics with precise source spans, and halts gracefully with terminal diagnostic `E0199` when the error count reaches $`C_{\text{max\_errors}}`$.
  10. **Deterministic UUIDv5 & Performance Budget Gate (Architectural Directives 1 & 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, assert that lowering and validating $`10^5`$ synthetic constraint definitions and usages executes in strictly under 25 ms, peak RSS memory remains strictly under 100 MB, all nodes receive deterministic RFC 4122 UUIDv5 identifiers, and consecutive compilation runs exhibit bitwise determinism with 0-byte diff churn.
