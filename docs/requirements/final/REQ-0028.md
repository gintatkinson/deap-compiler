### REQ-0028: OMG IDL AST Ingestion for Structs, Interfaces & Directional Parameters

- **Normative Statement**: The Universal Schema Ingestion Engine shall provide a native OMG Interface Definition Language (OMG IDL v4.2 and v3.x specification) lexer, parser, and intermediate representation lowering engine that ingests `.idl` interface specifications into intermediate schema IR without external compiler dependencies or preprocessors. The ingestion engine shall parse IDL compilation units consisting of hierarchical module namespaces, composite value types (`struct`), discriminated variant types (`union`), enumerated types (`enum`), type definitions (`typedef`), and component interface definitions (`interface`) containing operations, directional parameters, and attributes. The lowering transformation shall map IDL constructs to intermediate schema IR entities in accordance with the following contract:
  1. Module Lowering: IDL `module` statements shall lower to nested `IngestedPackage` namespaces, establishing deterministic hierarchical lexical scoping and constructing fully qualified symbol paths (e.g., `Module_Alpha::SubModule_Beta::Interface_Gamma`).
  2. Interface Lowering: IDL `interface` declarations shall lower to `IngestedPart` definitions annotated with boolean flag `is_interface: true`, preserving interface inheritance hierarchies as generalization relationships.
  3. Struct Lowering: IDL `struct` definitions shall lower to `IngestedClassifierDef` entities with structural kind `ClassifierKind::Struct`, lowering each member field sequentially into an `IngestedAttr` property binding member identifier, classifier type reference, and multiplicity interval.
  4. Union Lowering: IDL `union` definitions shall lower to `IngestedClassifierDef` entities with structural kind `ClassifierKind::Union`, recording the explicit discriminant type and lowering each case branch label (including `default`) into an indexed variant field definition.
  5. Enum Lowering: IDL `enum` declarations shall lower to `IngestedClassifierDef` entities with structural kind `ClassifierKind::Enum`, preserving the ordered sequence of enumerator symbol identifiers.
  6. Typedef Lowering: IDL `typedef` declarations shall lower to `IngestedTypeDef` symbol aliases within the enclosing lexical scope table.
  7. Operation and Parameter Lowering: IDL operations within an interface shall lower to `IngestedAction` operation entities. Every formal parameter declared in an IDL operation parameter list must bind an explicit directional token: `in`, `out`, or `inout`. Implicit or missing parameter directions are strictly prohibited and shall trigger diagnostic error code `E0102`. The parser shall partition operation parameters such that:
     - `in` parameters are mapped to the action input parameter list (`inputs`),
     - `out` parameters are mapped to the action output parameter list (`outputs`),
     - `inout` parameters are mapped to both input and output parameter lists (`inputs` and `outputs`) with bidirectional binding (`inouts`).
     - If the operation specifies a non-void return type, the lowering engine shall synthesize a formal return output parameter binding identifier `result` with the declared return type into `outputs`. If the return type is `void`, no synthetic return parameter shall be added.
  8. Attribute Lowering: IDL `attribute` and `readonly attribute` declarations shall lower to `IngestedAttr` properties owned by the enclosing interface entity, with boolean flag `is_readonly` set to `false` and `true` respectively.
  9. Sequence and Array Multiplicity Lowering: Bounded sequences `sequence<T, K>` shall lower to classifier type `T` with multiplicity interval $\langle 0, K \rangle$; unbounded sequences `sequence<T>` shall lower to classifier type `T` with multiplicity interval $\langle 0, \infty \rangle$; fixed arrays `T ident[K]` shall lower to classifier type `T` with multiplicity interval $\langle K, K \rangle$.

  All synthesized intermediate AST nodes (`IngestedPackage`, `IngestedPart`, `IngestedClassifierDef`, `IngestedAction`, `IngestedAttr`) shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, yielding deterministic node handles with stable relative offsets. In accordance with Architectural Directive 1 and REQ-0010, every lowered AST node shall receive a deterministic RFC 4122 UUIDv5 identifier derived from the namespace OID and the fully qualified symbol path. In accordance with Architectural Directive 3 and REQ-0036, copying string bytes from the input IDL buffer into the global symbol interner pool for scalar `SymbolId` tokens during this initial ingestion pass is the sole permitted exception to the zero-copy invariant. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the ingestion engine shall implement synchronization token error recovery on statement and block delimiter boundaries ($\text{SYM}_{\text{SEMI}}$ `;`, $\text{SYM}_{\text{RBRACE}}$ `}`, and $\text{SYM}_{\text{RPAREN}}$ `)`): upon encountering a syntax error, illegal token, or missing parameter direction, the engine shall record a structured diagnostic record binding diagnostic error code `E0102` (IDL syntax or grammar violation) or `E0103` (unsupported type or discriminant mismatch) per REQ-0191, substitute a typed sentinel error node $\bot_{\text{idl}}$, and resynchronize at the next delimiter boundary rather than aborting compilation. Multi-file IDL compilation passes shall be scheduled strictly onto a bounded work-stealing thread pool with worker bound $N_{\text{max\_workers}}$ in accordance with Architectural Directive 2 and REQ-0012. The parser shall enforce Architectural Directive 5, guaranteeing a total, deterministic, non-panicking execution contract with total-function termination across all inputs. Latency (< 25 ms) and RSS (< 100 MB) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196. All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Module_Alpha`, `Interface_Beta`, `Struct_Gamma`, `Union_Delta`, `op_omega`, `param_x : Real`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $\mathcal{I}_{\text{idl}}$ denote the abstract syntax tree of an OMG IDL compilation unit. The lowering transformation $\mathcal{T}_{\text{idl}} : \mathcal{I}_{\text{idl}} \longrightarrow \mathcal{A}_{\text{IR}}$ maps IDL AST constructs to intermediate schema IR entities:

$$
\begin{aligned}
\text{module } M \{ \mathcal{D}^* \} &\longmapsto \text{IngestedPackage}(M, \text{members}: \mathcal{T}_{\text{idl}}(\mathcal{D}^*)) \\
\text{interface } I \{ \mathcal{M}^* \} &\longmapsto \text{IngestedPart}(I, \text{is\_interface}: \text{true}, \text{members}: \mathcal{T}_{\text{idl}}(\mathcal{M}^*)) \\
\text{struct } S \{ \mathcal{F}^* \} &\longmapsto \text{IngestedClassifierDef}(S, \text{kind}: \text{ClassifierKind::Struct}, \text{fields}: \mathcal{T}_{\text{idl}}(\mathcal{F}^*)) \\
\text{union } U \text{ switch}(D) \{ \mathcal{C}^* \} &\longmapsto \text{IngestedClassifierDef}(U, \text{kind}: \text{ClassifierKind::Union}, \text{discriminant}: D, \text{cases}: \mathcal{T}_{\text{idl}}(\mathcal{C}^*)) \\
\text{enum } E \{ e_0, \dots, e_{k-1} \} &\longmapsto \text{IngestedClassifierDef}(E, \text{kind}: \text{ClassifierKind::Enum}, \text{enumerators}: \langle e_0, \dots, e_{k-1} \rangle) \\
\text{typedef } T \; A &\longmapsto \text{IngestedTypeDef}(A, \text{target\_type}: T)
\end{aligned}
$$

Let $\text{op} = \langle \text{id}, T_{\text{ret}}, \text{Params}(\text{op}) \rangle$ denote an IDL operation declaration, where $\text{Params}(\text{op}) = \langle p_1, p_2, \dots, p_m \rangle$ is the ordered sequence of formal parameters. Each parameter $p_j$ is a triple $\langle \text{name}_j, T_j, \text{dir}_j \rangle$. The operation lowering transformation satisfies:

$$
\mathcal{T}_{\text{idl}}(\text{op}) = \text{IngestedAction}(\text{id}, \text{inputs}: \mathcal{P}_{\text{in}}(\text{op}), \text{outputs}: \mathcal{P}_{\text{out}}(\text{op}), \text{inouts}: \mathcal{P}_{\text{inout}}(\text{op}))
$$

where the parameter partition sets are defined as:

$$
\begin{aligned}
\mathcal{P}_{\text{in}}(\text{op}) &= \{ \langle \text{name}(p), \text{type}(p) \rangle \mid p \in \text{Params}(\text{op}) \;\wedge\; \text{dir}(p) \in \{ \text{In}, \text{InOut} \} \} \\
\mathcal{P}_{\text{out}}(\text{op}) &= \{ \langle \text{name}(p), \text{type}(p) \rangle \mid p \in \text{Params}(\text{op}) \;\wedge\; \text{dir}(p) \in \{ \text{Out}, \text{InOut} \} \} \;\cup\; \text{ReturnParam}(T_{\text{ret}}) \\
\mathcal{P}_{\text{inout}}(\text{op}) &= \{ \langle \text{name}(p), \text{type}(p) \rangle \mid p \in \text{Params}(\text{op}) \;\wedge\; \text{dir}(p) = \text{InOut} \}
\end{aligned}
$$

and the synthetic return parameter function $\text{ReturnParam}(T_{\text{ret}})$ satisfies:

$$
\text{ReturnParam}(T_{\text{ret}}) = 
\begin{cases}
\{ \langle \text{result}, T_{\text{ret}} \rangle \}, & \text{if } T_{\text{ret}} \ne \text{void} \\
\emptyset, & \text{if } T_{\text{ret}} = \text{void}
\end{cases}
$$

Directional Parameter Completeness Invariant: Each parameter in an IDL operation binds an explicit direction belonging strictly to the closed ternary set:

$$
\forall \text{op} \in \text{Operations}(\mathcal{I}_{\text{idl}}), \, \forall p \in \text{Params}(\text{op}), \quad \text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}
$$

Sequence and Array Multiplicity Invariant: The parsed multiplicity interval $\text{Mult}(T) \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \})$ for an IDL type expression $T$ satisfies:

$$
\text{Mult}(T) = 
\begin{cases}
\langle 0, K \rangle, & \text{if } T = \text{sequence}\langle T', K \rangle \;\wedge\; K \in \mathbb{N}^+ \\
\langle 0, \infty \rangle, & \text{if } T = \text{sequence}\langle T' \rangle \\
\langle K, K \rangle, & \text{if } T = T'[K] \;\wedge\; K \in \mathbb{N}^+ \\
\langle 1, 1 \rangle, & \text{otherwise}
\end{cases}
$$

Module Containment DAG Invariant: Let $G_{\text{mod}} = (\mathcal{M}_{\text{pkg}}, \mathcal{E}_{\text{mod}})$ denote the module containment directed graph, where $(M_1, M_2) \in \mathcal{E}_{\text{mod}}$ indicates that module $M_1$ encloses module $M_2$. The transitive containment closure $\mathcal{E}_{\text{mod}}^+$ is strictly irreflexive:

$$
\forall M \in \mathcal{M}_{\text{pkg}}, \quad (M, M) \notin \mathcal{E}_{\text{mod}}^+
$$

and every nested module has at most one immediate enclosing module:

$$
\forall M_2 \in \mathcal{M}_{\text{pkg}}, \quad |\{ M_1 \in \mathcal{M}_{\text{pkg}} \mid (M_1, M_2) \in \mathcal{E}_{\text{mod}} \}| \le 1
$$

Deterministic UUIDv5 and Bump Arena Invariant: For every lowered AST node $u \in \mathcal{A}_{\text{IR}}$, its RFC 4122 UUIDv5 identifier satisfies:

$$
\text{UUID}(u) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))
$$

and sequential allocation into the contiguous typed bump arena satisfies:

$$
\forall i \in \{1, \dots, M-1\}, \quad \text{Offset}(h_{i+1}) = \text{Offset}(h_i) + \text{sizeof}(\text{ASTNode})
$$

Diagnostic Code Binding Invariant: Grammar violations, missing directions, cycle detections, and type errors trigger structured diagnostic records in accordance with REQ-0191:

$$
\begin{aligned}
\text{dir}(p) \notin \{ \text{In}, \text{Out}, \text{InOut} \} &\implies \text{Diagnostic}(\text{span}(p), \text{DiagnosticCode::E0102}, \text{MissingOrInvalidParameterDirection}) \in \mathcal{D} \\
\text{HasSyntaxError}(\text{token}_k) &\implies \text{Diagnostic}(\text{span}(\text{token}_k), \text{DiagnosticCode::E0102}, \text{IDLSyntaxGrammarViolation}) \in \mathcal{D} \\
(M, M) \in \mathcal{E}_{\text{mod}}^+ &\implies \text{Diagnostic}(\text{span}(M), \text{DiagnosticCode::E0102}, \text{ModuleContainmentCycle}) \in \mathcal{D} \\
\text{IsUnsupportedType}(T) &\implies \text{Diagnostic}(\text{span}(T), \text{DiagnosticCode::E0103}, \text{UnsupportedPrimitiveDataType}) \in \mathcal{D} \\
\text{DiscriminantMismatch}(U, D, C) &\implies \text{Diagnostic}(\text{span}(C), \text{DiagnosticCode::E0103}, \text{UnionDiscriminantTypeMismatch}) \in \mathcal{D}
\end{aligned}
$$

Diagnostic Taxonomy Containment Invariant: All emitted diagnostics strictly belong to the Subsystem 2 ingestion family:

$$
\forall D \in \mathcal{D}_{\text{idl}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0103} \} \subset \mathcal{E}_{\text{ingest}}
$$

- **Computational Complexity & Algorithmic Bounds**: The OMG IDL AST ingestion engine executes within Complexity Class $\mathbf{P}$. Lexical analysis and tokenization operate via a deterministic finite automaton (DFA) scanning the input byte buffer of size $N$ bytes monotonically without lookbehind or backtracking, executing in deterministic $O(N)$ linear time. The IDL grammar subset is an LL(1) deterministic grammar with bounded lookahead $k \le 2$ tokens (used to disambiguate scoped identifiers `A::B` and distinguish attribute declarations from operation declarations). Parsing via recursive descent visits each lexical token $t_j \in \mathcal{T}$ ($1 \le j \le T$, with $T \le N$) at most a constant number of times without backtracking, achieving deterministic $O(T) = O(N)$ linear time:

$$
O(N) = O\left( \sum_{j=1}^{T} |t_j| \right)
$$

Symbol interning of identifier tokens operates in $O(L)$ time where identifier length $L \le L_{\text{max}} = 256$, achieving $O(1)$ amortized time per identifier using a preallocated symbol table. Allocating synthesized AST nodes into the contiguous typed bump arena requires a single pointer bump operation, executing in strict $O(1)$ constant time per node. Parameter partitioning for an operation containing $m$ parameters ($m \le 256$) executes in $O(m) = O(1)$ constant time per operation, and $O(T) = O(N)$ total time across all operations in the compilation unit. Module containment hierarchy validation executes in $O(D) = O(1)$ time per module where maximum nesting depth $D \le 32$. When ingesting $K$ distinct IDL files across $N_{\text{max\_workers}}$ threads in a bounded work-stealing thread pool, parallel wall-clock runtime is bounded by $O(\lceil K / N_{\text{max\_workers}} \rceil \cdot N_{\text{max}})$. Total single-file parsing time is strictly bounded by $O(N)$ deterministic linear time in input byte size $N$. Call stack depth for recursive descent is strictly bounded by the maximum syntactic nesting depth $D_{\text{max}} \le 64$, requiring $O(D_{\text{max}}) = O(1)$ auxiliary stack space. Total auxiliary space complexity is strictly bounded by $O(N)$ for node arena allocations with zero unbounded dynamic heap allocations.

- **Verification & Conformance Criteria**: Automated verification suites shall assert 100% parsing fidelity and intermediate IR lowering accuracy across synthetic OMG IDL specifications containing abstract MBSE entities (e.g., `Package_0`, `Module_Alpha`, `Interface_Beta`, `Struct_Gamma`, `Union_Delta`, `op_omega`, `param_x : Real`). Conformance shall be validated through the following deterministic test gates:
  1. Struct Lowering Gate: Ingest an IDL struct declaration (`struct Struct_Alpha { long field_1; double field_2; boolean flag_3; };`); assert that the parser generates an `IngestedClassifierDef` node with `kind = Struct`, three owned `IngestedAttr` properties with matching scalar types, and allocations in the bump arena with stable offsets.
  2. Union Lowering Gate: Ingest an IDL union declaration (`union Union_Beta switch (short) { case 1: long val_int; case 2: double val_real; default: boolean val_bool; };`); assert that the parser lowers it into an `IngestedClassifierDef` with `kind = Union`, binds discriminant type `short`, and constructs 3 branch cases including the default branch.
  3. Interface and Operation Lowering Gate: Ingest an IDL interface declaration (`interface Interface_Gamma { void op_step(in Real p_in, out Real p_out, inout Real p_state); };`); assert that the parser lowers the interface into an `IngestedPart` with `is_interface: true`, and lowers `op_step` into an `IngestedAction` node.
  4. Directional Parameter Partitioning Gate: Verify that `in Real p_in` is partitioned into `inputs`, `out Real p_out` is partitioned into `outputs`, and `inout Real p_state` is partitioned into both `inputs` and `outputs` (and `inouts`). Verify that a non-void operation (`long op_calc(in long x);`) synthesizes a return output parameter `result : long` in `outputs`.
  5. Missing or Invalid Direction Gate: Ingest an IDL operation declaration omitting the directional token (e.g., `void op_bad(Real p_missing);` or `void op_bad2(input Real p_bad);`); assert that the parser emits a structured diagnostic record binding error code `E0102` with precise byte coordinates, logs `MissingOrInvalidParameterDirection`, substitutes sentinel $\bot_{\text{idl}}$, and continues parsing.
  6. Module Containment and Scoping Gate: Ingest deeply nested IDL modules (`module Module_0 { module SubModule_1 { interface Interface_A {}; }; };`); assert that the parser constructs nested `IngestedPackage` namespaces and that all contained elements receive correct fully qualified paths (`Module_0::SubModule_1::Interface_A`).
  7. Sequence and Fixed Array Multiplicity Gate: Ingest IDL declarations containing bounded sequences (`sequence<Real, 10>`), unbounded sequences (`sequence<Real>`), and fixed arrays (`Real arr[8]`); assert that the type lowerer binds multiplicity intervals $\langle 0, 10 \rangle$, $\langle 0, \infty \rangle$, and $\langle 8, 8 \rangle$ respectively.
  8. Synchronization Token Error Recovery Gate: Ingest an IDL file containing deliberate syntax errors (e.g., missing semicolons, unmatched braces, malformed parameter lists) on specific lines; assert that the parser emits `E0102` diagnostics, resynchronizes at delimiter tokens ($\text{SYM}_{\text{SEMI}}$ `;`, $\text{SYM}_{\text{RBRACE}}$ `}`), and successfully extracts all subsequent valid interfaces, structs, and operations.
  9. Total Non-Panicking Contract Gate: Execute fuzz testing with 100,000 malformed, truncated, and randomized IDL inputs; assert 100% total-function completion with structured diagnostic error generation and zero panics or unhandled exceptions.
  10. Release Mode Latency Gate: Measure ingestion throughput and latency strictly in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests, asserting throughput exceeding $10^5$ tokens/s and execution latency within the 25 ms budget for standard IDL schemas.
  11. Bitwise Determinism Gate: Verify 0-byte diff churn across repeated compilations of IDL specifications on multi-threaded and single-threaded configurations, asserting byte-identical AST serialization.
