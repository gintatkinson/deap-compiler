### REQ-0137: Automated Boolean Safety Invariant Synthesis from Hazard Scenarios

- **Normative Statement**: The safety compiler, formal hazard analysis engine, and invariant synthesis pipeline of Subsystem 7 shall automatically synthesize formal Boolean safety invariants from identified unsafe control action scenarios and confirmed hazardous system states by generating the logical negation of hazardous state conditions as invariant predicates over the system state vector, verifying their satisfiability and mutual consistency, lowering them into strongly-typed SysML v2 / KerML constraint expressions, and establishing bidirectional traceability across the verification graph.

  Specifically, the safety compiler, invariant synthesis engine, and formal verification framework shall strictly enforce the following structural, algebraic, and operational invariants:
  1. **System State Vector Formulation ($`\mathbf{x}`$)**:
     - The compiler shall construct the system state vector $`\mathbf{x} = \langle x_1, x_2, \dots, x_k \rangle`$ spanning all continuous state variables, discrete operational modes, port flow values, and control action execution statuses defined across the AST model.
     - Each state variable $`x_j`$` (`$`1 \le j \le k`$`) shall bind an explicit, strongly-typed domain `$`D_j`$` (such as boolean truth values `$`\mathbb{B} = \{ \text{true}, \text{false} \}`$`, finite enumeration sets `$`\mathcal{E}`$`, bounded integer intervals `$`[a, b] \subset \mathbb{Z}`$`, or bounded real operational envelopes `$`[v_{\min}, v_{\max}] \subset \mathbb{R}`$` in the `$`\mathbb{Q}^7`$ rational metric space per REQ-0098).
     - If any hazard scenario or safety rule references an undefined, unresolvable, or out-of-scope state variable $`x \notin \mathbf{x}`$, the compiler shall reject the compilation unit at compile time with diagnostic error code `E0400` (`UndefinedStateVariable`).
  2. **Hazard Scenario Condition Formulation ($`H(\mathbf{x})`$)**:
     - The compiler shall formalize each identified hazard scenario $`H_i \in \mathcal{H}`$` (`$`1 \le i \le m`$`) as a computable Boolean condition `$`H_i(\mathbf{x}) \in \mathbb{B}`$` over system state vector `$`\mathbf{x}`$, characterizing the exact state-space region wherein safe operational boundaries are breached.
     - Hazard conditions shall be derived from pruned Unsafe Control Actions (UCAs) generated in REQ-0136 ($`u \in \mathcal{U}_{\text{pruned}} \subseteq A \times G \times S_{\text{context}}`$) or minimal hazard cut-sets computed in REQ-0135 (NP-4).
     - Each hazard condition $`H_i(\mathbf{x})`$ shall be expressed as a well-formed propositional predicate over atomic relational constraints (e.g., equality, inequality, set membership, or discrete mode occupancy).
     - If a declared hazard scenario contains an unparseable, malformed, or untyped condition expression, the compiler shall deterministically reject the declaration with diagnostic error code `E0400` (`MalformedHazardCondition`).
  3. **Automated Boolean Safety Invariant Synthesis ($`\mathcal{I}_{\text{safe}}(\mathbf{x})`$)**:
     - For each identified hazard scenario $`H_i(\mathbf{x})`$`, the safety compiler shall synthesize a corresponding Boolean safety invariant `$`\mathcal{I}_{\text{safe}, i}(\mathbf{x})`$ defined as the strict logical negation of the hazardous state condition:

```math
       \mathcal{I}_{\text{safe}, i}(\mathbf{x}) \equiv \neg H_i(\mathbf{x})
```

     - Context-Guarded Invariant Synthesis: If a hazard scenario $`H_i`$` is active exclusively within a specific operational context or lifecycle mode characterized by guard condition `$`C_i(\mathbf{x})`$, the compiler shall synthesize the context-guarded invariant as a logical implication:

```math
       \mathcal{I}_{\text{safe}, i}^{\text{context}}(\mathbf{x}) \equiv C_i(\mathbf{x}) \implies \neg H_i(\mathbf{x}) \equiv \neg C_i(\mathbf{x}) \lor \neg H_i(\mathbf{x})
```

     - System-Wide Composite Safety Invariant ($`\mathcal{I}_{\text{system}}(\mathbf{x})`$): The compiler shall synthesize the global composite safety invariant as the conjunction of all individual synthesized invariants:

```math
       \mathcal{I}_{\text{system}}(\mathbf{x}) = \bigwedge_{i=1}^m \mathcal{I}_{\text{safe}, i}(\mathbf{x}) \equiv \neg \left( \bigvee_{i=1}^m H_i(\mathbf{x}) \right)
```

     - Complementary Safe State-Space Region ($`\mathcal{S}_{\text{safe}}`$`): The invariant defines the certified safe operational envelope `$`\mathcal{S}_{\text{safe}} = \{ \mathbf{x} \in \mathbf{X} \mid \mathcal{I}_{\text{system}}(\mathbf{x}) = \text{true} \}`$`, representing the exact set-theoretic complement of the hazardous state regions: `$`\mathcal{S}_{\text{safe}} = \mathbf{X} \setminus \bigcup_{i=1}^m \mathcal{S}_{\text{hazard}, i}`$.
  4. **Satisfiability, Consistency & Triviality Verification**:
     - The compiler shall verify the logical satisfiability and non-vacuity of every synthesized safety invariant prior to AST emission:
       - Unsatisfiable Safety Invariant Detection (`E0400`): If a hazard condition is universally valid across the state domain ($`H_i(\mathbf{x}) \equiv \text{true}`$`), its negation yields an identically false invariant (`$`\mathcal{I}_{\text{safe}, i}(\mathbf{x}) \equiv \text{false}`$), indicating that no safe state exists. The compiler shall deterministically reject compilation with diagnostic error code `E0400` (`UnsatisfiableSafetyInvariant`).
       - Tautological / Vacuous Invariant Pruning: If a hazard condition is provably unreachable or unsatisfiable ($`H_i(\mathbf{x}) \equiv \text{false}`$`), its synthesized invariant is a tautology (`$`\mathcal{I}_{\text{safe}, i}(\mathbf{x}) \equiv \text{true}`$). The compiler shall flag the vacuous condition and safely prune it from the composite conjunction.
       - Contradictory Safety Invariant Detection (`E0400`): If two or more synthesized invariants are mutually exclusive ($`\exists i, j : \mathcal{I}_{\text{safe}, i}(\mathbf{x}) \land \mathcal{I}_{\text{safe}, j}(\mathbf{x}) \equiv \text{false}`$), simultaneous satisfaction is impossible. The compiler shall detect the conflict and emit diagnostic error code `E0400` (`ContradictorySafetyInvariants`).
       - Step-Bounded Invariant Checking: Formal satisfiability checks shall execute under a deterministic step budget $`\kappa_{\text{safety}}`$` (defaulting to `$`10^5`$` steps). If decision steps exceed the cutoff (`$`N_{\text{step}} \gt \kappa_{\text{safety}}`$), compilation shall fail deterministically with diagnostic error code `E0406` (`SafetySolverStepLimitExceeded`).
  5. **SysML v2 / KerML AST Lowering & CNF Preparation**:
     - The compiler shall lower every synthesized invariant into an explicit SysML v2 `AssertConstraintUsage` (REQ-0084) or KerML `ConstraintDefinition` (REQ-0083) AST node instantiated within contiguous bump arena memory.
     - The synthesized AST node shall retain the unreduced predicate structure to serve as the direct input to the De Morgan normalization engine (REQ-0138), which transforms expressions into canonical Conjunctive Normal Form (CNF).
  6. **Bidirectional Traceability & Regulatory DAG Binding**:
     - The compiler shall construct bidirectional traceability edges in the 7-tier traceability DAG (REQ-0128) linking each synthesized safety invariant $`\mathcal{I}_{\text{safe}, i}`$ to:
       - Its causal hazard scenario $`H_i \in \mathcal{H}`$;
       - Contributing unsafe control actions $`u \in \mathcal{U}_{\text{pruned}}`$ (REQ-0136);
       - Upstream system safety requirements (REQ-0085, REQ-0129);
       - Downstream verification cases and runtime monitors (REQ-0087, REQ-0141).
  7. **The 5 Executive Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every synthesized safety invariant node, composite invariant expression, and traceability relation shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and invariant fully qualified path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(H_i) \mathbin{\Vert} \text{"::SafeInvariant"}))`$ in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel synthesis and consistency verification of safety invariants across decoupled subsystem packages shall execute strictly on a centralized, bounded work-stealing worker pool ($`P_{\text{workers}} \le \min(C_{\text{logical}}, N_{\text{max\_workers}})`$) in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Invariant names, state variable tokens, predicate symbols, and fully qualified path strings shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The safety compiler shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When invariant synthesis violations occur (`E0400`) or solver step limits are exceeded (`E0406`), diagnostics shall accumulate in the error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{inv}}`$`), and continue validating subsequent safety rules. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The invariant synthesis engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Invariant synthesis latency ($`\lt 25\text{ ms}`$` for `$`10^4`$` hazard conditions) and peak RSS memory (`$`\lt 100\text{ MB}`$) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Controller_0`, `Process_0`, `Hazard_0`, `Hazard_1`, `Invariant_0`, `Invariant_1`, `Port_1`, `Flow_A`, `param_x : Real`, `State_0`, `State_1`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage, and let `$`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.

  The automated Boolean safety invariant synthesis system is formalized as an 8-tuple:

```math
  \mathcal{M}_{\text{inv}} = \langle \mathbf{X}, \mathcal{H}, \mathcal{U}_{\text{pruned}}, \mathcal{I}_{\text{safe}}, \mathcal{I}_{\text{system}}, \mathcal{S}_{\text{safe}}, \Delta_{\text{inv}}, \kappa_{\text{safety}} \rangle
```

  where:

```math
  \begin{aligned}
  \mathbf{X} &= \prod_{j=1}^k D_j \quad (\text{Cartesian system state space over } k \text{ state variables}) \\
  \mathcal{H} &= \{ H_1, H_2, \dots, H_m \} \subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of identified hazard scenarios}) \\
  \mathcal{U}_{\text{pruned}} &\subseteq A \times G \times S_{\text{context}} \quad (\text{set of pruned unsafe control actions from REQ-0136}) \\
  \mathcal{I}_{\text{safe}} &: \mathcal{H} \to \mathcal{V}_{\text{AST}} \quad (\text{mapping from hazards to synthesized safety invariant AST nodes}) \\
  \mathcal{I}_{\text{system}} &\in \mathcal{V}_{\text{AST}} \quad (\text{composite system-wide safety invariant AST node}) \\
  \mathcal{S}_{\text{safe}} &\subseteq \mathbf{X} \quad (\text{certified safe operational state-space region}) \\
  \Delta_{\text{inv}} &: \mathcal{H} \to \Sigma^{36} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor mapping}) \\
  \kappa_{\text{safety}} &\in \mathbb{N}_{\ge 1} \quad (\text{deterministic safety solver decision step budget})
  \end{aligned}
```

  1. State Space & Variable Typing Invariant:
  Each system state vector $`\mathbf{x} \in \mathbf{X}`$` is a `$`k`$-tuple of strongly typed valuations:

```math
  \mathbf{x} = \langle x_1, x_2, \dots, x_k \rangle \in \prod_{j=1}^k D_j
```

  where each domain $`D_j`$ satisfies:

```math
  D_j \in \{ \mathbb{B}, \, \mathcal{E}_j, \, [a_j, b_j] \subset \mathbb{Z}, \, [v_{j,\min}, v_{j,\max}] \subset \mathbb{R} \}
```

  2. Hazard Scenario Predicate Invariant:
  Each hazard scenario $`H_i \in \mathcal{H}`$` defines a computable Boolean characteristic function `$`H_i : \mathbf{X} \to \mathbb{B}`$ with hazardous state-space region:

```math
  \mathcal{S}_{\text{hazard}, i} = \{ \mathbf{x} \in \mathbf{X} \mid H_i(\mathbf{x}) = \text{true} \}
```

  3. Automated Boolean Invariant Synthesis Invariant:
  For each hazard scenario $`H_i \in \mathcal{H}`$`, the synthesized invariant predicate `$`\mathcal{I}_{\text{safe}, i}(\mathbf{x})`$ satisfies the exact logical negation identity:

```math
  \forall \mathbf{x} \in \mathbf{X}, \quad \mathcal{I}_{\text{safe}, i}(\mathbf{x}) \equiv \neg H_i(\mathbf{x})
```

  4. Context-Guarded Invariant Invariant:
  For a hazard scenario $`H_i`$` conditioned on operational context guard predicate `$`C_i : \mathbf{X} \to \mathbb{B}`$, the synthesized context-guarded invariant satisfies:

```math
  \forall \mathbf{x} \in \mathbf{X}, \quad \mathcal{I}_{\text{safe}, i}^{\text{context}}(\mathbf{x}) \equiv \left( C_i(\mathbf{x}) \implies \neg H_i(\mathbf{x}) \right) \equiv \left( \neg C_i(\mathbf{x}) \lor \neg H_i(\mathbf{x}) \right)
```

  5. System-Wide Composite Safety Invariant Invariant:
  The global composite safety invariant $`\mathcal{I}_{\text{system}}(\mathbf{x})`$` is the strict conjunction of all `$`m`$ synthesized safety invariants:

```math
  \forall \mathbf{x} \in \mathbf{X}, \quad \mathcal{I}_{\text{system}}(\mathbf{x}) = \bigwedge_{i=1}^m \mathcal{I}_{\text{safe}, i}(\mathbf{x}) = \bigwedge_{i=1}^m \neg H_i(\mathbf{x}) \equiv \neg \left( \bigvee_{i=1}^m H_i(\mathbf{x}) \right)
```

  6. Set-Theoretic Safe Operational Envelope Complementarity:
  The certified safe state-space region $`\mathcal{S}_{\text{safe}}`$ satisfies strict set-theoretic complementarity against the union of all hazardous regions:

```math
  \mathcal{S}_{\text{safe}} = \{ \mathbf{x} \in \mathbf{X} \mid \mathcal{I}_{\text{system}}(\mathbf{x}) = \text{true} \} = \mathbf{X} \setminus \bigcup_{i=1}^m \mathcal{S}_{\text{hazard}, i}
```

  7. Non-Emptiness & Global Satisfiability Invariant:
  Safe operation is feasible if and only if the safe state-space region is non-empty:

```math
  \mathcal{S}_{\text{safe}} \ne \emptyset \iff \exists \mathbf{x} \in \mathbf{X} : \mathcal{I}_{\text{system}}(\mathbf{x}) = \text{true}
```

  8. Pairwise Consistency Invariant:
  Every pair of distinct synthesized safety invariants $`\mathcal{I}_{\text{safe}, i}`$` and `$`\mathcal{I}_{\text{safe}, j}`$` (`$`i \ne j`$) must be jointly satisfiable:

```math
  \forall i \ne j, \quad \exists \mathbf{x} \in \mathbf{X} : \mathcal{I}_{\text{safe}, i}(\mathbf{x}) \land \mathcal{I}_{\text{safe}, j}(\mathbf{x}) = \text{true}
```

  9. SysML v2 AST Node Instantiation Invariant:
  Each synthesized invariant $`\mathcal{I}_{\text{safe}, i}`$ is instantiated as a typed AST node:

```math
  \text{AST}(\mathcal{I}_{\text{safe}, i}) = \langle \text{id}_i, \text{name}_i, \text{negate}(\text{expr}(H_i)), \Delta_{\text{inv}}(H_i), \text{span}_i \rangle \in \mathcal{V}_{\text{AST}}
```

  where $`\text{negate} : \mathcal{V}_{\text{AST}} \to \mathcal{V}_{\text{AST}}`$ constructs the negated expression tree without altering subexpression semantics.

  10. Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
  \begin{aligned}
  \forall H_i \in \mathcal{H}, &\quad \Delta_{\text{inv}}(H_i) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(H_i) \mathbin{\Vert} \text{"::SafeInvariant"}) \\
  \Delta_{\text{system}} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\text{"SystemSafetyInvariant"}))

```

  11. Deterministic Diagnostic Trigger Rules (REQ-0191):

```math
  \begin{aligned}
  \exists H_i \in \mathcal{H} : (\forall \mathbf{x} \in \mathbf{X}, \, H_i(\mathbf{x}) \equiv \text{true}) &\implies \text{Diagnostic}(H_i, \text{DiagnosticCode::E0400}, \text{UnsatisfiableSafetyInvariant}) \in \mathcal{D}_{\text{sink}} \\

  \end{aligned}
```

- **Computational Complexity & Algorithmic Bounds**: Automated Boolean Safety Invariant Synthesis from Hazard Scenarios resides strictly in **Complexity Class P** (Deterministic Polynomial Time) for syntactic negation, expression AST generation, and composite invariant conjunction. Formal satisfiability and contradiction verification across arbitrary propositional or linear arithmetic theories is delineated under **Algorithmic Bound NP-8** (REQ-0197) and **Algorithmic Bound NP-4** (REQ-0135).

  **Mathematical Delineation from Other Algorithmic Frontiers**:
  - *Delineation from NP-8 (REQ-0197)*: NP-8 governs formal proof obligation generation and satisfiability modulo theories (SMT) solving across decidable quantifier-free first-order fragments (QF_LRA, QF_LIA, QF_UF) via DPLL(T), which is NP-complete. In contrast, REQ-0137 performs deterministic syntactic and structural AST synthesis ($`\neg H_i(\mathbf{x})`$` and `$`\bigwedge \mathcal{I}_i`$`). When semantic consistency checking is invoked, REQ-0137 enforces an explicit step budget `$`\kappa_{\text{safety}}`$ with error code `E0406`, bounding execution steps and preventing exponential solver stagnation.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 solves the minimal hitting set problem over hazard cut-sets, which is NP-complete. In contrast, REQ-0137 takes the identified hazards and unsafe control actions and synthesizes the exact Boolean dual invariants without combinatorial minimization.
  - *Delineation from NP-1 (REQ-0117)*: NP-1 addresses qualitative temporal interval consistency under Allen's interval algebra. In contrast, REQ-0137 synthesizes static propositional and state-space invariant predicates over system state vectors.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 solves PSPACE-complete reachability across orthogonal discrete state machines. In contrast, REQ-0137 evaluates invariant formulas directly over declared state spaces without state-space graph exploration.

  **Asymptotic Complexity Analysis**:
  Let $`m = |\mathcal{H}|`$` denote the number of hazard scenarios, `$`k = |\mathbf{x}|`$` denote the number of state variables in the system state vector, and let `$`N_{\text{nodes}} = \sum_{i=1}^m |H_i|`$ denote the aggregate number of AST expression nodes across all hazard conditions.
  1. *State Vector Indexing & Scope Verification*:
     Constructing the state variable symbol table and verifying that all referenced variables $`x \in \text{Vars}(H_i)`$` belong to `$`\mathbf{x}`$ requires scanning variable declarations and hazard AST leaves:

```math
     T_{\text{scope}}(k, N_{\text{nodes}}) \in O(k + N_{\text{nodes}})
```

  2. *Syntactic Negation & AST Allocation*:
     For each hazard condition $`H_i`$`, wrapping the expression root in a logical negation node (`$`\neg`$) and allocating the corresponding `AssertConstraintUsage` AST node in contiguous bump arena memory takes $`O(1)`$ pointer operations per hazard:

```math
     T_{\text{negate}}(m) \in O(m)
```

  3. *Context Guard Implication Synthesis*:
     Synthesizing the context-guarded invariant $`C_i(\mathbf{x}) \implies \neg H_i(\mathbf{x})`$` requires allocating a binary implication node, executing in `$`O(1)`$ operations per guarded hazard:

```math
     T_{\text{guard}}(m) \in O(m)
```

  4. *Composite Conjunction Construction*:
     Assembling the system-wide composite invariant $`\mathcal{I}_{\text{system}} = \bigwedge_{i=1}^m \mathcal{I}_{\text{safe}, i}`$ as a balanced binary or multi-ary conjunction AST tree requires:

```math
     T_{\text{conj}}(m) \in O(m)
```

  5. *Step-Bounded Consistency & Satisfiability Verification*:
     Evaluating triviality ($`H_i \equiv \text{true}`$` or `$`H_i \equiv \text{false}`$`) and pairwise consistency under step cutoff `$`\kappa_{\text{safety}}`$ takes:

```math
     T_{\text{verify}}(m, \kappa_{\text{safety}}) \in O(m \cdot \kappa_{\text{safety}})
```

     If $`N_{\text{step}} \gt \kappa_{\text{safety}}`$`, execution terminates deterministically in `$`O(1)`$ operations with diagnostic `E0406`.
  6. *Aggregate Worst-Case Time Complexity*:
     Summing indexing, negation, conjunction, and bounded verification passes:

```math
     T_{\text{total}}(m, k, N_{\text{nodes}}, \kappa_{\text{safety}}) \in O(k + N_{\text{nodes}} + m \cdot \kappa_{\text{safety}})
```

     In standard compilation mode where semantic checking utilizes cached valuations or syntactic normal forms, invariant synthesis executes in deterministic linear time $`O(k + N_{\text{nodes}})`$, without backtracking or branching.
  7. *Parallel Work-Stealing Scaling (Directive 2)*:
     When synthesizing invariants across $`M`$` independent packages on a bounded work-stealing thread pool with worker bound `$`N_{\text{max\_workers}}`$:

```math
     T_{\text{parallel}}(m, k, N_{\text{nodes}}, N_{\text{max\_workers}}) \in O\left( \frac{k + N_{\text{nodes}} + m \cdot \kappa_{\text{safety}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  8. *Space Complexity & Arena Memory Bounds*:
     Synthesized invariant nodes, negation operators, and conjunction trees reside in contiguous bump arena memory, consuming $`O(m + N_{\text{nodes}})`$` bytes. Interned symbol identifiers require `$`O(k + m)`$` bytes in the global symbol pool. The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ capacity.
