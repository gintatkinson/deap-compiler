### REQ-0157: Protocol Framing Overhead Calculation & Header Serialization Penalty

- **Normative Statement**: The Level 1C Interface Control Document (ICD) generation engine, protocol analysis framework, and interconnect serialization synthesizer of Subsystem 8 shall calculate protocol framing overheads, encapsulation bit costs, and header serialization penalties across heterogeneous transport protocol profiles. For every declared communication connection and signal flow in the Master Signal Flow Dictionary, the engine shall compute exact total frame lengths, framing efficiency metrics, channel transmission occupancy durations, and worst-case bit-stuffing and padding penalties, asserting that framing overheads remain within allocated channel capacity budgets without compiler-dependent framing ambiguity.

  Specifically, the ICD framing overhead calculation engine and serialization contract verifier shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Canonical Transport Protocol Profile Representation**:
     - The compiler shall model all interconnect communication protocols as abstract parameterized transport profiles $`\Pi \in \mathcal{P}_{\text{transport}}`$.
     - Each transport protocol profile $`\Pi`$ shall specify bit-exact structural framing parameters:
       - Preamble and synchronization word bit length: $`L_{\text{preamble}} \in \mathbb{N}_0`$.
       - Protocol header bit length: $`L_{\text{header}} \in \mathbb{N}_0`$.
       - Protocol trailer and postamble bit length: $`L_{\text{trailer}} \in \mathbb{N}_0`$.
       - Frame check sequence (FCS) / Cyclic Redundancy Check (CRC) bit length: $`L_{\text{crc}} \in \mathbb{N}_0`$.
       - Inter-frame gap (IFG) or line quiet spacing bit length: $`L_{\text{ifg}} \in \mathbb{N}_0`$.
       - Minimum allowable payload bit length: $`L_{\text{payload\_min}} \in \mathbb{N}_0`$.
       - Maximum Transmission Unit (MTU) payload bit length: $`L_{\text{mtu}} \in \mathbb{N}^+`$.
       - Frame boundary bit alignment constraint: $`\text{Align}_{\text{frame}} \in \{1, 8, 16, 32, 64\}`$ bits.
       - Worst-case bit-stuffing rule configuration: $`\Sigma_{\text{stuffing}}`$.
       - Channel nominal bus transmission bit rate: $`R_{\text{bus}} \in \mathbb{Q}^+`$` (bits per second, `$`R_{\text{bus}} \gt 0`$).
       - Segmentation / fragmentation enablement flag: $`\Pi_{\text{fragment}} \in \{ \text{true}, \text{false} \}`$.
     - If a protocol profile specifies a non-positive transmission bus rate ($`R_{\text{bus}} \le 0`$), the compiler shall deterministically fail closed and emit diagnostic error code `E0500` (`NonPositiveBusRate`).
     - If a protocol profile specifies an alignment constraint that is not in $`\{1, 8, 16, 32, 64\}`$ bits, the compiler shall emit diagnostic error code `E0500` (`InvalidFramingAlignment`).
  2. **Total Frame Length & Component Overhead Synthesis**:
     - For every serialized payload associated with connection $`C`$` or signal flow `$`\sigma`$` having payload bit length `$`L_{\text{payload}} = \text{TotalBits}(\Lambda_{\text{layout}})`$` derived from the binary wire layout (REQ-0150), the engine shall compute the total transmitted frame length `$`L_{\text{frame}}`$` under profile `$`\Pi`$:

```math
L_{\text{frame}} = L_{\text{fixed}} + L_{\text{payload}} + \Delta_{\text{padding}}(L_{\text{payload}}, \Pi) + \Delta_{\text{stuffing}}(L_{\text{payload}}, \Pi)
```

       where fixed protocol framing overhead is:

```math
L_{\text{fixed}} = L_{\text{preamble}} + L_{\text{header}} + L_{\text{trailer}} + L_{\text{crc}} + L_{\text{ifg}}
```

     - *Alignment and Minimum Payload Padding Penalty $`\Delta_{\text{padding}}`$*:
       - If payload bit length falls below the minimum payload requirement ($`L_{\text{payload}} \lt L_{\text{payload\_min}}`$), the synthesizer shall calculate explicit zero-padding bits to reach the minimum payload threshold:

```math
\Delta_{\text{min\_pad}} = L_{\text{payload\_min}} - L_{\text{payload}}
```

       - The synthesizer shall compute frame boundary alignment padding $`\Delta_{\text{align\_pad}}`$` such that the complete on-wire packet satisfies `$`\text{Align}_{\text{frame}}`$ modular divisibility:

```math
\Delta_{\text{align\_pad}} = (\text{Align}_{\text{frame}} - ((L_{\text{fixed}} + L_{\text{payload}} + \Delta_{\text{min\_pad}}) \pmod{\text{Align}_{\text{frame}}})) \pmod{\text{Align}_{\text{frame}}}
```

       - The aggregate padding penalty is the sum: $`\Delta_{\text{padding}} = \Delta_{\text{min\_pad}} + \Delta_{\text{align\_pad}}`$.
     - *Worst-Case Bit-Stuffing Penalty $`\Delta_{\text{stuffing}}`$*:
       - For protocol profiles employing run-length bit-stuffing with consecutive identical bit threshold $`k_{\text{stuff}} \ge 2`$, the synthesizer shall calculate the deterministic worst-case stuffing bit insertions over the stuffed frame segment:

```math
\Delta_{\text{stuffing}} = \left\lfloor \frac{L_{\text{stuffed\_segment}} - 1}{k_{\text{stuff}} - 1} \right\rfloor
```

         where $`L_{\text{stuffed\_segment}} = L_{\text{header}} + L_{\text{payload}} + \Delta_{\text{padding}} + L_{\text{crc}}`$.
       - For byte-oriented or unstuffed profiles ($`\Sigma_{\text{stuffing}} = \text{None}`$`), `$`\Delta_{\text{stuffing}} = 0`$.
  3. **Framing Efficiency & Serialization Penalty Metrics**:
     - The engine shall compute the dimensionless framing efficiency $`\eta_{\text{framing}}`$ representing the proportion of useful payload information relative to total on-wire bits:

```math
\eta_{\text{framing}} = \frac{L_{\text{payload}}}{L_{\text{frame}}} \in (0, 1]
```

     - The engine shall compute the header serialization penalty $`\Pi_{\text{penalty}}`$ expressing the non-payload framing overhead relative to useful payload:

```math
\Pi_{\text{penalty}} = \frac{L_{\text{frame}} - L_{\text{payload}}}{L_{\text{payload}}} = \frac{1}{\eta_{\text{framing}}} - 1
```

     - If a protocol profile or signal contract establishes a minimum framing efficiency threshold $`\eta_{\text{min}} \in (0, 1]`$` and `$`\eta_{\text{framing}} \lt \eta_{\text{min}}`$, the compiler shall emit diagnostic error code `E0500` (`FramingEfficiencyBelowThreshold`).
  4. **Channel Transmission Occupancy Duration & Duty Cycle**:
     - The engine shall compute exact transmission occupancy duration $`\tau_{\text{occupancy}}`$` over channel nominal bit rate `$`R_{\text{bus}}`$:

```math
\tau_{\text{occupancy}} = \frac{L_{\text{frame}}}{R_{\text{bus}}}
```

       represented as an exact rational number in seconds ($`\mathbb{Q}^+`$) to prevent numerical rounding drift across end-to-end timing analyses.
     - For periodic signal flows with transmission period $`T_{\text{period}} \in \mathbb{Q}^+`$, the engine shall compute the frame channel occupancy duty cycle:

```math
\rho_{\text{occupancy}} = \frac{\tau_{\text{occupancy}}}{T_{\text{period}}}
```

       providing this value to REQ-0154 for aggregate channel capacity verification and to REQ-0155 / REQ-0156 for schedulability analysis.
  5. **Payload Segmentation & Fragmentation Processing**:
     - When payload bit length exceeds the Maximum Transmission Unit ($`L_{\text{payload}} \gt L_{\text{mtu}}`$):
       - If fragmentation is disabled ($`\Pi_{\text{fragment}} = \text{false}`$), the compiler shall fail closed and emit diagnostic error code `E0500` (`PayloadExceedsMTU`), detailing the excess bit count ($`L_{\text{payload}} - L_{\text{mtu}}`$), connection handle, and profile identifier.
       - If fragmentation is enabled ($`\Pi_{\text{fragment}} = \text{true}`$`), the engine shall decompose the payload into `$`N_{\text{fragments}} = \lceil L_{\text{payload}} / L_{\text{mtu}} \rceil`$` discrete fragment frames. The engine shall compute individual framing overheads, padding, and bit-stuffing for each fragment `$`j \in \{1, \dots, N_{\text{fragments}}\}`$, accumulating aggregate wire occupancy:

```math
L_{\text{total\_frames}} = \sum_{j=1}^{N_{\text{fragments}}} L_{\text{frame}}(L_{\text{payload}}^{(j)}, \Pi)
```

         and recomputing aggregate framing efficiency over the multi-frame sequence.
  6. **Contiguous Memory Bump Arena Storage & Node Handles**:
     - All protocol profiles, framing calculation descriptors, segmentation records, and transmission occupancy witnesses shall be allocated sequentially in contiguous bump arena storage in accordance with REQ-0009 and REQ-0034, referenced by stable 32-bit arena node handles in accordance with REQ-0035.
  7. **Diagnostic Emission & Synchronization Token Recovery**:
     - The ICD framing calculation engine shall implement synchronization token error recovery on statement delimiters (`;`) and table row delimiters (`|`) in accordance with REQ-0013 and REQ-0016.
     - Upon encountering framing violations (`E0500`), the engine shall record structured diagnostics into the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{framing}}`$), and continue validating subsequent signal and connection declarations.
     - If accumulated diagnostics reach capacity limit $`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
  8. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every transport protocol profile, framing calculation record, fragmentation descriptor, and occupancy witness shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and the node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010. Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel extraction, framing overhead calculation, and occupancy duration evaluation across independent transport channels and signal catalogs shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Protocol profile names, transport layer labels, signal identifiers, and framing field names shall be interned into the deduplicated global symbol interner pool during initial lexical analysis in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The engine shall recover on statement delimiters (`;`) and record delimiters (`|`), accumulating diagnostics in $`\mathcal{D}_{\text{sink}}`$ without premature process abortion, halting with `E0199` only upon reaching capacity limit $`C_{\text{max\_errors}}`$ in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The protocol framing calculation engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Calculation latency (strictly under 25 ms for $`|F| = 10^4`$ signal flows) and peak RSS memory (strictly under 100 MB) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

```math

```

  where:

```math
  \begin{aligned}
  \text{id}_{\Pi} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
  \text{name}_{\Pi} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned protocol symbol identifier}) \\
  L_{\text{preamble}} &\in \mathbb{N}_0 \quad (\text{preamble and synchronization word bit length}) \\
  L_{\text{header}} &\in \mathbb{N}_0 \quad (\text{protocol header bit length}) \\
  L_{\text{trailer}} &\in \mathbb{N}_0 \quad (\text{protocol trailer and postamble bit length}) \\
  L_{\text{crc}} &\in \mathbb{N}_0 \quad (\text{frame check sequence / CRC bit length}) \\
  L_{\text{ifg}} &\in \mathbb{N}_0 \quad (\text{inter-frame gap / line quiet spacing bit length}) \\
  L_{\text{payload\_min}} &\in \mathbb{N}_0 \quad (\text{minimum allowable payload bit length}) \\
  L_{\text{mtu}} &\in \mathbb{N}^+ \quad (\text{maximum transmission unit payload bit length}) \\
  \text{Align}_{\text{frame}} &\in \{1, 8, 16, 32, 64\} \quad (\text{frame boundary bit alignment constraint}) \\
  \Sigma_{\text{stuffing}} &\in \{ \text{None} \} \cup \{ \text{BitStuffing}(k) \mid k \in \mathbb{N}_{\ge 2} \} \quad (\text{stuffing rule}) \\
  R_{\text{bus}} &\in \mathbb{Q}^+ \quad (\text{nominal transmission bit rate in bits per second}, \; R_{\text{bus}} \gt 0) \\
  \Pi_{\text{fragment}} &\in \{ \text{true}, \text{false} \} \quad (\text{payload segmentation enablement flag}) \\
  \Delta_{\Pi} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor})
  \end{aligned}
```

  Let $`\mathcal{F}_{\text{dict}}`$` denote the set of signal flows cataloged in the Master Signal Flow Dictionary (REQ-0148). Each signal flow `$`\sigma \in \mathcal{F}_{\text{dict}}`$` bound to transport profile `$`\Pi_\sigma`$` has a synthesized wire payload bit length `$`L_{\text{payload}}(\sigma) \in \mathbb{N}^+`$` and transmission period `$`T_{\text{period}}(\sigma) \in \mathbb{Q}^+`$.

  1. Fixed Protocol Framing Overhead Invariant:
  The constant framing overhead $`L_{\text{fixed}}(\Pi)`$ is invariant with respect to payload length:

```math
  L_{\text{fixed}}(\Pi) = L_{\text{preamble}} + L_{\text{header}} + L_{\text{trailer}} + L_{\text{crc}} + L_{\text{ifg}}
```

  2. Deterministic Alignment & Minimum Payload Padding Invariant:
  For payload length $`L \in \mathbb{N}^+`$`, padding `$`\Delta_{\text{padding}}(L, \Pi)`$ satisfies:

```math
  \begin{aligned}
  \Delta_{\text{min\_pad}}(L, \Pi) &= \max(0, L_{\text{payload\_min}} - L) \\
  L_{\text{base}}(L, \Pi) &= L_{\text{preamble}} + L_{\text{header}} + L_{\text{trailer}} + L_{\text{crc}} + L + \Delta_{\text{min\_pad}}(L, \Pi) \\
  \Delta_{\text{align\_pad}}(L, \Pi) &= (\text{Align}_{\text{frame}} - (L_{\text{base}}(L, \Pi) \pmod{\text{Align}_{\text{frame}}})) \pmod{\text{Align}_{\text{frame}}} \\
  \Delta_{\text{padding}}(L, \Pi) &= \Delta_{\text{min\_pad}}(L, \Pi) + \Delta_{\text{align\_pad}}(L, \Pi)
  \end{aligned}
```

  3. Deterministic Worst-Case Bit-Stuffing Invariant:
  For a bit-stuffing rule with threshold $`k_{\text{stuff}} \in \mathbb{N}_{\ge 2}`$ applied over the continuous bit sequence spanning header, padded payload, and CRC:

```math
  \Delta_{\text{stuffing}}(L, \Pi) = \begin{cases}
  \left\lfloor \dfrac{L_{\text{header}} + L + \Delta_{\text{padding}}(L, \Pi) + L_{\text{crc}} - 1}{k_{\text{stuff}} - 1} \right\rfloor, & \text{if } \Sigma_{\text{stuffing}} = \text{BitStuffing}(k_{\text{stuff}}) \\
  0, & \text{if } \Sigma_{\text{stuffing}} = \text{None}
  \end{cases}
```

  4. Single-Frame Total Bit Length Invariant:
  For an unfragmented payload $`L_{\text{payload}} \le L_{\text{mtu}}`$`, the total wire frame length `$`L_{\text{frame}}(L_{\text{payload}}, \Pi)`$ satisfies:

```math
  L_{\text{frame}}(L_{\text{payload}}, \Pi) = L_{\text{fixed}}(\Pi) + L_{\text{payload}} + \Delta_{\text{padding}}(L_{\text{payload}}, \Pi) + \Delta_{\text{stuffing}}(L_{\text{payload}}, \Pi)
```

  5. Multi-Frame Payload Fragmentation Invariant:
  When $`L_{\text{payload}} \gt L_{\text{mtu}}`$` and `$`\Pi_{\text{fragment}} = \text{true}`$`, the payload is partitioned into `$`N_{\text{fragments}}`$ discrete packets:

```math
  \begin{aligned}
  N_{\text{fragments}}(L_{\text{payload}}, \Pi) &= \left\lceil \frac{L_{\text{payload}}}{L_{\text{mtu}}} \right\rceil \\
  L_{\text{payload}}^{(j)} &= \begin{cases}
  L_{\text{mtu}}, & \text{if } 1 \le j \lt N_{\text{fragments}} \\
  L_{\text{payload}} - (N_{\text{fragments}} - 1) \cdot L_{\text{mtu}}, & \text{if } j = N_{\text{fragments}}
  \end{cases} \\
  L_{\text{total\_frames}}(L_{\text{payload}}, \Pi) &= \sum_{j=1}^{N_{\text{fragments}}} L_{\text{frame}}(L_{\text{payload}}^{(j)}, \Pi)
  \end{aligned}
```

  For unfragmented frames ($`L_{\text{payload}} \le L_{\text{mtu}}`$`), `$`N_{\text{fragments}} = 1`$` and `$`L_{\text{total\_frames}} = L_{\text{frame}}(L_{\text{payload}}, \Pi)`$.

  6. Framing Efficiency & Header Serialization Penalty Invariants:
  Framing efficiency $`\eta_{\text{framing}}`$` and header serialization penalty `$`\Pi_{\text{penalty}}`$ satisfy:

```math
  \begin{aligned}
  \eta_{\text{framing}}(L_{\text{payload}}, \Pi) &= \frac{L_{\text{payload}}}{L_{\text{total\_frames}}(L_{\text{payload}}, \Pi)} \in (0, 1] \\
  \Pi_{\text{penalty}}(L_{\text{payload}}, \Pi) &= \frac{L_{\text{total\_frames}}(L_{\text{payload}}, \Pi) - L_{\text{payload}}}{L_{\text{payload}}} = \frac{1}{\eta_{\text{framing}}(L_{\text{payload}}, \Pi)} - 1
  \end{aligned}
```

  7. Channel Transmission Occupancy Duration & Duty Cycle Invariant:
  Transmission occupancy duration $`\tau_{\text{occupancy}}`$` and periodic channel duty cycle `$`\rho_{\text{occupancy}}`$ satisfy:

```math
  \begin{aligned}
  \tau_{\text{occupancy}}(L_{\text{payload}}, \Pi) &= \frac{L_{\text{total\_frames}}(L_{\text{payload}}, \Pi)}{R_{\text{bus}}} \in \mathbb{Q}^+ \\
  \rho_{\text{occupancy}}(\sigma) &= \frac{\tau_{\text{occupancy}}(L_{\text{payload}}(\sigma), \Pi_\sigma)}{T_{\text{period}}(\sigma)} \in \mathbb{Q}^+
  \end{aligned}
```

  8. Deterministic Diagnostic Trigger Rules (REQ-0191):

