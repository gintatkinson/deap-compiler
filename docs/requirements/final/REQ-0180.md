### REQ-0180: Register Allocation & SSA Basic Block Scheduling in LUMI IR (NP-7)

- **Normative Statement**: The code generation engine, intermediate representation lowering pipeline, and machine optimization framework of Subsystem 10 shall execute global register allocation and intra-block instruction scheduling over LUMI IR basic blocks to produce optimized, hardware-conforming machine code representations. Because both optimal register allocation (Chaitin Graph $`K`$-Coloring) and latency-constrained DAG instruction scheduling under finite execution units are NP-complete (Algorithmic Bound NP-7), the compiler shall implement Kempe's degree-based heuristic with optimistic spilling (Chaitin-Briggs) for global register assignment, and critical-path list scheduling for intra-block instruction reordering, guaranteeing deterministic polynomial-time compilation bounds. If register spill capacity is breached, variable coloring encounters conflicts, or basic block dependency cycles arise, the compiler shall fail closed and emit diagnostic error code `E0500`.

  Specifically, the register allocation and instruction scheduling engine shall strictly enforce the following structural, algebraic, and operational provisions across all compilation units:
  1. **Liveness Analysis & Variable Interference Graph Construction**:
     - The engine shall compute live ranges for all virtual value registers $`\mathcal{V}_{\text{ssa}}`$` across the control flow graph `$`\mathcal{G}_{\text{cfg}} = (\mathcal{B}, \mathcal{E}_{\text{cfg}})`$ defined in REQ-0175.
     - Dataflow analysis shall iteratively compute entry and exit liveness sets ($`\text{LiveIn}(B)`$` and `$`\text{LiveOut}(B)`$`) for each basic block `$`B \in \mathcal{B}`$.
     - The engine shall construct the undirected variable interference graph $`\mathcal{G}_{\text{interf}} = (\mathcal{V}_{\text{ssa}}, \mathcal{E}_{\text{interf}})`$`. An interference edge `$`(u, v) \in \mathcal{E}_{\text{interf}}`$` shall be created if and only if variable `$`u`$` and variable `$`v`$ are simultaneously live at any program execution point.
     - Self-interference loops ($`(v, v) \in \mathcal{E}_{\text{interf}}`$) are strictly invalid; detection of a self-loop shall trigger compile-time failure with diagnostic error code `E0500` (`MalformedInterferenceGraph`).
     - Pre-colored architectural registers: Architecture-specific calling convention constraints, fixed parameter passing registers, and function return registers shall be modeled as pre-colored nodes in $`\mathcal{G}_{\text{interf}}`$ with fixed physical register bindings.
  2. **Kempe Simplification & Degree Reduction**:
     - Let $`K \ge 1`$` denote the number of target machine physical registers `$`\mathcal{R}_{\text{phys}} = \{ r_1, r_2, \dots, r_K \}`$.
     - While there exists an active non-precolored variable $`v \in \mathcal{V}_{\text{active}}`$` whose current degree in the interference graph is strictly less than `$`K`$` (`$`\text{degree}_{\mathcal{G}_{\text{interf}}}(v) \lt K`$`), the allocator shall push `$`v`$` onto the allocation stack `$`\mathcal{S}_{\text{alloc}}`$` and remove `$`v`$` along with its incident edges from `$`\mathcal{G}_{\text{interf}}`$.
     - Removal of $`v`$` dynamically decrements the degree of adjacent vertices, potentially creating new candidates satisfying `$`\text{degree}(w) \lt K`$.
  3. **Optimistic Spill Selection (Chaitin-Briggs)**:
     - If all remaining active variables in $`\mathcal{G}_{\text{interf}}`$` satisfy `$`\text{degree}_{\mathcal{G}_{\text{interf}}}(v) \ge K`$` and `$`\mathcal{G}_{\text{interf}} \ne \emptyset`$`, the allocator shall select an optimistic spill candidate `$`v_{\text{spill}}`$:

```math
v_{\text{spill}} = \arg\min_{v \in \mathcal{V}_{\text{active}}} \frac{\text{spill\_cost}(v)}{\text{degree}_{\mathcal{G}_{\text{interf}}}(v)}
```

     - The static spill cost $`\text{spill\_cost}(v)`$` shall be computed from definition and use frequencies weighted by loop nesting depth factor `$`10^{\text{depth}(B)}`$:

```math
\text{spill\_cost}(v) = \sum_{B \in \mathcal{B}} 10^{\text{depth}(B)} \cdot \left( |\text{Def}(v) \cap B| + |\text{Uses}(v) \cap B| \right)
```

     - The selected candidate $`v_{\text{spill}}`$` shall be marked with an optimistic spill flag, pushed onto the allocation stack `$`\mathcal{S}_{\text{alloc}}`$`, and eliminated from `$`\mathcal{G}_{\text{interf}}`$ without immediately emitting spill memory instructions.
     - Deterministic tie-breaking: If multiple candidates share identical minimum cost ratio, ties shall be resolved deterministically by ascending variable arena handle index ($`\text{id}_v`$), followed by interned symbol byte order and RFC 4122 UUIDv5 byte order, ensuring bitwise determinism and 0-byte diff churn.
  4. **Stack Reconstruction, Physical Color Assignment & Actual Spill Resolution**:
     - The allocator shall pop variables from $`\mathcal{S}_{\text{alloc}}`$` in Last-In First-Out (LIFO) sequence, restoring their incident edges in `$`\mathcal{G}_{\text{interf}}`$.
     - For each popped variable $`v`$`, the allocator shall inspect the colors already assigned to its adjacent neighbors in `$`\mathcal{G}_{\text{interf}}`$` and assign `$`v`$ the lowest available physical color:

```math
c(v) = \min \left( \{1, \dots, K\} \setminus \{ c(u) \mid (u, v) \in \mathcal{E}_{\text{interf}} \ \wedge \ c(u) \in \{1, \dots, K\} \} \right)
```

     - If an optimistically pushed variable encounters a color conflict where all $`K`$ physical colors are consumed by adjacent neighbors, the variable shall be designated as an actual spill.
     - For every actually spilled variable $`v_{\text{spill}}`$`, the code generator shall allocate a dedicated, deterministic memory stack frame offset `$`\text{slot}(v) \in \mathbb{N}`$` within the function activation record (REQ-0176, REQ-0185). The allocator shall insert a spill load instruction immediately preceding each instruction using `$`v`$`, and insert a spill store instruction immediately following each definition of `$`v`$.
     - If the total count of spilled frame slots exceeds the target machine stack limit $`M_{\text{max\_spill\_slots}}`$, the compiler shall fail closed and emit diagnostic error code `E0500` (`RegisterSpillCapacityExceeded`).
     - If any variable remains uncolored and unspilled upon completion of the allocation phase, the compiler shall emit diagnostic error code `E0500` (`UnresolvedRegisterAllocation`).
     - If two interfering variables are assigned the same physical register ($`c(u) = c(v)`$` for `$`(u, v) \in \mathcal{E}_{\text{interf}}`$), the compiler shall emit diagnostic error code `E0500` (`RegisterAllocationConflict`).
  5. **Conservative Copy Coalescing (Briggs & George Criteria)**:
     - For register-to-register copy instructions ($`v_1 \leftarrow v_2`$), the allocator shall evaluate conservative coalescing conditions prior to simplification to eliminate redundant move instructions.
     - Under the Briggs criterion, variables $`v_1`$` and `$`v_2`$` may be coalesced into a single node if the resulting merged node has fewer than `$`K`$` neighbors of significant degree (`$`\ge K`$).
     - Under the George criterion, variable $`v_1`$` may be coalesced into `$`v_2`$` if for every neighbor `$`t`$` of `$`v_1`$`, either `$`\text{degree}(t) \lt K`$` or `$`t`$` already interferes with `$`v_2`$.
     - Coalesced variables share an identical physical register assignment, deleting the redundant copy instruction from the basic block.
  6. **Basic Block Intra-Block Instruction Scheduling DAG Construction**:
     - Within each basic block $`B \in \mathcal{B}`$`, the instruction scheduler shall construct the directed acyclic graph of instruction dependencies `$`\mathcal{D}_{\text{bb}} = (\mathcal{I}_B, \mathcal{E}_{\text{dep}})`$.
     - The set of nodes $`\mathcal{I}_B`$` comprises the linear body instructions of basic block `$`B`$`. `$`\phi`$`-node instructions (`$`\mathbf{\Phi}_B`$`) remain anchored at the entry join boundary, and the control flow terminator (`$`T_B`$) remains anchored at the terminal block exit.
     - Directed edges $`\mathcal{E}_{\text{dep}} \subseteq \mathcal{I}_B \times \mathcal{I}_B`$ shall represent Read-After-Write (RAW, true data dependency), Write-After-Read (WAR, anti-dependency), Write-After-Write (WAW, output dependency), and memory side-effect serialization barriers.
     - Latency function $`\lambda : \mathcal{E}_{\text{dep}} \to \mathbb{N}_0`$` assigns the target hardware pipeline latency (in clock cycles) required between the completion of producer instruction `$`u`$` and the issue of consumer instruction `$`v`$.
     - If the dependency graph $`\mathcal{D}_{\text{bb}}`$` contains a directed cycle (`$`\neg \text{DAG}`$), the compiler shall fail closed and emit diagnostic error code `E0500` (`InstructionSchedulingDependencyCycle`).
  7. **Critical-Path List Scheduling with Greedy Priority Reordering**:
     - The scheduler shall compute the bottom-up critical path priority $`\text{Priority}(u)`$` for every instruction `$`u \in \mathcal{I}_B`$:

```math
\text{Priority}(u) = \text{latency}(u) + \max_{v \in \text{succ}_{\mathcal{D}_{\text{bb}}}(u)} \left( \text{Priority}(v) + \lambda(u, v) \right)
```

       with base case $`\text{succ}_{\mathcal{D}_{\text{bb}}}(u) = \emptyset \implies \text{Priority}(u) = \text{latency}(u)`$.
     - The scheduler shall maintain a ready list $`\mathcal{R}(t)`$` containing all instructions whose predecessors in `$`\mathcal{D}_{\text{bb}}`$ have already been scheduled.
     - At clock cycle $`t \ge 0`$`, the scheduler selects an instruction `$`u^* \in \mathcal{R}(t)`$` maximizing `$`\text{Priority}(u^*)`$ whose incoming latency constraints are satisfied:

```math
\forall p \in \text{pred}_{\mathcal{D}_{\text{bb}}}(u^*), \quad t \ge t_{\text{sched}}(p) + \lambda(p, u^*)
```

     - Deterministic tie-breaking: When multiple ready instructions share identical critical-path priority, ties shall be resolved deterministically by higher individual instruction latency, followed by higher number of dependent successors, and finally deterministic RFC 4122 UUIDv5 byte order.
     - If no ready instruction can issue at cycle $`t`$` due to unresolved latency stalls, the scheduler advances the clock cycle (`$`t \leftarrow t + 1`$), inserting pipeline stall cycles (NOPs or bubbles) until dependencies clear.
     - The resulting scheduled instruction sequence $`\pi_B`$ minimizes total execution latency and pipeline stall cycles while strictly preserving all data and memory dependencies.
  8. **Contiguous Bump Arena Allocation & Stable Handle Addressing**:
     - All interference graph structures, liveness bitvectors, allocation stacks, spill frame descriptors, dependency DAGs, and scheduled instruction sequences shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034.
     - All entities shall be addressed exclusively by stable 32-bit arena node handles (REQ-0035), prohibiting raw pointers and reference cycles.
  9. **Enforcement of the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every physical register binding, spilled stack slot record, dependency DAG node, and scheduled basic block sequence shall bind an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and entity fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{label}_B \mathbin{\Vert} \text{"::"} \text{name}_v)`$). Time-based UUIDs are strictly banned.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel register allocation and instruction scheduling across independent LUMI IR functions and basic blocks shall execute strictly on a centralized, bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012. Unbounded manual thread spawning is strictly banned.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Physical register names, machine register aliases, basic block labels, and opcode mnemonics shall be interned into the deduplicated global symbol interner pool during lowering in accordance with REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The register allocation and instruction scheduling engine shall implement synchronization token error recovery on basic block boundaries, function boundaries, and statement delimiters (`;`) in accordance with REQ-0013 and REQ-0016. When allocation capacity violations (`E0500`), cyclic dependencies, or malformed interference graphs occur, the engine shall record structured diagnostics into the preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{reg}}, \bot_{\text{sched}}`$`), and continue validating subsequent basic blocks and functions. If accumulated diagnostics reach capacity limit `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Paths & Benchmarking Isolation)*: The register allocation and instruction scheduling pipeline shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Allocation and scheduling latency (strictly under 25 ms for an architectural model containing $`10^4`$ virtual registers and instructions) and peak RSS memory (strictly under 100 MB) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.
  10. **Pure Abstract MBSE Placeholder Mandate**:
      - All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Function_0`, `Block_0`, `Block_1`, `Block_Entry`, `Var_0`, `Var_1`, `Var_2`, `Reg_0`, `Reg_1`, `Instr_0`, `Instr_1`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous typed bump arena storage, and let `$`\mathcal{S}_{\text{intern}}`$ denote the deduplicated global symbol interner pool.

  Let $`\mathcal{F}_{\text{lumi}}`$ denote the set of lowered LUMI IR functions within a compilation unit:

```math
  \mathcal{F}_{\text{lumi}} = \{ F_1, F_2, \dots, F_M \}
```

  Each function $`F \in \mathcal{F}_{\text{lumi}}`$ is formalized as a 9-tuple:

```math
  F = \langle \text{id}_F, \text{name}_F, \tau_{\text{ret}}, \mathbf{P}_F, B_{\text{entry}}, \mathcal{B}, \mathcal{E}_{\text{cfg}}, \Delta_F, \text{span}_F \rangle
```

  where:

```math
  \begin{aligned}
  \text{id}_F &\in \mathbb{N}_{32} \quad (\text{contiguous arena function handle}) \\
  \text{name}_F &\in \mathcal{S}_{\text{intern}} \quad (\text{interned function symbol identifier}) \\
  \tau_{\text{ret}} &\in \mathcal{T}_{\text{lumi}} \quad (\text{formal return type}) \\
  \mathbf{P}_F &= \langle p_1, p_2, \dots, p_m \rangle \quad (\text{ordered vector of formal parameter registers}) \\
  B_{\text{entry}} &\in \mathcal{B} \quad (\text{distinguished unique entry basic block}) \\
  \mathcal{B} &= \{ B_0, B_1, \dots, B_{n-1} \} \quad (\text{finite set of basic blocks}) \\
  \mathcal{E}_{\text{cfg}} &\subseteq \mathcal{B} \times \mathcal{B} \quad (\text{directed control flow graph edges}) \\
  \Delta_F &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
  \text{span}_F &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{lexical source provenance})
  \end{aligned}
```

  Let $`\mathcal{V}_{\text{ssa}}(F)`$` denote the finite set of virtual SSA value registers defined within function `$`F`$`, and let `$`\mathcal{R}_{\text{phys}} = \{ r_1, r_2, \dots, r_K \}`$` denote the set of `$`K \ge 1`$ physical machine registers.

  1. Liveness Analysis Dataflow Equations:
  For each basic block $`B \in \mathcal{B}`$`, liveness sets `$`\text{LiveIn}(B)`$` and `$`\text{LiveOut}(B)`$ satisfy:

```math
  \begin{aligned}
  \text{LiveOut}(B) &= \bigcup_{S \in \text{succ}(B)} \text{LiveIn}(S) \\
  \text{LiveIn}(B) &= \text{Gen}(B) \cup \left( \text{LiveOut}(B) \setminus \text{Kill}(B) \right)
  \end{aligned}
```

  where $`\text{Gen}(B)`$` is the set of variables used in `$`B`$` before any definition in `$`B`$`, and `$`\text{Kill}(B)`$` is the set of variables defined in `$`B`$.

  2. Variable Interference Graph Formulation:
  The undirected interference graph is defined as $`\mathcal{G}_{\text{interf}} = (\mathcal{V}_{\text{ssa}}(F), \mathcal{E}_{\text{interf}})`$ where:

```math
  (u, v) \in \mathcal{E}_{\text{interf}} \iff \exists p \in \text{Points}(F) : u \in \text{Live}(p) \ \wedge \ v \in \text{Live}(p) \ \wedge \ u \ne v
```

  Irreflexivity invariant (zero self-loops):

```math
  \forall v \in \mathcal{V}_{\text{ssa}}(F), \quad (v, v) \notin \mathcal{E}_{\text{interf}}
```

  3. Kempe Degree Simplification Invariant:
  Let $`\mathcal{V}_{\text{active}} \subseteq \mathcal{V}_{\text{ssa}}(F)`$ denote the set of uneliminated active variables.
  If a variable satisfies degree reduction:

```math
  v \in \mathcal{V}_{\text{active}} \ \wedge \ \text{degree}_{\mathcal{G}_{\text{interf}}}(v) \lt K \implies \text{push}(v, \mathcal{S}_{\text{alloc}}) \ \wedge \ \mathcal{G}_{\text{interf}} \leftarrow \mathcal{G}_{\text{interf}} \setminus \{v\}
```

  4. Optimistic Spill Selection Invariant (Chaitin-Briggs):
  If all remaining active variables satisfy $`\text{degree}_{\mathcal{G}_{\text{interf}}}(v) \ge K`$:

```math
  \left( \forall v \in \mathcal{V}_{\text{active}}, \ \text{degree}_{\mathcal{G}_{\text{interf}}}(v) \ge K \right) \implies v_{\text{spill}} = \arg\min_{v \in \mathcal{V}_{\text{active}}} \frac{\text{spill\_cost}(v)}{\text{degree}_{\mathcal{G}_{\text{interf}}}(v)}
```

  Static spill cost computation:

```math
  \text{spill\_cost}(v) = \sum_{B \in \mathcal{B}} 10^{\text{depth}(B)} \cdot \left( |\text{Def}(v) \cap B| + |\text{Uses}(v) \cap B| \right)
```

  5. Physical Register Assignment Function:
  Let $`c : \mathcal{V}_{\text{ssa}}(F) \to \mathcal{R}_{\text{phys}} \cup \mathcal{M}_{\text{stack}}`$ denote the mapping of virtual registers to physical registers or spilled stack frame slots:

```math
  \forall v \in \mathcal{V}_{\text{ssa}}(F), \quad c(v) \in \{1, \dots, K\} \setminus \{ c(u) \mid (u, v) \in \mathcal{E}_{\text{interf}} \ \wedge \ c(u) \in \{1, \dots, K\} \}
```

  Actual spill slot assignment:

```math
  \{1, \dots, K\} \subseteq \{ c(u) \mid (u, v) \in \mathcal{E}_{\text{interf}} \} \implies c(v) = \text{Spill}(\text{slot}(v))
```

  Spill stack slot bound:

```math
  \forall v \in \mathcal{V}_{\text{ssa}}(F), \quad c(v) = \text{Spill}(\text{slot}(v)) \implies \text{slot}(v) \le M_{\text{max\_spill\_slots}}
```

  6. Conservative Copy Coalescing Invariants:
  For copy instruction $`u \leftarrow v`$:
  - Briggs Criterion:

```math
  |\{ w \in \text{adj}(u) \cup \text{adj}(v) \mid \text{degree}(w) \ge K \}| \lt K \implies \text{Coalesce}(u, v)
```

  - George Criterion:

```math
  \forall t \in \text{adj}(u), \quad \left( \text{degree}(t) \lt K \ \lor \ (t, v) \in \mathcal{E}_{\text{interf}} \right) \implies \text{Coalesce}(u, v)
```

  7. Instruction Dependency Directed Acyclic Graph (DAG):
  Within basic block $`B = \langle \text{id}_B, \text{label}_B, \mathbf{\Phi}_B, \mathbf{I}_B, T_B, \Delta_B \rangle`$, the dependency DAG is formalized as:

```math
  \mathcal{D}_{\text{bb}} = (\mathcal{I}_B, \mathcal{E}_{\text{dep}})
```

  where edges partition into data, anti, output, and memory dependencies:

```math
  \mathcal{E}_{\text{dep}} = \mathcal{E}_{\text{raw}} \cup \mathcal{E}_{\text{war}} \cup \mathcal{E}_{\text{waw}} \cup \mathcal{E}_{\text{mem}}
```

  Acyclicity invariant:

```math
  \forall \text{cycle} \subseteq \mathcal{I}_B \times \mathcal{I}_B, \quad \text{cycle} \not\subseteq \mathcal{E}_{\text{dep}}
```

  8. Critical-Path Priority & Ready-List Scheduling:
  For each instruction $`u \in \mathcal{I}_B`$:

```math
  \text{Priority}(u) = \text{latency}(u) + \max_{v \in \text{succ}_{\mathcal{D}_{\text{bb}}}(u)} \left( \text{Priority}(v) + \lambda(u, v) \right)
```

  with base case:

```math
  \text{succ}_{\mathcal{D}_{\text{bb}}}(u) = \emptyset \implies \text{Priority}(u) = \text{latency}(u)
```

  Ready instruction candidate set at cycle $`t \ge 0`$:

```math
  \text{Ready}(t) = \{ u \in \mathcal{I}_B \setminus \mathcal{I}_{\text{sched}} \mid \forall p \in \text{pred}_{\mathcal{D}_{\text{bb}}}(u), \ p \in \mathcal{I}_{\text{sched}} \ \wedge \ t \ge t_{\text{sched}}(p) + \lambda(p, u) \}
```

  Greedy priority selection:

```math
  u^* = \arg\max_{u \in \text{Ready}(t)} \text{Priority}(u)
```

  9. Deterministic Diagnostic Trigger Rules (REQ-0191):

```math
  \begin{aligned}
  \exists v : c(v) = \text{Spill}(\text{slot}(v)) \ \wedge \ \text{slot}(v) \gt M_{\text{max\_spill\_slots}} &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0500}, \text{RegisterSpillCapacityExceeded}) \in \mathcal{D}_{\text{sink}} \\
  \exists (u, v) \in \mathcal{E}_{\text{interf}} : c(u) = c(v) \ \wedge \ c(u) \in \{1, \dots, K\} &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0500}, \text{RegisterAllocationConflict}) \in \mathcal{D}_{\text{sink}} \\
  \exists \text{cycle} \in \mathcal{D}_{\text{bb}} : \text{Length}(\text{cycle}) \ge 1 &\implies \text{Diagnostic}(B, \text{DiagnosticCode::E0500}, \text{InstructionSchedulingDependencyCycle}) \in \mathcal{D}_{\text{sink}} \\
  \exists v \in \mathcal{V}_{\text{ssa}} : c(v) = \bot &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0500}, \text{UnresolvedRegisterAllocation}) \in \mathcal{D}_{\text{sink}} \\
  \exists v \in \mathcal{V}_{\text{ssa}} : (v, v) \in \mathcal{E}_{\text{interf}} &\implies \text{Diagnostic}(v, \text{DiagnosticCode::E0500}, \text{MalformedInterferenceGraph}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  10. Deterministic RFC 4122 UUIDv5 Anchor Invariants (Directive 1):

```math

  \Delta_{\text{alloc}}(v) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{name}_v \mathbin{\Vert} \text{"::alloc"}) \\
  \Delta_{\text{sched}}(B) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(F) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{label}_B \mathbin{\Vert} \text{"::sched"})
  \end{aligned}
```

- **Computational Complexity & Algorithmic Bounds**: Register Allocation & SSA Basic Block Scheduling in LUMI IR resides in Complexity Class **NP-complete** for the optimal decision problems (Algorithmic Bound NP-7). Optimal register allocation is isomorphic to Chaitin Graph $`K`$`-Coloring, which is NP-complete for any fixed target machine register count `$`K \ge 3`$`. Optimal instruction scheduling on directed acyclic graphs under execution latency and resource limits is NP-complete. To guarantee predictable, real-time compilation throughput, the compiler enforces deterministic polynomial-time tractable algorithmic bounds: Kempe's degree-based heuristic with optimistic spilling (Chaitin-Briggs) executing in `$`O(|\mathcal{V}_{\text{ssa}}|^2)`$` time, and critical-path list scheduling executing in deterministic linear time `$`O(|\mathcal{I}| + |\mathcal{E}_{\text{dep}}|)`$ over basic block instruction graphs.

  **Mathematical Delineation from the 8 NP Frontiers**:
  - *Delineation from NP-1 (REQ-0117)*: NP-1 addresses temporal consistency over continuous and discrete occurrence lifecycles using Allen's 13 qualitative interval relations, solved via ORD-Horn SMT difference logic in $`O(N^3)`$` polynomial time. In contrast, REQ-0180 schedules discrete programmatic instructions within a single basic block according to integer clock cycle latencies `$`\lambda \in \mathbb{N}_0`$ without interval relational algebra or SMT constraint solving.
  - *Delineation from NP-2 (REQ-0147)*: NP-2 addresses strongly NP-hard multi-dimensional vector bin packing for logical signal flow channel allocation and interconnect multiplexing across interface matrices. In contrast, REQ-0180 maps virtual value registers to a one-dimensional set of $`K`$ homogeneous physical registers or stack slots without multi-capacity knapsack packing or inter-subsystem matrix cut optimization.
  - *Delineation from NP-3 (REQ-0061--REQ-0063)*: NP-3 formalizes subtyping lattice redefinition, multiple inheritance, and feature subsetting via C3 linearization in deterministic $`O(V + E)`$ time. In contrast, REQ-0180 operates on lowered LUMI IR value registers and machine instructions where all data types are concrete and lowered, requiring no poset traversal or inheritance hierarchy linearization.
  - *Delineation from NP-4 (REQ-0135)*: NP-4 minimizes STPA hazard cut-sets and Unsafe Control Actions via NP-complete Minimal Hitting Set reductions with logarithmic approximation factors. In contrast, REQ-0180 performs graph coloring and DAG list scheduling on compiler intermediate representations without combinatorial safety cut-set extraction or fault hazard covers.
  - *Delineation from NP-5 (REQ-0124)*: NP-5 analyzes state machine reachability, deadlock, and livelock in orthogonal regions (PSPACE-complete / NP-complete Bounded Model Checking via SAT unrolling). In contrast, REQ-0180 evaluates acyclic dependency DAGs within individual basic blocks where reachability and cycle detection are solvable in deterministic $`O(|\mathcal{I}| + |\mathcal{E}_{\text{dep}}|)`$ linear time without state space explosion.
  - *Delineation from NP-6 (REQ-0105)*: NP-6 solves switched piecewise conservative flow networks using linear complementarity problems and Lemke pivoting (NP-complete). In contrast, REQ-0180 resolves discrete register conflicts and pipeline latency bubbles without continuous conductance matrices, Kirchhoff conservation laws, or pivoting tableaus.
  - *Delineation from NP-7 (REQ-0180)*: NP-7 is the primary anchor requirement formalized herein. It governs global register allocation on variable interference graphs $`\mathcal{G}_{\text{interf}}`$` and intra-block instruction scheduling on dependency DAGs `$`\mathcal{D}_{\text{bb}}`$`, solving the NP-complete problems via the polynomial-time Kempe heuristic in `$`O(|\mathcal{V}_{\text{ssa}}|^2)`$` and critical-path list scheduling in `$`O(|\mathcal{I}| + |\mathcal{E}_{\text{dep}}|)`$.
  - *Delineation from NP-8 (REQ-0197)*: NP-8 proves satisfiability of first-order invariant contracts and proof obligations using decidable SMT fragments (QF_LRA, QF_LIA, QF_UF) via DPLL(T). In contrast, REQ-0180 executes deterministic heuristic algorithms without first-order theorem proving or symbolic quantifier reasoning.

  **Asymptotic Complexity Analysis**:
  Let $`N_V = |\mathcal{V}_{\text{ssa}}(F)|`$` denote the number of virtual SSA value registers, `$`N_E = |\mathcal{E}_{\text{interf}}|`$` denote the number of interference edges, `$`N_B = |\mathcal{B}|`$` denote the number of basic blocks, `$`N_I = |\mathcal{I}|`$` denote the aggregate instruction count, and `$`N_{\text{dep}} = |\mathcal{E}_{\text{dep}}|`$ denote the aggregate dependency edge count across basic block DAGs.
  1. *Liveness Analysis Phase*:
     - Iterative dataflow computation over the control flow graph executes in:

```math
T_{\text{liveness}}(N_B, N_V) \in O(N_B \cdot N_V), \quad S_{\text{liveness}} \in O(N_B \cdot N_V)
```

       For typical structured control flow programs with bounded loop nesting depth, liveness computation converges in $`O(N_V)`$ time.
  2. *Interference Graph Assembly*:
     - Inspecting simultaneous liveness at all program points and inserting undirected edges into $`\mathcal{G}_{\text{interf}}`$ executes in:

```math
T_{\text{interf}}(N_V, N_E) \in O(N_V + N_E), \quad S_{\text{interf}} \in O(N_V + N_E)
```

       In the dense worst case, $`N_E \le \frac{1}{2} N_V (N_V - 1)`$`, yielding `$`O(N_V^2)`$ operations.
  3. *Kempe Simplification & Color Assignment (NP-7 Bound)*:
     - Maintaining degree buckets via doubly-linked bucket queues allows constant-time degree inspection and decrements.
     - Simplification phase executes at most $`N_V`$ vertex removals, each inspecting incident edges:

```math
T_{\text{simplify}}(N_V, N_E) \in O(N_V + N_E) \subseteq O(N_V^2)
```

     - Optimistic spill selection inspects remaining active vertices, taking at most $`O(N_V)`$` per spill event. With at most `$`N_V`$ spill events:

```math
T_{\text{spill}}(N_V) \in O(N_V^2)
```

     - Stack reconstruction pops each variable and assigns colors from $`\{1, \dots, K\}`$`, checking neighbor colors in `$`O(K \cdot \text{degree}(v))`$:

```math
T_{\text{color}}(N_V, N_E, K) \in O(K \cdot (N_V + N_E)) \subseteq O(K \cdot N_V^2)
```

     - Total register allocation latency is strictly bounded by:

```math
T_{\text{alloc}}(N_V, K) \in O(N_V^2)
```

  4. *Instruction Dependency DAG Assembly*:
     - Computing def-use chains (RAW) and tracking recent loads/stores (WAR, WAW, memory barriers) within basic block $`B`$ executes in single-pass linear time:

```math
T_{\text{dag}}(N_I, N_{\text{dep}}) \in O(N_I + N_{\text{dep}}), \quad S_{\text{dag}} \in O(N_I + N_{\text{dep}})
```

  5. *Critical-Path Priority Computation*:
     - Reverse topological traversal of $`\mathcal{D}_{\text{bb}}`$` to compute `$`\text{Priority}(u)`$ visits each instruction and dependency edge exactly once:

```math
T_{\text{priority}}(N_I, N_{\text{dep}}) \in O(N_I + N_{\text{dep}})
```

  6. *List Scheduling Simulation*:
     - Maintaining ready instructions in a binary max-heap ordered by $`\text{Priority}(u)`$` supports ready insertion and maximum extraction in `$`O(\log N_I)`$ time:

```math
T_{\text{sched}}(N_I, N_{\text{dep}}) \in O(N_I \log N_I + N_{\text{dep}})
```

  7. *Aggregate Compilation Unit Complexity*:
     - Combining register allocation and instruction scheduling across all basic blocks and functions:

```math
T_{\text{total}}(N_V, N_I, N_{\text{dep}}, K) \in O(N_V^2 + N_I \log N_I + N_{\text{dep}})
```

     - Space complexity is strictly $`O(N_V^2 + N_I + N_{\text{dep}})`$ in contiguous bump arena storage, requiring zero unbounded heap allocations.
  8. *Parallel Work-Stealing Scaling (Directive 2)*:
     - Partitioning independent functions across $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool achieves near-linear speedup:

```math
T_{\text{parallel}} \in O\left( \frac{N_V^2 + N_I \log N_I + N_{\text{dep}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```
