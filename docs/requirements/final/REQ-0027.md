### REQ-0027: Protocol Buffer (Proto3) AST Ingestion for Messages, Fields & RPCs

- **Normative Statement**: The compiler ingestion engine shall provide a native, self-contained Protocol Buffer version 3 (Proto3) parser that parses `.proto` schema definitions into intermediate schema representation (IR) without external compiler dependencies or external toolchain invocations. The ingestion engine shall transform Protobuf message definitions into `IngestedPart` component structures, scalar and message field declarations into `IngestedAttr` property definitions, service RPC declarations into `IngestedAction` operations, and enum definitions into `IngestedClassifierDef` data types. Field declarations must be mapped to strongly typed attribute definitions preserving identifier names, field data types, field tags, and multiplicity intervals $`\langle l, u \rangle \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})`$, where fields marked with the `repeated` qualifier map to interval $`\langle 0, \infty \rangle`$, fields with explicit `optional` presence map to $`\langle 0, 1 \rangle`$`, and singular Proto3 fields map to `$`\langle 1, 1 \rangle`$`. Every declared field tag `$`i`$` must strictly satisfy the field tag validity invariant `$`i \in [1, 2^{29}-1] \setminus [19000, 19999]`$`; field tags equal to 0, exceeding `$`2^{29}-1`$` (`$`536{,}870{,}911`$`), or falling within the Protocol Buffer reserved implementation range `$`[19000, 19999]`$ shall be rejected with structured diagnostic code `E0103`. Duplicate field tags within the same message definition are strictly prohibited and shall deterministically trigger diagnostic code `E0102`. Nested message declarations shall be recursively parsed and lowered to hierarchical child classifiers scoped within the namespace of the enclosing parent message. Service declarations shall lower to structural interface components whose RPC methods synthesize `IngestedAction` nodes binding ordered input parameters and output parameters, recording streaming indicators (`stream`) as parameter multiplicity qualifiers. Proto3 enum declarations must enforce the requirement that the first enum constant binds tag 0; any enum missing a 0-tag default constant shall emit diagnostic code `E0103`. All parsed AST entities shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, yielding deterministic node handles with stable relative offsets. In accordance with Architectural Directive 3 and REQ-0036, copying string bytes from the input `.proto` buffer into the global symbol interner pool for scalar symbol tokens during this initial lexical pass is the sole permitted exception to the zero-copy invariant. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the ingestion engine shall implement synchronization token error recovery on statement delimiter boundaries (semicolons `;`, closing braces `}`, or line delimiters $`\text{SYM}_{\text{LF}}`$`), logging structured diagnostics, substituting typed sentinel error nodes (`$`\bot_{\text{msg}}`$`, `$`\bot_{\text{field}}`$`, `$`\bot_{\text{rpc}}`$), and resuming parsing at the subsequent declaration rather than aborting compilation. Multi-file `.proto` compilation units shall be processed in parallel across a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with Architectural Directive 2 and REQ-0012. The ingestion parser must enforce Architectural Directive 5, guaranteeing a total, deterministic, non-panicking execution contract across all inputs. All test models, diagnostic messages, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Message_Alpha`, `Message_Beta`, `Field_1`, `Service_A`, `RPC_Op`, `Classifier_0`, `param_x : Real`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $`\mathcal{P}_{\text{proto}}`$ denote a parsed Protocol Buffer schema definition unit formalized as a 6-tuple:

```math
\mathcal{P}_{\text{proto}} = \langle \mathcal{H}_{\text{syntax}}, \mathcal{N}_{\text{pkg}}, \mathcal{I}_{\text{imp}}, \mathcal{M}, \mathcal{E}, \mathcal{S} \rangle
```

where:
- $`\mathcal{H}_{\text{syntax}} \in \{ \text{"proto3"} \}`$ specifies the mandatory Proto3 language level,
- $`\mathcal{N}_{\text{pkg}} \in \mathcal{S}_{\text{sym}} \cup \{ \bot \}`$ is the optional package namespace symbol,
- $`\mathcal{I}_{\text{imp}} \subset \mathcal{S}_{\text{sym}}`$ is the set of imported schema references,
- $`\mathcal{M} = \{ M_1, M_2, \dots, M_m \}`$ is the set of message definitions,
- $`\mathcal{E} = \{ E_1, E_2, \dots, E_e \}`$ is the set of enum definitions,
- $`\mathcal{S} = \{ S_1, S_2, \dots, S_s \}`$ is the set of service definitions.

The lowering transformation $`\mathcal{T}_{\text{proto}}`$ maps Proto3 syntactic declarations into intermediate schema IR entities:

```math
\begin{aligned}
\text{message } M \{ \dots \} &\longmapsto \text{IngestedPart}(M) \\
\text{field } T \, f = i &\longmapsto \text{IngestedAttr}(f, \text{type}: T, \text{tag}: i, \text{mult}: \mu(f)) \\
\text{rpc } R(A) \text{ returns } (B) &\longmapsto \text{IngestedAction}(R, \text{inputs}: [(A)], \text{outputs}: [(B)]) \\
\text{enum } E \{ \dots \} &\longmapsto \text{IngestedClassifierDef}(E, \text{kind}: \text{Enum})
\end{aligned}
```

Multiplicity mapping function $`\mu : \text{Fields}(M) \longrightarrow \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})`$ is defined as:

```math
\mu(f) = \begin{cases}
\langle 0, \infty \rangle, & \text{if } f \text{ is qualified by repeated} \\
\langle 0, 1 \rangle, & \text{if } f \text{ is qualified by optional} \\
\langle 1, 1 \rangle, & \text{if } f \text{ is singular}
\end{cases}
```

Field Tag Validity Invariant: Every declared field tag $`i = \text{Tag}(f)`$ must reside within the valid Protobuf numeric interval, excluding the implementation reserved range:

```math
\forall M \in \mathcal{M}, \quad \forall f \in \text{Fields}(M), \quad \text{Tag}(f) \in [1, 2^{29}-1] \setminus [19000, 19999]
```

where $`2^{29}-1 = 536{,}870{,}911`$` and `$`[19000, 19999]`$ defines the reserved implementation span.

Field Tag Uniqueness Invariant: Within any message definition $`M \in \mathcal{M}`$, all field tags must be strictly distinct:

```math
\forall M \in \mathcal{M}, \quad \forall f_1, f_2 \in \text{Fields}(M), \quad f_1 \ne f_2 \implies \text{Tag}(f_1) \ne \text{Tag}(f_2)
```

Enum Zero-Value Invariant: Every Proto3 enum definition $`E \in \mathcal{E}`$ must define its first enumerator constant with tag value 0:

```math
\forall E \in \mathcal{E}, \quad \exists v_0 \in \text{Values}(E) \quad (\text{Index}(v_0) = 0 \;\wedge\; \text{Tag}(v_0) = 0)
```

Nested Message Scoping Invariant: For any message $`M_{\text{child}}`$` declared inside parent message `$`M_{\text{parent}}`$, the fully qualified path satisfies:

```math
\forall M_{\text{child}} \in \text{NestedMessages}(M_{\text{parent}}), \quad \text{FQP}(M_{\text{child}}) = \text{FQP}(M_{\text{parent}}) \mathbin{::} \text{name}(M_{\text{child}})
```

Service RPC Parameter Invariant: Each RPC operation $`R \in \text{Methods}(S)`$ defines typed input and output parameter structures:

```math
\begin{aligned}
\text{Inputs}(R) &= \langle \text{param}_{\text{in}}, T_{\text{req}}, \text{mult}_{\text{req}} \rangle \\
\text{Outputs}(R) &= \langle \text{param}_{\text{out}}, T_{\text{resp}}, \text{mult}_{\text{resp}} \rangle
\end{aligned}
```

where streaming modifiers determine parameter multiplicity:

```math
\text{mult}_{\text{req}} = \begin{cases} \langle 0, \infty \rangle, & \text{if streaming} \\ \langle 1, 1 \rangle, & \text{otherwise} \end{cases}, \qquad
\text{mult}_{\text{resp}} = \begin{cases} \langle 0, \infty \rangle, & \text{if streaming} \\ \langle 1, 1 \rangle, & \text{otherwise} \end{cases}
```

Contiguous Arena Allocation Invariant: All synthesized AST entities are allocated in contiguous bump arena memory with deterministic relative offsets:

```math
\forall x \in \mathcal{T}_{\text{proto}}(\mathcal{P}_{\text{proto}}), \quad \text{Allocate}(\text{Arena}, x) = h_x \in \mathcal{H}_{\text{node}}
```

Diagnostic Code Binding Invariant: Syntax and structural violations deterministically construct structured diagnostics in accordance with REQ-0191:

```math
\begin{aligned}
\text{Tag}(f) \notin [1, 2^{29}-1] \setminus [19000, 19999] &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0103}, \text{InvalidFieldTag}) \in \mathcal{D} \\
(\exists f_1 \ne f_2 \in \text{Fields}(M) : \text{Tag}(f_1) = \text{Tag}(f_2)) &\implies \text{Diagnostic}(f_2, \text{DiagnosticCode::E0102}, \text{DuplicateFieldTag}) \in \mathcal{D} \\
\neg (\exists v_0 : \text{Index}(v_0) = 0 \wedge \text{Tag}(v_0) = 0) &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0103}, \text{EnumZeroValueMissing}) \in \mathcal{D} \\
\mathcal{H}_{\text{syntax}} \ne \text{"proto3"} &\implies \text{Diagnostic}(\mathcal{P}_{\text{proto}}, \text{DiagnosticCode::E0100}, \text{UnsupportedSyntaxVersion}) \in \mathcal{D} \\
\text{SyntaxError}(\text{span}) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0100}, \text{ProtoSyntaxError}) \in \mathcal{D}
\end{aligned}
```

Diagnostic Taxonomy Containment Invariant: All emitted diagnostic codes reside strictly within the ingestion family:

```math
\forall D \in \mathcal{D}_{\text{proto}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0100}, \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0103} \} \subset \mathcal{E}_{\text{ingest}}
```

- **Computational Complexity & Algorithmic Bounds**: The Proto3 AST ingestion engine executes within Complexity Class $`\mathbf{P}`$`. Tokenization of the input buffer executes via a deterministic finite-state lexer advancing monotonically without backtracking in `$`O(N)`$` time for an input schema of `$`N`$` bytes. Parsing executes via deterministic recursive descent with a lookahead of at most one token (LL(1)), evaluating grammar productions in `$`O(N)`$` operations. Identifier and keyword interning into the global symbol pool operates in `$`O(L)`$` time for token byte slice of length `$`L \le 256`$`, achieving `$`O(1)`$` amortized time per token. Field tag validation and duplicate tag detection for a message containing `$`F`$` fields evaluate in `$`O(F)`$` time by recording encountered tags in a dense bitset or integer set. Since `$`\sum_{M \in \mathcal{M}} |\text{Fields}(M)| \le N`$`, aggregate tag validation across the entire compilation unit executes in `$`O(N)`$` linear time. Lowering AST nodes into contiguous typed bump arena memory requires a single pointer advance per entity, executing in `$`O(1)`$` constant time per node and `$`O(N)`$` aggregate time. Parsing nesting depth for hierarchical messages is bounded by `$`D \le D_{\text{max}} = 64`$`, ensuring recursive call stack space is strictly bounded by `$`O(D) = O(1)`$` auxiliary stack frames. When compiling `$`K`$ independent `.proto` files across a bounded work-stealing thread pool with $`N_{\text{max\_workers}}`$` workers, parallel wall-clock runtime is bounded by `$`O(\lceil K / N_{\text{max\_workers}} \rceil \cdot N_{\text{max}})`$`. Aggregate sequential execution time is strictly `$`O(N)`$` deterministic linear time in input byte size `$`N`$`, with auxiliary heap space bounded by `$`O(N)`$ for synthesized AST nodes.

- **Verification & Conformance Criteria**: Automated verification suites shall assert 100% parsing accuracy, structural integrity, and diagnostic conformance across synthetic Proto3 schemas using abstract MBSE placeholders (e.g., `Package_0`, `Message_Alpha`, `Message_Beta`, `Field_1`, `Field_2`, `Service_A`, `RPC_Op`, `Enum_0`, `Classifier_Alpha`, `param_x : Real`). Conformance shall be validated through the following deterministic test gates:
  1. Full Schema Ingestion Gate: Ingest a canonical Proto3 file defining messages, scalar fields (`int32`, `int64`, `uint32`, `uint64`, `sint32`, `sint64`, `fixed32`, `fixed64`, `sfixed32`, `sfixed64`, `float`, `double`, `bool`, `string`, `bytes`), complex message fields, enums, and RPC services; assert that 100% of declarations lower into valid `IngestedPart`, `IngestedAttr`, `IngestedClassifierDef`, and `IngestedAction` AST nodes with zero diagnostics.
  2. Multiplicity Mapping Gate: Validate that fields marked `repeated` map to multiplicity interval $`\langle 0, \infty \rangle`$, fields marked `optional` map to $`\langle 0, 1 \rangle`$`, and unmarked singular fields map to `$`\langle 1, 1 \rangle`$.
  3. Field Tag Validity & Upper Limit Gate: Verify that field tags in $`[1, 2^{29}-1] \setminus [19000, 19999]`$ are preserved exactly in synthesized `IngestedAttr` nodes; assert that field tag $`2^{29}-1 = 536{,}870{,}911`$` compiles cleanly, while tag `$`2^{29} = 536{,}870{,}912`$ triggers diagnostic code `E0103`.
  4. Tag Zero & Negative Rejection Gate: Ingest a message declaring a field with tag 0 or negative tag; assert deterministic emission of diagnostic error code `E0103` (`InvalidFieldTag`).
  5. Reserved Tag Rejection Gate: Ingest a message with field tags within $`[19000, 19999]`$ (e.g., tag 19000, 19500, 19999); assert deterministic emission of diagnostic error code `E0103` (`InvalidFieldTag`).
  6. Duplicate Field Tag Rejection Gate: Ingest a message declaring two distinct fields with identical tag numbers (e.g., `int32 Field_1 = 5;` and `string Field_2 = 5;`); assert emission of diagnostic error code `E0102` (`DuplicateFieldTag`) for the conflicting declaration.
  7. Enum Proto3 Zero-Value Gate: Ingest an enum declaration whose first entry has tag 0; assert successful lowering. Ingest an enum whose first entry has tag 1; assert deterministic emission of diagnostic error code `E0103` (`EnumZeroValueMissing`).
  8. Nested Message Scoping Gate: Ingest a top-level message `Message_Alpha` containing nested message `Message_Beta`; assert that the fully qualified path of the nested classifier evaluates to `Message_Alpha::Message_Beta` and child fields resolve in the nested scope.
  9. Service & Streaming RPC Gate: Ingest a service declaring unary and streaming RPC methods (`rpc RPC_1(Message_Alpha) returns (Message_Beta);` and `rpc RPC_2(stream Message_Alpha) returns (stream Message_Beta);`); assert that both methods lower to `IngestedAction` nodes with matching request/response types and streaming multiplicity.
  10. Synchronization Token Error Recovery Gate: Ingest a `.proto` file containing deliberate syntax errors in two declarations (e.g., missing semicolons or corrupted field type tokens); assert that the parser emits exactly two structured diagnostic records (`E0100` or `E0102`), substitutes typed sentinels $`\bot_{\text{field}}`$, synchronizes at subsequent delimiters (`;` or `}`), and successfully extracts all subsequent valid declarations.
  11. Total Non-Panicking Contract & Release Mode Latency Gate: Execute stress tests over malformed, truncated, and randomized UTF-8 byte streams; assert total-function termination with zero panics or crashes. In compiled Release mode (`--release`), evaluate parsing latency under dedicated benchmark harnesses isolated from CI logic tests, asserting throughput exceeding $`50{,}000`$ lines/s and execution latency within the 25 ms compiler budget for files up to 1 MB.
  12. Bitwise Determinism Gate: Repeated compilation passes of identical `.proto` sources across multiple executions and thread configurations shall produce bitwise-identical AST structures with 0-byte diff churn.
