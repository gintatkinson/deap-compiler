### REQ-0127: State Machine Simulation Stepper & Trace Log Generation

- **Normative Statement**: The spatio-temporal dynamics and discrete state machine solver of Subsystem 6 shall provide a deterministic state machine simulation stepper and structured execution trace logger that executes discrete statecharts step-by-step against simulated event traces, producing structured JSON execution logs detailing active state configurations, state entries, state exits, guard evaluations, action executions, and transition firings.

  Specifically, the state machine simulation stepper, execution engine, and trace generator shall strictly enforce the following structural, algebraic, and operational invariants:
  1. **Discrete State Machine Simulation Configuration & State Vector**:
     - The compiler core shall model the dynamic simulation state as an explicit simulation configuration:

```math
       C = \langle \mathcal{S}_{\text{active}}, \mathcal{V}_{\text{env}}, \mathcal{Q}_{\text{events}}, t_{\text{sim}}, \kappa_{\text{step}} \rangle
```

       where $`\mathcal{S}_{\text{active}} \subseteq \mathcal{S}`$` is the active state configuration (set of currently active states satisfying statechart hierarchy: if a composite state is active, its active sub-states form an orthogonal or non-orthogonal tree), `$`\mathcal{V}_{\text{env}}`$` is the valuation environment mapping variable symbols to typed values in contiguous arena memory, `$`\mathcal{Q}_{\text{events}}`$` is the FIFO simulated event queue containing scheduled input events `$`\langle e_1, e_2, \dots \rangle`$`, `$`t_{\text{sim}} \in \mathbb{R}_{\ge 0}`$` is the simulation timestamp (or discrete tick count `$`\tau_{\text{tick}} \in \mathbb{N}_{64}`$`), and `$`\kappa_{\text{step}} \in \mathbb{N}_{64}`$ is the monotonic macro-step counter.
     - The stepper shall initialize the simulation at step $`\kappa_{\text{step}} = 0`$` with initial configuration `$`C_0`$` derived from the designated root initial state `$`s_0`$, recursively activating initial default sub-states and executing initial entry actions.
  2. **Step-by-Step Micro-Step and Macro-Step Semantics**:
     - The simulation stepper shall execute in discrete macro-steps and micro-steps adhering to deterministic statechart execution semantics:
       - *Event Dequeue*: At macro-step $`k`$`, the stepper dequeues the head event `$`e_k \in \mathcal{Q}_{\text{events}}`$` (or processes a completion / spontaneous event `$`\epsilon`$ if an active state has completed).
       - *Candidate Transition Selection & Guard Evaluation*: The stepper inspects all candidate transitions originating from active states $`s \in \mathcal{S}_{\text{active}}`$`. For each candidate transition `$`T`$`, its guard predicate `$`g_T`$` is evaluated in valuation environment `$`\mathcal{V}_{\text{env}}`$`. If `$`g_T`$` evaluates to true, `$`T`$ is marked viable.
       - *Preemptive Priority & Conflict Resolution*: If multiple candidate transitions are viable within the same orthogonal region, conflict resolution shall be strictly deterministic:
         1. *Hierarchical Scope*: Sub-state transitions take precedence over enclosing super-state transitions (inner-first semantics), unless overridden by emergency failsafe priority per REQ-0125.
         2. *Explicit Priority*: Between competing transitions at the same hierarchical scope, the transition with strictly greater priority ($`\pi(T_1) \gt \pi(T_2)`$) preempts lower-priority transitions.
         3. *Topological Determinism*: If priorities are identical, ties shall be resolved deterministically using canonical lexicographical ordering of interned symbol fully qualified names (FQN).
       - *Least Common Ancestor (LCA) State Exit Sequence*: The stepper determines the Least Common Ancestor (LCA) between source state $`s_{\text{src}}`$` and target state `$`s_{\text{tgt}}`$`. Active states along the exited branch are exited in strict bottom-up sequence (innermost active leaf state first, up to the LCA). For each exited state `$`s`$`, its declared exit action `$`A_{\text{exit}}(s)`$` is executed, and `$`s`$` is removed from `$`\mathcal{S}_{\text{active}}`$.
       - *Transition Action Execution*: The transition action effect $`A_{\text{trans}}(T)`$` is executed atomically, updating variable valuations in `$`\mathcal{V}_{\text{env}}`$.
       - *State Entry Sequence*: States along the entry path from LCA down to target state $`s_{\text{tgt}}`$` are entered in strict top-down sequence (outermost first down to `$`s_{\text{tgt}}`$`). For each entered state `$`s`$`, its declared entry action `$`A_{\text{entry}}(s)`$` is executed, and `$`s`$` is added to `$`\mathcal{S}_{\text{active}}`$.
       - *Default Sub-State Expansion*: If $`s_{\text{tgt}}`$` is a composite state, its designated default initial sub-state `$`s_{0,\text{child}}`$ is entered recursively.
       - *Spontaneous Micro-Step Fixed-Point*: Any completion transitions ($`\epsilon`$`-transitions) enabled following state entry shall be evaluated as micro-steps until reaching a quiescent stable configuration. Unbounded completion loops shall be terminated at maximum micro-step bound `$`\kappa_{\text{micro\_max}}`$ emitting diagnostic error code `E0400` (`SimulationMicroStepLimitExceeded`).
  3. **Deterministic Structured JSON Trace Log Generation**:
     - The stepper shall generate an immutable, structured JSON execution log (`TraceLog`) recording every simulation step with zero diff churn.
     - Each step record within the generated JSON trace log shall contain the following deterministic schema fields:
       - `step_index` ($`\mathbb{N}_{64}`$): Monotonic simulation macro-step sequence number.
       - `timestamp` ($`\mathbb{R}_{64}`$`): Simulated time `$`t_{\text{sim}}`$ or discrete tick count.
       - `pre_configuration`: Array of active state fully qualified names before step execution.
       - `consumed_event`: Event identifier, payload attribute dictionary, and source provenance.
       - `guard_evaluations`: Array of evaluated candidate transitions with boolean evaluation results (`true` or `false`) and operand variable valuations.
       - `fired_transition`: The selected transition identifier, UUIDv5, source state, target state, and discrete priority.
       - `exited_states`: Ordered array of exited states in exact execution sequence.
       - `executed_actions`: Ordered array of executed action identifiers (exit actions, transition action, entry actions) and resultant environment updates $`\Delta \mathcal{V}_{\text{env}}`$.
       - `entered_states`: Ordered array of entered states in exact execution sequence.
       - `post_configuration`: Array of active state fully qualified names after step completion.
       - `status`: Execution status enumeration (`Status::Success`, `Status::Quiescent`, `Status::Terminal`, `Status::Fault`).
     - The JSON document shall be serialized using deterministic key ordering, ASCII UTF-8 encoding, and standardized indentation (or newline-delimited JSON streaming format for long-running traces).
  4. **Quiescence, Terminal Detection & Fault Diagnostics**:
     - If an event $`e \in \mathcal{Q}_{\text{events}}`$` is dequeued and zero transitions are enabled (`$`T = \emptyset`$), the stepper shall record a quiescent step (`Status::Quiescent`), leaving configuration $`C`$ unchanged and advancing to the next queued event.
     - If the active configuration contains a designated final state ($`s \in \mathcal{S}_{\text{final}}`$`) and the event queue is empty (`$`\mathcal{Q}_{\text{events}} = \emptyset`$), the simulation halts with terminal status `Status::Terminal`.
     - If guard evaluation encounters an undefined variable, type incompatibility, or division by zero, the stepper records `Status::Fault` and emits diagnostic error code `E0400` (`SimulationGuardEvaluationFault`).
  5. **Compliance with the 5 Executive Architectural Directives**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every trace log entry, step record, state machine entity, transition descriptor, event instance, and action execution record shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical DEAP namespace OID and node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))`$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel execution of batch simulation runs, parametric scenario sweeps, and independent state machine trace evaluations shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Memory Allocation Exception)*: State names, event symbols, action identifiers, and fully qualified path segments shall be interned into the deduplicated global symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The simulation trace parser and event ingestion engine shall implement synchronization token error recovery on statement delimiters (`;`) and trace step delimiters (`}`). When malformed trace inputs or guard evaluation faults occur (`E0400`), diagnostics shall accumulate in the error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinels (`$`\bot_{\text{step}}`$`, `$`\bot_{\text{trace}}`$`), and continue validating subsequent steps. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Isolation)*: The simulation stepper and trace logging engine shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Simulation throughput ($`\lt 25\text{ ms}`$` for `$`10^4`$` simulation steps) and peak RSS memory (`$`\lt 100\text{ MB}`$) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `StateMachine_Alpha`, `StateMachine_Beta`, `State_Alpha`, `State_Beta`, `State_Gamma`, `State_Active_0`, `State_Active_1`, `State_Comp_0`, `State_Child_0`, `State_Final_Omega`, `Transition_1`, `Transition_2`, `Event_0`, `Event_1`, `Event_Step`, `Action_0`, `Action_1`, `Port_1`, `Flow_A`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous arena storage.

  A discrete statechart machine $`\mathcal{M}`$ is formalized as an 8-tuple:

```math
  \mathcal{M} = \langle \mathcal{S}, \mathcal{T}, \mathcal{E}, \mathcal{A}, s_0, \mathcal{S}_{\text{final}}, \sqsubset, \pi \rangle
```

  where:

```math
  \begin{aligned}
  \mathcal{S} &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of state entities}) \\
  \mathcal{T} &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of directed transitions}) \\
  \mathcal{E} &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of event symbols}) \\
  \mathcal{A} &\subset \mathcal{V}_{\text{AST}} \quad (\text{finite set of action definitions}) \\
  s_0 &\in \mathcal{S} \quad (\text{designated unique root initial state}) \\
  \mathcal{S}_{\text{final}} &\subseteq \mathcal{S} \quad (\text{set of declared terminal/final states}) \\
  \sqsubset &\subset \mathcal{S} \times \mathcal{S} \quad (\text{irreflexive parent-child state containment relation}) \\
  \pi &: \mathcal{T} \to \mathbb{N}_{32} \quad (\text{discrete priority assignment function})
  \end{aligned}
```

  A simulation configuration $`C \in \mathcal{C}`$` at step `$`\kappa_{\text{step}}`$ is formalized as a 5-tuple:

```math
  C = \langle \mathcal{S}_{\text{active}}, \mathcal{V}_{\text{env}}, \mathcal{Q}_{\text{events}}, t_{\text{sim}}, \kappa_{\text{step}} \rangle
```

  where:

```math
  \begin{aligned}
  \mathcal{S}_{\text{active}} &\subseteq \mathcal{S} \quad (\text{active state configuration vector}) \\
  \mathcal{V}_{\text{env}} &: \text{Var} \to \text{Val} \quad (\text{variable valuation mapping}) \\
  \mathcal{Q}_{\text{events}} &\in \text{Queue}(\mathcal{E} \times \mathcal{V}_{\text{payload}}) \quad (\text{FIFO simulated event queue}) \\
  t_{\text{sim}} &\in \mathbb{R}_{\ge 0} \quad (\text{simulated physical timestamp or clock tick}) \\
  \kappa_{\text{step}} &\in \mathbb{N}_{64} \quad (\text{monotonic simulation step counter})
  \end{aligned}
```

  Initial Configuration Invariant:

```math
  C_0 = \langle \text{InitActive}(s_0), \mathcal{V}_0, \mathcal{Q}_0, 0.0, 0 \rangle
```

  where $`\text{InitActive}(s)`$ recursively activates default sub-states:

```math
  \text{InitActive}(s) = \{ s \} \cup \bigcup_{s' \in \{ c \in \mathcal{S} \mid c \sqsubset s \land \text{is\_initial}(c) \}} \text{InitActive}(s')
```

  Candidate Transition Selection Function:

```math
  \text{Enabled}(C, e) = \{ T \in \mathcal{T} \mid s_{\text{src}}(T) \in \mathcal{S}_{\text{active}} \land e_{\text{trig}}(T) = e \land \text{Eval}(g_T, \mathcal{V}_{\text{env}}) \equiv \text{true} \}
```

  Deterministic Transition Resolution Operator $`\text{Select}`$:

```math
  T^* = \text{Select}(\text{Enabled}(C, e)) = \arg\max_{T \in \text{Enabled}(C, e)} \langle \pi(T), \text{Depth}(s_{\text{src}}(T)), -\text{FQN}(T) \rangle
```

  Least Common Ancestor ($`\text{LCA}`$) and State Traversal Paths:

```math
  \text{LCA}(s_1, s_2) = \arg\max_{a \in (\text{anc}(s_1) \cup \{s_1\}) \cap (\text{anc}(s_2) \cup \{s_2\})} \text{Depth}(a)
```

```math
  \begin{aligned}
  \text{ExitPath}(s_{\text{src}}, s_{\text{tgt}}) &= \{ s \in \mathcal{S}_{\text{active}} \mid s \sqsubset^+ \text{LCA}(s_{\text{src}}, s_{\text{tgt}}) \} \quad (\text{ordered bottom-up by descending depth}) \\
  \text{EntryPath}(s_{\text{src}}, s_{\text{tgt}}) &= \{ s \in \text{InitActive}(s_{\text{tgt}}) \mid s \sqsubset^+ \text{LCA}(s_{\text{src}}, s_{\text{tgt}}) \} \quad (\text{ordered top-down by ascending depth})
  \end{aligned}
```

  Single-Step Statechart Stepper Transformation $`\text{Step}`$:

```math
  \text{Step}(C, e) = \langle C', \sigma \rangle
```

  where:

```math
  \begin{aligned}
  \mathcal{S}'_{\text{active}} &= (\mathcal{S}_{\text{active}} \setminus \text{ExitPath}(s_{\text{src}}(T^*), s_{\text{tgt}}(T^*))) \cup \text{EntryPath}(s_{\text{src}}(T^*), s_{\text{tgt}}(T^*)) \\
  \mathcal{V}'_{\text{env}} &= \text{ExecActions}(A_{\text{entry}}, \text{ExecActions}(A_{\text{trans}}(T^*), \text{ExecActions}(A_{\text{exit}}, \mathcal{V}_{\text{env}}))) \\
  \mathcal{Q}'_{\text{events}} &= \text{tail}(\mathcal{Q}_{\text{events}}) \\
  t'_{\text{sim}} &= t_{\text{sim}} + \Delta t \\
  \kappa'_{\text{step}} &= \kappa_{\text{step}} + 1
  \end{aligned}
```

  Step Record $`\sigma`$ Formalization:

```math
  \sigma = \langle \kappa_{\text{step}}, t_{\text{sim}}, \mathcal{S}_{\text{active}}, e, \text{Enabled}(C, e), T^*, \text{ExitPath}, A_{\text{exec}}, \text{EntryPath}, \mathcal{S}'_{\text{active}}, \text{status} \rangle
```

  Complete Trace Log Vector:
  Given input event sequence $`\vec{e} = \langle e_1, e_2, \dots, e_m \rangle`$, the generated simulation trace log is:

```math
  \text{Trace}(\vec{e}) = \langle \sigma_1, \sigma_2, \dots, \sigma_m \rangle
```

  Deterministic JSON Bijective Serialization Mapping:

```math
  \mathcal{J} : \text{Trace}(\vec{e}) \to \mathbb{S}_{\text{JSON}}
```

  Bitwise Determinism Invariant:

```math
  \forall \mathcal{M}, \vec{e}, \quad \text{Simulate}(\mathcal{M}, \vec{e})_1 = \text{Simulate}(\mathcal{M}, \vec{e})_2 \implies \mathcal{J}(\text{Trace}(\vec{e}))_1 = \mathcal{J}(\text{Trace}(\vec{e}))_2
```

  Deterministic Diagnostic Emission Invariant (REQ-0191):

```math
  \begin{aligned}
  \exists T \in \text{Enabled}(C, e) : \text{Eval}(g_T, \mathcal{V}_{\text{env}}) = \bot_{\text{eval}} &\implies \text{Diagnostic}(T, \text{DiagnosticCode::E0400}, \text{SimulationGuardEvaluationFault}) \in \mathcal{D}_{\text{sink}} \\
  \kappa_{\text{micro}} \gt \kappa_{\text{micro\_max}} &\implies \text{Diagnostic}(\mathcal{M}, \text{DiagnosticCode::E0400}, \text{SimulationMicroStepLimitExceeded}) \in \mathcal{D}_{\text{sink}} \\
  |\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
  \end{aligned}
```

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
  \begin{aligned}
  \forall \sigma_k \in \text{Trace}(\vec{e}), &\quad \Delta_{\sigma_k} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(\mathcal{M}) \mathbin{\Vert} \text{String}(\kappa_k)) \\
  \forall s \in \mathcal{S}, &\quad \Delta_s = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(s)) \\
  \forall T \in \mathcal{T}, &\quad \Delta_T = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(T))
  \end{aligned}
```

- **Computational Complexity & Algorithmic Bounds**: State machine simulation stepping, deterministic transition resolution, hierarchical path evaluation, and structured JSON trace log generation reside strictly in **Complexity Class P** (Deterministic Polynomial Time).

  **Mathematical Delineation from Algorithmic Bound NP-5**:
  In concurrent statecharts containing $`K`$` orthogonal parallel regions, reachability analysis, deadlock freedom, and livelock detection is PSPACE-complete (or NP-complete under bounded depth unrolling `$`k \le k_{\text{max}}`$), as formalized under Algorithmic Bound NP-5 (REQ-0124) via SAT-based Bounded Model Checking (BMC). This exponential state explosion arises because verification must exhaustively explore the combinatorial Cartesian product state space:

```math
  |\mathcal{S}_{\text{global}}| = \prod_{i=1}^K |\mathcal{S}_i|
```

  In contrast, REQ-0127 executes a single, concrete, deterministic simulation trajectory along an explicit sequence of $`m`$` input events. No state-space unrolling, branching exploration, backtracking, or SAT solving is performed. Each simulation step evaluates only the currently active state configuration and its immediate outgoing transitions, operating in strictly linear time relative to trace length `$`m`$.

  **Asymptotic Complexity Analysis**:
  Let $`V = |\mathcal{S}|`$` denote the total number of state nodes, `$`E = |\mathcal{T}|`$` denote the total number of transitions, and `$`h`$` represent the maximum containment tree depth (`$`h \le 32 \ll V`$` in valid MBSE models). Let `$`\Delta_{\max}`$` denote the maximum out-degree of any state node, and let `$`m`$` denote the number of events in the simulated event sequence `$`\vec{e}`$.
  1. *Candidate Transition Evaluation & Guard Checking*:
     At each simulation step, the active state set has size bounded by $`|\mathcal{S}_{\text{active}}| \le h \cdot K`$`, where `$`K`$` is the number of orthogonal regions (`$`K \le 8`$`). The total number of candidate transitions inspected is at most `$`h \cdot K \cdot \Delta_{\max} \in O(1)`$`. Evaluating boolean guard AST expressions requires `$`O(|g|)`$` operations per candidate transition, bounded by `$`O(1)`$ for standard constraint predicates.
  2. *Least Common Ancestor (LCA) & Path Resolution*:
     Computing the LCA of source and target states on the hierarchical containment tree requires traversing ancestor chains of depth at most $`h`$:

```math
     T_{\text{LCA}}(h) \in O(h) \subseteq O(1)
```

  3. *Action Sequence Execution*:
     Executing exit actions, transition action effects, and entry actions involves sequential evaluation of bounded assignment expressions without unbounded loops:

```math
     T_{\text{actions}}(|A|) \in O(|A|) \subseteq O(1)
```

  4. *Single Macro-Step Time Complexity*:
     Combining candidate inspection, guard evaluation, LCA traversal, action execution, and active set update yields a bounded single-step execution time:

```math
     T_{\text{step}}(h, \Delta_{\max}, |A|) \in O(h \cdot \Delta_{\max} + |A|) \subseteq O(1)
```

  5. *Aggregate Simulation Time Complexity for Trace of Length $`m`$*:
     For an input event trace comprising $`m`$ events, total simulation time is strictly linear in the length of the event sequence:

```math
     T_{\text{sim}}(m, V, E) \in O(m \cdot (h \cdot \Delta_{\max} + |A|)) = O(m)
```

  6. *Structured JSON Log Serialization Complexity*:
     Streaming serialization of each step record produces $`O(|\sigma|)`$` bytes, where `$`|\sigma| \in O(h + |A|)`$`. Total serialization time across `$`m`$ steps is:

```math
     T_{\text{JSON}}(m) \in O(m)
```

  7. *Parallel Scenario Sweeps Scaling (Architectural Directive 2)*:
     When executing $`P`$` independent scenario simulation traces across `$`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool:

```math
     T_{\text{parallel}}(m, P, N_{\text{max\_workers}}) \in O\left( \frac{m \cdot P}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  8. *Space Complexity & Arena Memory Bounds*:
     The simulation configuration maintains active state handles and environment variable valuations, consuming $`O(h + |\mathcal{V}_{\text{env}}|) = O(1)`$` working memory. In streaming emission mode, the trace log requires `$`O(1)`$` buffer memory overhead; if retained in memory, the log consumes `$`O(m)`$` contiguous bytes. The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ capacity.
