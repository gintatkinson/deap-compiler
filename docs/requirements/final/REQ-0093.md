### REQ-0093: KerML Standard Library: `Collections` Package (Set, Sequence, OrderedSet, Bag)

#### 1. Normative Statement

The Core Metamodel, Node Arena & AST Graph Engine, KerML Metamodel Lowering Engine, and Semantic Type Checker shall bootstrap and lower the normative KerML `Collections` standard library package into the compiler root symbol environment prior to ingesting user compilation units. The `Collections` package shall provide generic collection types parameterizing over an arbitrary element classifier $`T`$` (`$`\mathcal{C}\langle T \rangle`$`), structured along two orthogonal Boolean metadata dimensions: `$`\text{isUnique}`$` (enforcing element set distinction) and `$`\text{isOrdered}`$ (enforcing sequence order preservation).

  The compiler shall strictly enforce the following normative provisions:
  1. **Canonical Collection Type Matrix**:
     - The abstract root classifier shall be `Collection<T>` (specializing KerML `DataType`, `Classifier`, and `Type`), defining common collection semantics.
     - The collection taxonomy shall instantiate four concrete generic collection classifiers categorized along $`(\text{isUnique}, \text{isOrdered})`$:
       - **`Set<T>`**: $`\text{isUnique} = \text{true}, \text{isOrdered} = \text{false}`$`, denoting an unordered mathematical set of unique elements of type `$`T`$.
       - **`Sequence<T>`**: $`\text{isUnique} = \text{false}, \text{isOrdered} = \text{true}`$`, denoting an ordered list of elements of type `$`T`$ where duplicate elements are permitted.
       - **`OrderedSet<T>`**: $`\text{isUnique} = \text{true}, \text{isOrdered} = \text{true}`$`, denoting an ordered sequence of unique elements of type `$`T`$.
       - **`Bag<T>`**: $`\text{isUnique} = \text{false}, \text{isOrdered} = \text{false}`$`, denoting an unordered multiset of elements of type `$`T`$ where duplicate elements are permitted.
  2. **Metamodel Subtyping Lattice & Multiple Inheritance**:
     - All collection classifiers shall specialize root `Collection<T>`: $`\text{Set}\langle T \rangle \le \text{Collection}\langle T \rangle`$`, `$`\text{Sequence}\langle T \rangle \le \text{Collection}\langle T \rangle`$`, `$`\text{OrderedSet}\langle T \rangle \le \text{Collection}\langle T \rangle`$`, and `$`\text{Bag}\langle T \rangle \le \text{Collection}\langle T \rangle`$.
     - `OrderedSet<T>` shall specialize both `Set<T>` and `Sequence<T>` via multiple inheritance in the subtyping meet-semilattice, establishing that an ordered set satisfies both set uniqueness and sequence ordering invariants ($`\text{OrderedSet}\langle T \rangle \le \text{Set}\langle T \rangle \wedge \text{OrderedSet}\langle T \rangle \le \text{Sequence}\langle T \rangle`$).
     - `Set<T>` shall specialize `Bag<T>` ($`\text{Set}\langle T \rangle \le \text{Bag}\langle T \rangle`$), formalizing that every set is an unordered multiset with element multiplicity at most 1.
  3. **Covariant Subtyping Semantics**:
     - KerML collections shall denote pure immutable mathematical values with value semantics. Because collections are immutable and referentially transparent, all collection classifiers shall be strictly covariant with respect to their element type parameter $`T`$`: for any classifiers `$`T_1`$` and `$`T_2`$`, `$`T_1 \le T_2 \implies \mathcal{C}\langle T_1 \rangle \le \mathcal{C}\langle T_2 \rangle`$` for all `$`\mathcal{C} \in \{ \text{Collection}, \text{Set}, \text{Sequence}, \text{OrderedSet}, \text{Bag} \}`$.
     - Any attempt to assign, bind, or pass a collection $`\mathcal{C}\langle T_{\text{actual}} \rangle`$` where `$`T_{\text{actual}} \not\le T_{\text{expected}}`$ shall be statically rejected at compile time with diagnostic error code `E0200` (`CollectionSubtypingViolation`).
  4. **Generic Instantiation, Deduplication & Typing Conformance**:
     - Generic parameter $`T`$ shall resolve to a valid, accessible classifier in the enclosing scope. Declaring a collection with an unresolvable type parameter shall trigger diagnostic error code `E0200` (`UnresolvedCollectionTypeArgument`).
     - When lowering collection literals, constructor invocations, or default values, the compiler shall verify that every member element expression $`e_i`$` conforms to element type `$`T`$` (`$`\tau(e_i) \le T`$). Incompatible elements shall be rejected with diagnostic error code `E0200` (`CollectionElementTypeMismatch`).
     - Generic instantiations with identical collection kind and type argument $`T`$` shall be canonicalized and memoized within the contiguous arena storage, guaranteeing identical arena node handles and `$`O(1)`$ identity checks.
  5. **Standard Functional Operations & Directionality Invariants**:
     - The package shall define pure, side-effect-free functional operations (specializing KerML `Function`):
       - *Introspection Queries*: `size(c : Collection<T>) : Integer`, `isEmpty(c : Collection<T>) : Boolean`, `notEmpty(c : Collection<T>) : Boolean`, `includes(c : Collection<T>, element : T) : Boolean`, `excludes(c : Collection<T>, element : T) : Boolean`, `count(c : Collection<T>, element : T) : Integer`, `includesAll(c1 : Collection<T>, c2 : Collection<T>) : Boolean`, `excludesAll(c1 : Collection<T>, c2 : Collection<T>) : Boolean`.
       - *Sequence Operations*: `get(seq : Sequence<T>, index : Integer) : T`, `first(seq : Sequence<T>) : T`, `last(seq : Sequence<T>) : T`, `indexOf(seq : Sequence<T>, element : T) : Integer`, `subSequence(seq : Sequence<T>, start : Integer, end : Integer) : Sequence<T>`, `append(seq : Sequence<T>, element : T) : Sequence<T>`, `prepend(seq : Sequence<T>, element : T) : Sequence<T>`, `reverse(seq : Sequence<T>) : Sequence<T>`. Static literal indexing with constant index $`i \lt 1`$` or `$`i \gt |seq|`$ shall trigger diagnostic error code `E0200` (`SequenceIndexOutOfBounds`).
       - *Set-Theoretic Algebraic Operations*: `union`, `intersection`, `difference`, `symmetricDifference`. Incompatible operand types shall trigger diagnostic error code `E0200` (`CollectionAlgebraicOperandMismatch`).
       - *Higher-Order Functional Combinators*: `select(c, predicate)`, `reject(c, predicate)`, `collect(c, transform)`, `forAll(c, predicate)`, `exists(c, predicate)`, `reduce(c, initial, accumulator)`. Predicate expressions must evaluate to `Boolean`; non-Boolean predicates shall trigger diagnostic error code `E0200` (`CollectionPredicateTypeMismatch`).
     - All collection operation parameters must declare immutable `In` directionality ($`\text{dir}(p) = \text{In}`$). Declaring mutating `InOut` or `Out` parameters shall trigger diagnostic error code `E0201` (`InvalidCollectionParameterDirection`).
  6. **Acyclicity & Dependency Verification**:
     - Mutually recursive generic collection type aliases or definitions lacking base-case stratification shall be detected via Tarjan's strongly connected components algorithm and rejected at compile time with diagnostic error code `E0203` (`CircularCollectionTypeDependency`).
  7. **Total-Function Error Recovery & Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every bootstrapped collection classifier, instantiated generic collection type, and collection operation AST node shall receive a deterministic RFC 4122 UUIDv5 identifier generated by namespace-hashing the node fully qualified topological path with the canonical compiler namespace OID per REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel lowering, type inference, and validation of independent collection definitions and usages across packages shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
     - *Directive 3 (String Interner Allocation Exception)*: Interning string bytes for package, type, feature, and operation names into the global symbol interner pool per REQ-0036 is the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The lowering engine shall implement synchronization token error recovery per REQ-0013 and REQ-0016: upon detecting an invalid collection parameter, element type mismatch (`E0200`), direction violation (`E0201`), or cyclic dependency (`E0203`), the engine shall record structured diagnostics into diagnostic sink $`\mathcal{D}_{\text{sink}}`$`, substitute typed error sentinel `$`\bot_{\text{type}}`$`, and resynchronize at the next delimiter token. If accumulated diagnostics reach capacity limit `$`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully.
     - *Directive 5 (Panic-Free Release Isolation)*: The compiler shall strictly enforce a deterministic, non-panicking execution contract with total-function termination across all inputs. Performance latency ($`\lt 25\text{ ms}`$`) and peak memory RSS (`$`\lt 100\text{ MB}`$` for `$`10^4`$ collection declarations and operations) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.
     - *Domain Purity*: All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Classifier_Delta`, `Collection_0`, `Set_Alpha`, `Seq_Beta`, `Bag_Gamma`, `OrderedSet_Delta`, `param_x : Real`, `param_y : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

#### 2. Formal Invariant

Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage. Let `$`\mathcal{T}_{\text{coll}} = \{ \text{Collection}, \text{Set}, \text{Sequence}, \text{OrderedSet}, \text{Bag} \} \subset \mathcal{C}`$ denote the set of bootstrapped collection classifier definitions.

  Generic collection types parameterize over element type $`T \in \mathcal{T} \setminus \{ \bot_{\text{type}} \}`$`: `$`\mathcal{C}\langle T \rangle`$`. The collection matrix partitions along the two orthogonal Boolean dimensions `$`(\text{isUnique}, \text{isOrdered}) \in \mathbb{B} \times \mathbb{B}`$:

```math
\begin{aligned}
\text{Set}\langle T \rangle &: \text{isUnique} = \text{true}, \quad \text{isOrdered} = \text{false} \\
\text{Sequence}\langle T \rangle &: \text{isUnique} = \text{false}, \quad \text{isOrdered} = \text{true} \\
\text{OrderedSet}\langle T \rangle &: \text{isUnique} = \text{true}, \quad \text{isOrdered} = \text{true} \\
\text{Bag}\langle T \rangle &: \text{isUnique} = \text{false}, \quad \text{isOrdered} = \text{false}
\end{aligned}
```

  Each instantiated generic collection type node $`C_{\text{coll}} \in \mathcal{V}_{\text{AST}}`$ is formalized as an 8-tuple:

```math
C_{\text{coll}} = \langle \text{id}_C, \text{name}_C, \text{kind}_C, T_C, \text{isUnique}_C, \text{isOrdered}_C, \Delta_C, \text{span}_C \rangle
```

  where:

```math
\begin{aligned}
\text{id}_C &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_C &\in \mathcal{S}_{\text{intern}} \quad (\text{interned scalar symbol identifier}) \\
\text{kind}_C &\in \mathcal{T}_{\text{coll}} \quad (\text{collection taxonomic kind}) \\
T_C &\in \mathcal{T} \setminus \{ \bot_{\text{type}} \} \quad (\text{bound element classifier handle}) \\
\text{isUnique}_C &\in \mathbb{B} \quad (\text{element uniqueness invariant}) \\
\text{isOrdered}_C &\in \mathbb{B} \quad (\text{element sequence ordering invariant}) \\
\Delta_C &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
\text{span}_C &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

  Metamodel Subtyping Lattice & Multiple Inheritance Invariants:

```math
\begin{aligned}
\forall T \in \mathcal{T}, &\quad \text{OrderedSet}\langle T \rangle \le \text{Set}\langle T \rangle \le \text{Bag}\langle T \rangle \le \text{Collection}\langle T \rangle \\
\forall T \in \mathcal{T}, &\quad \text{OrderedSet}\langle T \rangle \le \text{Sequence}\langle T \rangle \le \text{Collection}\langle T \rangle \\
\forall T \in \mathcal{T}, &\quad \text{OrderedSet}\langle T \rangle = \text{Set}\langle T \rangle \wedge \text{Sequence}\langle T \rangle
\end{aligned}
```

  Subtyping Covariance Invariant:

```math
\forall \mathcal{C} \in \mathcal{T}_{\text{coll}}, \quad \forall T_1, T_2 \in \mathcal{T}, \quad T_1 \le T_2 \implies \mathcal{C}\langle T_1 \rangle \le \mathcal{C}\langle T_2 \rangle
```

  Denotational Value Semantics over Instance Universe $`\mathcal{U}`$:
  Let $`\llbracket T \rrbracket \subseteq \mathcal{U}`$` denote the value set of type `$`T`$. The instance denotation functions map collection types to finite mathematical structures:

```math
\begin{aligned}
\llbracket \text{Set}\langle T \rangle \rrbracket &= \{ S \subseteq \llbracket T \rrbracket \mid |S| \lt \infty \} \\
\llbracket \text{Sequence}\langle T \rangle \rrbracket &= \{ \sigma \in \llbracket T \rrbracket^* \mid |\sigma| \lt \infty \} \\
\llbracket \text{OrderedSet}\langle T \rangle \rrbracket &= \{ \sigma \in \llbracket T \rrbracket^* \mid |\sigma| \lt \infty \;\wedge\; (\forall i, j \in [1, |\sigma|], \, i \ne j \implies \sigma[i] \ne \sigma[j]) \} \\
\llbracket \text{Bag}\langle T \rangle \rrbracket &= \{ B : \llbracket T \rrbracket \to \mathbb{N}_0 \mid \sum_{x \in \llbracket T \rrbracket} B(x) \lt \infty \}
\end{aligned}
```

  Algebraic Properties of Functional Collection Operations:

```math
\begin{aligned}
|c| &= \begin{cases} |S| & c = S \in \llbracket \text{Set}\langle T \rangle \rrbracket \\ \text{length}(\sigma) & c = \sigma \in \llbracket \text{Sequence}\langle T \rangle \rrbracket \\ \sum_{x} B(x) & c = B \in \llbracket \text{Bag}\langle T \rangle \rrbracket \end{cases} \\
\text{isEmpty}(c) &\iff |c| = 0 \\
\text{notEmpty}(c) &\iff |c| \gt 0 \\
\text{includes}(c, x) &\iff \begin{cases} x \in S & c = S \\ \exists i \in [1, |\sigma|] : \sigma[i] = x & c = \sigma \\ B(x) \gt 0 & c = B \end{cases} \\
\text{excludes}(c, x) &\iff \neg \text{includes}(c, x)
\end{aligned}
```

  Higher-Order Functional Combinator Formalisms:

```math
\begin{aligned}
\llbracket \text{select}(c, P) \rrbracket &= \begin{cases} \{ x \in S \mid P(x) = \text{true} \} & c = S \\ [ \sigma[i] \mid i \in [1, |\sigma|] \;\wedge\; P(\sigma[i]) = \text{true} ] & c = \sigma \\ B' \text{ where } B'(x) = [P(x) = \text{true}] \cdot B(x) & c = B \end{cases} \\
\llbracket \text{reject}(c, P) \rrbracket &= \llbracket \text{select}(c, \neg P) \rrbracket \\
\llbracket \text{collect}(c, f) \rrbracket &= \begin{cases} \{ f(x) \mid x \in S \} & c = S \\ [ f(\sigma[i]) \mid i \in [1, |\sigma|] ] & c = \sigma \\ B' \text{ where } B'(y) = \sum_{x \in f^{-1}(y)} B(x) & c = B \end{cases} \\
\text{forAll}(c, P) &\iff \forall x \in c, \, P(x) = \text{true} \\
\text{exists}(c, P) &\iff \exists x \in c, \, P(x) = \text{true}
\end{aligned}
```

  Sequence Index Access Formalism:

```math
\text{get}(\sigma, i) = \sigma[i] \quad \text{subject to } 1 \le i \le |\sigma|
```

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Architectural Directive 1):

```math
\begin{aligned}
\Delta(\mathcal{C}_{\text{base}}) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{\_Collections\_::\_} \mathbin{\Vert} \text{name}(\mathcal{C}_{\text{base}})) \\
\Delta(\mathcal{C}\langle T \rangle) &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{\_Collections\_::\_} \mathbin{\Vert} \text{kind}(\mathcal{C}) \mathbin{\Vert} \text{\_<} \mathbin{\Vert} \text{FQN}(T) \mathbin{\Vert} \text{\_>})
\end{aligned}
```

  Diagnostic Code Trigger Invariants per REQ-0191:

```math
\begin{aligned}
T \notin \mathcal{T} \vee T = \bot_{\text{type}} &\implies \text{Diagnostic}(\mathcal{C}\langle T \rangle, \text{DiagnosticCode::E0200}, \text{UnresolvedCollectionTypeArgument}) \in \mathcal{D}_{\text{sink}} \\
\exists e_i \in \text{elements}(c) : \tau(e_i) \not\le T &\implies \text{Diagnostic}(e_i, \text{DiagnosticCode::E0200}, \text{CollectionElementTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\tau(c_{\text{src}}) \not\le \tau(c_{\text{dst}}) &\implies \text{Diagnostic}(c_{\text{src}}, \text{DiagnosticCode::E0200}, \text{CollectionSubtypingViolation}) \in \mathcal{D}_{\text{sink}} \\
\tau(P) \not\le (T \to \text{Boolean}) &\implies \text{Diagnostic}(P, \text{DiagnosticCode::E0200}, \text{CollectionPredicateTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\text{isConstant}(idx) \;\wedge\; (idx \lt 1 \vee idx \gt |seq|) &\implies \text{Diagnostic}(idx, \text{DiagnosticCode::E0200}, \text{SequenceIndexOutOfBounds}) \in \mathcal{D}_{\text{sink}} \\
\exists p \in \mathcal{P}_{\text{op}} : \text{dir}(p) \ne \text{In} &\implies \text{Diagnostic}(p, \text{DiagnosticCode::E0201}, \text{InvalidCollectionParameterDirection}) \in \mathcal{D}_{\text{sink}} \\
(C, C) \in \mathcal{R}_{\text{type\_dep}}^+ &\implies \text{Diagnostic}(C, \text{DiagnosticCode::E0203}, \text{CircularCollectionTypeDependency}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

#### 3. Computational Complexity & Algorithmic Bounds

Lowering, type checking, and operations evaluation for the KerML `Collections` package execute strictly within Complexity Class $`\mathbf{P}`$.

  **Algorithmic Bound NP-3 Formulation**: In general partially ordered sets (posets) with multiple inheritance and arbitrary generic subtyping, type satisfiability is NP-complete (NP-3). The DEAP compiler guarantees polynomial tractability by restricting the type hierarchy to a finite monotonic meet-semilattice $`(\mathcal{T}, \le, \wedge)`$` with C3 superclass linearization. Under this formulation, verifying collection subtyping `$`\mathcal{C}\langle T_1 \rangle \le \mathcal{C}\langle T_2 \rangle`$` reduces directly to checking `$`T_1 \le T_2`$` via `$`O(1)`$` bitset operations or bounded ancestor list climbing (`$`h \le 32`$`). The structural collection lattice relations (`$`\text{OrderedSet} \le \text{Set} \le \text{Bag} \le \text{Collection}`$` and `$`\text{OrderedSet} \le \text{Sequence} \le \text{Collection}`$`) are static constant relations evaluated in `$`O(1)`$ time.

  **Asymptotic Verification & Evaluation Bounds**:
  1. *Standard Library Bootstrapping*: Allocating the 5 core collection classifiers and their associated function signatures in contiguous bump arena storage executes in deterministic $`O(1)`$` time and `$`O(1)`$ space during compiler initialization.
  2. *Generic Type Instantiation & Memoization*: Lowering an instantiated generic collection $`\mathcal{C}\langle T \rangle`$` checks a hash-indexed memoization table in amortized `$`O(1)`$` time. If absent, allocating the specialized classifier node in contiguous bump arena storage requires `$`O(1)`$ time.
  3. *Type Checking & Covariant Subtyping*: Verifying $`\mathcal{C}\langle T_1 \rangle \le \mathcal{C}\langle T_2 \rangle`$` checks collection kind compatibility in `$`O(1)`$` and verifies element subtyping `$`T_1 \le T_2`$` in `$`O(1)`$` bitset lookup, totaling `$`O(1)`$ time.
  4. *Collection Literal & Constructor Type Checking*: For a collection literal containing $`k`$` elements, verifying `$`\tau(e_i) \le T`$` for all `$`i \in \{1, \dots, k\}`$` requires `$`O(k)`$` subtyping checks, evaluating in deterministic `$`O(k)`$ linear time.
  5. *Static Constant Index Bounds Checking*: Evaluating constant sequence indexing $`\text{get}(\sigma, idx)`$` against literal length `$`|\sigma|`$` requires `$`O(1)`$ integer comparisons.
  6. *Higher-Order Combinator Type Verification*: Checking predicate codomain conformance $`\tau(P) \le \text{Boolean}`$` and projection signature compatibility requires `$`O(1)`$ type semilattice lookups per combinator AST node.
  7. *Finite Collection Operation Evaluation*:
     - `size`, `isEmpty`, `notEmpty`, `first`, `last`, `get(i)`: evaluate in strictly $`O(1)`$ time.
     - `includes`, `excludes`, `count`: evaluate in $`O(1)`$` average time for hash-indexed sets; evaluate in `$`O(|c|)`$ linear time for sequences and bags.
     - `select`, `reject`, `collect`, `forAll`, `exists`, `reduce`: evaluate in deterministic $`O(|c|)`$` linear time over finite collection `$`c`$` with `$`|c|`$ elements.
     - `union`, `intersection`, `difference`: evaluate in $`O(|c_1| + |c_2|)`$` time for ordered or hash-indexed sets, and `$`O(|c_1| \cdot |c_2|)`$ worst-case time for unindexed collections.
  8. *Type Dependency Acyclicity*: Cycle detection over the collection type dependency graph $`\mathcal{G}_{\text{type\_dep}} = (V, E)`$` executes via Tarjan's strongly connected components algorithm in deterministic `$`O(V + E)`$ time.
  9. *Aggregate Compilation Unit Complexity*: For a compilation unit containing $`N`$` collection type declarations, `$`M`$` generic instantiations, and `$`K`$ collection expressions:

```math
T_{\text{validate}}(N, M, K) \in O(N + M + K)
```

  **Parallel Work-Stealing Scheduling (Architectural Directive 2)**: When collection lowering and type checking across independent compilation units is scheduled onto a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}}(N, M, K, N_{\text{max\_workers}}) \in O\left( \frac{N + M + K}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  **Space Complexity & Memory Bounds**: Contiguous bump arena storage for lowered collection nodes requires $`O(N + M + K)`$` bytes with zero heap fragmentation. The diagnostic error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ preallocated records. Total auxiliary memory overhead scales linearly with model size.

#### 4. Verification & Conformance Criteria

Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models containing abstract placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Classifier_Delta`, `Collection_0`, `Set_Alpha`, `Seq_Beta`, `Bag_Gamma`, `OrderedSet_Delta`, `param_x : Real`, `param_y : Real`). Conformance validation shall enforce the following test gates:

  1. **Canonical Standard Library Bootstrapping Gate**: Initialize the compiler without user input files. Assert that the `Collections` package is automatically bootstrapped into the root arena storage, containing valid classifier handles for `Collection`, `Set`, `Sequence`, `OrderedSet`, and `Bag`, with zero diagnostics emitted.
  2. **Orthogonal Matrix Dimension Gate**: Query the bootstrapped collection classifiers. Assert that $`\text{isUnique}`$` and `$`\text{isOrdered}`$ evaluate to the exact expected Boolean values: `Set` $`(\text{true}, \text{false})`$, `Sequence` $`(\text{false}, \text{true})`$, `OrderedSet` $`(\text{true}, \text{true})`$, and `Bag` $`(\text{false}, \text{false})`$.
  3. **Multiple Inheritance Semilattice Gate**: Verify that `OrderedSet<Classifier_Alpha>` specializes both `Set<Classifier_Alpha>` and `Sequence<Classifier_Alpha>`, and that all concrete collection types specialize `Collection<Classifier_Alpha>`. Assert that `Set<Classifier_Alpha>` specializes `Bag<Classifier_Alpha>`.
  4. **Subtyping Covariance Conformance Gate**: Declare specialization `Classifier_Beta :> Classifier_Alpha` ($`Classifier\_Alpha \le Classifier\_Beta`$`). Assert that `$`\text{Set}\langle Classifier\_Alpha \rangle \le \text{Set}\langle Classifier\_Beta \rangle`$`, `$`\text{Sequence}\langle Classifier\_Alpha \rangle \le \text{Sequence}\langle Classifier\_Beta \rangle`$`, `$`\text{OrderedSet}\langle Classifier\_Alpha \rangle \le \text{OrderedSet}\langle Classifier\_Beta \rangle`$`, and `$`\text{Bag}\langle Classifier\_Alpha \rangle \le \text{Bag}\langle Classifier\_Beta \rangle`$ evaluate to `true` with zero diagnostics.
  5. **Subtyping Covariance Rejection Gate (`E0200`)**: Attempt to assign an instance of $`\text{Set}\langle Classifier\_Beta \rangle`$` to a feature typed by `$`\text{Set}\langle Classifier\_Alpha \rangle`$` where `$`Classifier\_Beta \not\le Classifier\_Alpha`$. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`CollectionSubtypingViolation`).
  6. **Generic Instantiation & Memoization Gate**: Instantiate `Set<Classifier_Alpha>` at two distinct AST locations. Assert that the lowering engine memoizes the instantiation, returning identical 32-bit arena node handles ($`\text{id}_{C_1} == \text{id}_{C_2}`$) and generating zero redundant AST nodes.
  7. **Element Type Incompatibility Gate (`E0200`)**: Construct a collection literal `Set<Classifier_Alpha> { elem_1, elem_2 }` where `elem_2` is typed by `Classifier_Gamma` ($`Classifier\_Gamma \not\le Classifier\_Alpha`$). Assert deterministic rejection with diagnostic error code `E0200` (`CollectionElementTypeMismatch`) and exact source byte span coordinates.
  8. **Unresolved Generic Type Argument Gate (`E0200`)**: Attempt to declare `Sequence<UnresolvedClassifier>`. Assert deterministic rejection at compile time with diagnostic error code `E0200` (`UnresolvedCollectionTypeArgument`) and assignment of error sentinel $`\bot_{\text{type}}`$.
  9. **Higher-Order Predicate Boolean Codomain Gate (`E0200`)**: Ingest a `select` combinator expression whose predicate lambda evaluates to a non-Boolean type (e.g., arithmetic `Real`). Assert deterministic rejection with diagnostic error code `E0200` (`CollectionPredicateTypeMismatch`).
  10. **Static Literal Sequence Out-of-Bounds Gate (`E0200`)**: Lower an expression evaluating constant index `get(seq_lit, 5)` against a sequence literal `seq_lit` containing 3 elements. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`SequenceIndexOutOfBounds`).
