### REQ-0030: XML Schema Definition (XSD) & ADL Schema Ingestion for Component Topologies

- **Normative Statement**: The Universal Schema Ingestion Engine shall provide a native, self-contained XML Schema Definition (XSD) and Architecture Description Language (ADL) parser that ingests XML-based structural schemas and architecture specifications into intermediate schema Abstract Syntax Tree (AST) representations without external XML parser dependencies or external toolchain preprocessors. The ingestion engine shall parse XML documents conforming to W3C XML Schema Definition (`xs:*` / `xsd:*`) specifications and XML-based Architecture Description Language dialects (`adl:*`), mapping complex types, component prototypes, elements, attributes, directional ports, and assembly connectors into intermediate schema IR entities in accordance with the following contract:
  1. Package and Namespace Lowering: The document root (`xs:schema` or `adl:architecture`) shall lower to an enclosing `IngestedPackage` namespace node, establishing a deterministic hierarchical scope and resolving XML namespace prefixes (`xmlns`) to canonical symbol paths.
  2. Complex Type and Component Lowering: XSD `xs:complexType` definitions and ADL `adl:component` definitions shall lower to `IngestedPart` entities, preserving identifier names, structural kind annotations, and component containment hierarchies.
  3. Element and Attribute Lowering: XSD `xs:element` child declarations within complex types and ADL component attributes shall lower to `IngestedAttr` property definitions. The parser must map declared type references (`type`) to canonical classifier handles. Declared occurrence constraints (`minOccurs`, `maxOccurs`) must be lowered to multiplicity intervals $`\langle l, u \rangle \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})`$`, where omitted attributes default to `$`\langle 1, 1 \rangle`$, `minOccurs="0"` with `maxOccurs="1"` maps to $`\langle 0, 1 \rangle`$, and `maxOccurs="unbounded"` maps to $`\langle l, \infty \rangle`$. XSD `xs:attribute` declarations shall lower to `IngestedAttr` properties, where `use="optional"` maps to multiplicity $`\langle 0, 1 \rangle`$, `use="required"` maps to $`\langle 1, 1 \rangle`$, and `use="prohibited"` maps to $`\langle 0, 0 \rangle`$`. Any occurrence constraint specifying `$`l \gt u`$ or invalid negative integers shall be rejected with structured diagnostic code `E0103`.
  4. Simple Type and Enumeration Lowering: XSD `xs:simpleType` definitions containing `xs:restriction` and `xs:enumeration` facets shall lower to `IngestedClassifierDef` data types with structural kind `ClassifierKind::Enum`, preserving the ordered sequence of enumerator value tokens.
  5. Port Lowering and Directional Classification: ADL `adl:port` declarations within components shall lower to `IngestedPort` entities with explicit directionality. The ingestion engine must classify port direction strictly according to declared port kind:
     - Provided ports (`P-Port`, `provided`, `kind="provided"`) shall map to directional classification `Out`, signifying services or data flows exposed outward from the component boundary.
     - Required ports (`R-Port`, `required`, `kind="required"`) shall map to directional classification `In`, signifying services or data flows consumed inward across the component boundary.
     - Bidirectional ports (`kind="bidirectional"`, `kind="inout"`) shall map to directional classification `InOut`, signifying bidirectional flow.
     - Unrecognized, ambiguous, or missing port direction attributes shall deterministically trigger diagnostic error code `E0102`.
  6. Assembly Connector Lowering: ADL `adl:connector` (or `adl:connection`) elements shall lower to `IngestedConnection` links. The parser must extract the unique connector identifier, the fully qualified source port endpoint path ($`P_{\text{src}}`$`), and the fully qualified target port endpoint path (`$`P_{\text{tgt}}`$) formatted as hierarchical paths `Component_A::Port_Out` and `Component_B::Port_In`.
  7. Interconnect Topology and Directionality Invariant Enforcement: The parser shall validate that all referenced component and port endpoints exist within the compilation unit scope; dangling or unresolved endpoint references shall be rejected with diagnostic error code `E0104`. The engine shall enforce endpoint directionality compatibility: an assembly connector must connect an `Out` (provided) port to an `In` (required) port, or connect two `InOut` (bidirectional) ports. Incompatible directional bindings (such as connecting `Out` to `Out` or `In` to `In`) and direct self-loops ($`P_{\text{src}} = P_{\text{tgt}}`$) lacking explicit queueing or delay parameters shall deterministically trigger diagnostic error code `E0104`.
  8. Zero Regex XML Processing Invariant: XML parsing must be executed strictly via a deterministic, single-pass event-driven or pull-based pushdown automaton over the UTF-8 byte stream without regular expressions. Element nesting and tag matching shall be managed via an explicit bounded pushdown stack with maximum nesting depth $`D_{\text{max}} = 128`$. XML syntax errors, malformed tags, or unclosed element blocks shall trigger diagnostic error code `E0100` or `E0102`.

  All synthesized intermediate AST entities (`IngestedPackage`, `IngestedPart`, `IngestedPort`, `IngestedAttr`, `IngestedConnection`, `IngestedClassifierDef`) shall be allocated sequentially into contiguous typed bump arena storage in accordance with REQ-0009 and REQ-0034, yielding deterministic node handles with stable relative offsets. In accordance with Architectural Directive 1 and REQ-0010, every lowered AST node shall receive a deterministic RFC 4122 UUIDv5 identifier derived from the namespace OID and the fully qualified topological path. In accordance with Architectural Directive 3 and REQ-0036, copying string bytes from the input XML buffer into the global symbol interner pool for scalar `SymbolId` tokens (element tags, attribute names, type identifiers, endpoint paths) during this initial lexical pass is the sole permitted exception to the zero-copy invariant. In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the ingestion engine shall implement synchronization token error recovery on XML element and tag delimiter boundaries (closing tags `</...>`, self-closing delimiters `/>`, or block terminators `>`): upon encountering a syntax error, mismatched tag, or invalid attribute, the engine shall record a structured diagnostic record binding diagnostic error code `E0100`, `E0102`, `E0103`, or `E0104` per REQ-0191, substitute a typed sentinel error node ($`\bot_{\text{xml}}`$`, `$`\bot_{\text{part}}`$`, `$`\bot_{\text{port}}`$`, `$`\bot_{\text{conn}}`$`), pop the pushdown stack to the nearest valid enclosing scope, and resume parsing at the subsequent XML tag rather than aborting compilation. Multi-file XSD and ADL compilation units shall be processed in parallel across a bounded work-stealing thread pool with worker bound `$`N_{\text{max\_workers}}`$ in accordance with Architectural Directive 2 and REQ-0012. The ingestion parser must enforce Architectural Directive 5, guaranteeing a total, deterministic, non-panicking execution contract across all inputs. Performance latency (< 25 ms) and peak RSS memory (< 100 MB) gates shall be evaluated exclusively in compiled Release mode (`--release`) via dedicated benchmark harnesses isolated from standard CI logic tests in accordance with REQ-0011 and REQ-0196. All test models, diagnostic messages, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (e.g., `Package_0`, `Component_Alpha`, `Component_Beta`, `Port_1`, `Port_2`, `Port_P`, `Port_R`, `Flow_A`, `param_x : Real`, `Type_A`, `Attr_0`, `Conn_AlphaBeta`), strictly prohibiting hardcoded domain concepts and mock data.

- **Formal Invariant**: Let $`\mathcal{X}_{\text{xml}}`$` denote an ingested XML document tree parsed from a UTF-8 character sequence. The schema lowering transformation `$`\mathcal{T}_{\text{xml}} : \mathcal{X}_{\text{xml}} \longrightarrow \mathcal{A}_{\text{IR}}`$ maps XML syntactic constructs to intermediate schema IR entities:

```math
\begin{aligned}
\text{xs:schema } S &\longmapsto \text{IngestedPackage}(S, \text{members}: \mathcal{T}_{\text{xml}}(\text{Children}(S))) \\
\text{xs:complexType } T &\longmapsto \text{IngestedPart}(T, \text{kind}: \text{PartKind::Component}, \text{attrs}: \mathcal{T}_{\text{xml}}(\text{Elements}(T))) \\
\text{xs:element } e \text{ of type } T &\longmapsto \text{IngestedAttr}(e, \text{type}: T, \text{mult}: \mu_{\text{elem}}(e)) \\
\text{xs:attribute } a \text{ of type } T &\longmapsto \text{IngestedAttr}(a, \text{type}: T, \text{mult}: \mu_{\text{attr}}(a)) \\
\text{xs:simpleType } E &\longmapsto \text{IngestedClassifierDef}(E, \text{kind}: \text{ClassifierKind::Enum}, \text{values}: \text{EnumFacets}(E)) \\
\text{adl:component } C &\longmapsto \text{IngestedPart}(C, \text{kind}: \text{PartKind::Component}, \text{ports}: \mathcal{T}_{\text{xml}}(\text{Ports}(C))) \\
\text{adl:port } p &\longmapsto \text{IngestedPort}(p, \text{dir}: \text{Direction}(p), \text{payload}: \text{Type}(p)) \\
\text{adl:connector } c &\longmapsto \text{IngestedConnection}(\text{id}(c), P_{\text{src}}(c), P_{\text{tgt}}(c))
\end{aligned}
```

Port Directionality Mapping:
Let $`\text{kind}(p)`$` denote the declared kind string of an ADL port `$`p`$`. The port direction function `$`\text{Direction} : \text{Ports} \longrightarrow \{ \text{In}, \text{Out}, \text{InOut} \}`$ is defined as:

```math
\text{Direction}(p) = \begin{cases}
\text{Out}, & \text{if } \text{kind}(p) \in \{ \text{"provided"}, \text{"P-Port"}, \text{"p\_port"}, \text{"out"} \} \\
\text{In}, & \text{if } \text{kind}(p) \in \{ \text{"required"}, \text{"R-Port"}, \text{"r\_port"}, \text{"in"} \} \\
\text{InOut}, & \text{if } \text{kind}(p) \in \{ \text{"bidirectional"}, \text{"inout"}, \text{"duplex"} \}
\end{cases}
```

Element and Attribute Multiplicity Invariants:
The element multiplicity mapping $`\mu_{\text{elem}} : \text{Elements} \longrightarrow \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})`$ is defined by the declared or default occurrence constraints:

```math
\mu_{\text{elem}}(e) = \langle \text{minOccurs}(e), \text{maxOccurs}(e) \rangle
```

where default and explicit bounds satisfy:

```math
\begin{aligned}
\text{minOccurs}(e) &= \begin{cases} k, & \text{if declared with non-negative integer } k \in \mathbb{N}_0 \\ 1, & \text{if attribute is omitted} \end{cases} \\
\text{maxOccurs}(e) &= \begin{cases} k, & \text{if declared with non-negative integer } k \in \mathbb{N}_0 \\ \infty, & \text{if declared as "unbounded"} \\ 1, & \text{if attribute is omitted} \end{cases}
\end{aligned}
```

Multiplicity Interval Ordering Invariant:
For every XML element $`e`$, the lower occurrence bound must not exceed the upper occurrence bound:

```math
\forall e \in \text{Elements}(\mathcal{X}_{\text{xml}}), \quad \text{minOccurs}(e) \le \text{maxOccurs}(e)
```

The attribute multiplicity mapping $`\mu_{\text{attr}} : \text{Attributes} \longrightarrow \mathbb{N}_0 \times \mathbb{N}_0`$ is defined by:

```math
\mu_{\text{attr}}(a) = \begin{cases}
\langle 1, 1 \rangle, & \text{if use} = \text{"required"} \\
\langle 0, 1 \rangle, & \text{if use} = \text{"optional" or attribute is omitted} \\
\langle 0, 0 \rangle, & \text{if use} = \text{"prohibited"}
\end{cases}
```

Assembly Connector Topological Invariant:
Let $`c`$` be an assembly connector in an ADL component model, defining source endpoint `$`P_{\text{src}}(c)`$` and target endpoint `$`P_{\text{tgt}}(c)`$. Each endpoint decomposes into an owning component instance handle and a terminal port:

```math
\begin{aligned}
P_{\text{src}}(c) &= C_{\text{src}} \mathbin{::} p_{\text{src}} \\
P_{\text{tgt}}(c) &= C_{\text{tgt}} \mathbin{::} p_{\text{tgt}}
\end{aligned}
```

Every valid assembly connector must satisfy strict endpoint existence, directional compatibility, and non-reflexivity:

```math
\begin{aligned}
\forall c \in \text{Connectors}(\mathcal{X}_{\text{xml}}), \quad &P_{\text{src}}(c) \in \mathcal{P}_{\text{ports}} \;\wedge\; P_{\text{tgt}}(c) \in \mathcal{P}_{\text{ports}} \\
&\wedge\; (\text{Direction}(p_{\text{src}}) = \text{Out} \implies \text{Direction}(p_{\text{tgt}}) = \text{In}) \\
&\wedge\; (\text{Direction}(p_{\text{src}}) = \text{InOut} \implies \text{Direction}(p_{\text{tgt}}) = \text{InOut}) \\
&\wedge\; (P_{\text{src}}(c) \ne P_{\text{tgt}}(c))
\end{aligned}
```

Zero Regex Pushdown Automaton Stack Invariant:
Let the pushdown automaton parser state be represented by configuration $`\sigma = \langle q, \Gamma_{\text{stack}} \rangle`$`, where `$`q \in Q_{\text{parser}}`$` is the finite control state and `$`\Gamma_{\text{stack}} = \langle \tau_1, \tau_2, \dots, \tau_d \rangle`$` is the stack of open element tags with depth `$`d = |\Gamma_{\text{stack}}|`$`. The parser transitions over input byte stream `$`B = \langle b_1, b_2, \dots, b_N \rangle`$ deterministically:

```math
\delta : Q_{\text{parser}} \times \Sigma_{\text{byte}} \times (\Gamma_{\text{tag}} \cup \{ \bot \}) \longrightarrow Q_{\text{parser}} \times (\Gamma_{\text{tag}}^* \cup \{ \text{pop} \})
```

such that:
1. Parsing evaluates with zero regular expression evaluations ($`\text{RegexUsage} \equiv 0`$).
2. Element nesting depth is strictly bounded by $`D_{\text{max}} = 128`$:

```math
\forall \sigma \in \text{Trace}(\mathcal{X}_{\text{xml}}), \quad |\Gamma_{\text{stack}}(\sigma)| \le D_{\text{max}} = 128
```

3. Upon complete input consumption of a well-formed document, the tag stack is strictly empty:

```math
\Gamma_{\text{stack}}(\sigma_{\text{final}}) = \langle \rangle
```

Deterministic UUIDv5 and Arena Invariant:
Every lowered intermediate AST node $`u \in \mathcal{A}_{\text{IR}}`$ receives a deterministic RFC 4122 UUIDv5 identifier computed from the repository fixed namespace OID and its fully qualified topological path:

```math
\text{UUID}(u) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))
```

and sequential allocation into contiguous bump arena storage satisfies:

```math
\forall i \in \{1, \dots, M-1\}, \quad \text{Offset}(h_{i+1}) = \text{Offset}(h_i) + \text{sizeof}(\text{ASTNode})
```

Diagnostic Code Binding Invariant:
Grammar violations, mismatched tags, invalid occurrence intervals, and topological connector faults trigger structured diagnostic records in accordance with REQ-0191:

```math
\begin{aligned}
\text{MalformedXMLSyntax}(\text{span}) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0100}, \text{XMLWellFormednessViolation}) \in \mathcal{D} \\
\text{MismatchedEndTag}(\tau_{\text{start}}, \tau_{\text{end}}) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0102}, \text{MismatchedXMLElementTag}) \in \mathcal{D} \\
\text{DuplicateEntityIdentifier}(u_1, u_2) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0102}, \text{DuplicateXMLEntityIdentifier}) \in \mathcal{D} \\
\text{minOccurs}(e) \gt \text{maxOccurs}(e) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0103}, \text{InvalidMultiplicityInterval}) \in \mathcal{D} \\
\text{IsUnresolvedTypeReference}(T) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0103}, \text{UnresolvedClassifierType}) \in \mathcal{D} \\
P \notin \mathcal{P}_{\text{ports}} &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0104}, \text{DanglingConnectionPortEndpoint}) \in \mathcal{D} \\
\text{IncompatiblePortDirection}(p_{\text{src}}, p_{\text{tgt}}) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0104}, \text{IncompatiblePortDirectionBinding}) \in \mathcal{D} \\
(P_{\text{src}} = P_{\text{tgt}}) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0104}, \text{InvalidSelfLoopConnection}) \in \mathcal{D}
\end{aligned}
```

Diagnostic Taxonomy Containment Invariant:
All emitted diagnostic records strictly belong to the Subsystem 2 ingestion family:

```math
\forall D \in \mathcal{D}_{\text{xml}}, \quad \text{code}(D) \in \{ \text{DiagnosticCode::E0100}, \text{DiagnosticCode::E0102}, \text{DiagnosticCode::E0103}, \text{DiagnosticCode::E0104} \} \subset \mathcal{E}_{\text{ingest}}
```

- **Computational Complexity & Algorithmic Bounds**: The XML/XSD and ADL schema ingestion engine executes within Complexity Class $`\mathbf{P}`$`. Tokenization and structural document scanning evaluate via a deterministic pushdown automaton that reads the input UTF-8 byte stream of size `$`N`$` bytes monotonically without lookbehind or backtracking, operating in deterministic `$`O(N)`$` linear time. The pushdown tag stack maintains open element identifiers with maximum nesting depth bounded by `$`D \le D_{\text{max}} = 128`$`; each opening tag triggers a single `$`O(1)`$` push operation and each closing tag triggers a single `$`O(1)`$` pop operation, guaranteeing that aggregate stack operations across the document require at most `$`O(N)`$` steps and consume bounded `$`O(D_{\text{max}}) = O(1)`$` auxiliary stack space. String interning of element tag names, attribute keys, and identifier tokens operates in `$`O(L)`$` time for token length `$`L \le 256`$`, achieving `$`O(1)`$ amortized time per token using a preallocated global symbol pool. Lowering parsed XML nodes into intermediate AST entities (`IngestedPart`, `IngestedPort`, `IngestedAttr`, `IngestedConnection`, `IngestedClassifierDef`) within the contiguous typed bump arena requires a single pointer bump operation, executing in strict $`O(1)`$` constant time per entity and `$`O(M) = O(N)`$` total time for `$`M`$` synthesized nodes. Port directionality classification evaluates in `$`O(1)`$` time via constant-size dictionary lookup. Interconnect endpoint resolution and directionality compatibility validation evaluate in `$`O(1)`$` time per connection via hash table lookups over interned port handles, requiring `$`O(C) = O(N)`$` total time for `$`C`$` declared assembly connectors. When compiling `$`K`$` independent XML/XSD/ADL documents in parallel across a bounded work-stealing thread pool with `$`N_{\text{max\_workers}}`$` workers, parallel wall-clock runtime is bounded by `$`O(\lceil K / N_{\text{max\_workers}} \rceil \cdot N_{\text{max}})`$`. Aggregate single-file compilation time is strictly bounded by `$`O(N)`$` deterministic linear time in input byte size `$`N`$`. Total auxiliary memory complexity is bounded by `$`O(N)`$ for bump arena node storage with zero dynamic heap reallocations.

- **Verification & Conformance Criteria**: Automated verification suites shall assert 100% extraction fidelity, structural integrity, and diagnostic conformance across synthetic XSD and ADL XML schemas using abstract MBSE placeholders (e.g., `Package_0`, `Component_Alpha`, `Component_Beta`, `Port_1`, `Port_2`, `Port_P`, `Port_R`, `Flow_A`, `param_x : Real`, `Type_A`, `Attr_0`, `Conn_AlphaBeta`). Conformance shall be validated through the following deterministic test gates:
  1. XSD ComplexType and Element Lowering Gate: Ingest an XSD schema declaring `xs:complexType name="Component_Alpha"` containing `xs:element name="attr_1" type="xs:string"` and `xs:element name="attr_2" type="xs:decimal" minOccurs="0" maxOccurs="unbounded"`; assert lowering to `IngestedPart(Component_Alpha)` with two `IngestedAttr` nodes binding scalar types and multiplicity intervals $`\langle 1, 1 \rangle`$` and `$`\langle 0, \infty \rangle`$.
  2. XSD Attribute and SimpleType Enum Gate: Ingest an XSD schema declaring `xs:attribute name="attr_req" type="xs:int" use="required"` and `xs:simpleType name="Enum_State"` with `xs:enumeration` facets; assert lowering to `IngestedAttr` with $`\langle 1, 1 \rangle`$ and `IngestedClassifierDef` with `kind: ClassifierKind::Enum`.
  3. ADL Component and Port Lowering Gate: Ingest an ADL schema declaring `adl:component name="Component_Beta"` containing `adl:port name="Port_P" kind="provided" type="Type_A"` and `adl:port name="Port_R" kind="required" type="Type_A"`; assert lowering to `IngestedPart` with two `IngestedPort` nodes having directions `Out` and `In` respectively.
  4. ADL Bidirectional Port Gate: Ingest an ADL schema declaring `adl:port name="Port_Bi" kind="bidirectional" type="Type_B"`; assert lowering to `IngestedPort` with direction `InOut`.
  5. ADL Assembly Connector Lowering Gate: Ingest an ADL schema declaring an assembly connector `adl:connector id="Conn_AlphaBeta" src="Component_Alpha::Port_P" tgt="Component_Beta::Port_R"`; assert lowering to `IngestedConnection` linking the two fully qualified port endpoints.
  6. Mismatched or Corrupted XML Tag Gate (Error Recovery): Ingest an XML file with mismatched opening and closing tags (e.g. `<xs:complexType name="Type_Err"> ... </xs:element>`); assert deterministic emission of diagnostic error code `E0102` (`MismatchedXMLElementTag`), substitution of typed error sentinel $`\bot_{\text{part}}`$, stack unwinding to parent scope, and successful recovery to parse subsequent valid elements.
  7. Malformed XML Syntax Gate: Ingest an XML file with unclosed angle brackets or illegal byte tokens; assert emission of diagnostic code `E0100` (`XMLWellFormednessViolation`) with exact line/column provenance coordinates.
  8. Invalid Multiplicity Range Gate: Ingest an XSD element declaring `minOccurs="5"` and `maxOccurs="2"`; assert deterministic emission of diagnostic error code `E0103` (`InvalidMultiplicityInterval`).
  9. Dangling Port Endpoint Rejection Gate: Ingest an ADL connector referencing a nonexistent component or port (e.g. `src="Component_Alpha::Port_Missing"`); assert deterministic emission of diagnostic error code `E0104` (`DanglingConnectionPortEndpoint`).
  10. Incompatible Port Direction Gate: Ingest an ADL connector attempting to connect two provided ports (`Out` to `Out`) or two required ports (`In` to `In`); assert emission of diagnostic error code `E0104` (`IncompatiblePortDirectionBinding`).
  11. Self-Loop Connection Rejection Gate: Ingest an ADL connector declaring identical source and target endpoints (`src="Component_Alpha::Port_1" tgt="Component_Alpha::Port_1"`); assert emission of diagnostic error code `E0104` (`InvalidSelfLoopConnection`).
  12. Zero Regex Pushdown Automaton Invariant Gate: Verify through static analysis and runtime tracing that the XML parsing pipeline uses zero regular expressions, executing strictly via deterministic state-machine lexing and stack-bounded pushdown automata.
  13. Total Non-Panicking Contract & Release Mode Latency Gate: Execute stress tests against 100,000 malformed, truncated, deeply nested (exceeding $`D_{\text{max}}`$), and fuzzed XML schemas; assert 100% total-function termination with structured diagnostics and zero panics. In compiled Release mode (`--release`), evaluate parsing latency under dedicated benchmark harnesses isolated from CI logic tests, asserting throughput exceeding $`40{,}000`$ lines/s and execution latency within the 25 ms compiler budget for files up to 1 MB.
  14. Bitwise Determinism Gate: Verify that repeated compilations of identical XSD and ADL documents produce bitwise-identical intermediate IR AST structures with 0-byte diff churn.
