### REQ-0090: SysML v2 MetadataDefinition (`metadata def`) & Semantic Annotation Usage (`@`)

- **Normative Statement**: The KerML and SysML v2 metamodel lowering engine and semantic type checker of Subsystem 4 shall formalize SysML v2 metadata definitions (`metadata def`, `MetadataDefinition`) as strongly typed annotation classifiers specializing KerML `Classifier` (specifically `Structure`, `Class`, and `Classifier`), and semantic annotation usages (`@` annotation syntax, `MetadataUsage` or `Annotation`) as non-intrusive semantic metadata attachments binding typed attribute dictionaries to AST nodes without altering base metamodel semantics or operational behaviors.

  The metadata subsystem and lowering engine shall strictly enforce the following structural, semantic, and typing invariants:
  1. **Metamodel Classifier Specialization & Taxonomy**:
     - `MetadataDefinition` (`metadata def`) shall specialize KerML `Structure`, `Class`, `Classifier`, and `Type` ($`\text{MetadataDef} \le \text{Structure} \le \text{Class} \le \text{Classifier} \le \text{Type}`$). Every `MetadataDefinition` shall represent an extensional, identity-bearing structural metadata classifier defining typed metadata schemas.
     - `MetadataUsage` (`@Annotation` usage) shall specialize KerML `ItemUsage` and `Feature` ($`\text{MetadataUsage} \le \text{ItemUsage} \le \text{Feature}`$) and instantiate an annotating relationship (`Annotation` or `AnnotatingElement`) linking the metadata usage to its target annotated AST element $`e \in \mathcal{V}_{\text{AST}}`$.
     - **Disjointness & Invalid Classifier Specialization**: A `MetadataDefinition` must never specialize behavioral actions (`ActionDefinition`), state classifiers (`StateDefinition`), connection classifiers (`ConnectionDefinition`), or interface classifiers (`InterfaceDefinition`). Any declaration where a `metadata def` specializes an incompatible classifier kind shall be deterministically rejected at compile time with diagnostic error code `E0200` (`InvalidMetadataDefSpecialization`) in accordance with REQ-0191.
  2. **Metadata Attribute Typing & Property Declarations**:
     - A `MetadataDefinition` may declare zero or more owned attributes or properties $`\mathbf{A}_{\text{attr}} = (a_1 : T_1, \dots, a_p : T_p)`$`, where each attribute possesses an interned symbol name `$`a_i \in \mathcal{S}_{\text{intern}}`$`, a declared value type `$`T_i \in \mathcal{T}`$ (e.g., `Boolean`, `Integer`, `Real`, `String`, or enumeration type), and an optional default value expression $`v_{\text{default}, i}`$.
     - All attribute types $`T_i`$ shall resolve to valid data types or classifiers in scope. If an attribute references an undefined type, the lowering engine shall emit diagnostic error code `E0200` (`UnresolvedMetadataAttributeType`).
     - Circular attribute containment across metadata definitions shall be strictly prohibited and detected via dependency cycle detection, emitting diagnostic error code `E0203` (`CircularMetadataAttributeDependency`).
  3. **Annotated Element Target Restriction & Typing (`about` / `annotates`)**:
     - A `MetadataDefinition` may specify an annotated element constraint restricting the set of permissible target AST elements it may annotate (e.g., restricting target applicability to `Classifier`, `Feature`, `PartDefinition`, `ActionDefinition`, or other specific metaclasses).
     - When an annotated element target restriction $`T_{\text{target}}`$` is specified, the semantic type checker shall verify that any AST element `$`e`$ annotated by `@M` satisfies $`e : T_{\text{target}}`$` (i.e., the classifier or metaclass of `$`e`$` conforms to `$`T_{\text{target}}`$ in the metamodel subtyping lattice).
     - If an annotation `@M` is attached to an AST element that violates the declared target constraint, the compiler shall reject the annotation deterministically with diagnostic error code `E0200` (`InvalidAnnotatedElementTarget`).
  4. **Semantic Annotation Usage Syntax & Binding (`@`)**:
     - The lexer and parser shall recognize the prefix `@` token as the initiator of a semantic annotation usage attached to the immediately following or enclosing AST declaration.
     - The annotation identifier following `@` shall resolve to a visible `MetadataDefinition` in the current lexical scope. An unresolved identifier shall be rejected with diagnostic error code `E0200` (`UnresolvedMetadataDefinition`).
     - If the identifier resolves to a classifier that does not specialize `MetadataDefinition`, the usage shall be rejected with diagnostic error code `E0200` (`InvalidMetadataClassifier`).
     - Positional and named argument syntax: An annotation may supply argument values either positionally `@M(v_1, \dots, v_p)` or by named key `@M(a_1 = v_1, \dots, a_k = v_k)`.
     - The type checker shall statically verify:
       - All named argument keys correspond to declared attributes of $`M`$. Unrecognized attribute names shall be rejected with diagnostic error code `E0200` (`UnknownMetadataAttributeName`).
       - Duplicate argument assignments for the same attribute shall be rejected with diagnostic error code `E0200` (`DuplicateMetadataArgumentAssignment`).
       - Missing mandatory attributes (attributes lacking default values) shall be rejected with diagnostic error code `E0200` (`MissingMandatoryMetadataAttribute`).
       - The evaluated type of each actual argument expression $`v_i`$` must conform to the declared attribute type `$`T_i`$` in the subtyping semilattice (`$`\tau(v_i) \le_{\text{sub}} T_i`$). Type incompatibilities shall be rejected with diagnostic error code `E0200` (`MetadataAttributeTypeMismatch`).
  5. **Metamodel Neutrality & Operational Non-Intrusiveness**:
     - Semantic metadata annotations shall be purely non-intrusive and orthogonal to base metamodel execution semantics.
     - Attaching, modifying, or detaching a metadata annotation shall strictly preserve the underlying core typing, structural classification, and operational execution semantics of the host element $`e`$:

```math
\llbracket e \rrbracket \equiv \llbracket e \mathbin{\Vert} @M \rrbracket
```

     - The compiler shall prohibit base language semantics, type-checking rules, or control-flow behavior from mutating based on arbitrary user-defined metadata annotations unless an explicit compiler plugin or profile (per REQ-0144) is active.
  6. **Extrinsic Metadata Dictionary & Secondary Index Storage**:
     - All lowered annotation usages shall be stored extrinsically from core AST structural nodes in an extrinsic annotation dictionary mapping node handles to attribute value maps:

```math
\alpha : \text{NodeHandle} \times \text{SymbolId} \longrightarrow \text{Value}
```

     - The compiler shall construct a bidirectional secondary index:
       - Forward Index: $`\mathcal{I}_{\text{fwd}} : \text{NodeHandle} \to \text{List}\langle \text{AnnotationRecord} \rangle`$, mapping each AST node handle to its attached annotations.
       - Reverse Index: $`\mathcal{I}_{\text{rev}} : \text{MetadataDefHandle} \to \text{Set}\langle \text{NodeHandle} \rangle`$, mapping each metadata definition to all AST nodes annotated with it.
     - Fast lookup operations over the forward and reverse indices shall execute in amortized $`O(1)`$ time per node handle.
  7. **Multiple & Repeated Annotation Rules**:
     - An AST element may be annotated with multiple distinct metadata definitions ($`e \mathbin{\Vert} @M_1 \mathbin{\Vert} @M_2`$).
     - Unless a metadata definition explicitly declares a `@Repeatable` modifier or attribute, repeated annotations of the same metadata definition on the same AST element shall be rejected with diagnostic error code `E0200` (`DuplicateAnnotationViolation`).
  8. **Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered `MetadataDefinition`, `MetadataUsage`, and annotation attribute binding node shall receive an immutable, deterministic RFC 4122 UUIDv5 identifier derived by namespace-hashing the canonical compiler namespace OID with the node's fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel parsing, lowering, argument validation, and index construction for metadata definitions and annotations across independent compilation packages shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Allocation Exception)*: String bytes representing metadata definition names, attribute identifiers, string literal values, and fully qualified path tokens shall be interned into the global deduplicated symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The parser and metadata type checker shall implement synchronization token error recovery on statement delimiters (`;`), block boundaries (`}`, `{`), and annotation prefixes (`@`). Upon encountering syntax errors, unresolved metadata definitions (`E0200`), attribute type mismatches (`E0200`), or dependency cycles (`E0203`), the engine shall record the diagnostic into error sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute an error sentinel `$`\bot_{\text{meta}}`$`, and resynchronize on the next token delimiter without aborting compilation. If accumulated diagnostics reach capacity `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
     - *Directive 5 (Panic-Free Release Isolation)*: The metadata lowering and indexing engine shall enforce a deterministic, non-panicking execution contract with total-function error handling across all valid and invalid inputs. Performance latency ($`\lt 25\text{ ms}`$`) and peak memory RSS (`$`\lt 100\text{ MB}`$` for `$`10^5`$ metadata annotations) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `MetadataDef_Alpha`, `MetadataDef_Beta`, `Node_0`, `Node_1`, `Port_1`, `Flow_A`, `param_x : Real`, `attr_1 : Integer`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes in contiguous bump arena storage. Let `$`\mathcal{MD} \subset \mathcal{V}_{\text{AST}}`$` denote the set of metadata definitions, and let `$`\mathcal{MU} \subset \mathcal{V}_{\text{AST}}`$ denote the set of metadata annotation usages.

  The specialization taxonomy of `MetadataDefinition` and `MetadataUsage` within the KerML metamodel poset ordered by subtyping relation $`\le_{\text{sub}}`$ satisfies:

```math
\text{MetadataDef} \le_{\text{sub}} \text{Structure} \le_{\text{sub}} \text{Class} \le_{\text{sub}} \text{Classifier} \le_{\text{sub}} \text{Type}
```

```math
\text{MetadataUsage} \le_{\text{sub}} \text{ItemUsage} \le_{\text{sub}} \text{Feature}
```

  Each metadata definition $`MD \in \mathcal{MD}`$ is formalized as an 8-tuple:

```math
MD = \langle \text{id}_{MD}, \text{name}_{MD}, \text{owner}_{MD}, \mathbf{A}_{MD}, \tau_{\text{target}}(MD), \kappa_{\text{rep}}, \Delta_{MD}, \text{span}_{MD} \rangle
```

  where:

```math
\begin{aligned}
\text{id}_{MD} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{MD} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_{MD} &\in \mathcal{K} \cup \mathcal{P}_{\text{pkg}} \quad (\text{owning classifier or package}) \\
\mathbf{A}_{MD} &= (a_1 : T_1, \dots, a_p : T_p) \quad (\text{ordered typed attribute signatures}) \\
\tau_{\text{target}}(MD) &\in \mathcal{P}(\mathcal{K}) \cup \{ \top_{\text{any}} \} \quad (\text{permissible annotated target classifier kinds}) \\
\kappa_{\text{rep}} &\in \{ \text{Unique}, \text{Repeatable} \} \quad (\text{repetition policy}) \\
\Delta_{MD} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{MD} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

  Each metadata annotation usage $`MU \in \mathcal{MU}`$ is formalized as a 7-tuple:

```math
MU = \langle \text{id}_{MU}, h_{\text{target}}, \tau(MU), \mathbf{V}_{MU}, \Delta_{MU}, \text{span}_{MU}, \text{status}_{MU} \rangle
```

  where:

```math
\begin{aligned}
\text{id}_{MU} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
h_{\text{target}} &\in \mathcal{V}_{\text{AST}} \quad (\text{target annotated AST node handle}) \\
\tau(MU) &\in \mathcal{MD} \quad (\text{referenced metadata definition handle}) \\
\mathbf{V}_{MU} &= \{ a_i \mapsto v_i \mid a_i \in \text{attrs}(\tau(MU)) \} \quad (\text{bound attribute value dictionary}) \\
\Delta_{MU} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{MU} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance}) \\
\text{status}_{MU} &\in \{ \text{Valid}, \bot_{\text{meta}} \} \quad (\text{validation and error recovery status})
\end{aligned}
```

  Metamodel Neutrality Invariant: Attaching or detaching metadata annotations preserves underlying core typing and operational semantics:

```math
\llbracket e \rrbracket \equiv \llbracket e \mathbin{\Vert} @M \rrbracket
```

  Extrinsic Mapping Function: The extrinsic metadata dictionary mapping function $`\alpha`$ binds node handles and interned attribute symbol identifiers to typed evaluated values:

```math
\alpha : \mathcal{V}_{\text{AST}} \times \mathcal{S}_{\text{intern}} \longrightarrow \mathcal{V}_{\text{value}} \cup \{ \bot_{\text{none}} \}
```

  such that:

```math
\forall MU \in \mathcal{MU}, \forall (a_i \mapsto v_i) \in \mathbf{V}_{MU}, \quad \alpha(h_{\text{target}}(MU), a_i) = v_i
```

  Target Element Conformance Invariant: If a metadata definition restricts annotated targets, the target node must specialize the permitted target classifier:

```math
\forall MU \in \mathcal{MU}, \quad \tau_{\text{target}}(\tau(MU)) \ne \top_{\text{any}} \implies \text{kind}(h_{\text{target}}(MU)) \le_{\text{sub}} \tau_{\text{target}}(\tau(MU))
```

  Attribute Typing Conformance Invariant: For every bound attribute in an annotation usage, the evaluated value type conforms to the declared attribute type:

```math
\forall MU \in \mathcal{MU}, \forall (a_i \mapsto v_i) \in \mathbf{V}_{MU}, \quad \tau(v_i) \le_{\text{sub}} \tau(a_i)
```

  Annotation Uniqueness Invariant: Unless marked as repeatable, an AST element cannot have multiple instances of the same metadata definition:

```math
\forall MU_1, MU_2 \in \mathcal{MU}, \quad \left( h_{\text{target}}(MU_1) = h_{\text{target}}(MU_2) \wedge \tau(MU_1) = \tau(MU_2) \wedge \kappa_{\text{rep}}(\tau(MU_1)) = \text{Unique} \right) \implies MU_1 = MU_2
```

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Directive 1):

```math
\begin{aligned}
\forall MD \in \mathcal{MD}, &\quad \Delta_{MD} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(MD)) \\
\forall MU \in \mathcal{MU}, &\quad \Delta_{MU} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(h_{\text{target}}(MU)) \mathbin{\Vert} \text{FQN}(\tau(MU)) \mathbin{\Vert} \text{index}(MU))
\end{aligned}
```

  Diagnostic Trigger Rules: In accordance with REQ-0191, semantic violations deterministically emit structured diagnostic records:

```math
\begin{aligned}
\exists MD \in \mathcal{MD} : MD \not\le \text{Structure} &\implies \text{Diagnostic}(MD, \text{DiagnosticCode::E0200}, \text{InvalidMetadataDefSpecialization}) \in \mathcal{D}_{\text{sink}} \\
\exists MU \in \mathcal{MU} : \tau(MU) \notin \mathcal{MD} &\implies \text{Diagnostic}(MU, \text{DiagnosticCode::E0200}, \text{UnresolvedMetadataDefinition}) \in \mathcal{D}_{\text{sink}} \\
\exists MU \in \mathcal{MU}, (a \mapsto v) \in \mathbf{V}_{MU} : a \notin \text{attrs}(\tau(MU)) &\implies \text{Diagnostic}(MU, \text{DiagnosticCode::E0200}, \text{UnknownMetadataAttributeName}) \in \mathcal{D}_{\text{sink}} \\
\exists MU \in \mathcal{MU}, (a \mapsto v) \in \mathbf{V}_{MU} : \tau(v) \not\le_{\text{sub}} \tau(a) &\implies \text{Diagnostic}(MU, \text{DiagnosticCode::E0200}, \text{MetadataAttributeTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists MU \in \mathcal{MU} : \text{kind}(h_{\text{target}}(MU)) \not\le_{\text{sub}} \tau_{\text{target}}(\tau(MU)) &\implies \text{Diagnostic}(MU, \text{DiagnosticCode::E0200}, \text{InvalidAnnotatedElementTarget}) \in \mathcal{D}_{\text{sink}} \\
\exists MU_1 \ne MU_2 : (h_{\text{target}}(MU_1) = h_{\text{target}}(MU_2) \wedge \tau(MU_1) = \tau(MU_2) \wedge \kappa_{\text{rep}} = \text{Unique}) &\implies \text{Diagnostic}(MU_2, \text{DiagnosticCode::E0200}, \text{DuplicateAnnotationViolation}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

- **Computational Complexity & Algorithmic Bounds**: Lowering, argument validation, indexing, and extrinsic dictionary lookup of `MetadataDefinition` and `MetadataUsage` elements execute strictly within Complexity Class $`\mathbf{P}`$.

  For an abstract MBSE model graph $`\mathcal{M}_{\text{model}} = (\mathcal{V}_{\text{model}}, \mathcal{E}_{\text{model}})`$` containing `$`V = |\mathcal{V}_{\text{model}}|`$` AST nodes, `$`N_{MD} = |\mathcal{MD}|`$` metadata definitions, and `$`N_{MU} = |\mathcal{MU}|`$ metadata annotation usages:
  1. *Arena Allocation & Symbol Interning*: Allocating AST nodes for metadata definitions, metadata usages, and attribute bindings in contiguous bump arena storage requires amortized $`O(1)`$` time and `$`O(1)`$` auxiliary space per node, yielding `$`O(N_{MD} + N_{MU})`$ total allocation time.
  2. *Annotation Argument Validation*: Each annotation usage binds $`p`$` attributes. Validating attribute names and checking type conformance `$`\tau(v_i) \le_{\text{sub}} \tau(a_i)`$` requires `$`O(p)`$` time. For models with bounded attribute arity `$`p \le p_{\max}`$`, argument validation for all annotations executes in deterministic linear time `$`O(N_{MU})`$.
  3. *Secondary Index Construction*: Populating forward index $`\mathcal{I}_{\text{fwd}}`$` and reverse index `$`\mathcal{I}_{\text{rev}}`$` via contiguous hash tables or indexed vectors requires amortized `$`O(1)`$` time per annotation attachment, yielding `$`O(N_{MU})`$ total indexing time.
  4. *Extrinsic Dictionary Lookup*: Querying the metadata dictionary $`\alpha(h, a)`$` for an attached attribute value or querying all annotations on node `$`h`$` via `$`\mathcal{I}_{\text{fwd}}(h)`$` executes in deterministic amortized `$`O(1)`$` time. Reverse lookup `$`\mathcal{I}_{\text{rev}}(MD)`$` retrieves the set of annotated node handles in `$`O(|\mathcal{I}_{\text{rev}}(MD)|)`$ time.
  5. *Aggregate Compilation Unit Complexity*: The total sequential execution time for lowering, validating, indexing, and verifying all metadata definitions and annotations in a compilation unit is strictly linear in the model size:

```math
T_{\text{total}}(V, N_{MD}, N_{MU}) \in O(V + N_{MD} + N_{MU}) \subseteq O(V)
```

  6. *Parallel Work-Stealing Scaling (Architectural Directive 2)*: When independent packages are lowered concurrently on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}}(V, N_{MD}, N_{MU}, N_{\text{max\_workers}}) \in O\left( \frac{V + N_{MD} + N_{MU}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  7. *Space Complexity & Memory Bounds*: Contiguous arena memory is bounded by $`O(V + N_{MD} + N_{MU})`$`. The extrinsic forward and reverse indices require `$`O(N_{MU})`$` auxiliary reference space. The error sink buffer is strictly bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ memory.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `MetadataDef_Alpha`, `MetadataDef_Beta`, `Node_0`, `Node_1`, `Port_1`, `Flow_A`, `param_x : Real`, `attr_1 : Integer`) across the following verification gates:

  1. **Canonical `metadata def` Metamodel Specialization Gate**: Declare `metadata def MetadataDef_Alpha;`. Assert that the lowered AST node specializes KerML `Structure` and `Class`, represents an extensional structural classifier, binds to contiguous arena storage, and emits zero diagnostics.
  2. **Multi-Attribute `metadata def` Lowering & Typing Gate**: Declare `metadata def MetadataDef_Alpha { attr attr_1 : Integer; attr attr_2 : String; }`. Assert that the lowered definition records both attributes with correct symbol IDs, validated types, and default values, emitting zero diagnostics.
  3. **Semantic Annotation Usage (`@`) Attachment Gate**: Declare `@MetadataDef_Alpha(attr_1 = 42, attr_2 = "test_val") part def Classifier_Alpha;`. Assert that the lowering engine parses the `@` prefix, resolves `MetadataDef_Alpha`, binds the attribute dictionary, attaches the annotation to `Classifier_Alpha`, and records valid lexical provenance coordinates.
  4. **Metamodel Neutrality & Behavioral Invariance Gate**: Assert that attaching `@MetadataDef_Alpha` to `Classifier_Alpha` produces identical base semantic denotations ($`\llbracket e \rrbracket \equiv \llbracket e \mathbin{\Vert} @M \rrbracket`$), preserving subtyping relations, port directions, and action semantics without modification.
  5. **Unresolved Metadata Definition Rejection Gate (`E0200`)**: Ingest a model containing an annotation referencing an undeclared metadata definition: `@NonExistentDef part def Classifier_Alpha;`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`UnresolvedMetadataDefinition`), binding sentinel $`\bot_{\text{meta}}`$, and continuing compilation.
  6. **Invalid Metadata Classifier Rejection Gate (`E0200`)**: Ingest a model attempting to use a non-metadata classifier as an annotation: `part def Classifier_Beta; @Classifier_Beta part def Classifier_Alpha;`. Assert deterministic rejection with diagnostic error code `E0200` (`InvalidMetadataClassifier`).
  7. **Metadata Attribute Type Mismatch Rejection Gate (`E0200`)**: Ingest an annotation supplying a value with an incompatible type: `@MetadataDef_Alpha(attr_1 = "string_value") part def Classifier_Alpha;` where `attr_1` is declared as `Integer`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`MetadataAttributeTypeMismatch`).
  8. **Unknown Metadata Attribute Name Rejection Gate (`E0200`)**: Ingest an annotation specifying an undeclared attribute key: `@MetadataDef_Alpha(unknown_attr = 10) part def Classifier_Alpha;`. Assert deterministic rejection with diagnostic error code `E0200` (`UnknownMetadataAttributeName`).
  9. **Missing Mandatory Attribute Rejection Gate (`E0200`)**: Declare a metadata definition with an attribute lacking a default value. Ingest an annotation omitting this attribute. Assert deterministic rejection with diagnostic error code `E0200` (`MissingMandatoryMetadataAttribute`).
  10. **Target Element Restriction Gate (`E0200`)**: Declare `metadata def MetadataDef_Alpha` restricted to annotating `ActionDefinition`. Ingest a model attempting to annotate a `PartDefinition`: `@MetadataDef_Alpha part def Classifier_Alpha;`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`InvalidAnnotatedElementTarget`).
  11. **Duplicate Non-Repeatable Annotation Rejection Gate (`E0200`)**: Ingest a model attaching two instances of non-repeatable `MetadataDef_Alpha` to the same element: `@MetadataDef_Alpha @MetadataDef_Alpha part def Classifier_Alpha;`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`DuplicateAnnotationViolation`).
  12. **Extrinsic Fast Dictionary & Secondary Index Lookup Gate ($`O(1)`$`)**: Construct an AST with `$`10^5`$` annotated nodes. Assert that querying `$`\alpha(h, a)`$` and forward lookup `$`\mathcal{I}_{\text{fwd}}(h)`$` executes in amortized `$`O(1)`$` time per node handle, and reverse lookup `$`\mathcal{I}_{\text{rev}}(MD)`$ retrieves all annotated nodes with 100% precision and recall.
  13. **Synchronization Token Error Recovery Gate (Architectural Directive 4)**: Ingest a compilation unit containing 5 malformed metadata definitions and annotations interspersed with valid code. Verify that the lowering engine resynchronizes at statement delimiters (`;`), block boundaries (`}`), and `@` prefixes, accumulates all 5 `E0200` diagnostics with exact source spans, and halts gracefully with terminal diagnostic `E0199` when the error count reaches $`C_{\text{max\_errors}}`$.
  14. **Deterministic RFC 4122 UUIDv5 Anchor Gate (Architectural Directive 1)**: Verify that 100% of lowered `MetadataDefinition`, `MetadataUsage`, and attribute binding nodes receive deterministic RFC 4122 UUIDv5 identifiers computed from the canonical compiler namespace OID and fully qualified symbol paths, maintaining zero-churn bitwise determinism across consecutive compilation runs.
  15. **Bounded Work-Stealing Parallelism Gate (Architectural Directive 2)**: Ingest a synthetic model containing 50 packages with $`10^5`$` metadata annotations across `$`N_{\text{max\_workers}}`$ threads in the bounded work-stealing pool; assert thread isolation, data-race freedom, and identical AST topology compared to single-threaded compilation.
  16. **Release Mode Latency & Peak RSS Memory Gate (Architectural Directive 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, assert that lowering, validating, indexing, and verifying $`10^5`$ synthetic metadata annotations executes in under 25 ms, peak RSS memory remains strictly under 100 MB, and consecutive compilation runs exhibit bitwise determinism with 0-byte diff churn.
