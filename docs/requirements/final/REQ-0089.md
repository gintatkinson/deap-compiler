### REQ-0089: SysML v2 Expose Filtering & Viewpoint Conformance Grammar

- **Normative Statement**: The query engine, semantic lowering engine, and viewpoint conformance validator of Subsystem 4 shall formalize SysML v2 `expose` statements and declarations within view definitions (`view def`, `ViewDefinition`) and view usages (`view`, `ViewUsage`) as strongly typed, declarative model selection expressions supporting explicit element inclusion, recursive namespace hierarchy expansion, and tag-based element query predicates, verifying viewpoint conformance across exposed subgraphs.

  The lowering engine and query compiler shall strictly verify and enforce the following structural, semantic, and typing invariants during expose filtering and viewpoint conformance validation:
  1. **Grammar & Abstract Syntax of `expose` Declarations**:
     - An `expose` statement shall occur within the featured body of a `ViewDefinition` or `ViewUsage` AST node.
     - The grammar shall support the following orthogonal selection modalities:
       - *Explicit Element Path Inclusion*: `expose <path>;` or `expose <path_1>, <path_2>, ..., <path_m>;`, where each path resolves to a declared classifier, package, part usage, port usage, item flow, state, action, or constraint in the lexical scope table.
       - *Shallow Namespace Expansion*: `expose <namespace_path>::*;`, exposing all immediate owned members of the designated namespace without descending into nested sub-namespaces.
       - *Recursive Namespace Hierarchy Expansion*: `expose <namespace_path>::**;`, computing the transitive membership closure of the designated namespace and exposing all recursively contained elements across the entire subtree.
       - *Predicate-Based Element Filtering*: `expose filter <predicate_expr>;`, evaluating a boolean query expression $`\Phi_{\text{filter}}`$ over candidate elements within the model multigraph.
       - *Classifier Kind & Type Predicates*: `expose filter isKindOf(<Classifier_Kind>)` and `expose filter isTypeOf(<Classifier_Type>)`, selecting elements based on subtyping poset membership or exact classifier typing.
       - *Tag & Metadata Annotation Predicates*: `expose filter @<Metadata_Tag>` or `expose filter hasMetadata(<Metadata_Def>)`, selecting elements decorated with specified semantic metadata annotations.
       - *Compound Boolean Query Expressions*: Conjunction (`and`), disjunction (`or`), and negation (`not`) over elementary predicates, enabling compositional filtering expressions (e.g., `expose filter (isKindOf(PartDef_Alpha) and @Tag_Alpha)`).
       - *Directed Structural Traversal*: Traversal expressions that follow declared relationship edges (such as connections, flows, allocations, or specializations) starting from exposed root elements.
  2. **Namespace Path Resolution & Scope Validation**:
     - Every target path in an expose declaration shall be resolved against the compilation unit's hierarchical lexical scope table constructed during symbol hoisting per REQ-0040 and REQ-0041.
     - If a path expression fails to resolve to an active AST entity in the symbol table, the semantic analyzer shall reject the declaration deterministically at compile time with diagnostic error code `E0200` (`UnresolvedExposeTarget`) in accordance with REQ-0191.
  3. **Query Filter Predicate Semantic Typing & Evaluation**:
     - The query engine shall statically type-check all filter predicate expressions $`\Phi_{\text{filter}}`$.
     - Every variable, feature access, or metadata key referenced within a predicate expression must bind to a valid attribute or property declared in candidate classifier definitions.
     - The codomain of any filter predicate expression must unify with the canonical boolean type $`\mathbb{B} = \{ \text{true}, \text{false} \}`$. Expressions yielding non-boolean types or referencing unbound attributes shall be rejected at compile time with diagnostic error code `E0202` (`TypeMismatchInQueryPredicate`) or `E0200` (`InvalidExposePredicate`).
  4. **Conformant Induced Subgraph Model Projection ($`\pi_{\text{view}}`$)**:
     - The compiler's model projection engine shall formalize the sovereign system model as a directed multigraph $`\mathcal{M}_{\text{model}} = (\mathcal{V}_{\text{model}}, \mathcal{E}_{\text{model}})`$.
     - Evaluating all expose declarations $`\mathbf{E}_{V} = \{ E_1, \dots, E_k \}`$ owned by view $`V`$ computes the exposed vertex set $`V_{\text{exp}} \subseteq \mathcal{V}_{\text{model}}`$ through the union of resolved paths and satisfying predicate evaluations:

$$
V_{\text{exp}} = \bigcup_{E \in \mathbf{E}_{V}} \text{ExposedElements}(E)
$$

     - The rendered view model graph $`G_{\text{view}} = (V_{\text{exp}}, E_{\text{exp}})`$ shall strictly preserve all induced relationship edges from $`\mathcal{E}_{\text{model}}`$ whose source and target endpoints both reside within $`V_{\text{exp}}`$:

$$
E_{\text{exp}} = \{ (u, v) \in \mathcal{E}_{\text{model}} \mid u \in V_{\text{exp}} \wedge v \in V_{\text{exp}} \}
$$

     - *Projection Soundness & Completeness*: The projection mapping shall guarantee that all and only those model elements satisfying the view's expose declarations are included in $`V_{\text{exp}}`$.
  5. **Viewpoint Conformance Grammar & Semantic Verification (`satisfy viewpoint`)**:
     - When a view declares conformance to a viewpoint definition via `satisfy viewpoint <Viewpoint_Name>;` (per REQ-0088), the conformance engine shall parse and validate the viewpoint's framing obligations.
     - The semantic checker shall verify that:
       - The target viewpoint identifier resolves in scope to a valid `ViewpointDefinition` or `ViewpointUsage`. Conformance targeting non-viewpoint classifiers shall be rejected with diagnostic error code `E0200` (`UnresolvedViewpointReference`).
       - *Mandatory Element Coverage*: If the viewpoint definition prescribes mandatory element kinds, features, or concerns ($`\mathbf{M}_{\text{vp}} \subseteq \mathcal{V}_{\text{model}}`$), the exposed vertex set must satisfy the inclusion condition $`\mathbf{M}_{\text{vp}} \subseteq V_{\text{exp}}`$. Missing mandatory elements shall be rejected with diagnostic error code `E0200` (`ViewpointConformanceViolation`).
       - *Predicate Subsumption & Consistency*: If the viewpoint specifies a global filter constraint $`\Phi_{\text{vp}} : \mathcal{V}_{\text{model}} \to \mathbb{B}`$, every exposed element $`u \in V_{\text{exp}}`$ must satisfy $`\Phi_{\text{vp}}(u) \equiv \text{true}`$. Any element in $`V_{\text{exp}}`$ violating the viewpoint filter shall trigger diagnostic error code `E0200` (`ViewpointConformanceViolation`).
       - *Negative Exclusions*: Viewpoints specifying exclusion rules ($`\mathbf{X}_{\text{vp}} \subset \mathcal{V}_{\text{model}}`$) shall enforce $`V_{\text{exp}} \cap \mathbf{X}_{\text{vp}} = \emptyset`$. Exposure of forbidden elements shall trigger diagnostic error code `E0200` (`ViewpointConformanceViolation`).
  6. **Expose Dependency Graph & Acyclicity**:
     - Expose relationships that include nested views or reference other view definitions shall form a directed dependency graph $`\mathcal{G}_{\text{exp\_dep}} = (\mathcal{VD}, \mathcal{R}_{\text{exp\_dep}})`$.
     - Circular view containment or recursive expose definitions ($`V_1 \to V_2 \to \dots \to V_1`$) shall be strictly prohibited and detected via topological cycle detection, emitting diagnostic error code `E0203` (`CircularExposeDependency`).
  7. **Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered `Expose` AST node, filter expression, and projection link shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier derived from the canonical compiler namespace OID and the fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel path resolution, query predicate evaluation, induced subgraph extraction, and viewpoint conformance verification across independent views in distinct packages shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Allocation Exception)*: String bytes representing symbol names, qualified paths, filter predicates, and metadata tag keys shall be interned into the global deduplicated symbol interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The expose parser and semantic checker shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). Upon encountering unresolvable paths (`E0200`), malformed filter predicates (`E0202`), or circular expose dependencies (`E0203`), the engine shall record the diagnostic into preallocated error sink buffer $`\mathcal{D}_{\text{sink}}`$, substitute typed error sentinels $`\bot_{\text{exp}}`$, and resynchronize on the next delimiter without aborting compilation. If accumulated diagnostics reach $`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.
     - *Directive 5 (Panic-Free Release Isolation)*: The lowering, filtering, and conformance validation engine shall enforce a deterministic, non-panicking execution contract with total-function error handling across all inputs. Performance latency ($`\lt 25\text{ ms}`$) and peak memory RSS ($`\lt 100\text{ MB}`$ for $`10^4`$ AST nodes / expose expressions) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `PartDef_Alpha`, `ViewDef_Alpha`, `ViewDef_Beta`, `View_1`, `View_2`, `ViewpointDef_Alpha`, `ViewpointDef_Beta`, `Viewpoint_1`, `Metadata_Alpha`, `Tag_Alpha`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous bump arena storage. Let $`\mathcal{M}_{\text{model}} = (\mathcal{V}_{\text{model}}, \mathcal{E}_{\text{model}})`$ denote the system model multigraph where $`\mathcal{V}_{\text{model}} \subset \mathcal{V}_{\text{AST}}`$ and $`\mathcal{E}_{\text{model}} \subseteq \mathcal{V}_{\text{model}} \times \mathcal{V}_{\text{model}} \times \mathcal{K}_{\text{rel}}`$.

  Let $`\mathcal{VD} \subset \mathcal{V}_{\text{AST}}`$ denote the set of view definitions, $`\mathcal{VU} \subset \mathcal{V}_{\text{AST}}`$ the set of view usages, and $`\mathcal{VPD} \subset \mathcal{V}_{\text{AST}}`$ the set of viewpoint definitions.

  Let $`\mathcal{E}_{\text{exp}}`$ denote the set of lowered expose declarations. Each expose declaration $`E \in \mathcal{E}_{\text{exp}}`$ is formalized as a 7-tuple:

$$
E = \langle \text{id}_{E}, \text{owner}_{E}, \mathbf{P}_{E}, \Omega_{E}, \Phi_{E}, \Delta_{E}, \text{span}_{E} \rangle
$$

  where:

$$
\begin{aligned}
\text{id}_{E} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{owner}_{E} &\in \mathcal{VD} \cup \mathcal{VU} \quad (\text{owning view definition or view usage}) \\
\mathbf{P}_{E} &\subset \mathcal{S}_{\text{path}} \quad (\text{finite set of referenced element paths}) \\
\Omega_{E} &\in \{ \text{Exact}, \text{ShallowWildcard}, \text{RecursiveWildcard} \} \quad (\text{namespace expansion mode}) \\
\Phi_{E} &\in (\mathcal{V}_{\text{model}} \to \mathbb{B}) \cup \{ \top_{\text{filter}} \} \quad (\text{element selection query predicate}) \\
\Delta_{E} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{E} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

  The path expansion mapping $`\text{Expand} : \mathcal{S}_{\text{path}} \times \{ \text{Exact}, \text{ShallowWildcard}, \text{RecursiveWildcard} \} \to \mathcal{P}(\mathcal{V}_{\text{model}})`$ is formalized as:

$$
\text{Expand}(p, \Omega) = \begin{cases}
\{ e \in \mathcal{V}_{\text{model}} \mid \text{FQN}(e) = p \} & \text{if } \Omega = \text{Exact} \\
\{ e \in \mathcal{V}_{\text{model}} \mid \text{Parent}(e) = \text{ResolvePath}(p) \} & \text{if } \Omega = \text{ShallowWildcard} \\
\{ e \in \mathcal{V}_{\text{model}} \mid \text{FQN}(e) = p \vee \text{DescendantOf}(e, p) \} & \text{if } \Omega = \text{RecursiveWildcard}
\end{cases}
$$

  The exposed element set for an individual expose declaration $`E \in \mathcal{E}_{\text{exp}}`$ is defined as:

$$
\text{ExposedElements}(E) = \left( \bigcup_{p \in \mathbf{P}_{E}} \text{Expand}(p, \Omega_{E}) \right) \cap \{ e \in \mathcal{V}_{\text{model}} \mid \Phi_{E}(e) = \text{true} \}
$$

  For a view $`V \in \mathcal{VD} \cup \mathcal{VU}`$ with owned expose declarations $`\mathbf{E}_{V} = \{ E \in \mathcal{E}_{\text{exp}} \mid \text{owner}_{E} = V \}`$, the aggregated exposed vertex set $`V_{\text{exp}}(V)`$ is the union of individual exposures:

$$
V_{\text{exp}}(V) = \bigcup_{E \in \mathbf{E}_{V}} \text{ExposedElements}(E)
$$

  Conformant Subgraph Projection Invariant: The rendered view model graph $`G_{\text{view}}(V) = (V_{\text{exp}}(V), E_{\text{exp}}(V))`$ preserves all induced edges between exposed vertices:

$$
E_{\text{exp}}(V) = \{ (u, v, k) \in \mathcal{E}_{\text{model}} \mid u \in V_{\text{exp}}(V) \wedge v \in V_{\text{exp}}(V) \}
$$

  Projection Soundness and Completeness Invariant: An element $`e \in \mathcal{V}_{\text{model}}`$ belongs to the projected view if and only if it is selected by at least one expose declaration of view $`V`$:

$$
\forall e \in \mathcal{V}_{\text{model}}, \quad e \in V_{\text{exp}}(V) \iff \exists E \in \mathbf{E}_{V} : \left( \exists p \in \mathbf{P}_{E}, e \in \text{Expand}(p, \Omega_{E}) \wedge \Phi_{E}(e) = \text{true} \right)
$$

  Viewpoint Conformance Invariant: Let $`V \in \mathcal{VD} \cup \mathcal{VU}`$ declare conformance to viewpoint $`VP \in \mathcal{VPD}`$ with filter predicate $`\Phi_{\text{vp}} : \mathcal{V}_{\text{model}} \to \mathbb{B}`$, mandatory elements $`\mathbf{M}_{\text{vp}} \subseteq \mathcal{V}_{\text{model}}`$, and excluded elements $`\mathbf{X}_{\text{vp}} \subseteq \mathcal{V}_{\text{model}}`$. View $`V`$ conforms to viewpoint $`VP`$ ($`V \models VP`$) if and only if all three conformance obligations hold:

$$
V \models VP \iff \left( \forall u \in V_{\text{exp}}(V), \; \Phi_{\text{vp}}(u) = \text{true} \right) \wedge \left( \mathbf{M}_{\text{vp}} \subseteq V_{\text{exp}}(V) \right) \wedge \left( V_{\text{exp}}(V) \cap \mathbf{X}_{\text{vp}} = \emptyset \right)
$$

  Expose Dependency Acyclicity Invariant: Let $`\mathcal{G}_{\text{exp\_dep}} = (\mathcal{VD}, \mathcal{R}_{\text{exp\_dep}})`$ denote the directed dependency graph where $`(V_1, V_2) \in \mathcal{R}_{\text{exp\_dep}}`$ if view $`V_1`$ exposes or includes view $`V_2`$. The transitive closure $`\mathcal{R}_{\text{exp\_dep}}^+`$ must be irreflexive:

$$
\forall V \in \mathcal{VD}, \quad (V, V) \notin \mathcal{R}_{\text{exp\_dep}}^+
$$

  Deterministic RFC 4122 UUIDv5 Anchor Invariant (Architectural Directive 1): Every lowered expose declaration and projection link receives an immutable bitwise deterministic RFC 4122 UUIDv5 identifier:

$$
\begin{aligned}
\forall E \in \mathcal{E}_{\text{exp}}, &\quad \Delta_{E} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(E)) \\
\forall V \in \mathcal{VD} \cup \mathcal{VU}, &\quad \Delta_{G_{\text{view}}(V)} = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(V) \text{ \texttt{::} } \text{"projected\_graph"})
\end{aligned}
$$

  Diagnostic Trigger Rules: Violations of path resolution, predicate typing, viewpoint conformance, or dependency acyclicity deterministically emit structured diagnostics in accordance with REQ-0191:

$$
\begin{aligned}
\exists p \in \mathbf{P}_{E} : \text{ResolvePath}(p) = \emptyset &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0200}, \text{UnresolvedExposeTarget}) \in \mathcal{D}_{\text{sink}} \\
\text{TypeCheck}(\Phi_{E}) = \bot_{\text{type}} &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0202}, \text{TypeMismatchInQueryPredicate}) \in \mathcal{D}_{\text{sink}} \\
\exists u \in V_{\text{exp}}(V) : \Phi_{\text{vp}}(u) = \text{false} &\implies \text{Diagnostic}(V, \text{DiagnosticCode::E0200}, \text{ViewpointConformanceViolation}) \in \mathcal{D}_{\text{sink}} \\
\exists m \in \mathbf{M}_{\text{vp}} : m \notin V_{\text{exp}}(V) &\implies \text{Diagnostic}(V, \text{DiagnosticCode::E0200}, \text{MissingMandatoryExposedElement}) \in \mathcal{D}_{\text{sink}} \\
\exists x \in \mathbf{X}_{\text{vp}} : x \in V_{\text{exp}}(V) &\implies \text{Diagnostic}(V, \text{DiagnosticCode::E0200}, \text{ForbiddenElementExposed}) \in \mathcal{D}_{\text{sink}} \\
(V, V) \in \mathcal{R}_{\text{exp\_dep}}^+ &\implies \text{Diagnostic}(V, \text{DiagnosticCode::E0203}, \text{CircularExposeDependency}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Model filtering, query predicate evaluation, induced subgraph extraction, and viewpoint conformance validation execute strictly within Complexity Class $`\mathbf{P}`$.

  For an abstract MBSE model multigraph $`\mathcal{M}_{\text{model}} = (\mathcal{V}_{\text{model}}, \mathcal{E}_{\text{model}})`$ containing $`V = |\mathcal{V}_{\text{model}}|`$ vertices, $`E = |\mathcal{E}_{\text{model}}|`$ edges, $`K = |\mathcal{E}_{\text{exp}}|`$ expose declarations, and $`N_{V} = |\mathcal{VD}| + |\mathcal{VU}|`$ views:
  1. *Path Resolution & Scoped Symbol Lookup*: Resolving an explicit path $`p \in \mathbf{P}_{E}`$ executes in amortized $`O(1)`$ time via the hierarchical lexical scope table. Resolving all $`m = |\mathbf{P}_{E}|`$ paths in declaration $`E`$ requires $`O(m)`$ time.
  2. *Namespace Expansion & Subtree Traversal*:
     - Shallow wildcard expansion (`::*`) inspects the immediate child table of the target namespace in $`O(\text{deg}_{\text{containment}}(p))`$ time.
     - Recursive wildcard expansion (`::**`) traverses the containment subtree rooted at $`p`$ via depth-first or breadth-first search in $`O(V_{\text{subtree}} + E_{\text{subtree}}) \subseteq O(V)`$ operations without revisiting nodes.
  3. *Query Predicate Filtering*: Evaluating query filter predicate $`\Phi_{E}`$ across candidate elements checks AST classifier tags, metadata annotations, or attribute values in $`O(|\Phi_{E}|)`$ time per candidate. Since predicate expression trees are bounded by specification design ($`|\Phi_{E}| \le C_{\Phi} = O(1)`$), predicate evaluation for $`V_{\text{cand}}`$ candidate vertices executes in strictly $`O(V_{\text{cand}}) \subseteq O(V)`$ time.
  4. *Induced Subgraph Edge Preservation*: Extracting induced edges $`E_{\text{exp}}`$ iterates over incident edges of exposed vertices $`u \in V_{\text{exp}}`$. Using an indexed adjacency list or sparse multigraph representation, membership check $`v \in V_{\text{exp}}`$ executes in $`O(1)`$ time via bitset or hash table lookup, yielding total edge extraction complexity:

$$
T_{\text{induced\_edges}}(V_{\text{exp}}, E) = O\left( \sum_{u \in V_{\text{exp}}} \text{deg}(u) \right) \subseteq O(E)
$$

  5. *Viewpoint Conformance Verification*: Validating predicate consistency ($`\forall u \in V_{\text{exp}}, \Phi_{\text{vp}}(u) = \text{true}`$), mandatory element inclusion ($`\mathbf{M}_{\text{vp}} \subseteq V_{\text{exp}}`$), and exclusion non-intersection ($`V_{\text{exp}} \cap \mathbf{X}_{\text{vp}} = \emptyset`$) executes in $`O(|V_{\text{exp}}| + |\mathbf{M}_{\text{vp}}| + |\mathbf{X}_{\text{vp}}|) \subseteq O(V)`$ operations.
  6. *Expose Dependency Graph Acyclicity Checking*: Evaluating acyclicity over $`\mathcal{G}_{\text{exp\_dep}} = (\mathcal{VD}, \mathcal{R}_{\text{exp\_dep}})`$ using Tarjan's strongly connected components algorithm or Kahn's topological sort executes in deterministic $`O(|\mathcal{VD}| + |\mathcal{R}_{\text{exp\_dep}}|)`$ time.
  7. *Aggregate Compilation Unit Complexity*: The total sequential execution time for resolving, filtering, projecting, and verifying all expose declarations across all views in a compilation unit is strictly linear in the size of the model graph:

$$
T_{\text{total}}(V, E, K, N_{V}) \in O(V + E + K + N_{V} + |\mathcal{R}_{\text{exp\_dep}}|) \subseteq O(V + E)
$$

  8. *Parallel Work-Stealing Scaling (Architectural Directive 2)*: When $`M`$ independent view projections across distinct packages are evaluated concurrently on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

$$
T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{V + E}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  9. *Space Complexity & Memory Bounds*: Contiguous arena memory is bounded by $`O(V + E)`$ for lowered AST nodes. Projected views maintain index references into the underlying arena nodes, requiring $`O(|V_{\text{exp}}| + |E_{\text{exp}}|)`$ auxiliary index space. The diagnostic error sink buffer is strictly bounded by $`O(C_{\text{max\_errors}}) = O(1)`$ memory.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `PartDef_Alpha`, `ViewDef_Alpha`, `ViewDef_Beta`, `View_1`, `View_2`, `ViewpointDef_Alpha`, `ViewpointDef_Beta`, `Viewpoint_1`, `Metadata_Alpha`, `Tag_Alpha`, `param_x : Real`) across the following verification gates:

  1. **Canonical `expose` Explicit Element Path Inclusion Gate**: Declare `view def ViewDef_Alpha { expose Package_0::Classifier_Alpha, Package_0::PartDef_Alpha; }`. Ingest the model and assert that the lowering engine extracts an exposed vertex set $`V_{\text{exp}}`$ containing precisely `Classifier_Alpha` and `PartDef_Alpha`, records valid source spans, and emits zero diagnostics.
  2. **Shallow Namespace Expansion Gate (`::*`)**: Declare `view def ViewDef_Alpha { expose Package_0::*; }` where `Package_0` contains three classifiers and one nested sub-package `Package_1`. Assert that $`V_{\text{exp}}`$ contains the three immediate classifiers and `Package_1`, but does not contain elements nested inside `Package_1`.
  3. **Recursive Namespace Hierarchy Expansion Gate (`::**`)**: Declare `view def ViewDef_Alpha { expose Package_0::**; }` where `Package_0` contains a nested hierarchy of 5 packages and 50 classifiers. Assert that $`V_{\text{exp}}`$ contains 100% of the transitive membership closure (all 55 elements) and zero extraneous elements.
  4. **Predicate-Based Element Filtering Gate (`isKindOf` & `isTypeOf`)**: Construct a package containing a heterogeneous collection of parts, ports, and actions. Declare `view def ViewDef_Alpha { expose filter isKindOf(PartDef_Alpha); }`. Assert that $`V_{\text{exp}}`$ contains all and only those elements specializing `PartDef_Alpha`, rejecting non-conforming elements.
  5. **Tag & Metadata Annotation Predicate Filtering Gate**: Annotate a subset of model elements with metadata tag `@Tag_Alpha`. Declare `view def ViewDef_Alpha { expose filter @Tag_Alpha; }`. Assert that $`V_{\text{exp}}`$ contains exactly the tagged elements, executing in linear time $`O(V)`$.
  6. **Compound Boolean Query Expression Gate**: Declare `view def ViewDef_Alpha { expose filter (isKindOf(PartDef_Alpha) and @Tag_Alpha); }`. Assert that only elements simultaneously satisfying both the classifier type predicate and the metadata tag annotation are admitted into $`V_{\text{exp}}`$.
  7. **Induced Subgraph Edge Preservation Gate**: Construct a model graph containing 100 vertices and 300 relationship edges (connections, flows, allocations). Define `view def ViewDef_Alpha` exposing 30 vertices. Assert that the projected graph $`G_{\text{view}} = (V_{\text{exp}}, E_{\text{exp}})`$ contains exactly those edges whose source and target endpoints both belong to $`V_{\text{exp}}`$ ($`E_{\text{exp}} = \{ (u, v) \in \mathcal{E}_{\text{model}} \mid u, v \in V_{\text{exp}} \}`$).
  8. **Projection Soundness & Completeness Gate**: Ingest a model graph with 1,000 vertices. Assert that every vertex satisfying the expose query is included in $`V_{\text{exp}}`$ (completeness) and no vertex violating the expose query is present in $`V_{\text{exp}}`$ (soundness).
  9. **Viewpoint Conformance Verification Gate (`satisfy viewpoint`)**: Declare `viewpoint def ViewpointDef_Alpha` mandating inclusion of `Classifier_Alpha` and filtering for `@Tag_Alpha`. Declare conforming view `view def ViewDef_Alpha { satisfy viewpoint ViewpointDef_Alpha; expose Package_0::Classifier_Alpha; expose filter @Tag_Alpha; }`. Assert successful compilation and zero diagnostics emitted.
  10. **Viewpoint Conformance Violation Gate (`E0200`)**: Declare a view that exposes an element violating the viewpoint's filter predicate $`\Phi_{\text{vp}}`$ or omits a mandatory element $`\mathbf{M}_{\text{vp}}`$. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`ViewpointConformanceViolation` or `MissingMandatoryExposedElement`) and assignment of sentinel $`\bot_{\text{exp}}`$.
  11. **Unresolved Expose Target Rejection Gate (`E0200`)**: Declare `view def ViewDef_Alpha { expose Package_0::NonExistentClassifier; }`. Assert deterministic compile-time rejection with diagnostic error code `E0200` (`UnresolvedExposeTarget`) and exact lexical source coordinate mapping.
  12. **Query Filter Predicate Typing Violation Gate (`E0202`)**: Declare `view def ViewDef_Alpha { expose filter (param_x + 5.0); }` where the predicate yields a real number rather than a boolean. Assert deterministic rejection with diagnostic error code `E0202` (`TypeMismatchInQueryPredicate`).
  13. **Circular Expose Dependency Cycle Detection Gate (`E0203`)**: Declare mutually recursive view exposures where `ViewDef_Alpha` exposes `ViewDef_Beta` and `ViewDef_Beta` exposes `ViewDef_Alpha`. Assert that topological cycle detection isolates the cycle, emits diagnostic error code `E0203` (`CircularExposeDependency`) identifying participating views, and halts gracefully.
  14. **Synchronization Token Error Recovery Gate (Architectural Directive 4)**: Ingest a model containing 5 malformed expose declarations interspersed with valid code.
