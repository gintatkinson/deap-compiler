### REQ-0075: SysML v2 InterfaceDefinition (`interface def`) & InterfaceUsage Lowering

- **Normative Statement**: The Universal Schema Ingestion and Metamodel Lowering Engine shall implement the OMG Systems Modeling Language (SysML v2) and Kernel Modeling Language (KerML) InterfaceDefinition (`interface def`) and InterfaceUsage (`interface`) lowering transformations. The lowering engine shall formalize interface definitions as contractual association structures specifying dual complementary end-roles, and interface usages as communication protocol bindings between interacting component ports requiring exact conjugate role duality.

  Specifically, the lowering engine shall satisfy the following normative provisions:
  1. Metamodel Classification and AST Representation: The lowering engine shall classify `InterfaceDefinition` as a specialized `ConnectionDefinition` (specializing KerML `AssociationStructure` and `Structure`), unifying structural classification with contractual multi-ary interaction semantics. The lowering engine shall classify `InterfaceUsage` as a specialized `ConnectionUsage` (specializing KerML `ConnectorAsUsage` and `Feature`), representing an instantiated communication channel bound between directed interaction points.
  2. Binary Dual End-Role Specification: Every binary interface definition $`I`$` shall declare exactly two complementary end-roles `$`\text{ends}(I) = (e_{1}, e_{2})`$. An interface definition declaring fewer than two or more than two end-roles in a binary interface context shall be strictly rejected at compile time with structured diagnostic error code `E0200`. Each end-role $`e_{i}`$ must specify:
     - An interned role identifier $`\text{name}(e_{i}) \in \mathcal{S}_{\text{intern}}`$,
     - A declared port definition type $`\tau(e_{i}) \in \mathcal{P}_{\text{def}}`$,
     - A declared multiplicity interval $`\mu(e_{i}) = [l_{i}, u_{i}]`$` with `$`0 \le l_{i} \le u_{i}`$` and `$`u_{i} \ge 1`$,
     - Directional navigability designation $`\text{nav}(e_{i}) \in \{ \text{Navigable}, \text{NonNavigable} \}`$.
  3. Exact Conjugate Role Duality Invariant: The lowering engine shall enforce that the two end-roles of an interface definition are algebraically conjugate:
     $`\tau(e_{2}) \equiv {\sim}\tau(e_{1})`$,
     where $`{\sim}`$` denotes the KerML conjugation involution operator defined in REQ-0063. If an interface definition specifies end-roles that fail conjugate duality (`$`\tau(e_{2}) \not\equiv {\sim}\tau(e_{1})`$), the compiler shall deterministically emit diagnostic error code `E0201`.
  4. Interface Usage Port Binding and Subtyping Conformance: An interface usage $`u`$` shall bind two actual port instances `$`(p_{1}, p_{2})`$` of communicating parts to the declared end-roles `$`(e_{1}, e_{2})`$` of its typing interface definition `$`I = \tau(u)`$. The type checking engine shall verify that each actual port conforms to its corresponding end-role type under the subtyping partial order:
     $`\text{type}(p_{1}) \le \tau(e_{1}) \wedge \text{type}(p_{2}) \le \tau(e_{2})`$.
     By the conjugate role duality of $`I`$`, this condition guarantees mutual conjugate compatibility between the connected ports: `$`\text{type}(p_{1}) \le {\sim}\text{type}(p_{2})`$. If either port instance fails to specialize its bound end-role type, the compiler shall emit diagnostic error code `E0201`.
  5. Dangling and Cardinality Invariants: An interface usage $`u`$` must bind exactly two compatible port instances (`$`|\text{bound\_ports}(u)| = 2`$). An interface usage that leaves one or both end-roles unbound, binds more than two ports, or references non-existent port instances shall be strictly rejected at compile time with diagnostic error code `E0220`.
  6. Owned Flows, Messages, and Protocol Adherence: An `interface def` may declare owned item flows (`flow`), message exchanges, and behavioral interactions between its end-roles. All items, signals, and payloads routed across an interface usage $`u`$` must conform to the payload types and transfer rates declared on `$`I`$. Any payload type mismatch or rate multiplicity violation shall trigger diagnostic error code `E0202`. All message sequences and interaction occurrences across $`u`$` must conform to the temporal interaction constraints (such as temporal interval sequences and statechart protocols) declared on `$`I`$; any protocol ordering violation shall trigger diagnostic error code `E0400`.
  7. Interface Specialization and Subtyping (Algorithmic Bound NP-3): An interface definition $`I_{\text{sub}}`$` may specialize another interface definition `$`I_{\text{base}}`$` (`$`I_{\text{sub}} \le I_{\text{base}}`$) strictly under monotonic covariance:
     - End-role subtyping: for each end $`e_{i}`$`, `$`\tau(e_{i}^{\text{sub}}) \le \tau(e_{i}^{\text{base}})`$,
     - Multiplicity interval narrowing: $`\mu(e_{i}^{\text{sub}}) \subseteq \mu(e_{i}^{\text{base}})`$,
     - Contract invariant strengthening: $`\Psi_{\text{sub}} \implies \Psi_{\text{base}}`$.
     Interface inheritance hierarchies shall form a bounded monotonic meet-semilattice. Multiple inheritance shall be resolved deterministically via C3 linearization without backtracking in $`O(V + E)`$` polynomial time. Circular interface inheritance (`$`I_{A} \le I_{B} \le I_{A}`$) shall be detected and rejected with diagnostic error code `E0203`.
  8. Architectural Directives Compliance:
     - Directive 1 (Deterministic UUIDv5): Every lowered `InterfaceDefinition`, `InterfaceUsage`, and interface end-role node shall be assigned a deterministic RFC 4122 UUIDv5 identifier computed from the compiler namespace OID and canonical fully qualified symbol path. Time-based UUIDs are strictly banned.
     - Directive 2 (Bounded Work-Stealing Parallelism): Ingestion, lowering, and verification of interface definitions and usages across independent compilation units shall be scheduled strictly on a bounded work-stealing thread pool with worker thread upper bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - Directive 3 (String Interner Memory Allocation Exception): All interface names, end-role symbols, and port paths shall be interned into the global symbol interner pool during initial lexical ingest as the sole permitted exception to zero-copy arena management in accordance with REQ-0036.
     - Directive 4 (Synchronization Token Error Recovery): The interface lowering engine shall implement synchronization token error recovery in accordance with REQ-0013 and REQ-0016: upon detecting a syntax error, invalid arity (`E0200`), direction/duality mismatch (`E0201`), payload mismatch (`E0202`), circular inheritance (`E0203`), or dangling interface (`E0220`), the engine shall record the structured diagnostic into the preallocated diagnostic sink buffer $`\mathcal{D}_{\text{sink}}`$`, substitute a typed error sentinel `$`\bot`$, and resynchronize at the next definition or delimiter token (`;`, `}`, `end interface`). If accumulated diagnostics reach capacity limit $`C_{\text{max\_errors}}`$, diagnostic code `E0199` shall be emitted and compilation terminated gracefully.
     - Directive 5 (Panic-Free Release Execution and Benchmarking Isolation): Compiler library code shall strictly enforce a deterministic, non-panicking execution contract with total-function error handling. Performance latency (< 25 ms) and peak RSS memory (< 100 MB for $`10^5`$ interface bindings) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests.
     - Pure Abstract Schema: All diagnostic messages, test models, and examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `InterfaceDef_0`, `InterfaceDef_Alpha`, `InterfaceDef_Beta`, `InterfaceUsage_0`, `PortDef_0`, `PortDef_1`, `Port_1`, `Port_2`, `Part_1`, `Part_2`, `Feature_A`, `Feature_B`, `param_x : Real`), with zero domain-specific concepts or mock data.

- **Formal Invariant**: The KerML subtyping poset $`(\text{Classifiers}, \le)`$ formalizes `InterfaceDefinition` and `InterfaceUsage` within the classifier taxonomy:

```math
\begin{aligned}
\text{InterfaceDefinition} &\le \text{ConnectionDefinition} \le \text{PartDefinition} \le \text{Structure} \le \text{Class} \le \text{Classifier} \\
\text{InterfaceDefinition} &\le \text{AssociationStructure} \le \text{Association} \le \text{Relationship} \le \text{Element} \\
\text{InterfaceUsage} &\le \text{ConnectionUsage} \le \text{PartUsage} \le \text{Feature}
\end{aligned}
```

Each interface definition $`I \in \mathcal{I}_{\text{def}}`$ is formalized as an 8-tuple:

```math
I = \langle \text{id}_{I}, \text{name}_{I}, \mathcal{E}_{I}, \mathcal{F}_{I}, \mathcal{S}_{I}, \Psi_{I}, \mu_{I}, \Delta_{I} \rangle
```

where:

```math
\begin{aligned}
\text{id}_{I} &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_{I} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\mathcal{E}_{I} &= (e_{1}, e_{2}) \quad (\text{ordered dual end-roles}, \; |\mathcal{E}_{I}| = 2) \\
\mathcal{F}_{I} &= \{ f_{1}, \dots, f_{m} \} \quad (\text{owned flow and behavioral interaction feature handles}) \\
\mathcal{S}_{I} &\subseteq \mathcal{I}_{\text{def}} \quad (\text{direct super-interface definitions}) \\
\Psi_{I} &= \{ \psi_{1}, \dots, \psi_{k} \} \quad (\text{formal contract invariants and temporal protocol constraints}) \\
\mu_{I} &= [l_{I}, u_{I}] \subseteq \mathbb{N}_{0} \times (\mathbb{N}_{0} \cup \{ \infty \}) \quad (\text{multiplicity interval}, \; 0 \le l_{I} \le u_{I} \wedge u_{I} \ge 1) \\
\Delta_{I} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor})
\end{aligned}
```

Each interface end-role $`e_{i} \in \mathcal{E}_{I}`$ is formalized as a 6-tuple:

```math
e_{i} = \langle \text{id}_{e_{i}}, \text{name}_{e_{i}}, \tau(e_{i}), \mu(e_{i}), \text{nav}(e_{i}), \Delta_{e_{i}} \rangle
```

where:

```math
\begin{aligned}
\text{id}_{e_{i}} &\in \mathbb{N}_{32} \quad (\text{contiguous arena feature handle}) \\
\text{name}_{e_{i}} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned role name}) \\
\tau(e_{i}) &\in \mathcal{P}_{\text{def}} \quad (\text{declared port definition classifier type}) \\
\mu(e_{i}) &= [l_{e_{i}}, u_{e_{i}}] \subseteq \mathbb{N}_{0} \times (\mathbb{N}_{0} \cup \{ \infty \}) \quad (\text{role multiplicity interval}, \; 0 \le l_{e_{i}} \le u_{e_{i}} \wedge u_{e_{i}} \ge 1) \\
\text{nav}(e_{i}) &\in \{ \text{Navigable}, \text{NonNavigable} \} \quad (\text{directional navigability flag}) \\
\Delta_{e_{i}} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor})
\end{aligned}
```

Binary Interface Arity Invariant: Every binary interface definition must declare exactly two end-roles:

```math
\text{Arity}(I) = |\mathcal{E}_{I}| = 2
```

Dual End-Role Conjugate Duality Invariant: The declared types of the two interface ends must be exact conjugates under the KerML conjugation operator:

```math
\text{ends}(I) = (e_{1}, e_{2}) \implies \tau(e_{2}) \equiv {\sim}\tau(e_{1}) \quad \wedge \quad \tau(e_{1}) \equiv {\sim}\tau(e_{2})
```

where $`{\sim} : \mathcal{P}_{\text{def}} \to \mathcal{P}_{\text{def}}`$ is the algebraic involution over port classifiers defined in REQ-0063.

Each interface usage $`u`$ is formalized as a 7-tuple:

```math
u = \langle \text{id}_{u}, \text{name}_{u}, \tau(u), \mathcal{B}_{u}, \mathcal{F}_{u}, \Delta_{u}, \text{span}_{u} \rangle
```

where:

```math
\begin{aligned}
\text{id}_{u} &\in \mathbb{N}_{32} \quad (\text{contiguous arena usage handle}) \\
\text{name}_{u} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned usage identifier}) \\
\tau(u) &\in \mathcal{I}_{\text{def}} \quad (\text{typing interface definition}) \\
\mathcal{B}_{u} &= (p_{1}, p_{2}) \quad (\text{ordered pair of bound port instances}) \\
\mathcal{F}_{u} &= \{ f_{u, 1}, \dots, f_{u, k} \} \quad (\text{owned flow and feature occurrences}) \\
\Delta_{u} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 anchor}) \\
\text{span}_{u} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

Interface Usage Port Binding and Conjugate Conformance Invariant: An interface usage $`u`$` binding actual port instances `$`(p_{1}, p_{2})`$` to end-roles `$`(e_{1}, e_{2})`$` of `$`I = \tau(u)`$ satisfies:

```math
\begin{aligned}
|\mathcal{B}_{u}| &= 2 \quad \wedge \quad \mathcal{B}_{u} = (p_{1}, p_{2}) \\
\text{type}(p_{1}) \le \tau(e_{1}) &\wedge \text{type}(p_{2}) \le \tau(e_{2}) \implies \text{type}(p_{1}) \le {\sim}\text{type}(p_{2}) \wedge \text{type}(p_{2}) \le {\sim}\text{type}(p_{1})
\end{aligned}
```

Feature-Level Directional Complementarity: For all directed features $`f \in \mathcal{F}_{\tau(p_{1})}`$`, there exists a corresponding complementary feature `$`f' \in \mathcal{F}_{\tau(p_{2})}`$:

```math
\forall f \in \mathcal{F}_{\tau(p_{1})}, \quad \exists f' \in \mathcal{F}_{\tau(p_{2})} : \left( \text{name}(f') = \text{name}(f) \wedge \tau(f') \le \tau(f) \wedge \text{dir}(f') = {\sim}\text{dir}(f) \right)
```

Flow Payload Conservation Invariant: For every item flow $`w \in \mathcal{F}_{I}`$` transferring payload across the interface between `$`e_{1}`$` and `$`e_{2}`$:

```math
\forall w \in \mathcal{F}_{I}, \quad \tau(\text{payload}(w)) \in \mathcal{T}_{\text{item}} \wedge \mu(\text{payload}(w)) \subseteq \mu(\text{flow}(w))
```

Subtyping Meet-Semilattice and C3 Linearization Invariant (Algorithmic Bound NP-3): Let $`(\mathcal{I}_{\text{def}}, \le)`$ denote the subtyping poset of interface definitions:

```math
\begin{aligned}
I_{\text{sub}} \le I_{\text{base}} \iff &\left( \forall i \in \{1, 2\}, \, \tau(e_{i}^{\text{sub}}) \le \tau(e_{i}^{\text{base}}) \wedge \mu(e_{i}^{\text{sub}}) \subseteq \mu(e_{i}^{\text{base}}) \right) \\
&\wedge \left( \forall f \in \mathcal{F}_{I_{\text{base}}}, \, \exists f' \in \mathcal{F}_{I_{\text{sub}}} : \tau(f') \le \tau(f) \right) \\
&\wedge (\Psi_{\text{sub}} \implies \Psi_{\text{base}})
\end{aligned}
```

For an interface definition $`I`$` with ordered direct supertypes `$`\mathcal{S}_{I} = \langle S_{1}, \dots, S_{k} \rangle`$, the deterministic resolution order is computed by C3 linearization:

```math
\text{C3}(I) = [I] \mathbin{\Vert} \text{merge}(\text{C3}(S_{1}), \dots, \text{C3}(S_{k}), [S_{1}, \dots, S_{k}])
```

Diagnostic Code Trigger Invariants: Diagnostic emissions are strictly bound to the standardized taxonomy of REQ-0191:

```math
\begin{aligned}
|\mathcal{E}_{I}| \ne 2 &\implies \text{Diagnostic}(I, \text{DiagnosticCode::E0200}, \text{InvalidInterfaceArity}) \in \mathcal{D}_{\text{sink}} \\
\tau(e_{2}) \not\equiv {\sim}\tau(e_{1}) &\implies \text{Diagnostic}(I, \text{DiagnosticCode::E0201}, \text{InterfaceEndDualityMismatch}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{B}_{u}| \ne 2 &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0220}, \text{DanglingInterfaceEnd}) \in \mathcal{D}_{\text{sink}} \\
\neg(\tau(p_{1}) \le \tau(e_{1})) \vee \neg(\tau(p_{2}) \le \tau(e_{2})) &\implies \text{Diagnostic}(u, \text{DiagnosticCode::E0201}, \text{InterfacePortBindingTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\exists w \in \mathcal{F}_{I} : \neg \text{FlowCompatible}(w, u) &\implies \text{Diagnostic}(w, \text{DiagnosticCode::E0202}, \text{InterfaceFlowPayloadMismatch}) \in \mathcal{D}_{\text{sink}} \\
\text{HasInheritanceCycle}(G_{\text{interface\_inherit}}) &\implies \text{Diagnostic}(G_{\text{interface\_inherit}}, \text{DiagnosticCode::E0203}, \text{CircularInterfaceInheritance}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Deterministic RFC 4122 UUIDv5 Identification Invariant:

\Delta_{I} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(I)) \\
\Delta_{e_{i}} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(I) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{name}(e_{i})) \\

- **Computational Complexity & Algorithmic Bounds**: Interface definition lowering, dual end-role conjugation, and interface usage binding verification execute within Complexity Class $`\mathbf{P}`$. The computational characteristics and bounds are formalized as follows:
  1. Frontier NP-3 Complexity Context: Subtyping lattice consistency and feature redefinition across multiple inheritance hierarchies is NP-complete for arbitrary, unconstrained partially ordered sets (posets). In the sovereign compiler, the interface subtyping space is restricted to a monotonic bounded meet-semilattice $`(\mathcal{I}_{\text{def}}, \le)`$ with unambiguous C3 linearization. This structural restriction eliminates exponential backtracking search, ensuring all subtyping checks and feature redefinition verifications execute in deterministic polynomial time.
  2. Dual End-Role Conjugate Duality Check: For an interface definition $`I`$`, evaluating `$`\tau(e_{2}) \equiv {\sim}\tau(e_{1})`$` verifies that the feature rosters of `$`\tau(e_{1})`$` and `$`\tau(e_{2})`$` are pairwise complementary. With `$`F`$` features in the port definition, using interned symbol table lookups, this verification evaluates in strictly deterministic `$`O(F)`$` time (or `$`O(1)`$ when port definitions are nominal and previously lowered).
  3. Interface Usage Port Binding Verification: For an interface usage $`u`$` binding actual port instances `$`(p_{1}, p_{2})`$` to declared end-roles `$`(e_{1}, e_{2})`$`, verifying nominal subtyping `$`\text{type}(p_{1}) \le \tau(e_{1})`$` and `$`\text{type}(p_{2}) \le \tau(e_{2})`$` evaluates in strictly deterministic `$`O(1)`$ constant time via cached transitive closure bitsets and topological index in the subtyping meet-semilattice.
  4. Flow Payload Conformance Check: For $`K`$` declared item flows across `$`I`$`, verifying payload type conformance against bound ports evaluates in deterministic `$`O(K)`$ linear time.
  5. Interface Arity and Dangling Check: Verifying $`|\mathcal{E}_{I}| = 2`$` and `$`|\mathcal{B}_{u}| = 2`$` evaluates in `$`O(1)`$ constant time with zero heap allocations.
  6. C3 Linearization of Interface Hierarchy: For an interface definition specializing multiple parent interfaces across $`V`$` transitive ancestor interfaces and `$`E`$` specialization edges, computing the C3 linearized resolution order executes in `$`O(V + E)`$ time using deterministic list-merging.
  7. Aggregate Model Complexity: For an entire AST model containing $`M`$` interface definitions, `$`N`$` interface usages, `$`F_{\text{total}}`$` total interface and port features, and `$`E_{\text{sub}}`$ specialization edges:

```math
T(M, N, F_{\text{total}}, E_{\text{sub}}) = O(M + N + F_{\text{total}} + E_{\text{sub}})
```

  8. Bounded Work-Stealing Parallelism: Parallel lowering and binding verification across independent compilation units scheduled onto a bounded work-stealing thread pool with $`N_{\text{max\_workers}}`$ workers executes within:

```math
T_{\text{parallel}}(M, N, F_{\text{total}}, E_{\text{sub}}) = O\left(\frac{M + N + F_{\text{total}} + E_{\text{sub}}}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}}\right)
```

  9. Space Complexity: Auxiliary heap allocation is strictly $`O(1)`$` beyond contiguous bump arena storage for AST nodes (`$`O(M + N + F_{\text{total}})`$`) and the preallocated diagnostic sink buffer (`$`O(C_{\text{max\_errors}}) = O(1)`$), ensuring zero heap reallocation during the lowering pass.
