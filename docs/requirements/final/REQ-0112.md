### REQ-0112: Parametric Operational Envelopes & Closed Interval $`[v_{\min}, v_{\max}]`$ Validation

- **Normative Statement**: The physical metrology and abstract flow conservation network engine of Subsystem 5 shall validate system parameters, attributes, structural features, and operational signals against declared operational envelopes specified as closed real intervals $`[v_{\min}, v_{\max}] \subset \mathbb{R}`$ accompanied by engineering units and physical dimensions in the 7-dimensional rational vector space $`\mathbb{Q}^7`$.

  Specifically, the metrology engine, semantic type checker, and constraint synthesis pipeline shall strictly enforce the following structural, dimensional, interval-arithmetic, and diagnostic invariants:
  1. **Parametric Operational Envelope Formalism & Closed Interval Semantics**:
     - System parameters, component attributes, port signals, through variables, across variables, and state variables may declare an operational envelope defining the permissible continuous domain of operation.
     - An operational envelope $`\mathcal{E}_x`$ shall be defined over the extended real numbers $`\overline{\mathbb{R}} = \mathbb{R} \cup \{-\infty, +\infty\}`$ as a closed interval $`[v_{\min}, v_{\max}] = \{ v \in \mathbb{R} \mid v_{\min} \le v \le v_{\max} \}`$, where $`v_{\min} \in \mathbb{R} \cup \{-\infty\}`$ denotes the lower operating bound and $`v_{\max} \in \mathbb{R} \cup \{+\infty\}`$ denotes the upper operating bound.
     - When either bound is infinite ($`v_{\min} = -\infty`$ or $`v_{\max} = +\infty`$), the interval shall represent a semi-infinite operational envelope (e.g., $`(-\infty, v_{\max}]`$ or $`[v_{\min}, +\infty)`$), evaluated using standard extended real arithmetic.
     - Each operational envelope shall bind an associated physical dimension vector $`\mathbf{d}_{\mathcal{E}} \in \mathbb{Q}^7`$ over the International System of Quantities (ISQ) base dimensions $`[M, L, T, I, \Theta, N, J]`$ and a declared coherent or non-coherent measurement unit $`u_{\mathcal{E}} \in \mathcal{U}`$.
  2. **Interval Bound Validity & Degenerate Point Interval Handling**:
     - The metrology validator shall verify the proper ordering of interval bounds at compile time:

$$
v_{\min} \le v_{\max}
$$

     - Inverted Bounds Rejection: Any operational envelope declaration exhibiting an inverted bound relationship ($`v_{\min} \gt v_{\max}`$) represents a mathematically empty set and shall be deterministically rejected at compile time with diagnostic error code `E0300` (`InvalidOperationalEnvelopeBounds`) in accordance with REQ-0191.
     - Degenerate Singleton Intervals: When $`v_{\min} = v_{\max}`$, the envelope shall be recognized as a valid degenerate singleton point interval $`[v_{\min}, v_{\min}] = \{ v_{\min} \}`$, representing an invariant fixed-parameter constraint.
  3. **Physical Dimensional Homogeneity & Exact Rational Unit Commensurability**:
     - All constituent components of an operational envelope declaration--including the lower bound $`v_{\min}`$, upper bound $`v_{\max}`$, nominal operating point $`v_{\text{nom}}`$, initial state value $`v_{\text{init}}`$, and failsafe default value $`v_{\text{default}}`$--must share identically equal physical dimension vectors in $`\mathbb{Q}^7`$:

$$
\mathbf{d}(v_{\min}) \equiv \mathbf{d}(v_{\max}) \equiv \mathbf{d}(v_{\text{nom}}) \equiv \mathbf{d}(v_{\text{init}}) \equiv \mathbf{d}(v_{\text{default}}) \equiv \mathbf{d}(x)
$$

     - Any dimensional mismatch detected among bounds or operating points shall be deterministically rejected at compile time with diagnostic error code `E0300` (`DimensionalMismatch`).
     - Unit Commensurability & Exact Rational Scaling: If bounds and values are declared using disparate measurement units sharing identical physical dimensions in $`\mathbb{Q}^7`$, the compiler shall verify unit commensurability and normalize all numerical quantities to canonical coherent SI base units using exact rational scale factors $`c \in \mathbb{Q}^+`$ ($`c = \frac{p}{q}`$, $`p \in \mathbb{Z}^+`$, $`q \in \mathbb{Z}^+`$, $`\gcd(p, q) = 1`$) prior to interval comparison. Floating-point conversions in interval bounds normalization are strictly prohibited.
  4. **Compile-Time Static Point Containment & Boundary Verification**:
     - Static Constant Parameters: For any attribute or parameter $`x_{\text{const}}`$ with a statically evaluable compile-time value $`v_{\text{const}}`$, the compiler shall verify membership in the declared operational envelope:

$$
v_{\min} \le v_{\text{const}} \le v_{\max} \iff v_{\text{const}} \in \mathcal{E}_x
$$

     - Initial State Values: For any dynamic state variable or physical signal $`x(t)`$ with a declared initial condition $`v_{\text{init}} = x(0)`$, the compiler shall verify initial state containment:

$$
v_{\min} \le v_{\text{init}} \le v_{\max} \iff v_{\text{init}} \in \mathcal{E}_x
$$

     - Nominal Design Operating Points: For any signal or parameter declaring a nominal operating point $`v_{\text{nom}}`$, the compiler shall verify nominal containment:

$$
v_{\min} \le v_{\text{nom}} \le v_{\max} \iff v_{\text{nom}} \in \mathcal{E}_x
$$

     - Failsafe / Default Values: For any signal or parameter declaring a failsafe fallback or default value $`v_{\text{default}}`$, the compiler shall verify default value containment:

$$
v_{\min} \le v_{\text{default}} \le v_{\max} \iff v_{\text{default}} \in \mathcal{E}_x
$$

     - Compile-Time Out-of-Bounds Diagnostics: If any static constant, initial state, nominal point, or failsafe default value falls strictly outside the declared closed envelope ($`v \lt v_{\min}`$ or $`v \gt v_{\max}`$), the compiler shall deterministically reject the model at compile time with diagnostic error code `E0301` (`OperationalEnvelopeViolation`).
     - Boundary Inclusivity: Boundary values exactly coinciding with interval endpoints ($`v = v_{\min}`$ or $`v = v_{\max}`$) satisfy closed interval containment unconditionally and shall produce zero diagnostic warnings or errors.
  5. **Multi-Tier Nested Operational Envelopes & Monotonic Inclusion**:
     - Parameters and signals may define a hierarchy of nested operational envelopes corresponding to distinct operational and safety regimes, including:
       * Normal Operating Range: $`\mathcal{E}_{\text{normal}} = [v_{\min}^{\text{norm}}, v_{\max}^{\text{norm}}]`$
       * Extended / Degraded Operational Envelope: $`\mathcal{E}_{\text{extended}} = [v_{\min}^{\text{ext}}, v_{\max}^{\text{ext}}]`$
       * Hard Safety / Damage Limits: $`\mathcal{E}_{\text{safety}} = [v_{\min}^{\text{safe}}, v_{\max}^{\text{safe}}]`$
     - Monotonic Inclusion Invariant: The compiler shall enforce strict subset monotonicity across declared envelope tiers:

$$
\mathcal{E}_{\text{normal}} \subseteq \mathcal{E}_{\text{extended}} \subseteq \mathcal{E}_{\text{safety}}
$$

       requiring:

$$
v_{\min}^{\text{safe}} \le v_{\min}^{\text{ext}} \le v_{\min}^{\text{norm}} \le v_{\text{nom}} \le v_{\max}^{\text{norm}} \le v_{\max}^{\text{ext}} \le v_{\max}^{\text{safe}}
$$

     - Inverted Hierarchy Diagnostic: Any declaration violating envelope subset monotonicity (e.g., $`v_{\max}^{\text{norm}} \gt v_{\max}^{\text{safe}}`$ or $`v_{\min}^{\text{norm}} \lt v_{\min}^{\text{safe}}`$) shall be deterministically rejected at compile time with diagnostic error code `E0300` (`InvertedEnvelopeHierarchy`).
  6. **Interconnect Envelope Compatibility & Closed Interval Intersection**:
     - When two directed ports or structural interfaces $`A`$ and $`B`$ are connected via an abstract flow branch or signal interconnect, the compiler shall compute the joint operational envelope as the intersection of their individual envelopes:

$$
\mathcal{E}_{\text{joint}} = \mathcal{E}_A \cap \mathcal{E}_B = [\max(v_{\min, A}, v_{\min, B}), \min(v_{\max, A}, v_{\max, B})]
$$

     - Compatibility Condition: The joint operational envelope must be non-empty:

$$
\mathcal{E}_A \cap \mathcal{E}_B \ne \emptyset \iff \max(v_{\min, A}, v_{\min, B}) \le \min(v_{\max, A}, v_{\max, B})
$$

     - Disjoint Envelopes Rejection: If the intersection is empty ($`\max(v_{\min, A}, v_{\min, B}) \gt \min(v_{\max, A}, v_{\max, B})`$), the connected ports cannot operate at any shared physical point. The compiler shall deterministically reject the interconnect at compile time with diagnostic error code `E0301` (`DisjointOperationalEnvelopes`).
  7. **Dynamic Symbolic Constraint AST Synthesis & Runtime Lowering**:
     - For dynamic time-varying signals and symbolic expressions $`x(t)`$, the constraint synthesis pipeline shall generate formal AST assertion nodes representing the operational envelope invariant:

$$
\forall t \ge 0, \quad v_{\min} \le x(t) \le v_{\max}
$$

     - Synthesized constraint expressions shall be lowered into:
       * LUMI IR SSA basic blocks emitting conditional branch guards or clamping primitives,
       * SMT-LIB2 / Z3 verification assertions encoding quantifier-free linear real arithmetic (QF_LRA) formulas per REQ-0188,
       * Continuous simulation solver zero-crossing event equations triggering envelope boundary detection per REQ-0179.
  8. **Diagnostic Error Reporting, Cascade Poisoning Suppression & Error Recovery**:
     - All diagnostic emissions (`E0300`, `E0301`) shall attach source-mapped lexical byte spans identifying the exact offending bound, expression, or interconnect.
     - When an envelope fails validation, the validator shall substitute a typed error sentinel $`\bot_{\text{env}}`$ on the invalid attribute. Consuming expressions and downstream network equations encountering $`\bot_{\text{env}}`$ shall suppress secondary cascade diagnostics.
  9. **Architectural Directives Compliance**:
     - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every declared operational envelope AST node, bound expression node, and synthesized containment constraint AST node shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier hashed from the compiler namespace OID and the node fully qualified topological path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(n))`$) in accordance with REQ-0010.
     - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel traversal, dimensional verification, interval arithmetic checking, and constraint synthesis across independent packages and components shall execute concurrently on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ in accordance with REQ-0012.
     - *Directive 3 (String Interner Memory Allocation Exception)*: Parameter names, signal symbols, unit identifiers, and envelope labels shall be interned into the deduplicated global string interner pool during lexical analysis per REQ-0036 as the sole permitted exception to zero-copy memory management.
     - *Directive 4 (Synchronization Token Error Recovery)*: The metrology parser and validator shall implement synchronization token error recovery on statement delimiters (`;`) and block boundaries (`}`). When semantic violations occur (`E0300`, `E0301`), diagnostics shall accumulate in the error sink buffer $`\mathcal{D}_{\text{sink}}`$, substitute typed error sentinels ($`\bot_{\text{env}}`$, $`\bot_{\text{dim}}`$), and continue auditing subsequent model elements. If accumulated diagnostics reach $`C_{\text{max\_errors}}`$, terminal diagnostic `E0199` shall be emitted and compilation halted gracefully in accordance with REQ-0013 and REQ-0016.
     - *Directive 5 (Panic-Free Release Isolation)*: The operational envelope validation pipeline shall enforce a deterministic, non-panicking execution contract with total-function error handling. Verification latency ($`\lt 25\text{ ms}`$) and peak RSS memory ($`\lt 100\text{ MB}`$ for $`10^5`$ envelope validations) shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests in accordance with REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Package_1`, `Classifier_Alpha`, `Classifier_Beta`, `Port_1`, `Port_2`, `Flow_A`, `param_x : Real`, `param_y : Real`, `Signal_Alpha`, `Signal_Beta`, `Envelope_Alpha`, `Envelope_Beta`, `Quantity_1`, `Unit_Alpha`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$ denote the universe of allocated AST nodes in contiguous arena storage.

  The 7-dimensional physical quantity dimension space is formalized as a rational vector space over the field $`\mathbb{Q}`$:

$$
\mathbb{Q}^7 = \{ \mathbf{d} = (\alpha, \beta, \gamma, \delta, \epsilon, \zeta, \eta) \mid \alpha, \beta, \gamma, \delta, \epsilon, \zeta, \eta \in \mathbb{Q} \}
$$

  where coordinate positions correspond to the canonical ISQ basis $`\mathcal{B} = \{ [M], [L], [T], [I], [\Theta], [N], [J] \}`$.

  An operational envelope $`\mathcal{E}`$ associated with an attribute, parameter, or signal $`x`$ is formalized as a 10-tuple:

$$
\mathcal{E} = \langle \text{id}_{\mathcal{E}}, \text{name}_{\mathcal{E}}, v_{\min}, v_{\max}, v_{\text{nom}}, \mathbf{d}_{\mathcal{E}}, u_{\mathcal{E}}, \text{tier}_{\mathcal{E}}, \Delta_{\mathcal{E}}, \text{span}_{\mathcal{E}} \rangle
$$

  where:

$$
\begin{aligned}
\text{id}_{\mathcal{E}} &\in \mathbb{N}_{32} \quad (\text{contiguous arena handle}) \\
\text{name}_{\mathcal{E}} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned envelope name identifier}) \\
v_{\min}, v_{\max} &\in \overline{\mathbb{R}} \quad (\text{lower and upper bounds, } \overline{\mathbb{R}} = \mathbb{R} \cup \{-\infty, +\infty\}) \\
v_{\text{nom}} &\in \mathbb{R} \cup \{ \bot_{\text{val}} \} \quad (\text{nominal operating point}) \\
\mathbf{d}_{\mathcal{E}} &\in \mathbb{Q}^7 \cup \{ \bot_{\text{dim}} \} \quad (\text{inferred physical dimension vector}) \\
u_{\mathcal{E}} &\in \mathcal{U} \quad (\text{declared engineering unit}) \\
\text{tier}_{\mathcal{E}} &\in \{ \text{Normal}, \text{Extended}, \text{Safety} \} \quad (\text{operational envelope severity tier}) \\
\Delta_{\mathcal{E}} &\in \{0, 1\}^{128} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_{\mathcal{E}} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
$$

  Closed Real Interval Semantics:

$$
\mathcal{E}_x = [v_{\min}, v_{\max}] = \{ v \in \mathbb{R} \mid v_{\min} \le v \le v_{\max} \}
$$

  Interval Ordering & Non-Emptiness Invariant:

$$
v_{\min} \le v_{\max}
$$

  When $`v_{\min} = v_{\max}`$, the envelope defines a degenerate singleton point interval:

$$
[v_{\min}, v_{\min}] = \{ v_{\min} \}
$$

  Physical Dimensional Homogeneity Invariant:

$$
\begin{aligned}
\mathbf{d}(v_{\min}) \equiv \mathbf{d}(v_{\max}) &\equiv \mathbf{d}(v_{\text{nom}}) \equiv \mathbf{d}_{\mathcal{E}} \\
\mathbf{d}(v_{\text{init}}) &\equiv \mathbf{d}_{\mathcal{E}} \\
\mathbf{d}(v_{\text{default}}) &\equiv \mathbf{d}_{\mathcal{E}} \\
\mathbf{d}(x) &\equiv \mathbf{d}_{\mathcal{E}}
\end{aligned}
$$

$$
\begin{aligned}
\tilde{v}_{\min} &= c_{\min} \cdot v_{\min} \\
\tilde{v}_{\max} &= c_{\max} \cdot v_{\max} \\
\tilde{v}_{\text{nom}} &= c_{\text{nom}} \cdot v_{\text{nom}}
\end{aligned}
$$

  Normalized SI Bound Invariant:

$$
\tilde{v}_{\min} \le \tilde{v}_{\text{nom}} \le \tilde{v}_{\max}
$$

  Compile-Time Static Point Containment Invariants:

$$
\begin{aligned}
\forall x_{\text{const}} \text{ with constant value } v_{\text{const}}, &\quad v_{\min} \le v_{\text{const}} \le v_{\max} \iff v_{\text{const}} \in \mathcal{E}_x \\

\forall x \text{ with nominal operating point } v_{\text{nom}}, &\quad v_{\min} \le v_{\text{nom}} \le v_{\max} \iff v_{\text{nom}} \in \mathcal{E}_x \\

\end{aligned}

- **Computational Complexity & Algorithmic Bounds**: Parametric operational envelope validation, interval ordering checking, dimensional verification, static containment testing, and assertion AST synthesis execute strictly within Complexity Class $`\mathbf{P}`$.

  For an MBSE compilation unit containing $`N`$ declared parameters/signals, $`K`$ operational envelope tiers per parameter, and $`M`$ connected interface pairs:
  1. *Interval Bound Ordering & Degenerate Point Detection*:
     - Comparing lower bound $`v_{\min}`$ and upper bound $`v_{\max}`$ evaluates in $`O(1)`$ real comparisons per envelope tier.
     - For $`N`$ parameters with $`K`$ tiers, total ordering validation requires:

$$
T_{\text{ordering}}(N, K) \in O(N \cdot K)
$$

  2. *Dimensional Homogeneity & Rational Unit Conversion*:
     - Verifying equality across 7 rational exponents in $`\mathbb{Q}^7`$ executes in exactly 7 coordinate checks ($`O(1)`$ time).
     - Scaling declared bounds and nominal values to coherent SI units performs at most 3 exact rational multiplications per envelope, executing in $`O(1)`$ operations.
     - Total dimensional and unit normalization executes in:

$$
T_{\text{dim\_norm}}(N, K) \in O(N \cdot K)
$$

  3. *Compile-Time Static Point Containment Testing*:
     - Verifying static constant $`v_{\text{const}}`$, initial state $`v_{\text{init}}`$, nominal point $`v_{\text{nom}}`$, or default value $`v_{\text{default}}`$ against interval $`[v_{\min}, v_{\max}]`$ performs exactly 2 real comparisons per value: $`v_{\min} \le v \le v_{\max}`$.
     - Total static containment testing executes in deterministic linear time:

$$
T_{\text{containment}}(N, K) \in O(N \cdot K)
$$

  4. *Multi-Tier Monotonic Hierarchy Verification*:
     - Verifying nested subset inclusions $`\mathcal{E}_1 \subseteq \mathcal{E}_2 \subseteq \dots \subseteq \mathcal{E}_K`$ across $`K`$ tiers per parameter requires $`2(K - 1)`$ comparisons.
     - Total multi-tier hierarchy verification executes in:

$$
T_{\text{tier\_check}}(N, K) \in O(N \cdot K)
$$

  5. *Interconnect Joint Envelope Intersection*:
     - Computing the intersection of two closed intervals for each of the $`M`$ connected interface pairs performs 2 extremum operations ($`\max`$ of lower bounds, $`\min`$ of upper bounds) and 1 inequality comparison ($`\le`$).
     - Total interconnect envelope compatibility evaluation executes in:

$$
T_{\text{interconnect}}(M) \in O(M)
$$

  6. *Dynamic Constraint AST Synthesis*:
     - Synthesizing assertion AST nodes for continuous signals allocates fixed-size AST expressions in contiguous arena storage in $`O(1)`$ operations per parameter.
     - Total synthesis time across all dynamic signals requires:

$$
T_{\text{synth}}(N) \in O(N)
$$

  7. *Aggregate Algorithmic Complexity*:
     - Total sequential execution time across all envelope processing stages is strictly linear with respect to the number of parameters and interconnects:

$$
T_{\text{total}}(N, K, M) \in O(N \cdot K + M)
$$

     Given that the number of envelope tiers per parameter is bounded by a small constant ($`K \le K_{\max} = 3`$), total execution simplifies to:

$$
T_{\text{total}}(N, M) \in O(N + M)
$$

  8. *Parallel Work-Stealing Scaling (Architectural Directive 2)*:
     - When validating envelopes across $`P`$ independent packages over $`N_{\text{max\_workers}}`$ threads on a bounded work-stealing thread pool:

$$
T_{\text{parallel}}(N, M, N_{\text{max\_workers}}) \in O\left( \frac{N + M}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
$$

  9. *Space Complexity & Memory Bounds*:
     - Contiguous arena storage for envelope tuples, bound expressions, and synthesized assertion AST nodes is strictly bounded by $`O(N \cdot K + M)`$ bytes.
     - Deduplicated string interner memory is bounded by the lengths of unique parameter and unit symbol strings.
     - Diagnostic buffer memory is strictly bounded by $`O(C_{\text{max\_errors}}) = O(1)`$.
