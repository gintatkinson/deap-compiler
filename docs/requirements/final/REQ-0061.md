### REQ-0061: KerML Subsetting Relationship (`:>`) Lowering & Co-variance Invariants

- **Normative Statement**: The KerML metamodel lowering engine and semantic type checker shall formalize the feature subsetting relationship (`Subsetting`, denoted by the binary operator `:>`) as a value-set inclusion constraint within the subtyping meet-semilattice $`(\mathcal{T}, \le, \wedge)`$`. When a feature subsetting relationship `$`f_{\text{sub}} :> f_{\text{sup}}`$` is declared between a subsetting feature `$`f_{\text{sub}}`$` and a subsetted feature `$`f_{\text{sup}}`$`, the compiler shall enforce that for every semantic instance `$`x`$` within the evaluation domain of the owning classifier `$`\llbracket \text{owner}(f_{\text{sub}}) \rrbracket`$`, the value set projected by `$`f_{\text{sub}}(x)`$` is a subset of the value set projected by `$`f_{\text{sup}}(x)`$` (`$`\pi_{f_{\text{sub}}}(x) \subseteq \pi_{f_{\text{sup}}}(x)`$).

  The lowering engine must statically verify the following four structural invariants for every subsetting declaration:
  1. **Co-variant Type Specialization**: The declared or inferred type $`\tau(f_{\text{sub}})`$` of the subsetting feature shall specialize or equal the declared type `$`\tau(f_{\text{sup}})`$` of the subsetted feature within the subtyping partial order (`$`\tau(f_{\text{sub}}) \le \tau(f_{\text{sup}})`$). Subsetting declarations specifying contravariant types or disjoint types without common subtype specialization shall be strictly rejected at compile time with diagnostic code `E0200`.
  2. **Multiplicity Interval Narrowing**: The multiplicity interval $`\mu(f) = [m_{\min}, m_{\max}]`$` must preserve value-set inclusion. The upper multiplicity bound of the subsetting feature shall not exceed the upper multiplicity bound of the subsetted feature (`$`\mu(f_{\text{sub}}).m_{\max} \le \mu(f_{\text{sup}}).m_{\max}`$`), and the lower multiplicity bound of the subsetting feature shall not exceed the upper multiplicity bound of the subsetted feature (`$`\mu(f_{\text{sub}}).m_{\min} \le \mu(f_{\text{sup}}).m_{\max}`$`). Widening the upper bound (`$`\mu(f_{\text{sub}}).m_{\max} \gt \mu(f_{\text{sup}}).m_{\max}`$`) or declaring inconsistent lower bounds (`$`\mu(f_{\text{sub}}).m_{\min} \gt \mu(f_{\text{sup}}).m_{\max}`$) shall be strictly rejected with diagnostic code `E0200`.
  3. **Domain and Owning Classifier Specialization**: The featuring classifier context $`\text{owner}(f_{\text{sub}})`$` shall specialize or coincide with the featuring classifier context `$`\text{owner}(f_{\text{sup}})`$` (`$`\text{owner}(f_{\text{sub}}) \le \text{owner}(f_{\text{sup}})`$). Subsetting between features residing in disjoint classifiers without an established inheritance or subtyping specialization path shall be rejected with diagnostic code `E0200`.
  4. **Directional Flow Polarity Preservation**: When subsetting directed features (including directed ports and parameters with directionality $`\delta \in \{ \text{In}, \text{Out}, \text{InOut} \}`$`), `$`f_{\text{sub}}`$` must preserve identical flow directionality (`$`\delta(f_{\text{sub}}) = \delta(f_{\text{sup}})`$) unless explicit port conjugation is declared in accordance with REQ-0063. Subsetting across conflicting directionalities without conjugation shall be rejected with diagnostic code `E0200`.

  **Algorithmic Bound NP-3 Integration**: In arbitrary partially ordered sets (posets), general subtyping satisfiability and multiple-inheritance feature redefinition is NP-complete. To guarantee polynomial tractability, the compiler shall enforce that all classifier inheritance graphs form a monotonic meet-semilattice and resolve multiple inheritance precedence using deterministic C3 linearization without backtracking. Under this restriction, subtyping constraint checking over subsetting chains reduces to monotonic poset reachability, solvable in deterministic $`O(V + E)`$ polynomial time.

  **Acyclicity Enforcement**: Circular subsetting chains among distinct features ($`f_1 :> f_2 :> \dots :> f_1`$) shall be strictly prohibited and detected at compile time via topological cycle detection, emitting diagnostic error code `E0203`.

  **Total-Function Error Recovery & Sentinel Binding**: In accordance with Architectural Directive 4 and Architectural Directive 5, the lowering engine shall implement synchronization token error recovery. Upon detecting an invalid subsetting relationship, the type checker shall record diagnostic `E0200` or `E0203` into the diagnostic sink, assign an error sentinel type $`\bot_{\text{type}}`$` to the invalid feature node to prevent cascading compiler failures, and continue processing subsequent feature declarations up to the error limit `$`C_{\text{max\_errors}}`$`. If accumulated diagnostics reach `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered subsetting relationship AST node shall be assigned a deterministic RFC 4122 UUIDv5 identifier generated by namespace-hashing the fully qualified names of $`f_{\text{sub}}`$` and `$`f_{\text{sup}}`$ with the canonical compiler namespace OID per REQ-0010.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel validation of independent classifier packages and subtyping lattices shall execute on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
  - *Directive 3 (String Interner Allocation Exception)*: Scalar feature identifiers, qualified name segments, and namespace tokens shall be interned into the global symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
  - *Directive 5 (Panic-Free Release Isolation)*: The lowering engine shall enforce a total-function, panic-free execution contract across all valid and malformed inputs. Execution latency ($`\lt 25\text{ ms}`$`) and peak memory RSS (`$`\lt 100\text{ MB}`$` for `$`10^5`$ features) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Feature_Sub`, `Feature_Sup`, `Port_1`, `Port_2`, `param_x : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{V}_{\text{AST}}`$` denote the universe of allocated AST nodes. The set of feature nodes `$`\mathcal{F} \subset \mathcal{V}_{\text{AST}}`$ is defined by discriminant kind:

```math
\mathcal{F} = \{ f \in \mathcal{V}_{\text{AST}} \mid \text{kind}(f) = \text{Feature} \}
```

Each feature node $`f \in \mathcal{F}`$ is formalized as a 9-tuple:

```math
f = \langle \text{id}_f, \text{name}_f, \text{owner}_f, \tau(f), \mu(f), \delta(f), \mathcal{S}_f, \Delta_f, \text{span}_f \rangle
```

where:

```math
\begin{aligned}
\text{id}_f &\in \mathbb{N}_{32} \quad (\text{contiguous arena node handle}) \\
\text{name}_f &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\text{owner}_f &\in \mathcal{C} \quad (\text{owning classifier definition}) \\
\tau(f) &\in \mathcal{T} \setminus \{ \bot_{\text{type}} \} \quad (\text{authoritative classifier type}) \\
\mu(f) &= [m_{\min}(f), m_{\max}(f)] \subseteq \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \}) \quad (\text{multiplicity interval}) \\
\delta(f) &\in \{ \text{In}, \text{Out}, \text{InOut}, \text{None} \} \quad (\text{flow directionality attribute}) \\
\mathcal{S}_f &\subseteq \mathcal{F} \quad (\text{set of directly subsetted features}) \\
\Delta_f &\in \Sigma^* \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span}_f &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance})
\end{aligned}
```

The subsetting relation $`\mathcal{R}_{\text{subset}} \subset \mathcal{F} \times \mathcal{F}`$ captures all explicit subsetting declarations:

```math
\mathcal{R}_{\text{subset}} = \{ (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{F} \times \mathcal{F} \mid f_{\text{sup}} \in \mathcal{S}_{f_{\text{sub}}} \}
```

Semantic Fiber Value-Set Inclusion Invariant: For every subsetting pair $`(f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}`$`, the value projection function `$`\pi_f : \llbracket \text{owner}(f) \rrbracket \to \mathcal{P}(\llbracket \tau(f) \rrbracket)`$` satisfies value-set containment for every instance `$`x \in \llbracket \text{owner}(f_{\text{sub}}) \rrbracket`$:

```math
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad \forall x \in \llbracket \text{owner}(f_{\text{sub}}) \rrbracket : \pi_{f_{\text{sub}}}(x) \subseteq \pi_{f_{\text{sup}}}(x)
```

Subtyping Co-variant Specialization Invariant: The bound type $`\tau(f_{\text{sub}})`$` must specialize or equal `$`\tau(f_{\text{sup}})`$` in the subtyping meet-semilattice `$`(\mathcal{T}, \le, \wedge)`$:

```math
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad \tau(f_{\text{sub}}) \le \tau(f_{\text{sup}})
```

Multiplicity Interval Narrowing Invariant: The upper multiplicity bound must not widen, and the lower bound must be consistent with the superset upper bound:

```math
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad \mu(f_{\text{sub}}).m_{\max} \le \mu(f_{\text{sup}}).m_{\max} \;\wedge\; \mu(f_{\text{sub}}).m_{\min} \le \mu(f_{\text{sup}}).m_{\max}
```

Multiplicity Well-Formedness Invariant: Every feature multiplicity interval must be well-formed:

```math
\forall f \in \mathcal{F}, \quad 0 \le \mu(f).m_{\min} \le \mu(f).m_{\max}
```

Domain Specialization Invariant: The owning classifier of the subsetting feature must specialize or equal the owning classifier of the subsetted feature:

```math
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad \text{owner}(f_{\text{sub}}) \le \text{owner}(f_{\text{sup}})
```

Directional Flow Polarity Invariant: Directed features must maintain invariant flow directionality:

```math
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad \delta(f_{\text{sup}}) \ne \text{None} \implies \delta(f_{\text{sub}}) = \delta(f_{\text{sup}})
```

Transitive Closure and Poset Reachability: The transitive closure $`\mathcal{R}_{\text{subset}}^+`$ satisfies inductive transitivity:

```math
\forall f_1, f_2, f_3 \in \mathcal{F}, \quad ((f_1, f_2) \in \mathcal{R}_{\text{subset}} \;\wedge\; (f_2, f_3) \in \mathcal{R}_{\text{subset}}) \implies (f_1, f_3) \in \mathcal{R}_{\text{subset}}^+
```

Acyclicity Invariant: The directed subsetting graph must be strictly acyclic:

```math
\forall f \in \mathcal{F}, \quad (f, f) \notin \mathcal{R}_{\text{subset}}^+
```

NP-3 Bounded Meet-Semilattice and C3 Linearization Invariant: The type universe $`\mathcal{T}`$` forms a bounded meet-semilattice with unique meets, and classifier inheritance order `$`\text{C3}(C)`$` is deterministically computed via C3 linearization over direct parents `$`P_1, \dots, P_k`$:

```math
\begin{aligned}
\forall \tau_1, \tau_2 \in \mathcal{T}, &\quad \exists ! (\tau_1 \wedge \tau_2) \in \mathcal{T} : \tau_1 \wedge \tau_2 = \inf \{ \tau_1, \tau_2 \} \\
\text{C3}(C) &= [C] \mathbin{\Vert} \text{merge}(\text{C3}(P_1), \dots, \text{C3}(P_k), [P_1, \dots, P_k])
\end{aligned}
```

Deterministic RFC 4122 UUIDv5 Relationship Anchor (Architectural Directive 1): Each subsetting relationship edge $`r = (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}`$ is anchored by a deterministic UUIDv5 identifier:

```math
\forall r = (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad \Delta_{\text{rel}}(r) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(f_{\text{sub}}) \mathbin{\Vert} \text{\_subset\_} \mathbin{\Vert} \text{FQN}(f_{\text{sup}}))
```

Diagnostic Code Trigger Invariant: Any violation of subtyping covariance, multiplicity narrowing, domain compatibility, directionality, or acyclicity deterministically triggers structured diagnostics in accordance with REQ-0191:

```math
\begin{aligned}
\tau(f_{\text{sub}}) \not\le \tau(f_{\text{sup}}) &\implies \text{Diagnostic}(f_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{IncompatibleSubsettingType}) \in \mathcal{D}_{\text{sink}} \\
\mu(f_{\text{sub}}).m_{\max} \gt \mu(f_{\text{sup}}).m_{\max} &\implies \text{Diagnostic}(f_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{SubsettingMultiplicityViolation}) \in \mathcal{D}_{\text{sink}} \\
\mu(f_{\text{sub}}).m_{\min} \gt \mu(f_{\text{sup}}).m_{\max} &\implies \text{Diagnostic}(f_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{SubsettingLowerBoundViolation}) \in \mathcal{D}_{\text{sink}} \\
\text{owner}(f_{\text{sub}}) \not\le \text{owner}(f_{\text{sup}}) &\implies \text{Diagnostic}(f_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{SubsettingDomainMismatch}) \in \mathcal{D}_{\text{sink}} \\
(\delta(f_{\text{sup}}) \ne \text{None} \;\wedge\; \delta(f_{\text{sub}}) \ne \delta(f_{\text{sup}})) &\implies \text{Diagnostic}(f_{\text{sub}}, \text{DiagnosticCode::E0200}, \text{SubsettingDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
(f, f) \in \mathcal{R}_{\text{subset}}^+ &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0203}, \text{CircularSubsettingDependency}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Diagnostic Taxonomy Containment Invariant: All diagnostics emitted by the subsetting lowering engine strictly belong to the Metamodel and Typing family and Ingestion error limit family:

```math
\forall d \in \mathcal{D}_{\text{subset}}, \quad \text{code}(d) \in \{ \text{DiagnosticCode::E0200}, \text{DiagnosticCode::E0203}, \text{DiagnosticCode::E0199} \} \subset \mathcal{E}_{\text{type}} \cup \mathcal{E}_{\text{ingest}}
```

- **Computational Complexity & Algorithmic Bounds**: Feature subsetting relationship lowering and subtyping verification executes strictly within Complexity Class $`\mathbf{P}`$.

  **Algorithmic Bound NP-3 Formulation**: In unconstrained partially ordered sets (posets) with arbitrary multiple inheritance, structural subtyping and feature specialization satisfiability is NP-complete. The DEAP compiler eliminates backtracking and combinatorial explosion by enforcing two structural constraints:
  1. The type hierarchy forms a monotonic meet-semilattice $`(\mathcal{T}, \le, \wedge)`$ with unique greatest lower bounds.
  2. Multiple inheritance linearization is resolved via the deterministic C3 linearization algorithm, guaranteeing a total topological ordering for every classifier in $`O(V + E)`$ time.

  **Asymptotic Verification Complexity**: For an abstract model containing $`V = |\mathcal{F}|`$` feature nodes and `$`E = |\mathcal{R}_{\text{subset}}|`$ subsetting edges:
  1. *Graph Construction & Interning*: Allocating feature nodes in the contiguous arena and resolving interned symbol identifiers executes in amortized $`O(1)`$` time per node, totaling `$`O(V)`$ time.
  2. *Cycle Detection (Tarjan's SCC / DFS)*: Detecting circular subsetting chains over the directed graph $`(\mathcal{F}, \mathcal{R}_{\text{subset}})`$` executes in deterministic `$`O(V + E)`$ time.
  3. *Topological Ordering (Kahn's Algorithm)*: Establishing the subsetting evaluation order executes in deterministic $`O(V + E)`$ time.
  4. *Poset Reachability & Subtyping Queries*: Evaluating $`\tau(f_{\text{sub}}) \le \tau(f_{\text{sup}})`$` executes in `$`O(1)`$` time using precomputed reachability bitsets, or in bounded `$`O(h)`$` time where inheritance tree depth `$`h \le 32`$.
  5. *Multiplicity Interval Validation*: Verifying $`\mu(f_{\text{sub}}).m_{\max} \le \mu(f_{\text{sup}}).m_{\max}`$` and `$`\mu(f_{\text{sub}}).m_{\min} \le \mu(f_{\text{sup}}).m_{\max}`$` executes in strictly `$`O(1)`$ scalar integer comparisons per edge.
  6. *Domain & Directionality Verification*: Evaluating $`\text{owner}(f_{\text{sub}}) \le \text{owner}(f_{\text{sup}})`$` and `$`\delta(f_{\text{sub}}) = \delta(f_{\text{sup}})`$` executes in `$`O(1)`$ scalar enum and pointer comparisons per edge.

  Total sequential verification time across all subsetting relationships is strictly linear in the size of the feature graph:

```math
T_{\text{validate}}(V, E) \in O(V + E)
```

  **Parallel Work-Stealing Scaling (Architectural Directive 2)**: When subtyping validation across disjoint classifier packages is scheduled on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}}(V, E, N_{\text{max\_workers}}) \in O\left( \frac{V + E}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  **Space Complexity & Memory Bounds**: Auxiliary memory is bounded by $`O(V + E)`$` arena storage for AST nodes and relationship edges. Transitive reachability bitsets require at most `$`O(V \cdot \lceil V / 64 \rceil)`$` bits, which reduces to `$`O(V)`$` for hierarchical sparse trees. Traversal call stacks are bounded by recursion depth `$`O(h) \le 32`$` frames (`$`O(1)`$` auxiliary stack memory). The diagnostic error sink is bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$ allocated memory.

- **Verification & Conformance Criteria**: Deterministic conformance shall be verified by automated test suites operating on synthetic MBSE models containing abstract placeholders (`Package_0`, `Classifier_Alpha`, `Classifier_Beta`, `Classifier_Gamma`, `Feature_Sub`, `Feature_Sup`, `Port_1`, `Port_2`, `param_x : Real`). Conformance validation shall enforce the following test gates:
  1. **Canonical Subsetting Gate (`:>`)**: Declare `Classifier_Alpha` with feature `Feature_Sup : Classifier_Alpha [0..10]`. In specializing classifier `Classifier_Beta :> Classifier_Alpha`, declare `Feature_Sub :> Feature_Sup : Classifier_Beta [1..5]`. Assert that the lowering engine verifies co-variant typing, multiplicity narrowing, and domain specialization, producing valid AST edges and zero diagnostics.
  2. **Co-variant Typing Invariant Gate**: Declare `Feature_Sup : Classifier_Alpha`. In a specializing context, attempt to declare `Feature_Sub :> Feature_Sup : Classifier_Gamma` where `Classifier_Gamma` does not specialize `Classifier_Alpha`. Assert deterministic rejection with diagnostic code `E0200` (`IncompatibleSubsettingType`), assignment of error sentinel $`\bot_{\text{type}}`$, and zero panics.
  3. **Upper Multiplicity Narrowing Gate**: Declare `Feature_Sup` with multiplicity `[0..10]`. Declare `Feature_Sub :> Feature_Sup` with widened multiplicity `[0..15]`. Assert deterministic rejection with diagnostic code `E0200` (`SubsettingMultiplicityViolation`).
  4. **Lower Multiplicity Feasibility Gate**: Declare `Feature_Sup` with multiplicity `[0..5]`. Declare `Feature_Sub :> Feature_Sup` with lower bound exceeding superset upper bound `[6..10]`. Assert deterministic rejection with diagnostic code `E0200` (`SubsettingLowerBoundViolation`).
  5. **Owning Classifier Domain Specialization Gate**: Declare `Classifier_Alpha` containing `Feature_Sup`. In an unrelated, non-specializing classifier `Classifier_Gamma`, attempt to declare `Feature_Sub :> Feature_Sup`. Assert deterministic rejection with diagnostic code `E0200` (`SubsettingDomainMismatch`).
  6. **Directional Flow Polarity Gate**: Declare directed port `Port_1 : in Classifier_Alpha`. In a specializing classifier, declare `Port_2 :> Port_1 : in Classifier_Beta`; assert successful validation. Attempt to declare `Port_3 :> Port_1 : out Classifier_Alpha` without conjugation; assert deterministic rejection with diagnostic code `E0200` (`SubsettingDirectionMismatch`).
  7. **Transitive Subsetting Chain Resolution Gate**: Declare a 3-level subsetting chain $`f_3 :> f_2 :> f_1`$` with monotonic type specialization and multiplicity narrowing. Assert that the lowering engine verifies transitive reachability `$`(f_3, f_1) \in \mathcal{R}_{\text{subset}}^+`$` in `$`O(V + E)`$ time with zero diagnostics.
  8. **Circular Subsetting Dependency Detection Gate (`E0203`)**: Declare a cyclic subsetting chain $`f_1 :> f_2 :> f_3 :> f_1`$. Assert that cycle detection deterministically identifies the loop and emits diagnostic error code `E0203` (`CircularSubsettingDependency`) with exact source byte spans for all participating features.
  9. **NP-3 Algorithmic Tractability Benchmark Gate**: Construct a synthetic diamond multiple-inheritance DAG with $`10^4`$` feature nodes and `$`5 \times 10^4`$` subsetting edges conforming to the monotonic meet-semilattice and C3 linearization rules. Assert that subtyping and subsetting conformance validation completes in strictly linear `$`O(V + E)`$ time without backtracking or exponential pause.
  10. **Synchronization Token Recovery & Error Accumulation Gate (Architectural Directive 4)**: Ingest a model unit containing 5 distinct malformed subsetting declarations interspersed with valid code. Verify that the lowering engine resynchronizes on delimiter boundaries, accumulates all 5 `E0200` diagnostics with precise source spans, and halts gracefully with terminal diagnostic `E0199` when the error count reaches $`C_{\text{max\_errors}}`$.
  11. **Deterministic UUIDv5 Anchor Gate (Architectural Directive 1)**: Verify that 100% of lowered subsetting relationship AST nodes bind valid RFC 4122 UUIDv5 identifiers computed from compiler namespace OID and feature fully qualified paths.
  12. **Release Mode Latency & Memory Budget Gate (Architectural Directive 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, assert that validating $`10^5`$ synthetic subsetting declarations executes in under 25 ms, peak RSS memory remains strictly under 100 MB, and consecutive compilation runs exhibit bitwise determinism with 0-byte diff churn.
