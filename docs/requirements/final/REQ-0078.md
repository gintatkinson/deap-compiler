### REQ-0078: SysML v2 ActionDefinition (`action def`) & ActionUsage (`action`) Lowering

- **Normative Statement**: The behavioral compiler and semantic metamodel lowering engine of Subsystem 4 shall formalize SysML v2 action definitions (`ActionDefinition`, denoted by keyword `action def`) as behavioral process classifiers specializing KerML `Behavior` and `OccurrenceDefinition`, and action usages (`ActionUsage`, denoted by keyword `action`) as discrete executable steps within control and data flow graphs specializing KerML `Step` and `OccurrenceUsage`.

  The lowering engine must statically verify and enforce the following structural, typing, and behavioral invariants for every lowered action definition and action usage:
  1. **Dual Inheritance Specialization & Classification**: Every `ActionDefinition` shall specialize both KerML `Behavior` and KerML `OccurrenceDefinition` within the metamodel subtyping poset, inheriting occurrence lifecycle semantics, temporal bounds, and classifier feature ownership. Every `ActionUsage` shall specialize KerML `Step` and KerML `OccurrenceUsage`, acting as a discrete feature usage owned by an enclosing classifier or composite action.
  2. **Parameter Signature & Directionality Invariants**: An action definition shall declare an ordered sequence of parameter features $`\mathcal{P}_{\text{param}}`$`, where each parameter `$`p \in \mathcal{P}_{\text{param}}`$` specifies an immutable directionality `$`\delta(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}`$`, a declared classifier type `$`\tau(p)`$`, and a multiplicity interval `$`\mu(p) = [m_{\min}(p), m_{\max}(p)]`$`. Data flow edges `$`e_{\text{data}} = (u, p_{\text{src}}, v, p_{\text{tgt}})`$` binding parameter pins between action steps must connect an output or inout parameter (`$`\delta(p_{\text{src}}) \in \{ \text{Out}, \text{InOut} \}`$`) to an input or inout parameter (`$`\delta(p_{\text{tgt}}) \in \{ \text{In}, \text{InOut} \}`$). Connecting conflicting flow polarities (e.g., binding an `In` parameter as a source or an `Out` parameter as a target) shall be strictly rejected at compile time with diagnostic error code `E0201`.
  3. **Data Flow Payload Subtyping & Multiplicity Conformance**: For every data flow edge $`e_{\text{data}} = (u, p_{\text{src}}, v, p_{\text{tgt}})`$`, the payload value type of the source parameter `$`\tau(p_{\text{src}})`$` must specialize or equal the declared type of the target parameter `$`\tau(p_{\text{tgt}})`$` within the subtyping meet-semilattice (`$`\tau(p_{\text{src}}) \le_{\text{sub}} \tau(p_{\text{tgt}})`$`). Furthermore, the upper multiplicity bound of the source parameter shall not exceed the upper multiplicity bound of the target parameter (`$`\mu(p_{\text{src}}).m_{\max} \le \mu(p_{\text{tgt}}).m_{\max}`$). Incompatible payload types or multiplicity overflows shall be rejected at compile time with diagnostic error code `E0202`.
  4. **Control Node Topology & Cardinality Invariants**: Control flows within an action workflow multigraph $`G_{\text{flow}} = (V, E_{\text{ctrl}} \cup E_{\text{data}})`$` may interconnect action steps (`$`V_{\text{steps}}`$`) and explicit control nodes (`$`V_{\text{ctrl}}`$). The compiler shall enforce topological degree invariants:
     - Initial nodes ($`V_{\text{init}}`$) must have an in-degree of 0 and an out-degree of 1.
     - Final/Done nodes ($`V_{\text{final}}`$) must have an in-degree of at least 1 and an out-degree of 0.
     - Fork nodes ($`V_{\text{fork}}`$`) must have an in-degree of 1 and an out-degree of `$`k \ge 2`$, replicating incoming control tokens across all concurrent branches.
     - Join nodes ($`V_{\text{join}}`$`) must have an in-degree of `$`k \ge 2`$ and an out-degree of 1, synchronizing all incoming control tokens before releasing an outgoing token.
     - Decision nodes ($`V_{\text{decision}}`$`) must have an in-degree of 1 and an out-degree of `$`k \ge 2`$, routing execution along branches guarded by mutually disjoint boolean expressions.
     - Merge nodes ($`V_{\text{merge}}`$`) must have an in-degree of `$`k \ge 2`$ and an out-degree of 1, passing an outgoing token when any single incoming control token arrives.
     Malformed control node degree configurations or dangling control paths shall be rejected with diagnostic error code `E0200`.
  5. **Step Execution Lifecycle & Token Readiness**: Each action step $`s \in V_{\text{steps}}`$` models a discrete occurrence execution governed by a deterministic four-state lifecycle: `$`\text{State}(s) \in \{ \text{Waiting}, \text{Ready}, \text{Executing}, \text{Completed} \}`$. A step transitions from `Waiting` to `Ready` if and only if all incoming control tokens across incident control edges $`E_{\text{ctrl}}`$` are asserted and all required data inputs across incident data edges `$`E_{\text{data}}`$ are bound and verified. A step in `Ready` transitions to `Executing` upon dispatch, and upon termination transitions to `Completed`, producing its output parameters and asserting outgoing control tokens.
  6. **Acyclicity & Deadlock Cycle Elimination**: The unified step dependency graph $`G_{\text{dep}} = (V, E_{\text{ctrl}} \cup E_{\text{data\_dep}})`$` across discrete sequential and concurrent action blocks must form a directed acyclic graph (DAG). The lowering engine shall execute deterministic cycle detection via topological sorting (Tarjan's strongly connected components or Kahn's in-degree reduction). Any unintended circular causal dependency or step deadlocks (`$`s \to^+ s`$) shall be isolated and rejected with diagnostic error code `E0203`.

  **Total-Function Error Recovery & Sentinel Binding (Architectural Directive 4)**:
  In accordance with Architectural Directive 4, REQ-0013, and REQ-0016, the lowering engine shall implement synchronization token error recovery on action boundary and statement delimiters. Upon detecting any semantic defect (`E0200`, `E0201`, `E0202`, or `E0203`), the engine shall record a structured diagnostic record into the preallocated diagnostic sink buffer $`\mathcal{D}_{\text{sink}}`$`, bind an error sentinel node `$`\bot_{\text{action}}`$` or `$`\bot_{\text{type}}`$` to prevent cascading compiler failures, sever cyclic dependency edges in an overlay graph `$`\mathcal{E}_{\text{overlay}}`$`, and resume parsing subsequent steps and action definitions. If accumulated diagnostics reach the preallocated capacity limit `$`C_{\text{max\_errors}}`$, the compiler shall emit terminal diagnostic `E0199` and halt gracefully.

  **Architectural Directives Compliance**:
  - *Directive 1 (Deterministic UUIDv5 Anchors)*: Every lowered action definition, action usage, parameter, control node, and flow edge AST node shall be assigned an immutable deterministic RFC 4122 UUIDv5 identifier hashed from the canonical compiler namespace OID and the fully qualified symbol path ($`\text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))`$) per REQ-0010.
  - *Directive 2 (Bounded Work-Stealing Parallelism)*: Parallel lowering and validation of independent action definition blocks across distinct packages shall execute strictly on a bounded work-stealing thread pool with worker bound $`N_{\text{max\_workers}}`$ per REQ-0012.
  - *Directive 3 (String Interner Allocation Exception)*: Scalar identifiers, action names, parameter names, and qualified name tokens shall be interned into the global deduplicated symbol interner pool per REQ-0036 as the sole permitted exception to zero-copy memory management.
  - *Directive 5 (Panic-Free Release Isolation)*: Production compiler library code shall enforce a deterministic, non-panicking execution contract with total-function termination across all valid and malformed inputs. Execution latency ($`\lt 25\text{ ms}`$`) and peak memory RSS (`$`\lt 100\text{ MB}`$` for `$`10^5`$ action step nodes) performance gates shall be evaluated exclusively in compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196.

  All diagnostic messages, test models, and illustrative examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `ActionDef_Alpha`, `ActionDef_Beta`, `ActionUsage_1`, `ActionUsage_2`, `Step_Alpha`, `Step_Beta`, `Port_1`, `Flow_A`, `param_in : Real`, `param_out : Real`), strictly prohibiting hardcoded domain concepts, mock data, and non-ASCII dashes.

- **Formal Invariant**: Let $`\mathcal{T}_{\text{metamodel}}`$` denote the KerML classifier specialization poset ordered by subtyping relation `$`\le_{\text{sub}}`$. The dual inheritance invariant of `ActionDefinition` is formalized as:

```math
\text{ActionDef} \le_{\text{sub}} \text{Behavior} \;\wedge\; \text{ActionDef} \le_{\text{sub}} \text{OccurrenceDefinition}
```

The taxonomy of `ActionUsage` specializes `Step` and `OccurrenceUsage`:

```math
\text{ActionUsage} \le_{\text{sub}} \text{Step} \;\wedge\; \text{ActionUsage} \le_{\text{sub}} \text{OccurrenceUsage} \;\wedge\; \text{ActionUsage} \le_{\text{sub}} \text{Feature}
```

Each lowered action definition $`A_{\text{def}} \in \mathcal{A}_{\text{def}}`$ is formalized as a 6-tuple:

```math
A_{\text{def}} = \langle \text{id}_{\text{def}}, \text{name}, \mathcal{P}_{\text{param}}, G_{\text{flow}}, \Delta_{\text{def}}, \text{span} \rangle
```

where:

```math
\begin{aligned}
\text{id}_{\text{def}} &\in \mathbb{N}_{32} \quad (\text{stable 32-bit arena node handle}) \\
\text{name} &\in \mathcal{S}_{\text{intern}} \quad (\text{interned symbol identifier}) \\
\mathcal{P}_{\text{param}} &\subset \mathcal{H}_{\text{param}} \quad (\text{ordered sequence of parameter feature handles}) \\
G_{\text{flow}} &= (V, E_{\text{ctrl}} \cup E_{\text{data}}) \quad (\text{directed workflow multigraph}) \\
\Delta_{\text{def}} &\in \Sigma^{36} \quad (\text{deterministic RFC 4122 UUIDv5 topological anchor}) \\
\text{span} &= \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle \quad (\text{source lexical provenance coordinate})
\end{aligned}
```

Each parameter feature $`p \in \mathcal{P}_{\text{param}}`$ is formalized as:

```math
p = \langle \text{id}_p, \text{name}_p, \delta(p), \tau(p), \mu(p), \Delta_p \rangle
```

where $`\delta(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}`$` denotes parameter flow directionality, `$`\tau(p) \in \mathcal{T}`$` is the declared classifier type, `$`\mu(p) = [m_{\min}(p), m_{\max}(p)]`$` is the multiplicity interval with `$`0 \le m_{\min}(p) \le m_{\max}(p)`$`, and `$`\Delta_p`$ is its deterministic UUIDv5 anchor.

The workflow multigraph vertex set $`V`$ is partitioned into action steps and control nodes:

```math
V = V_{\text{steps}} \cup V_{\text{ctrl}}
```

```math
V_{\text{ctrl}} = V_{\text{init}} \cup V_{\text{final}} \cup V_{\text{fork}} \cup V_{\text{join}} \cup V_{\text{decision}} \cup V_{\text{merge}}
```

Each action step $`s \in V_{\text{steps}}`$ is formalized as:

```math
s = \langle \text{id}_s, \text{name}_s, \text{def}_s, \mathcal{P}_{\text{in}}(s), \mathcal{P}_{\text{out}}(s), \Delta_s \rangle
```

where $`\text{def}_s \in \mathcal{A}_{\text{def}} \cup \{ \bot_{\text{action}} \}`$` is the typing action definition handle, and `$`\mathcal{P}_{\text{in}}(s), \mathcal{P}_{\text{out}}(s)`$ are input and output parameter pin sets.

Dynamic Step Lifecycle and Token Readiness Invariant: The execution state of every step satisfies:

```math
\forall s \in V_{\text{steps}}, \quad \text{State}(s) \in \{ \text{Waiting}, \text{Ready}, \text{Executing}, \text{Completed} \}
```

The transition predicate from `Waiting` to `Ready` is satisfied if and only if all incoming control tokens are present and all incoming data parameters are bound:

```math
\text{Ready}(s) \iff \left( \forall (u, s) \in E_{\text{ctrl}}, \; \text{Token}(u, s) = 1 \right) \;\wedge\; \left( \forall (u, p_{\text{src}}, s, p_{\text{tgt}}) \in E_{\text{data}}, \; \text{Bound}(p_{\text{tgt}}) = \text{true} \right)
```

Directional Polarity Preservation Invariant: For every data flow edge $`e_{\text{data}} = (u, p_{\text{src}}, v, p_{\text{tgt}}) \in E_{\text{data}}`$, the source pin must be an output or inout parameter, and the target pin must be an input or inout parameter:

```math
\forall (u, p_{\text{src}}, v, p_{\text{tgt}}) \in E_{\text{data}}, \quad \delta(p_{\text{src}}) \in \{ \text{Out}, \text{InOut} \} \;\wedge\; \delta(p_{\text{tgt}}) \in \{ \text{In}, \text{InOut} \}
```

Subtyping and Multiplicity Conformance Invariant: Data flow bindings must preserve type safety and avoid multiplicity overflow:

```math
\forall (u, p_{\text{src}}, v, p_{\text{tgt}}) \in E_{\text{data}}, \quad \tau(p_{\text{src}}) \le_{\text{sub}} \tau(p_{\text{tgt}}) \;\wedge\; \mu(p_{\text{src}}).m_{\max} \le \mu(p_{\text{tgt}}).m_{\max}
```

Control Node Topology Degree Invariants: Every control node $`n \in V_{\text{ctrl}}`$ must satisfy strict in-degree and out-degree bounds:

```math
\begin{aligned}
\forall n \in V_{\text{init}}, &\quad \text{deg}_{\text{in}}(n) = 0 \;\wedge\; \text{deg}_{\text{out}}(n) = 1 \\
\forall n \in V_{\text{final}}, &\quad \text{deg}_{\text{in}}(n) \ge 1 \;\wedge\; \text{deg}_{\text{out}}(n) = 0 \\
\forall n \in V_{\text{fork}}, &\quad \text{deg}_{\text{in}}(n) = 1 \;\wedge\; \text{deg}_{\text{out}}(n) \ge 2 \\
\forall n \in V_{\text{join}}, &\quad \text{deg}_{\text{in}}(n) \ge 2 \;\wedge\; \text{deg}_{\text{out}}(n) = 1 \\
\forall n \in V_{\text{decision}}, &\quad \text{deg}_{\text{in}}(n) = 1 \;\wedge\; \text{deg}_{\text{out}}(n) \ge 2 \\
\forall n \in V_{\text{merge}}, &\quad \text{deg}_{\text{in}}(n) \ge 2 \;\wedge\; \text{deg}_{\text{out}}(n) = 1
\end{aligned}
```

Step Dependency Graph & Acyclicity Invariant: Let $`G_{\text{dep}} = (V, E_{\text{dep}})`$ be the unified dependency graph where:

```math
E_{\text{dep}} = E_{\text{ctrl}} \cup \{ (u, v) \in V_{\text{steps}} \times V_{\text{steps}} \mid \exists p_{\text{src}}, p_{\text{tgt}} : (u, p_{\text{src}}, v, p_{\text{tgt}}) \in E_{\text{data}} \}
```

The transitive closure $`E_{\text{dep}}^+`$ enforces strict acyclicity across discrete action executions:

```math
\text{IsAcyclic}(G_{\text{dep}}) \iff \forall v \in V, \quad (v, v) \notin E_{\text{dep}}^+
```

Equivalently, there exists a deterministic topological sorting injection $`\sigma: V \to \{ 1, 2, \dots, |V| \}`$ such that:

```math
\forall (u, v) \in E_{\text{dep}}, \quad \sigma(u) \lt \sigma(v)
```

Deterministic RFC 4122 UUIDv5 Identifier Invariant (Architectural Directive 1): Every lowered metamodel entity receives an immutable UUIDv5 identifier:

```math
\forall u \in \mathcal{A}_{\text{def}} \cup V_{\text{steps}} \cup V_{\text{ctrl}} \cup \mathcal{P}_{\text{param}} \cup E_{\text{ctrl}} \cup E_{\text{data}}, \quad \Delta(u) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u))
```

Diagnostic Code Trigger Invariant: Violations of directionality, subtyping, topology, or acyclicity deterministically trigger diagnostic records in accordance with REQ-0191:

```math
\begin{aligned}
(\delta(p_{\text{src}}) \notin \{ \text{Out}, \text{InOut} \} \;\vee\; \delta(p_{\text{tgt}}) \notin \{ \text{In}, \text{InOut} \}) &\implies \text{Diagnostic}(e_{\text{data}}, \text{DiagnosticCode::E0201}, \text{ParameterDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
\tau(p_{\text{src}}) \not\le_{\text{sub}} \tau(p_{\text{tgt}}) &\implies \text{Diagnostic}(e_{\text{data}}, \text{DiagnosticCode::E0202}, \text{DataFlowPayloadTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\mu(p_{\text{src}}).m_{\max} \gt \mu(p_{\text{tgt}}).m_{\max} &\implies \text{Diagnostic}(e_{\text{data}}, \text{DiagnosticCode::E0202}, \text{DataFlowMultiplicityOverflow}) \in \mathcal{D}_{\text{sink}} \\
\text{InvalidControlNodeTopology}(n) &\implies \text{Diagnostic}(n, \text{DiagnosticCode::E0200}, \text{MalformedControlTopology}) \in \mathcal{D}_{\text{sink}} \\
(v, v) \in E_{\text{dep}}^+ &\implies \text{Diagnostic}(A_{\text{def}}, \text{DiagnosticCode::E0203}, \text{CircularActionDependency}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Sanitized Analysis Overlay Graph Invariant: During error recovery, closing cyclic back-edges are pruned in $`\mathcal{E}_{\text{overlay}}`$ to enable downstream verification:

```math
E_{\text{dep}, \text{overlay}} = E_{\text{dep}} \setminus \{ (u, v) \in E_{\text{dep}} \mid (u, v) \in E_{\text{dep}}^+ \;\wedge\; (v, u) \in E_{\text{dep}}^+ \}
```

```math
\text{IsAcyclic}((V, E_{\text{dep}, \text{overlay}})) \equiv \text{true}
```

- **Computational Complexity & Algorithmic Bounds**: Lowering and static semantic verification of SysML v2 action definitions and action usages execute strictly within Complexity Class $`\mathbf{P}`$.

  **Algorithmic Bound Formulation & NP Decoupling**: While arbitrary concurrent state machines and general reachability over orthogonal regions inhabit PSPACE-complete or NP-complete frontiers (such as NP-5 in REQ-0124), discrete acyclic action workflows and structured control-flow DAGs are bounded to deterministic polynomial time. By enforcing structural well-formedness, explicit control node branching, and acyclic data dependencies, verification avoids combinatorial state explosion.

  **Asymptotic Verification Complexity**: For an action definition containing $`V = |V_{\text{steps}}| + |V_{\text{ctrl}}|`$` nodes, `$`E = |E_{\text{ctrl}}| + |E_{\text{data}}|`$` edges, and `$`P = |\mathcal{P}_{\text{param}}|`$ parameters:
  1. *Node Allocation & Symbol Interning*: Allocating action definitions, steps, parameters, and control nodes in contiguous typed bump arena storage executes in amortized $`O(1)`$` time per element, requiring `$`O(V + P)`$ time.
  2. *Parameter Directionality & Subtyping Validation*: Validating $`\delta(p_{\text{src}})`$`, `$`\delta(p_{\text{tgt}})`$`, and subtyping `$`\tau(p_{\text{src}}) \le_{\text{sub}} \tau(p_{\text{tgt}})`$` across all data flow edges executes in `$`O(1)`$` time per edge via precomputed reachability bitsets or bounded hierarchy paths (`$`h \le 32`$`), requiring `$`O(|E_{\text{data}}|)`$` time. Multiplicity interval verification requires strictly `$`O(1)`$ integer comparisons per edge.
  3. *Control Node Degree Verification*: Verifying in-degree and out-degree bounds across all control nodes $`n \in V_{\text{ctrl}}`$` executes in `$`O(|V_{\text{ctrl}}| + |E_{\text{ctrl}}|)`$ time using direct degree accumulators.
  4. *Acyclicity Detection & Topological Sort (Kahn / Tarjan)*: Constructing the dependency graph $`G_{\text{dep}} = (V, E_{\text{dep}})`$ and evaluating acyclicity processes each node at most twice and traverses each dependency edge exactly once:

```math
T_{\text{topo}}(V, E) = \sum_{v \in V} \left( O(1) + \sum_{w \in \text{Succ}(v)} O(1) \right) \in O(V + E)
```

  If a cycle is detected, reconstructing the deterministic cycle traceback path executes in $`O(V_C + E_C) \subseteq O(V + E)`$ time via breadth-first traversal over the non-trivial strongly connected component.
  5. *Total Sequential Verification Complexity*: Total time across all validation phases is strictly linear in the size of the workflow graph:

```math
T_{\text{total}}(V, E, P) \in O(V + E + P) \subseteq O(V + E)
```

  6. *Parallel Work-Stealing Scaling (Architectural Directive 2)*: When $`M`$` independent action definitions `$`\{ A_1, A_2, \dots, A_M \}`$` across disjoint packages are verified concurrently on a bounded work-stealing thread pool with worker bound `$`N_{\text{max\_workers}}`$:

```math
T_{\text{parallel}} \in O\left( \frac{\sum_{i=1}^M (V_i + E_i)}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}} \right)
```

  7. *Space Complexity & Memory Bounds*: Auxiliary memory is bounded by $`O(V + E)`$` for adjacency lists, node in-degree arrays indexed directly by 32-bit arena offsets, and the topological evaluation queue. The diagnostic sink buffer is bounded by `$`O(C_{\text{max\_errors}}) = O(1)`$` allocated memory, guaranteeing that auxiliary memory remains strictly `$`O(V + E)`$ with zero unbounded heap reallocations.

- **Verification & Conformance Criteria**: Deterministic conformance shall be verified by automated test suites operating on synthetic MBSE models containing abstract placeholders (`Package_0`, `ActionDef_Alpha`, `ActionDef_Beta`, `ActionDef_Gamma`, `ActionUsage_1`, `ActionUsage_2`, `Step_Alpha`, `Step_Beta`, `param_in : Real`, `param_out : Real`, `Port_1`, `Flow_A`). Conformance validation shall enforce the following test gates:
  1. **Dual Inheritance Metamodel Gate**: Declare `action def ActionDef_Alpha`. Ingest the model and assert that the lowered AST node exhibits dual specialization edges to KerML `Behavior` and KerML `OccurrenceDefinition`, verifying correct feature inheritance and occurrence semantics with zero diagnostics emitted.
  2. **Canonical Action Usage & Step Lowering Gate**: Declare `action def ActionDef_Alpha` containing two sequential steps `action Step_Alpha : ActionDef_Beta` and `action Step_Beta : ActionDef_Gamma` connected by control succession and parameter data flow. Assert that lowering creates valid AST nodes in contiguous arena storage, generates valid RFC 4122 UUIDv5 anchors, and emits zero diagnostics.
  3. **Parameter Directionality Violation Gate (`E0201`)**: Ingest an action model attempting to bind an input parameter pin (`in param_in : Real`) as the source of a data flow edge, or an output parameter pin (`out param_out : Real`) as the target. Assert deterministic rejection with diagnostic error code `E0201` (`ParameterDirectionMismatch`), assignment of error sentinel node $`\bot_{\text{action}}`$, and zero panics.
  4. **Data Flow Payload Subtyping Gate (`E0202`)**: Declare `action def ActionDef_Alpha` binding an output parameter of type `Classifier_Alpha` to an input parameter of type `Classifier_Beta`, where `Classifier_Beta` does not specialize `Classifier_Alpha`. Assert deterministic rejection with diagnostic error code `E0202` (`DataFlowPayloadTypeMismatch`). Inject a conforming subtype and assert successful compilation with zero diagnostics.
  5. **Parameter Multiplicity Overflow Gate (`E0202`)**: Declare a source parameter with multiplicity `[0..10]` bound to a target parameter with multiplicity `[0..5]`. Assert deterministic rejection with diagnostic error code `E0202` (`DataFlowMultiplicityOverflow`).
  6. **Control Node Topology Invariant Gate (`E0200`)**: Declare a malformed fork node having in-degree 2, or a join node having out-degree 2. Assert deterministic compile-time rejection emitting diagnostic error code `E0200` (`MalformedControlTopology`) with exact source byte spans.
  7. **Circular Action Dependency Cycle Detection Gate (`E0203`)**: Ingest an action definition containing a cyclic step dependency chain `Step_Alpha -> Step_Beta -> Step_Gamma -> Step_Alpha`. Assert that cycle detection isolates the loop, emits diagnostic error code `E0203` (`CircularActionDependency`), outputs the exact cycle traceback path, and severs the back-edge in the analysis overlay graph.
  8. **Step Lifecycle Execution Simulation Gate**: Simulate step execution across an acyclic workflow DAG. Assert that an action step remains in state `Waiting` until all incoming control tokens are satisfied and required input parameters are bound, transitions to `Ready`, executes to `Completed`, and asserts outgoing control tokens.
  9. **Synchronization Token Error Recovery Gate (Architectural Directive 4)**: Ingest a model unit containing 5 distinct malformed action declarations interspersed with valid code. Verify that the lowering engine resynchronizes on delimiter boundaries, accumulates all 5 diagnostic records (`E0200`, `E0201`, `E0202`, `E0203`) into $`\mathcal{D}_{\text{sink}}`$, and halts gracefully with terminal diagnostic `E0199` when the error count reaches $`C_{\text{max\_errors}}`$.
  10. **Deterministic UUIDv5 Anchor Gate (Architectural Directive 1)**: Verify that 100% of lowered action definitions, action usages, parameters, control nodes, and flow edges receive deterministic RFC 4122 UUIDv5 identifiers derived from the compiler namespace OID and canonical FQN paths.
  11. **Bounded Work-Stealing Parallelism Gate (Architectural Directive 2)**: Concurrently verify $`10^4`$` synthetic action definitions across `$`N_{\text{max\_workers}}`$ threads in the bounded work-stealing pool. Assert data-race freedom, zero deadlocks, and 100% bitwise identical diagnostic outputs compared to single-threaded sequential execution.
  12. **Release Mode Latency & Peak RSS Memory Gate (Architectural Directive 5)**: In compiled Release mode (`--release`) under dedicated benchmark harnesses isolated from CI logic tests per REQ-0011 and REQ-0196, assert that verifying $`10^5`$ synthetic action step nodes executes in under 25 ms, peak RSS memory remains strictly below 100 MB, and consecutive compilation runs exhibit bitwise determinism with 0-byte diff churn.
