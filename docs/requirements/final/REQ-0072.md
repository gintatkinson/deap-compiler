### REQ-0072: SysML v2 PortDefinition (`port def`) & DirectedPort Usage Lowering

- **Normative Statement**: The Universal Schema Ingestion and Metamodel Lowering Engine shall lower OMG Systems Modeling Language (SysML v2) Port Definition (`port def`) classifiers and Directed Port Usage (`port`) declarations into canonical Core Metamodel abstract syntax tree (AST) arena representations. The lowering engine shall formalize `port def` as an interaction point classifier specializing Kernel Modeling Language (KerML) `Structure` (`Base::Structure`), and `port` usages as directed boundary interface features declared on structural classifiers possessing explicit directionality (`in`, `out`, `inout`), payload typing, conjugate instantiation capabilities (`~P`), and strict boundary encapsulation guarantees.

  Specifically, the lowering engine shall satisfy the following normative provisions:
  1. PortDefinition Classifier Specialization: The compiler shall lower `port def` declarations into first-class arena classifier nodes that specialize KerML `Structure`. A port definition shall define an interaction boundary and communication protocol, declaring an owned roster of features including directed flow features (`in`, `out`, `inout`), nested port usages, operations, attributes, and operational invariant constraints.
  2. DirectedPort Usage Lowering: The compiler shall lower `port` usages declared within structural classifiers (`part def`, `part`, `item def`, or composite `port def`) as boundary interaction points. Every lowered port usage shall possess:
     - An interned scalar symbol handle representing its local identifier,
     - An immutable parent classifier handle identifying its owning component scope,
     - A referenced port definition classifier $\tau_{P} \in \mathcal{P}_{\text{def}}$ or conjugated classifier ${\sim}\tau_{P}$,
     - An effective directionality $d_{\text{eff}} \in \mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut} \}$,
     - A multiplicity interval $\mu = [l, u]$ with $0 \le l \le u$ and $u \ge 1$,
     - Source provenance byte span coordinates.
  3. Explicit Directional Enforcement: When a port usage declares an explicit directional prefix (`in port`, `out port`, `inout port`), the lowering engine shall bind the declared direction to constrain all interactions and flows traversing that boundary interface:
     - `in port`: flow items and interactions must strictly enter the owning classifier from the external environment; outgoing flows traversing an `in` port are strictly invalid,
     - `out port`: flow items and interactions must strictly exit the owning classifier toward the external environment; incoming flows traversing an `out` port are strictly invalid,
     - `inout port`: bidirectional flows and interactions entering and exiting the owning classifier are permitted,
     - Standard `port` (unprefixed): directionality shall be derived from the owned directional features of the referenced port definition $P$.
  4. Conjugate Port Instantiation: The lowering engine shall support conjugate port instantiation denoted by the conjugation marker (`~`). Declaring $p : {\sim}P$ shall bind port usage $p$ to the conjugated interface with inverted directional features:
     - For every feature $f \in \text{features}(P)$, its directional orientation shall invert via the algebraic involution operator ${\sim}\text{dir}(f)$, mapping `In` to `Out`, `Out` to `In`, and preserving `InOut`,
     - All payload types, structural definitions, multiplicity intervals, and invariant contract constraints $\psi \in \Psi(P)$ shall be preserved identically,
     - The involution identity ${\sim}({\sim}P) \equiv P$ shall hold unconditionally.
  5. Boundary Encapsulation & Information Hiding Contract: The lowering engine shall enforce strict boundary encapsulation on all component classifiers:
     - External connections (inter-component assembly connections or parent-to-child delegation connections from the external parent perspective) linking into or out of a component $C$ must terminate exclusively at declared boundary port usages $\text{ports}(C)$,
     - Direct connection to internal private features of $C$ (such as internal sub-parts, internal attributes, internal actions, or internal flow features) without routing through a declared boundary port is strictly prohibited,
     - Any external connection attempting to bypass declared boundary ports shall be rejected deterministically with diagnostic error code `E0220` per REQ-0191.
  6. Subtyping Lattice & C3 Linearization (Algorithmic Bound NP-3): Port definitions participate in multiple inheritance and specialization hierarchies (`:>` subsetting/specialization): `port def PortDef_Gamma :> PortDef_Alpha, PortDef_Beta`. The subtyping relation $(\mathcal{P}_{\text{def}}, \le)$ shall form a bounded monotonic meet-semilattice. When a port definition specializes multiple parent port definitions, the lowering engine shall resolve the linearized precedence list deterministically via the C3 linearization algorithm without backtracking, executing in deterministic $O(V + E)$ polynomial time to eliminate exponential search and undecidable subtyping cycles. Circular inheritance among port definitions shall be detected and rejected deterministically with diagnostic error code `E0203`.
  7. Connection Compatibility Verification:
     - Peer-to-peer assembly connections between sibling port usages $p_{1}$ and $p_{2}$ must satisfy anti-parallel directional compatibility (`In` to `Out`, `Out` to `In`, or `InOut` to `InOut`), or conjugate typing $p_{2} : {\sim}\tau(p_{1})$. Directional incompatibility shall deterministically emit diagnostic error code `E0201`,
     - Flow features traversing connected ports must satisfy payload type conformance ($\tau_{\text{source}} \le \tau_{\text{target}}$) and stream multiplicity bounds. Violations shall deterministically emit diagnostic error code `E0202`.
  8. Architectural Directives Compliance:
     - Directive 1 (Deterministic UUIDv5 Anchors): Every lowered port definition classifier node, port usage node, and lowered port feature node shall receive a deterministic RFC 4122 UUIDv5 identifier computed from the compiler namespace OID and canonical fully qualified symbol path. Time-based UUIDs are strictly banned.
     - Directive 2 (Bounded Work-Stealing Parallelism): Lowering and validation of independent port definitions and usages across compilation units shall be scheduled strictly on a bounded work-stealing thread pool with worker upper bound $N_{\text{max\_workers}}$ in accordance with REQ-0012.
     - Directive 3 (String Interner Memory Allocation Exception): Identifier strings, port names, and fully qualified symbol paths shall be copied into the global symbol interner pool during the initial lexical pass as the sole permitted exception to zero-copy bump arena storage in accordance with REQ-0036.
     - Directive 4 (Synchronization Token Error Recovery): The lowering engine shall implement synchronization token error recovery in accordance with REQ-0013 and REQ-0016: upon detecting a malformed port declaration (`E0200`), directional mismatch (`E0201`), payload type mismatch (`E0202`), circular inheritance (`E0203`), or encapsulation bypass (`E0220`), the engine shall record the diagnostic into preallocated sink buffer $\mathcal{D}_{\text{sink}}$, substitute typed error sentinel $\bot$, and resynchronize at the next delimiter or definition boundary. If diagnostic count reaches $C_{\text{max\_errors}}$, diagnostic code `E0199` shall be emitted and compilation terminated gracefully.
     - Directive 5 (Panic-Free Release Paths & Benchmarking Isolation): Compiler library code shall strictly enforce a deterministic, non-panicking execution contract with total-function termination across all inputs. Performance gates (< 25 ms latency, < 100 MB RSS) shall be evaluated exclusively in compiled Release mode (`--release`).
     - Domain Purity: All diagnostic messages, test models, and examples shall strictly employ synthetic abstract MBSE placeholders (`Package_0`, `Classifier_Alpha`, `Part_0`, `Part_1`, `PortDef_0`, `PortDef_1`, `Port_1`, `Port_2`, `Flow_A`, `param_x : Real`).

- **Formal Invariant**: Let $\mathcal{D}$ denote the discrete closed direction domain:

$$
\mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut} \}
$$

The directional inversion involution operator ${\sim} : \mathcal{D} \to \mathcal{D}$ is defined as:

$$
{\sim}(d) = \begin{cases}
\text{Out}, & \text{if } d = \text{In} \\
\text{In}, & \text{if } d = \text{Out} \\
\text{InOut}, & \text{if } d = \text{InOut}
\end{cases}
$$

Involution Identity:

$$
\forall d \in \mathcal{D}, \quad {\sim}({\sim}d) \equiv d
$$

Port Definition Classifier Specialization: Every port definition classifier $P \in \mathcal{P}_{\text{def}}$ specializes KerML $\text{Structure}$:

$$
P \le \text{Structure}
$$

Each port definition classifier $P \in \mathcal{P}_{\text{def}}$ is formalized as an 8-tuple:

$$
P = \langle \text{id}_{P}, \text{name}_{P}, \mathcal{F}_{P}, \mathcal{S}_{P}, \Psi_{P}, \mu_{P}, \kappa_{P}, \Delta_{P} \rangle
$$

where:
- $\text{id}_{P} \in \mathbb{N}_{32}$ is the unique typed bump arena node handle,
- $\text{name}_{P} \in \mathcal{S}_{\text{intern}}$ is the interned scalar symbol identifier,
- $\mathcal{F}_{P} = \{ f_{1}, \dots, f_{m} \}$ is the set of owned and inherited feature handles,
- $\mathcal{S}_{P} \subseteq \mathcal{P}_{\text{def}}$ is the set of direct generalization supertypes,
- $\Psi_{P} = \{ \psi_{1}, \dots, \psi_{k} \}$ is the set of invariant contract constraints,
- $\mu_{P} = [l_{P}, u_{P}] \subseteq \mathbb{N}_{0} \times (\mathbb{N}_{0} \cup \{ \infty \})$ is the definition multiplicity interval with $0 \le l_{P} \le u_{P}$ and $u_{P} \ge 1$,
- $\kappa_{P} = \text{PortDefinitionKind}$ is the classifier discriminant,
- $\Delta_{P} \in \Sigma^{*}$ is the deterministic RFC 4122 UUIDv5 identifier.

Each port usage $p \in \mathcal{V}_{\text{port}}$ declared on structural classifier $C \in \mathcal{C}$ is formalized as a 10-tuple:

$$
p = \langle \text{id}_{p}, \text{name}_{p}, \text{owner}_{p}, \tau_{p}, c_{p}, d_{\text{decl}}, d_{\text{eff}}, \mu_{p}, \text{span}_{p}, \Delta_{p} \rangle
$$

where:
- $\text{id}_{p} \in \mathbb{N}_{32}$ is the arena node handle,
- $\text{name}_{p} \in \mathcal{S}_{\text{intern}}$ is the interned symbol handle,
- $\text{owner}_{p} \in \mathcal{H}_{\text{classifier}}$ is the parent component or classifier handle ($C = \text{owner}_{p}$),
- $\tau_{p} \in \mathcal{P}_{\text{def}}$ is the referenced port definition classifier,
- $c_{p} \in \mathbb{B}$ is the boolean conjugation flag ($c_{p} = \text{true} \iff p : {\sim}\tau_{p}$),
- $d_{\text{decl}} \in \mathcal{D} \cup \{ \bot \}$ is the declared port direction,
- $d_{\text{eff}} \in \mathcal{D}$ is the resolved effective port direction,
- $\mu_{p} = [l_{p}, u_{p}]$ is the multiplicity interval ($0 \le l_{p} \le u_{p}, u_{p} \ge 1$),
- $\text{span}_{p} = \langle \text{file\_id}, p_{\text{start}}, p_{\text{end}}, \text{line}, \text{col} \rangle$ is the exact source provenance coordinate,
- $\Delta_{p} \in \Sigma^{*}$ is the deterministic RFC 4122 UUIDv5 identifier.

Effective Direction Resolution Invariant:

$$
d_{\text{eff}}(p) = \begin{cases}
{\sim}d_{\text{decl}}, & \text{if } c_{p} = \text{true} \wedge d_{\text{decl}} \ne \bot \\
d_{\text{decl}}, & \text{if } c_{p} = \text{false} \wedge d_{\text{decl}} \ne \bot \\
\text{InferDirection}(\tau_{p}, c_{p}), & \text{if } d_{\text{decl}} = \bot
\end{cases}
$$

Conjugate Port Feature Inversion Invariant:
For port usage $p$ typed by ${\sim}P$ ($c_{p} = \text{true}$):

$$
\forall f \in \mathcal{F}_{\tau_{p}}, \quad \text{dir}(\pi_{f}(p)) = {\sim}\text{dir}(f) \wedge \tau(\pi_{f}(p)) \equiv \tau(f) \wedge \mu(\pi_{f}(p)) \equiv \mu(f)
$$

Boundary Encapsulation Invariant:
Let $C \in \mathcal{C}$ be a component classifier. The feature set of $C$ is partitioned into boundary ports and internal features:

$$
\mathcal{F}_{\text{all}}(C) = \text{ports}(C) \cup \text{internal\_features}(C), \quad \text{ports}(C) \cap \text{internal\_features}(C) = \emptyset
$$

Let $\mathcal{E}_{\text{ext}}(C)$ denote the set of external connections connecting $C$ to its enclosing environment or sibling components. For any connection $K = \langle u, v \rangle \in \mathcal{E}_{\text{ext}}(C)$:

$$
\begin{aligned}
(u \in \mathcal{F}_{\text{all}}(C) \implies u \in \text{ports}(C)) &\wedge (v \in \mathcal{F}_{\text{all}}(C) \implies v \in \text{ports}(C)) \\
\text{endpoints}(K) \cap \text{internal\_features}(C) &= \emptyset
\end{aligned}
$$

Subtyping Meet-Semilattice and C3 Linearization Invariant (Algorithmic Bound NP-3):
Let $(\mathcal{P}_{\text{def}}, \le)$ denote the poset of port definitions. Subtyping satisfies:

$$
\begin{aligned}
\forall P \in \mathcal{P}_{\text{def}}, &\quad P \le P \quad (\text{reflexivity}) \\
\forall P_{1}, P_{2}, P_{3} \in \mathcal{P}_{\text{def}}, &\quad (P_{1} \le P_{2} \wedge P_{2} \le P_{3}) \implies P_{1} \le P_{3} \quad (\text{transitivity}) \\
\forall P_{1}, P_{2} \in \mathcal{P}_{\text{def}}, &\quad (P_{1} \le P_{2} \wedge P_{2} \le P_{1}) \implies P_{1} = P_{2} \quad (\text{antisymmetry})
\end{aligned}
$$

For a port definition $P$ declaring direct supertypes $\mathcal{S}_{P} = \langle S_{1}, S_{2}, \dots, S_{k} \rangle$:

$$
\text{C3}(P) = [P] \mathbin{\Vert} \text{merge}(\text{C3}(S_{1}), \text{C3}(S_{2}), \dots, \text{C3}(S_{k}), [S_{1}, S_{2}, \dots, S_{k}])
$$

where $\mathbin{\Vert}$ denotes sequence concatenation and $\text{merge}$ extracts candidates preserving local precedence order without cyclic dependencies.

Peer-to-Peer Directional Compatibility Invariant:
For an assembly connection $K = \langle p_{1}, p_{2} \rangle$ between sibling ports $p_{1}$ and $p_{2}$:

$$
\text{CompatibleDirection}(p_{1}, p_{2}) \iff \begin{cases}
(d_{\text{eff}}(p_{1}) = \text{Out} \wedge d_{\text{eff}}(p_{2}) = \text{In}), & \text{or} \\
(d_{\text{eff}}(p_{1}) = \text{In} \wedge d_{\text{eff}}(p_{2}) = \text{Out}), & \text{or} \\
(d_{\text{eff}}(p_{1}) = \text{InOut} \wedge d_{\text{eff}}(p_{2}) = \text{InOut})
\end{cases}
$$

Diagnostic Code Trigger Invariants:
Compiler diagnostic emission is bound strictly to the taxonomy of REQ-0191:

$$
\begin{aligned}
\text{IsMalformedPort}(P) \vee \text{InvalidKind}(P) &\implies \text{Diagnostic}(P, \text{DiagnosticCode::E0200}, \text{MalformedPortDefinition}) \in \mathcal{D}_{\text{sink}} \\
\kappa_{\text{conn}}(K) = \text{Assembly} \wedge \neg \text{CompatibleDirection}(p_{1}, p_{2}) &\implies \text{Diagnostic}(K, \text{DiagnosticCode::E0201}, \text{PortDirectionMismatch}) \in \mathcal{D}_{\text{sink}} \\
\neg(\tau(p_{1}) \le \tau(p_{2})) \vee \neg(\mu(p_{1}) \subseteq \mu(p_{2})) &\implies \text{Diagnostic}(K, \text{DiagnosticCode::E0202}, \text{PayloadTypeMismatch}) \in \mathcal{D}_{\text{sink}} \\
\text{HasCycle}(G_{\text{inherit}}) &\implies \text{Diagnostic}(G_{\text{inherit}}, \text{DiagnosticCode::E0203}, \text{CircularPortInheritance}) \in \mathcal{D}_{\text{sink}} \\
\text{endpoints}(K) \cap \text{internal\_features}(C) \ne \emptyset &\implies \text{Diagnostic}(K, \text{DiagnosticCode::E0220}, \text{EncapsulationBypass}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
$$

Deterministic RFC 4122 UUIDv5 Identification Invariant:

$$
\begin{aligned}
\Delta_{P} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(P)) \\
\Delta_{p} &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(C) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \text{name}_{p})
\end{aligned}
$$

- **Computational Complexity & Algorithmic Bounds**: Lowering of `port def` and directed port usages executes within Complexity Class $\mathbf{P}$. The computational bounds are formalized as follows:
  1. Frontier NP-3 Complexity Context: Subtyping lattice consistency and feature redefinition across multiple inheritance hierarchies is NP-complete for arbitrary partially ordered sets (posets). In the sovereign compiler, the subtyping space is restricted to a monotonic bounded meet-semilattice $(\mathcal{P}_{\text{def}}, \le)$ with unambiguous C3 linearization. This restriction eliminates exponential backtracking search, ensuring all subtyping checks and feature redefinition verifications execute in deterministic polynomial time.
  2. Port Definition Symbol Resolution: Registering and resolving a port definition in the lexical symbol table executes in strictly $O(1)$ amortized time via interned symbol handles.
  3. Directional Feature Inversion & Binding: For a port definition $P$ with $M = |\mathcal{F}_{P}|$ features, binding directional projections to a port usage or computing conjugated feature inversions executes in strictly deterministic $O(M)$ linear time.
  4. Boundary Encapsulation Verification: For a component classifier $C$ declaring $K$ connections, verifying that all external connection endpoints belong to the declared port set $\text{ports}(C)$ executes in $O(1)$ set membership lookup per endpoint, yielding $O(K)$ time.
  5. C3 Linearization of Multiple Supertypes: For a port definition hierarchy with $V$ ancestor definitions and $E$ specialization edges, computing the linearized precedence order via C3 executes in deterministic $O(V + E)$ time without backtracking.
  6. Peer Connection Compatibility Check: Checking directional compatibility and type conformance across connected ports executes in $O(1)$ scalar direction lookup and $O(1)$ cached subtyping check.
  7. Aggregate Model Lowering Complexity: For an entire AST model with $N$ classifiers, $P$ total port usages, $M$ port features, and $K$ connections:

$$
T(N, P, M, K) = O(N + P \cdot M + K)
$$

  8. Bounded Work-Stealing Parallelism: Parallel lowering and verification across independent compilation units scheduled onto a bounded work-stealing thread pool with $N_{\text{max\_workers}}$ workers executes within:

$$
T_{\text{parallel}}(N, P, M, K) = O\left(\frac{N + P \cdot M + K}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}}\right)
$$

  9. Space Complexity: Auxiliary memory overhead is strictly $O(1)$ beyond contiguous bump arena storage for AST nodes ($O(N + P \cdot M)$) and the preallocated diagnostic sink buffer ($O(C_{\text{max\_errors}}) = O(1)$), ensuring zero heap reallocation during the lowering pass.

- **Verification & Conformance Criteria**: Automated test suites shall deterministically verify compliance against synthetic abstract MBSE models (e.g., `Package_0`, `Classifier_Alpha`, `Part_0`, `Part_1`, `PortDef_0`, `PortDef_1`, `Port_1`, `Port_2`, `Flow_A`, `param_x : Real`) across the following verification gates:
  1. PortDefinition Specialization Gate: Define `port def PortDef_0` containing feature `out Flow_A : Real`. Assert that `PortDef_0` lowers as a first-class classifier node specializing KerML `Structure` (`Base::Structure`) with valid arena handles and interned symbol identifiers.
  2. Directed Port Usage Lowering Gate: Declare `in port Port_1 : PortDef_0` and `out port Port_2 : PortDef_0` within `part def Part_0`. Assert that each port usage lowers with correct effective directions (`In` and `Out`), referenced definition handles, and source provenance coordinates.
  3. Conjugate Port Instantiation Gate: Declare `port Port_1 : ~PortDef_0` within `part def Part_0`. Assert that the conjugate flag $c_{p}$ is set to `true`, the effective direction of `Flow_A` is inverted from `Out` to `In`, and payload type `Real` is preserved.
  4. Boundary Encapsulation & Bypass Rejection Gate: Declare component `part def Part_0` containing internal sub-part `part SubPart_0` and boundary `port Port_0 : PortDef_0`. Construct an external connection directly targeting internal feature `SubPart_0.Flow_A` bypassing `Port_0`. Assert deterministic rejection with diagnostic error code `E0220` (`EncapsulationBypass`) with exact source span coordinates.
  5. Peer Directional Compatibility & Mismatch Gate:
     - Connect `Port_1` (effective direction `Out`) to `Port_2` (effective direction `In`) across sibling parts; assert connection validates successfully with zero diagnostics.

  6. Payload Typing & Stream Multiplicity Gate:
     - Connect a source port with payload `Real` to a target port with payload `Integer`; assert deterministic rejection with diagnostic error code `E0202` (`PayloadTypeMismatch`).

  7. Port Subtyping Lattice & C3 Linearization Gate (Algorithmic Bound NP-3): Construct a multiple inheritance diamond hierarchy:
     - Declare `port def PortDef_Root`, `port def PortDef_Left :> PortDef_Root`, `port def PortDef_Right :> PortDef_Root`, and `port def PortDef_Bottom :> PortDef_Left, PortDef_Right`.
     - Assert that C3 linearization resolves the deterministic precedence order without backtracking in $O(V + E)$ time.
     - Assert that `PortDef_Bottom` conforms to `PortDef_Root` within the subtyping meet-semilattice.
  8. Circular Inheritance Detection Gate: Construct mutually recursive port definition inheritance:
     - Declare `port def PortDef_CycleA :> PortDef_CycleB;` and `port def PortDef_CycleB :> PortDef_CycleA;`.
     - Assert cycle detection engine identifies the cycle and deterministically emits diagnostic error code `E0203` (`CircularPortInheritance`).
  9. Error Recovery & Sink Capacity Graceful Halt Gate:

  10. Bitwise Determinism & Deterministic UUIDv5 Gate:
      - Assert repeated compilation runs on identical AST models produce bitwise identical lowered nodes and Merkle digest roots with 0-byte diff churn.
      - Assert every generated UUIDv5 matches RFC 4122 namespace hashing of the namespace OID and symbol path.
