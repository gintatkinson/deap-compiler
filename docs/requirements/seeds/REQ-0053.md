### REQ-0053: Tombstone Pruning Engine for Renamed & Orphaned AST Nodes
- **Normative Statement**: The persistence engine shall maintain a centralized manifest of generated artifacts (`CodegenManifest`) and execute automated tombstone pruning (`prune_tombstones`) so that when a SysML classifier is deleted or renamed, all previously generated artifacts derived from that element are cleanly pruned from disk and empty parent directories are removed.
- **Formal Invariant**: Let $\mathcal{A}_{\text{active}}$ be the set of active generated file paths, and $\mathcal{A}_{\text{manifest}}$ be the set recorded in the previous compilation manifest. The set of orphaned artifacts to prune $\mathcal{T}_{\text{prune}}$ satisfies:
$$
\mathcal{T}_{\text{prune}} = \mathcal{A}_{\text{manifest}} \setminus \mathcal{A}_{\text{active}}
$$
Safe Unlink Invariant:
$$
\forall f \in \mathcal{T}_{\text{prune}}, \quad \text{UnlinkFile}(f) \wedge \text{CleanEmptyParentDirs}(\text{Parent}(f))
$$
Manifest Synchronization Invariant: Following pruning, the updated on-disk manifest records strictly the active set:
$$
\mathcal{A}_{\text{manifest}}^{\text{updated}} = \mathcal{A}_{\text{active}}
$$
No Orphan Artifacts Invariant: The workspace working tree contains zero residual files from removed model elements.
- **Computational Complexity & Algorithmic Bounds**: Set difference and tombstone pruning execute in $O(|\mathcal{A}_{\text{manifest}}| + |\mathcal{A}_{\text{active}}|)$ linear time.
- **Verification & Conformance Criteria**: Verification suite tests renaming and deleting model classifiers and verifies that obsolete generated files and directories are cleanly deleted from disk.
