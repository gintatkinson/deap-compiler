### REQ-0029: OpenAPI (JSON/YAML) Schema Ingestion for Paths, Operations & Payloads
- **Normative Statement**: The ingestion engine shall provide an OpenAPI parser that parses OpenAPI 3.0 and 3.1 specifications in JSON and YAML formats into intermediate schema IR, mapping schema component objects to parts and data types, API paths to interface endpoints, and HTTP operations (GET, POST, PUT, DELETE) to actions with typed request and response payload schemas.
- **Formal Invariant**: Let $\mathcal{O}$ be an OpenAPI document. The lowering mapping $\mathcal{T}_{\text{openapi}}$ satisfies:
$$
\begin{aligned}
\text{components/schemas/}S &\longmapsto \text{IngestedPart}(S) \\
\text{paths/}P/\text{method} &\longmapsto \text{IngestedAction}(\text{method} \mathbin{\Vert} \text{"\_"} \mathbin{\Vert} P, \text{endpoint}: P)
\end{aligned}
$$
Payload Schema Mapping Invariant:
$$
\text{requestBody}(P, m) \longmapsto \text{InputParameter}(\text{"payload"}, \tau_{\text{schema}})
$$
$$
\text{responses}(P, m, 200) \longmapsto \text{OutputParameter}(\text{"result"}, \tau_{\text{schema}})
$$
Path parameter extraction: URL path parameters (`{param}`) lower to typed input parameters on the synthesized action.
- **Computational Complexity & Algorithmic Bounds**: Parsing OpenAPI JSON/YAML trees executes in $O(N)$ linear time where $N$ is document byte size.
- **Verification & Conformance Criteria**: Verification suite tests petstore and enterprise OpenAPI specs, verifying 100% path, operation, and schema model extraction.
