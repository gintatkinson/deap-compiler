### REQ-0182: ROS2 Node Architecture Emission: Publishers, Subscribers & QoS Profiles
- **Normative Statement**: The code generation engine shall synthesize idiomatic ROS2 C++ nodes from component specifications, generating strongly typed publishers, subscriptions, service servers, client handlers, and Quality of Service (QoS) profiles matching interface timing and reliability contracts.
- **Formal Invariant**: Each emitted ROS2 communication endpoint maps bijectively to an AST port definition:
$$
\text{ROS2Endpoint}(P) = \langle \text{TopicName}(P), \text{MessageType}(P), \text{QoSProfile}(P) \rangle
$$
where QoS configuration enforces reliability, durability, history depth, and deadline parameters:
$$
\text{QoSProfile}(P) = \langle \text{Reliability}, \text{Durability}, \text{HistoryKind}, \text{Depth}, \text{DeadlinePeriod} \rangle
$$
with $\text{Reliability} \in \{\text{Reliable}, \text{BestEffort}\}$ and $\text{Durability} \in \{\text{Volatile}, \text{TransientLocal}\}$.
Callback execution model: Generated subscriptions bind to non-blocking deterministic executors without heap allocations during steady-state execution.
Complexity bound: Node synthesis executes in deterministic linear time $O(|P|)$ with respect to component port count $|P|$.
