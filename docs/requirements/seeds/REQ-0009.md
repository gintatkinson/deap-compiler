### REQ-0009: Zero-Copy Bump Arena Memory Management
- **Normative Statement**: The compiler front-end and core AST engine shall utilize zero-copy memory management via contiguous bump allocation arenas for all parsed AST nodes, token streams, and intermediate representation graphs, borrowing byte slice references directly from memory-mapped source file buffers without intermediate heap string cloning.
- **Formal Invariant**: Let $\mathcal{B}_{\text{file}}$ be a memory-mapped byte buffer of length $L$. An AST string token $T$ is represented as a contiguous byte slice reference:
$$
T = \text{Slice}(\mathcal{B}_{\text{file}}, s, l), \quad \text{where } 0 \le s \le s+l \le L
$$
Arena memory allocation satisfies monotonic bump pointer progression:
$$
\text{ArenaOffset}_{k+1} = \text{Align}(\text{ArenaOffset}_k + \text{sizeof}(\text{Node}_k), \text{Alignment})
$$
Zero Heap Allocation Invariant during parsing pass:
$$
\text{HeapAllocs}(\text{ParsePass}(\mathcal{B}_{\text{file}})) = 0
$$
All AST nodes reside in contiguous arena segments with linear physical memory locality, completely eliminating pointer indirection and individual heap deallocation overhead.
- **Computational Complexity & Algorithmic Bounds**: Node allocation executes in $O(1)$ constant time with zero amortized reallocations within sized arena blocks.
- **Verification & Conformance Criteria**: Memory profiler asserts zero individual node heap allocations during the primary lexical and parsing passes.
