### REQ-0033: Multi-File Cryptographic Digest Computation (`.pipeline/schema-digest.json`)
- **Normative Statement**: The ingestion engine shall compute a multi-file cryptographic manifest recording SHA-256 content hashes, byte sizes, line counts, and AST entity counts for all input schema files and the emitted `schema/model.sysml`, writing the manifest atomically to `.pipeline/schema-digest.json`.
- **Formal Invariant**: The digest manifest contains an entry for every input file $F_i \in \mathcal{F}_{\text{inputs}}$:
$$
\text{Digest}(F_i) = \langle P_i, \text{Hex}(\text{SHA256}(F_i)), |F_i|, \text{Lines}(F_i), N_i \rangle
$$
where $P_i$ is the workspace-relative path and $N_i$ is the count of parsed AST nodes.
Composite Root Digest Invariant:
$$
\text{CompositeHash} = \text{SHA256}\left( \bigoplus_{i=1}^M \text{Digest}(F_i) \right)
$$
Manifest Cache Invariant: If all input file digests match `.pipeline/schema-digest.json` upon subsequent invocation, ingestion skips parsing and reuses the cached model:
$$
\forall F_i, \text{Digest}(F_i) == \text{CachedDigest}(F_i) \implies \text{ReuseCachedModel}()
$$
- **Computational Complexity & Algorithmic Bounds**: Digest computation executes in $O(B)$ linear time where $B$ is the aggregate byte size across all schema input files.
- **Verification & Conformance Criteria**: Modifying a single character in any schema file invalidates the composite digest and triggers complete manifest regeneration.
