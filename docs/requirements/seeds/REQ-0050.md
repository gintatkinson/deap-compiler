### REQ-0050: AST Slice Serialization Contract with Reified Dependency Envelopes
- **Normative Statement**: The AST slicing engine shall serialize extracted slices according to a strict contract containing a reified dependency envelope that includes all referenced type definitions, unit systems, and constraint declarations required to evaluate the sliced component in complete isolation.
- **Formal Invariant**: Every symbol referenced within the sliced subgraph $G_{\text{slice}}$ is defined either within $G_{\text{slice}}$ or within the reified dependency envelope $\text{Deps}(G_{\text{slice}})$:
$$
\text{ReferencedSymbols}(G_{\text{slice}}) \subseteq \text{DefinedSymbols}(G_{\text{slice}}) \cup \text{DefinedSymbols}(\text{Deps}(G_{\text{slice}}))
$$
Standalone Validity Invariant:
$$
\text{ValidateSlice}(G_{\text{slice}} \cup \text{Deps}(G_{\text{slice}})) \equiv \text{Valid}
$$
Zero Dangling References Invariant:
$$
\text{UnresolvedSymbols}(G_{\text{slice}} \cup \text{Deps}(G_{\text{slice}})) = \emptyset
$$
The serialized envelope packages element AST definitions, interface port contracts, referenced data types, and associated numerical constraint bounds.
- **Computational Complexity & Algorithmic Bounds**: Dependency envelope closure computation executes in $O(|V_{\text{slice}}| \cdot \bar{d})$ where $\bar{d}$ is the average reference fan-out degree.
- **Verification & Conformance Criteria**: Subagent prompt payload verification confirms zero unresolved external symbol references when evaluating serialized slice envelopes.
